## 一、缺的是什么

报表引擎（`server/src/reporting/`）此前只有 **7 个数据集**：
订单 / 发票 / 收付凭证 / 运单 / 增值税发票 / 付汇水单 / 退税申报 —— **没有库存**。

引擎的消费方不是「报表设计器」（那个前端不存在），而是：
- **保存的报表定义**（`ReportDefinition`）→ `POST /definitions/:id/run`
- **定时任务** `scheduledReportRunner` → `runReportDefinition`（可按计划跑并投递）

所以「没有库存数据集」= **无法定义、也无法定时投递任何库存报表**。

### 数据集设计（写进 `description`，供设计器使用者看到）

三条口径**必须**遵守，故直接写在数据集描述里，并让对应字段可作维度：

1. **数量跨单位不可相加**（YD/M/KG/PC/SET）→ `unit` 是维度
2. **存货按货权（`ownership`）而非物理位置**：`Transferred`（货权已转移）不得计入我方存货 → `ownership` 是枚举维度（Owned/Transferred）
3. **单位成本是金额、跨币种不可相加** → `currency` 是维度

## 三、⚠️ 读 scope 必须收窄（本批的安全要点）

`route.ts` 的 `DATASET_SCOPE` 决定数据集对**出数动作**（preview/drill/run）与
**运行快照读取**（GET /runs/:id、export.csv）是否需要额外读 scope；
不在表内的数据集是「全员可读」。

**库存项含 `unitCost`（单位成本）= 金额。** 若照抄「orders/shipments 不额外拦」的做法，
持 `reports:write` 的角色就能经报表读到库存成本 —— 这正是 P1-2 / P4-1 修过的
「金额经报表旁路泄漏」同一类问题。故收窄到 `inventory:read`。

真库实测的风险画像是真的存在的：

| 账号 | `reports:write` | `inventory:read` |
|---|---|---|
| `charlie.qian`（财务） | ✅ | **❌** |
| `chloe.su`（业务员） | ✅ | **❌** |
| `jason.shen`（超管） | ✅ | ✅ |

## 五、❗本次未交付：UI 入口（必须知会）

**报表引擎完全没有前端** —— 不只是库存，**任何数据集都没有报表设计器**。
全仓 `services/` `components/` 里对 `/v1/reports` 的消费为 **0**。

所以本批交付的是**后端能力**：现在可以通过 API 定义库存报表定义并交给定时任务投递；
但**用户在界面上还看不到任何库存报表**。

进一步核查发现两处相关缺口（同一件事的两面）：

1. `inventoryOwnershipService.summarizeByOwnership`（D7-② 建的货权汇总）
   **连 GET 路由都没有**，全仓 UI 消费为 **0**
2. `InventoryItem.ownership` 字段在 `components/` 里**零出现** ——
   D7-② 的「货权」概念目前**只存在于数据库**

**建议的下一批（一个批次可同时收口三处）**：
- 后端：给 `summarizeByOwnership` 补 `GET /api/v1/inventory/ownership-summary`
- 前端：`InventoryManager` 加第 4 个 tab「货权汇总」（现有 items/warehouses/alerts），
  按**货权 × 单位 × 币种**分组展示（与报表数据集同口径：不跨单位、不跨币种相加）
- 效果：让 ⑤ 的「dashboard」半边 + D7-② 的货权字段 + 本批的数据集**同时变得可见**

> 放在 `InventoryManager` 而**不是**财务报表面板：后者的 8 个 tab（aging/statement/fx/…）
> 全属财务域，塞库存进去是域错位；库存归后勤。
