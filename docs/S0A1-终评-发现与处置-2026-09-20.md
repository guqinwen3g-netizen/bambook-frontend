## 1. Important #1（合并阻断）—— 本批自己引入的回归：签字端点把内部英文串甩上屏

**缺陷链（评审发现，我逐环节在代码里复核确认）**
1. Task 4 给 `StageGateError` 补了 `statusCode`，**默认一律 409**（`stageService.ts` 类定义）。
2. 补了 `statusCode` ⇒ 该类**从此满足 `isBusinessError`**（`code:string` + `statusCode:number`）。
3. 于是"**逃出 service try/catch** 的拒绝"从「非业务错误 → 500 + 注册表通用中文」
   变成「业务错误 → **原样透传自己的 code / status / message**」。
4. `POST /:orderId/sign/:stageKey` 正好有一条这样的逃出抛出：`signStage` 的
   `throw new StageGateError('INVALID_STAGE', \`Stage ${stageKey} not found\`)`。
   ⇒ 净效果：**409 + `INVALID_STAGE` + `"Stage pp not found"` 直接显示给业务员**。
5. 而同一个 `INVALID_STAGE` 在 block 端点被 `route.ts` 的状态映射答成 **400**
   ⇒ **同码不同状态**；且**没有任何测试覆盖签字端点这个被改掉的契约**。

**为什么严重**：它同时踩本批的三条判据 —— G7.5（用户看到的文案必须说清"发生了什么/怎么办"，
内部标识符不算）、B22 那一类"内部文本直上响应体"、以及 G6.5/R2"一个码一个状态只能有一处依据"。
它不是历史债，是本批新造的。评审员说得对：这类事必须由评审而不是由我自己发现。

**处置（`0f37c786`）**
- ① **默认状态改查注册表**：`statusCode = lookupErrorCode(code)?.status ?? 409`。
  ⇒ 类只是**读**那张表，没有在生产里再写第三本映射（R2）。
- ② **只登记两本既有映射口径一致的码**：`INVALID_STAGE` 400、`ORDER_NOT_FOUND` 404。
  `STAGE_NOT_SEQUENTIAL` **有意不登记** —— `route.ts` 给 400、`routeV2.ts` 给 409，
  登记进去 = 替两个已上线端点选边，那是行为契约决策 ⇒ 降级为 **B25** 等拍板。
- ③ 把 production 域 **10 处**业务拒绝文案改成中文（含 2 处 `return { ok:false, error:{…} }` 里的英文串），
  保留 `stageKey` 等业务标识在中文句子里（本域既有写法就是这样），去掉裸英文。
- ④ 新增守卫：**每一处** `throw new StageGateError(...)` 的文案必须含中文，
  并钉死**认得率 16/17**（唯一不覆盖的是动态转发那处 `new StageGateError(first.code, first.message)`，理由写在测试里）。

**TDD 与可证伪证据（`stageSignExitContract.test.ts`）**
- **RED 实跑**（改代码之前）：5 条全红，报出的正是缺陷本身 ——
  `expected 409 to be 400`；`上屏文案必须是中文：Stage pp not found`；`INVALID_STAGE 必须已登记进注册表: expected undefined`；
  守卫一次列出 **8 处**纯英文抛出点（含本批之外的 6 处历史点，顺带全修了）。
- **GREEN**：5/5 绿；`npx tsc --noEmit` exit 0；相关 **22 个测试文件全绿**；
  `check-fail-open-inventory.mjs` **L-A 190 / L-B 171 未变**（我新写的 `?? 409` 没被误判成业务量兜底，
  且清单红的是既有存量，不是本批新增）。
