## 1. 这是什么

### 1.1 定位

Bambook Agent OS 是 Panda Clothing 内部的"企业代理操作系统"。它把公司日常用到的能力放到一个端里，让员工和 AI 共同操作：

- **业务数据**：订单、关系智库、数字档案、样品、智能邮箱、策略文库、业务工具箱。
- **AI 助手**：基于全部数据的对话与执行，背后是数据中心上跑的 Agent Orchestrator。
- **企业级身份**：多角色 / 多部门 / 多权限，所有动作都进 AuditLog。
- **本地大脑**：所有 AI 任务在公司数据中心执行，桌面端只负责界面与输入。

### 1.2 三层架构（用户视角）

```
┌─────────────────────────────────────────┐
│  桌面端（Electron / 浏览器）            │
│  - 登录 / 注册                           │
│  - 主界面：业务模块 + AI 助手           │
│  - 设置 / 管理后台                       │
└──────────────┬──────────────────────────┘
               │ HTTPS via Cloudflare Tunnel
               │ jiangsupanda.com/bambook
┌──────────────▼──────────────────────────┐
│  数据中心                                 │
│  - 主 API（Express + Prisma + Auth）     │
│  - AI Runtime + Agent Orchestrator       │
│  - 知识库 API                             │
│  - PostgreSQL 业务库                      │
│  - Resend 出邮件                          │
│  - Ops Panel（运维入口）                  │
└─────────────────────────────────────────┘
```

你在桌面端做的每一件事，都通过 `jiangsupanda.com/bambook` 打到数据中心，数据中心写入 PostgreSQL，必要时调用外部 LLM，返回结果。**桌面端不存业务数据**，公司换桌面端不丢数据。

### 1.3 角色与权限


| 角色 ID            | 中文      | 典型授权对象           |
| ---------------- | ------- | ---------------- |
| `admin`          | 系统管理员   | IT / 信息化负责人      |
| `manager`        | 管理岗     | 部门主管、业务负责人       |
| `merchandiser`   | 跟单 / 业务 | 订单跟进、大货生产        |
| `finance`        | 财务      | 账期、发票、收付款        |
| `sales`          | 销售      | 客户对接、报价          |
| `agent_operator` | AI 运营   | 助手训练、工作流配置、知识库整理 |
| `viewer`         | 只读访客    | 仅查看授权范围内的数据      |


权限不是单向授予，而是 **角色 + 部门 + 资源 ACL** 三维组合（Agent OS 内部叫 `ActorContext`）。同一个员工在不同部门可以有不同权限。所有权限变更都会写入审计日志（AuditLog），不可绕过。

## 2. 注册与登录

### 2.1 公开注册（员工自助）

打开桌面端登录页 → 点 **"申请注册"**：

1. 填邮箱 → 点 **"发送验证码"**。
2. 收件箱（**也看垃圾邮件夹**）会收到一封 `Bambook 注册验证码：xxxxxx`，由 `noreply@pandaclothing.cn` 发出。
3. 把 6 位数字粘回，再填姓名、密码、确认密码、所属部门（选填）。
4. 提交后会显示"等待管理员审批"。

> 验证码每个邮箱每小时最多发送 5 次，每次有效期 10 分钟，错误 5 次自动作废。

### 2.2 等待审批

注册成功的账号默认是 `pending` 状态，**不能登录**。需要由管理员在 [第 8 章 管理后台](#8-管理后台) → 用户管理 → 待审批区点击 **"批准"** 并分配角色后，账号才会变成 `active`。

如果 24 小时仍未审批，给你的直属管理员或 IT 联系。

### 2.3 已有账号登录

回到登录页：

1. 输入工作邮箱 + 密码。
2. 点 **"Sign in"**。
3. 登录成功 7 天内不需要重新登录（同一终端、同一浏览器/Electron 实例）。

如果忘记密码，请联系管理员在管理后台点 **"重置密码"**，会把你的密码重置成默认值，登录后到 [第 7 章 设置 → 账号](#74-账号-account) 改新密码。

### 2.4 登录失败的常见提示


| 提示                     | 含义       | 怎么办                               |
| ---------------------- | -------- | --------------------------------- |
| 邮箱或密码错误                | 邮箱/密码不匹配 | 重试，或请管理员重置密码                      |
| 账号待管理员审批               | 注册了但还没批  | 联系管理员尽快审批                         |
| 账号申请已被拒绝               | 注册被驳回    | 联系管理员说明原因                         |
| 账号已被停用                 | 账号被禁用    | 联系管理员                             |
| 网络错误 / Failed to fetch | 网络或服务问题  | 看 [13.2 网络/CORS](#132-网络--cors-类) |

## 5. AI 助手

### 5.1 它是谁

AI 助手是 Bambook 与员工对话的主入口。所有计算（理解、检索、规划、调用工具、生成回复）都在数据中心完成；桌面端只负责输入框和把回答流式渲染出来。

### 5.2 它会做什么

- 自然语言查询订单 / 客户 / 产品（"帮我看一下下个月要交的所有 Sumida 订单"）。
- 摘要邮件、起草回复（与"智能邮箱"模块联动）。
- 生成报表、整理资料（与"业务工具箱"联动）。
- 帮助新员工理解公司规范（与"策略文库"联动）。
- 在你授权的前提下，调用公司业务工具（如生成发票草稿、登记样品流转）。

### 5.3 怎么用

1. 进入 **AI 助手** 页。
2. 在底部输入栏输入问题，回车发送。
3. 助手会以流式 token 形式返回，过程中你可以随时点 **停止** 中止本次回答（按钮在发送区域，回答中自动从"发送"切成"停止"）。
4. 切到其他模块再切回来，会**保持当前会话进度**，不会丢消息。

### 5.4 AI 是怎么决定要不要做某件事的

每次对话背后是一个 `ActorContext`：

```
{
  userId: <你>,
  roles: [<你的角色>],
  departmentIds: [<你所在部门>],
  permissionScopes: [<授权清单>],
  knowledgeScopes: [...],
  toolScopes: [...]
}
```

Agent OS 会把这个 context 传到 Orchestrator → 知识检索 → 工具调用。**没在你权限范围里的数据，AI 不会读到，更不会泄露**。

### 5.5 高风险操作

部分动作（如批量发邮件、改财务数据、自动化执行）属于 **high-risk tool**，会**额外要求一次审批**：会创建一个 `ApprovalRequest`，进入 [第 8 章 管理后台](#8-管理后台) 的"学习与审批"队列，待 admin / manager 同意后才执行。审批之前 AI 只会展示"将会发生什么"。

## 6. 业务模块

> 本节仅介绍每个模块的核心功能与该模块独有的注意事项；通用导航 / 视图切换 / 搜索行为在主界面已统一。

### 6.1 全景看板（Dashboard）

- 实时显示订单状态、关键产能指标、3D 生产地球。
- "生产地球"会用动效标记当前订单所在国家、产线节点。
- 数据来自数据中心实时计算，不依赖桌面端缓存。

### 6.2 关系智库（Relations）

- 三类对象：客户（buyer）、供应商（supplier）、关键联系人（contact）。
- 每个对象都有时间线，记录最近一次报价、订单、邮件、AI 摘要。
- 支持画关系图谱（谁和谁通过哪笔订单关联）。
- **删除是软删除**：误删可由 admin 在管理后台恢复。

### 6.3 数字档案（Products）

- 公司所有 SKU / 面料 / 工艺的真源（single source of truth）。
- 支持图片、PDF、面料样本属性、生产参数。
- 每个产品页右侧的 **Related Orders** 会自动列出最近订单与产能记录。

### 6.4 大货生产（Orders）

- 订单全生命周期：创建 → 报价 → 确认 → 排产 → 出货 → 收款。
- 支持 PO 文件批量导入（PDF / Excel）。
- 每个订单都有 `OrderLine` 明细 + 状态历史，AI 助手能直接基于明细回答问题。
- "Globe 视图"切换：把当前过滤集中的订单投到 3D 地球上。

### 6.5 开发管理（Development）

- 样品申请、寄送、客户反馈、转大货流程。
- 与关系智库、数字档案双向关联（这块布给谁、做了什么样、最后转成哪笔大货）。

### 6.6 智能邮箱（Emails）

- 多账号 IMAP/SMTP 聚合。
- 对话线程视图（按主题、客户聚合，不是单封邮件）。
- AI 起草、AI 摘要、附件即看即下。
- 邮件数据存在数据中心，桌面端只缓存索引。

### 6.7 策略文库（KnowledgeBase）

- 企业内部知识：工艺手册、市场调研、过往项目复盘、SOP。
- 支持文档级 / 段落级 ACL（不同部门看到不同内容）。
- 与 AI 助手深度绑定：AI 回答时会引用文库段落，并标注来源。

### 6.8 业务工具箱（BusinessTools）

- 发票生成器、工具脚本、生产力小程序。
- 任何被注册到 Agent OS 的"工具"都可被 AI 助手调用，权限受 `toolScopes` 控制。
- 高风险工具（如批量发邮件）会进入审批队列。

### 6.9 UI 实验室（UiLab）

- 仅工程 / agent_operator 用。
- 用来预览组件 / 调试样式，不要在生产环境对客户使用。

## 7. 设置（Settings）

设置页有 7 个子 tab，按使用频率排序：

### 7.1 外观（Appearance）

主题：浅色 / 深色 / 跟随系统。改了立刻生效。

### 7.2 AI 对话

- **主对话模型**：4 个预设（Auto / GLM-5 / Kimi-K2.5 / MiniMax-M2.5）。Auto = 网关自动路由，推荐默认。
- **采样温度**：0 更稳，1 更有创造力；正常工作选 0.5~0.7。

### 7.3 朗读（Voice）

- 控制 AI 回答完成后的自动朗读语速（0.75×~1.5×）。
- 引擎走数据中心的 TTS 代理。

### 7.4 同步（Sync）

- **主数据 API**：默认 `https://jiangsupanda.com/bambook`，桌面端拼 `/api/...`。
- **知识库 API**：默认同上，需要单独的 `Bearer` Key。
- 都有"测试连接"按钮，会显示请求 URL、HTTP 状态码、错误详情。

### 7.5 API（对外接口密钥）

- 给第三方 / 集成方使用的 SDK Key（不是你登录用的密码）。
- 与 Resend 邮箱 Key、模型 Key 是不同维度的密钥，不要混。

### 7.6 账号（Account）

- 显示：姓名、邮箱、角色、所属部门。
- **修改密码**：必须输入当前密码 + 新密码 + 确认。
- 没有"修改邮箱"按钮——邮箱即账号 ID，要换需联系管理员。

### 7.7 安全（Security）

- 数据脱敏开关（预留）。
- 后续会接入会话登出全部、强制改密、二次验证等。

## 8. 管理后台

> 入口仅 admin 可见，左侧 Sidebar 最下方"管理后台"。

### 8.1 用户管理

页面顶部固定一个 **"注册申请待审批"** 区域：

- 显示所有 `pending` 账号、邮箱、申请部门、是否邮箱已验证。
- 每个用户行右侧有：
  - **角色下拉**：默认 `viewer`，可选 admin / manager / merchandiser / finance / sales / agent_operator。
  - **批准** 按钮：把账号变为 `active`，并按下拉框分配角色。
  - **驳回** 按钮：把账号标为 `rejected`，可填驳回原因。
- 处理时按钮显示 "处理中"，失败会在页面顶部红条显示具体错误。

下方是已激活用户列表：

- 头像、姓名、邮箱、当前角色、状态徽章。
- **"重置密码"** 按钮会把对方密码重置为 `bambook2026`，对方下次登录后自己改。

右上角 **"新建用户"** 按钮：管理员直接开账号（不走自助注册），跳过邮箱验证码。

### 8.2 角色与权限

- 列出所有内置角色 + 它们的权限范围。
- 系统内置角色（`isSystem=true`）不能改名/删除；自定义角色后续版本支持。

### 8.3 知识库权限

- 文档/段落级 ACL，按角色 / 部门授予 read / write。
- 当前为列表展示版本，下个版本支持图形化编辑。

### 8.4 工具权限

- 列出 Agent OS 注册的所有"软件工具"，标 `risk` 等级。
- 高风险工具默认只允许 admin / manager 调用，且需要审批才执行。

### 8.5 学习与审批

- **待审批**：高风险工具调用、Agent 自主操作的待批列表。
- **学习建议**：Agent 主动学到的规则、模式、标签建议。审批通过后会写入企业记忆，影响后续 AI 行为。

### 8.6 系统日志（AuditLog）

- 谁在什么时间做了什么、来源 IP、目标对象、详情。
- 支持按 action / actorId / 时间筛选。
- **不可改不可删**：合规审计就靠这张表。

## 9. 邮件验证码与 Resend

### 9.1 谁配置

只有 admin 在 Ops Panel 配置一次。员工不需要管。

### 9.2 工作机制

```
桌面端注册页
    ↓ 提交邮箱
主 API /api/auth/send-code
    ↓ 调用 Resend API
Resend (re_*** Key + noreply@pandaclothing.cn)
    ↓ 发送邮件
员工邮箱
```

### 9.3 在 Ops Panel 改 Key

1. 打开 `https://jiangsupanda.com/bambook/ops`，输入 Ops 密码。
2. 点 **"配置邮件发送 (Resend)"**。
3. 第 1 个弹窗：发件人，填 `noreply@pandaclothing.cn`（不要带 `< >` 显示名）。
4. 第 2 个弹窗：粘贴 `re_xxx...` API Key。
5. 主 API 5~10 秒后自动重启，新 Key 生效。

> 详细 DNS / 域名验证步骤见公司内部 OPS 文档。

### 9.4 配额

Resend 免费档：3000 封/月、100 封/天。一家公司日常注册量远低于此。

## 10. 运维面板（Ops Panel）

入口：`https://jiangsupanda.com/bambook/ops`，需要 Ops 管理密码（与登录账号是两套体系）。

### 10.1 核心健康检查

- 主数据 API、知识库 API、Cloudflare 隧道、AI Runtime、Agent OS 5 盏核心灯，绿灯=正常，红灯=异常。
- 点 **刷新** 会向数据中心拉真实状态。

### 10.2 数据中心导览

- 列出 PostgreSQL 所有表的真实行数、最近写入时间，便于判断同步是否健康。

### 10.3 一键运维动作

每个动作都需要二次确认码，避免误操作：

- 重启主 API
- 重启 Cloudflare 隧道
- 数据库备份
- 演示数据 dry-run / 回滚
- 自动部署最新 Ops Panel

### 10.4 配置类弹窗

- **配置模型 API Key**：腾讯云 / 智谱 / 等模型 Key。
- **配置邮件发送 (Resend)**：同上。
- **修改 Ops 管理密码**：要输 `CHANGE_OPS_PASSWORD` 二次确认。

### 10.5 上传更新包并部署

工程在本机改完代码后，跑一次：

```bash
cd /Users/<你>/WorkBuddy/Claw/apps/Bambook
./scripts/ops-upload-package.sh
```

该脚本会弹窗输入 Ops Token，把 `server/ops-panel`、`server/scripts`、`server/src`、`server/prisma` 等打包上传，数据中心会自动 `npm install` + `prisma migrate deploy` + `npm run build` + 重启。

## 11. AI 与数据安全

### 11.1 数据走向


| 数据                | 是否离开数据中心      |
| ----------------- | ---------------- |
| 订单 / 关系 / 产品 / 样品 | 否                |
| 邮件正文 / 附件         | 否                |
| 知识库文档             | 否                |
| AI 对话历史           | 否                |
| 发送给 LLM 的提示词与上下文  | 是（按需走外部 LLM API） |
| 发件验证码             | 是（走 Resend）      |


> 即使 LLM 那段数据出数据中心，也只在本次请求内传一次，**不会被外部模型训练**（模型 API 都是 inference only）。

### 11.2 凭证存放

- 用户密码：`bcrypt` 12 轮哈希存数据库，明文不落任何日志。
- 登录 token：JWT，默认 7 天有效；当前桌面端临时用 `Authorization: Bearer` + sessionStorage 兜底，未来同源访问改回 httpOnly cookie。
- API Key（模型、Resend、SDK）：写在 `~/bambook-main-api/.env.local`（权限 0600，仅数据中心本机用户可读）。

### 11.3 审计

所有权限变更、登录、批准、驳回、Resend 配置更新、工具调用都会写入 `AuditLog` 表，保留 ≥ 1 年。

### 12.1 自动备份

Ops Panel → "数据库备份" 按钮，会触发 `pg_dump --format=custom`，输出到 `/Users/Shared/BambookBackups/<时间戳>.dump`。

### 12.3 灾难恢复

完整流程见仓库内的数据中心运维文档（位于 `server/docs/`）。简版：

1. 准备一台新的数据中心主机。
2. `git clone` 项目仓库到 `~/bambook-main-api`。
3. `cp` 旧主机的 `.env.local` 与最近 `pg_dump` 备份过来。
4. `pg_restore` 到新主机的 PostgreSQL。
5. 启 LaunchAgent，等 5~10 分钟，所有服务自起。

## 13. 故障排查

### 13.1 登录 / 注册 类


| 现象                                | 真实根因                              | 你可以做的                                  |
| --------------------------------- | --------------------------------- | -------------------------------------- |
| `Failed to fetch`                 | 浏览器拦截 / 网络断 / 后端宕                 | 看 Ops Panel；确认网络；管理员重启主 API            |
| `Send code failed (HTTP 500)`     | 主 API 数据库出错                       | Ops Panel → 切日志 main，看 stack；多半是迁移没跑完  |
| `验证码发送服务异常：UserAccount 不存在`       | 主 API 连到了空数据库 / 迁移未跑              | 在数据中心上 `npx prisma migrate deploy` |
| `邮件发送失败：Resend SDK not available` | 数据中心的 node_modules 没装 resend | Ops Panel 重新部署一次                       |
| `账号待管理员审批`                        | 是注册流程的正常状态                        | 联系管理员批准                                |
| 注册时提示 `该邮箱已注册或正在审批中`              | 同邮箱已在数据库里                         | 管理员去后台查询/激活/重置密码                       |


### 13.2 网络 / CORS 类


| 现象                     | 检查点                                                                                                 |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| 任意接口 `Failed to fetch` | 公网 `curl -i https://jiangsupanda.com/bambook/api/health` 看是否 200；不通就是 Cloudflare/Tunnel/数据中心问题 |
| 接口返回 200 但浏览器拒绝        | 看响应头 `Access-Control-Allow-Origin` 是否回显具体来源；为 `*` 且请求带 cookie 会被浏览器拦截，重新部署最新 Ops 包                  |


### 13.3 服务全红

1. 进 `https://jiangsupanda.com/bambook/ops`。
2. 切日志为 `main`，看最后 60 行；多半能看到 stack trace。
3. 若 `.env.local: line N: syntax error near unexpected token`，说明被 source 的 `.env.local` 含 `<>` 等被 bash 当作重定向；修成纯邮箱 `noreply@xxx`，或单引号包裹 `'Bambook Neural <...>'`。
4. 若进程根本起不来，用 UU 远程进数据中心跑：

```bash
cd ~/bambook-main-api
launchctl kickstart -k "gui/$(id -u)/com.bambook.main-data-api"
sleep 5
tail -n 80 /tmp/bambook-main-data-api.log
```

### 13.4 AI 助手不回答

- 看 Ops Panel "AI Runtime" 灯：红灯说明 `TENCENT_API_KEY` 未配置/失效。
- 在 Ops Panel 点 **"配置模型 API Key"** 重设，5~10 秒后自动生效。

### 13.5 邮件收不到

1. 去 Resend 控制台 **Logs**，看是否有发送记录：
  - 没记录 → 主 API 没成功调用 Resend，多半是 Key 失效；用 Ops Panel 重设。
  - 有记录但状态非 `Delivered` → 看 bounce/complaint 原因，常见是收件方域拦截。
2. 看垃圾邮件夹。
3. DNS 验证（SPF/DKIM/MX）是否仍然 verified（Resend 控制台 Domains）。

## 14. 设计原则与未来路线

### 14.1 三条不变的原则

1. **数据中心唯一**：业务数据只在数据中心，桌面端是消费端。
2. **身份是一等公民**：每个动作都带 `ActorContext`，每个 high-risk 动作都进审批。
3. **审计无法绕过**：所有变更写 AuditLog，权限再高也可被复盘。

### 14.2 v3.x → v4.x 路线

- ✅ 多账号自助注册 + 邮箱验证 + 管理员审批
- ✅ JWT + httpOnly cookie / Bearer 兜底
- ✅ Resend 邮件通道
- ⏳ 自定义角色与细粒度权限编辑器
- ⏳ 知识库 ACL 可视化编辑
- ⏳ Agent 学习建议自动应用工作流
- ⏳ 二次验证（TOTP）
- ⏳ 跨终端会话管理与"全部登出"
