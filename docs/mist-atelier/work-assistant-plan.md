# 工作助手方案（方案 B：桌面端自建精简 Agent 框架）

> 状态：用户已确认（2026-10-15，第 13 节为确认结果），按分期实施。口径来源：决策总账第二十三节“AI 模型分层与 ChatGPT 订阅接入”。
> 本文只覆盖**工作助手**；平台 AI（汇总、需求识别、报价/审阅、对账、业务问答）维持统一平台连接，不在此改动。

## 1. 目标与边界

- 工作助手是业务员**自己的** Agent：按本人的实时指令干活（查邮箱、整理并填写开发资料、做 PPT / 文档、写企划、查业务数据并起草操作）。
- **凭据只用本人的**：本人的提供商 API Key（OpenAI 兼容接口），或本人的 ChatGPT 账号登录。不使用平台连接，也不设公司共享 AI 池。
- **在人之下**：能力上限 = 账号本身的权限；在此之内再由 Agent 上限收窄。对外发送、确认、删除、涉及资金的动作一律由人点确认后才执行。
- **运行在本机**：Agent 循环、模型调用、会话记录、邮件和附件都在业务员电脑上；只有用户选择上传到平台的附件与业务写入才进后端。
- 不嵌入 OpenBitFun 运行时；只参照它的分层并照搬模型接入与提供商配置的设计。

不做：自动化定时任务、多 Agent 派生、任意命令行执行、电脑操控（ComputerUse）、通用编程工作区。以后需要时单独评审。

## 2. 总体结构

```
渲染进程（Mist 前端：工作助手页）
   │  preload: window.bambookAssistant（仅主窗口主框架可用）
   ▼
Electron 主进程（桥接 + 确认弹窗 + 凭据加解密 safeStorage）
   │  MessagePort
   ▼
assistant-host（utilityProcess，独立进程，有内存/并发上限）
   ├─ model/      模型适配：openai(chat/responses) · chatgpt-subscription
   ├─ harness/    循环 · 上下文预算与压缩 · 取消/超时/步数上限 · 检查点
   ├─ tools/      工具注册表（声明 风险/作用域/确认策略/输入输出 schema）
   │    ├─ bambook.*  经 Mist 接口读写（委托令牌）
   │    ├─ mail.*     本机 IMAP/SMTP + 本机邮件库
   │    ├─ files.*    仅限用户授权的文件夹
   │    └─ docs.*     PPT / Word / Excel / Markdown 生成
   ├─ policy/     权限交集 + 风险分级 + 确认请求
   └─ store/      本机会话、运行日志、邮件库（userData 下，按账号分目录）
```

所有工具都在 assistant-host 里执行；渲染进程只拿到事件流（文本增量、工具调用、待确认卡片、结果），拿不到凭据。

## 3. 本机运行时形态

- **独立进程**：用 Electron `utilityProcess` 启动 assistant-host，崩溃或卡死不影响主窗口；主进程负责拉起、心跳、重启（有退避和上限）。
- **资源守护**（吸取旧实验 201GB 内存事故的教训）：
  - 进程启动参数限制堆内存（如 `--max-old-space-size=1024`），超限即重启并在页面提示。
  - 同时运行的任务数 ≤ 2；单轮最多 40 步工具调用；单次工具调用超时 60 秒（邮件同步、文档生成可单独放宽到 300 秒）；单轮总时长 30 分钟。
  - 文件读取、邮件正文、附件解析设单项大小上限（如 20MB），超出只取摘要并说明。
- **依赖轻**：只用 Node 内置能力加少量库（IMAP/SMTP、mail 解析、pptx/docx/xlsx 生成）；不需要 Rust、Tauri、本地 Web 服务。打包增量目标 < 60MB。
- **浏览器开发模式**：工作助手只在桌面端可用；浏览器访问时页面说明“需在 Bambook 桌面端使用”，不做假数据降级。

## 4. 模型适配层

照搬 OpenBitFun 的提供商配置字段，便于以后互相导入：

| 字段 | 说明 |
|---|---|
| `name` | 用户起的名称 |
| `format` | `openai`（chat completions）/ `openai-responses` / `chatgpt-subscription`（不接 Anthropic / Gemini 原生格式；它们若提供 OpenAI 兼容地址可按 `openai` 接入） |
| `base_url` / `request_url` | 基础地址；`request_url` 可覆盖完整请求地址 |
| `api_key` | 本人 Key；只存本机，用系统钥匙串（Electron `safeStorage`）加密 |
| `model` | 模型名；提供“获取可用模型”按钮（各家 models 接口；订阅用 codex models 清单） |
| `context_window` / `max_tokens` | 上下文与输出上限，用于预算与压缩 |
| `temperature` / `top_p` | 可选 |
| `reasoning` | 推理档位 low / medium / high / xhigh / max（支持的模型才显示） |
| `custom_headers` / `custom_request_body` | 兼容代理与私有网关 |
| `skip_ssl_verify` | 默认关闭，开启时页面明确警示 |

- 统一接口：`stream(messages, tools, options) → 事件流（text / tool_call / usage / done / error）`，Chat Completions 与 Responses 两种格式在适配器里转换（工具调用格式、system 消息位置、图像输入）。
- **ChatGPT 账号登录**：把服务端 `codexSubscription.ts` 的设备码登录、令牌刷新、Responses SSE 抽成共享模块，在 assistant-host 里运行；令牌存本机（加密），**不再经过后端**。服务端现有的个人订阅接口 `/api/mist/ai/subscriptions*` 在工作助手上线后下线（避免个人凭据存服务器）。
- 失败处理：限额、授权失效、网络错误给出固定中文提示和“重新登录 / 切换模型”入口；不自动切到其他人或平台的凭据。

## 5. 精简 Harness

- **循环**：用户消息 → 模型（带工具清单）→ 若有工具调用：按策略检查 → 执行或挂起等确认 → 结果回填 → 继续；直到模型给出最终答复或触达上限。
- **系统提示**：一份经评审的 Bambook 业务说明（身份、可做/不可做、确认规则、引用来源的要求），加上当前账号、角色、当前所在业务对象等上下文。不提供“模式切换”。
- **上下文预算**：按 `context_window` 预留输出与工具清单空间；超出时先截短大工具结果（保留结构和引用 id），再把较早回合压缩成摘要（摘要用同一模型，低推理档位）。
- **取消与超时**：每轮有取消按钮，立即中止模型流和正在跑的工具；挂起的确认卡片随之作废。
- **检查点**：每步写入本机会话文件（JSONL），断电或重启后可看到历史并从最后一步继续；挂起中的确认在重启后需要重新确认。
- **不做**：子 Agent、并行工具风暴（同一步工具调用最多 4 个并行，且写操作串行）。

## 6. 工具目录（首批）

工具保持少而稳定，沿用 `query / get / expand / draft / execute` 的形状。

| 工具 | 用途 | 风险 | 确认 |
|---|---|---|---|
| `bambook.query` / `bambook.get` / `bambook.expand` | 查询客户、产品、订单、开发单、报价等（按账号可见范围） | 读 | 不需要 |
| `bambook.draft` | 生成某个 Mist 类型化命令的草稿（如新建开发资料、更新产品字段），展示差异 | 写草稿 | 不需要（只是草稿） |
| `bambook.execute` | 执行草稿 | 写 | 普通写：**同一表单 / 任务 / 业务对象的改动合并成一张确认卡片一次确认**；确认 / 删除 / 资金 / 对外：必须逐条确认 |
| `bambook.upload` | 把用户选定的本机附件上传到平台对象 | 写 | 每次确认，列出文件名和大小 |
| `mail.sync` / `mail.search` / `mail.read` | 本机邮箱同步与检索 | 读 | 不需要 |
| `mail.draft` | 起草回复 / 新邮件，存本机草稿 | 草稿 | 不需要 |
| `mail.send` | 发送 | 对外 | **必须逐条确认**，展示收件人、正文、附件 |
| `files.list` / `files.read` | 读用户授权文件夹内的文件（PDF、Office、图片识别文字） | 读 | 首次授权文件夹时确认 |
| `files.write` | 在授权文件夹内新建文件（不覆盖、不删除） | 本机写 | 不需要；覆盖需确认 |
| `docs.pptx` / `docs.docx` / `docs.xlsx` / `docs.md` | 生成 PPT、文档、表格、企划稿 | 本机写 | 不需要 |
| `web.fetch` | 抓取用户给出的网页 | 读 | 不需要 |

- `bambook.*` 的写入口就是 Mist 现有的类型化命令（约 333 种），不为 Agent 另开写接口；`bambook.draft` 只接受一份**白名单**里的命令，首批限开发资料、产品资料、客户资料、报价草稿相关；资金、发票、付款、审批类命令首批不开放。
- 工具结果带业务对象 id 和链接，答复里引用，页面可点开核对。

## 7. 权限与确认

三层，任何一层不通过都不执行：

1. **账号权限**：Mist 现有的 scope / 角色 / 工作区成员校验，原样生效。
2. **Agent 委托令牌**：工作助手不直接用用户会话令牌。启动时由用户会话向 Mist 申请短期委托令牌（如 2 小时，可续），带 `permissionCeiling = 账号 scope ∩ 工作助手上限`，并标记 `actorKind: 'agent'`、`sessionId`。服务端 `hasScope` 已遵守 `permissionCeiling`，新增部分只是签发接口和标记。
3. **高敏感动作由人执行**：确认、删除、资金、对外发送类命令，服务端**拒绝**委托令牌直接执行；Agent 只能产出草稿，用户在确认卡片上点“确认执行”，由渲染进程用**用户本人会话**提交。这样即使本机客户端被改动，Agent 也越不过人。

工作助手上限首批 = 读取类 scope + 白名单命令所需的写 scope；管理员可在系统设置里看到（不可放大到超过账号权限）。

## 8. 邮箱（本机）

- 用户在工作助手设置里添加邮箱（IMAP/SMTP，或常见服务商预设）；密码 / 授权码用 `safeStorage` 加密存本机。
- 邮件同步到本机邮件库（userData 下按账号分目录，SQLite 或 JSONL + 附件文件），只同步用户选定的文件夹和时间范围（默认近 90 天）。
- 邮件和附件**不上传**；只有用户在 `bambook.upload` 确认后，选定附件才进入平台对象。
- 与服务端现有邮件流程（`server/src/agent/email*Flow`）的边界：那是旧服务端 Agent 的托管邮箱，工作助手不依赖它；是否保留由后续单独决定。

## 9. 审计

- **本机运行日志**：每轮的指令、模型、工具调用（参数摘要）、确认记录、结果，用户可在会话里查看和导出；不上传。
- **平台审计**：凡经委托令牌或确认卡片落到平台的写入，服务端审计记录 `actor = 用户`、`via = 工作助手`、`sessionId`、命令和差异；与人工操作在同一审计表里可筛选。

## 10. 与平台 AI 的边界

| | 工作助手 | 平台 AI |
|---|---|---|
| 触发 | 业务员实时指令 | 系统固定流程 |
| 凭据 | 本人 API（OpenAI 兼容）/ 本人 ChatGPT 登录，存本机 | 统一平台连接（测试期用户订阅，生产期企业 API） |
| 运行位置 | 业务员电脑 | 服务端 |
| 数据 | 邮件、附件留本机；平台数据按账号权限读取 | 平台数据 |
| 写入 | 草稿 → 人确认 | 按各流程既有规则 |

工作助手可以调用平台 AI 的结果（如读取已有的报价审阅），但不能使用平台连接去跑自己的对话。

## 11. 清理旧嵌入

- 移除 `openbitfun:*` IPC、`bambookOpenBitFun` 桥、`tmp/openbitfun-*` 目录约定和相关脚本；`docs/AGENT_RUNTIME_ARCHITECTURE.md` §2.2 标注为历史记录并指向本方案。
- 服务端旧 Agent（`/api/agent`，Mist 独立服务未挂载）不在本方案内改动；其工具形状（query/get/expand/draft/execute）被沿用。

## 12. 分期与验收

| 期 | 内容 | 验收标准 |
|---|---|---|
| P0 骨架 | assistant-host 进程与资源守护、preload 桥、模型适配（OpenAI 兼容 + ChatGPT 登录）、Harness 循环、本机会话、工作助手页（会话列表 + 对话 + 设置） | 本人 Key 或 ChatGPT 登录可对话；取消、超时、崩溃重启可用；强制超限后进程重启且主窗口正常；凭据文件为加密内容 |
| P1 业务读 | 委托令牌签发、`bambook.query/get/expand`、引用链接 | 不同角色账号只能查到各自可见数据；令牌过期续签；越权查询被服务端拒绝（测试覆盖） |
| P2 草稿与确认 | `bambook.draft/execute`（白名单命令）、确认卡片、高敏感动作由人执行、平台审计 | 委托令牌直接调高敏感命令被拒；确认后写入成功且审计可查；拒绝确认后无任何写入 |
| P3 本机邮箱与文件 | IMAP/SMTP、本机邮件库、`mail.*`、授权文件夹、`bambook.upload` | 同步、检索、起草、确认发送全流程；未确认不发送；附件只在确认后上传 |
| P4 文档生成 | `docs.pptx/docx/xlsx/md`、上下文压缩 | 以真实业务数据生成可打开的 PPT 与企划稿；长会话压缩后仍能正确引用对象 |

进度：P0 骨架已完成（2026-10-15，见 LIVE-PROGRESS 检查点）；P1 起待开工。

每期：类型检查 + 单元测试 + `verify:mist`；页面浅 / 深色 × 1440 / 1180 / 390 截图检查；真实模型验收用用户本人的连接。

## 13. 用户确认结果（2026-10-15）

1. 首批白名单命令：开发资料、产品资料、客户资料、报价草稿；资金 / 发票 / 审批类首批不开放。
2. 普通写操作按**同一表单 / 任务 / 业务对象**合并为一张确认卡片一次确认；不同对象分别确认；确认 / 删除 / 资金 / 对外发送仍逐条确认。
3. 本机邮件默认同步近 90 天、收件箱 + 已发送，用户可调整。
4. 工作助手上线后下线服务端个人订阅接口 `/api/mist/ai/subscriptions*`，个人凭据不再存服务器。
5. 只接 OpenAI 兼容（Chat Completions / Responses）与 ChatGPT 登录，不接 Anthropic / Gemini 原生格式。
