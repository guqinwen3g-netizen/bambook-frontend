# AGENT BRIEF · 仅在 Mist Atelier 上开发

## 当前授权

2026-10-13 用户最终明确：项目只剩 Mist Atelier 这一套前端。把现成 Mist 成果当作当前产品的前端起点，在它上面继续接业务、扩全站。旧前端退役，必要时仅参考其业务功能和控制逻辑。

## 先定位

- 运行源码：`dev-ui-preview/mist-atelier/app/main.tsx`、`ReferenceApp.tsx`、`pages/*`。
- 共享系统：`components/mist/*`、`styles/mist/*`。
- 3001 与 3131 使用相同源码；根 Web/Electron 入口也只导入同一 Mist main。
- 先读 `01-principles.md` 与 `05-migration-playbook.md`，再按任务读对应页面源码和组件 API。

## 实施方式

直接在 Mist 原页面的数据、事件和导航槽位接真实业务适配器。适配器使用已有 services/API/数据契约，保留身份、权限、状态、准确版本/条目/批次、真实回执及返回；不包含旧 JSX/CSS，不导入旧 Manager 页面。

原参考页面、token、布局、排版、材质、组件和交互是锁定基线。没有对应页面时沿 Mist 页型与共享组件扩展。必要新业务内容按真实场景增加；不借接线重新设计已认可页面，不伪造数据或保存成功。

当前演示不是业务实现：邮件不属于 MVP，开发公差自动判断与生产拖列等行为须按有效业务规则替换。当前完成度以真实接口及页面验证为准，不将 35 项模块映射当作已完成页面。

禁止恢复“新外壳挂旧页面”“在旧 Manager 上换皮”“多个前端并行作为正式产品”的路线。旧文件只作业务参考，未完成分支不能用旧页面顶替。

## 验证

按实际改动运行 Mist 守门、类型/构建与必要的行为测试；对照原参考页查看同主题、同视口和同状态的实际截图。分开报告功能、交互、视觉及未完成范围。源码扫描、占位、导入或入口替换不能作为业务完成证据。
