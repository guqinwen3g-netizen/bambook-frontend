# 01 · 设计原则（Flat Frost）

这些是**硬规则**。`scripts/check-mist.mjs` 会机器检查其中大部分；其余在 [`06-qa-checklist.md`](./06-qa-checklist.md) 人工检查。

## 1. 零描边、零投影
- 卡片、输入框、按钮、选中项、表格行**不画边框、不加阴影**。
- 唯一允许的投影属于「浮起来的东西」：命令面板、抽屉、对话框、下拉菜单、Toast——**组件自带**，业务代码永远不写。
- 唯一允许的线：表头下方、KeyValue 行之间、Tabs 底线这种 1px `--mist-line` 分隔线——同样由组件自带。

## 2. 层级只靠填充深浅
从外到内：外壳渐变 `--mist-shell` → 画布 `--mist-canvas` → 卡片 `--mist-card` → 填充 `--mist-fill` → 凹陷 `--mist-sunken` → 强调浅色 `--mist-accent-tint*`。
- **选中 = 填充加深**（例如 ChoiceCards、Pipeline 当前项、表格选中行），不是加边框。
- **聚焦 = 加深 + 强调色浅底**，键盘聚焦才出现 2px outline（可访问性）。

## 3. 一屏一个主按钮
- `variant="primary"` 每屏最多一个，给「这一页最该做的那件事」。
- 其余用默认（浅填充）、`quiet`（文字）。危险操作用 `danger`，并且一定经过 `Dialog` 确认。

## 4. 颜色只表达状态
- 绿 `ok` = 完成/通过/已核销；黄 `warn` = 待处理/临近；红 `bad` = 逾期/失败/风险；蓝 `accent` = 进行中/当前；中性 = 其它。
- 状态色只用于小面积：`Pill`、圆点、进度条、`Banner`。**不允许大面积彩色背景。**
- 不要用颜色区分「类别」（客户、工厂、品类），用文字和图标。

## 5. 竹青与珠光彩色 = AI
- AI 文字与小控件保留竹青；小竹外壳和 AI 面板增加冰蓝、淡珊瑚与香槟，少量薰衣草仅作折射，不以紫色作为主体。
- 这些 token 只给：小竹、AI 建议（`AIBadge`、`Banner tone="ai"`、`Button variant="ai"`）、AI 简报。非 AI 功能不借用 AI 专属色。
- 成功仍使用 `--mist-ok*`，不以 AI 的竹青色代替完成或通过状态；品牌原色保持不变。
- AI 面板通过 `--mist-ai-surface` / `--mist-ai-panel` 叠加约 6%–20% 的分区色光，保持现有浅色与深色的明度层级。小竹使用专用冰蓝与珊瑚折射色，使小尺寸轮廓可辨，同时保留透明材质、白眼和高光。按钮、Pill 维持单色浅底，不使用高饱和彩虹或流动渐变。

## 6. 数字要轻、要对齐
- 大数字用 light（300）+ `tabular-nums`；单位用小一号的 muted 文字（`StatCard`、`SummaryBar` 已处理）。
- 金额、数量在表格里右对齐（`Column.align='right'`）。
- 编号（订单号、款号、发票号）一律 `<Mono>`。

## 7. 状态要齐全
每个数据区域都要有：加载（`DataTable loading` / `Skeleton`）、空（`EmptyState`）、无结果（`EmptyState` + 清除筛选）、无权限、出错（`Banner tone="bad"` + 重试）。参考 `?view=states`。

## 8. 交互约定
- 列表：单击行 = 预览（T2）或打开（T3）；双击 / 回车 = 打开详情。
- 详情页左上角 `BackLink` 返回列表；面包屑最后一级是编号（`Mono`）。
- 新建一律走 T9（分步 + 侧边步骤 + 底部吸附操作栏），表单不放在弹窗里（除非 ≤3 个字段）。
- 全局 ⌘K 搜索、⌘J 小竹。成功反馈用 `useToast()`，不用 `alert`。

## 9. 文案
- 中文为主，句子短，动词开头：「确认这一版」「去确认」「导入流水」。
- 页面说明一句话讲清「这页干什么」。空状态告诉用户下一步做什么。

## 10. 深色模式免费
- 业务代码**不写任何深色分支**（不许 `isDarkMode ? … : …`、不许 `dark:`）。全部用 token，深色自动成立。
