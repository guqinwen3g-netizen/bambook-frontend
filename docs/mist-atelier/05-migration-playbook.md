# 05 · 在 Mist Atelier 上继续开发

## 报价成本 AI 审阅操作协议（2026-10-14，quote-cost-advisor-v1）

### 模型连接（2026-10-15）

- AI 分两层：**工作助手**（本机运行、业务员本人 API 或 ChatGPT 账号，待立项）与**平台 AI**（报价审阅、汇总、对账、业务问答等固定流程）。平台 AI 只用平台连接，不用个人连接。
- 服务器设 `BAMBOOK_CODEX_SUBSCRIPTION=1` 后，管理员在“管理后台 → 平台 AI 模型”连接 ChatGPT 账号：点击连接 → 打开 `https://auth.openai.com/codex/device` 输入验证码 → 自动显示已连接。若提示未允许设备码登录，需在 ChatGPT 安全设置中开启 Codex 设备码授权。测试期所有同事的平台 AI 共用该订阅额度；生产期配置企业 API（`ARK_*` / `BAMBOOK_LLM_BACKUP*`），平台订阅失败时也回落到企业 API。
- 默认模型 `gpt-6-luna`；推理档位按功能：报价审阅 max、业务问答 medium、汇总 medium、对账 high（`BAMBOOK_PLATFORM_REASONING_<PROFILE>` 覆盖）。可用模型由 OpenAI 按账号与客户端版本下发，会变化；若返回“不支持该模型”，核对 `chatgpt.com/backend-api/codex/models?client_version=1.0.0` 中 `visibility=list` 的模型后调整 `BAMBOOK_CODEX_MODEL`。

### 边界与工作方法

报价前的产品 / 面料单价核算留在准确报价条目；订单与周期的实际成本 / 利润留在“成本与利润核算”，不把整个模块叫 BOM。AI 是可选审阅层，不取代专业公式、财务事实、人工决策或审批。

1. 业务员从准确报价条目进入三步核算，填写供应商成品价 + 明确未包含费用，或专业逐项拆解。数量、耗用单位、损耗、原币单价、费用范围、来源日期 / 有效期及包含条件必须有人工依据；每行整笔费用按准确行数量分摊。不自动填行业价格，不将参考成本当实际成本。
2. 第二步可人工选择并确认历史来源及差异处理，再勾选发送授权，请求 AI 审阅。未配置模型或没有权限时继续人工核算。未选择的其他报价、客户档案、联系人和附件正文 / 名称不发送；历史反馈只投影当前准确行相关现行事实，不包含附件 / 联系人 / 其他行。人工依据文本仍可能含敏感信息，发送前经办人负责核对，备用模型亦属于此次授权范围。
3. AI 只能指出依据、风险、缺口和本次策略。禁止按客户大小设固定加成，禁止凭未成交推定价格原因；缺少依据可不给策略。模型只返回受限 JSON 与授权来源 ID，不提供可执行工具，不直接返回可信价格 / 成本区间 / 接受概率。系统提示版本在 `server/src/mist/quoteCostAdvisor.ts`，结构契约在 `server/src/shared/mistQuoteCostAdvisor.ts`。
4. 服务器校验授权主体、模块权限、空间版本、准确报价 / 行目标、未提交草稿、币种 / 单位、本行分母、供应商和人工历史来源。成本及建议价格用既有定点公式重算；无效 JSON、幻造来源、越界比例拒绝。普通模型文字仍是待核对判断，不保证专业正确性。
5. 人工点击“采纳至人工策略草稿”仅填本次加成 / 毛利目标和注明 AI 参考的人工理由；**不改人工拟报价，不执行业务命令**。修改输入、空间、会话或版本后取消旧请求并清除旧建议 / 授权；最终需人工填拟报价、独立勾选写入范围、保存快照并经原业务审批。保存与审批仍走原契约，历史不覆盖。

### 管理员模型接入（仅服务器，不能把 key 写到浏览器 / 仓库）

复用现有 `server/src/ai/llmProviders.ts` 的 OpenAI 兼容网关，不另建模型 runner。GPT / DeepSeek 可作为一组兼容 provider：服务器环境设置 `BAMBOOK_LLM_BACKUP_URL`（OpenAI 通常 `https://api.openai.com/v1`；DeepSeek 通常 `https://api.deepseek.com/v1`）、`BAMBOOK_LLM_BACKUP_KEY` 和 `BAMBOOK_LLM_BACKUP_MODEL`（须填该账号实际开通的模型标识）。URL 不含 `/chat/completions`。凭据通过部署环境的秘密管理注入，不提交 `.env`、不让用户在聊天贴 key。备用 URL + KEY 必须齐备；若主 provider 已配置，仍先尝试主 provider，再备用，**不能把配置列表第一项当成实际成功调用模型**。

现有主 provider 保持 ARK 等旧 key 语义，`BAMBOOK_MODEL_BASE_URL` / `BAMBOOK_MODEL_NAME` 仍有效；可用第二备用 `BAMBOOK_LLM_BACKUP2_*`。没有配置时明确503；订阅到期 / 模型未开通、失败、超时和取消显示真实错误，不返回原始 provider 错误或 key。状态 `GET /api/mist/workspaces/:id/assistant/status` 只读配置；专用 `POST /api/mist/workspaces/:id/quotation-cost-advisor` 是只读端点，不属于 commands。

上线前由管理员核对第三方数据使用 / 保留政策、模型权限与计费；用非敏感软件测试依据做真实接通验证，再进行专业人员场景复核。当前本批自动及浏览器验收使用明确模拟 provider 传输 / 测试数据，**没有真实 GPT / DeepSeek 或行业行情调用，不等于实连、准确性、生产就绪**。

### 当前缺口与后续批次（不能因为界面可用就标成全部完成）

- 模型建议暂不作为独立服务端签名 / 持久化审计记录；人工采纳仅保存人工策略文字，不能信任客户端模型标签为服务端证明，实际 fallback 模型未记录。
- 行业参数 / 原料价格接入、结构化税费 / MOQ / 跨单位和汇率、专业面料 / 成衣校准、完整可比检索及个性化价格区间，仍需真实证据源和独立批次；不生成虚构行业参考或成交训练标签。
- 实际收入确认、费用归属与跨行 / 订单 / 周期分摊、真实经营利润、银行与应付账套仍是另一条业务链，不由 AI 建议补齐。
- 本批验收 / 云端检查 / main 状态以 PR #8 和实时进度实际回执为准，开发检查点不等于合入完成。


## 2026-10-17 智能邮箱真实收发批次（P1）

- **接入与凭据**：页面“邮箱账号”抽屉接入邮箱。个人邮箱 `emails:write` 本人接入、仅本人可见；共享邮箱需 `emails:admin`，可见范围 = 接入人 + 所选工作空间成员（按用户 ID）。只有接入人能改设置 / 凭据；改服务器、端口、加密方式或用户名后需重新绑定。绑定时先真实登录 IMAP 与 SMTP，成功才保存；凭据存服务端私有目录（`MIST_MAIL_CREDENTIAL_DIR`，默认 `server/private/mist-mail-credentials`，目录 0700 / 文件 0600，可选 `MIST_MAIL_CREDENTIAL_KEY` 做 AES-256-GCM），不进入工作空间数据、不回显、不入库。
- **收信**：手动“同步”按 账号 + 收信来源代际 + 文件夹 + UIDVALIDITY + UID 增量（每文件夹每次 100 封），只同步 INBOX / 已发送 / 归档；UIDVALIDITY 重置或本系统发出的邮件回到“已发送”时按 Message-ID 合并，不重复。收信来源 = 邮箱地址 + 收信服务器 + 端口 + 加密方式 + 登录用户名：任一项变化，账号 `sourceGeneration` +1 并清空文件夹游标，新来源从 UID 1 重新同步；去重与 Message-ID 合并只在当前代际内（邮件 `source` 字段），旧来源已同步邮件保留不改。只改发信设置需重新绑定凭据，但不换代际、不重置游标；只改显示名 / 签名 / 别名 / 成员无需重新绑定。同步期间来源被改，旧代际的写回整体作废（`email.server.sync.source` 不匹配即拒绝）。附件存为私有文件（>50 MB 只记录不保存）；部分文件夹失败保留上次结果并显示失败文件夹与原因。
- **发信**：先持久登记发送记录（requestKey 幂等，同一次编辑重点“发送”不重复投递），再经 SMTP 投递。发送记录按收件人（`recipients[]`：地址、收件 / 抄送 / 密送、`pending / accepted / rejected / failed / unknown`、服务器原文）记录结果，整封状态由此推导：全部接受 → `sent`；部分接受、其余被拒或未送出 → `partial`（仍在“待发送”，可“仅重发未接收的收件人”）；无人接受 → `failed`；存在无法确认 → `unknown`。重发的 SMTP 信封只含尚未被接受的收件人，已接受者不会收到第二封；同一 Message-ID，已发送副本与远端“已发送”只在第一次有人被接受时生成 / 写入一次，副本页如实列出已接受与未接收者。不确定（投递中断、无答复、超过 5 分钟仍在发送）→ 不自动重发，先“核对”（只查发件账号自己的收件箱 / 已发送 / 归档，按 Message-ID）：找到副本只有在待确认收件人全是本邮箱自身地址时才确认，否则仅记“本邮箱有副本”，其他收件人仍待确认；再由人确认未送达后重发。“已接受”只表示发件服务器收下，不代表对方最终收到。回复带 In-Reply-To / References，转发可带原附件，密送不写入信头。
- **边界**：客户端不能调用 `email.server.*` 命令；邮件、草稿、发送记录、附件、相关事件 / 待办 / 通知 / 日历按邮箱可见范围裁剪。核对不读取其他邮箱账号；不以登录收件人邮箱作为发送成功判据。服务器策略：`MIST_MAIL_ALLOWED_HOSTS`（设置后严格白名单，未设置时端口限 143 / 465 / 587 / 993）、`MIST_MAIL_INSECURE_TLS_HOSTS`（仅内部自签证书主机）、`MIST_MAIL_ALLOWED_RECIPIENT_DOMAINS`（设置后限制收件域名，用于内部测试防误发外部）。示例邮箱不连接服务器、不能发送。
- **未完成 / 待授权**：跨账号真实互发与共享邮箱授权的真实验收，需要用户确认具体测试邮箱与读取授权后再做；状态以对应 PR 为准。
