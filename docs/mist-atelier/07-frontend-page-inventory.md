## 0. 本轮边界

- **前端先行**：所有菜单页与菜单外节点都要有完整的 Mist 页面：列表 / 详情 / 新建编辑 / 状态页，按钮都有明确的交互结果。
- **数据只用工作空间**：读写走 `/api/mist/workspaces/:id`（状态）与 `/commands`（命令 + 回执）。示例空间（`seed:"demo"`）提供标注清楚的示例记录；空白空间显示真实空态。
- **没有后端能力的动作**：按钮保留但禁用，旁边写明原因和解锁入口（例如“该邮箱尚未接入发信服务 · 管理后台 › 邮箱账号”）。**不做假成功、不伪造数量或回执。**
- **参考页锁定**：我的工作、开发与寻样（列表/新建/详情）、订单（列表/新建/详情）、生产进度、财务核销、客户、日历、设置、登录、状态页、设计系统 —— 只在原构图里增加必要的业务内容，不改布局、token、排版与材质。
- **深度链路后置**：真实 IMAP/SMTP、审批路由引擎、正式账套、外部门户等，本轮只做前端与工作空间内可验证的交互；后续再逐条做端到端核验。

## 1. 全站设计规则（每页都适用）

### 每页完成标准

1. **功能**：页面上的数据都来自工作空间；每个按钮要么执行命令并显示真实回执，要么禁用并写明原因。
2. **交互**：列表 ↔ 详情往返保留上下文；阶段推进、校验提示、不可逆操作的确认弹窗都可用。
3. **视觉**：浅/深 × 1440 / 1180 / 390 截图（列表、详情、新建、空态），无横向溢出；`npm run mist:check` 0 / 0。
4. **测试**：关键交互有组件测试；`npm run verify:mist` 全绿。

## 3. 批次 1 · 订单履约

### 3.1 样品仓库 `samples`（CAP-samples-01..03 · 09 开工方案）

- **谁用**：业务员（登记、借出、寄出、归还、移位）；其他岗位只读。没有样品管理员。
- **首页**：标题 → 操作区（刷新、新建样品）→ 类别入口：面料 / 成衣 / 其他 → 检索（关键字、形态、来源、状态；同组多选 OR、不同组 AND）→ 结果。
  - 面料按**档案**一行：档案号 + 名称 + 缩略图、来源（开发版本 / 订单条目 / 手工）、**每种形态一行余额**（“米样 12.5 米可用”“色卡 3 份可用”）、位置摘要、最近流转。
  - 成衣按**每件实物**一行：实物编号、尺码颜色、来源版本或订单分支、位置（空值写“位置未记录”）、在库 / 借出中 / 已寄出。
- **档案详情**（右侧卡，T4 结构）：身份卡（产品码 / 供应商码，或开发案·轮次·工厂·版本）→ 形态库存表（形态、总量、已借出、可用、单位、位置）→ 照片与属性 → 流转记录（倒序，含数量、去向、经手人、来源单据）。成衣明确区分“产品图”和“本件实物照片”。
- **新建 / 补录**（T9 两步）：类别与来源（可选关联开发版本或订单条目）→ 形态、数量、单位、位置、照片。来源同步生成的档案只能补充，不能改来源字段。
- **流转**（Dialog）：借出（借给谁、预计归还）、寄出（不归还，收件方与运单号）、分次归还、移位。数量不得超过可用量；单位跟随形态，不可改。
- **状态**：首次空态“还没有样品档案”；筛选无结果；无写权限只读。

### 3.2 订单管理 `orders`（R，补内容 · CAP-orders-01..05 · 12 开工方案）

保持现有列表 / 新建 / 主单详情构图，补齐：

- **新建菜单**：手工新建、从报价转单、从开发版本转单、从产品档案复购；都进入同一份草稿，来源显示在草稿顶部。
- **列表**：板块（成衣 / 面料）在 Tab 之上；每单显示各条目独立阶段条和阻断标记，不用整单百分比掩盖差异；待业务动作、QC NOK、待出运条目数。
- **条目履约详情** `orders/detail` + `orderLineId`：顶部固定订单、客户、PO、规格、数量 / 尺码、履约模式、工厂分支；下方水平阶段轨迹（成衣：产前样 → 面辅料 → 开裁 → 生产检验 → 完工登记 → 出运；面料：坯布 / 染整 → 色样确认 → 生产检验 → 完工 → 出运），遵守 G5。
- **变更**：正式订单的商业修改走“变更申请”（原值 → 新值、原因、影响条目），审批后生效；冻结状态只读。
- **分批与尾数**：出运累计、短溢装、尾数收口（“按实际完工结案”需写原因），与财务结算分离显示。

### 3.3 QC 工作台 `qc-workbench`（P · CAP-qc-workbench-01..04 · 11 开工方案）

- **谁用**：面料 QC、成衣 QC；授权分派人；业务员只发起和读回。
- **板块入口**：两张入口卡“面料 QC”“成衣 QC”，各显示待处理样品数、未结生产检验分支数、NOK 待恢复数。不做混合总表。
- **板块工作台**：顶部切换 `样品评审` / `生产检验`；任务**按工厂与检查地点分组**（待办条数、最早检查日期、地址联系人），展开看任务卡（来源单号、准确版本或订单条目 / 分支、类别、发起人、状态）。看板视图保留为可选。
- **样品评审详情**：来源与送审实物（只读）→ 现场信息 → 报告（尺寸测量表、外观、结论 认可 / 需修改 / 不采用）→ 附件 → 历史报告 → 当前门禁状态。
- **生产检验详情**：准确条目 / 工厂 / 产线 / 批次 → 持续检查时间线 → 当前记录（检查量、抽检量、缺陷分级、结论 OK / NOK）→ NOK 后的暂停、复验、恢复。
- **第三方测试**：送检机构、项目、样品、预计出报告日；报告上传后由 QC 判读。
- **动作**：认领、转交（写原因）、改期、提交报告（确认弹窗）。QC 结论**不替来源模块推进业务**，只解锁来源的下一步。

### 3.4 生产进度 `production-board`（R，补内容 · CAP-production-board-01..03）

- 卡片以**订单条目 × 工厂分支**为单位；列为业务阶段，不允许拖动越过门禁（拖动时提示缺什么）。
- 补：产前样确认与开裁确认（需 QC / 客户确认依据）、延期（新日期 + 原因 + 是否已告知客户）、异常暂停 / 恢复（原因、责任方、恢复条件）、在手订单汇总条。

### 3.5 采购管理 `procurement`（G → 重做 · CAP-procurement-01..04 · 14 开工方案）

- **谁用**：面料 / 成衣业务组的实际经办人；适用审批人；QC 做来料检验；财务做付款。
- **工作台**：两个不可合并的入口 `采购订单` / `委外加工单`；每个入口视图：需求草稿 · 待审批 · 已批准待供应商确认 · 供应履约中 · 已完成；按最近到期、异常优先排序。
- **列表列**：单据号、业务组、供应商、币种、付款条件、交付地点、要求交期、来源订单行数、审批状态、供应商承诺日、累计交付 / 回交、差异标志。
- **新建**（T9）：选择来源订单行需求（兼容需求可合单：同供应商、币种、交付地点、付款条件）→ 供应商与条款 → 明细（物料、规格、数量 + 单位、单价、交期）→ 复核提交审批。也可手工新建。
- **单据详情**（T5）：阶段轨迹 审批 → 供应商确认（上传对方盖章原件）→ 分批交付 / 加工回交 → 验收 → 对账 → 付款申请（交财务）。委外加工单另有“原料交接”（发出原料、数量、损耗、余料归还）。
- **门禁**：未批准不能发供应商；供应商确认后修改走变更；来料不合格进入退换。

### 3.6 库存与仓储 `inventory`（P · CAP-inventory-01..04）

- **谁用**：对应业务组成员按实际经手操作；没有独立仓储岗位。
- **首页**：汇总卡（可用、已预留、质量冻结、在途）按单位分开；库存表：物料 / 产品、批次 / 缸号、仓库与位置、**货权**（公司 / 客户 / 供应商）、质量状态（待检 / 可用 / 冻结）、数量 + 单位、预留给哪个订单条目。
- **库存条目详情**（T4）：事实卡 → 当前可做的动作 → 流水时间线。
- **动作**：入库（来自采购交付 / 退货）、出库（发工厂供料 / 出运）、预留与释放、调拨、盘点（差异需原因）、质量冻结 / 解冻（依据 QC 结论）、工厂直发登记（不经仓）。

### 3.7 货运管理 `shipments`（P · CAP-shipments-01..05 · 10 开工方案）

- 对话整页：回答带来源；建议的操作以卡片呈现，需人工确认后执行并显示回执；长任务有进度与恢复。未配置模型时明确显示“未配置”。

### 6.7 人事管理 `hr`（G → 重做 · CAP-hr-01..03）

- Tab：人员（入职 / 转岗 / 离职）、组织团队（树形）、考勤请假（申请 → 审批）、绩效培训、薪资（仅授权人可见，批次工资）。员工本人只看自己的。

### 6.8 业务工具 `business-tools`（G → 重做 · CAP-business-tools-01..02）

- 入口卡网格 → 各工具页：面料计算（克重 g/m² ↔ oz/yd²、米 ↔ 码、按门幅与克重换算 米 ↔ 公斤）、汇率换算（引用定价参数版本）、导入导出工具（转到数据中心正式入口）。

### 6.9 管理后台 `admin-panel`（P · CAP-admin-01..03）

- 分区：用户与角色、操作权限与数据范围、审批路由与预授权、审计日志、编号规则与印章、字典、**邮箱账号**（见 4.1）、运行与备份（只读状态）。

### 6.10 设置 `settings`（R · CAP-settings-01..03）

- 个人（账户、偏好、登录退出）、公司档案与规则字典、通知订阅与通道失败回执；新增“邮件签名”。

### 6.11 审批与放行 `approvals`（N，菜单外 · workflow / release）

- 入口：我的工作待办、顶栏。列表：待我审批 / 我发起的 / 已处理；类型：订单审批、报价偏差、采购审批、付款申请、生产与出运放行、索赔方案、受控例外。
- 详情：被审对象的准确快照（版本 / 条目）、适用规则版本、发起人与理由、依据（QC / 财务）；动作：批准、退回（理由必填）、转交；历史。

### 6.12 通知中心 `notifications`（P，菜单外）

- 顶栏抽屉（已有）+ 全部通知页：未读 / 类型筛选、全部已读、直达对象；订阅设置跳到设置。

### 6.13 统一搜索 `search`（P，菜单外）

- 命令面板（已有）补对象搜索（开发案、订单、客户、样品、邮件），只返回有权查看的结果；“查看全部结果”进入结果页，按模块分组。

### 6.14 外部边界（本轮不建页面）

- 客户门户、供应商、承运人、银行、检测机构都是业务参与方，不混入员工角色；本轮由内部经办人登记对方确认与原件。UI 研发工具不属于产品。
