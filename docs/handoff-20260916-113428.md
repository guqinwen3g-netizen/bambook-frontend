## 四、本轮新踩的坑（接上轮 9 条，共 14 条）

10. **不存在"两个库"**：`server/.env` 与 `server/.env.local` 的 `DATABASE_URL` 完全相同
    （都指向 `panda_hub_local`）。别再花时间"补第二库迁移"。
11. **服务端全量 vitest 的失败数是浮动的**（同一份代码 4 例 → 9 例）。判定流程必须是：
    ① **隔离复跑单文件**（绿 = 并发偶发）；② 仍红 → `git worktree add /tmp/x HEAD`
    + symlink 根/server 两个 `node_modules`，在干净 HEAD 上复跑同一用例，才能定性"不是我这批引入的"。
12. **硬编码未来日期的测试用例 = 时间炸弹**：`orderChangeRequestService.test.ts:289` 写死
    `'2026-09-15'`，服务要求"不早于今天"。同类硬编码在 `shippingLock.regression.test.ts:109,203`、
    `internalTransferService.test.ts:335` 等处还有（只是那些不校验未来性，暂不红）。
    修法建议：改成相对日期（`today + 30d`）。
13. **`.mjs` 验收脚本别在顶层函数和内部函数重名**：我写了 `const rollback = …`（内层）+ 
    `async function rollback`（内层）+ 顶层 `rollbackAll`，直接
    `SyntaxError: Identifier 'rollback' has already been declared`。脚本只保留一个回滚函数。
14. **源码计数类契约钉在新增同类代码时必须同步上调，且要证伪**：
    `shipmentGateBlockedContract.test.ts` 钉的是"`reportError(error);` 出现 3 次"，我新增陆运段
    catch 后变 4 → 必须改成 4（并**证伪**：临时改回 3 会转红，证明钉子非空转）。
    这类钉子"放宽"前一定先证伪，否则等于悄悄拆了守卫。
