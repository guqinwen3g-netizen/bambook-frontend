## 二、⚠️ 没做的 4 项（逐项证据 + 理由）

### 1. 发票「只填号 + 金额」的孤儿创建 —— 不做，**硬依赖 T2**

- 现状：`handleSaveInvoice` 只校验 `invoiceNumber` + `amount`（`components/FinanceManager.tsx:1058`），不要求任何来源锚点。
- **为什么不摘**：T2（H14 发票锚定运单/报关 + 品类派生）**还没做**。此刻强制要求来源，等于在锚定能力建好之前把开票通道整个堵死 —— 一张票都开不出来。
- 处置：**挂在 T2 名下**。T2 完成后，摘发票孤儿入口应当是 T2 批次内的收尾动作（那时"要求来源"才有可选项可填）。

### 2. 现货状态 / 现货数量两个字段 —— 不做，**它不是入口级改动**

- 现状远不止两个输入格（原判断偏窄），它是贯穿产品档案的一整套属性：
  - 表单输入格 `components/ProductsManager.tsx:2634-2644`（`stockStatus` / `stockQuantity` / `stockUnit`）
  - **列表列**显示 `:360`、`:364`
  - **完整度检查** `:1422`（`{ label: '现货状态', ok: hasText(profile?.stockStatus) }`，`:2098`）
  - 详情页显示 `:3984-3985`
  - profile 构造 `:1587-1589`、`:1725-1727`
  - 状态文案 `:1253-1254`、`:1374-1375`、`:2045-2046`
- **为什么不摘**：摘掉输入格后 `:1422` 那条完整度检查**永远不达标**，会在产品完整度上留一个永久缺口 —— 制造新问题，不是消除假象。
- 业务方口径（2026-09-16）：「产品档案相当于一款产品的所有信息、所有详情」，现货数量**理想态是由库存关联显示**，而不是在产品档案上手工填。
- 处置：**登记为独立待办**（见 §五-1）——「产品档案的现货字段改为由库存关联的只读显示」是一个**新功能**（要接库存取数），不属于「摘入口」。

### 3. MES 精细部分 —— 不做，**已核实不是想象中的那个东西**

- 已核实 `components/MesManager.tsx` 承载的是**生产计划 + 委外加工**（`:80-112` 工位/状态枚举），
  `components/moduleRegistry.ts:535` 是它的模块入口。
- 委外是**真实在跑的业务**：`scripts/acceptance-req2-05.mjs` 是工序级委外链的实机验收脚本
  （坯布织造 → 染整 → 后整理，含累计损耗与加工费聚合）。
- 矩阵拍板的是「MES **精细管理**（耗料 / 流水线监控）不做」，**不是**「生产计划与委外不做」。摘掉 MesManager 会误伤真实业务。
- **MES 孤岛事件**（`server/src/mes/mesService.ts:583-592`、`:1191-1200`，`publish({...} as any)`，类型不在总线联合里、零订阅者）：
  已核实只有自身 + 测试在引用（`mesService.test.ts:272-273`、`:512`）。
  但 `publish` 是**副作用**（业务数据照常落库），删它**没有任何业务收益**，却要动服务端 + 改测试。
  handoff 原话是「摘入口即可，**不接订阅**」—— 意思是不为它接订阅者（本批确实没接），不是删 publish。
- 处置：**不动**。若要清理，应作为「事件总线卫生」独立小批，与业务验收无关。

### 4. CommandPalette 死入口 —— 未定位到，**不能凭空摘**

- 已核实 CommandPalette **本身在用**：`App.tsx:171` import、`:1502` 挂载、`:1574` 传 `onOpenCommandPalette`；
