## 1. 工作方式（不可妥协的部分）

- **三层对齐 + 批次化**：每批 = 定向现状核准 → 设计 → **口径拿不准必须弹窗问业务方（不擅自发挥）** → 实现 → 门禁全绿 → 落账（feat + docs 成对 commit）。

## 2. 业务口径（§10 已定案，勿再问业务方）

- 业务骨架 = **单据生命周期网**（不是三条单向链）；连通性 = 跳转 + 联动 + 单一真源三者缺一不可。
- v1 上线零缺口 = 主线单据网 + 财务四件全量 + 主数据 + 客户门户 + **全部周边模块**（HR/营销/风险/驾驶舱/库存/日历/数据中心）+ QC 全程参与 + 全套自制单据（产地证除外）。**v2**：AI Agent、邮箱域、Dashboard、知识库。**不做**：供应商门户、产地证。
- 结案绿 = 全额核销自动判定；回款认领双通道；双币种+汇兑入利润；PP 样门禁 = 硬拦截 + 老板特批（已落地，见下）；**放行无双签 = 领导单签**（工厂不在体系内——组织现实，勿按 DR-053 双签理解）；封样 = 物理留存登记（大货也封样，确认→才可封样，不承载放行语义）；空库从 0 上线；账号 = 管理员建号 + 邮箱验证码双通道；通知中心必交付。
- 角色 = 六角色 + 三档数据范围（自己/团队/全部）+ 按单分配兜底（§10.4）。

## 5. 工程陷阱（接班人踩过的坑）

- **Bash 工作目录会漂移**：长会话中 `cd` 残留会导致相对路径写错位置（本轮曾把改动写到错误路径后重做）。**多文件 python 改写一律用绝对路径或先 `cd` 到仓库根并显式校验**；改完必须 `npx tsc --noEmit` 验证。
- `ls`/`grep` 输出偶尔被截断呈现——结论前用 `wc -l`/精确 grep 复核（曾有"文件不存在"的误判）。
- `docs/` 真源文档在 git 与工作区均正常（曾有误判称 Unicode 分裂——不存在）。
- 后端 `npm run dev` 是 ts-node 无 watch：改代码后需手动重启 8081 才生效。
- 邮箱域暂缓 ≠ 无邮件通道：验证码注册依赖最小邮件发送能力（§10.3-10），实施账号批时核对 SMTP 现状。
