# D7 · 仓库归属（货权标记 + 样品↔大货转化通道）—— 定向现状核准（2026-09-16）

> 矩阵 D7 拍板（`docs/业务变体矩阵-2026-09-16.md:247-273`）分**两块**，本文逐块核准。
> 本文只做核准 + 设计建议，**未动代码**。D7 此前在 handoff 里一直标为「挂起」。

## 一、拍板原文（两块）

1. **两套库存不统一，但必须加「转化通道」**
   - 理由：样品侧有**借出/归还/封样**语义；大货侧有**数量/锁定/单位/成本/预警**语义。强行合并会让借出归还污染大货账。
   - 通道要承载三类动作：**米样裁剪后给客户 / 米样转大货 / 米样转售**，
     记录**来源样品、转化数量、损耗、余量退回、目标对象**，并生成**双侧流水**（样品侧减、大货侧增或应收侧增）。
   - 与 D6 是同一件事的两端：**D6（米样 Decimal 长度口径）是前提，转化通道是出口**。
2. **第三方仓/货代仓要区分货权**
   - 新增仓库类型 + 货权标记，区分「货在第三方仓但我方货权」与「货权已转移」。
   - **影响口径**：资产/存货报表必须**按货权**而非按物理位置汇总——货权已转移的货不得计入我方存货。
     （与 D2-Q4「CIF 垫付运费改开应收」同属一处原则：**账按权利义务记，不按物理位置记**。）
   - 与 D4 联动：先进第三方仓再发的路径，出仓扣库存的前提是**该仓的货我方有货权**。

## 三、⚠️ 两个容易踩的混淆点（核准时发现）

### 混淆点 1：「转大货」在系统里**已经有一个同名但语义完全不同**的功能

`server/src/development/convertService.ts` 里的「转大货」是 **开发案 → 大货订单**的**业务转单**：
- `:207` 「仅已确认（approved）的开发案可转大货订单」
- `:209-217` DR-050/051 强制建档后转（`ASSET_REQUIRED`）
- `:240` 「转大货订单必须填写数量」「必须填写交期」
- `notifications/notificationTemplateEngine.ts:173` 通知文案「样品 {caseCode} 转大货成功」

**这是「案子转订单」，不是「米样实物转大货库存」**。D7 要的转化通道是**库存层面的量转移**
（样品侧长度/张数减少 → 大货侧库存增加）。**实现时绝不要复用/改动 `convertService`**，
两者名字像但域不同。

### 混淆点 2：「货权」在系统里**也已经有实现，但在另一个域**

`server/src/credit/bankruptcyService.ts` = **REQ2-15 客户破产货权处置（DR-055）**：
- 双表 `BankruptcyProceeding` + `BankruptcyAction`（append-only：`declare / resale / return_shipment / bad_debt / recover / close`）
- 设计真源 `docs/design/04-模块设计/05-财务与结算/客户破产货权处置.md`
- 净损失 = 申报债权额 − 转卖回收 − 部分回款 + 退运成本

这是**对客户的债权/货物处置**（客户破产了，货怎么办），
与 D7 的「**仓库存货归属**」不是一回事。**不要把它当 D7 的已有实现**，也不要改动它。

## 四、现状载体对照（实现时的落点）

| 侧 | 模型 | 关键字段 | 已有流水 |
|---|---|---|---|
| **样品侧（张数口径）** | `SampleCardItem` | `quantity` / `availableQty` / `minStock` / `maxStock` / `unit`（默认「张」）/ `warehouseId`（软关联 Warehouse）/ `location`（架位文本）/ `status`(in_stock\|borrowed\|shipped\|retired) / 封样四字段 | —— |
| **样品侧（长度口径，D6）** | `Sample` + `SampleLengthMovement` | `Sample.lengthQty/lengthUnit`；SLM `type`(set\|cut\|give\|return\|loss\|borrow_in\|borrow_return) / `quantity` / `counterpartSampleId` / `balanceAfter` | ✅ 已有 |
| **大货侧** | `InventoryItem` + `StockMovement` | `quantity` / `lockedQuantity` / `unit` / `unitCost` / `minStock` / `maxStock`；**单一写入口 = `createStockMovement`**（T3 已确立，严禁绕过直改 quantity） | ✅ 已有 |
| **仓库** | `Warehouse` | `type`(Main\|Auxiliary\|Temporary\|Virtual) / `code` / `isActive` / `sortOrder` | —— |

**两套库存确实互不相通**（矩阵判断成立）：样品间也是一个 `Warehouse` 行，但样品库存记在
`SampleCardItem` / `Sample.lengthQty` 上，**不进 `InventoryItem`**。

## 五、设计建议（待拍板后实施；本批只核准）

### ① 转化通道（建议拆两个动作，复用 D6 的台账范式）

新增 `SampleConversion`（或扩 `SampleLengthMovement.type`）承载：
- `to_bulk`：**米样转大货** —— 样品侧 `SampleLengthMovement` 减（新 type），
  大货侧经 `createStockMovement` 增（`referenceType='Sample'`，与 T3 的 `'Order'`/`'Shipment'` 并列）；
  记录**来源样品 / 数量 / 损耗 / 余量退回 / 目标 InventoryItem**。
- `to_resale`：**米样转售** —— 样品侧减，**应收侧增**（走既有 `BillingItem`/发票通路，不新建收款通道）；
  记录来源样品 / 数量 / 金额 / 客户。

**关键约束**：
- 样品侧必须走 D6 的 `SampleLengthMovement`（**单一写入口**，同 T3 对 `StockMovement` 的要求）；
- 大货侧必须走 `createStockMovement`（**严禁绕过直改 `InventoryItem.quantity`**）；
- **双侧同事务**（一边失败整体回滚），避免"样品扣了但大货没增"。

### ② 货权标记（新增字段 + 存货报表）

- `Warehouse` 新增 `type` 取值 **`ThirdParty`（第三方仓）/ `Forwarder`（货代仓）**；
- 新增货权标记：建议放 `InventoryItem`（**货权是"这批货"的属性，不是"这个仓"的属性**——
  同一个第三方仓里可能既有我方货权的货、也有已转移的货），
  如 `ownership: Owned | Transferred`（或 `custodyType`）；
- **新建存货报表**（现在根本没有）：按 `ownership` 汇总，`Transferred` 的**不计入我方存货**；
  数据集注册进报表引擎（`reporting/datasets.ts` 的 datasetKey 白名单）。

**⚠️ 工作量提示**：② 里的"存货报表"是**从零新建**（报表引擎现有 7 个数据集没有 inventory），
不是改现有报表——**这块比拍板时预估的要大**。

## 六、❓ 待你定

1. **先做哪一块**？① 转化通道（依赖 D6，已就绪）与 ② 货权标记（要动 schema + 新建报表）
   彼此独立，可分批。**我建议先 ①**（D6 已铺好前提，规模小、闭环完整）。
2. **货权标记放哪**：`InventoryItem`（我的建议：货权是"货"的属性）还是 `Warehouse`（矩阵原文写的是
   "新增仓库类型 + 货权标记"，读起来像放在仓上）？—— 我倾向 `InventoryItem`，因为**同一个第三方仓
   里可能同时存在我方货权与已转移的货**；放仓上表达不了这种混合。
3. **"米样转售"的应收侧**：走既有 `BillingItem → 发票` 通路对吗？（不新建收款通道。）
4. **损耗与余量退回**：转大货时若样品有损耗，"损耗"是否也进大货成本？（还是只记数量差、不进成本？）
5. ② 的存货报表要不要**同时纳入 Dashboard/驾驶舱**（现在驾驶舱有毛利/回款，没有存货）。
