### D4 佣金/中间商的订单应付闭环（`67136a86`）
- 实测：佣金在**定价侧**算得很细（`PricingCalculation.commissionRate/commissionAmount` + `CommissionRule`
  + `commissionRuleId` 追溯），但**只算不收** —— 没有任何地方能回答「这张单欠中间人多少佣金、开了没、付了没」。
- 修法（**零 migration**）：佣金应付 = **给中间人开一张应付发票**（`Invoice{type:'Payable'}`）⇒
  立刻进入既有 **AP 账龄 / 付款凭证 / 供应商对账单**链路 = 真正的闭环。
  为什么不建 `OrderCommissionPayable` 表：① 应付这件事本仓已有模型，再建一张会「同一笔应付两处记」
  ② 生产已 28 条待迁移。
- 真源 `pricing/commissionPayableService`：**只算已确认的定价行**（草稿不是承诺）；缺数量的行**不按 1 顶替**；
  **多行归属不同中间人 → 不猜**（返回 null + issue 要人工处理）；开票复用 `createInvoice` 真源。
- ★★ **真库演练抓出一个真死锁**：`Invoice` 有 `@@unique([sourceType, sourceId])`（**不排除 Cancelled**）⇒
  若锚点直接用 `orderId`，「开错票 → 作废 → 重开」会撞唯一键 ⇒ **再也开不出来**
  （而"金额算错了要重开"是真实需求）。已把锚点改为 `<orderId>#<序号>`：
  既能按前缀查出该订单全部佣金票（含历史作废票，可追溯），又让重开拿到新锚点 ⇒ **出口存在**。

### C6 寄售/在途库存（`43155359`）
- 实测：`InventoryItem.ownership` 只有 `Owned`/`Transferred`，而面料外贸有两类**货权仍属我方、
  但不在自己仓里**的货无处可标：**寄售**（货在客户/海外仓，卖出才结算）、**在途**（已发运未到货）。
  标不出来的后果二选一都是错账：塞进 `Owned` ⇒ 我方存货虚高且看不出"能不能马上用"；
  塞进 `Transferred` ⇒ **我方存货静默少算**。

    Owned/Consignment/InTransit 计入，Transferred 不计入；**未知档位按不计入**
  - 汇总新增 `ourStock`（计入档合并，按单位/币种分组）+ `ourStockBreakdown`（分档：可用/在途/寄售）；
    `ownedOnly` 降级为 `ourStock` 的 **@deprecated 别名**（它此前"只含 Owned"⇒ 会静默少算）
  - 前端：选项补两档（与后端枚举**逐字对撞**有守卫）+ 徽标语义判据改为「是否计入我方存货」

### D6 远期结汇：与银行的远期结汇合约（`2c59e58e`）
- 实测：`FxRateLock`（订单级锁汇，解决"这笔生意按什么汇率算成本/利润"）+ `FxSettlement`（结汇水单，解决"实际结了多少"）都在 ⇒ 缺**与银行的远期合约**这一层：
  ① 到期日没人管（远期合约到期必须交割，逾期有展期成本/罚息）
  ② **合约汇率 vs 实际结汇汇率的损益算不出来** —— 而"锁汇率 + 算损益"正是远期结汇的意义。
- 修法（**本会话唯一新迁移；只建新表、不碰既有表：回滚 = DROP 两张**）：
  - `ForwardFxContract`（合约号/银行/币种/合约金额/约定汇率/签约日/到期日/已交割额/状态）
  - `ForwardFxSettlementLink`（合约 ↔ 结汇水单：**一笔合约可分次交割、一笔水单只能用一张合约** = 唯一键）
  - 真源纯函数：`forwardFxRemainingOf` / `forwardFxStatusOf`（**Cancelled 是终态，不会"起死回生"）/
    `forwardFxPnlCnyOf((实际 − 合约) × 金额；入参非法 → null **不猜**) / `daysToMaturityOf`（日期非法 → null，不显示成"今天到期"）
  - 路由 `GET|POST /api/v1/finance/forward-fx` + `POST /forward-fx/:id/settlements`（`remit:read|write` 门控）
- ⚠️ **刻意不把银行合约信息塞进 `FxRateLock`**：两者语义不同（订单侧内部定价锚 vs 外部金融合约），混在一个模型里必然漂移 —— 用结构守卫钉死。
- 守卫：真源 15/15 · 真库 7/7（分次交割累计 + 损益 120/−80 汇总 40 / OVER_CONTRACT 409 / CURRENCY_MISMATCH /
  一笔水单挂两张合约 409 / 到期天数正负 / 合约号重复 409）· 结构守卫 5/5（两表 + 迁移只建新表 + 路由映射 +
  `FxRateLock` 不被污染 + 派生量走真源）
