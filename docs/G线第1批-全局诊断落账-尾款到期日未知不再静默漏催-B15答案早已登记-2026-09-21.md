## 二、修的缺陷（G1/G3）：尾款到期日解析不出 ⇒ 财务看不见这笔应收

**机制（本会话逐行自核，不引二手结论）**：

| 消费点 | 过滤条件 | null 会怎样 |
|---|---|---|
| `finance/dunningStageService.ts` `loadOverdueFinalPayments`（**催款分级看板的"尾款喂入"，前端真消费**） | `finalPaymentDueDate: { not: null }` | **被整条排除** ⇒ 不进分级、不定档、不计金额 |
| `shipping/orderShipmentBatchService.ts` `listOverdueFinalBatches` | `finalPaymentDueDate: { lt: today }` | null 永不满足 `lt` ⇒ 不进该清单（该清单前端**零消费**） |
| `orderShipmentBatchService.ts:134-137`（批次全景里的"是否逾期"标记） | `finalPaymentDueDate != null && …` | 不标逾期 |

**为什么这是缺陷而不是"数据没填"**：到期日来自 `parseCreditDaysFromPaymentTerms(order.paymentTerms)`，
该解析器（`orderShipmentBatchService.ts:49-56`）**只认 `(\d+)\s*days?`** ⇒
`Net 60` / `60 天` / `见票后 60 天` 一律解析失败 ⇒ 留空 ⇒ 上面三处同时把它当"不存在"。
`logger.warn` 只写日志，业务人员看不到 ⇒ 违反 **G3.1/G3.4**（拿不到数必须可见，不得静默）。

**修法（口径刻意保守，D62）**：新增 `loadUnresolvedFinalPayments()` + 看板返回体新桶 `unresolvedFinalPayments`
（按 客户×币种 汇总 `outstanding` / `batchCount` + 中文 `reason`）⇒ **只列示、不定级、不进 `rows`、不进 `summary`**。
理由两条：① 该文件自己已有的原则「债务真实存在，不能从看板消失」；② 把"未知"当"已逾期"会让财务对**按时付款的客户发催款函**，那比漏催更伤（G3 不给错数）。
前端 `DunningStageBoardPanel.tsx` 头部渲染该桶（`types.ts` 加接口；路由 `{ ok: true, ...result.data }` 自动透传，未改契约）。

**R3 覆盖派生（3 条用例，全部先 RED 后 GREEN）**：
① null 末批必须出现在待核桶，且 `rows` 长度 0、五档 `summary` 计数全 0（**反向断言：不许污染逾期额与分级**）；
② 同客户"一笔有到期日 + 一笔没有" ⇒ 逾期额只含有到期日那笔（40000），待核桶只装另一笔（50000）；
③ 不误伤：已结清 / 未发运 / 非末批 / 软删 的空到期日**不进**待核桶。

**D56 探针**：把待核查询翻成旧语义（`{ not: null }`）⇒ **2 条用例红，且红在正确的 assertion 上**
（`到期日未知的末批不得从看板静默消失: expected [] to have a length of 1`），随即还原、`diff` 验证相同。
⚠️ **第一次探针无效**：我注入的代码破坏语法 ⇒ vitest 报 "no tests" —— 那是**假红**（不是行为红）。⇒ 规矩：**探针必须让断言本身变红**，"跑不起来"不算证伪。
