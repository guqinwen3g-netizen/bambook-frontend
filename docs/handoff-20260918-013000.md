## 三、★★ 两个真缺陷（都已修 + 都已验证）

### 3.1 运单表单栈溢出（用户可感知 ✗）

```ts
// components/ShipmentManager.tsx（修前）
const clearError = useCallback(() => {
  clearError();        // ← 自己调自己 ⇒ 无限递归
  setGateBlock(null);
}, []);
```
- **影响**：点「**新建运单**」/「**编辑运单**」⇒ `RangeError: Maximum call stack size exceeded` ⇒ **表单打不开** ✗
  （该函数在 **8 处**被调用 + 挂在**错误横幅关闭按钮**上 ⇒ 影响面大 ✗）
- **修**：`setErrorMessage('')` ✓ · **守卫**：`components/noSelfRecursiveCallback.test.ts`（判据**三次收紧**才精准 ✓）
- ★ **为什么三层门禁全瞎**：`tsc` 不报（名字在自己作用域内**合法**）· 单测不渲染该交互 ·
  **连栈帧都骗人**（200 帧全指向一个**无关组件**的 `<input>` 行 ✗）
  ⇒ 靠 **`curl` 开发服务器拿「浏览器实际执行的转换后代码」**才定位 ✓

### 3.2 ★★ 删实体不清引用（**结构性问题** ✗）

- **根因**：`server/src` 里 `entityReference` / `entityLink` **只有 `upsert`，一个 `deleteMany` 都没有** ✗
  ⇒ 删实体时引用**永远不被清理** ✗ ⇒ 悬挂引用**必然累积** ✗
  （09-17 手工清过「806 → 49 → 0」✗ —— **源头一直在产** ✗）
- **修（方案 A · Kevin 拍板）**：`server/src/entities/entityRefPurgeMiddleware.ts` ✓
  挂在 Prisma 的 `delete`/`deleteMany` 上 ⇒ **一次覆盖 10+ 条删除路径**（含未来的新路由 ✓）
  ★ 与「逐路由补」相反 —— 后者**必然再漂移** ✗（本仓最高产的一类 bug：**收口点错位** ✗）
- **验证**：守卫 7 例 ✓（含「**不得漏收**」计数对撞 ✓）· **端到端 7/7** ✓（`delete` + `deleteMany` 两条路径 ✓）
- ★ **踩点**：type 字符串**写法是混的** ✗（`order` / `development-case` / `orderLine` / `relation.organization`）
  ⇒ **只能照抄 `sync.ts`，不能按规律推** ✗ · 且 **`Relation` 对应三个 type** ✗

## 六、环境/工具坑（本会话踩到并记录的）

| 坑 | 现象 | 修法 |
|---|---|---|
| **`child.on('close')` 永不触发** | 批量跑到某页**卡死不动** ✗（Chromium 继承管道 ✗） | 改 `exit` ✓ + 看门狗 ✓ |
| **`nohup &` 起的进程被沙箱回收** | 现象同上（日志停住 ✗） | 用**受管后台任务** ✓ |
| **`grep "a\|b"` 静默失效**（BSD grep ✗） | 搜不到却**不报错** ✗（**本会话踩了 23 次** ✗） | 用 **Grep 工具**或 `grep -E` ✓ |
| **`\| head -N` 触发 SIGPIPE** | vitest 只跑 33 秒就退出（正常 11 分钟 ✗） | 用 `\| tail` ✓ |
| **`curl` 访问本地 8081 返 502** | 像后端挂了 ✗（沙箱 `HTTP_PROXY` ✗） | `curl --noproxy '*'` ✓ |
| **`ps` / `pgrep` 不可用** | — | `launchctl print gui/$(id -u)/com.bambook.dev-server` ✓ |
| **`String.replace` 替换串里 `$` 有特殊含义** | 把**整个文件头**塞进一行 ⇒ 语法崩溃 ✗ | ★ **改代码一律用 Edit 工具** ✗ |
| ★ **报错被我自己 `slice(0,200)` 截断** | Prisma 的详细报错看不到 ⇒ **白试两轮** ✗ | **报错原样打出来，别截** ✓ |
