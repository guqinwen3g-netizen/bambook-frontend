## 四、批次 3 三条的要点

### C3（`750447e8`）—— ★ 实测比清单描述更严重
- 清单写「出运侧只算上限，可无限少出」。真身是：**`OrderLine.shipmentQuantity`（订单详情「溢短装条款」面板的唯一数据源）只被 `internalTrade` 写过，出运模块从不写它** ⇒ 面板永远显示「未发货」、`checkTolerance` 的短装/溢装判定**从不触发** = **一块永远绿的假面板**（比没有更糟：让人以为条款校验过了）。
- 修法：真源 `shared/orderLineShippedQty.ts`（行级分配直归该行 / 整单分配按**行量比例**分摊 / 单位不可互算 → 不计入并上报）；口径与 `allocationService` 的上限校验**同源**（排除 `Cancelled` 票）——**同源比"更精确"重要**，否则出现「上限校验说没超、容差面板说短装」。
- 收口点 **5 处**：分配 create/update/delete + 票取消 + 票软删（结构守卫用**调用计数**对撞，漏一处即红）。
- ⓘ **双轨未合并**：内部交易与手工台账仍可写该字段（已在结构守卫登记在案，**未擅自禁写**）。

### C2（`b5bff550`）
- 真库实测驱动：`shippingMethod` 是自由文本零校验，75 张票 `Sea 67 / Air 7 / Sea Freight 1`。
- 两档口径**必须分开**：写入 `coerceShippingMethodForWrite`（严格；中文/别名/脏值/FCL/LCL → **归一**而非拒绝）+ 展示 `normalizeShippingMethod`（宽容，只影响分组与展示，**不改库**）。
- **不回溯历史行**：只校验本次写入的值 —— 否则改一条老票的备注都会被拒（真库那条 `Sea Freight` 就是判据）。
- 前端改下拉时把**历史脏值作为「历史值」选项**保留，避免保存时静默改成别的值。

### C7（`5f8bb7c4`）
- A3 修了「CN 抵扣发票」的**内核**，但 CN 唯一创建路径是索赔处置（5 步 + 语义错位）⇒ 几块钱尾差实务上没人处理，发票永远 `PartiallyPaid`、账龄天天报警。**A3 缺的是入口。**
- 真源 `finance/writeOffService.ts`：对未结额开 CN（`claimCaseId=null` 纯折让）**并立即抵扣**。
  - **原子**：为此给 `createCreditNote` / `applyCreditNote` 加可选外部事务参数（默认行为不变），并修正其内部读要用 tx（否则读不到本事务内刚建的 CN）。
  - **不重写状态机**：结构守卫反向断言禁止自己拼 `CreditNoteAllocation` / 改 CN 状态。
  - **有上限**：`min(票面×5%, 等值 500 CNY)`（⚠️ 两个默认值是我按行业惯例取的，可用 `WRITE_OFF_TAIL_MAX_RATIO` / `WRITE_OFF_TAIL_MAX_BASE_CNY` 覆盖，**待业务确认**）。
- 路由 `POST /api/v1/invoices/:id/write-off-tail`（`aftersales:write`）；前端发票详情「尾差销账」按钮（应收票 + Issued/PartiallyPaid + 写权限，先取事由再二次确认）。
