## 一、业务视角（先懂业务，再碰代码）

### 1.1 真实业务链（起点不是"新建订单"！）

```
客户来样/询盘 → 打样 → 报价 → 客户接受 → 【转单】 → 订单行(一行一色)
  → 采购（供应商）→ 生产阶段推进 → QC 验货(含幅宽) → 出运样(S/S 寄客户确认)
  → 运单 → 出运批次 → 【出运门禁】→ 报关 → 发票 → 收款 → 核销 → 利润表/成本三环 → 结案
  ↘ 变异：分批出运 · 拼柜 · 溢短装 · 少收汇 · 改单 · 延期 · 索赔 · 多币种 · 指定货代 · 反复打样

★ 业务起点是**报价/来样**，不是"系统里新建订单"（我曾犯此错，被 Kevin 纠正）。
★ 业务是**交叉网络**，不是固定流水线：老客户可直接下 PO，打样与报价可并行，索赔可在任何时点插入。
```

## 二、架构与"唯一真源"清单

- **栈**：React + TS 前端（根域）· Express + Prisma/Postgres 后端（`server/`）· vitest 双端测试。
- **后端分层**：`route → service → (shared 真源函数)`。controller 不写业务逻辑，口径一律抽成**纯函数 + 单测**（防"同数不同判"）。
- **权限**：scope 门（如 `pricing:read`、`sensitive:cost`）叠在认证门之上；**敏感字段服务端遮罩**（前端遮罩不算数）。

### ★★ 判断"连通"必须先看系统怎么表达（我因此错判 4 次）

| 关系      | 真源（**不是**直觉外键）                                                                  |
| ------- | ------------------------------------------------------------------------------- |
| 发票 ↔ 订单 | `InvoiceOrderAllocation`（多对多；`Invoice.orderId` 常为空！）                            |
| 运单 ↔ 订单 | `ShipmentOrderAllocation`（合票按分摊，单位不同不按数量摊）                                      |
| 报价 ↔ 订单 | `EntityLink.linkKind='convertedToOrder'`（+ `Quotation.convertedOrderId`）        |
| 核销      | `InvoiceAllocation`（invoiceId + voucherId）                                      |
| 已发量     | `OrderLine.shipmentQuantity`（由 `shared/orderLineShippedQty` 按 **actualQty** 刷新） |

**铁律**：`EntityLink` 共 4051 条 / 25 种 linkKind。想当然按"父 id 外键"判，必错。

### 5.2 ★ 真跑抓出并修复的 5 处**口径级缺陷**（不报错但算错，最危险那类）

| # | 缺陷                 | 现象 → 修复后                                                                                          |
| - | ------------------ | ------------------------------------------------------------------------------------------------- |
| 1 | 利润表收入恒 0           | 收入段只按 `Invoice.orderId` 查，走分摊路径建的票永远读不到 ⇒ 毛利算成负。改真源为 `InvoiceOrderAllocation`：**0 → 161,317 CNY** |
| 2 | 三环把整单价当单价          | `finalUnitPrice` 实为**整单**价，×数量 ⇒ 收入放大 2000 倍。改直接取整单 + 另给单价                                        |
| 3 | 跨币种静默相减            | 售价 USD − 成本 CNY ⇒ 毛利率 −600%。加保护：跨币种毛利置 null（#13 不隐式折算）                                            |
| 4 | **短装门禁 fail-open** | 整单级分配被 `.filter(x=>!!x)` 整行跳过 ⇒ 判定行 0 ⇒ 门禁不执行。改：整单分配纳入全部行 ⇒ 实测拦住（还少 140 M + 自动发起审批单）              |
| 5 | 船样两套链路             | 门禁读 `Sample`，补的数据写 `FabricShipmentSample`（旧表）⇒ 永远被拦。迁移 13 条 + 旧端点同步锚写新表                           |
