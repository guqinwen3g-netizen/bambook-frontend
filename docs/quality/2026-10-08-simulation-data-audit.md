# 2026-10-08 模拟数据审计、修复与覆盖缺口

## 结论与范围

只处理本机 `localhost/panda_hub_dev`，未操作共享库或生产库。修复当前数据，同时修正模拟生成器的产品字段来源；没有重做前端。

这次确实不是单纯的列表筛选问题：原库只有15张面料订单、没有成衣订单。产品描述被用来写“待复验”“出运后待收款”等流程剧本，内部测试标识又被当作商业品号。报价、询价、独立采购/加工合同、寻样和库存等样例覆盖也不足。

截至2026-10-09本轮收尾，当前39张有效订单由已有员工身份调用原生业务接口创建。原定面料、成衣各18个场景全部到达各自指定的停止节点；另补成衣全包及其内部面料供给两张订单、内部备货草稿一张。场景覆盖包含草稿、拒绝、返工、在产、待出运、分批出运、未收款、部分核销和结清，不能把“到达场景停止节点”解释成所有订单均已履约完成。

## 生成器与程序修正

1. 订单产品名称/品号从真实目录取得；packing产品名称、品号改从实际订单条目读取，采购/加工行描述也读实际来源条目。
2. 开发产品名称、开发方向与真正保存的羊毛斜纹/西装规格保持一致；流程场景说明只放在nextAction/备注等过程字段，不当成产品名。
3. 历史目录生成器补上工厂质量编号、色号等字段；修复后的目录与未来生成规则一致。
4. 删除“所有面料一律羊毛HS、所有服装一律同一个HS”的假设。没有专业归类依据时HS保留null，不能凭面料/成衣两分类猜测税号；本次没有实际生成新的报关完成事实。
5. 修正部门授权交集中业务安排QC任务的动作：业务可以安排，专业检验仍须QC属性及inspect权限。没有给业务员后勤制单或专业QC签署权限。

## 业务链路与程序修正补充

- 业务发起出运交接使用 `orders:write`，底层创建仅限交接事务内的空白Export/Draft及本人交接数量预留。后勤接收、装箱、制单、实绩操作继续要求专业出运权限；实际离港由后勤登记。没有给业务员批量追加后勤角色。
- 原生出运驱动由业务发送准确版本CI/PL，后勤验证后登记离港；文件下载适配器正确处理PDF二进制响应。
- 内部供给产品字段读取真实目录和色号，内部用途单独存放，关联分配双向回读。内部备货保持待确认草稿，不伪造收货入库。
- 两个已有开发案复用原始20CNY费用、100USD收费登记，没有重记费用。保留原CI版本，刷新草稿至v2、签发v3，再登记各100USD未收应收。
- 本地BillingItem旧CHECK不支持business_ci_draft/issued，已通过严格本机库保护脚本执行现有前向SQL `20261007330000_development_business_ci_workflow_states`，校验八个合法状态。只声明该SQL已应用，不代表整个迁移链已部署验收。

## 尚未验收的范围

1. 正式SC文件创建、查看与下载没有在本轮作为完整文件链验收；合同号不代表实际文件已生成。
2. 全包材料分配已核验，后续实际材料交付与入库不是本次场景停止点。内部备货也是草稿，不冒称已备货完成。
3. 索赔、佣金最终结算、报关/LC专项末端和全站跨角色UI连续操作仍未全部验收；佣金待结算样例不等于佣金已经收款。
4. 30份自动BOM草稿仍未填写实际物料成本，只有3份独立估算草稿具备用量/费用明细；零成本不能当真实毛利。
5. 数据核验不能代替全站软件验收，出运回归现已通过，但本轮缺少浏览器检查、其他模块尚未全站验收的边界仍需明确保留。

## 2026-10-09 出运扩大回归修复（完成）

用户要求从实际业务角度诊断上一轮98项失败，不为绿灯放宽规则。本轮限定出运回归；前端未改。真库演练改用独立本地克隆库 `bambook_shipping_regression_20261009`，不写当前演示库。

已定位三类根因：

- 实时授权、部门业务属性和客户组织校验升级后，测试存储夹具缺少必要字段/委托，导致预期的装箱、回滚或专属面料判断尚未执行就提前失败。修正有效主体及存储契约，同时保留非法主体负例。
- 旧用例继续新建整单分配、使用Express或写入ETA；最新MVP明确按准确订单条目执行、运输仅海运/空运、无目的地到港追踪。更新场景数据与预期，不恢复旧入口。
- 新增交接错误适配器及出口申报完成响应未进入有限错误出口登记；补齐精确出口和错误载体验证，并用变异负例证明不能转发原始异常、丢失details或增加未知出口。

原98项失败分组如下（具体测试身份保留在 `shipping-original-failures.json`）：

| 原失败数 | 根因与修复 | 保留的业务规则 |
|---|---|---|
