## 一、为什么必须有（核准结论）

水单核销链（`receiptClaimService` / `allocationService`）只到**发票 / 订单**层，
**完全不碰报关单**（grep `declaration/customs/报关` 零命中）→ 收汇与报关 FOB 各在各的域，永远碰不上。
而外汇核销 / 退税核查恰恰要求二者勾稽：收汇显著低于 FOB 可能是**未收汇即申报退税**；
显著高于 FOB 可能是多收 / 错汇 / 混入非本单款项。

**数据源**：收汇 = `PaymentVoucher(type='Receipt', orderId, deletedAt:null).amount`；
报关 FOB = `CustomsDeclaration.totalValue` 按 `tradeTerms` 剥运保费（运费保费取自 `Shipment.freightAmount/insuranceAmount`）。

**CIF → FOB 剥离表**：

| 成交方式 | 处理 |
|---|---|
| `FOB` / `FCA` / `EXW` | 不剥（本身即离岸/出厂价） |
| `CFR` / `CPT` | 剥运费 |
| `CIF` / `CIP` | 剥运费 + 保费 |
| `DDP` / `DAP` / `DPU` | **不猜**（含关税+送货）→ 标记 `unStrippable`，该票不参与比对 |
| 未填 / 其它 | 按**不剥**处理（保守方向：FOB 偏高 → 报「收汇不足」而非「多收」，方向安全） |

**两条铁律**：
1. **不引入任何汇率换算**——运单运保费币种 ≠ 报关币种时，不换算、改为「该票不参与比对」并说明原因
   （与口径 A「汇率锚点只有结汇汇率」一致）。
2. **容差 = max(5% × FOB, 500)**；固定 500 按该币种金额单位（业务主币种 USD 时即 500 美元），
   返回体带 `toleranceBasis` 说明用了哪个阈值。

### ⭐ 真库暴露的现象（值得你看一眼）

**10 个样本单 100% 超差**，且差异幅度很大：

| 订单 | 收汇 | 报关 FOB | 差异率 |
|---|---|---|---|
| SIM-ORD-003 | 6,450 | 12,900 | **−50%** |
| SIM-ORD-010 | 38,439 | 128,130 | **−70%** |
| SIM-ORD-014 / 011 / 017 | **0** | 11,325 / 25,500 / 82,215 | **−100%** |
| SIM-ORD-013 | 2,925 | 9,750 | −70% |

**判断**：这是**演练数据本身收汇与报关金额不匹配**（SIM 数据是生成的），不是本功能的 bug
——容差与剥离的自洽性断言全部通过。但它说明两件事：
1. 该功能一旦上线会**报出很多**（若生产数据也如此，说明确实存在大量少收汇/未收汇）；
2. 其中 3 单是**完全未收汇**，我已把「尚无收汇记录」与「少收汇」**分开表述**
   （前者提示「若尚未到收款期属正常；若已申报退税则需核实未收汇即退税」），避免财务被同一句话误导。

**⚠️ 真库样本限制（诚实标注）**：真库 48 张报关单**成交方式全是 FOB** →
**CIF/CFR 剥离分支在真库完全没被覆盖**（`发生过剥离 0 / 含不可剥票 0`），只由单测钉住（5 例）。
