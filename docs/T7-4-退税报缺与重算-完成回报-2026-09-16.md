**三类缺项（实时计算，**刻意不存库**——缺失是当前状态的函数，补齐后应自动消失；存库会陈旧且要迁移）**：

| code | 触发 | howToFix |
|---|---|---|
| `fx_rate` | 订单既无应收发票汇率、也无收汇凭证汇率 | 给应收发票或收汇凭证补 `exchangeRate` |
| `hs_rebate_rate` | 报关行缺 HS 编码 / 该 HS 未登记 `exportTaxRebateRate` | 去 HS 编码档案补退税率 |
| `line_total` | 报关行缺 `totalAmount` | 补报关行金额 |
| `no_lines` | 报关单没有商品行 | 先补商品行 |

**重算两种模式**：
- `fill_missing`（默认）：**只填当前为 null 的字段**，已有值一律不动 —— 人工填过的金额不会被冲掉。
- `force`：**只返回 diff（before → after），不落库** —— 一键重算不得悄悄改掉审核过的数。
- **状态约束**：仅 `Draft` / `Rejected` 可重算；`Submitted` 之后 → **409**（已提交的申报数据不可悄悄修改，审计要求）。
- 重算走 **update 既有退税单**，不新建（`declarationId` 唯一约束不变）。

**口径**：出口单的**实际回笼资金 = 已结汇折 CNY + 已退税 CNY**，**两者都只算已到账的**

（预提等于拿没到手的钱做结算）。同时明确：**毛利层面不受影响**（那是成本侧，与退税不同域）。

### ⭐ 真库把 T7-4 要解决的根因**精确定位**了

真库只有 **1 张退税单**（`TRA-SIM-CD-2026-0048`），它的 `refundableVat = null` ——
**正是"算不出来"的真实样本**。报缺端点给出的答案是：

```
SIM-CD-2026-0048 缺项 → hs_rebate_rate:6006.21.00
SIM-CD-2026-0036 缺项 → hs_rebate_rate:6110.20.99
SIM-CD-2026-0038 缺项 → hs_rebate_rate:6204.43.00 / hs_rebate_rate:6204.43.00
```

**8/8 样本报关单全部有缺项，且全是 `hs_rebate_rate`** —— 因为真库 **HS 编码档案只有 1 条**，
而报关行用了 `6006.21.00` / `6110.20.99` / `6204.43.00` 等各种编码，**全都未登记出口退税率**。

**业务结论（重要）**：**生产上线前必须补全 HS 编码档案的出口退税率**，否则退税金额永远算不出来
（旧实现静默存 null，用户只能看到一张金额全空的单，完全不知道卡在哪 —— 这正是本批修掉的病）。
现在报缺端点会直接告诉你「缺 HS 6006.21.00 的出口退税率，去 HS 编码档案补」。
