## 三、fail-closed 的设计取向（为什么"不过"不等于"不许跑"）

自证不通过**不阻断**执行：有时就是要观察别的分支的行为。它改变的是**署名的权利**——
`run-all-acceptance` 的报告里从此带一行结论：`✗ 不可署名：<原因>`。
这与 §0.4「不得以没测出问题推定专业」、G3「算不出来不给数」同一条纪律：**宁可拒绝署名，不许错署名**。

本 worktree 实测输出（真实运行，不是构造）：

```
── 验收自证（acceptance self-check）────────────────────────
  脚本仓库  /Users/qinwengu/WorkBuddy/Claw/apps/bambook-s0a @ s0/error-truth-foundation (1f0dfe84)
  数据库    未知 @ ?:?  ← ★ 本仓无 env 文件
  后端      http://127.0.0.1:8081  pid=68014  cwd=.../apps/Bambook/server  分支=main (86a451ce)
  ⇒ ✗ 读数**不可**署名本分支：
      · 本仓找不到 env 文件（找过 server/.env.local、server/.env）⇒ 不知道连的是哪个库（ENV_MISSING）
      · ★ 后端跑在另一个 checkout：后端=…Bambook（main）≠ 本脚本=…bambook-s0a（s0/error-truth-foundation）（ARTIFACT_MISMATCH）
```

## 四、守卫的可证伪性（D56）

`scripts/acceptance-selfcheck.test.ts` 11 例全绿，**三条关键设计**：

1. **正向对照必须有**：同 checkout + 同分支 + 本机演练库 ⇒ 判 `ok=true`、banner 出 `✓ 读数可署名本分支`。
   ★ 理由：fail-closed 型判据若写成"恒拒绝"，只测负例的守卫会**全绿通过**——这正是本仓反复出现的"判据空转"。
2. **断言具体理由串**（`ARTIFACT_MISMATCH` / `BRANCH_DRIFT` / `NO_BACKEND` / `ENV_MISSING` / `不像演练库`），不写 `.length > 0` 这种恒真形态。
3. **verdict 三态各自可杀**：0% ⇒ "B35 未清"；30% ⇒ "以存量为主"（**不许报喜**）；90% ⇒ ✓。

**两条探针**（各红一条，随后还原，`diff` 证明与备份逐字节一致）：
- 探针 1：把 checkout 不匹配的分支判断改成 `else if (false)` ⇒ 该用例红，红在"理由串不等于 ARTIFACT_MISMATCH"上（代码退化成了 BRANCH_DRIFT ⇒ 说明两条判据确实是**分开**在管两件事）。
- 探针 2：把"无监听 ⇒ NO_BACKEND"短路掉 ⇒ 该用例红。
