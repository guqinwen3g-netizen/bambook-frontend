## 一、为什么要补：v2.56 那句"78 条没有任何门"是**尺的口径**，不是仓的实情

派生面 v2.56 只看得见一种写法：`router.post(路径, 门…, handler)`。本批逐处读源码后确认，至少两类真门在参数表里根本不存在：

1. **门写在 handler 体内**（本仓的主流写法之一）。`server/src/mes/mesRoute.ts:203` 起 26 条长这样：
   ```ts
   router.post('/work-stations', async (req, res) => {
     if (!requireProductionWrite(req, res)) return;   // ← 门在这里，参数表里一个字都没有
   ```
   全仓这类"局部门函数"实测 26 处定义（`authenticate` / `scopeGate` / `requireScope` / `requireProductionWrite` / `requireCrmWrite` …）。
2. **门在挂载点注入**：`server/src/index.ts` 有 `(req,res,next) => sdkAuth(req,res,() => createXRouter(prisma)(req,res,next))` 这种包装（`app.use` 共 204 处，其中 80 个 router 工厂可解析到文件）。

★ 而最容易看错的一件事：`createXRouter({ requireAuth: SDK_CONFIG.requireAuth })` 里的 **`requireAuth` 是 boolean，不是中间件**：

- `server/src/index.ts:245` — `requireAuth: process.env.BAMBOOK_REQUIRE_AUTH === 'true' || process.env.NODE_ENV === 'production'`
- `server/src/mes/mesRoute.ts:122 / :135` — 局部门第一行都是 `if (!requireAuth) return true;`

⇒ 本地开发（两个条件都不成立）时**整条鉴权链放行**。所以它既不算权限门、也不算认证门，本批**特意不给它记任何一层的功**，并在守卫里放了一条断言：`booleanFlagOnlyFiles`（实测 71 个文件只拿到这个布尔）里的任何一条路由，都不许出现"挂载层记功"（`mountAuthn || mountPermission`）。将来有人把 `requireAuth` 当中间件接进来，这条会当场红。

## 二、分类按"做了什么"，不按名字猜（B35/B75/B76 同族教训）

| 档 | 判据（定义体里出现） | 现场例 |
| --- | --- | --- |
| `permission` | `hasScope*(` / `hasPermission(` / `checkPermission(` / `permissionService.` / `roleCode` / `scopeName.includes(` | `scopeGate`、`requireScope` |
| `authn`（只有身份） | `extractActorFromRequest` / `apiKeys.has` / `verifyJwt` / `status(401)` | `authenticate`（无 actor 就 401，但**不判角色**） |
| 不是门 | 既不写状态、也不调用别的门 ⇒ 丢弃 | `actorOf(req)`、`apiKey = (req.query… as string)` |
| `unknown` | 能拒绝但读不出判据 ⇒ **进棘轮，逼表态** | —— |

三条实现约束（都是本批自己踩出来的，写在代码注释里）：
- **体会用花括号配平**，不用"固定 1400 字符窗口"：窗口会越过本函数把**下一个函数**里的 `res.status(` 算进来 ⇒ 给只解析身份的 `authenticate` 记成 permission（危险的放绿方向）。
- **锚点从 `=>` 之后开始**：返回类型注解自己带花括号（approvalKernelRoute 的 `): { userId: string; roles: string[] } | null => {`），从定义处直接找 `{` 会**把类型注解当函数体** ⇒ 那个真门被静默丢掉（实测该文件门数 = 0）。
- **首参必须就是 `req`**：`const apiKey = (req.query.apiKey as string) || …` 会被吃成"名叫 apiKey 的门"，且它后面没有 `=>`，锚点滑到下一个函数 ⇒ mesRoute 凭空多出一个 permission 门（实测过）。
- **传递闭包 3 轮**：`requireProductionWrite = authenticate(req,res) && scopeGate(...)` 自身体内既没有 `res.status(` 也没有 `hasScope(` ⇒ 不继承就会被当"取值函数"丢掉，并把 mesRoute 那 26 条降级成"只有身份"。只向上继承 `permission` 一档。
