### 五-b：尾逗号伪像（一处"噪声看着像缺陷"的活例）

多行注册写法带尾逗号时 `splitArgs` 会切出一个**空实参段**：

```
router.post(
  '/x',
  requirePermission('knowledge:write'),
  // 注释一行
  async (req, res) => { … },
)                      // ← 这个逗号让 args 末尾多一个空串
```

后果有两层，都不是仓的缺陷、但都被尺**当成**了东西：
1. 最后一段是空串 ⇒ "最后一个实参不是内联 handler"成立 ⇒ 该路由掉进 `named-handler` 桶 ⇒ **14 条里有 13 条是这么来的**（真·命名 handler 只有 `admin/route.ts:320` 一条）；
2. 空段继续去归类门 ⇒ `unknown` 清单里出现 **13 条 ident 为空**的条目（清单存在但不含任何信息，等于"登记了但没人能看"）。

★ 修法在**解析边界**（`enumerateWriteRoutes` 里丢掉尾部空段），不在下游逐处 `if`。
★ 关键对账：修后 `guarded` 565 → 578、`named-handler` 14 → 1、`unknown` 83 处 → 8 处，但**三个覆盖桶 610 / 29 / 18 一格未动** ⇒ 这处改动只是清噪声；
若当时桶跟着动了，就必须像 §三 那样逐条归因，不能读成"顺手修好了权限"。
★ 牙齿实测（把 `args.pop()` 那行注释掉，其余不动）：**3 例同时红** ——
`尾逗号伪像`（本条新判据）+ `未归类形状只许下降`（8 种 > 基线 6 种）+ `新旧口径差额必须逐条可解释` ⇒ 已还原（还原后 14/14 绿，`diff -q` 与 /tmp 副本一致）。

### 五-c：注释把解析器骗了（两处后果，方向相反）

`splitArgs` 的引号状态机原先不认识注释 ⇒ 注释里的一个撇号（英文所有格 / `don't`）就把后面整段代码当字符串吃掉：
① **假"括号未闭合"** ⇒ `orders/route.ts:147` 这条**带着 `requireWrite + requirePermission('orders:write')` 的真写面**被踢出分母（658 之前是 657；`unparsedMax=1` 把这件事登记了，但登记成"切不出来"而不是"少一条分母"，读起来完全不像缺陷）；
② 反过来，注释行会被切成一个"只有注释的实参段"送去归类 ⇒ `unknown` 清单里出现**中文注释碎片当"中间件形状"**（清单存在但不可读）。
★ 修在解析边界：注释整体跳过、**原样保留文本**（下游要用 `indexOf(handlerText)` 回查偏移）。
⚠️ 第一版我改成"用空格替换注释"，**结果 15 条路由的体内门全部消失**（`perm` 611→601、`noEvidence` 18→33）—— 因为 handler 文本不再与源码逐字相同。
⇒ 这条自伤被"数字变了"抓到而不是被测试抓到：**改解析器时，覆盖桶动了就必须逐条归因**（本条已并入 §九 的处置表）。
