★ 本批**只动判据与清单，一行数据都没删**；删除仍只在 `server/scripts/cleanup-test-residue.mjs --apply` 时发生，且要先出命中清单 + 行数并经 Kevin 点头。

## 一、为什么要做（不是"顺手收口"，是对撞出不相容）

B35 的第一刀给了"验收读数自证层"（报告写明库名 + 关键表行数 + 按前缀过滤）。第二刀要动的是**"什么算演练数据"这件事有几份真源**。
我原先的笔记说"三处清单"，**先复量才发现连路径都是错的**：`diag-test-residue.mjs`、`cleanup-test-residue.mjs` 在 `server/scripts/` 下，不在 `scripts/`。

复量后的真实分布（4 个消费者 + 1 个基座）：

| 位置 | 是否 import 基座 | 它自带的东西 |
|---|---|---|
| `scripts/lib/drill-residue.mjs` | = 基座 | `RESIDUE_MARKERS`(6) / `SIM_DATASET_MARKERS`(`SIM-`) / `BROAD_MARKERS`(验收·冒烟) / 派生 `ATTRIBUTION_MARKERS` / **`DELETABLE_MARKER_RES = []`** |
| `scripts/clean-drill-residue.mjs` | 是 | 用基座 markers 做清扫 |
| `scripts/audit-drill-residue.mjs` | 是 | **另加私有两项** `'smoke'`、`'TEST-'` |
| `server/scripts/diag-test-residue.mjs` | **否** | 自带 `CHECKS` 16 条（按 model+字段+前缀定向） |
| `server/scripts/cleanup-test-residue.mjs` | **否** | 自带 `TARGETS` 14 条 + `ORDER` 顺序表（`--apply` 真删的那一份） |

★ 关键点是后两份**不是"格式不同"，是会漂**，而且已经漂出两处**方向相反**的不相容：

1. `forwardFxSettlementLink.contractId ~ TEST_D6WD_` —— **诊断看得见、删除器看不见** ⇒ 清理跑完留孤儿关联行，下一次验收读数继续被污染（这正是 B35 的原始病：演练残留让"我跑出来的数"不可信）。
2. `auditLog.actorId` —— **删除器看得见 7 个演练执行者，诊断只列了 2 个** ⇒ 诊断会报"干净"，而实际还有 5 个 actor 的留痕在库里。

## 二、做了什么

- 基座新增 `DRILL_TARGETS`（**15 条 = 两份清单的并集**）+ `drillWhere()` / `drillTargets()`；两个消费者改成 `const CHECKS = drillTargets()` / `const TARGETS = drillTargets()`，**代码里再没有手抄前缀**。
- `id` vs `contractNumber` 那个"按 id 查会空过"的**对照探针**也进基座（`DRILL_PROBE_FX`）—— 它查的命中面与删除目标不同，因此**断言删除侧不得引用它**。
- 顺带修掉一处 B85 同族：两份脚本写死 `createRequire('/Users/…/apps/Bambook/server/')` ⇒ 在本工作树跑的是**别人的生成 client**。改成 `createRequire(import.meta.url)`。

## 三、牙齿（新守卫 `scripts/drill-targets-single-source.test.ts`，7 例）

| 断言 | 它能抓住什么 |
|---|---|
| 两个消费者的**代码行**里不许出现 `TEST_*_` 字面量 | 有人图省事再抄一遍前缀（漂移的源头）。注释里讲背景不算，且配了"非注释行不许被过滤规则放过"的反面对照 |
| `ORDER` 必须覆盖清单里**每一个** model，且交割关联排在远期合约之前 | 新增一族忘了排序 ⇒ 靠 `indexOf` 返回 `-1` 蒙对顺序、FK 会炸 |
| 两处已证实漂移必须在共享清单里存在 | 有人把清单缩回去 ⇒ 孤儿关联 / actor 少报复发 |
| `drillWhere` 三种形状（`prefix→startsWith`、`ids→in`、`extra` 合入） | 佣金发票若丢了 `sourceType: 'CommissionPayable'`，删除的"向"就没了 ⇒ 会误伤同前缀之外的发票 |
| import 基座不得 `new PrismaClient()` | 保证这条判据**不连库**（否则"跑守卫"就变成摸生产数据） |
| 前缀必须符合 `TEST_<族>_` | 有人往清单里塞宽词（如裸 `TEST`）⇒ 认领面过宽 |

★ 恒真检查也配了：`TEST_D6FX_` 字面量喂给同一条正则必须命中 ⇒ 证明"没有字面量"不是空断言。

## 四、⚠️ 刻意没做的三件事（别把本批读成"B35 已闭环"）

1. **基座的 `DELETABLE_MARKER_RES` 仍是空表**（lib 侧 allow-list）。本批刻意不打开：它匹配的是"任意字段含标记"，命中面远大于按 model+字段定向的目标。打开它需要单独一次判断，不能夹在收口里做。
2. **一行数据都没删**（按边界要求）。
3. **因把交割关联纳入删除侧，将来 `--apply` 会删的比上一版多**（+1 族、`auditLog` 从 2 个 actor 扩到 7 个）。⇒ 这一条是**扩大删除面**的变更，必须先在 diff 里看得见；跑 `--apply` 之前要按新清单先量一次行数并交 Kevin 点头。
4. `audit-drill-residue.mjs` 的私有 `'smoke'` / `'TEST-'` 两项**暂未收编**：`'TEST-'` 是宽词，收进来会不会命中正常业务内容还没量（与 `BROAD_MARKERS`"只能显式开启"是同一条戒律）。
