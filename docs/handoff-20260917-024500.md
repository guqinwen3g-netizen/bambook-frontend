## 一、本批做了什么（L2 高危 2 号，已提交 `5cc9b71`，工作区干净）

### ★ 修掉「合并开票不校同客户」——应收/账龄/催办/授信会静默挂错人

**病灶**：应收、账龄、催办、信用额度（`CreditLimit.usedAmount`）**全部按客户记账**。
一张发票挂上两个客户的订单 → 两边都算到**票头客户**头上，另一个客户凭空少债，
而且**全程不报错**（静默错账，只有对账时才发现）。
出运合票早有同口径硬校验（`shipping/allocationService.assertConsolidationAllowed`：仅同客户允许合票），
开票侧此前**完全没校** —— 这是不对称的那一半。

**修法（三层）**：

| 层 | 文件 | 内容 |
|---|---|---|
| 真源（纯函数，零依赖） | `server/src/finance/allocationCustomerGuard.ts`（新） | `findAllocationCustomerViolation(orders, invoice)` |
| 服务端硬门禁 | `server/src/finance/invoiceMutationService.ts` | `syncInvoiceOrderAllocations` 改收整个 `invoice`（不再只收 id）；create/update 两条路径都校验；**新增「只改客户不动分配」的迁移联动校验** |
| 路由状态码 | `server/src/finance/route.ts` | 两个新码 → **409**（顺手补了 `LINE_ALREADY_ALLOCATED`，此前会落 500） |
| 前端同口径预筛 | `components/FinanceManager.tsx` | 按客户筛选订单勾选列表 + 跨客户/不符时**红字 + 禁用提交**；先勾订单、票头客户空着时**自动带出客户** |

两个新错误码（**409**）：

- `INVOICE_CONSOLIDATION_CUSTOMER_MISMATCH` —— 所选订单分属多个客户（合并开票）
- `INVOICE_CUSTOMER_MISMATCH` —— 票头客户 ≠ 订单签约客户（挂错人）

**判定口径（三处必须一致：真源 / 服务端 / 前端）**：

1. 客户判据 **relationId 优先、客户名兜底**：只要所选订单里**任一**带 `customerRelationId`
   就只比 relationId；一个都没有（旧数据）才退化为比 `customer` 名称。
   —— 与后端 `relationIds.length > 0 ? relationIds : names` 逐字一致。
2. 票头 vs 订单：**仅 Receivable 校**（Payable 的 `customerRelationId` 存的是**供应商**，口径不同），
   且只在**票头有客户档案**时校。
3. **数据不全不误判**：宁可漏（后端兜底），不可过严（会把用户卡死）。

**⚠️ 已知留白（口径待 Kevin 判）**：双方都只有手输客户名（无客户档案）且名称不一致时，
前后端**都不校** —— 名称是自由文本，硬校会被大小写/后缀差异误伤。要不要校、按什么规则校，需要一句话。

|---|---|

## 四、坑（本批新踩，接手人直接复用）

1. **★ 跨层 import 会穿透 `tsconfig.json` 的 `exclude`**。root tsconfig `exclude: ["server"]`，
   但前端测试 `import '../server/src/finance/xxx'` 仍会把服务端文件拖进**前端** program ——
   真源若住在重依赖模块（`@prisma/client` / `creditService`）里，服务端的类型错误会
   **把前端 tsc 门禁从 0 打成非 0**（实测：`server/src/shipping/orderShipmentBatchService.ts(435)`
   冒出来）。解法：判定逻辑单独成文件、**零 import**，前后端都引它。
2. **★ 门禁类演练的回滚要按「用例键」无条件扫**，不能只清「API 返回 201」的实体。
   证伪跑时被拒用例会**真的落库**，只清成功实体 → 三张残留票 + 各自 IOA/EntityLink/AuditLog 全留下。
   做法见 `purgeInvoices()`：`POST_INV_KEYS.map(INV_NO)` 无条件 `deleteMany`。
3. **★ 不能用 env 开关证伪服务端守卫**。后端由 **launchd 托管**，不继承你 shell 的环境变量。
   只能：改代码 → `launchctl kickstart -k` → 跑 → 改回 → 再 `kickstart -k`（改前 `cp` 备份，改完 `diff` 复核）。
4. **`invoices:write` 只有「财务」与超管有**。`hank.zheng@`（后勤）能过 `customs:*` 但开票类接口返
   **403 `INSUFFICIENT_SCOPE: need one of [invoices:write]`** —— 别误判成门禁坏了。
   可用：`charlie.qian@` / `melissa.zhao@`（财务）· `jason.shen@`（超管）。
5. **Finance 页禁语义色族**：写 `text-rose-400` 会被 `components/rdlVisualBaseline.test.ts` 打红。
   错误提示统一走 `bds-alert danger`。
6. **`export { X } from './y'` 不会把 X 带进本地作用域**（只有 `import` 才会）。
   re-export + 本地使用要写成 `import { X } from './y'; export { X };`。
