## 一、我定的口径（业务方授权按专业判断）

| 项 | 判断 | 理由 |
|---|---|---|
| **确认粒度** | **按期间**（月度对账函），不是逐张发票 | 与客户财务的对账习惯一致（对账函就是按期的：「截至 X 月 X 日往来余额为 Y」） |
| **确认后触发什么** | **记录 + 通知内部**，**不锁定数据** | 对账后仍可能有新业务（新开票/新收款），锁定会卡死开票；行业上对账函也不冻结账务 |
| **回执 PDF** | **不做**（结构化记录已够） | 避免过度建设；电子确认本身即凭证。若要盖章版可后续加 |
| **异议通道** | 客户填说明 → **落库 + 通知内部**（同一条回执，status=disputed） | 不另起工单系统（内部通知中心已够用） |
| **同一期间重复提交** | **拒绝（409）** | 回执是客户凭证，反复提交会让"确认"失去意义；变更走业务员 |

**金额口径**：期初余额 / 本期开票 / 本期收款 / 期末余额，**按币种分组**（跨币种不合并 —— T7-① 口径）；
**期末余额 = 期初 + 本期开票 − 本期收款**。
（开票取 `Invoice(type=Receivable, 未作废)` 的 `issueDate`；收款取 `PaymentVoucher(type=Receipt)` 的 `paymentDate`
—— 这是"客户视角"的口径：我开了多少票 / 我付了多少钱。）

## 二、⭐ 客户门户的**第一个写端点**

`customer/route.ts:13` 原写「**只读（无任何写端点）**」—— 本批打破了这个性质，新增：

```
POST /api/v2/customer/reconciliation/acks     ← 提交回执（确认 / 异议）
GET  /api/v2/customer/reconciliation/statement ← 对账单（指定期间）
GET  /api/v2/customer/reconciliation/acks     ← 我的历史回执
```

**安全边界（写端点仍守住）**：
- 归属强制 `customerRelationId = req.customer.relationId`（客户只能提交自己的回执）；

- 头部注释已同步更新（不再宣称"无任何写端点"）。

### ⚠️ 一处我自己的失误（已修正并清理）

`await import('@prisma/client')` 解析不到 → **真库留了 1 条残留回执**。
处理：① 立刻直连 prisma **软删残留**（复核未删=0）；② 改用 `createRequire(<server 目录>)` 解析；
③ 复跑验收 **14/14 通过、回滚成功、无残留**。
**教训**：`scripts/` 下的脚本要碰 prisma，必须用 `createRequire` 以 `server/` 为基准（不能裸 import）。
