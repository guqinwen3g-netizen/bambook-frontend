## 一、我定的一个关键设计决策（请追认）

**货权字段放在 `InventoryItem`（「这批货」），而不是 `Warehouse`（「这个仓」）。**

矩阵原文写的是「新增仓库类型 + 货权标记」，读起来像把货权挂在**仓**上。但我按行业实务判断挂在**货**上，理由：
- **同一个第三方仓里可能同时存在我方货权（Owned）与货权已转移（Transferred）的货** ——
  挂在仓上表达不了这种混合；
- 货权是**这批货的法律/权利状态**，会随「货权转移时点」变化，而仓是物理位置，两者正交。

（已加单测钉住这个场景：「同一仓混合货权」用例。）

**汇总纪律（T7-① 教训的直接迁移）**：
- **数量按 `unit` 分组**——M / YD / KG / PC 相加没有意义；
- **金额按 `currency` 分组**——跨币种相加没有意义；
- `ownedOnly` 只含 `Owned`（**报表口径：货权已转移的不得计入我方存货**）；
- 无 `unitCost` 的项**不计入金额**（不猜成本）。

**真库实测印证了这条纪律的必要性**：真库汇总输出 `Owned: 48921.9M + 1800PCS` ——
若不分单位就会得到「50721.9」这个没有意义的数字（与 T7-① 的「USD 10000 + CNY 5000 = 15000」同类错误）。
