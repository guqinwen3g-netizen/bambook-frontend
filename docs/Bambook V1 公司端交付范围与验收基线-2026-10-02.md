## 已确定的范围

1. 全景看板从公司端首页及导航移出，作为与公司端、客户端、供应商端平行的第四个数字大屏端保留后续归属。本轮不开发数字大屏。
2. AI 助手、数据中心明确显示“开发中”，以占位页面保留。占位不能先挂载原功能再覆盖遮罩，也不能由其公司端入口启动功能请求、AI 任务或后台续跑。底层业务数据库和正常业务页面的数据获取继续工作。已提交的修复与历史证据保留；AI 原任务恢复 B 不再作为本轮阻断或继续开发。
3. 业务工具箱仅存独立实用工具，例如计算器和汇率换算。发货通知、合同、CI、装箱单及其他业务单据回到所属业务流程，从原订单、实际行目、原运单等明确来源生成，遵守原权限、业务状态及留痕。工具箱不再保留这些制单入口或绕到制单页面的跳转卡。
4. 经营驾驶舱改名 Dashboard，成为每个账号登录后的首页。首页按当前账号的实际责任和权限呈现当日待办、需推进事项、异常与快捷操作；操作直达原业务对象及对应步骤。不能只改名称，也不能让所有账号看到同一组九张经营图。财务、成本等敏感数据仍受当前权限和数据范围约束。
5. 智能邮箱按 2026-10-03 最新明确决策重新纳入 V1。必须完整打通收发、草稿、附件、回复全部/转发、文件夹与持久标记、搜索、当前账号权限、原业务关联、分类跟进以及发送结果恢复；只恢复旧入口不算完成。
6. 除以上豁免外，所有公司端页面及必要子页面均须在 V1 交付，不能用未声明占位缩小范围。功能、模型、业务变体、角色分工、交接和数据联通都必须有真实软件验收证据。

## 登记与验收规则

当前页面注册有 35 项；正式范围登记为 32 项必交模块、2 项开发中占位、1 项公司端移出。设置的账号/系统子页面和其他模块子视图仍在必交范围内。完整逐项清单见同目录交付范围 JSON；此数字表示范围，不表示已通过页面数。

推进顺序为：固定范围和入口 → 收拢无上下文单据入口 → 构建真实岗位 Dashboard → 按当前业务缺陷修复和原流程验证 → 同一候选完整回归 → 更新本地测试环境 → 用户人工验收。装箱和收费创建的真实 PostgreSQL 事务、并发、精度、撤权、原回执验证继续进行。

每项只有可追溯证据满足要求后才记通过。局部测试绿、服务启动、模型登记和源代码扫描均不能代替完整页面或 V1 交付通过。完整面料/成衣流程须使用原记录和真实软件操作，不伪造批准、库存或财务事实。

最终交给用户的是可实际操作的公司端 V1 候选，包含当前范围的完整页面、清晰的剩余限制和固定版本证据。用户后续人工审核用于实际使用及优化；不能把软件层已知阻断留给用户排查。
