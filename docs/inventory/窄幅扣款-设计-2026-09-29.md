## 一、口径（使用方 2026-09-29 晚，问答原话）

**问**：幅宽实际量出来以后，你想把它录在系统的哪个地方？

> 「这里几个关键点，我们可能有这个颗粒度口径的差异没有搞清楚，就是你说第三方测试是指 ITS 之类的嘛，
>  **这些不用我们管**。这些我们只要把样品寄给他们，他们自己去管，包括他们的结果，也是主要发给客人的，
>  **跟我们没有关系**。然后如果说是 QC 的话，**这不是属于第三方 QC，是属于我们内部的 QC 团队**，
>  服装面料我们都会派 QC 出去查货验货的。然后这部分我们肯定是**自己去在 QC 的工作过程当中把它记录下来的**。」

⇒ ★★ 三点必须记住（我第一版理解错了其中一点）：
1. **第三方送检（ITS/SGS/SGS 那类）不是这件事的载体** —— 我们管不到、结果也不给我们；
   ⇒ 落在 `TestRequest` 是**错的**（我起初就是那么打算的，被这句话拦下）。
2. 幅宽 = **我方内部 QC 出去查货验货时量到的值** ⇒ 载体 = **那次查货的验货记录**（`InspectionReport`）。
3. 记录发生在 **QC 的工作过程**里 ⇒ 入口应该在 **QC 工作台**，不是订单页、也不是财务页。

**问**：扣款比例乘在什么金额上？

> 答：**该订单行的货款金额**。

⇒ 基数 = `OrderLine.netValue`（真源：`order/orderAmountRecalc.ts`「订单金额 = 明细行合计，主档金额由明细行派生」）。
★ 特意**不是**整单金额、也**不是**该票出运金额。

## 二、真实规则（库内已抽取的客户质检标准）

`docs/inventory/业务能力清单.md` §7.2（源：`02-Knowledge/质检标准/PEERLESS产品标准要求_20260105.docx`）：

> | **幅宽** | 可用幅宽 **≥147CM**；**窄幅索赔扣款**：偏差 **≤3%→扣10%** · **≤4.5%→扣25%** · **≤6%→扣30%** |

════ 由此推出两个**必须**的性质 ════

1. **量纲 = 幅宽偏差 %**，不是幅宽绝对值（cm）。
   各客户的可用幅宽不同（147 / 150 / …），用 cm 分档等于给每个客户重算一遍区间 —— 多一次换算多一次错。
2. **幅宽扣款没有出厂默认**（沿用公差标准那批的刻意取舍）：
   数量公差那套 ±5/3/2/1% 是"某一个客户的 PO"，抄不来幅宽扣款；没有可引用的参考数值就**宁可不给**。

| | 修前 | 修后 |
|---|---|---|
| 注释 | 「幅宽扣款比例分档（**按幅宽**选档）」 | 「（**按幅宽偏差 %** 选档）」 |

## 四、落点与形状

### 4.1 新表 `InspectionWidthMeasurement`（迁移 `20260929220000_add_inspection_width_measurement`）

| 列 | 说明 |
|---|---|
| `reportId` | 哪一次查货（事实来源） |
| `orderId` / `orderLineId` | **哪一支面料** —— 索赔基数按订单行算，不按行就算不出钱 |
| `measuredWidthCm` | QC 实测幅宽（cm）★ **NOT NULL** |
| `basisWidthCm` | 基准幅宽（合同/PO 可用幅宽，cm）★ **NOT NULL** |
| `note` | 备注（如"第一支布"） |

★★ **两列幅宽 NOT NULL 是刻意的**，与"可空 = 未录"那条纪律方向相反：
   这条路**没有"半条记录"的合法形态** —— 没有实测谈不上量过；没有基准**算不出偏差**。
   宁可不建这条记录，也不许拿别处的默认幅宽替它猜基准（R6）。
★ `@@unique([reportId, orderLineId])`：一份报告里同一行只留一条（修正 = 覆盖，不堆历史）。
★ 为什么**不是**给 `InspectionReport` 加两个列：一张订单常有多支面料（多行），
   加在报告级就只能记一次 ⇒ 要么算不出钱，要么逼人开多张报告。

### 4.2 写入：QC 工作台「完成任务」时随报告提交

`server/src/qc/qcService.ts` 的 `completeAssignment()`：
- 新增入参 `report.widthMeasurements?: WidthMeasurementInput[]`（可空 ⇒ 不录幅宽也照旧能用）；
- ★★ **先校验后写**：`normalizeWidthInputs()`（纯函数）+ 「订单行必须属于本订单」——
  否则先建了报告、再发现数据非法，会留下"报告已存在但数据没录全"的死结（重试会撞"报告已存在"）；
- ★ **报告 + 幅宽实测同一事务**（`$transaction`）：要么都在、要么都不在，不留半截 QC 记录。

### 4.3 判定与建议（`orders/toleranceStandardService.ts`）

| 函数 | 作用 |
|---|---|
| `widthDeviationPct(basis, measured)` | 纯函数：偏差 %（**正数 = 窄于基准**）；基准缺失/≤0/非数字 ⇒ `null`（不猜） |
| `evaluateWidthDeduction({basis, measured, lineNetValue, tolerance})` | 纯函数：偏差 → 比例（**与数量公差同一套标准链**）→ 建议额（`suggestWidthDeduction`），★ **不写任何东西** |
| `loadWidthMeasurements(prisma, orderId)` | 读该订单**每行最新一条**幅宽实测（历史不丢，视图按最新算）；★ 读失败**抛**，不许返回空 Map 冒充"没量过" |
| 订单视图 `getOrderToleranceStatus` | 每行新增 `widthDeduction`（`null` = 还没量过）+ 顶层 `widthMeasurementUnavailable` |

三个判定出口（`verdict`）：`ok`（够宽，不扣，**不需要标准**）/ `deduct`（窄了且算得出比例）/ `undetermined`（缺数据 / 未录标准 / 落档位空档）。

### 4.4 ★★ 落地时踩到的一个真陷阱（值得记）

`gateToleranceOf()` 在"未判定"时给的是 **`pct: 0`**（数量口径下"按 0 卡"的语义）+ 非空 `unresolvedReason`
—— **不是** `pct: null`。我第一版按 `pct == null` 判未判定 ⇒ 未判定会被当成"**扣 0%**"静默放过去，
正好与"不拿默认假设冒充客户条款"相反。⇒ 判据必须是 `unresolvedReason != null`。已写成断言。
另：`gateNote` 那句话是**数量**口径的（"按不放溢装处理、上限 = 合同量"），**不许**抄进幅宽语境。

### 6.2 录入：QC 工作台「完成验货」表单
`components/QcWorkbenchManager.tsx` 新增「**幅宽实测（可选）**」区块：
- 每行 = 选**本单订单行** + 实测幅宽 + 基准幅宽 + （可选）备注；带**行内即时偏差**显示；
- ★ **三态严格分开**：`加载中` / `加载失败（明确报错并停用录入）` / `就绪（空数组 = 本单确实没有行）` ——
  读不到时**绝不**渲染成"没量过"（那会把故障读成业务事实）；

- ★ 校验口径与后端 `normalizeWidthInputs` 同形（前端为提前反馈、后端才是真防线）：空行跳过、
  选了行缺数/重复行 ⇒ 报错。
- ⓘ 这里**只即时显示偏差**、不显示"扣多少 / 建议扣多少钱" —— 扣款比例要按**客户标准**算，
  前端没有那条标准链 ⇒ 提交后看订单详情的「幅宽扣款」列（不在这里编一个数）。

### 6.3 展示：订单详情「溢短装条款」新增「幅宽扣款」列
`components/order/OrderToleranceSection.tsx` 新增一列，四态分明：
| 状态 | 显示 | 为什么 |
|---|---|---|
| 表读不到 | 读取失败 | **不许**显示成"未量" |
| 无实测记录 | 未量（QC 查货时未登记） | "还没量"与"量了算不出"是两件事 |
| 够宽 | 不窄（偏差 x%） | 不需要标准 |
| 窄了且算得出 | 扣 N% · 建议额 + "偏差 x% · 来源 · 仅建议，不落账" | 建议不是账 |
| 窄了但算不出 | 未判定 + 偏差 x%，原因挂在状态列下方 | 未判定必须给原因与下一步 |

★ 顺带：`types.ts` 的 `ToleranceSource` 补上了 **`internal_default`**（前端此前漏了"我方标准（出厂默认）"这一层，
来源标签会显示成空）；`fmtPct` 放宽到可空（`null` ⇒ `—`，避免 `NaN%`）。
