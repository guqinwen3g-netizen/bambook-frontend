## 1. ① 类：会让数字错 / 越权 / 丢数据（**10 条**）

### ①-1 超短装容差**没有按数量分档** `[PO]`
- **真实规则**：1–999m **±5%** · 1000–3000m **±3%** · 3001–5000m **±2%** · 5001m+ **±1%**
- **软件现状**：`OrderLine.tolerancePercent Decimal @default(5)` —— **一个扁平百分比**
- **危害**：5001m 的单若沿用默认 5%，系统**放行一个超出合同 ±1% 的出运** ⇒ **数字错**
- **修法（不重构）**：加**按数量取容差**的单一真源函数，`tolerancePercent` 保留为**覆盖值**；
  默认从分档表取。★ 不新增字段、不改流程

### ①-2 **大货批准（bulk approval）** 在系统里没有对应物 `[PO]`
- **真实规则**：「bulk approval must be sent 1 week prior to ex-mill」⇒ 合同强制前置
- **软件现状**：搜 `bulkApproval`/`大货批准` 无生产代码实现（命中的是"开发单转大货订单"，**语义不同**，已复核）
- **危害**：前置可被跳过 ⇒ **越权/失控**

### ①-3 **<20kg 按体积重** 无实现 `[PO]`
- **真实规则**：「SHIPMENT LESS THAN 20 KILOS, VOLUME WEIGHT NOT ACTUAL WEIGHT」
- **软件现状**：`shipmentPackingService.ts` 有 **volume/CBM** 推导（L×W×H÷1e6），但**无计费重/体积重**规则
- **危害**：运费/成本算错 ⇒ **数字错**

### ①-4 **B31 表（出运 > CAD 10,000）** 无实现 `[PO]`
- **软件现状**：生产代码零命中（仅测试文件）；已复核
- **危害**：单证不全 ⇒ 清关受阻

### ①-5 **5 份签名加拿大海关发票 + 附样布** 无实现 `[PO]`
- **危害**：同上

### ①-6 **迟于 ex-mill 5 个工作日 ⇒ 空运费归供应商** 无罚则判定 `[PO]`
- **软件现状**：有 `exMillDate` 字段，**无"5 工作日 + 空运费归属"的判定**
- **危害**：罚不到供应商 ⇒ **钱错**

### ①-7 **窄幅索赔扣款比例** 无实现 `[QC]`
- **真实规则**：幅宽偏差 ≤3%→**扣10%** · ≤4.5%→**扣25%** · ≤6%→**扣30%**
- **危害**：索赔**算不出来** ⇒ **钱错**

### ①-8 **QC 检测项没有阈值** ⇒ 判不了"合不合格" `[QC]`
- **真实标准**：20+ 项，每项带阈值（pH 6~8 · 甲醛 ≤75ppm · 克重 ±5% · 缩水率家庭≤3%/干洗≤2% …）
- **软件现状**：`TEST_ITEMS` **9 个扁平项** + `TEST_RESULTS = ['pending','pass','fail']` **手填三态**
- **危害**：**阈值在人的脑子里**，系统只存结论 ⇒ 不合格品可能被放行 ⇒ **质量判定失效**
- ★ 已语义复核：`qc/qcService.ts` 的 `≥90% / ≤3%` 是**验货放行口径**，**不是逐项阈值**

### ①-9 **QC 同一项按条件分档无处表达** `[QC]`
- **真实**：缩水率分 **家庭洗涤 / 干洗 / 氨纶混纺** 三套；色牢度分 **干摩擦 / 湿摩擦 / 干洗 / 漂白 / 日晒**
- **软件**：各只有**一个扁平项**（`shrinkage` / `color_fastness`）
- **危害**：同 ①-8

### ①-11 **回潮率（moisture regain）无实现** `[采购合同]`
- **真实条款**：合理损耗「**按 18.25% ±1% 回潮计算**」（毛纺业务的核心计量规则）
- **软件现状**：搜 `回潮`/`moistureRegain`/`regain` ⇒ **零命中**
- **危害**：合理损耗、结算重量**算不出来** ⇒ **数字错**

### ①-11 **回潮率（moisture regain）无实现** `[采购合同]`
- **真实条款**：合理损耗「**按 18.25% ±1% 回潮计算**」（毛纺业务的核心计量规则）
- **软件现状**：搜 `回潮`/`moistureRegain`/`regain` ⇒ **零命中**
- **危害**：合理损耗、结算重量**算不出来** ⇒ **数字错**

### ①-10 **真实报表字段无处可放**（`OrderLine` 缺 4 个字段）`[SR]`
| 真实字段 | 软件 | 危害 |
|---|---|---|
| `Meters Needed`（需求米数） | 无（只有 `quantity`） | ★ 与 ①-1 同源：**容差该按哪个量算？系统没得选** |
| `Price Confirmed`（价格已确认） | 无 | 价格是否已确认**无留痕** |
| `Ship-To`（**行级**收货地） | 无行级字段 | 真实报表**每行一个 Ship-To** ⇒ **丢数据** |
| `Priority` | 无 | **丢数据** |
| `ZROH`（客户料号） | 疑似 `materialCode` | ⚠️ 若 `materialCode` 是"我方料号"，则客户料号**无位可放** ⇒ 需业务确认 `[?]` |

## 4. ★★★ 头号发现：**软件生成的销售合同，条款是错的**

### 4.1 事实（两处代码 + 两份真实合同对撞）

**软件生成的合同**（`server/src/templates/docTemplates/contract.ts:178-190`）：
条款区**只有 4 条**：
```
Delivery 交货：        {deliveryTerms}
Payment 付款：         {paymentTerms}
Quantity Tolerance 溢短装： 按各订单行级溢短装条款执行（默认 ±5%，行业惯例）。
General 一般条款：      …以「订单一览」与「合并明细」为准；如与订单原始文件冲突，
                      以买卖双方书面确认的最新版本为准。
```

**真实销售合同**（OCR，`PO#4500157698&4500157747_SALES_CONTRACT.pdf`）条款区有：
```
1. 装运期 Date of Shipment：…（允许溢短装 1%）
2. 装运口岸和目的地
3. 保险：□ 由出卖人按发票金额 110% 投保一切险及战争险，按 1981/1/1 中国人民保险公司条款
        □ 由买受人自理
4. 支付方式 Terms of payment
5. 品质数量异议、索赔：货到目的口岸 30/15 天内提出，凭公证机构检验报告
```

### 4.2 两处**实质错误**

| # | 软件写的 | 真实合同写的 | 性质 |
|---|---|---|---|
| **1** | 溢短装「**默认 ±5%，行业惯例**」 | 销售侧：**按数量分档**（1–999m ±5% · 1000–3000m ±3% · 3001–5000m ±2% · 5001m+ **±1%**）；采购侧：**±1%** | ★★ **把"错的口径"印在对外合同上** |
| **2** | **没有**保险条款 | **发票金额 110% 投保一切险及战争险**（PICC 1981/1/1） | 条款缺失 |
| **3** | **没有**索赔期条款 | **货到目的口岸 30/15 天内**提出，凭公证机构检验报告 | 条款缺失 |
| **4** | **没有**装运期/口岸/目的地 | 有 | 条款缺失 |

### 4.3 ★★★ 为什么这是**头号**发现

1. **不是"缺功能"** —— 合同**能生成、能打印、能导出**，功能测试**全绿**
2. **不是"报错"** —— 没有任何异常、没有任何红
3. **是"软件主动写了一句错话，还印给客户看"** —— 而那句话（±5%）**与合同实际条款（±1%/分档）相反**
4. ★ 它还带一条**兜底免责**：「如与订单原始文件冲突，以买卖双方书面确认的最新版本为准」
   —— **这正是把问题盖住的东西**：出了问题，系统可以说"我提醒过以原始文件为准"

⇒ 这**同时**印证使用方的两句话：
- 「**低端设计在应用层面貌似可以通过，但没有意义**」
- 「**以业务员/管理员这样的真实生产角色上手**」——一个业务员用这个系统出合同，
  **会把一份条款错的合同发给客户**，而**系统不会告诉他**。

### 4.4 定性

| 项 | 结论 |
|---|---|
| 分类 | **① 类**（会让数字错 + **对外文件错误**） |
| 风险等级 | ★★ **最高**（对外的、可被客户发现的、与合同不符的） |
| 危害 | 出运量按错容差判 ⇒ 超容差出运被放行 ⇒ **客户索赔**；保险/索赔期缺失 ⇒ **争议时无依据** |
| 修法（不重构） | ① 把容差从"扁平默认 ±5%"改为**按数量分档的单一真源**；② 给合同条款区**补上真实条款**（保险/索赔期/装运期），字段来源落 `Order` 或行级；③ **删掉"行业惯例"这种自我背书** |

### 4.5 诚实边界
- 我读了**一份**销售合同 + **一份**采购合同的条款区（其余 44 份 OCR 后**未逐份比对条款**）
- "软件合同模板只有 4 条"是**读源码**得出（`contract.ts:178-190`），可复核

## 5. ★ 头号发现的**量化**（全部 44 份合同，不是单样本）

| 条款 | 含该条款的合同数 / 44 | 占比 |
|---|---|---|
| **保险**（发票金额 110% 投保一切险及战争险） | **37** | **84%** |
| **索赔/异议**（货到目的口岸 30/15 天内，凭公证机构检验报告） | **41** | **93%** |
| **溢短装/公差** | **37** | **84%** |

★ 保险条款的写法**高度一致**（OCR 后去重）：
```
由出卖人按发票金额 110% 投保一切险及战争险
```
（OCR 把"出卖人"识别成"出人/出尖人"，是识别噪声，不是文本差异）

### ⇒ 结论升级
这不是"某一份合同的特殊条款"，而是**这家公司合同的**标准条款**：

## 16. ★★ 又一层：**"裸印"的根因有三种，修法完全不同**

修 `DocumentCenter` 时把这一族**拆成了三种根因**（**这次没有一律当"忘了用标签表"处理**）：

  Draft: 'Draft', Issued: 'Issued', PartiallyPaid: 'Partially Paid',
  Paid: 'Paid', Cancelled: 'Cancelled',

★★ **内部界面需要的是另一套中文标签，而那套全仓不存在**（搜 `已开票/部分核销/已结清` 零命中）。

**产品状态** —— `components/ProductsManager.tsx:491`：
```ts
const PRODUCT_STATUS_OPTIONS = [
  { value: 'Development', label: 'Development' },
  { value: 'Active', label: 'Active' },
  { value: 'Archived', label: 'Archived' },
];
```
★ **label 与 value 一模一样** ⇒ 也没有中文。
★ 对照：**同文件的 `GARMENT_STATUS_OPTIONS` 用的是中文值**（`'开发样'`）⇒ **两种产品类型不一致**。

### 16.2 ★ 我提出的草案（**待你定，不是替你定**）

**发票状态 → 中文**（内部界面用，与客户门户那份**并存不冲突**）：

| 枚举 | 建议中文 | 备注 |
|---|---|---|
| `Draft` | 草稿 | 与 `DOC_STATUSES` 的 '草稿' 一致 |
| `Issued` | 已开票 | ★ **不叫"已签发"** —— 发票语境下"开票"更准 |
| `PartiallyPaid` | 部分核销 | 与仓内既有说法一致 |
| `Paid` | 已结清 | |
| `Cancelled` | 已作废 | |

**产品状态 → 中文**：

| 枚举 | 建议中文 |
|---|---|
| `Development` | 开发中 |
| `Active` | 启用 |
| `Archived` | 已归档 |

★ **两张表我都没有写进代码** —— 因为**术语一旦定下就进了对外界面**，
**属"产品决定"**，不是"修 bug"。★ 你说"用"我就落码；你说"换词"我改词。

### 16.3 ★★ 纪律（第 9 条，本次固化）

**"裸印枚举"是一个症状，不是一个病。** 拆根因至少三种（**没引 / 够不到 / 根本没有**），
