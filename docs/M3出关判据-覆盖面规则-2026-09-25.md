## 一 判据（三条一起满足才算 M3 出关）

1. **三类对撞各必须有**（不许只挑一类）：
   - **① 主档 vs 明细行**：主档上的金额/数量与明细行汇总互相对得上；
   - **② 派生量**：**至少覆盖「毛利 / 未收额 / 逾期额」**（这三条是"算错不报错"的高危面）；
   - **③ 跨视图同值**：同一笔业务在**列表 / 详情 / 账龄 / 驾驶舱 / 利润表**五面取到同一个值。
2. **每条对撞必须带"能红的阳性对照"**：即有一条**已知会失败的构造**（改一个数/换一条路径），
   跑它必须红。**没有阳性对照的"通过"不算通过**（本仓老病：恒等式没有牙齿）。
3. **结论必须标「输入为模拟数据」**，并写明库名 + 有没有常驻后端在跑。

> 数字**由规则派生**（三类各若干条），**不再钉死"8 个"**——这是 Kevin 拍这条时明确要改的地方。

## 二·补：② 毛利 / ③ 利润表 为什么接不上 —— **是数据缺口，不是功能缺口（本批实测）**

只读查库（`panda_hub_local`，2026-09-25）：

| 量 | 现量 |
|---|---|
| `order` 总数 | **1069** |
| 带 `supplierInvoiceAmount` | **0** |
| 带 `purchasePrice` | **0** |
| 带 `shipmentAmount`（毛利口径的收入侧） | **0** |

而驾驶舱的毛利正是这么算的（`dashboardService.ts:425-461`）：
`收入 = shipmentAmount ?? orderAmountOf(o)` · `成本 = supplierInvoiceAmount ?? (purchasePrice × quantity)` ·
`毛利 = 收入 − 成本（成本为 null 则毛利为 null）`。

⇒ **1069 张订单没有一张有成本数据** ⇒ 毛利全为 `null` ⇒ 驾驶舱那 69 行**整片被排除**（`excludedCount: 69`）。
⇒ 这不是"算错"，是**没有输入**。同理，`OrderProfitSheet`（模型确实存在）按订单资金链聚合，**没有成本就没有毛利**。
