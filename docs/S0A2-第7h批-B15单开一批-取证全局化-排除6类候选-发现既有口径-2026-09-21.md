## 一、做了什么

### 1. 取证**全局化**（从"一个文件里的埋点"变成"全仓自动"）

- **新建共用工具** `server/src/shared/__tests__/utils/httpEvidence.ts`：
  `httpEvidence(res)` 打出应答指纹（`body/ct/server/allow/powered/seenBy/text`）+ `expectStatus(res, n, label)`。
  ⚠️ 此前这份埋点只写在 `system-assets/__tests__/route.test.ts` **一个文件里** —— 属"判据活两处"的同型问题（R2）⇒ **收成一份**。
- **`server/src/test-setup.ts` 加全局取证**：patch `supertest.Test.prototype.end` 记录最近 8 次响应，
  `afterEach` 判定**仅当该用例失败**时打印指纹 ⇒ 随全量日志**落盘**。

**实测两条性质**（不是写完就信）：
| 性质 | 实测 |
|---|---|
| **失败时打印** | ✓ 故意失败用例打出 `[0] GET /ok :: status=200 ct=application/json; charset=utf-8 server=- powered=Express allow=- text="{\"ok\":true}"` |
| **通过时不打印** | ✓ 通过用例零输出（否则 6900 个用例的日志会被淹没） |
| **不改变任何测试行为** | ✓ 全程 try/catch、只记录；跑代表性 7 个域 **48 文件 / 668 例全绿** |

### 2. **排除 6 类候选**（逐条有命令，这是本批的实质产出）

7f 拿到的字面证据是：`404` + `ct=text/plain; charset=utf-8` + `server=-` + `allow=-` + `text=Not Found`。

| 候选 | 实测结果 | 结论 |
|---|---|---|
| 裸 **Express 4.22.1** 默认 404（本仓用 Express 4） | `text/html` + `<!DOCTYPE html>…<title>Error</title>` | ❌ **不是它** |
| **沙箱代理 `127.0.0.1:62177`**（环境设了 `HTTP_PROXY`/`http_proxy`，**无 `NO_PROXY`**） | **502** + `upstream connect failed: Connection refused` | ❌ 不是它 |
| `127.0.0.1:3210` 的 404 | `text/html` + `X-Powered-By: Express` | ❌ 不是它 |
| `127.0.0.1:3211` 的 404 | `application/json` | ❌ 不是它 |
| `127.0.0.1:5173`（Vite）/ `:3000`（dev server） | 未知路径 **200 + text/html**（SPA 回退） | ❌ 不是它 |
| `127.0.0.1:1082`（MacPacket 代理） | **405** + `text/html` | ❌ 不是它 |
| **本仓 `server/src` 全部代码** | 无 `Not Found` 字面量、无 `res.type('text/plain')`、无 `sendStatus(404)` | ❌ 不是它 |

### 3. ★ 指纹指向（**推断，未证实 —— 不许当结论写**）

`404` + **`text/plain; charset=utf-8`** + 正文恰为 **`Not Found`** 是 **`res.sendStatus(404)`** 的默认形状
（Express 的 `sendStatus` 把 body 设为状态短语、ct 设为 `text/plain`）
⇒ 应答者是**另一个 Express 应用**，且**不是本仓 `src` 里的代码**。
**下一步**：等下次红，用新埋点判定"请求是否到过被测应用"（`httpEvidence.ts` 里已预留 `EXPECT_APP_HEADER` 用法）。

### 4. ★★ 发现**既有口径**：B15 不是新问题，配置里 2026-08-19 就登记过

`server/vitest.config.ts` 里写着（原文摘录）：

> 【登记 2026-08-19】全量串跑仍有既有的「每轮约 1 个随机模块失败」抖动（观察：shipping orderLink / admin auditLogs / moq 等
> mock+supertest 用例，**错误表现为 HTTP 状态码/响应体随机错位**，隔离跑全绿）。曾试 `pool:'threads'+isolate:true` 未消除，
> 故判定非 vi.mock 模块串扰，更可能是**残留 setInterval/异步句柄**或**共享 Postgres 定时任务**在 72s 全量跑中途触发的**时序类抖动**。
> 待后续系统二分定位（scheduler/pdml/ai SSE 候选）。
> **未定位到根因前，单测全绿请以「隔离/定向跑」为准，全量单次失败不判回归。**

⇒ **两个后果**：
1. **D56 不是新放松，而是对既有口径的确认与引用** —— 我已在 §12.05 D56 里**公开补记**这一点
   （本条新增的只有"把域测试+探针写成每批必做产物"+"门禁仍每批跑"，**比既有口径更严**）。
2. **B15 的候选机制早就有三条**（残留定时器 / 共享 PG 定时任务 / SSE）—— 本批新增的是
   **一条可排除清单** + **一次"指纹指向另一个 Express 应用"的推断**，**不是**从零开始。
