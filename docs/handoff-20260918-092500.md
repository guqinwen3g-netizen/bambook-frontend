## 四、五条修复的要点（设计决策都在代码注释里，这里只列接手要知道的）

### A2（`06d186c6`）
- **先纠正一个口径**：账龄 / 授信 / 催办**本来就按 `Invoice.customerRelationId`（合同客户）归集，是对的**
  ⇒ 清单里「账龄/授信记到代付方头上」这一句**不准确**。真正的缺口在**收款侧**：
  `getCustomerStatement` 一律 `where: { customerRelationId, type:'Receipt' }`（= 打款人口径）
  ⇒ A 替 B 付的钱 **B 的对账单上查不到**（客户拿水单来对不上），A 的对账单凭空多一笔无发票收款（余额变负）。
- 修法 = 新真源按「核销了谁的票」重算归属；**自付场景输出与改造前逐字节一致**（合并成一行全额），
  所以这是**纯增量**，不制造回归。
- 对账单/单据模板带 `isThirdParty` / `payerName` / `note`（发给客户的对账单必须写清谁付的）。

### A4 + A1-b（`5cd81a5f`）
- **PG 的唯一约束把 NULL 视为互不相同** ⇒ `@@unique([shipmentId, orderId, orderLineId])` 对**整单分配**
  （`orderLineId IS NULL`）**完全不生效**，可以无限插。⇒ 只能服务层挡。
- 挡两种：① 完全同键（含 NULL 分支）② **粒度混用**（整单与行级并存 = 同一批货计两次）。
- **A1-b 是顺带发现的「收口点错位」**：A1 只锁了 PATCH（改），漏了 DELETE（删）。
- ⓘ **残留（诚实声明）**：并发双写仍有小窗口（READ COMMITTED）。根治要加 partial unique index
  （`WHERE orderLineId IS NULL`），但**生产库若已有历史重复行，建索引会让迁移直接失败、打断部署**
  ⇒ 本轮不迁，留给运维在清完重复行之后再加。

### A5（`5585752a`）
- 原设计是「Cancelled 不联动订单，留人工」⇒ 但**库存已反向回冲、货已回库**，订单却仍卡 `Shipping`，
  且人工既没入口也不知道该退回哪一档。
- 修法：**合票/分批感知** —— 该订单还有别的在途票就不回退（不误退）；
  回退目标取自 `OrderStatusTransition` 里最后一条 `toStatus='Shipping'` 的 `fromStatus`，
  取不到 → `Confirmed`（**不猜 Pending**：Pending 是「未确认」语义，把已生产已出运的单退回未确认是错的）。
- 取消时**合票订单（经 `ShipmentOrderAllocation` 关联）一起回退**（原来只回退主订单）。

### B2（`2388f598`）
- `ExchangeRate.rate` 语义 = **1 单位外币兑 CNY** ⇒ A→B 必须**经 CNY 过桥**（`rA / rB`），不要自造直盘。
- 取数优先级：**锁汇（`FxRateLock`）> 市场汇率（≤ 业务日最近一条，无则回退最新）> null（不猜）**。
- 跨币种订单**不再整体排除**：折后成本 `costInSalesCurrency` 计入合计
  （此前合计**系统性偏乐观** —— 被排除的恰恰是汇率风险最大的那批单）。
- ⓘ CNY 的汇率恒为 1（表里不存 CNY 行，硬编码是唯一正确解）；来源标记只数**外币侧**（否则会把
  「销售美元锁汇、采购人民币」误标成 mixed）。

### B3 + 收口（`7d047a8b`）
- 锁从「只锁交期」扩到 **delivery / price / quantity**；改价/交期 → 已出运即拒
  （出口 = 「订单状态回退 Confirmed」审批链，**出口已存在 ⇒ 不是死锁**）。
- **改量的判据必须是「改后 < 已出运量」而不是「已出运就挡」**：订单 10000、已发 6000、
  客户说剩下 4000 不发了 —— 这是**合法减量**，一律硬挡会把正常业务卡死。
- 判定**不只看 `Order.status`**，还查「该订单名下有没有已离厂的运单」⇒ 合票订单（状态没跟上）也挡得住。
- `customer` / `product` **刻意不硬锁**（主体描述，出运后仍有合法更正，且本身是 high-risk 审批）。
- **收口**：本仓曾有 **5 处**各写一份同样的「已发运」4 值集合 ⇒ 全部收口到 `shared/shippingLock.ts` +
  结构守卫（源码扫描：**内容与真源完全一致**的内联集合即红）。
