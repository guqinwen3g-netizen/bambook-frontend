# UI04 开发管理复样与费用交接修复契约

本片处理开发管理的原生面料许可、同批复样及显示错误；执行结果由固定源码的隔离 PG 与浏览器证据另行登记。源码和替身测试本身不等于业务通过。

## 本片业务边界

1. 同一个 SampleBatch 的 `revise → revising → start` 才进入下一轮。`start` 从 revising 推进该 batch 的 round；不修改开发案 currentRound，也不修改其它工厂/独立批次。新独立批次始于 S1。
2. 最新客户反馈和复样使当前认可、设计批次确认、封样许可失效。客户正反馈亦须随后明确认可，不能借旧 approved 继续消费。`needs_recast`/`rejected` 永远不能由旧标签恢复当前许可。
3. 历史反馈、寄送、认可、封样、转档以 `attachments.fabricHistory` 追加事件保留。当前投影可清空认可主体/时间、确认主体/时间与封样基准；不删除历史档案 ID。
4. batch、seal、case→order、completed 结案的面料成果消费核当前有效事实。新原生 approve/convert/seal 事件必须有相符的 mandatory audit 依据。合法 legacy 记录只作为既有真实认可的兼容来源，不能覆盖当前负面反馈。
5. 父案→batch 锁后重新读取实际账号、scope、credential ceiling 与客户 L2，并核当前状态及原命令。转档 profile、source、mill、首档指向和 before audit 仅使用锁后的 liveCase/liveSource；并发其它批次转档不能被过时首档指向覆盖。
6. Agent 原生注册分派和正式 commit 均传实际 execution context.actor；ApprovalRequest.requesterId/tool body/after.actorId 不能替代当前身份。

## 字段与 API

- SampleBatch DTO 追加 `eligibility { eligible, assetCurrent, approvalAllowed, revision, reason }`。保留原字段和 response envelope。
- `attachments.fabricHistory { schemaVersion:1, revision, events[] }`。每个 event 保存稳定 id、kind、round、actorId、at、auditId、原命令 requestKey/fingerprint/input、before/after 快照。history 与 projection 与 audit 在同一事务。
- stage、customer-feedback、confirm 命令接受 `requestKey + expectedRevision + expectedRound`。同 actor/key/内容返回原事件 commandAck；变内容或版本/轮次失配拒绝。旧语法仍受真实身份、当前状态和许可检查，不提供授权兜底。
- 前端只在 batchId/kind/actor/key/原完整 commandInput 与 mandatory auditId/eventId 回执一致后清除命令。未知失败保留原请求，提供「重试原操作」，不得换内容悄悄重提。
- sessionStorage 只保存当前 actor/endpoint 的原命令恢复缓存；不保存 token，不作为许可/审计/提交成功事实。每次重试仍由后端当前授权检查。

## 原生界面与 BDS

- 「开始复样」收原因并说明下一轮；随后「复样开工」。负面反馈的旧 approved/converted 显示历史转档，不显示当前确认/转档入口；逐轮历史保留旧反馈及寄样金额。
- 建案/删除后旧 total 暂时失效，等待 authoritative list/total；不继续显示「1 行但共 0 单」。
- 工厂来源区分加载中、失败可重试、尚无供应商档案、全部可见工厂已在案。空库不声称全已在案。
- 使用既有 bds-btn、bds-input、badge、modal、compiled form primitives 与 tokens，不增全局圆角或容器层级。
- 当前身份/endpoint/permissions/ceiling/credentials 变化后重挂载；列表、关系、HR、批次、供应商、费用交接与 mutation 晚返回不得写回先前身份的状态/全局提示。HR personnel 仅当前 hr:read 才加载。

## 邮寄费与财务交接

SampleBatch.shippingFee 及 legacy case.sampleShippingFee 没有币种；45.5 是寄样登记信息，不能自动解释为 CNY/客户合同币种，不能自动求成财务成本。逐轮历史保留原金额；列表只显示有待核金额的案数，不跨币种求和为「寄样支出」。

「另登记实际费用」打开既有本案费用表单，明确原批次与轮次，amount 与 currency 留空，由实际凭据填金额、币种、日期/归属。本按钮和 callback 不表示已生成 CostRecord。本片不自动创建 CostRecord、不猜承担方、不绑定财务核齐状态。持久 CostRecord 与 batch/round/proof 的精确交接另片完成。

## 保留事实与未关闭范围

复样后再次转档产生新 ProductAsset ID。只有 case 当前首档指向为空或恰指向本来源的旧资产时，才更新当前 case 指向；其它工厂选定首档保持。旧资产 ID 可从既有转换审计与 history before/after 追溯。

旧 ProductAsset 手工建单及已有 ReleaseScope/生产执行是否可继续消费旧认可，不能靠查询 latest convertedProductAssetId 判断；必须稳定反查 native conversion audit、batch/seal/history，并追加暂停/失效事件保留原 ReleaseEvent。该下游由独立租约处理，本片不宣称全局放产门禁已完成。

转档 API 本片保留原成功响应和写入方式，尚未增加新的 stable requestKey 精确回执协议；未知转档响应失败需核原档案，不承诺自动重试不会重复生成资产。已存在的收样实物和历史结案保留，不能因复样把历史库存或 completed event 抹除。
