## 一、说人话：修掉之前是什么局面

`server/src/index.ts` 里还留着 7 条"老 broad-sync 面"（`app.all('/api/xxx', legacyWriteGuard(...), handleSync)`），
是给 Mac mini 切换期旧界面用的整表同步口。其中：

- **2 条根本不查权限**（`/api/dev-memory`、`/api/insights`）——守卫里写着 `if (!scope) return next();`，
  调用时少传一个参数，就变成"**任何登录进来的账号都能写**"：质检、物流、只读账号都一样。
- 写实现 `handleSync` 是 `model.upsert({ where:{id: item.id}, update: payload, create: payload })`，
  而 `payload = {...item}` 直接来自请求体 ⇒ **没有字段白名单、没有"这行归谁"的判断**
  ⇒ 越权方不只"能建"，还能**挑一个已存在的 id 把整行任意字段改掉**。
- 那 7 条上方的注释白纸黑字写着"写方法叠加 requireJwtForWrite + **对应域 write scope**" ⇒ 对这两条是**假陈述**。

## 二、修法（三条一起，都不新造政策）

1. `scope` 由可选改**必填**，并删掉 `if (!scope) return next();`。
   ⇒ 这一类缺陷从"靠人复核"变成**编译不过**（判据侧再钉一条源码普查，见 §四）。
2. `/api/insights` 挂 `knowledge:write`。**为什么是这一枚**（有出处，不是"挑一个能用的"）：
   `lib/rolePermissionMatrix.ts` 里 `[View.DataCenter] = { read: 'knowledge:read', write: 'knowledge:write' }`，
   而 `'knowledge:read'` 的描述原文是「知识库/**数据中心看板**查看」——Insight 正是那块的看板数据。
3. `/api/dev-memory` 改**只读**（`app.all` → `app.get` + `sdkAuth`）。
   ⇒ 它**没有**对应的 scope 出处（不像 insights 有 DataCenter 那条），"该给谁写"属政策，**不自裁**；
   而"开着写口但没人用"也不是安全状态 ⇒ 选择"先不开放写"。依据（都可复核）：
   两棵 checkout（本 worktree + 主 checkout 的 `App.tsx`/`services`/`server/src`）里 `dev-memory`
   **只出现在它自己的注册行**；`ProjectMemory` 在服务端也没有任何 service/路由使用；生产尚未部署 ⇒ 无历史流量可查。

## 三、修的时候撞到同一条上的第二个缺陷（顺带修掉）

`handleSync` 只有 GET 与 POST 两个分支，**其余方法两个 `if` 都不进、函数直接返回**——
既不 `res.xxx()` 也不 `next()` ⇒ **PUT/PATCH/DELETE 会一直挂着直到超时**。7 条面全注册在 `app.all` 上，
所以这四类方法是真的能进来的。现在给明确出口：`405 UNSUPPORTED_METHOD`（对外形状用本文件既有的 `{error, message}` 两键）。
⚠️ 这是本批**唯一新增的对外状态码**（全仓 `server/src` 此前 `status(405)` 命中 0 次）——
但替代项是"请求挂死"，两者不可同日而语，故仍选择明说。
