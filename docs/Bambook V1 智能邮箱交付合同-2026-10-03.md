# Bambook V1 智能邮箱交付合同

用户最新明确将智能邮箱重新纳入 V1。本合同规定实现及验收边界；写下合同不等于功能完成。固定诊断源为 de5c2f4c，当前邮箱源与 2a8e8dc2 一致。公司入口仍临时封存，必须完成关键修复和实际验证后接回。

## 员工应能完成的工作

1. 在获准邮箱收信、同步和搜索完整邮件，查看准确正文与附件；换账号、换文件夹、切服务地址不能串信。
2. 保存草稿，刷新后继续编辑；新建、回复、回复全部、转发时保留正确收件人、线程和人工选择的附件，真实发送并回读已发件。
3. 同时保存已读、星标、重要等标记，移动、归档、软删及恢复均由实际持久记录证明，不能只改变本地列表。
4. 从可见原客户、订单、发票关联邮件，生成有原邮件来源的跟进；分类明确区分规则结果、AI 完成及未配置/失败，不能用 AI 助手占位免除邮箱自己的交付要求。
5. 权限不足、连接失败、同步部分失败和发送结果不明有准确提示与恢复路径；刷新、双击、超时重试不会新建重复待发邮件或自动重复投递。

## 账号与可见性

当前 Email 没有邮箱账号或所有者字段，属于既有 emails:read/write 约束下的公司共享业务档案，不能宣称已经实现个人邮箱隔离。历史记录不凭 fromAddress 猜归属，不自动转为任意员工私人邮箱，也不因新合同扩大现有角色权限。

V1 正式接入采用受控邮箱账号：个人账号绑定明确的 ERP 主体，共享账号使用明确授权成员；读取和发送还必须分别满足当前模块权限。账号、服务器及允许的发件别名由受控管理入口维护，网络目的地受已登记配置约束。凭据只保存在服务器的密钥存储或授权的临时连接中，不存浏览器 localStorage、日志、URL 或响应体。旧共享档案保持显式历史来源，迁移必须可回读且不能把缺失归属假设成已确认。

邮箱账号模型及存量归属迁移单独成包；精确客户端读取包和发送记录包均不能替代该项验收。移除用户权限、停用账号、切换端点会使旧请求失效；附件、CID 与短期会话必须再次核验原邮件、原账号及当前主体。

## 发送意图与记录

每次明确创建待发邮件使用稳定 UUID 意图。当前主体、邮箱身份、收件人、正文和附件清单构成不可变发送内容指纹；相同意图重放回到原 Email，意图与内容不一致拒绝。不能收到不明结果就重新创建另一封 Outbox。

发送记录独立于通用 AuditLog。最小数据合同为 EmailSendIntent 与 EmailSendAttempt：意图关联准确 Email、创建主体、请求键、邮箱身份、内容指纹、稳定 RFC Message-ID；尝试保存序号、发送前持久 claim、发送状态、已接受和已拒绝的收件人、时间以及准确结果。Email 唯一发送意图与数据库约束防止本系统并发重复；凭据不写入这些记录。后续正式邮箱账号可关联稳定账号 ID，临时运输身份不可冒充对象权限。

状态至少区分 prepared、sending、accepted、rejected、unknown；部分收件人接受必须保存各自结果，不能将全部收件人记作成功，也不能向已接受收件人盲重发。prepared 到 sending 的数据库锁及原行复验先于网络。sending 崩溃或回执丢失进入待核对，绝不靠超时自动清空 claim。只有明确未接受的失败才能允许人工重试；accepted 复用原结果。旧直接 SMTP 路由必须并入同一核心或明确拒绝，不能保留旁路。

SMTP 已接受而业务更新/审计失败时，保留已有外部事实并进入恢复核对；不得报“没发送，可以重试”，也不得虚造 Sent 或审计。稳定 Message-ID 不代表第三方去重保证；SMTP 超时本身可能产生重复投递，须保守处理不确定结果。[RFC 5321](https://www.rfc-editor.org/rfc/rfc5321.html#section-4.5.3.2.6)

## 精确读取与附件

DB 邮件按准确 ID 请求详情，不以列表缓存正文作为当前授权证明。IMAP 读取身份包含邮箱账号、物理文件夹、UIDVALIDITY、UID；未知 UIDVALIDITY 时不复用旧 UID 正文缓存。协议中的持久身份由文件夹、UIDVALIDITY 和 UID 共同确定。[RFC 9051](https://www.rfc-editor.org/rfc/rfc9051.html#section-2.3.1.1)

发件附件先登记私有文件及内容哈希，发送使用已确认的不可变文件清单；不能接收任意服务器路径。回复线程、To/CC/BCC、文本/HTML 与附件须通过实际 SMTP MIME 解析验证。下载时核原邮件/账号、软删状态、文件路径与当前权限，旧静态存储不得旁路授权。

## 分包与交付证据

| 包 | 实现边界 | 通过证据 |
|---|---|---|
| A | 客户端 URL/认证/精确读取/上下文/分页/写权限 | 实际 DOM 与原公开路由的正负控；慢回包、账号及端点 ABA、同 UID 文件夹隔离；旧源撤回复现 |
| B | 稳定 Outbox 与持久发送记录、旧路由收口 | 独立 PG 及实际 TLS SMTP：并发同意图一次 DATA，接受后 DB 故障、回执丢失、进程恢复不再发送 |
| C | 受控邮箱账号、同步身份、私有附件及当前权限 | 真实 IMAP/PG/文件读取、主体隔离、尾部撤权、UID 变化和存量升级回读 |
| D | 草稿/标记/文件夹、回复全部/转发、发件附件 | 实际刷新续办、状态重读、完整 MIME 与附件哈希 |
| E | 原业务关联、分类、跟进、全页 BDS | 实际业务父对象权限和事务、分类状态、并发跟进，以及原界面操作和异常路径 |

这些包使用隔离的合成邮箱、独立数据库和本地 TLS 服务，禁止测试向真实联系人投递。每包冻结源码、环境、当前角色与原始结果，再独立复核、提交和应用测试环境。完整邮箱、32 个必交模块及整套 V1 当前均未通过；任何单包绿色都不能代替最后的完整公司端验收。
