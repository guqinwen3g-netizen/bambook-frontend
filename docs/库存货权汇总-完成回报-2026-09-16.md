## 三、堵掉的门控旁路（本批的意外收获）

上一批 `d169110` 把报表数据集 `inventoryItems` 的读 scope 收窄到 `inventory:read`
（因为该数据集含 `unitCost` 金额），理由是「否则持 `reports:write` 而无 `inventory:read`
的角色可经报表读到库存成本」。

**但同一份金额在 `GET /v1/inventory/summary-by-ownership` 上原本只有认证门** ——
于是形成旁路：报表侧被 403 的主体，直接打这个端点就能拿到按货权的成本汇总。

本批把两条路径拉成同口径。真库实测：

```

hank.zheng （单证，有 inventory:read）                  → 200
```

## 七、本轮踩的坑（接上批 19 条，共 21 条）

20. **JSX 文本里写 markdown 星号会原样渲染出来**。口径说明我写了「米和码…都\*\*不相加\*\*」，
    浏览器里就是字面的两个星号。**注释里写 markdown 没问题，JSX 文本里不行** ——
    这只能靠真浏览器走查发现（单测与 tsc 都看不见）。
21. **走查断言取到了整页文本 → 假绿**。U3 原本用 `querySelectorAll('div')` 找「含某文本」的
    最外层元素，把侧栏、账号名、调试面板里的数字一起算进来，于是「页面有数字」就通过。
    **必须在最小容器（`.bds-card`）内取文本**。这跟「守卫判据可能是逻辑空集」是同一类错误：
    断言要能证伪，就得让失败的输入真的落到断言上。
    （附带：`hasInnerText` 的选择器漏了 `button`，导致 Tab 文案找不到 —— 分段控件是 button。）
