### ★ 本轮拿到的硬证据：失败响应**不是本应用的格式**

`system-assets/__tests__/route.test.ts` 里**前序会话已埋了取证埋点**（`B15 取证`），第 2 轮的失败把它打出来了：

```
B15 取证 DELETE：body={} ct=text/plain; charset=utf-8 server=- allow=- text=Not Found
```

**可陈述的事实**：
- 该失败收到的是 **`404`**，`Content-Type` 为 **`text/plain; charset=utf-8`**，正文是 **`Not Found`**；
- 本仓的错误响应一律是 **JSON**（`{"error":{"code":…,"message":…}}` 或 `{"error":"CODE","message":…}`）；
- Express 的默认 404 也不是 `text/plain`（它返回 `text/html` + `Cannot GET …`）。

⇒ **这一次的红，不是被测应用答的。** 这与 §9 B15 早先记录的推断一致
（*"红时被本仓之外的应答者接走"*），但**本批第一次有取证埋点把它打成了字面证据**。

⚠️ **仍不写机制结论**：`server=-` / `allow=-` 说明这两项没取到，**谁在答、为什么**本批**没有证据**区分
（可能是并发下的端口/代理/常驻服务，也可能是别的）。⇒ 只升级**证据等级**，不升级**结论**。
⇒ 并据此把 B15 的**取样要求**再加一条：**跑全量时必须同时落盘"失败响应的 ct / text"**，
否则"404"这个数字本身区分不出"应用答的 404"与"别人答的 404"。

```bash

import fs from "node:fs";

const out = [];

  const binds = [...src.matchAll(/(?:const|let)\s+([A-Za-z_$][\w$]*)\s*=\s*([A-Za-z_$][\w$]*)\??\.code\b/g)];
  if (!binds.length) continue;

console.log(out.reduce((s,[,n])=>s+n,0), "处 /", out.length, "文件");
```
