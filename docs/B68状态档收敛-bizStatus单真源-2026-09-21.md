## 二、修法：一份实现，按"最可信 → 最不可信"排四档

新增 `server/src/shared/bizStatus.ts`，三个文件里那三份本地函数**连函数带别名一并删除**，调用点直接叫它。判定顺序：

1. 错误自己带 `statusCode` / `status` → 就是它（业务错误两件套已经会写）；
2. 错误带**已登记**的 `code` → 取 `shared/errorCodes` 注册表里的档位（**复用既有真源**，不在路由里重抄映射）；
3. **文本读起来是系统故障 ⇒ 500**（`ECONN`/`P20xx`/`timeout`/`transaction`/`deadlock`/`数据库`/`超时`/`内部错误`…）；
4. 最后才认那张关键词表（取**三域并集**）；都不认才用 fallback。

★ **第 3 档为什么必须排在关键词表前面**：`数据库连接池不可用` 含「不可」⇒ 挂在第 4 档之后会被判成 409，
  即"把服务故障报成业务冲突"，方向和原病灶一样错。
★ 动手前先量了安全性：报关 + MES 服务层可静态取到的 **120 条**抛错文案里，含系统故障字样的 **0 条**
  （★ v2.45 复核重新量过：同一批文件按 `throw new Error(` 数到 **121 条**，差的 1 条是模板串写法计不计入 —— 两口径都记在这里；
  复核与自己各自量的结果都是**命中 0 条**，且第 3 档已扩到真实数据层字样后仍是 0 条 ⇒ 这条安全性结论稳）。
  ⇒ 这一档不会把任何既有业务文案改判，只会把原本被误判成 4xx 的技术故障抬回 5xx。
  （不量就加关键词，正是本仓"假阳性也是判据失真"那一族的反面。）

调用点从 `errStatus(e?.message ?? '')` 改成 `statusFromError(e)`（76 + 1 处带 500）。
**没有盲改**：先枚举出参数只有 `e?.message ?? ''` 与 `e?.message ?? '', 500` 两种形状，
再逐处校验这 77 个调用点的**最近一个 `catch` 声明的变量确实叫 `e`**（结果 0 处可疑），
并用测试钉住"三文件里不许再出现只传文本的写法"。

★ **中途改了一次主意（留痕）**：第一版我保留了一层本地别名 `const errStatus = (e, fallback = 400) => statusFromError(e, fallback)`，
  理由是"少动 77 行"。自查时否掉了：别名**必须自带一个 `fallback` 默认值**，于是"兜底档 = 400"同时存在于 1 真源 + 3 别名 = 4 处，
  而 76 个调用点都不传第二参 ⇒ 它们实际用的是**别名那份**，改真源默认值会被静默覆盖 —— 这正是本仓反复登记的那族病（同一件事两个名字/两处真源）。
  最终：别名删掉，调用点直呼 `statusFromError`；守卫同时禁"再长出本地壳"。

### 9.1 说人话：之前是什么局面

报关的"合并装箱单 / 合并销售合同"这三个端点（预览、生成 PDF、提交签署）出错时，档位是**看一句中文里有没有特定字眼**定的：

| 现场 | 改造前怎么答 | 改造后怎么答 | 为什么 |
|---|---|---|---|
| 合同要的订单被删了 | **400**「你的请求有问题」 | **404** | 抛出方声明了 `NOT_FOUND` |
| 合并只要给了一张运单 | 400 | 400（**不变**） | 声明 `VALIDATION_FAILED` |
| 运单在、但它的单据集装配抛了异常 | **400**（看"装配失败"四个字） | **500** | 声明 `ASSEMBLE_FAILED` |
| 审批人解析不到（DR-007） | 409（但靠 `msg.includes('NO_REVIEWER_RESOLVED')`） | **409**（认 `.code`） | ★ **档位不变，变的是出处** |

最要紧的是最后两行的对比：**同一件事的档位，过去挂在"人读的那句话"上**。第三行那句"装配失败：xxx"里的 `xxx` 是内层异常原文 —— 它含"不存在"就被判 404、含数据层字样就被抬 500，**外层根本没资格表态**。第四行更险：那句真文案是「申请人**不存在**或已停用」，一旦哪天有人把站点手写的码名匹配删掉，"管理员没配审批人"就会被对外说成"你要的东西没了"（实测旧关键词表对这句给的就是 **404**，见 9.5）。

### 9.2 做法：注册表是唯一出处，不新造语义、不加关键词

- `compositeDocumentService` **7 处抛错全部带上 `code`+`statusCode`**（该文件 `throw new Error` 归零）：
  `VALIDATION_FAILED` / `NOT_FOUND` 是注册表里**已有**的两枚；
  `NO_REVIEWER_RESOLVED`(409)、`ASSEMBLE_FAILED`(500) 是**抛出方早就挂了 `err.code`、只是没登记**的两枚 ⇒ 登记即可命中第 2 档，不需要给关键词表加词。
- `ASSEMBLE_FAILED` 是 `shipping/documentSetService.ts:140` 域内自己声明的码，在 `shipping/route.ts:485` 已经当兜底码在用（`spec?.status ?? 500` = 500）⇒ **登记前后那一点的状态与文案都不变**（文案由调用点 `fallbackMessage` 优先，`routeError.ts:93`）；这里没有"替两本打架的映射选边"（对照 `INVALID_STAGE` / `STAGE_NOT_SEQUENTIAL` 那条既有纪律）。
- `businessError(code, message)` 这个构造器从 `riskService` 的**私有实现上移**进 `shared/errorCodes`（注册表旁边），risk 侧改为 import。★ 若留在原地就是两处真源；上移后它**查不到码就抛**（不静默给默认档）。
- `customsRoute.ts` 三处内联三元 → `statusFromError(e, 500)`：调用点 33→36、三域合计 **77（改造前）→ 80**（净增 3 处是原来不叫 `errStatus` 的内联三元 ⇒ 两个数是同一把尺在不同时点的读数，**不加减**；守卫 `bizStatusB68.test.ts` 的分母已同步为 36/22/22）。

### 9.4 ★ 撞出来的 B73：棘轮尺被"函数调用状态档"绕过，账面自己变好了
