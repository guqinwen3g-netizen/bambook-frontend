### 6h system-assets —— 结论是"保留公开读"而非"补鉴权"

`/:id/file` 前置守卫看似漏洞，实为**刻意设计**。依据两条硬证据（不是推断）：
1. 顺序实证：`/file` 匿名 → 404（无守卫分支），`/` 匿名 → 401（守卫分支）；
2. 前端 `utils/publicAssets.ts` 把该 URL 当公开素材，**登录页壁纸依赖登录前可加载**，套鉴权会让登录页取不到图。

收口：写明意图 + 仅 `kind==='wallpaper'` 公开读 + 其余落回守卫 + `filePath` 越界防护。

### 7 SSRF —— 两个绕过均有真机复现

| 写法 | 修复前 |
|---|---|
| `http://127.0.0.1:9999/` | ✅ 拦住（对照） |
| **外网 302 → `http://127.0.0.1:9999/`** | **❌ 读到内网标记服务响应** |
| `http://[::ffff:127.0.0.1]:8081/` | ❌ 未拦，请求到达本机 8081 |
| `2130706433` / `0177.0.0.1` / `0x7f.0.0.1` | ✅ 已拦（WHATWG URL 归一化，原实现是幸运而非正确） |

根因：**SSRF 防护默认"只校第一跳"，HTTP 客户端默认"自动跟随重定向"，两个默认撞车 = 防护归零**。
修复后：地址字面量（含 v4-mapped/NAT64/6to4/ULA）+ DNS 逐地址判定 + **逐跳重校**（最多 3 跳）。

### 9 / 10 / 11 要点

- **门户登录**：主站有 15 分钟/5 次限流，门户**一处都没有**，而它才是对外入口。已复用同款限流器补齐。
- **SSE 通知**：`publishNotificationEvent` 全员广播，而 REST 侧 `/v1/notifications` 严格按 `actor.userId` 隔离——同一份数据两套口径。已改为只推给收件人；空 `recipientIds` 丢弃告警（fail-closed）。`data-change` 仍广播（只含 entity/action/ids，是设计）。

## 二、⛔ 上线硬阻断：生产跑的是修复前代码（6i）

用「**空 body 404 = 被守卫拦下 / HTML `Cannot GET` = 落到 static**」这个判据，在**真实生产入口**实测：

| 请求 | 生产返回 | 判读 |
|---|---|---|
| `/api/uploads/trade-documents/不存在.pdf` | 404 **空 body** | 旧的字面量前缀守卫命中 |
| `/api/uploads//trade-documents/…` | 404 **HTML** | **落到 static → 守卫被绕过** |
| `/api/uploads/trade%2Ddocuments/…` | 404 HTML | 同上 |
| `/api/uploads/trade-documents%2F…` | 404 HTML | 同上 |
| `/api/uploads//products/…`（对照） | 404 HTML | 判据自检：非敏感子树本就该落 static |

⇒ 6b/6d/6g 的修复**只 commit 未 push**，生产仍在旧代码上。当前生产库空（订单 0/产品 0）⇒ **暂无实害**，
但上线后有真实发票/装箱单即成实害。**「先部署再上线」不是建议，是前置条件。**

生产侧已确认安全的：`/api/dev/*`（含一键登录任意账号）**全部 404 不可达**；`/api/v1/system-assets/` → 401。

## 七、本轮踩的坑（值得传给下一轮）

1. **`pkill -f "ts-node src/index.ts"` 匹配不到**（进程名是 `node`）→ 旧 pid 继续占 8081，新进程 EADDRINUSE 静默退出，
   表现为"修好的东西在真机上不生效"。可靠做法：`lsof` 取 pid → `kill -9` → 探到端口释放 → 启动 → **核对新 pid ≠ 旧 pid**。
   **「3 秒就就绪」本身就是警报**（ts-node 冷启动约 20s）。
2. **扫描脚本三次假阴性**：内联守卫匹配漏变量挂载 / 首参必须字符串漏匿名中间件 / 字面量匹配漏等价校验函数。
   ⇒ 自动扫描的"命中"和"未命中"**都必须人工抽查**。
3. **数组解构是按位置**：`const [g0,g1,g2,g5,g6,g7]=arr` 拿到下标 0..5。第一版让 v4-mapped 判定永远落空，而单测"恰好没覆盖"依旧全绿。
4. **加严 IP 黑名单前先确认本机 DNS**：本机 DNS 代理（fake-ip）把所有域名解析到 `198.18.0.x`，一度导致**全部公网域名 400**。
5. **一条用例有没有判别力，取决于用哪种证伪去问它**：门户限流的"成功后清零"在"短路 check"的证伪下必然仍绿，必须补定向证伪。
6. **隔离复跑要分批**：一次给太多目录会被系统 SIGTERM（exit 137），每批 2~4 个模块。
7. **单元测试测到函数、测不到接线**：删掉 `fileFilter:` 那行单测仍全绿，补了一条读源码断言接线的守卫用例。
