## 三、修这些脚本的**统一模式**（照抄 `acceptance-claim-model.ts` ✓）

本仓已有更好的范式，**不要**继续沿用"依赖库里既有演示数据"的写法 ✗：

1. **自建前置数据**（用 `DRILL-` 前缀 ✓），不依赖库里恰好存在什么 ✗
2. **自回滚**（`finally` 里按前缀**无条件扫** + 清联动副作用 `EntityLink`/`EntityReference`/`AuditLog` ✓）
3. **独立复核零残留**（不信回滚自述 ✓）
4. **三态计数** `pass` / `fail` / **`gap`（待口径）** ✓ —— 待口径的别用 `fail` ✗
   （否则脚本永远红 ⇒ **失去复跑价值** ✗ —— 今晚 `credit-note-settlement-gap` 就是这个问题 ✓）
5. **阳性对照**（防"空过的验证器" ✓）
