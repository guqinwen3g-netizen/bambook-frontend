# G3 判据接门禁：L-A 棘轮 + 一处会让读数说谎的工具缺陷（v2.53 批 · 2026-09-22）

> 判据本体在 `docs/交付目标与验收标准-2026-09-20.md` §2 G3（当前 v2.52，本批把账面回写并进下一批，见 §五）。
> 本批改动面 = **2 个文件**：`scripts/check-fail-open-inventory.mjs`（尺）+ `scripts/fail-open-gate.test.ts`（新增守卫）。

## 一. 一句话

G3 的"L-A 零容忍"此前**只是一句账面话**：派生它的扫描器 `check-fail-open-inventory.mjs` 写完之后
**全仓没有任何调用方**（`grep -rln check-fail-open-inventory scripts server/src` 只命中它自己）
⇒ 一把没人跑的尺可以静默瞎掉，新增一处 `catch(() => 0)` 进写路径也不会红。
本批把它接进仓根门禁，并顺手抓到**一个会让所有"跑通了"结论作废的工具缺陷**。

## 二. ★ 接进门禁时撞到的矛盾，以及为什么"不能直接把判据当退出码"

| 事实 | 量 |
|---|---|
| G3 判据 | L-A **必须为 0** |
| 现存 L-A（2026-09-22 23:45 现量，`--json`） | **191** |
| 旧脚本的退出码 | `la.length > BASELINE.la`，而 `BASELINE.la` 写死 **0** ⇒ **恒 1** |

⇒ 直接挂进门禁 = **永久红**；而"永久红的门禁"的实际下场是下一批被 `skip` 掉（本仓 D57 讨论过降频的诱惑）。
**修法不是放宽判据**（§0.1 明令禁止"放宽判据使其变绿"），而是**把两件事拆开**：

- **判据**留在账面与打印里：脚本现在输出 `⚠️ G3 判据未达标：L-A 要求 0，现存 191 处…这是账面缺口，不是本脚本的门禁条件`；
- **棘轮**进门禁：`BASELINE = { la: 191, lb: 171 }`，**只允许下降** ⇒ 新增一处当场红；
- 守卫**同时断言那句"未达标"必须被说出来**（`toContain('G3 判据未达标')`）⇒
  不许有人用"删掉打印"或"把 TARGET.la 改成 191"来制造绿色。

★ 代价如实写明：**现存 191 处不拦住任何新代码**（它们本来也没被拦），棘轮换来的是
"从今天的读数起不许变多"+"这把尺从此每次门禁都被跑一遍"。登记为 **D94**（待写进台账）。

## 三. ★ 新缺陷（本批实测，建议立账 B78）：`process.exit()` 在管道下截断 stdout，且退出码仍然是 0

同一命令、同一棵树，两种接法给出两种"事实"：

| 接法 | stdout 字节 | 结果 |
|---|---|---|
| `node scripts/check-fail-open-inventory.mjs --json > /tmp/fo.json` | **218296** | `JSON.parse` 通过 |
| 同样命令，stdout **接成管道**（守卫的 `spawnSync` / `| jq` / CI 收集） | **51855** | `Expected double-quoted property name in JSON at position 51855` |

成因：`process.exit(main())`。stdout 指向**文件或终端**时写是同步的 ⇒ 完整；
指向**管道**时写是异步的 ⇒ `process.exit()` 在缓冲区刷完前杀进程。
**最坏的一点是退出码仍然是 0** ⇒ "命令跑通了、输出可解析"这类结论**在管道下曾经是假的**，
而且失败方向是**静默**（不报错、只少数据）。
本脚本的 `--json` 输出 218KB，正好踩中。

修法：改成只设 `process.exitCode = main()`（`runSelfCheck()` 里那处 `process.exit` 同样改成 return）。
修后实测：管道下 `bytes 218296 · parse OK · status 0`，`--selfcheck` 报告完整。

★ **普查的边界（不声称已清）**：`grep -c 'process.exit(' ` 命中 **90 个脚本**（`scripts/*.mjs` + `server/scripts/*.mjs`）。
本批只修了**有实测证据的这一个**（它的输出最大且现在被守卫经管道消费）。
其余 89 个**未逐个验**：它们的输出是否大到会跨过管道缓冲、是否有人经管道消费 ⇒ **未覆盖**。
（这也是 B75/B76 那一族的第三种形状：不是"尺看不见某种写法"，也不是"尺整块被跳过"，
而是**尺的读数在传输路上被截了一段，而它自己说"我成功了"**。）

## 四. 守卫做了什么（`scripts/fail-open-gate.test.ts`，4 条用例）

1. **分母自检**：`filesScanned ≥ 700`（现量 792）· `missing == []` · server/frontend/portal 三组各自非空
   ⇒ 区分"没问题"与"没遍历"（只报命中数的判据做不到这条）。
2. **分桶加得回总数**：`L-A + L-B + 待核实 == all` 且 `hits.length == all`（D89 定的规矩，加不回就红）；
   并钉住**台账 §2 G3 那两个数**（L-A **191**、L-B **171**）⇒ 账面与尺一旦漂移，这条先红而不是靠人眼。
3. **棘轮今天必须绿 + 基线不许被置空**：`status == 0`、`baseline.la/lb != null`、`target.la == 0`（判据不许降格）、
   且"未达标"必须被说出来。
4. **反面对照（决定前三条不是恒绿）**：
   - 分类器还分得出 `catch` 与 `nullish` 两种形状（枚举/掩码坏了先在这里红）；
   - `--la=190` ⇒ **必须 exit 1**；`--lb=170` ⇒ **必须 exit 1**（等价于"新增一处"）；
   - `--selfcheck` ⇒ exit 0。

实测：`npx vitest run scripts/fail-open-gate.test.ts` → **4 passed（1.3s）**；仓根全量见 §五。
