# T7-③ 收汇 ↔ 报关 FOB —— 应收到期日门槛 · 完成回报

日期：2026-09-16　｜　批次：T7-3 遗留项 ⑦（预警噪音治理）

## 一、为什么做

T7-③ 上线后跑真库发现一个**会让预警失效**的问题：只要「收汇 < 报关 FOB 超容差」就报，
**完全不看到期日**。于是刚下单、还没到付款期的单子全部报警。

口径是「只预警不阻断」，预警本来就靠人看；**预警一旦被无视就失效**。
把「还没到该付钱的时候」混进「该收的钱没收到」，等于把真信号埋掉。

## 二、判据（关键设计决定）

**用发票 `dueDate`，不用 `Order.dueDate`。**

`Order.dueDate` 是**订单交期（交货日）**，不是付款期限 —— 拿它当收款门槛会把
「货还没交」误判成「钱该到了」。改为取该订单**应收发票**（`type='Receivable'`、
未作废、未软删）中**最早**的 `dueDate`：

- 取**最早**：分批付款场景下，不能因为某张发票到期日晚就整体漏报；
- 无应收发票 → `paymentDueDate = null` → **不享受门槛，照报**（保守方向：宁可报也不漏）；
- `dueDate` 脏数据（非 `YYYY-MM-DD` / null）→ 忽略该行，不误判。

## 三、门槛是**方向性**的（自审时发现并修正的缺陷）

第一版写成「未到期就一条都不报」，这是**错的**：

| 方向 | 是否受门槛抑制 | 理由 |
|---|---|---|
| 收汇 **少于** FOB | ✅ 抑制 | 钱还没到，是时间问题 |
| 收汇 **多于** FOB | ❌ 照报 | 钱不该多出来，与到期日无关 —— 是错汇/混入他单款项的信号 |

压掉「多收」方向即漏报。实现上落为
`suppressByDueDate = notYetDue && difference.lt(0)`。

### 踩坑：`.catch()` 接不住同步 TypeError

`db.invoice.findMany(...).catch(() => [])` 在 mock/老库**没有 `invoice` 模型**时，
是**同步抛 TypeError**（属性访问就炸），Promise 链根本建不起来 → `.catch` 形同虚设，
14 个既有测试全红。改用 `try/catch` 块才真正兜住。

## 七、口径登记

- **门槛方向性**：未到期只抑制「收汇不足」，「多收」永远照报。
- **到期日真源**：`Invoice.dueDate`（应收、未作废、未软删）取**最早**；无则视为已到期。
- **severity 恒 `'warning'`**（口径 D 不变，类型即字面量）。
- 本次**未引入任何汇率换算**（口径 A 不变）。
