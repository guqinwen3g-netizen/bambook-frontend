## 5. 本段会话留下的四条方法教训（下次同类任务先想这四句）

1. **"反查"要问到第三问**：前两问（有没有完整句拍板 / 别域是否已实现）我已养成，第三问漏了 ——
   **"我这份实现是否覆盖了全部入口"**。G-4 的 PI 转正旁路、V2 白名单丢字段都是这一问的产物，与前两次（G-2 读半句拍板、
   G-3 换口径下结论）**同族**：都是"我声称的面比实际的大"。
2. **两条棘轮夹死时，正解通常是"查真源"而不是"绕开判据"**：B34 要抛点带 `statusCode`、B32 只许一份 `code→status` 真源
   ⇒ 在 service 里写 `code === 'X' ? 500 : 403` 必红。仓库里早有正确答案（`production/stageService.ts:95` 查注册表）——
   **先找既有真源再提新建**这条，第 N 次成立。
3. **复核的结论也要现读核实**：G-4 复核说"没有任何真实录入路径能产出触发数据"——实测**不成立**
   （V1 建单白名单 `orders/route.ts:812` **含** `paymentInstrument`，能录出 L/C 单）。
   反过来它说的旁路、丢字段、假绿全部为真。**接受为真的、改掉不实的、两边都留痕**，别整份照抄也别整份驳回。
4. **文本判据有形状盲区，别把"扫不到"当"没有"**：`status: toStatus`（变量写法）、`String(e?.message ?? e)`（非 `message: X.message` 形状）
   两类都逃出现有扫描 ⇒ 枚举覆盖面时只能"逐处现读 + 明写这不是全量分母"。
