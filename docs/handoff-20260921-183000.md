## 5. 本段新增的方法教训（下次同类任务先想这五句）
1. **桩件的缺失 delegate 会让测试"为错误的原因变绿"**：`$transaction` 报 `Cannot read properties of undefined` 也算"没写成"，看着像门禁生效。⇒ 阻断类断言要断**具体码 + 零写入 + 零回执**，别只断"没成功"。
2. **`$transaction` 调用次数不是"门禁在事务之前"的判据**：`exceptionService` 内部也开事务。真正的判据是"事务体的第一笔写（幂等回执）没出现"。
3. **反例不许用 `python3 -c "…\"…\"…"` 打 patch**：那次转义失败 ⇒ patch 没打上，"15 passed"是空跑。heredoc + `assert s.count(old)==1` 之后才准开跑。
4. **按行号插入代码要先断言行内容**：我把 helper 插进了多行箭头函数体内部，直接编译炸（两次 off-by-one）。多行对象字面量优先用 Edit 而不是行号。
5. **"活路径"要分清可达与已发生**：可达性看调用图，是否真跑过看库里的痕迹（回执/审计行数）。上一批我说了前者、听着像后者。
6. **判"可达"要看分发优先级**：`executeTool` 是**注册表优先 return** ⇒ 同一工具的内联 `if` 分支是死代码。我按"有四处调用"报了可达性，复核指出真跑的只有两处 —— 而且**唯一可达的那条恰好是坏的那条**。读代码要读到"谁先 return"，不是读到"有没有这行"。
