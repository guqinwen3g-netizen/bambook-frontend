# 砍价画像与报价版本对比 (Price Negotiation Profile)

> **REQ2-19** · 痛度 19 · 来源 生命周期③ L0 · 批次四 C 级 · 成本 S-M
> **甲方场景**：客户砍价——报价发出后改价重报，谈判轮次要留痕；销售想看"这个客户历史上平均砍几个点、成交价偏离首报多少"。
> **验收标准**：生命周期③——报价版本快照 + 客户历史成交价/首报偏差统计。

## §1 元信息

| **定位** | 报价域扩展：版本 append-only 快照（谈判留痕）+ 客户维度砍价画像聚合 |

## §2 关键设计决策（DR-060）

### DR-060-① 版本链 append-only：Draft 编辑自动快照 + revise 显式修订通道

- **现状约束**：updateQuotation 仅 Draft 可编辑（既有铁律）；Sent 后砍价 = 无通道（只能新建单，历史断裂）
- **Draft 编辑自动快照**：金额或行变化 → 旧版全量快照（header + lines）append 进 QuotationVersion + version+1；金额不变（仅备注）不快照
- **revise 显式修订**（砍价重报通道）：`POST /:id/revise`（Draft/Sent 可用）——快照当前版（可带 changeReason"客户砍价 8%"）+ version+1 + 状态回 Draft（编辑后重发）；Accepted/Rejected/Expired 终态不可修订（新询价新建单）
- 快照含 linesSnapshot（行级单价/数量留痕——砍价证据链：v1 $10/YD → v2 $9/YD）

### DR-060-② 砍价画像 = 客户维度首报偏差聚合

- `GET /api/v1/quotations/price-profile?relationId=`：
  - 每报价单：firstAmount（版本链最早快照，无快照=当前即首报）/ currentAmount / cutPct（降幅）/ rounds（砍价轮次）/ 成交关联（convertedOrderId → Order.totalNet → dealDeviationPct 成交偏差）
  - 汇总：报价单数 / 砍价单数 / 平均降幅 / 最大降幅 / 成交单数 / 成交平均偏差
- 降幅语义：cutPct = (current − first) / first（负数 = 砍价）；maxCutPct 取最小值（砍得最深）

### DR-060-③ 前端最小集成（报价卡片内嵌，不出新页）

- QuotationManager 报价卡：版本徽章（v≥2 显示）+ 「修订」动作（Draft/Sent 卡）+ 版本历史 BottomSheet（金额/原因/行快照对比）
- 画像：报价列表客户筛选下「砍价画像」入口 → 画像面板（汇总卡 + 明细表）

## §3 API 合约（挂 /api/v1/quotations，守卫沿报价域惯例）

| 端点 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `/:id/revise` | POST | `{ changeReason? }` | `{ quotation }`（version+1，status=Draft） |
| `/:id/versions` | GET | — | `{ versions[] }`（正序） |
| `/price-profile` | GET | `?relationId=` | `{ relationId, items[], summary }` |

错误：`仅 Draft/Sent 可修订` → 409；relationId 缺失 → 400。

## §4 增强项

## §5 验收锚点（scripts/acceptance-req2-19.mjs）

1. 建报价（$1000）→ Draft 改价 $900 → 版本快照 v1($1000) 落库 + version=2
2. send → revise（"客户砍价"）→ version=3 + 回 Draft + 审计 revise_quotation
3. 改价 $850 → v2 快照；版本历史正序 [v1 1000, v2 900]
4. accept → convert-to-order（$920 PO）→ 画像：firstAmount=1000 / current=850 / cutPct=-15 / 成交偏差 -8%
5. 终态 revise → 409；无 relationId 画像 → 400；无报价客户 → 空画像
