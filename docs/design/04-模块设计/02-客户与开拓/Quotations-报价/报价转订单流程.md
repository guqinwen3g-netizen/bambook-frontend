## 一、流程定位与边界

报价转订单是售前到生产的「最后一公里」——客户接受报价后，业务员一键将报价单转化为可生产的生产订单。该流程在单个数据库事务内原子完成，保证报价与订单的数据一致性。

**在边界内**：转单前置校验、字段映射、Order+OrderLine 创建、convertedOrderId 标记、审计日志、EntityLink 图谱同步、幂等防重、成功横幅与直达跳转。
**不在边界内**：订单后续状态流转（在 Orders 模块）、PI 生成（独立流程，转单后可选触发）、订单详情页展示（在 Orders 模块）。

---

## 二、转单前置校验

| 校验项 | 条件 | 失败结果 |
|--------|------|----------|
| 报价单存在 | findUnique 非 null 且 deletedAt 为 null | throw → 404 |
| 状态合法 | status === 'Accepted' | throw「仅 Accepted 可转为订单」→ 409 |
| 未重复转换 | convertedOrderId 为 null | throw「已转为订单 X，不可重复转换」→ 409 |

三项校验任一失败即终止，不创建订单。校验在事务外先查询 existing（含 lines），通过后进入事务。

## 三、字段映射

转单将 Quotation + QuotationLine 的字段映射至 Order + OrderLine：

### 3.1 Quotation → Order 映射

| Order 字段 | 来源 | 映射规则 |
|------------|------|----------|
| id | 生成 | `ORD-QT-${String(now).slice(-8)}`（时间戳后 8 位） |
| customer | existing.customerName \|\| customerCode \|\| '未知客户' | 优先客户名 |
| product | existing.lines[0]?.description \|\| '' | 首行品名 |
| type | overrides.type \|\| 'Fabric' | 可覆盖 |
| quantity | Σ lines.quantity | 行数量合计 |
| status | 'Pending' | 固定初始态 |
| dueDate | overrides.dueDate \|\| existing.validUntil \|\| '' | 优先覆盖，其次有效期 |
| quoteAmount | existing.totalAmount | 报价金额原值 |
| poNumber | overrides.poNumber \|\| existing.quotationNumber | 优先覆盖，其次报价号 |
| customerCode | existing.customerCode | 直接映射 |
| currency | existing.currency | 直接映射 |
| deliveryTerms | existing.deliveryTerms | 直接映射 |
| paymentTerms | existing.paymentTerms | 直接映射 |
| customerRelationId | existing.customerRelationId | 直接映射 |
| millName | overrides.millName \|\| '' | 可覆盖 |
| source | 'quotation-convert' | 标记来源 |
| salesCurrency | existing.currency | 销售币种 |
| purchaseCurrency | existing.baseCurrency \|\| 'CNY' | 采购币种 |
| fieldSources | { source: 'quotation-convert' } | 字段溯源 |
| updatedAt / importedAt | BigInt(now) | 时间戳 |

### 3.2 QuotationLine → OrderLine 映射

| OrderLine 字段 | 来源 | 映射规则 |
|---------------|------|----------|
| id | 生成 | `OL-${orderId}-${i+1}` |
| lineNumber | i+1 | 序号 |
| materialCode | line.fabricCode | 面料编码→物料编码 |
| description | line.description | 直接映射 |
| quantity | line.quantity | 直接映射 |
| unit | line.unit | 直接映射 |
| unitPrice | line.unitPrice | 直接映射 |
| netValue | line.amount | 行金额→净值 |
| status | 'Pending' | 固定初始态 |

### 3.3 Quotation 更新

| Quotation 字段 | 更新值 | 说明 |
|----------------|--------|------|
| convertedOrderId | orderId | 标记已转换（幂等防重依据） |
| updatedAt | now | 时间戳 |

## 四、事务流程

```
convertToOrder(id, actorId, overrides)
        │
        ▼
前置校验（事务外）：
  ① existing = findUnique(id, include lines) → 不存在/deleted → 404
  ② status !== 'Accepted' → 409
  ③ convertedOrderId 已存在 → 409
        │
        ▼
prisma.$transaction(async (tx) => {
  ① 创建 Order + OrderLine（tx.order.create with lines.create）
  ② 更新 Quotation.convertedOrderId = orderId（tx.quotation.update）
  ③ 审计日志：convert_quotation_to_order（Quotation 维度）
  ④ 审计日志：create_order_from_quotation（Order 维度）
  ⑤ EntityLink 图谱：
     syncQuotationReferences(quotation) — quotedFor + convertedToOrder
     syncOrderEntityReferences(order) — 新订单关系 FK 入图
  return { order, quotation }
})
        │
        ▼
返回 { orderId, quotation }
        │
        ▼
路由层 onDataChange 双回调：
  ① { entity: 'Quotation', action: 'convert', ids: [quotation.id] }
  ② { entity: 'orders', action: 'create', ids: [orderId] }
        │
        ▼
前端 setConvertedOrderId(orderId) → 成功横幅 + 「查看订单」直达
```

## 五、幂等机制

| 维度 | 机制 |
|------|------|
| 防重复转换 | convertedOrderId 非 null → 校验失败 409「已转为订单 X，不可重复转换」 |
| 事务原子 | Order 创建 + Quotation 更新 + 审计 + EntityLink 同在 $transaction，任一失败全回滚 |
| ID 生成 | orderId = `ORD-QT-${时间戳后8位}`，同毫秒并发理论可能冲突（当前未加唯一约束，依赖前端按钮 disabled 防连点） |

**幂等保证**：同一报价单只能转一次订单；convertedOrderId 是幂等键，事务内更新确保原子。

## 六、事件联动 L9

转单触发两层事件联动：

### 6.1 onDataChange 回调（实时推送）

路由层 convert-to-order 成功后触发双回调：
- `{ entity: 'Quotation', action: 'convert', ids: [quotation.id] }` — 报价侧订阅者刷新
- `{ entity: 'orders', action: 'create', ids: [orderId] }` — 订单侧订阅者刷新

onDataChange 是 SSE/WebSocket 实时推送的触发器，确保客户端列表自动刷新。

### 6.2 审计日志（持久化）

事务内创建两条审计日志：
- `convert_quotation_to_order`（targetType=Quotation, operationType=transition, fieldPath=convertedOrderId）
- `create_order_from_quotation`（targetType=Order, operationType=create, detail.source='quotation-convert'）

### 6.3 EntityLink 图谱同步

- `syncQuotationReferences` — 报价 convertedToOrder + quotedFor 关系入图
- `syncOrderEntityReferences` — 新订单的 customerRelationId 等 FK 关系入图

EntityLink 是跨实体关系图谱的持久化，支持溯源查询（TraceabilityPanel quoteToShip 场景）。

## 七、API 端点

| 端点 | 方法 | 参数 | 说明 |
|------|------|------|------|
| /v1/quotations/:id/convert-to-order | POST | body: { poNumber?, millName?, type?, dueDate? } | 转订单，201 返回 { orderId, quotation } |

## 九、四态规范

| 状态 | 表现 | 实现路径 |
|------|------|----------|
| **空态** | Accepted 且未转 → 显示「转为订单」按钮 | convertedOrderId 为 null |
| **加载态** | 按钮 Loader2 + disabled（actionLoading=`${id}_convert`） | handleAction |
| **错误态** | bds-alert danger「操作失败：${message}」 | error state |
| **成功态** | bds-alert success 横幅「已转为订单 {orderId}」+ 「查看订单」直达（onOpenOrder） | convertedOrderId state |

转单成功后报价卡片操作区改为显示「已转订单」+ orderId 直达链接（onOpenOrder 可用时可点击跳转）。

## 十一、可访问性 & 交互细节

- 「转为订单」按钮仅在 Accepted 且 convertedOrderId 为空时渲染
- 转单中按钮 Loader2 + disabled
- 成功横幅「查看订单」可点击直达（onOpenOrder(orderId)）
- 已转订单后操作区显示「已转订单」+ orderId 链接（onOpenOrder 可用时）
- overrides 参数（poNumber/millName/type/dueDate）当前前端未暴露 UI，走默认映射

## 十四、待补的设计缺口

| # | 缺口 | 影响 | 建议优先级 |
|---|------|------|-----------|
| 1 | orderId 格式 `ORD-QT-{ts后8位}` 非标准业务编号（SO-YYYYMM-NNNN） | 与 Order.code 编号体系不一致，溯源可能混淆 | P2 |
| 2 | overrides 参数（poNumber/millName/type/dueDate）前端未暴露 UI | 无法在转单时自定义 PO 号/工厂/类型/交期 | P2 |
| 3 | 同毫秒并发转单 orderId 可能冲突（无唯一约束） | 高并发场景理论风险 | P3 |
| 4 | 转单后报价行面料编码映射为 OrderLine.materialCode，但未关联 ProductAsset | 订单侧无法命中面料档案 | P3 |
| 5 | 转单不自动生成 PI，需用户手动点「生成 PI」 | 流程多一步操作 | P3（可评估自动联动） |
