## §2 业务背景与口径

外贸企业向境外供应商/货代/保险公司付款时，需通过银行购汇或使用自有外汇向境外付汇。付汇水单（OutwardRemittance）登记实际付汇事实，与结汇（FxSettlement）构成外汇核销的收付双侧闭环。

### 2.1 与结汇的镜像关系

| 维度 | FxSettlement（结汇） | OutwardRemittance（付汇） |
|------|---------------------|--------------------------|
| 凭证类型 | Receipt（收款） | Disbursement（付款） |
| 资金方向 | 外币 → CNY 入账 | CNY/自有外汇 → 外币出境 |
| 关键校验 | `NOT_A_RECEIPT` | `NOT_A_DISBURSEMENT` |
| CNY 凭证 | `CNY_VOUCHER_NO_SETTLEMENT` | `CNY_VOUCHER_NO_REMITTANCE` |
| 余额语义 | 核销余额（已结汇） | 未付余额（已付汇） |
| 收款方信息 | —（境内入账） | payeeName / payeeBank / payeeSwift（境外收款方） |
| purpose | — | GoodsPayment / Freight / Insurance / Commission / Other |

### 2.2 核心设计决策（fail closed）

| 决策 | 实现 |
|------|------|
| 一笔外币付款可分次付汇 | `1 voucher : N remittances`，未付余额 = `voucher.amount - Σactive remittances.foreignAmount` |
| cnyAmount 服务端计算 | `round4(foreignAmount × fxRate)`，客户端传入一律拒绝（`INVALID_INPUT`） |
| orderId / customerRelationId 从凭证继承 | 单一真源，不接受客户端覆盖 |
| CNY 凭证无付汇语义 | `CNY_VOUCHER_NO_REMITTANCE`（fail closed） |
| Receipt 凭证走结汇路径 | `NOT_A_DISBURSEMENT`（仅 Disbursement 凭证可付汇） |
| purpose 枚举校验 | 非空时必须在 `REMITTANCE_PURPOSES` 内 |
| 软删即回滚未付余额 | 余额是 derived 查询，软删后自动剔除 |

## §3 付汇水单生命周期

OutwardRemittance 无独立状态机——它是**事实记录**，只有创建与软删两个动作：

```
┌─────────────────────────────────────────────────────────────┐
│  createOutwardRemittance                                    │
│  ┌──────────┐  校验   ┌──────────┐  写入   ┌──────────┐    │
│  │ 输入校验  │────────▶│ 凭证校验  │────────▶│ 创建水单  │    │
│  │ + purpose │         │ + 余额   │         │ + AuditLog│    │
│  │  枚举     │         │  校验    │         │ + Event   │    │
│  └──────────┘         └──────────┘         └─────┬────┘    │
│                                                  │         │
│                                                  ▼         │
│                                          publishBusiness   │
│                                          Event(Outward     │
│                                          RemittanceCreated)│
└─────────────────────────────────────────────────────────────┘
                                                  │
                                                  │ 软删
                                                  ▼
┌─────────────────────────────────────────────────────────────┐
│  deleteOutwardRemittance                                    │
│  ┌──────────┐  查询   ┌──────────┐  软删   ┌──────────┐   │
│  │ 存在性   │────────▶│ deletedAt│────────▶│ EntityLink│   │
│  │ 校验     │         │ = now    │         │ inactive  │   │
│  └──────────┘         └──────────┘         │ + AuditLog│   │
│                                            └──────────┘   │
│  → 未付余额自动回滚（derived 查询剔除软删行）                │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 创建校验链（createOutwardRemittance）

| 步骤 | 校验 | 失败码 |
|------|------|--------|
| 1 | voucherId 非空字符串 | `INVALID_INPUT` |
| 2 | remitDate 匹配 `YYYY-MM-DD` | `INVALID_DATE` |
| 3 | foreignAmount 为正 decimal | `INVALID_AMOUNT` |
| 4 | fxRate 为正 decimal | `INVALID_AMOUNT` |
| 5 | cnyAmount 不得传入（服务端计算） | `INVALID_INPUT` |
| 6 | purpose 非空时在枚举内 | `INVALID_PURPOSE` |
| 7 | 凭证存在且未软删 | `VOUCHER_NOT_FOUND` |
| 8 | `voucher.type === 'Disbursement'` | `NOT_A_DISBURSEMENT` |
| 9 | `voucher.currency !== 'CNY'` | `CNY_VOUCHER_NO_REMITTANCE` |
| 10 | currency 与凭证一致（缺省继承） | `CURRENCY_MISMATCH` |
| 11 | `foreignAmount ≤ remaining`（防超付） | `OVER_REMITTANCE` |

### 3.2 防超付机制

```typescript
// outwardRemittanceService.ts L147-L156
const remitted = await sumRemittedForVoucher(tx, voucher.id);   // Σ active remittances
const voucherAmount = Number(voucher.amount.toString());
const remaining = round4(voucherAmount - remitted);
const foreignAmount = Number(input.foreignAmount);
if (foreignAmount > remaining) {
  throw { code: 'OVER_REMITTANCE',
    message: `foreignAmount ${foreignAmount} exceeds remaining ${remaining} ${voucher.currency} ...` };
}
```

## §4 付汇用途枚举（REMITTANCE_PURPOSES）

```typescript
export const REMITTANCE_PURPOSES = ['GoodsPayment', 'Freight', 'Insurance', 'Commission', 'Other'] as const;
```

| 枚举值 | 中文 | 业务场景 |
|--------|------|---------|
| GoodsPayment | 货款 | 向供应商支付货款（最常见） |
| Freight | 运费 | 向货代支付海运/空运费 |
| Insurance | 保费 | 支付出口货物运输保险费 |
| Commission | 佣金 | 向中间人支付佣金（关联 CommissionRule） |
| Other | 其他 | 其他用途（需 notes 说明） |

purpose 可为空（`null`），但非空时必须在枚举内。空 purpose 不触发校验失败，便于「先登记后补用途」的灵活流程。

## §5 境外收款方信息

付汇水单独有的境外收款方三件套（结汇无此字段，因结汇是境内入账）：

| 字段 | 说明 | 示例 |
|------|------|------|
| payeeName | 收款人名称 | "XYZ Textile Co., Ltd." |
| payeeBank | 收款行 | "HSBC Hong Kong" |
| payeeSwift | SWIFT 代码 | "HSBCHKHHXXX" |

这三项是银行付汇指令的必备信息，登记在水单中便于后续审计追溯与重复付汇时快速调取。

## §6 cnyAmount 服务端计算（防篡改口径）

```typescript
// outwardRemittanceService.ts L159-L160
const fxRate = Number(input.fxRate);
const cnyAmount = round4(foreignAmount * fxRate);
```

与 FxSettlement 完全同口径：foreignAmount 用 `Decimal(18,4)`，fxRate 用 `Decimal(18,8)`，cnyAmount 用 `Decimal(18,4)`。客户端传入 cnyAmount 一律拒绝。

## §7 凭证付汇摘要（getVoucherRemittanceSummary）

单凭证视角的付汇进度查询：

| 返回字段 | 计算 | 说明 |
|---------|------|------|
| voucherAmount | `Number(voucher.amount)` | 凭证原币金额 |
| remittedAmount | `Σ remittances.foreignAmount`（active） | 已付汇外币 |
| remainingAmount | `round4(voucherAmount - remitted)` | 未付余额 |
| fullyRemitted | `remaining <= 0` | 是否全额付汇 |
| remittances[] | 按 remitDate 升序 | 付汇水单明细列表 |

## §8 付汇台账列表（listOutwardRemittances）

支持按凭证 ID + 日期范围筛选的付汇水单列表：

| 筛选参数 | 字段 | 说明 |
|---------|------|------|
| voucherId | `where.voucherId` | 按凭证过滤 |
| from | `where.remitDate.gte` | 起始日期 |
| to | `where.remitDate.lte` | 结束日期 |

排序：`[{ remitDate: 'desc' }, { createdAt: 'desc' }]`（最近付汇优先）。

> **与 getFxLedger 的区别**：付汇侧无对应「外汇台账」聚合视图（结汇侧有 getFxLedger 按币种汇总）。付汇台账目前仅提供列表查询，如需币种汇总可在 reportService 中扩展。

## §9 付汇审批流（设计规格 · 当前为水单登记制）

### 9.1 当前实现状态

OutwardRemittance 服务本身**无内置审批状态机**——付汇水单是「事后登记」的事实记录（银行已实际付汇后登记），不是「事前申请」的审批流。审批控制点在**上游 PaymentVoucher 层**：

| 控制点 | 位置 | 说明 |
|--------|------|------|
| 付款凭证审批 | PaymentVoucher.status（pending） | 付款凭证录入后可挂 pending 状态待审批 |
| 付汇水单登记 | OutwardRemittance（无状态机） | 凭证审批通过 + 银行实际付汇后登记水单 |

### 9.2 审批流口径（DR-007 组织归属路由）

| 阶段 | 触发 | 动作 |
|------|------|------|
| 付汇申请（付款申请） | 出纳发起 | 在上游 PaymentVoucher 层创建付款申请，组织归属按 DR-007 解析审批人 |
| DR-007 审批 | 审批人批准/驳回 | 审批人 = 付款申请人所属部门主管；申请人无主管/部门为财务时→系统管理员（总领导）兜底；**单次一位审批人即可** |
| 银行付汇 | 出纳执行 | 审批通过后，出纳执行银行付汇，然后登记 OutwardRemittance 水单 |
| 软删 | 误登记 | 仅登记后可软删回滚（derived 查询自动回滚未付余额） |

> 当前版本以「凭证审批 + 水单登记」为主防线，前置审批流列为 P2 待补缺口。

## §14 数据完整性约束

| 约束 | 实现 | 违反后果 |
|------|------|---------|
| 凭证存在 + 未软删 | findUnique + deletedAt 检查 | `VOUCHER_NOT_FOUND` |
