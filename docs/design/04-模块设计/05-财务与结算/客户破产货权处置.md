## §2 关键设计决策（DR-055）

### DR-055-① 案件 + 动作流双表（全程留痕是第一性）

- **BankruptcyProceeding**（案件）：同客户同时仅一个 `processing` 案件（唯一活跃约束，业务校验）；状态机 `processing → closed`（closed 终态不可再追加动作）
- **BankruptcyAction**（动作，append-only）：declare 开案即首动作；处置期追加 `resale`（转卖：买家/数量/回收金额）/ `return_shipment`（退运：运单号/退运成本）/ `bad_debt`（坏账登记：金额/关联发票号与订单号快照）/ `recover`（部分回款）；`close` 闭案
- 每动作快照当时业务上下文（payload Json：金额/对手方/单号引用）——后续单据变更后历史不失真（快照哲学全局一致）

### DR-055-② 发票/订单闭环靠引用快照 + 既有通道，不双轨

- 坏账动作的 payload 记录关联发票号/订单号（快照引用）——案件详情完整呈现"哪些订单/发票进了坏账"（闭环可见性）
- **不直接改发票状态**：发票作废走既有 voidDeleteService（cancelInvoice 通道），本域只登记处置事实——避免第二套发票状态真源（P1-004 核销真源分裂教训）
- 闭案汇总自动计算：申报债权额 / 转卖回收合计 / 退运成本合计 / 坏账合计 / 部分回款合计 → **净损失** = 申报额 − 回收 − 回款 + 退运成本

### DR-055-③ 开案即信用冻结（衔接既有，不重造）

- declare 成功后调用既有 creditService freeze（Revoked 语义——破产客户信用不可用）
- 闭案**不自动解冻**：破产客户信用恢复属重大人工决策，闭案响应提示走既有 thaw 端点人工执行

## §4 数据模型

```prisma
/// 设计真源：客户破产货权处置.md §4（REQ2-15，X-10）
/// 业务语义：客户破产案件 + 处置动作流（append-only 全程留痕）。
model BankruptcyProceeding {
  id                 String  @id // 格式：BKP__${shortId}
  proceedingNumber   String  @unique // 业务号：BKP-YYYYMMDD-001
  relationId         String // 破产客户 Relation
  relationName       String // 冗余快照
  status             String  @default("processing") // processing | closed
  declaredAt         String // 宣告日 YYYY-MM-DD
  totalClaimedAmount Decimal @default(0) @db.Decimal(18, 4) // 申报债权总额（开案登记）
  closeNote          String? // 闭案备注（含净损失结论）
  closedAt           BigInt?
  createdAt          BigInt
  updatedAt          BigInt
  deletedAt          BigInt?

  @@index([relationId])
  @@index([status])
}

/// 处置动作（append-only；declare 首动作开案，close 终动作闭案）
model BankruptcyAction {
  id           String  @id // 格式：BKA__${shortId}
  proceedingId String
  actionType   String // declare | resale | return_shipment | bad_debt | recover | close
  amount       Decimal @default(0) @db.Decimal(18, 4) // 金额（转卖回收/坏账/回款/退运成本；declare/close 为 0）
  payload      Json? // 快照：买家/运单号/发票号/订单号/币种等
  note         String?
  actor        String? // 操作人
  createdAt    BigInt
  deletedAt    BigInt?

  @@index([proceedingId])
}
```

## §5 API（挂 /api/v1/credit/bankruptcy，与信用域同路由）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/bankruptcy` | 开案 {relationId, declaredAt, totalClaimedAmount, note?} → 首动作 declare + 自动信用冻结（DR-055-③） |
| GET | `/bankruptcy?relationId=&status=` | 案件列表（含动作计数与金额汇总） |
| GET | `/bankruptcy/:id` | 案件详情 + 动作时间线（append-only 正序）+ 损益汇总 |
| POST | `/bankruptcy/:id/actions` | 追加动作 {actionType, amount?, payload?, note?}（resale/return_shipment/bad_debt/recover；closed 案件 409） |
| POST | `/bankruptcy/:id/close` | 闭案 {note} → close 动作 + 汇总快照落 closeNote（终态） |

守卫：读模块守卫；写 requireWrite + 信用域既有角色链（freeze 同款）。
