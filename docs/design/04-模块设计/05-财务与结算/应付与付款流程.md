## §2 付款全流程链路

```
┌─────────────┐  prime   ┌──────────────┐  录入    ┌──────────────┐  核销   ┌──────────────┐
│ 采购单       │─────────▶│ 应付发票      │────────▶│ 付款凭证      │───────▶│ InvoiceAlloc │
│ PurchaseOrder│ session  │ Invoice      │         │ PaymentVoucher│        │ 核销明细      │
│ (供应商/金额) │ Storage  │ type=Payable │         │ type=Disbur  │        │              │
└─────────────┘         └──────────────┘         └──────────────┘        └──────────────┘
                                                        │
                                                        │ 外币?
                                                        ▼
                                                ┌──────────────┐
                                                │ 付汇水单      │
                                                │ OutwardRemit │
                                                │ (购汇→境外)   │
                                                └──────────────┘
```

| 阶段 | 模型 | type | 状态流转 |
|------|------|------|---------|
| ① 采购单 | PurchaseOrder | — | → Confirmed |
| ② 应付发票 | Invoice | `Payable` | Draft → Issued → PartiallyPaid → Paid |
| ③ 付款凭证 | PaymentVoucher | `Disbursement` | unreconciled → partially_reconciled → reconciled |
| ④ 核销 | InvoiceAllocation | — | create/update/delete + recalc |
| ⑤ 付汇 | OutwardRemittance | — | create/delete（外币 Disbursement only） |

## §3 跨模块 prime（采购→应付发票）

### 3.1 触发

ProcurementManager 中采购单确认后，调用 `primeFinanceInvoiceCreate`：

```typescript
primeFinanceInvoiceCreate({
  supplierRelationId,
  supplierName,
  currency,
  amount,
  notes,
});
```

### 3.2 传递机制

- **sessionStorage** 暂存（key: `bambook_finance_invoice_prime`）
- FinanceManager mount 时 `readFinanceInvoicePrime()` → `clearFinanceInvoicePrime()`
- 预填发票表单：`type='Payable'`, `customerName=supplierName`, `amount`, `currency`, `notes`
- 自动切到发票 tab + 打开新建 modal

> **设计**：与 ProcurementCreatePrime 同模式。sessionStorage 失败静默忽略（跨模块连续性 only，不阻断业务）。

### 3.3 应付发票登记

应付发票复用 Invoice 模型（`type='Payable'`），创建流程与应收发票一致：
- 编号 `INV-YYYY-NNNN`（与应收同序列）
- 状态机：Draft → Issued → PartiallyPaid → Paid → Cancelled
- AR/AP 看板在 `getArApSummary` 中分别查询 `type='Payable'` 汇总

## §4 付款凭证录入

### 4.1 Disbursement 凭证

| 字段 | 说明 |
|------|------|
| type | `Disbursement`（付款） |
| amount | 实际出账金额（扣手续费前） |
| currency | 与发票币种一致（核销时校验） |
| paymentDate | 实际付款日 |
| paymentMethod | TT / LC / OA / DP / DA / Cash / Other |
| bankFee | 银行手续费（与 amount 同币种） |
| exchangeRate | 付款日汇率快照（外币） |
| customerRelationId | 供应商 Relation（billTo） |

### 4.2 创建契约

`POST /api/v1/finance/vouchers` → `createPaymentVoucher`：
- status 默认 `unreconciled`
- 编号服务端生成 `PV-YYYY-NNNN`
- 事务内：create + syncPaymentVoucherReferences + auditLog
- 事件：`PaymentVoucherCreated`

## §5 核销（InvoiceAllocation）

### 5.1 核销约束

| 校验 | 规则 |
|------|------|
| 发票类型 | 应付发票（`type='Payable'`）核销付款凭证（`type='Disbursement'`） |
| 币种一致 | `invoice.currency === voucher.currency` |
| 金额不超限 | `appliedAmount ≤ invoice.amount` 且 `≤ voucher.amount` |
| 剩余不超限 | `≤ invoice 剩余可核销` 且 `≤ voucher 剩余可分配` |
| 发票状态 | `∉ {Cancelled, Draft}` |
| 凭证状态 | `∉ {cancelled, void}` |

### 5.2 核销后状态重算

```
recalcInvoiceStatus:
  totalApplied >= invoice.amount → 'Paid'（自动写 settlementDate）
  totalApplied > 0 → 'PartiallyPaid'

recalcVoucherStatus:
  totalAllocated >= voucher.amount → 'reconciled'
  totalAllocated > 0 → 'partially_reconciled'
```

### 5.3 事件

- 发票全额结清 → `PaymentReceived`
- 凭证全额核销 → `AllocationReconciled`

## §6 外币付汇闭环（OutwardRemittance）

### 6.1 适用条件

| 条件 | 说明 |
|------|------|
| 凭证 type | `Disbursement`（付款） |
| 凭证 currency | `≠ CNY`（外币） |
| Receipt 凭证 | 走 FxSettlement 结汇路径，不可付汇 |

### 6.2 付汇登记

`POST /api/v1/finance/outward-remittances` → `createOutwardRemittance`：

| 校验 | 规则 |
|------|------|
| 凭证存在 | `deletedAt: null` → `VOUCHER_NOT_FOUND` |
| 凭证类型 | `type === 'Disbursement'` → `NOT_A_DISBURSEMENT` |
| 凭证币种 | `currency !== 'CNY'` → `CNY_VOUCHER_NO_REMITTANCE` |
| 币种一致 | `remittance.currency === voucher.currency` → `CURRENCY_MISMATCH` |
| 未付余额 | `foreignAmount ≤ remaining` → `OVER_REMITTANCE` |
| cnyAmount | 服务端计算（`round4(foreignAmount × fxRate)`），客户端传入拒绝 |

### 6.3 付汇水单字段

| 字段 | 说明 |
|------|------|
| remittanceNumber | `OWR-YYYYMMDD-XXXX` |
| voucherId | 关联付款凭证 |
| remitDate | 付汇日期 |
| foreignAmount | 付汇外币金额 |
| fxRate | 购汇汇率（外币 → CNY） |
| cnyAmount | 折合人民币（服务端计算） |
| payeeName / payeeBank / payeeSwift | 境外收款方 |
| purpose | GoodsPayment / Freight / Insurance / Commission / Other |
| bank / slipNumber | 付汇银行 / 水单号 |

### 6.4 未付余额

```
remittedAmount = Σ active OutwardRemittance.foreignAmount WHERE voucherId
remainingAmount = voucher.amount - remittedAmount
fullyRemitted = remainingAmount ≤ 0
```

软删付汇水单即回滚未付余额（余额是 derived 查询，无冗余字段，无双写漂移）。

## §7 供应商对账单（getSupplierStatement）

### 7.1 数据源

- 发票：`type='Payable'`, `status≠Cancelled`, `deletedAt: null`, `customerRelationId=supplierId`
- 凭证：`type='Disbursement'`, `deletedAt: null`, `customerRelationId=supplierId`

> **设计**：Invoice.customerRelationId 承载交易对象（billTo linkKind），应付发票的交易对象即供应商。

### 7.2 借贷口径

| 流水类型 | 借方 | 贷方 |
|---------|------|------|
| 收票（应付发票） | invoice.amount | 0 |
| 付款（Disbursement 凭证） | 0 | voucher.amount |

```
openingBalance = Σ(from 之前收票) - Σ(from 之前付款)
running balance = opening + Σ(debit - credit)
closingBalance = 最后一条 balance
```

### 7.3 按币种分节

与客户对账单同算法——按币种分组构建 section，多币种不折算。

## §8 付款审批流（设计规格 · P1 缺口）

### 8.1 审批规则（DR-007 组织归属路由 · 彻底去阈值化）

> **决策点 3-A 声明**：审批规则彻底去阈值化，完全不看金额/比例，统一走 DR-007 组织归属路由。

| 场景 | 条件 | 审批链（DR-007） |
|------|------|------------------|
| 所有付款单 | `type=Disbursement`（全部金额/首单/非首单统一规则） | 付款申请人所属部门的主管；申请人无主管或部门为财务时由系统管理员（总领导）兜底；单次一位审批人即可 |

### 8.2 落点

- PaymentVoucher create 时，所有 `type=Disbursement` 类型统一触发审批判断（不看金额/首单）
- reviewerId 在服务端通过 `resolveReviewerByDepartment(申请人userId)` 解析：
  - 优先 `User.department.managerId`（付款申请人所属部门主管）
  - 无主管或部门为财务时 → fallback 系统管理员 ADMIN（总领导兜底）
- 审批通过 → status='unreconciled'
- 审批拒绝 → cancelVoucher

**当前**：所有付款凭证 create 即落库，审批流待接入。

## §9 应付账龄

报表 tab 账龄子视图支持 `agingType='Payable'`：

| 桶 | 语义 |
|----|------|
| current | 未到期应付 |
| d1_30 ~ d90plus | 逾期应付 |

**到期日推定**：`baseDate = invoice.dueDate ?? invoice.issueDate`（Net30 推定同应收侧）。

**未付余额**：`open = invoice.amount - Σ InvoiceAllocation.appliedAmount`。

## §10 AR/AP 看板（getArApSummary）

```
payable.total = Σ Payable 发票（Issued/PartiallyPaid）amount
payable.paid = Σ Disbursement 凭证（未 reconciled）amount
payable.outstanding = max(0, total - paid)
payable.count = 应付发票数
```

> **注意**：看板的 `paid` 用 Disbursement 凭证总额（非核销额），是"已付资金"口径；`outstanding` 是"应付敞口"估算。精确的应付余额以账龄报表为准。
