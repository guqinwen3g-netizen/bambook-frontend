## §2 Invoice 三类型

| type | 中文 | 业务语义 | 入账 | 看板可见 |
|------|------|---------|------|---------|
| `Receivable` | 应收 | 客户账单（Commercial Invoice） | ✅ AR | ✅ |
| `Payable` | 应付 | 供应商/工厂账单 | ✅ AP | ✅ |
| `Proforma` | 形式发票 | 外贸 PI，非正式财务发票 | ❌ 不入账 | ❌（AR/AP 看板排除） |

> **设计决策**：PI 复用 Invoice 模型（`type='Proforma'`），不改 schema；PI 状态复用 Invoice 状态机（Draft→Issued→Cancelled）；AR/AP 看板在 `getArApSummary` 中过滤 `type='Receivable'/'Payable'`。

## §3 Invoice 5 态状态机

### 3.1 状态定义

| 状态 | 中文 | 语义 | 是否终态 |
|------|------|------|---------|
| `Draft` | 草稿 | 录入未开票 | 否 |
| `Issued` | 已开票 | 正式开票，进入 AR/AP | 否 |
| `PartiallyPaid` | 部分销账 | 有核销但未全额 | 否 |
| `Paid` | 已结清 | 全额收款/付款 | 否（可作废信用退） |
| `Cancelled` | 已作废 | 终态 | **是** |

**枚举真源**：`VALID_INVOICE_STATUS = ['Draft', 'Issued', 'PartiallyPaid', 'Paid', 'Cancelled']`（statusTransition.ts L14）。

### 3.2 合法转移矩阵

**后端真源** `INVOICE_TRANSITIONS`（statusTransition.ts L17-L23）：

| 当前 (from) | 可推进到 (to) | 说明 |
|-------------|--------------|------|
| Draft | Issued / Cancelled | 草稿可开票或作废 |
| Issued | PartiallyPaid / Paid / Cancelled | 开票后可被核销或作废 |
| PartiallyPaid | Paid / Cancelled | 部分核销可推进全额或作废 |
| Paid | Cancelled | 已结清可作废（信用退），不可回退 |
| Cancelled | — | **终态**，无任何推进 |

```
Draft ──▶ Issued ──▶ PartiallyPaid ──▶ Paid ──▶ Cancelled
  │          │            │              │
  └──────────┴────────────┴──────────────┘
                (任意非终态可直接作废)
```

### 3.3 手动 vs 自动状态设置

| 状态 | 手动 PATCH | 自动（allocation 重算） |
|------|-----------|------------------------|
| Draft | ✅ | — |
| Issued | ✅ | — |
| Cancelled | ✅ | — |
| PartiallyPaid | ❌ `STATUS_NOT_MANUAL_SETTABLE` | ✅ `recalcInvoiceStatus` |
| Paid | ❌ `STATUS_NOT_MANUAL_SETTABLE` | ✅ `recalcInvoiceStatus`（全额时自动写 `settlementDate`） |

> **设计决策**：PartiallyPaid/Paid 只能由 `allocationMutationService` 的 `recalcInvoiceStatus` 自动重算，禁止手动 PATCH 篡改，确保核销口径与发票状态强一致。

## §4 开票（createInvoice）

### 4.1 前端表单

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| invoiceNumber | string | ✅ | 服务端自动生成（INV-YYYY-NNNN），传入优先 |
| type | Receivable/Payable | ✅ | 默认 Receivable（prime 时预填 Payable） |
| status | InvoiceStatus | — | 默认 Draft |
| amount | number | ✅ | > 0 |
| currency | USD/CNY/EUR/HKD | ✅ | 默认 USD |
| customerName | string | — | 交易对象名 |
| customerRelationId | string | — | 关联 Relation（billTo） |
| issueDate | YYYY-MM-DD | — | 缺省开票当天 |
| dueDate | YYYY-MM-DD | — | 到期日 |
| exchangeRate | number | — | 外贸汇率快照 |
| orderId | string | — | 关联订单 |
| notes | string | — | 备注 |

### 4.2 后端契约

`POST /api/v1/finance/invoices` → `createInvoice`：

```
1. normalizeCreateInput
   ├─ pick(INVOICE_CREATE_FIELDS)
   ├─ status 校验: validateStatusTransition('Invoice', 'Draft', status)
   ├─ issueDate 兜底: 缺省/空串 → localToday()
   └─ amount 校验: isValidDecimalInput + normalizeDecimalFields

2. $transaction
   ├─ id = generateId('INV')
   ├─ invoiceNumber = input.invoiceNumber || nextBusinessNumber(tx, 'INV')
   ├─ tx.invoice.create({ ...data, createdAt, updatedAt })
   ├─ syncInvoiceReferences(prisma, invoice, source, tx)  ← EntityLink
   └─ writeRouteAuditLog(create_invoice)

3. 事务提交后 fire-and-forget
   └─ status === 'Issued' → publishBusinessEvent(InvoiceIssued)
```

**错误码**：`INVALID_STATUS` / `INVALID_TRANSITION` / `INVALID_AMOUNT` / `CREATE_FAILED`。

## §5 编辑（updateInvoice）

`PATCH /api/v1/finance/invoices/:id` → `updateInvoice`：

| 校验 | 规则 |
|------|------|
| 存在性 | `findUnique` + `deletedAt` 校验 → `NOT_FOUND` |
| status 手动限制 | `PartiallyPaid`/`Paid` → `STATUS_NOT_MANUAL_SETTABLE` |
| 状态转移 | `validateStatusTransition('Invoice', from, to)` |
| Decimal | `normalizeDecimalFields`（amount/exchangeRate） |

**事务内**：update + syncInvoiceReferences + auditLog（before/after status + amount）。

**事件发布**（仅 `hasStatus && fromStatus !== toStatus`）：
- → `Issued` → `InvoiceIssued`
- → `Cancelled` → `InvoiceCancelled`

---

## §6 作废（cancelInvoice）

`POST /api/v1/finance/invoices/:id/cancel` → `cancelInvoice`（voidDeleteService.ts）：

| 校验 | 规则 |
|------|------|
| 存在性 | `findUnique` + `deletedAt` → `INVOICE_NOT_FOUND` |
| 当前态 | 已 Cancelled → `INVALID_STATUS`（幂等拒绝） |
| 合法作废源 | `VALID_CANCEL_FROM = {Draft, Issued, PartiallyPaid, Paid}` |
| 核销阻断 | `InvoiceAllocation.count > 0` → `HAS_ALLOCATIONS`（必须先撤销核销） |

**事务内**：`status → 'Cancelled'` + `deactivateEntityLinks('invoice', id)` + auditLog。

> **关键约束**：有核销记录的发票不能直接作废——必须先 delete 所有 InvoiceAllocation（核销全撤销后 status 回退 Issued），再作废。防止孤儿核销。

---

## §7 软删（deleteInvoice）

`DELETE /api/v1/finance/invoices/:id` → `deleteInvoice`：

- 核销阻断：`InvoiceAllocation.count > 0` → `HAS_ALLOCATIONS`（409）
- 软删：`deletedAt = now` + `deactivateEntityLinks` + auditLog
- 归档后从默认列表移除（`deletedAt: null` 过滤）

## §8 形式发票（PI）管理

### 8.1 从报价单生成 PI

`POST /api/v1/finance/quotations/:id/generate-pi` → `generateFromQuotation`：

| 校验 | 规则 |
|------|------|
| 报价单存在 | `deletedAt: null` → `QUOTATION_NOT_FOUND` |
| 报价单状态 | `status === 'Accepted'` → `QUOTATION_NOT_ACCEPTED` |

**生成内容**：
- `type='Proforma'`, `status='Draft'`
- 金额/币种/汇率/客户从报价单快照
- 报价单行项目快照到 `attachments.lines`
- 条款信息（交货/付款/业务员）快照到 `notes`

**事件**：`ProformaInvoiceGenerated`。

### 8.2 PI 转换为正式应收发票

`POST /api/v1/finance/invoices/:id/convert-to-receivable` → `convertToReceivable`：

| 校验 | 规则 |
|------|------|
| 发票存在 | `deletedAt: null` → `NOT_FOUND` |
| 类型 | `type === 'Proforma'` → `NOT_PROFORMA` |
| 状态 | `status !== 'Cancelled'` → `ALREADY_CONVERTED` |

**转换逻辑**（事务内）：
1. 生成新应收发票编号（`seqSvc.nextNumber('invoice')`）
2. 新建 `type='Receivable'`, `status='Issued'` Invoice（金额/币种/汇率/客户从 PI 快照）
3. 原 PI `status → 'Cancelled'`，notes 追加 `已转换为正式应收发票: ${number}`
4. auditLog（before: PI 信息 / after: 应收发票信息）

**事件**：`ProformaInvoiceConverted`。

> **红冲语义**：Invoice 模型无独立红冲操作。外贸场景的"红冲"通过 PI 转换实现（原 PI → Cancelled + 新建 Receivable）；增值税发票的红冲在 VatInvoice 状态机内独立处理。

## §9 Decimal 金额校验

```typescript
function isValidDecimalInput(v: unknown): boolean {
  if (typeof v === 'number') return Number.isFinite(v);
  if (typeof v === 'string') {
    if (!/^-?\d+(\.\d+)?$/.test(v.trim())) return false;
    return new Prisma.Decimal(v).isFinite();
  }
  return false;
}
```

- `amount` / `exchangeRate` 为 Decimal 字段（`@db.Decimal(18,4)` / `@db.Decimal(18,4)`）
- 输入校验通过后转 `new Prisma.Decimal(v)` 写入，避免 IEEE 754 漂移
- audit 展示用 `decimalString(v)`（toString 保精度）

## §14 关联保护

发票删除/作废的关联保护校验：

```
InvoiceAllocation.count(where: { invoiceId }) > 0
  → HAS_ALLOCATIONS 400/409
  → 必须先 delete 所有 allocation（核销全撤销）
  → recalcInvoiceStatus 回退到 Issued
  → 再 cancel/delete
```
