## §2 账龄五桶模型

### 2.1 桶定义

| 桶 key | 中文 | 语义 |
|--------|------|------|
| `current` | 未到期 | daysOverdue ≤ 0 |
| `d1_30` | 1-30 天 | 0 < daysOverdue ≤ 30 |
| `d31_60` | 31-60 天 | 30 < daysOverdue ≤ 60 |
| `d61_90` | 61-90 天 | 60 < daysOverdue ≤ 90 |
| `d90plus` | 90 天以上 | daysOverdue > 90 |

**真源**：`bucketOf(daysOverdue)`（reportService.ts L48-L54）。

### 2.2 到期日推定（Net30）

```
baseDate = invoice.dueDate ?? invoice.issueDate
baseMs = new Date(baseDate + 'T00:00:00Z').getTime()
daysOverdue = floor((asOfMs - baseMs) / MS_PER_DAY)
```

| 场景 | baseDate 取值 | 说明 |
|------|-------------|------|
| 有 dueDate | `invoice.dueDate` | 显式到期日 |
| 无 dueDate | `invoice.issueDate` | **Net30 推定**——开票日即视为到期（保守口径） |

> **设计决策**：无 dueDate 时回退 issueDate（而非 issueDate + 30 天），采用最保守口径——开票即开始计账龄。这确保无到期日的发票不会"隐藏"在未到期桶里。Net30 推定语义体现在外贸 T/T 30 天默认账期，但账龄计算不自动加 30 天。

### 2.3 未核销余额口径

```
open = invoice.amount - Σ InvoiceAllocation.appliedAmount WHERE invoiceId
if (open <= 0) continue  // 已全额核销，不计入账龄
```

**与 recalcInvoiceStatus 同口径**：未核销余额 = 发票金额 - 核销汇总，确保报表与状态机一致。

## §3 InvoiceAllocation 核销机制

### 3.1 模型语义

```
InvoiceAllocation（核销明细，1:N:N 中间表）
  ├─ invoiceId  → Invoice（一张发票可被多笔凭证核销）
  ├─ voucherId  → PaymentVoucher（一笔凭证可核销多张发票）
  ├─ appliedAmount  本笔核销金额
  └─ appliedDate    核销日期

@@unique([invoiceId, voucherId])  一对 invoice-voucher 只能有一条明细
```

**硬删除**（无 deletedAt）：核销调整 = delete 旧明细 + insert 新明细，避免软删 + unique 冲突。

### 3.2 核销事务（applyAllocation）

`POST /api/v1/finance/allocations` → `createAllocation` → `applyAllocation`：

```
1. 校验（fail closed）
   ├─ invoice 存在 + 未删 + status∉{Cancelled, Draft}
   ├─ voucher 存在 + 未删 + status∉{cancelled, void}
   ├─ 币种一致: invoice.currency === voucher.currency
   ├─ appliedAmount ≤ invoice.amount
   ├─ appliedAmount ≤ voucher.amount
   ├─ appliedAmount ≤ invoice 剩余可核销（排除当前 voucher 已有 allocation）
   └─ appliedAmount ≤ voucher 剩余可分配（排除当前 invoice 已有 allocation）

2. upsert allocation（@@unique([invoiceId, voucherId])）
   ├─ update: appliedAmount, appliedDate, updatedAt
   └─ create: id=ALLOC__${invoiceId}__${voucherId}

3. recalcInvoiceStatus(tx, invoiceId)
   ├─ totalApplied = Σ allocation.appliedAmount
   ├─ totalApplied >= invoice.amount → 'Paid'（自动写 settlementDate）
   ├─ totalApplied > 0 → 'PartiallyPaid'
   └─ totalApplied == 0 → 回退 'Issued'（若当前 Paid/PartiallyPaid）

4. recalcVoucherStatus(tx, voucherId)
   ├─ totalAllocated = Σ allocation.appliedAmount
   ├─ totalAllocated >= voucher.amount → 'reconciled'
   ├─ totalAllocated > 0 → 'partially_reconciled'
   └─ else → 'unreconciled'

5. syncInvoiceReferences + syncPaymentVoucherReferences + syncAllocationVoucherLinks
6. writeRouteAuditLog
```

### 3.3 并发安全（Serializable）

```typescript
const SERIALIZABLE_TX = { isolationLevel: Prisma.TransactionIsolationLevel.Serializable };
```

**根因**：allocation check-then-act（检查剩余 → 写入）在 READ COMMITTED 下两事务并发核销同一发票可双双通过剩余校验 → 超核销。

**解决**：Serializable 隔离级别下，SSI 中止其中一方（P2034 → `CONFLICT` / 409），调用方重试即可。

## §4 账龄报表（getAgingReport）

### 4.1 输入

| 参数 | 类型 | 说明 |
|------|------|------|
| type | `Receivable` / `Payable` | 应收或应付账龄 |
| asOf | YYYY-MM-DD | 截止日，缺省当天 |

### 4.2 查询逻辑

```
1. invoices = findMany({ type, status∈{Issued, PartiallyPaid}, deletedAt: null })

2. allocSums = groupBy({ by: invoiceId, _sum: appliedAmount })
   → allocMap = Map<invoiceId, sumApplied>

3. for each invoice:
   ├─ open = amount - allocMap[invoiceId]
   ├─ if open <= 0 → continue  // 已全额核销
   ├─ daysOverdue = floor((asOf - baseDate) / MS_PER_DAY)
   ├─ bucket = bucketOf(daysOverdue)
   └─ 按 (customerRelationId ?? customerName, currency) 分组累加

4. rows = 按 total 降序
5. totals = 按币种汇总五桶
```

### 4.3 多币种不折算

> **设计决策**：多币种不折算汇总——按 (客户, 币种) 分行，避免汇率假设污染报表。每个币种独立汇总 totals。

## §5 客户对账单（getCustomerStatement）

### 5.1 数据源

- 发票：`type=Receivable`, `status≠Cancelled`, `deletedAt: null`
- 凭证：`type=Receipt`, `deletedAt: null`

### 5.2 按币种分节

每个币种独立构建 section：

```
openingBalance = Σ(from 之前发票) - Σ(from 之前收款)

transactions = [发票(借) + 收款(贷)] 按 date + number 排序
  → running balance = opening + Σ(debit - credit)

closingBalance = 最后一条 transaction 的 balance
```

| 列 | 借方 | 贷方 |
|----|------|------|
| 发票 | invoice.amount | 0 |
| 收款 | 0 | voucher.amount |

## §7 核销状态重算（Decimal-safe）

### 7.1 recalcInvoiceStatus

```typescript
let total = new Prisma.Decimal(0);
for (const a of allocs) total = total.plus(a.appliedAmount);
const invoiceAmount = new Prisma.Decimal(invoice.amount);

if (invoiceAmount.gt(0) && total.gte(invoiceAmount)) return 'Paid';
if (total.gt(0)) return 'PartiallyPaid';
if (invoice.status === 'Paid' || invoice.status === 'PartiallyPaid') return 'Issued';
return invoice.status;
```

**Decimal-safe**：用 `Prisma.Decimal`（非 `Number()`）累加，避免 IEEE 754 漂移。

### 7.2 recalcVoucherStatus

同算法，返回 `{ status, totalAllocated }`——totalAllocated 用汇总值写 `PaymentVoucher.appliedAmount`。

## §8 EntityLink 同步

核销操作后维护 `settlesInvoice` link（paymentVoucher → invoice）：

```
syncAllocationVoucherLinks(tx, voucherId):
  1. 当前 allocation rows → activeInvoiceIds 集合
  2. upsert active link for each current allocation
     └─ EntityReference + EntityLink (settlesInvoice, confidence=1)
  3. 停用不再属于当前 allocation 的 settlesInvoice link
     └─ status → 'inactive', deletedAt → now
```

> **设计**：split voucher（多张 invoice）/ delete allocation 时 EntityLink 与事实源一致，不漂移。

## §11 应收/应付切换

报表 tab 账龄子视图支持 `agingType` 切换：
- `Receivable`：应收账龄（客户欠我）
- `Payable`：应付账龄（我欠供应商）

切换后重新调 `getAgingReport(type)`，汇总卡片标题随之变化（应收未收 / 应付未付）。
