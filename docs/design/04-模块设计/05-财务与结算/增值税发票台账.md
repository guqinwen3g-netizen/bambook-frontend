## §2 业务背景

外贸企业适用「免退」办法：出口销售免征增值税，采购环节取得的增值税专用发票可申报出口退税。退税计算口径：

```
出口退税额 = 进项专票注明金额 × 退税率
```

**无增值税专用发票 = 无退税**。因此 VatInvoice 模型是退税合规的硬前提，其生命周期直接决定退税申报的合法性与可追溯性。

### 2.1 进项 vs 销项

| 维度 | Input（进项） | Output（销项） |
|------|--------------|--------------|
| 取得方向 | 采购取得（供应商开给本公司） | 内销开出（本公司开给客户） |
| 发票类型 | Special（专票）可退税；Normal（普票）不可退税 | Special / Normal 均用于销项税申报 |
| 退税资格 | ✅ 仅 Input + Special 可申报退税 | ❌ 销项不涉及出口退税 |
| 默认值 | `direction @default("Input")` | — |

### 2.2 专票 vs 普票

| 类型 | invoiceType | 退税资格 | 用途 |
|------|-------------|---------|------|
| 专票 | Special | ✅ 可退税 | 进项抵扣 + 出口退税 |
| 普票 | Normal | ❌ 不可退税 | 仅作入账凭证 |

## §3 VatInvoice 5 态状态机

### 3.1 状态定义

| 状态 | 含义 | 税务语义 |
|------|------|---------|
| Received | 已收票 | 发票已取得，尚未勾选认证 |
| Verified | 已勾选认证 | 进入抵扣/退税勾选池，记录勾选所属期 |
| Declared | 已申报退税 | 已用于出口退税申报，关联 TaxRefund |
| RedFlushed | 已红冲 | 原票作废，开具红字发票冲回 |
| Cancelled | 已作废 | 终态，票据作废（非红冲路径） |

### 3.2 合法转移矩阵

**后端真源** `VAT_TRANSITIONS`（vatInvoiceService.ts L111-L117）：

| 当前 (from) | 可推进到 (to) | 说明 |
|-------------|--------------|------|
| Received | Verified / Cancelled | 收票后可勾选认证或直接作废 |
| Verified | Declared / RedFlushed | 认证后可申报退税或红冲 |
| Declared | RedFlushed | 已申报仅可红冲（不可作废，税务留痕） |
| RedFlushed | — | **终态**，无任何推进 |
| Cancelled | — | **终态**，无任何推进 |

```
                ┌───────────┐
                │  Received │ ← createVatInvoice
                └─────┬─────┘
              ┌───────┴───────┐
              ▼               ▼
        ┌──────────┐    ┌──────────┐
        │ Verified │    │ Cancelled│ (终态)
        └─────┬────┘    └──────────┘
        ┌─────┴────┐
        ▼          ▼
  ┌──────────┐ ┌────────────┐
  │ Declared │ │ RedFlushed │ (终态)
  └─────┬────┘ └────────────┘
        │
        ▼
  ┌────────────┐
  │ RedFlushed │ (终态)
  └────────────┘
```

### 3.3 转移硬校验（transitionVatInvoiceStatus）

| 目标状态 | 硬校验 | 失败码 |
|---------|--------|--------|
| Verified | verifiedDate 缺省当日 + `YYYY-MM-DD` 校验 | `INVALID_DATE` |
| Verified | deductionPeriod 非空时 `YYYY-MM` 校验 | `INVALID_DATE` |
| Declared | `direction === 'Input' && invoiceType === 'Special'` | `NOT_INPUT_SPECIAL` |
| Declared | taxRefundId 必填（或已挂在票上） | `TAX_REFUND_REQUIRED` |
| Declared | TaxRefund 存在且未软删 | `TAX_REFUND_NOT_FOUND` |
| RedFlushed | redFlushDate 缺省当日 + `YYYY-MM-DD` 校验 | `INVALID_DATE` |
| 任意 | from → to 在 VAT_TRANSITIONS 内 | `INVALID_TRANSITION` |

> **关键约束**：`→Declared` 强制 `Input + Special`——普票与销项发票不可申报出口退税，这是「免退」办法的合规底线。

## §4 金额三栏校验（validateAmounts）

```typescript
// vatInvoiceService.ts L147-L159
function validateAmounts(netAmount, taxRate, taxAmount, totalAmount): VatInvoiceError | null {
  if (netAmount <= 0 || taxAmount < 0 || totalAmount <= 0 || taxRate < 0 || taxRate > 100)
    return { code: 'INVALID_AMOUNT', ... };
  // 精确：totalAmount == netAmount + taxAmount
  if (round4(netAmount + taxAmount) !== round4(totalAmount))
    return { code: 'AMOUNT_MISMATCH', ... };
  // 容差：taxAmount ≈ netAmount × taxRate/100（±0.02 开票尾差）
  const expectedTax = round4(netAmount * (taxRate / 100));
  if (Math.abs(expectedTax - taxAmount) > TAX_TOLERANCE)  // 0.02
    return { code: 'TAX_MISMATCH', ... };
  return null;
}
```

| 校验 | 精度 | 容差 | 失败码 |
|------|------|------|--------|
| totalAmount = netAmount + taxAmount | round4 精确一致 | 0（精确） | `AMOUNT_MISMATCH` |
| taxAmount ≈ netAmount × taxRate/100 | round4 | ±0.02（开票尾差） | `TAX_MISMATCH` |
| 各金额正值 / taxRate ∈ [0,100] | — | — | `INVALID_AMOUNT` |

> **容差 0.02 的来源**：税务开票系统按「金额×税率」计算税额时存在分位四舍五入尾差，0.02 元容差覆盖最常见的尾差场景，避免合法票据因尾差被拒。

### 4.1 字段精度

| 字段 | 类型 | 精度 | 说明 |
|------|------|------|------|
| netAmount | Decimal(18,4) | 4 位 | 不含税金额 |
| taxRate | Decimal(6,4) | 4 位 | 税率(%)，如 13.0000 |
| taxAmount | Decimal(18,4) | 4 位 | 税额 |
| totalAmount | Decimal(18,4) | 4 位 | 价税合计 = netAmount + taxAmount |
| currency | String | — | 默认 CNY（增值税发票以人民币计） |

## §5 唯一性与查重

### 5.1 复合唯一约束

```prisma
@@unique([vatCode, vatNumber])
```

| 字段 | 纸质票 | 全电票 |
|------|--------|--------|
| vatCode | 10/12 位发票代码 | NULL |
| vatNumber | 8 位发票号码 | 20 位号码 |

### 5.2 全电票 NULL 处理

PostgreSQL 中 NULL 不参与唯一约束冲突（`NULL != NULL`），因此全电票（vatCode 为 NULL）在数据库层不会触发唯一冲突。服务端在事务内**应用层查重兜底**：

```typescript
// vatInvoiceService.ts L207-L213
const dup = await tx.vatInvoice.findFirst({
  where: { vatCode, vatNumber, deletedAt: null },
  select: { id: true },
});
if (dup) throw { code: 'DUPLICATE_VAT_INVOICE', ... };
```

> **fail closed**：即使数据库唯一约束未触发，应用层查重确保全电票不会重复登记。查询包含 `deletedAt: null`，软删的发票号码可被重新登记（红冲后重开场景）。

## §6 退税联动（→Declared）

`→Declared` 是 VatInvoice 最严格的转移，硬校验链：

```
→Declared
  ├─ 1. direction === 'Input'           否则 NOT_INPUT_SPECIAL
  ├─ 2. invoiceType === 'Special'       否则 NOT_INPUT_SPECIAL
  ├─ 3. taxRefundId 非空                 否则 TAX_REFUND_REQUIRED
  └─ 4. TaxRefund 存在且 deletedAt=null  否则 TAX_REFUND_NOT_FOUND
```

### 6.1 TaxRefund 模型关联

VatInvoice.taxRefundId 关联 TaxRefund（退税申报），退税申报本身有独立状态机（Draft→Submitted→Reviewing→Approved→Rejected→Refunded→Cancelled）。一张专票对应一次退税申报，退税申报可关联多张专票（1:N）。

### 6.2 退税金额口径

```
出口退税额 = 进项专票 netAmount（不含税金额） × refundableRate（退税率）
```

> 退税额在 TaxRefund 模型中计算（`refundableVat` / `refundAmount`），VatInvoice 仅提供专票金额与税率的真源。

## §7 CRUD 操作约束

### 7.1 创建（createVatInvoice）

- 必填：vatNumber, sellerName, buyerName, issueDate, netAmount, taxRate, taxAmount, totalAmount
- 缺省：direction=Input, invoiceType=Special, status=Received, currency=CNY
- 金额三栏校验 + 查重

### 7.2 更新（updateVatInvoice）

| 状态 | 可编辑性 | 失败码 |
|------|---------|--------|
| Received / Verified | ✅ 可改票面与关联 | — |
| Declared / RedFlushed / Cancelled | ❌ 不可编辑（税务留痕） | `INVALID_STATUS` |

> 已申报/红冲/作废的发票票面与关联锁定，确保税务数据不可篡改。

### 7.3 删除（deleteVatInvoice）

| 状态 | 可删除性 | 失败码 |
|------|---------|--------|
| Received / Verified | ✅ 可软删 | — |
| Declared | ❌ 不可删除（税务留痕，仅可红冲） | `DELETE_FORBIDDEN` |
| RedFlushed / Cancelled | ✅ 可软删（终态清理） | — |

> **Declared 不可删除是税务合规硬约束**——已申报退税的发票必须保留留痕，错误申报只能通过红冲冲回，不可直接删除。

## §8 红冲机制（→RedFlushed）

红冲是税务上冲销原票的标准方式（开具红字增值税发票）：

| 字段 | 说明 |
|------|------|
| redFlushNumber | 红字发票号码（可带，登记红字票号） |
| redFlushDate | 红冲日期（缺省当日，`YYYY-MM-DD`） |

红冲后发票进入终态（RedFlushed），不可再推进。原票金额仍保留在记录中，税务上以红字票冲回。

## §14 交互规范

- 收票登记表单：vatCode/vatNumber（全电票 vatCode 留空）/买卖方/金额三栏/税率
- 金额三栏联动：输入 netAmount + taxRate 后自动计算 taxAmount 与 totalAmount（前端辅助，服务端仍校验）
- 状态转移按钮按当前状态动态显示合法目标（Received→Verified/Cancelled 等）
- →Declared 时强制选择 TaxRefund（下拉已申报未关联专票的退税申报）
- Declared 状态的行不可编辑不可删除（按钮置灰 + tooltip 说明）
