## §2 业务背景与口径

外贸企业收到外币货款后，须经过银行结汇将外币兑换为人民币入账。结汇存在两层口径：

| 口径 | 含义 | 真源 |
|------|------|------|
| **收款日汇率快照** | 凭证录入时落库的 `PaymentVoucher.exchangeRate`（外币 → CNY） | PaymentVoucher |
| **结汇日实际汇率** | 结汇水单登记时的银行实际结汇汇率 `FxSettlement.fxRate` | FxSettlement |

两者差额 × 结汇外币金额 = **汇兑损益线索**（`fxDiffEstimate`）。该值是估算口径（基于快照与实际汇率差），非最终会计损益——会计损益需结合月末调汇、已实现/未实现损益分类由总账系统确认，本系统提供线索与透明明细供财务复核。

### 2.1 核心设计决策（fail closed）

| 决策 | 实现 |
|------|------|
| 一笔外币收款可分次结汇 | `1 voucher : N settlements`，核销余额 = `voucher.amount - Σactive settlements.foreignAmount` |
| cnyAmount 服务端计算 | `round4(foreignAmount × fxRate)`，客户端传入一律拒绝（`INVALID_INPUT`） |
| orderId / customerRelationId 从凭证继承 | 单一真源，不接受客户端覆盖 |
| CNY 凭证无结汇语义 | `CNY_VOUCHER_NO_SETTLEMENT`（fail closed） |
| Disbursement 凭证走付汇路径 | `NOT_A_RECEIPT`（仅 Receipt 凭证可结汇） |
| 软删即回滚核销余额 | 余额是 derived 查询（无冗余字段），软删后 `sumSettledForVoucher` 自动剔除 |

## §3 结汇水单生命周期

FxSettlement 无独立状态机——它是**事实记录**（fact record），只有创建与软删两个动作：

```
┌─────────────────────────────────────────────────────────────┐
│  createFxSettlement                                         │
│  ┌──────────┐  校验   ┌──────────┐  写入   ┌──────────┐    │
│  │ 输入校验  │────────▶│ 凭证校验  │────────▶│ 创建水单  │    │
│  │ (fail    │         │ + 余额   │         │ + AuditLog│    │
│  │  closed) │         │  校验    │         │ + Event   │    │
│  └──────────┘         └──────────┘         └─────┬────┘    │
│                                                  │         │
│                                                  ▼         │
│                                          publishBusiness  │
│                                          Event(FxSettlement│
│                                          Created)         │
└─────────────────────────────────────────────────────────────┘
                                                  │
                                                  │ 软删
                                                  ▼
┌─────────────────────────────────────────────────────────────┐
│  deleteFxSettlement                                         │
│  ┌──────────┐  查询   ┌──────────┐  软删   ┌──────────┐   │
│  │ 存在性   │────────▶│ deletedAt│────────▶│ EntityLink│   │
│  │ 校验     │         │ = now    │         │ inactive  │   │
│  └──────────┘         └──────────┘         │ + AuditLog│   │
│                                            └──────────┘   │
│  → 余额自动回滚（derived 查询剔除软删行）                    │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 创建校验链（createFxSettlement）

| 步骤 | 校验 | 失败码 |
|------|------|--------|
| 1 | voucherId 非空字符串 | `INVALID_INPUT` |
| 2 | settleDate 匹配 `YYYY-MM-DD` | `INVALID_DATE` |
| 3 | foreignAmount 为正 decimal | `INVALID_AMOUNT` |
| 4 | fxRate 为正 decimal | `INVALID_AMOUNT` |
| 5 | cnyAmount 不得传入（服务端计算） | `INVALID_INPUT` |
| 6 | 凭证存在且未软删 | `VOUCHER_NOT_FOUND` |
| 7 | `voucher.type === 'Receipt'` | `NOT_A_RECEIPT` |
| 8 | `voucher.currency !== 'CNY'` | `CNY_VOUCHER_NO_SETTLEMENT` |
| 9 | currency 与凭证一致（缺省继承） | `CURRENCY_MISMATCH` |
| 10 | `foreignAmount ≤ remaining`（防超结） | `OVER_SETTLEMENT` |

### 3.2 防超结机制

```typescript
// fxSettlementService.ts L136-L145
const settled = await sumSettledForVoucher(tx, voucher.id);     // Σ active settlements
const voucherAmount = Number(voucher.amount.toString());
const remaining = round4(voucherAmount - settled);
const foreignAmount = Number(input.foreignAmount);
if (foreignAmount > remaining) {
  throw { code: 'OVER_SETTLEMENT',
    message: `foreignAmount ${foreignAmount} exceeds remaining ${remaining} ${voucher.currency} ...` };
}
```

> **关键约束**：`sumSettledForVoucher` 在事务内查询（tx 感知），确保并发结汇不会突破余额上限。但由于默认隔离级别非 Serializable，极端并发下仍可能存在窗口——如需更强保证，应在事务前对 voucher 加行锁（`SELECT ... FOR UPDATE`），当前实现以「校验 + 余额派生」为主防线。

## §4 cnyAmount 服务端计算（防篡改口径）

```typescript
// fxSettlementService.ts L148-L149
const fxRate = Number(input.fxRate);
const cnyAmount = round4(foreignAmount * fxRate);
```

落库时外币金额与汇率分别用 `Decimal(18,4)` 与 `Decimal(18,8)` 存储，cnyAmount 用 `Decimal(18,4)`：

| 字段 | 类型 | 精度 | 说明 |
|------|------|------|------|
| foreignAmount | Decimal(18,4) | 4 位小数 | 结汇外币金额 |
| fxRate | Decimal(18,8) | 8 位小数 | 结汇汇率（外币 → CNY），高精度避免累计误差 |
| cnyAmount | Decimal(18,4) | 4 位小数 | 折合人民币，服务端 `round4` 后落库 |

**客户端传入 cnyAmount 一律拒绝**：`if ((input as any).cnyAmount !== undefined) return INVALID_INPUT`。这防止前端口径漂移导致台账与水单不一致。

## §5 凭证结汇摘要（getVoucherSettlementSummary）

单凭证视角的结汇进度查询，用于详情面板展示「已结汇 / 未结汇」：

| 返回字段 | 计算 | 说明 |
|---------|------|------|
| voucherAmount | `Number(voucher.amount)` | 凭证原币金额 |
| settledAmount | `Σ settlements.foreignAmount`（active） | 已结汇外币 |
| remainingAmount | `round4(voucherAmount - settled)` | 未结汇余额 |
| fullySettled | `remaining <= 0` | 是否全额结汇 |
| settlements[] | 按 settleDate 升序 | 水单明细列表 |

> 该接口只读，不写审计日志。

## §6 外汇台账（getFxLedger）

外汇台账是报表 tab 的核心子视图，按币种聚合「收汇 / 结汇 / 未结汇 / 加权汇率 / 汇兑差额」：

### 6.1 FxLedgerRow 字段

| 字段 | 计算 | 口径 |
|------|------|------|
| currency | 币种 | 分组键 |
| receivedTotal | `Σ periodVouchers.amount` | 期间内外币收汇总额（Receipt，排除 CNY） |
| settledTotal | `Σ periodSettlements.foreignAmount` | 期间内已结汇外币总额 |
| unsettledBalance | `Σ allReceipts.remaining` | **全量口径**未结汇余额（不限期间） |
| settlementCount | `periodSettlements.length` | 结汇笔数 |
| weightedAvgSettleRate | `ΣcnyAmount / ΣforeignAmount` | 加权平均结汇汇率（8 位小数） |
| fxDiffEstimate | `Σ((fxRate - voucher.exchangeRate) × foreignAmount)` | 汇兑损益线索（4 位小数） |

### 6.2 期间 vs 全量口径

```
┌─────────────────────────────────────────────────────────────┐
│  期间口径（from/to）：回答「这段时间收了多少/结了多少」        │
│  ├─ periodVouchers: paymentDate ∈ [from, to]                │
│  └─ periodSettlements: settleDate ∈ [from, to]             │
│                                                             │
│  全量口径：回答「现在还有多少外币躺在账上」                    │
│  └─ allForeignReceipts + allSettlements → unsettledVouchers │
└─────────────────────────────────────────────────────────────┘
```

`unsettledVouchers` 列表按 paymentDate 倒序（最近收汇优先处理），每条含 `voucherNumber / customerName / paymentDate / currency / voucherAmount / remainingAmount`。

### 6.3 汇兑损益估算（fxDiffEstimate）

```typescript
// fxSettlementService.ts L381-L385
const vRate = voucherRateById.get(s.voucherId)?.exchangeRate;  // 收款日汇率快照
if (vRate != null) {
  b.fxDiff += (Number(s.fxRate.toString()) - Number(vRate.toString())) * foreign;
  b.fxDiffKnown = true;
}
```

| 情形 | fxDiffEstimate | 说明 |
|------|----------------|------|
| 凭证有 exchangeRate 快照 | 计算值 | `Σ((结汇汇率 - 收款日汇率) × 结汇外币)` |
| 凭证无 exchangeRate 快照 | `null` | `fxDiffKnown = false`，透明披露「无法估算」 |

> **正值为汇兑收益**（结汇汇率高于收款日），**负值为汇兑损失**。该值是线索而非最终会计损益——最终损益需总账系统按月末调汇与已实现/未实现分类确认。

## §7 编号规则

| 实体 | 前缀 | 生成规则 | 示例 |
|------|------|---------|------|
| FxSettlement.id | `FXS` | `FXS__${Date.now().toString(36)}${rand}` | `FXS__lxk4abc123` |

## §13 交互规范

- 结汇按钮仅在外币 Receipt 凭证详情面板显示（CNY/Disbursement 凭证隐藏）
- 结汇金额默认填入 `remainingAmount`，用户可调小但不可调大
- 汇率默认填入最新 `ExchangeRate` 记录，用户可修改（以银行实际水单为准）
- 软删水单需二次确认（影响核销余额回滚）
- 外汇台账支持按币种筛选 + 期间切换

## §14 数据完整性约束

| 约束 | 实现 | 违反后果 |
|------|------|---------|
| 凭证存在 + 未软删 | findUnique + deletedAt 检查 | `VOUCHER_NOT_FOUND` |
| 仅 Receipt 凭证可结汇 | type 检查 | `NOT_A_RECEIPT` |
| CNY 凭证无结汇语义 | currency 检查 | `CNY_VOUCHER_NO_SETTLEMENT` |
| 币种一致 | currency 与凭证比对 | `CURRENCY_MISMATCH` |
| 防超结 | foreignAmount ≤ remaining | `OVER_SETTLEMENT` |
| cnyAmount 服务端计算 | 拒绝客户端传入 | `INVALID_INPUT` |
