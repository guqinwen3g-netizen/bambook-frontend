## §2 关键设计决策（DR-050）

### DR-050-① 函生成即时组装（不落模板表）：账龄明细是快照不是模板变量

- 中英催款函由 dunningService **即时组装**（客户当前逾期发票 → 明细表 + 分段汇总 + 总额），不走 EmailTemplate 变量替换——账龄明细是逐发票动态行，模板变量机制（`{{var}}`）表达不了表格
- 既有 EmailTemplate 催款模板（英文单发票）保留不动——单发票轻提醒场景继续用；本模块是**账龄级**催款（多发票汇总），两档并存
- 函预览返回 `{ zh: {subject, body}, en: {subject, body}, summary }`——前端预览 + printDocument 打印 + 可复制到智能邮箱发送

### DR-050-② 催款记录独立建模（快照留痕）：记录即证据

- DunningRecord 快照当次催款的账龄全景（币种/总额/分段 JSON/发票数）——客户后续还款后历史记录不失真
- 渠道 channel：`email` 邮件 / `phone` 电话 / `visit` 拜访 / `other`；结果 result：`sent` 已送达 / `promised` 承诺付款 / `paid` 已付款 / `disputed` 有争议 / `no_response` 未回应
- 发送动作本身走既有邮件通道（Outbox/SMTP）——催款域只登记事实，不重造发送轮子

### DR-050-③ 一键发起挂账龄行（选中即上下文）

- 账龄页每行（客户×币种）加「催款」动作——行上下文即客户+币种，无需二次选择
- KPI-05 月度对账 ≤10min：对账单 Tab 既有单客户生成 + 批量导出走既有 printDocument 通道（本 MVP 不建批量循环——对账单 Tab 已支持逐客户快速切换，批量生成列入增强）

## §4 数据模型

```prisma
/// 设计真源：催款函套件.md §4（REQ2-08，C2 缺口/KPI-05）
/// 业务语义：催款记录——当次账龄全景快照留痕（DR-050-②）。
model DunningRecord {
  id                 String @id // 格式：DUN__${shortId}
  customerRelationId String? // 关联客户（快照 FK）
  customerName       String // 冗余快照（还款后历史不失真）
  currency           String // 币种
  totalOverdue       Decimal @db.Decimal(18, 4) // 逾期总额（函内总额快照）
  invoiceCount       Int // 逾期发票数
  agingBuckets       Json // 五桶快照 {current,d1_30,d31_60,d61_90,d90plus}
  channel            String // email | phone | visit | other
  result             String // sent | promised | paid | disputed | no_response
  note               String?
  operator           String? // 跟进人
  createdAt          BigInt

  @@index([customerRelationId])
  @@index([createdAt])
}
```

## §5 API（挂 /api/v1/finance）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/dunning/letter` | 生成中英催款函预览 {customerName 或 customerRelationId, currency, asOf?} → {zh, en, summary} |
| POST | `/dunning` | 登记催款记录 {customerName, customerRelationId?, currency, totalOverdue, invoiceCount, agingBuckets, channel, result, note?, operator?} |
| GET | `/dunning?customerRelationId=&customerName=` | 催款历史（倒序） |

守卫：finance 域既有（读模块守卫；写 requireWrite + requireRole 财务/管理）。

## §6 前端（FinanceReportsPanel aging Tab）

- 账龄行（客户×币种）加「催款」按钮 → DunningSheet（BottomSheet）：
  - **函预览**：中文催款函（含逾期明细表：发票号/金额/到期日/逾期天数/分段 + 汇总）+ 英文 Payment Reminder（同结构）双 tab
  - **打印**：printHtmlDocument 输出（中英合版）
  - **登记**：渠道 chips + 结果 chips + 备注 + 跟进人 → POST /dunning
  - **历史**：该客户催款记录时间线（渠道/结果/金额/日期）
- 生成即上下文注入（行数据 → letter 端点），全链 ≤5min 锚点：选中行 → 函生成（1 击）→ 登记（1 击）
