## §2 PaymentVoucher 两类型

| type | 中文 | 业务语义 | 外汇路径 |
|------|------|---------|---------|
| `Receipt` | 收款 | 客户付款入账 | 外币 → FxSettlement 结汇 |
| `Disbursement` | 付款 | 向供应商/工厂付款 | 外币 → OutwardRemittance 付汇 |

> **设计决策**：收款与付款共用 PaymentVoucher 模型，以 `type` 区分。结汇（FxSettlement）仅作用于 Receipt 外币凭证；付汇（OutwardRemittance）仅作用于 Disbursement 外币凭证。CNY 凭证无结汇/付汇语义（fail closed）。

## §3 核销状态机（3 态）

### 3.1 状态定义

| 状态 | 中文 | 语义 | 设置方式 |
|------|------|------|---------|
| `unreconciled` | 未核销 | 凭证未核销任何发票 | 创建默认 / recalc 回退 |
| `partially_reconciled` | 部分核销 | 已核销部分发票，余款挂账 | recalc 自动 |
| `reconciled` | 已核销 | 全额核销，资金流闭环 | recalc 自动 |
| `cancelled` | 已作废 | 不再参与核销 | 手动 cancelVoucher |

**枚举真源**：`VALID_PAYMENT_VOUCHER_STATUS = ['unreconciled', 'partially_reconciled', 'reconciled']`（paymentVoucherMutationService.ts L13）。

### 3.2 recalcVoucherStatus 重算逻辑

```
totalAllocated = Σ InvoiceAllocation.appliedAmount WHERE voucherId

voucherAmount <= 0           → 'unreconciled'
totalAllocated >= voucherAmount → 'reconciled'
totalAllocated > 0              → 'partially_reconciled'
else                            → 'unreconciled'
```

> **关键约束**：status 禁止手动 PATCH——`normalizeUpdateInput` 显式拒绝 `input.status !== undefined` → `STATUS_NOT_MANUAL_SETTABLE`。状态只能由 `allocationMutationService` 的 `recalcVoucherStatus` 自动重算。

### 3.3 状态指引（消费后端稳定枚举）

`VOUCHER_STATUS_GUIDE`（前端不猜字符串）：

| 状态 | 说明 + 下一步指引 |
|------|----------------|
| unreconciled | 该凭证尚未核销任何发票。可在发票模块关联核销，或等待 Agent 自动匹配。 |
| partially_reconciled | 该凭证已部分核销发票。余款仍挂账，可继续关联其他发票完成核销。 |
| reconciled | 该凭证已完全核销，资金流闭环。如需调整，请冲销后重新核销。 |
| cancelled | 该凭证已作废，不再参与核销。 |

## §4 凭证录入（createPaymentVoucher）

### 4.1 前端表单

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| voucherNumber | string | ✅ | 服务端自动生成（PV-YYYY-NNNN），传入优先 |
| type | Receipt/Disbursement | ✅ | 默认 Receipt |
| amount | number | ✅ | > 0 |
| currency | USD/CNY/EUR/HKD | ✅ | 默认 USD |
| paymentDate | YYYY-MM-DD | — | 缺省收/付款当天 |
| paymentMethod | TT/LC/OA/DP/DA/Cash/Other | ✅ | 默认 TT |
| customerName | string | — | 交易对象名 |
| customerRelationId | string | — | 关联 Relation |
| bankFee | number | — | 银行手续费（与 amount 同币种） |
| exchangeRate | number | — | 收/付款日汇率快照 |
| notes | string | — | 备注 |

### 4.2 后端契约

`POST /api/v1/finance/vouchers` → `createPaymentVoucher`：

```
1. normalizeCreateInput
   ├─ pick(PAYMENT_VOUCHER_CREATE_FIELDS)
   ├─ status 校验: isValidPaymentVoucherStatus → 默认 'unreconciled'
   ├─ paymentDate 兜底: 缺省/空串 → localToday()
   └─ amount + Decimal 字段校验

2. $transaction
   ├─ id = generateId('PAY')
   ├─ voucherNumber = input.voucherNumber || nextBusinessNumber(tx, 'PV')
   ├─ tx.paymentVoucher.create({ ...data, createdAt, updatedAt })
   ├─ syncPaymentVoucherReferences(prisma, voucher, source, tx)
   └─ writeRouteAuditLog(create_voucher)

3. 事务提交后 fire-and-forget
   └─ publishBusinessEvent(PaymentVoucherCreated)
```

**错误码**：`INVALID_STATUS` / `INVALID_AMOUNT` / `CREATE_FAILED`。

## §5 凭证编辑（updatePaymentVoucher）

`PATCH /api/v1/finance/vouchers/:id` → `updatePaymentVoucher`：

| 校验 | 规则 |
|------|------|
| 存在性 | `findUnique` + `deletedAt` → `NOT_FOUND` |
| status 禁改 | `input.status !== undefined` → `STATUS_NOT_MANUAL_SETTABLE` |
| Decimal | `normalizeDecimalFields`（amount/bankFee/exchangeRate/appliedAmount） |

**事务内**：update + syncPaymentVoucherReferences + auditLog（before/after status + amount + appliedAmount）。

> **注意**：update 不发布业务事件——凭证状态变更由 allocation 重算驱动，事件在 `allocationMutationService` 的 `publishAllocationEvents` 中发布（`AllocationReconciled`）。

## §6 付款审批流（设计规格 · P1 缺口）

### 6.1 审批规则（DR-007 组织归属路由 · 彻底去阈值化）

> **决策点 3-A 声明**：审批规则彻底去阈值化，完全不看金额/比例，统一走 DR-007 组织归属路由。Scope 命名 `vouchers:approve:pay_lt5/pay_gt5` 为兼容保留名，实质逻辑与金额无关；一次性只需一位有效审批人。

| 场景 | 条件 | 审批链（DR-007） | 当前状态 |
|------|------|------------------|---------|
| 所有付款单 | `type=Disbursement`（全部金额/首单/非首单统一规则） | 付款申请人所属部门的主管；申请人无主管或部门为财务时由系统管理员（总领导）兜底；单次一位审批人即可 | ⚠️ 当前所有凭证均无审批 |

**兼容 Scope 命名保留（与金额无关）**：
- `vouchers:approve:pay_lt5` → 兼容保留名，实际走 DR-007
- `vouchers:approve:pay_gt5` → 兼容保留名，实际走 DR-007

### 6.2 设计落点（待实现）

```
createPaymentVoucher
  ├─ type=Disbursement?
  │   └─ 所有 Disbursement → status='pending_approval'
  │        └─ reviewerId = resolveReviewerByDepartment(申请人userId)
  │             ├─ User.department.managerId（部门主管）
  │             └─ null 时 fallback = 系统管理员 ADMIN（总领导兜底）
  └─ type=Receipt → status='unreconciled'（收款无需审批）
```

**接入方式**：
- 复用 Agent Runtime 的 `lark-approval` skill 发起飞书审批
- 审批通过后 Agent callback 将 `status` 从 `pending_approval` → `unreconciled`
- 审批拒绝则 `cancelVoucher`

**当前临时方案**：所有凭证 create 即落库为 `unreconciled`，审批流为 P1 缺口。

## §7 作废与软删

### 7.1 作废（cancelVoucher）

`POST /api/v1/finance/vouchers/:id/cancel`：

| 校验 | 规则 |
|------|------|
| 存在性 | `findUnique` + `deletedAt` → `VOUCHER_NOT_FOUND` |
| 核销阻断 | `InvoiceAllocation.count > 0` → `HAS_ALLOCATIONS` |

**事务内**：`status → 'cancelled'` + `deactivateEntityLinks` + auditLog。

### 7.2 软删（deleteVoucher）

`DELETE /api/v1/finance/vouchers/:id`：
- 核销阻断：`InvoiceAllocation.count > 0` → `HAS_ALLOCATIONS`（409）
- 软删：`deletedAt = now` + `deactivateEntityLinks` + auditLog

## §8 结汇/付汇入口

凭证详情面板提供外汇闭环入口（仅外币凭证可见）：

### 8.1 收款凭证 → 结汇（FxSettlement）

| 条件 | 入口 |
|------|------|
| `type=Receipt` && `currency≠CNY` | 详情面板「结汇」按钮 → 打开结汇 modal |

modal 加载 `getVoucherSettlementSummary(voucherId)`，显示：
- 凭证金额 / 已结汇 / 未结汇余额
- 已有结汇水单列表
- 新建结汇表单（settleDate / foreignAmount / fxRate / bank / slipNumber）

### 8.2 付款凭证 → 付汇（OutwardRemittance）

| 条件 | 入口 |
|------|------|
| `type=Disbursement` && `currency≠CNY` | 详情面板「付汇」按钮 → 打开付汇 modal |

modal 加载 `getVoucherRemittanceSummary(voucherId)`，显示：
- 凭证金额 / 已付汇 / 未付汇余额
- 已有付汇水单列表
- 新建付汇表单（remitDate / foreignAmount / fxRate / purpose / payeeName / bank）

> **设计**：CNY 凭证无结汇/付汇按钮（fail closed）；Receipt 走结汇路径，Disbursement 走付汇路径，不可交叉。

## §9 核销明细展示

选中凭证后右侧详情加载 `InvoiceAllocation[]`（`allocationService.listAllocations({ voucherId })`）：

| 列 | 说明 |
|----|------|
| 核销日期 | appliedDate |
| 发票号 | invoice.invoiceNumber |
| 核销金额 | appliedAmount |
| 操作 | 「撤销核销」按钮（调 deleteAllocation） |

撤销核销后：
- `recalcVoucherStatus` 重算凭证 status（可能回退到 partially_reconciled / unreconciled）
- `recalcInvoiceStatus` 重算发票 status（可能回退到 Issued）
- `syncAllocationVoucherLinks` 更新 settlesInvoice EntityLink
