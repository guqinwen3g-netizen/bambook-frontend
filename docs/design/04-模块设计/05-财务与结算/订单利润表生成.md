## §2 四维聚合口径

订单利润表将订单全链路资金归集为四个维度，全部归一化至本位币（CNY）：

| 维度 | 数据源 | 过滤条件 | 金额字段 |
|------|--------|---------|---------|
| **销售收入** (sales) | Invoice | `type=Receivable, status≠Cancelled, deletedAt=null` | `amount` |
| **采购成本** (purchases) | PurchaseOrder | `status≠Cancelled, deletedAt=null` | `totalAmount` |
| **运费** (freight) | Shipment | `status≠Cancelled, deletedAt=null` | `freight+insurance+customs+otherCharges`（四类费用拆分） |
| **杂费** (misc) | PaymentVoucher | `type=Disbursement, invoiceId=null（未核销发票）, deletedAt=null` | `amount + bankFee` |

### 2.1 聚合公式

```
salesRevenue  = Σ sales.cnyAmount
purchaseCost  = Σ purchases.cnyAmount
freightCost   = Σ freight.cnyAmount
miscCost      = Σ misc.cnyAmount
grossProfit   = round4(salesRevenue - purchaseCost - freightCost - miscCost)
grossMargin   = salesRevenue > 0 ? round4(grossProfit / salesRevenue × 100) : null
```

### 2.2 杂费口径说明

杂费取「未核销发票的订单付款凭证」——即 `invoiceId === null` 的 Disbursement 凭证。这些凭证代表「挂账但未核销到发票」的付款（如运费、检验费、佣金等杂项支出），其 `amount + bankFee` 合计计入杂费成本。

> 已核销发票的凭证（`invoiceId` 非空）不计入杂费，因其成本已通过发票维度（销售/采购）归集，避免重复计算。

### 2.3 DR-005 内部面料交易利润口径

> **决策来源**：[DR-005 FOB 的内部面料交易与合并利润](../../10-评审与决策/2026-08-16-设计评审决策记录.md)
> **设计真源**：[报价与成本模型组.md §12 DR-005](../../02-数据模型/报价与成本模型组.md) / [实体关系总览.md §6.4](../../02-数据模型/实体关系总览.md)

#### 2.3.1 部门独立核算（双视角利润）

| 部门 | 收入口径 | 成本口径 | 部门利润 |
|------|---------|---------|---------|
| **服装部**（FOB 服装订单） | 外部客户销售收入（Invoice Receivable） | 内部面料采购价（`OrderLine.internalTransferPrice × quantity`）+ 服装生产成本 + 运费 + 杂费 | 服装部利润 = 收入 − 成本 |
| **面料部**（内部面料订单） | 内部面料销售收入（`OrderLine.internalSettlementPrice × quantity`） | 面料生产成本 + 运费 + 杂费 | 面料部利润 = 收入 − 成本 |

> **关键约束**：内部面料采购价 = 内部面料销售收入（同一笔金额在两个部门间流转，不产生价差利润）

#### 2.3.2 公司合并抵销口径

```
合并收入 = Σ 外部客户收入（剔除内部面料销售收入）
合并成本 = Σ 真实面料成本（剔除内部采购加价）+ Σ 服装生产成本 + Σ 运费 + Σ 杂费
合并利润 = 合并收入 − 合并成本
抵销额   = Σ OrderInternalTransfer.transferAmount（内部采购价 = 内部销售收入）
        = 服装部内部采购成本 − 面料部真实面料成本（若存在内部加价）
```

#### 2.3.3 OrderProfitSheet 字段扩展（❌ 待实现）

| 字段 | 类型 | 说明 |
|------|------|------|
| departmentProfit | Decimal? @db.Decimal(18,4) | 部门利润（服装部/面料部独立核算） |
| consolidatedAdjustment | Decimal? @db.Decimal(18,4) | 合并抵销额（仅公司合并报表使用） |
| isInternalTrade | Boolean @default(false) | 是否内部交易订单（true 时利润表标记为"内部"，合并报表抵销） |

> **禁止事项**：
> - 禁止将内部面料销售收入计入公司合并收入
> - 禁止将内部面料采购价计入公司合并面料成本（须还原为真实面料成本）
> - 禁止以单一"已收/未收"字段替代部门利润与合并抵销的分别核算

#### 2.3.4 利润表生成流程扩展

```
generateOrderProfitSheet(orderId):
  ① 现有四维聚合（sales/purchases/freight/misc）→ 基础 grossProfit
  ② IF order.isInternalFabricTrade === true:
       标记 isInternalTrade = true
       计算内部交易专属口径：
         - 面料部：sales 维度含内部销售收入
         - 服装部：purchases 维度含 internalTransferPrice × quantity
  ③ IF 请求方为公司合并报表视角:
       查询关联 OrderInternalTransfer
       consolidatedAdjustment = Σ transferAmount
       合并利润 = grossProfit − consolidatedAdjustment
  ④ departmentProfit = grossProfit（部门视角，不含抵销）
```

## §3 汇率归一化（normalizeLine）

每个金额行根据币种与汇率可用性，走三级回退口径：

```
┌─────────────────────────────────────────────────────────────┐
│  normalizeLine(amount, currency, snapshotRate, latestRates)│
│                                                             │
│  ① currency === 'CNY'?                                       │
│     → rate=1, rateSource='base', cnyAmount=round4(amount)   │
│                                                             │
│  ② snapshotRate 存在且为正有限数?                              │
│     → rate=snapshotRate, rateSource='snapshot',              │
│       cnyAmount=round4(amount × snapshotRate)               │
│                                                             │
│  ③ latestRates.get(currency) 存在且为正?                      │
│     → rate=latest, rateSource='latest-rate',                 │
│       cnyAmount=round4(amount × latest)                     │
│                                                             │
│  ④ 以上均不满足?                                             │
│     → 返回 unconverted（不计入合计，透明披露）                  │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 rateSource 枚举

| rateSource | 含义 | 数据来源 | 可靠度 |
|-----------|------|---------|--------|
| `base` | 本位币 | currency=CNY | ✅ 最高（无需折算） |
| `snapshot` | 单据汇率快照 | Invoice/PurchaseOrder/PaymentVoucher.exchangeRate | ✅ 高（开票/收付款日实际汇率） |
| `latest-rate` | 最新汇率表 | ExchangeRate 表最新记录 | ⚠️ 中（非当日实际汇率，估算口径） |

### 3.2 unconverted 透明披露

无任何可用汇率的外币行**不计入合计**，列入 `details.unconverted` 数组：

```typescript
interface UnconvertedLine {
  id: string;
  label: string;
  kind: 'sales' | 'purchase' | 'freight' | 'misc';
  amount: number;
  currency: string;
  reason: string;  // '无汇率快照且无最新汇率记录'
}
```

> **透明披露原则**：不强制用 0 或猜测汇率填充，而是明确标注「无法折算」并排除在合计外。财务复核时可识别哪些行缺失汇率，及时补录 ExchangeRate 或单据 exchangeRate 快照。

### 3.3 运费汇率特殊口径

运单（Shipment）无 `exchangeRate` 快照字段，因此外币运费一律走 `latest-rate` 口径（`snapshotRate=null`）。四类费用（freight/insurance/customs/otherCharges）各自独立折算：

```typescript
const charges = [
  [sh.freightAmount, sh.freightCurrency, '运费'],
  [sh.insuranceAmount, sh.insuranceCurrency, '保险费'],
  [sh.customsAmount, sh.customsCurrency, '报关费'],
  [sh.otherCharges, sh.otherChargesCurrency, '其他费用'],
];
```

## §4 details 结构（ProfitSheetDetails）

```typescript
interface ProfitSheetDetails {
  sales: ProfitLineItem[];       // 销售收入明细
  purchases: ProfitLineItem[];   // 采购成本明细
  freight: ProfitLineItem[];     // 运费明细
  misc: ProfitLineItem[];        // 杂费明细
  unconverted: UnconvertedLine[];// 无法折算的透明披露行
}

interface ProfitLineItem {
  id: string;          // 发票号 / 采购单号 / 运单号 / 凭证号
  label: string;       // 展示标签
  amount: number;      // 原币金额
  currency: string;
  rate: number;        // 实际采用汇率
  rateSource: 'snapshot' | 'base' | 'latest-rate';
  cnyAmount: number;  // 折算后 CNY 金额
}
```

details 以 JSON 存储于 `OrderProfitSheet.details` 字段，支持前端逐行展开与汇率口径追溯。

## §5 幂等生成（orderId 唯一）

```typescript
// profitSheetService.ts L182-L200
const existing = await db.orderProfitSheet.findUnique({ where: { orderId } });
if (existing) {
  sheet = await db.orderProfitSheet.update({
    where: { orderId },
    data: { ..., version: existing.version + 1, generatedAt: BigInt(ts), updatedAt: BigInt(ts) },
  });
} else {
  sheet = await db.orderProfitSheet.create({
    data: { id: generateId('OPS'), orderId, ..., version: 1, ... },
  });
}
```

| 特性 | 实现 |
|------|------|
| 唯一性 | `orderId String @unique`（一单一张） |
| 重生成 | 覆盖更新，`version + 1` |
| 不产生重复行 | upsert 语义（findUnique + update/create） |
| 历史版本 | 不保留（当前版本覆盖，无版本历史表） |

> **version 字段**：每次重生成 +1，可用于检测「数据是否已刷新」（前端对比 version 判断是否需重新拉取）。

## §6 生成流程（generateOrderProfitSheet）

```
generateOrderProfitSheet(orderId, actorId)
  │
  ├─ 1. 校验订单存在 + 未软删
  │
  ├─ 2. loadLatestRateMap()        ← ExchangeRate 表最新汇率（按 effectiveDate desc）
  │
  ├─ 3. 聚合销售收入                ← Invoice (Receivable, 非 Cancelled)
  │     └─ normalizeLine('sales', ...) per invoice
  │
  ├─ 4. 聚合采购成本                ← PurchaseOrder (非 Cancelled)
  │     └─ normalizeLine('purchase', ...) per PO
  │
  ├─ 5. 聚合运费                   ← Shipment (非 Cancelled)
  │     └─ 四类费用各自 normalizeLine('freight', ...)
  │
  ├─ 6. 聚合杂费                   ← PaymentVoucher (Disbursement, invoiceId=null)
  │     └─ normalizeLine('misc', ...) per voucher (amount + bankFee)
  │
  ├─ 7. 求和 + 计算毛利/毛利率
  │     salesRevenue  = round4(Σ sales.cnyAmount)
  │     purchaseCost  = round4(Σ purchases.cnyAmount)
  │     freightCost   = round4(Σ freight.cnyAmount)
  │     miscCost      = round4(Σ misc.cnyAmount)
  │     grossProfit   = round4(salesRevenue - purchaseCost - freightCost - miscCost)
  │     grossMargin   = salesRevenue > 0 ? round4(grossProfit/salesRevenue × 100) : null
  │
  ├─ 8. 幂等写入（findUnique + update/create，version+1）
  │
  └─ 9. logger.info 记录生成结果
```

## §8 利润分析（Track A / Track B 口径）

订单利润表是 Track B（实际成本）口径的真源，与 Track A（系统估算）形成双轨：

| 轨道 | 口径 | 数据源 | 用途 |
|------|------|--------|------|
| Track A | 系统估算 | MaterialPriceHistory + 加工成本 + 市场行情 | 内部谈判参考价（定价前） |
| Track B | 实际成本 | OrderProfitSheet（本表） | 事后利润核算（订单执行后） |

### 8.1 毛利分析维度

| 指标 | 计算 | 业务含义 |
|------|------|---------|
| grossProfit | salesRevenue - 总成本 | 绝对毛利额（CNY） |
| grossMargin | grossProfit / salesRevenue × 100 | 毛利率（%），跨订单可比 |
| 成本结构 | purchase:freight:misc 占比 | 成本结构分析 |
| 汇率影响 | snapshot vs latest-rate 差额 | 汇率波动对利润的影响 |

### 8.2 退税与利润

出口退税额（TaxRefund.refundAmount）是订单利润的**补充收入**，但当前 OrderProfitSheet 的四维聚合**未纳入退税**——退税属于税务返还，不纳入毛利口径（避免与销售收入重复）。退税影响的是净利而非毛利，净利分析需结合 TaxRefund 单独计算。

## §13 待补缺口

| 缺口 | 影响 | 优先级 |
|------|------|--------|
| 退税未纳入利润表 | 净利需单独计算 | P2（扩展 details.refund 维度） |
| 无版本历史 | 重生成覆盖旧版本，无法对比 | P3（新增 OrderProfitSheetVersion 表） |
| 运费无汇率快照 | 外币运费一律 latest-rate 估算 | P2（Shipment 模型加 exchangeRate） |
| 无自动触发 | 需手动生成，订单状态变更不自动刷新 | P3（监听 OrderStatusChanged 事件自动生成） |
