## §2 业务定位与目标

### 2.1 业务定位

数据工具与导入向导是 Bambook「**业务工具箱**」中的**数据入口工具集合**——支持用户从外部文件（PDF/Excel/CSV）批量导入订单/报价数据，减少手工录入：

```
PDF / Excel / CSV ──► 导入向导 ──► 解析 ──► 预览/修正 ──► 入库
```

### 2.2 两类导入向导分工

| 维度 | 订单导入向导（ImportWizard） | 报价导入向导（QuotationImportWizard） |
| --- | --- | --- |
| 输入格式 | PDF（客户 PO 单扫描件） | Excel/CSV（结构化表格） |
| 解析方式 | 后端 pdf-parse 抽取文本 + 客户规则识别 + 客户专属解析器 | 前端 xlsx 解析为行 JSON |
| 客户识别 | 5 条规则加权打分（peerless 法人名/税号/联系人/PO 号模式） | 表头别名映射（中英文兼容） |
| 解析器 | `parsersByCustomer.peerless`（1 个） | 通用（无需客户专属解析器） |
| 入库接口 | `POST /api/v1/orders/import` | `POST /api/v1/quotations/import`（mode=preview/commit） |
| 幂等机制 | poNumber upsert + per-field overwrite protection | 报号已存在自动跳过 |
| 步骤数 | 3 步（Upload → Preview → Confirm） | 3 步（Select → Validate → Commit） |
| 上限 | 单次最多 20 个 PDF，单文件 10MB | 单次最多 2000 行 |

### 2.3 核心目标

1. **业务员友好**：PDF 扫描件直接上传，系统自动识别客户并解析
2. **预览与修正**：解析结果可人工编辑后再入库，避免错误数据入库
3. **幂等性**：同一 PO/报号重复导入不创建副本，按业务键 upsert
4. **字段保护**：用户手填字段不会被后续 PDF 重新导入覆盖（fieldSources 标记机制）
5. **标准模板**：报价导入提供标准 Excel 模板下载，含字段说明和示例
6. **失败容忍**：单文件/单行失败不阻断整体流程

## §6 PDF 解析与客户识别

### 6.1 PDF 文本抽取（extractText.ts）

```typescript
// 使用 pdf-parse 库
import pdfParse from 'pdf-parse';

export async function extractPdfText(buffer: Buffer): Promise<{ text: string; pages: number }> {
  const data = await pdfParse(buffer);
  return {
    text: data.text,
    pages: data.numpages,
  };
}
```

- 输入：PDF Buffer（multer 内存存储）
- 输出：纯文本 + 页数
- 错误处理：抛出由 parseOrderPdf 捕获并转为 error 字段

### 6.2 客户识别（detectCustomer.ts）

5 条规则加权打分：

| # | 规则 | 正则 | 权重 | 命中说明 |
| --- | --- | --- | --- | --- |
| 1 | 法人名 | `/V[êe]tements Peerless Clothing Inc\./i` | 0.5 | Peerless 公司法律名称 |
| 2 | QST 税号 | `/T\.V\.Q\.\/Q\.S\.T\. No 1000873531/i` | 0.3 |魁北克省税号 |
| 3 | GST 税号 | `/T\.P\.S\.\/G\.S\.T\. No\. 104128616/i` | 0.2 | 联邦税号 |
| 4 | 联系人 | `/Sonya Catalano\/514-593-9300/i` | 0.2 | Peerless 联系人+电话 |

### 6.3 客户解析器注册表（registry.ts）

```typescript
export type CustomerParser = (text: string) => ParsedOrder;

export const parsersByCustomer: Record<string, CustomerParser> = {
  peerless: parsePeerless,
};
```

**当前仅注册 1 个解析器**（peerless）。新增客户时：
1. 编写 `parse<CustomerName>(text: string): ParsedOrder` 函数
2. 在 detectCustomer.ts 添加该客户的识别规则
3. 在 registry.ts 注册 `{ <customerId>: parse<CustomerName> }`

### 6.4 parseOrderPdf 顶层入口

```typescript
export async function parseOrderPdf(buffer: Buffer): Promise<ParseResult> {
  try {
    const { text, pages } = await extractPdfText(buffer);
    const detection = detectCustomer(text);
    if (!detection.customerId) {
      return { detection, rawText: text, pages };  // 识别失败，仅返回检测信息
    }
    const parser = parsersByCustomer[detection.customerId];
    if (!parser) {
      return {
        detection, rawText: text, pages,
        error: `No parser registered for ${detection.customerId}`,
      };
    }
    const order = parser(text);
    return { detection, order, rawText: text, pages };
  } catch (e: any) {
    return {
      detection: { customerId: null, confidence: 0, reasons: [] },
      rawText: '', pages: 0,
      error: String(e?.message ?? e),
    };
  }
}
```

错误捕获并转为 error 字段，不抛出，确保单文件失败不阻断整体流程。

## §7 订单持久化（persistOrders.ts）

### 7.1 持久化流程

```
persistOrders(prisma, parsedOrders, opts)
  └─► 遍历 parsedOrders
        └─► 校验 poNumber 必填
        └─► 查询 existing Order by poNumber
        └─► 若 skipExisting && existing → 跳过
        └─► mapHeader(parsed, ts) → incoming
        ├─► applyOverwriteProtection(incoming.update, previousSources, mode)
        │     └─► 过滤 manual/imported-then-edited 字段
        └─► 遍历 lines → mapLine(orderId, line, i)
        └─► 查询 existingLines fieldSources
        └─► prisma.$transaction(async (tx) => {
              await tx.order.upsert({ where: { poNumber }, update, create });
              await tx.orderLine.deleteMany({ where: { orderId } });
              await tx.orderLine.createMany({ data: lineRows });
            })
        └─► 记录 PersistResult
```

### 7.2 字段级覆盖保护（fieldSources）

```typescript
export type FieldSourceTag = 'pdf' | 'manual' | 'imported-then-edited';

// 持久化时检查每个字段的来源标签：
// - 'pdf'：可被新 PDF 覆盖
// - 'manual'：用户手填，不可被 PDF 覆盖
// - 'imported-then-edited'：导入后用户编辑过，不可被 PDF 覆盖

// 模式：
// - 'overwrite-pdf-fields-only'（默认）：保护 manual/imported-then-edited 字段
// - 'force-overwrite'：强制覆盖所有字段（管理后台使用）
```

### 7.3 幂等性

- 键：`poNumber`（@@unique）
- 重新导入同一 PO：upsert 更新该行，不创建副本
- per-field overwrite protection 防止用户手填字段被覆盖

### 7.4 原子性

- 每个订单独立事务（`prisma.$transaction`）
- 单订单失败不影响其他订单
- 调用方决定如何处理部分成功

### 8.5 Excel 日期归一化

```typescript
function normalizeDateCell(value: unknown): string {
  if (value instanceof Date && !Number.isNaN(value.getTime())) {
    // Date 对象 → YYYY-MM-DD
    return `${y}-${m}-${d}`;
  }
  if (typeof value === 'number' && Number.isFinite(value)) {
    // Excel 序列号（1899-12-30 起算）
    const epoch = new Date(Date.UTC(1899, 11, 30));
    const date = new Date(epoch.getTime() + value * 86400000);
    return `${y}-${m}-${d}`;
  }
  return String(value).trim().replace(/\//g, '-');  // 字符串
}
```

兼容三种输入：
- JavaScript Date 对象（xlsx 库默认解析日期单元格）
- Excel 序列号（某些 CSV 场景）
- 字符串（如 '2025-01-15' 或 '2025/01/15'）

## §9 后端导入路由（route.ts）

### 9.1 Express Router 配置

```typescript
const upload = multer({
  storage: multer.memoryStorage(),  // 内存存储，不写盘
  limits: {
    fileSize: opts.maxFileBytes ?? 10 * 1024 * 1024,  // 单文件 10MB
    files: opts.maxFiles ?? 20,                         // 单次最多 20 文件
  },
});

router.use((req, res, next) => {
  if (!opts.requireAuth) return next();  // 开放模式
  const k = req.headers['x-bambook-api-key'] as string | undefined;
  if (!k) return res.status(401).json({ error: 'UNAUTHORIZED', message: 'X-Bambook-API-Key header required' });
  if (!opts.apiKeys.has(k)) return res.status(403).json({ error: 'FORBIDDEN', message: 'Invalid API key' });
  next();
});
```

### 9.2 POST /order 端点

```typescript
router.post('/order', upload.array('files'), async (req, res) => {
  const files = req.files as Express.Multer.File[] | undefined ?? [];
  if (files.length === 0) {
    return res.status(400).json({ error: 'NO_FILES', message: 'Attach 1+ PDFs under multipart field name "files"' });
  }
  const results = await Promise.all(
    files.map(async (f) => {
      try {
        const r = await parseOrderPdf(f.buffer);
        return { filename: f.originalname, pages: r.pages, detection: r.detection, order: r.order ?? null, error: r.error ?? null };
      } catch (e: any) {
        return { filename: f.originalname, pages: 0, detection: { customerId: null, confidence: 0, reasons: [] }, order: null, error: String(e?.message ?? e) };
      }
    }),
  );
  return res.json({ count: results.length, results });
});
```

## §13 已知限制与未来扩展

### 13.1 当前限制

- ❌ **客户解析器仅 1 个**（peerless），其他客户 PDF 无法结构化解析
- ❌ **客户识别规则硬编码**，无法通过界面维护
- ❌ **报价导入不支持产品行明细**（仅 header 级，无 line items）
- ❌ **导入历史无记录**（不持久化导入批次/操作人/时间）
- ❌ **无导入模板在线编辑**（用户需下载模板后离线填写）
- ❌ **PDF 解析依赖 pdf-parse**，对扫描件 OCR 支持有限
- ❌ **字段保护规则不可配置**（硬编码 pdf/manual/imported-then-edited 三态）

### 13.2 未来扩展

- 新增客户解析器（按业务扩展）
- 客户识别规则界面化维护
- 报价导入支持产品行明细（line items）
- 导入历史持久化（ImportBatch 模型 + 操作审计）
- 在线模板编辑器（字段增删/顺序调整）
- 扫描件 OCR 支持（Tesseract / 云 OCR 服务）
- 字段保护规则可配置（管理后台设置）
- 导入预检（dry-run 模式，仅校验不入库）
- 导入报告导出（Excel/PDF）

## §14 实现备注

### 14.1 阶段 IA-2 收编说明

PO 文件导入与 MES 均为**跳转卡**——业务工具箱仅保留入口，实际功能由各主模块承载：

| 跳转卡 | 落点模块 | 落点位置 |
| --- | --- | --- |
| PO 文件导入 | Orders | 订单页顶部「批量导入」按钮 |
| MES | MES | MES 模块主页 |

收编理由：
- PO 导入依赖 Orders 数据模型，属订单域
- MES 是独立可选模块，已有独立视图

### 14.2 字段保护机制设计

字段保护机制是订单导入的**核心防错设计**：

```typescript
// 场景：用户首次 PDF 导入 PO 123456 → fieldSources 全标 'pdf'
// 用户在订单详情页手填 salesCurrency = 'EUR' → fieldSources.salesCurrency = 'manual'
// 用户再次 PDF 导入 PO 123456 → applyOverwriteProtection 过滤掉 salesCurrency
// 结果：用户的 'EUR' 保留，不被 PDF 的 'USD' 覆盖
```

避免：
- 用户手填字段被批量导入覆盖
- 数据丢失
- 重复劳动

### 14.3 客户识别阈值

detectCustomer 未设置硬阈值，只要任何规则命中即返回 customerId。confidence 字段供前端参考展示：

| confidence | 含义 |
| --- | --- |
| 0.1 - 0.3 | 弱命中（仅 PO 号模式） |
| 0.4 - 0.6 | 中等命中（税号或联系人） |
| 0.7+ | 强命中（法人名 + 多重命中） |

未来可引入阈值（如 <0.3 不自动识别，要求用户手动选择客户）。

### 14.4 文件上传安全

| 维度 | 限制 |
| --- | --- |
| 单文件大小 | 10MB |
| 单次文件数 | 20 |
| 存储方式 | 内存（multer memoryStorage），不写盘 |
| 鉴权 | 可选 API Key（环境变量控制） |
| 文件类型 | 前端 PDF 过滤 + 后端无校验（建议后端补充 Content-Type 校验） |

### 14.5 颜色与样式豁免

StepUpload 拖拽区使用 rgba() 任意值：

```typescript
const dropzoneBase = 'border-[rgba(100,116,139,0.50)] dark:border-[rgba(255,255,255,0.22)] bg-[rgba(255,255,255,0.60)] dark:bg-[rgba(255,255,255,0.04)] text-[var(--text-tertiary)]';
```

原因：flat-experimental 护栏会强制 `border:0 !important`，导致虚线描边消失。拖拽区的虚线描边是核心视觉可供性，必须保持可见。其余组件严格使用 BDS token。
