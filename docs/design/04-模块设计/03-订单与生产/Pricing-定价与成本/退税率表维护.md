## 一、模块定位与边界

退税率表是外贸出口企业的"税率真源"——HS Code（海关商品编码）到退税率的映射。轨道 B 退税美元定价时，业务员只需输入 HS Code，系统按最长前缀命中自动查找退税率，无需手工查表。

**核心特征**：
- **HS Code @unique**：注册真源，创建后不可修改（最长前缀命中依赖其稳定性）
- **最长前缀命中**：10 位编码依次尝试 10/8/6/4/2 位前缀，命中首个 isActive 注册项
- **启停控制**：isActive 切换不删除记录，停用的退税率不参与命中查询
- **软删除**：deletedAt BigInt，不物理删除
- **退税率合法区间**：0-16%（PRD §8.6 出口退税率实际范围）

**边界**：
- ✅ 在内：退税率 CRUD、最长前缀命中查询、启停切换、命中测试界面
- ❌ 不在内：HS Code 编码字典本身（海关税则真源外部维护）、退税申报（财务模块）、轨道 B 计算（Pricing 模块消费退税率）

## 三、TaxRefundRate 模型规格

### 3.1 模型定义（schema.prisma L3508）

```prisma
model TaxRefundRate {
  id     String @id              // 格式：TRR__${shortId}
  hsCode String @unique          // 支持 2/4/6/8/10 位编码
  rate   Decimal @db.Decimal(8, 4)  // 退税率百分比（13 = 13%）

  description String?
  isActive    Boolean @default(true)

  createdAt BigInt
  updatedAt BigInt
  deletedAt BigInt?

  @@index([isActive])
}
```

### 3.2 字段说明

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | String | @id | 格式：TRR__${6 字节 base64url 大写} |
| hsCode | String | @unique | 2/4/6/8/10 位数字，正则 `/^(\d{2}\|\d{4}\|\d{6}\|\d{8}\|\d{10})$/` |
| rate | Decimal(8,4) | 0-16 | 退税率百分比（13 = 13%） |
| description | String? | — | 说明（如「化纤梭织面料」） |
| isActive | Boolean | @default(true) | 启停状态，停用不参与命中查询 |
| createdAt | BigInt | — | epoch ms |
| updatedAt | BigInt | — | epoch ms |
| deletedAt | BigInt? | — | 软删标记，null = 未删除 |

### 3.3 索引

- `hsCode @unique`：唯一约束 + 查询主键
- `@@index([isActive])`：启停状态过滤

## 四、最长前缀命中算法（lookupRefundRate）

```
async function lookupRefundRate(hsCode: string): Promise<{ hsCode: string; rate: number } | null>
  code = hsCode.trim()
  if (!code || !/^\d+$/.test(code)) return null
  prefixes = [10, 8, 6, 4, 2]
    .filter(n => code.length >= n)
    .map(n => code.slice(0, n))
  if (prefixes.length === 0) return null
  rows = await db.taxRefundRate.findMany({
    where: { hsCode: { in: prefixes }, isActive: true, deletedAt: null },
  })
  if (rows.length === 0) return null
  // 最长前缀优先
  rows.sort((a, b) => b.hsCode.length - a.hsCode.length)
  return { hsCode: rows[0].hsCode, rate: Number(rows[0].rate) }
```

**命中规则**：
- 输入 10 位编码 `5407520000` → 依次尝试 10/8/6/4/2 位前缀
- 若注册了 `5407`（4 位）= 13%，则 `5407520000` 命中 `5407` → 13%
- 若同时注册了 `54075200`（8 位）= 11%，则 `5407520000` 命中 `54075200` → 11%（最长前缀优先）
- 无命中返回 null（调用方决定报错或人工输入）

**使用方**：
- 轨道 B `resolveCalculationData`：refundRate 缺省时调 lookupRefundRate(hsCode)
- TrackBPanel「查税率」按钮：调 `apiService.lookupTaxRefundRate(code)` 自动填退税率
- TaxRatesPanel「最长前缀命中测试」：调 `apiService.lookupTaxRefundRate(code)` 展示命中结果

## 六、状态机

退税率记录无复杂状态机——只有启停二态：

```
[启用 isActive=true] ──点击状态徽章──→ [停用 isActive=false]
                       ──编辑表单──→ 修改 rate/description/isActive
                       ──删除──→ 软删（deletedAt 非空，列表不可见）

[停用 isActive=false] ──点击状态徽章──→ [启用 isActive=true]
```

**约束**：
- hsCode 创建后不可修改（updateTaxRefundRate 抛「HS Code 不可修改」）
- 删除为软删（deletedAt = now），不物理删除
- 停用记录不参与 lookupRefundRate 命中查询

## 七、CRUD 服务规格

### 7.1 createTaxRefundRate

```
input: { hsCode, rate, description?, isActive? }
校验：
  hsCode 非空 + 正则匹配 2/4/6/8/10 位数字
  rate 0-16 之间
  hsCode 唯一性（dup check）
落库：id=generateId('TRR'), isActive=default true
返回：TaxRefundRate
```

### 7.2 listTaxRefundRates

```
query: { includeInactive?: boolean }
where: deletedAt=null, (!includeInactive ? isActive=true : 无过滤)
orderBy: hsCode asc
返回：{ items, total }
```

### 7.3 updateTaxRefundRate

```
input: TaxRefundRatePatch（rate / description / isActive；hsCode 不可改）
校验：
  记录存在 + 未软删
  (patch.hsCode !== undefined) → throw "HS Code 不可修改"
  (patch.rate !== undefined) → assertRate(0-16)
落库：updatedAt=now, 仅更新提供字段
返回：TaxRefundRate
```

### 7.4 deleteTaxRefundRate

```
校验：记录存在 + 未软删
落库：deletedAt=now, updatedAt=now（软删）
```

### 7.5 lookupRefundRate

```
input: hsCode string
返回：{ hsCode, rate } | null（见 §四 算法）
```

| 端点 | 方法 | 守卫 | 用途 |

### 请求/响应示例

**POST 注册**：
```json
// 请求
{ "hsCode": "5407", "rate": 13, "description": "化纤梭织面料" }
// 响应 201
{ "ok": true, "item": { "id": "TRR__ABC123", "hsCode": "5407", "rate": 13, "description": "化纤梭织面料", "isActive": true, ... } }
```

**GET 命中查询**：
```
GET /v1/pricing/tax-refund-rates/lookup?hsCode=5407520000
// 响应
{ "hit": { "hsCode": "5407", "rate": 13 } }
```
未命中时 `{ "hit": null }`。

**PATCH 更新**：
```json
// 请求（hsCode 不可改）
{ "rate": 11, "description": "化纤梭织面料（2026 调整）" }
// 响应
{ "ok": true, "item": { ... } }
```

**错误码**：
- 400：非法 HS Code / 退税率越界 / HS Code 不可修改 / 该 HS Code 退税率已存在
- 404：退税率记录不存在
- 500：其他

## 十四、待补的设计缺口

| # | 缺口 | 影响 | 建议优先级 |
|---|------|------|-----------|
| 1 | **批量 Excel 导入尚未实现** | 一次性维护大量 HS Code（如海关税则年度更新）时需逐条录入，效率低下 | P3（规划中） |
| 2 | 历史版本未独立建模 | 退税率调整时直接 update，无 version 字段；历史退税率靠软删 + 重新创建保留，查询历史不直观 | P3 |
| 3 | 生效日期 / 失效日期未建模 | TaxRefundRate 无 effectiveFrom / effectiveTo 字段，无法表达"某 HS Code 自某日起退税率调整为 X%" | P3（需评估业务需求） |
| 4 | 退税率变更对历史 PricingCalculation 的影响未追溯 | PricingCalculation.refundRate 落库为快照（规则调整不回溯），但无法查询"该定价创建时退税率表的完整状态" | Phase 4 |
| 5 | HS Code 编码字典未集成 | 当前 HS Code 全靠手工录入，未集成海关税则字典做自动补全 | P3 |

### 批量 Excel 导入规划（缺口 #1）

**目标**：支持上传 Excel 文件（列：HS Code / 退税率 / 说明），批量创建/更新退税率记录。

**建议方案**：
- API：`POST /v1/pricing/tax-refund-rates/batch-import`（multipart/form-data）
- 服务端：解析 Excel（复用现有 xlsx 库）→ 逐行校验 → 事务内 upsert（hsCode 已存在则更新 rate/description，不存在则创建）
- 前端：TaxRatesPanel 增加「批量导入」按钮 → 文件选择 → 上传 → 展示导入结果（成功数 / 失败数 + 失败明细）
- 校验：HS Code 正则 + 退税率 0-16 + 重复 hsCode 去重（取最后一条）
- 幂等：同文件重复导入不产生副作用（upsert 语义）
