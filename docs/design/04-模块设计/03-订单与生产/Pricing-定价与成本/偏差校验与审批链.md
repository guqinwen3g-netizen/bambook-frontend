## 一、模块定位与边界

偏差校验是双轨成本体系的"联动枢纽"——它把轨道 A（内部估算标尺）与轨道 B（对外报价真源）连接起来，通过百分比偏差驱动审批门禁，防止业务员报出显著偏离合理区间的价格。

**核心特征**：
- **纯函数计算**：`calculatePriceDeviation(finalPriceUsd, estimateMedianUsd)` 无副作用，前后端同源
- **3 级分类**：ok（≤15%）/ warn（>15%，触发审批）/ block（>30%，禁止发送）
- **对称分级**：负偏差（报价低于估算）同样分级——显著低于估算意味着亏损风险（PRD §9.2 报价低于成本价 → 管理层审批）
- **快照原则**：偏差在报价创建时计算并落库为 Quotation 快照字段，此后为历史快照，不随编辑变更
- **fail-closed 门禁**：block 状态未审批通过禁止发送，审批请求缺失同样禁止发送

**边界**：
- ✅ 在内：偏差纯函数、DeviationBadge 展示、报价创建时审批生成、发送时门禁
- ❌ 不在内：审批流程本身（ApprovalRequest 模型属于审批域，本模块仅生成 + 查询状态）、轨道 A/B 的计算（分别在各自模块）

## 三、calculatePriceDeviation 纯函数规格

### 3.1 输入

```typescript
calculatePriceDeviation(finalPriceUsd: number, estimateMedianUsd: number): PriceDeviation
```

- `finalPriceUsd`：轨道 B 终价美元单价（TrackBResult.finalUnitPrice）
- `estimateMedianUsd`：轨道 A 中位估算美元单价（TrackAResult.priceMedianUsd）

### 3.2 输出

```typescript
interface PriceDeviation {
  deviationPercent: number;  // 有符号百分比：(final - median) / median × 100
  level: 'ok' | 'warn' | 'block';
}
```

### 3.3 计算公式

```
deviationPercent = ((finalPriceUsd - estimateMedianUsd) / estimateMedianUsd) × 100
abs = |deviationPercent|
level = abs > 30 ? 'block' : abs > 15 ? 'warn' : 'ok'
```

### 3.4 校验

| 字段 | 校验 | 错误消息 |
|------|------|----------|
| finalPriceUsd | 必须大于 0 | 「终价必须大于 0」 |
| estimateMedianUsd | 必须大于 0 | 「估算中位必须大于 0」 |

### 3.5 阈值常量（前后端同源）

| 常量 | 值 | 后端位置 | 前端位置 |
|------|----|----------|----------|
| DEVIATION_WARN_PERCENT | 15 | trackAEstimator.ts L133 | DeviationBadge.tsx L18 PRICE_DEVIATION_WARN_PERCENT |
| DEVIATION_BLOCK_PERCENT | 30 | trackAEstimator.ts L134 | DeviationBadge.tsx L19 PRICE_DEVIATION_BLOCK_PERCENT |

**同步要求**：阈值改动需双边同步，否则前端展示与后端门禁不一致。

### 3.6 计算示例

```
轨道 A 中位估算 USD = 23.0584
轨道 B 终价 USD     = 28.5000
deviationPercent = (28.5000 - 23.0584) / 23.0584 × 100 = 23.60%
abs = 23.60 > 15 → level = 'warn'（黄标，触发审批）

轨道 B 终价 USD     = 32.0000
deviationPercent = (32.0000 - 23.0584) / 23.0584 × 100 = 38.78%
abs = 38.78 > 30 → level = 'block'（红标，禁止发送）

轨道 B 终价 USD     = 18.0000
deviationPercent = (18.0000 - 23.0584) / 23.0584 × 100 = -21.94%
abs = 21.94 > 15 → level = 'warn'（负偏差，亏损风险，同样触发审批）
```

## 四、DeviationBadge 组件规格

### 4.1 Props

```typescript
interface DeviationBadgeProps {
  finalUsd: number | null;      // 轨道 B 终价美元单价
  medianUsd: number | null;     // 轨道 A 中位估算美元单价
  medianUnit?: string;          // 估算单位提示（PC / M）
  isDarkMode?: boolean;         // 主题透明（保留兼容，组件内不使用）
}
```

### 4.2 三态展示

| level | 语义 | 颜色 | 图标 | 文字 |
|-------|------|------|------|------|
| ok | success | 绿 | CheckCircle2 | 「双轨偏差校验：... 偏差 +X%（≤15%，区间内）」 |
| warn | warning | 黄 | AlertTriangle | 「双轨偏差校验：... 偏差 +X%（>15%，保存将触发审批）」 |
| block | danger | 红 | AlertCircle | 「双轨偏差校验：... 偏差 +X%（>30%，禁止直接发送）」 |

**样式**：`statusSemanticClass(LEVEL_SEMANTIC[level])` 映射 ok=success / warn=warning / block=danger，与 rdlBusinessStatusTokens 同源。容器 `flex items-start gap-2 px-3 py-2 rounded-inset text-xs`。

### 4.3 computePriceDeviation 前端展示用计算

```typescript
function computePriceDeviation(finalUsd, medianUsd): PriceDeviationInfo | null {
  if (finalUsd === null || medianUsd === null || medianUsd <= 0 || !Number.isFinite(finalUsd)) return null;
  const deviationPercent = Math.round(((finalUsd - medianUsd) / medianUsd) * 10000) / 100;
  const abs = Math.abs(deviationPercent);
  const level = abs > 30 ? 'block' : abs > 15 ? 'warn' : 'ok';
  return { deviationPercent, level };
}
```

**与后端差异**：前端用 `Math.round(... * 10000) / 100` 保留 2 位小数（展示用），后端用 `round4` 保留 4 位小数（落库用）。分级结果一致。

### 4.4 渲染逻辑

```
1. dev = computePriceDeviation(finalUsd, medianUsd)
2. if !dev → return null（入参缺失/中位非正时不渲染）
3. sign = deviationPercent > 0 ? '+' : ''
4. unitHint = medianUnit ? '（$/件 或 $/米）' : ''
5. 渲染：图标 + 「双轨偏差校验：轨道 B 终价 $X vs 轨道 A 中位 $Y{unitHint}，偏差 {sign}{deviationPercent}%{level 说明}」
```

## 五、报价创建流程中的偏差处理代码路径

### 5.1 createQuotation 偏差快照 + ApprovalRequest 生成（quotationService.ts L124-L227）

```
1. 双轨偏差快照（PRD §8.6）：
   trackAOk = isFinite(input.trackAMedianUsd) && input.trackAMedianUsd > 0
   trackBOk = isFinite(input.trackBFinalUsd) && input.trackBFinalUsd > 0
   deviation = null
   if (trackAOk && trackBOk):
     deviation = calculatePriceDeviation(input.trackBFinalUsd, input.trackAMedianUsd)

2. warn/block → 需要审批：解析 requester（actor → UserAccount，fallback owner）
   if (deviation && deviation.level !== 'ok'):
     approvalRequesterId = await resolveActorUserAccountId(prisma, { userId: actorId }).catch(() => null)
     if (!approvalRequesterId):
       owner = await prisma.userAccount.findFirst({ id: 'usr_owner_default', ... })
       approvalRequesterId = owner?.id ?? null
     if (approvalRequesterId):
       approvalId = `ar_${now}_${random}`
     else:
       logger.warn('price deviation approval skipped: no resolvable requester')
       // 不阻断创建：快照照常落库，priceApprovalId 置空；发送门禁对 block 仍 fail-closed

3. 事务内创建 Quotation：
   - 落快照字段：trackAMedianUsd / trackAUnit / trackBFinalUsd
   - priceDeviationPercent = deviation?.deviationPercent ?? null
   - priceDeviationLevel = deviation?.level ?? null
   - priceApprovalId = approvalId

4. 事务内生成 ApprovalRequest（if approvalId && deviation && approvalRequesterId）：
   await tx.approvalRequest.create({
     data: {
       id: approvalId,
       requesterId: approvalRequesterId,
       actionType: 'quotation:price-deviation',
       targetType: 'Quotation',
       targetId: quotationId,
       status: 'pending',
       risk: deviation.level === 'block' ? 'high' : 'medium',
       payload: { quotationId, quotationNumber, trackAMedianUsd, trackAUnit, trackBFinalUsd,
                  deviationPercent, level, requestedAt, source: 'quotation-dual-track' },
     },
   })

5. 事务内写审计日志：detail.after.priceDeviationLevel = deviation?.level ?? null
```

### 5.2 关键设计决策

- **同事务生成审批**：ApprovalRequest 与 Quotation 在同一事务内创建，保证一致性（要么都成功，要么都回滚）
- **requester 解析容错**：actor 无法解析为 UserAccount 时 fallback 到 owner；owner 也不存在时跳过审批生成但不阻断创建——快照照常落库，priceApprovalId 置空，发送门禁对 block 仍 fail-closed（拒绝发送）
- **risk 分级**：block → high，warn → medium（供审批人优先级排序）
- **actionType 标识**：`quotation:price-deviation`，便于审批列表筛选

## 六、发送报价流程中的 409 门禁代码路径

### 6.1 sendQuotation block 门禁（quotationService.ts L432-L445）

```
async function sendQuotation(id, actorId):
  existing = await prisma.quotation.findUnique({ where: { id }, include: { lines: true } })
  if (!existing || existing.deletedAt) throw `报价单 ${id} 不存在`
  validateStatusTransition(existing.status, 'Sent')  // 仅 Draft → Sent

  // ── 双轨红标门禁（PRD §8.6）：偏差 >30% 未审批通过禁止发送（fail-closed）──
  if (existing.priceDeviationLevel === 'block'):
    approved = false
    if (existing.priceApprovalId):
      approval = await prisma.approvalRequest.findUnique({ where: { id: existing.priceApprovalId } })
      approved = approval?.status === 'approved'
    if (!approved):
      throw `报价单 ${quotationNumber} 双轨偏差 ${priceDeviationPercent}% 超过 30% 红标阈值，`
          + `需审批通过后方可发送（门禁：price-deviation${priceApprovalId ? '' : '，审批请求缺失'}）`

  // 门禁通过 → 事务内更新 status=Sent + 写审计日志 + 发布 QuotationIssued 事件
```

### 6.2 路由层 409 映射（quotationRoute.ts L198）

```
catch (e):
  msg = e?.message || ''
  status = msg.includes('不存在') ? 404
         : msg.includes('非法') || msg.includes('门禁') ? 409
         : 400
  res.status(status).json({ error: msg })
```

**门禁消息关键字**：「门禁：price-deviation」→ 409。前端按 409 状态码识别门禁拦截，展示审批提示。

### 6.3 fail-closed 原则

- `priceDeviationLevel === 'block'` 且 `priceApprovalId` 缺失 → 拒绝发送（消息含「审批请求缺失」）
- `priceDeviationLevel === 'block'` 且 `priceApprovalId` 存在但 status ≠ 'approved' → 拒绝发送
- `priceDeviationLevel === 'block'` 且 approval.status === 'approved' → 放行
- `priceDeviationLevel === 'warn'` 或 'ok' 或 null → 无门禁（warn 已生成审批但发送不拦截）

## 七、状态机

### 7.1 偏差等级流转（报价生命周期内）

```
[报价创建] ──calculatePriceDeviation──→ [ok: 无审批]
                                          │
                                          ├──warn──→ [ApprovalRequest pending(risk=medium)]
                                          │              │
                                          │              ├──approved──→ [warn: 已审批，可发送]
                                          │              └──rejected──→ [warn: 已拒绝，不可发送（但 warn 不拦截发送）]
                                          │
                                          └──block──→ [ApprovalRequest pending(risk=high)]
                                                         │
                                                         ├──approved──→ [block: 已审批，可发送（门禁放行）]
                                                         └──rejected/pending──→ [block: 发送被 409 拦截]
```

### 7.2 审批状态机（ApprovalRequest.status）

```
pending ──approved──→ approved（放行 block 门禁）
        └──rejected──→ rejected（不改变 block 门禁拦截状态，需重新创建报价或调整价格）
```

**注意**：审批被拒绝后，block 门禁仍拦截发送。业务员需调整轨道 B 终价（使偏差降级）或重新创建报价。

## 十五、可访问性 & 交互细节

- **DeviationBadge 实时展示**：轨道 A/B 试算完成后，DeviationBadge 自动出现在 TrackBPanel 下方，无需用户主动触发
- **三态图标**：ok=CheckCircle2（绿）/ warn=AlertTriangle（黄）/ block=AlertCircle（红），lucide-react 图标库
- **偏差百分比展示**：正偏差前缀 `+`，负偏差前缀无（自带 `-`）；保留 2 位小数（前端 computePriceDeviation）
- **单位提示**：medianUnit 提供时显示「（$/件）」或「（$/米）」，便于业务员理解对比口径
- **门禁消息**：409 响应含完整提示「报价单 XXX 双轨偏差 XX% 超过 30% 红标阈值，需审批通过后方可发送（门禁：price-deviation，审批请求缺失）」
- **审批请求缺失提示**：priceApprovalId 为空时消息含「审批请求缺失」，提示业务员需重新创建报价或联系管理员
