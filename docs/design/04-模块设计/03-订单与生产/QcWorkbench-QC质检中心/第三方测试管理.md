## §2 模块定位与范围

### 2.1 与既有质量域的边界（避免双轨）

```
质量域三轨分工：
┌──────────────────────────┐  ┌──────────────────────────┐  ┌──────────────────────────┐
│ QC 样品链（既有）          │  │ 验货报告（既有）           │  │ 第三方测试（本模块新增）    │
│ qcChainService            │  │ InspectionReport          │  │ TestRequest               │
│ 样品评审 pass/conditional │  │ AQL 抽检疵点计数           │  │ 实验室理化指标委托         │
│ /fail + 门禁              │  │ midline/final 验货        │  │ 色牢度/pH/甲醛… pass/fail │
│ （过程质量控制）           │  │ （出货前实物验货）          │  │ （合规与性能证据）          │
└──────────────────────────┘  └──────────────────────────┘  └──────────────────────────┘
```

- 测试**结果数据**只在 TestRequest 建模（色牢度等指标此前仅档案自由文本 `complianceTests`——那是客户要求，非测试结果）
- 验货（InspectionReport.inspectorOrg 虽可填 SGS）是**实物查验**；本模块是**送样检测**——委托单/报告编号/检测项目维度独立
- 三轨同挂 orderId，订单详情同屏共存

### 2.2 模块边界

| 包含 | 不包含 |
|------|--------|
| 测试委托登记（订单关联/项目枚举/机构/送样日） | 客户测试要求模板化（增强项，后续） |
| 报告 PDF 上传归档 + 下载 | 测试费用入订单成本（增强项） |
| 结论判定 pending→pass/fail | QC 样品链评审（既有） |
| 失败项整改闭环（登记→关闭） | 验货报告 AQL（既有） |
| 订单维度测试全景列表（3 击） | 工厂整改重做流程（qcChain 既有 direct-reject） |

## §3 核心概念与术语

| 概念 | 说明 |
|------|------|
| **测试项目 testItems** | 结构化枚举多选：`color_fastness` 色牢度 / `shrinkage` 缩水率 / `tensile` 强力 / `ph` pH 值 / `formaldehyde` 甲醛 / `azo` 偶氮 / `gsm` 克重实测 / `width` 幅宽实测 / `other` 其他 |
| **委托机构 agency** | 枚举：`sgs` / `its` / `bv` / `other`（前端展示中文名） |
| **结论 result** | `pending`（送样中/待报告）→ `pass` / `fail`（终态；fail 强制挂整改） |
| **整改记录 CorrectiveAction** | fail 后的行动跟踪：`open`（进行中）→ `closed`（已闭环）；一条对应一个失败项的处置（返工/复测/让步接收/客诉沟通） |
| **3 击查看** | 订单列表 → 订单详情 → 「第三方测试」区块（区块内即全部委托+报告+结论+整改状态） |

## §4 数据模型

```prisma
/// 设计真源：第三方测试管理.md §4（REQ2-04，IND-03 缺口补齐）
/// 业务语义：订单级第三方实验室测试委托。报告 PDF 附件归档；
/// fail 结论强制挂整改记录（100% 跟踪闭环验收锚点）。
model TestRequest {
  id      String @id // 格式：TR__${shortId}
  trNo    String @unique // 业务号：TR-YYYYMMDD-001

  orderId String // 挂订单（全类型：面料/成衣/其他）

  // ─── 委托内容 ───
  testItems     String[] // 测试项目枚举（多选，§3 术语表）
  agency        String // sgs | its | bv | other
  sentDate      String? // 送样日 YYYY-MM-DD
  expectedDate  String? // 预计报告日
  notes         String? // 委托备注（样品描述/客户特殊要求）

  // ─── 结论 ───
  result      String @default("pending") // pending | pass | fail
  reportNo    String? // 实验室报告编号
  reportDate  String? // 报告签发日
  failItems   String[] @default([]) // 失败项子集（fail 时登记，整改挂此维度）

  createdAt BigInt
  updatedAt BigInt
  deletedAt BigInt?

  files             TestReportFile[]
  correctiveActions TestCorrectiveAction[]

  @@index([orderId])
}

/// 报告 PDF 附件（ProductImage 范式：multer diskStorage + 相对路径 + 软删）
model TestReportFile {
  id           String @id
  testRequestId String
  filePath     String // 相对路径：test-reports/{requestId}/{timestamp}-{rand}.pdf
  fileName     String // 原始文件名
  mimeType     String // application/pdf
  fileSize     Int
  uploadedAt   BigInt
  deletedAt    BigInt?

  testRequest TestRequest @relation(fields: [testRequestId], references: [id], onDelete: Cascade)

  @@index([testRequestId])
}

/// 失败项整改记录（独立模型：open 清单可查询、闭环状态可审计）
model TestCorrectiveAction {
  id            String @id
  testRequestId String
  failItem      String // 对应 TestRequest.failItems 之一
  action        String // 整改措施（返工/复测/让步接收/客户沟通…）
  owner         String? // 责任人
  dueDate       String? // 整改期限
  status        String @default("open") // open | closed
  closedAt      BigInt?
  closeNote     String? // 闭环说明
  createdAt     BigInt
  updatedAt     BigInt

  testRequest TestRequest @relation(fields: [testRequestId], references: [id], onDelete: Cascade)

  @@index([testRequestId])
}
```

### 4.1 状态机

```
TestRequest.result:  pending ──┬──→ pass（终态：报告通过，无整改）
                                 └──→ fail（终态：强制 ≥1 条 open 整改才能落库）
CorrectiveAction.status:  open ────→ closed（closeNote 留痕）
```

- **fail 门禁**：PATCH result→fail 时，`failItems` 非空 且 同步传入或已存在 ≥1 条整改记录，否则 400（验收「失败项 100% 有整改跟踪记录」的服务端强制）
- pending→pass/fail 单向：终态后 result 不可回退（重测走新委托单）
- 软删（deletedAt）仅限 pending 态；有附件/整改的终态单保留归档不可删

## §5 API（挂 /api/v1/qc，读 qc:read / 写 qc:write）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/test-requests` | 登记委托 {orderId, testItems[], agency, sentDate?, expectedDate?, notes?} |
| GET | `/test-requests?orderId=` | 订单维度全景（含 files + correctiveActions + summary）——3 击数据源 |
| PATCH | `/test-requests/:id` | 更新结论 {result, reportNo?, reportDate?, failItems[]?, correctiveAction?{failItem,action,owner?,dueDate?}}；fail 门禁 §4.1 |
| DELETE | `/test-requests/:id` | 软删（仅 pending） |
| POST | `/test-requests/:id/files` | 上传报告 PDF（multer，PDF only ≤10MB，多文件） |
| GET | `/test-requests/:id/files/:fileId` | 下载/预览（res.sendFile 绝对路径拼接 uploadDir） |
| POST | `/test-requests/:id/corrective-actions` | 追加整改记录 {failItem, action, owner?, dueDate?} |
| POST | `/test-requests/corrective-actions/:caId/close` | 整改闭环 {closeNote?} |

守卫口径与 qc 域一致：`createModuleAuthGuard` + 写 `requireJwtForWrite` + `requirePermission('qc:write')`；审计 `writeRouteAuditLog` 同事务（operation: create_test_request / update_test_request / upload_test_report / …）。

## §6 前端（TestRequestPanel 挂订单详情）

- 位置：OrderManager 订单详情 `id="order-detail-test-requests"`（全订单类型，与色差区块并列）
- 结构（参照 SampleColorBatchPanel 范式）：
  - **汇总头**：N 项委托 · pass x / fail y / 待报告 z · 未闭环整改 w（fail 红 / 整改 open 黄 / pass 绿徽章）
  - **委托卡列表**：trNo / 机构 / 项目 chips / 送样日 / 结论徽章 / 报告号 / 附件（点击预览 PDF）/ 整改状态
  - **登记 BottomSheet**：项目多选 chips + 机构下拉 + 日期 + 备注
  - **结论登记**：pass/fail + 报告号 + 失败项多选（从 testItems 中选）+ 整改措施（fail 必填，同步创建）
  - **整改闭环**：open 整改行内「关闭」+ 闭环说明
- 上传交互：file input accept="application/pdf"，FormData 字段 `files`
