## §2 模块边界与职责

QC 质检中心模块是生产管线质量门禁的判据来源，其核心职责矩阵：

| 职责域 | 已实现 | 规划增强 | 上下游依赖 |
|--------|--------|----------|-----------|
| **验货任务管理** | ✅ QCAssignment 状态机（Assigned→InProgress→Completed/Cancelled）+ 看板三列 + 同订单同类型唯一进行中 | ⚠️ 验货日历视图 / 任务优先级 | 上游 Order；下游 InspectionReport |
| **中期验货** | ✅ InspectionReport inspectionType=midline（AQL 抽样 + 三级疵点 + 结论 pass/conditional/fail） | ⚠️ 疵点明细逐条记录 | 上游 QCAssignment；下游 Order |
| **终期验货** | ✅ InspectionReport inspectionType=final（AQL 门禁：0 致命 + passRate≥90% + 业务批准）+ qc_shipped 门禁强校验 | ⚠️ 多份终期报告历史版本 | 上游 QCAssignment；下游 ProductionStage qc_shipped |
| **疵点管理** | ✅ 三级疵点计数（critical/major/minor）+ defectSummary 文本描述 | ⚠️ 疵点逐条录入 + 照片 + 疵点趋势分析看板 | 上游 InspectionReport；下游 FactoryProfile 供应商评分 |
| **驻地管理** | ✅ QCLocation CRUD（code @unique + focus 业务线 + 软删引用校验） | — | 无上游；下游 QCAssignment |
| **业务线管理** | ✅ BusinessLine CRUD（MOQ/生产周期/付款条件 + 启停开关） | — | 无上游；下游 Order MOQ 校验 |
| **裁剪前检查** | ✅ PreCutChecklist 四项确认（推码/耗料/样板/产前会议）+ pre_cut_checked 门禁 | — | 上游 Order；下游 ProductionStage pre_cut_checked |
| **供应商质量评分** | ✅ 验货结论自动评分（inspectionScoreForResult → FactoryProfile.recordAutoEvaluation） | ⚠️ 评分趋势看板 | 上游 InspectionReport；下游 FactoryProfile |

## §5 验货类型与门禁

### 5.1 两种验货类型

| 类型 | inspectionType | 时机 | 报告 ID 格式 | 门禁关联 |
|------|---------------|------|-------------|---------|
| 中期验货 | `midline` | 生产过程中抽检 | `INR__${orderId}__midline` | 无直接门禁（质量监控） |
| 终期验货 | `final` | 出货前 AQL 全检 | `INR__${orderId}` | qc_shipped 门禁判据 |

### 5.2 生产管线 10 阶段门禁

| 阶段 # | stageKey | 名称 | QC 相关门禁 | 校验逻辑 |
|--------|---------|------|------------|---------|
| 6 | pre_cut_checked | 裁剪前检查 | PreCutChecklist 四项全 true | gradingConfirmed + consumptionConfirmed + patternConfirmed + preProductionMeeting |
| 7 | pp_sample_approved | 产前样确认 | 双签（生产部+业务部） | signedByProduction + signedByBusiness |
| 10 | qc_shipped | 验货发货 | Final AQL 三门禁 | ① criticalDefects=0 ② passRate≥90% ③ defectRate≤3% ④ approvedByBusiness=true |

### 5.3 qc_shipped 门禁校验逻辑

```
advanceStage(orderId, 'qc_shipped') 事务内：
1. 查 InspectionReport (orderId, inspectionType='final')
   └ 不存在 → throw INSPECTION_NOT_QUALIFIED「终期验货报告未建立」
2. result === 'fail' → throw「终期验货结论为不合格，需整改复验」
3. criticalDefects > 0 → throw「存在 N 个致命疵点（AQL 0 零容忍）」
4. passRate = passedUnits / totalUnits < 0.90 → throw「合格率 X% 低于阈值 90%」
5. defectRate = (total - passed) / total > 0.03 → throw「不合格率 X% 超过上限 3%」
6. approvedByBusiness !== true → throw「需业务部批准发货」
── 全部通过 → 推进 qc_shipped 阶段 + 发布 ProductionCompleted 事件 ──
```

**门禁常量**：MIN_PASS_RATE = 0.90 / MAX_DEFECT_RATE = 0.03

## §6 验货任务状态机

```
Assigned ──(start)──▶ InProgress ──(complete)──▶ Completed
   │                      │
   └──(cancel)────────────┘──(cancel)──▶ Cancelled
                                    (Completed 不可取消)
```

| 状态 | bds-badge 变体 | 标签 | 可执行操作 |
|------|---------------|------|-----------|
| Assigned | info | 已分配 | 开始 / 完成 / 取消 / 删除 |
| InProgress | warning | 进行中 | 完成 / 取消 / 删除 |
| Completed | success | 已完成 | 删除 |
| Cancelled | neutral | 已取消 | 删除 |

**状态流转校验**：
- start：仅 Assigned → InProgress
- complete：Assigned 或 InProgress → Completed（可关联 reportId）
- cancel：Assigned 或 InProgress → Cancelled（Completed 不可取消）
- 已完结任务（Completed/Cancelled）不可修改字段

**同订单同类型唯一性**：同订单同 inspectionType 仅允许一个非 Cancelled 状态的任务。

## §9 验货结论与供应商评分联动

```typescript
// saveInspectionReport 内（result 非 null 时）
if (result.result && order.millRelationId) {
  const score = inspectionScoreForResult(result.result, critical);
  await factoryService.recordAutoEvaluation({
    relationId: order.millRelationId,
    kind: 'inspection',
    score,
    sourceType: 'inspectionReport',
```

## §10 终期 fail 广播通知

终期验货结论从非 fail 迁移为 fail 时，广播 critical 级通知（天然幂等）：

| 通知字段 | 值 |
|---------|---|
| type | `inspection_fail` |
| level | `critical` |
| title | `订单 ${poNumber} 终期验货不通过（critical=N, major=M）` |
| body | 疵点明细 + 出运门禁锁定说明 + 整改复验提示 |
| link | `/production?orderId=${orderId}` |
| metadata | entityType=InspectionReport, entityId, orderId, criticalDefects, majorDefects, minorDefects |
| 推送对象 | QC + 业务员 + 管理层 |

> 状态迁移触发天然幂等：重复保存相同 fail 结论不再通知；整改后再次 fail 属新事件，重新通知。
