## §2 门禁 3 绑定（核心设计）

终期验货报告是 qc_shipped 阶段的**唯一判据来源**，推进 qc_shipped 时强制校验以下 4 条门禁：

| 门禁 # | 校验条件 | 失败错误码 | 错误消息 |
|--------|---------|-----------|---------|
| **门禁 1** | Final 报告必须存在 | INSPECTION_NOT_QUALIFIED | 「终期验货报告（final）未建立」 |
| **门禁 2** | result !== 'fail' | INSPECTION_NOT_QUALIFIED | 「终期验货结论为不合格（fail），需整改复验」 |
| **门禁 3** | criticalDefects === 0 | INSPECTION_NOT_QUALIFIED | 「存在 N 个致命疵点（AQL 0 零容忍）」 |
| **门禁 4** | passRate ≥ 90% | INSPECTION_NOT_QUALIFIED | 「合格率 X% 低于阈值 90%」 |
| **门禁 5** | defectRate ≤ 3% | INSPECTION_NOT_QUALIFIED | 「不合格率 X% 超过上限 3%」 |
| **门禁 6** | approvedByBusiness === true | BUSINESS_APPROVAL_REQUIRED | 「需业务部批准发货」 |

**门禁常量**：

```typescript
const MIN_PASS_RATE = 0.90;  // 合格率最低 90%
const MAX_DEFECT_RATE = 0.03; // 不合格率最高 3%
```

### 门禁校验逻辑（advanceStage 事务内）

```typescript
if (stageKey === 'qc_shipped') {
  // 1. 查 Final 报告
  const inspection = await tx.inspectionReport.findUnique({
    where: { orderId_inspectionType: { orderId, inspectionType: 'final' } },
  });
  // 2. 不存在 → 拒绝
  if (!inspection) throw { code: 'INSPECTION_NOT_QUALIFIED', message: '终期验货报告（final）未建立' };
  // 3. fail → 拒绝
  if (inspection.result === 'fail') throw { code: 'INSPECTION_NOT_QUALIFIED', message: '终期验货结论为不合格（fail），需整改复验' };
  // 4. 致命疵点 > 0 → 拒绝（AQL 0 零容忍）
  if ((inspection.criticalDefects ?? 0) > 0) throw { code: 'INSPECTION_NOT_QUALIFIED', message: `存在 ${inspection.criticalDefects} 个致命疵点（AQL 0 零容忍）` };
  // 5. passRate < 90% → 拒绝
  const pr = passRate(inspection.totalUnits, inspection.passedUnits);
  if (pr < MIN_PASS_RATE) throw { code: 'INSPECTION_NOT_QUALIFIED', message: `合格率 ${(pr * 100).toFixed(1)}% 低于阈值 90%` };
  // 6. defectRate > 3% → 拒绝
  const dr = defectRate(inspection.totalUnits, inspection.passedUnits);
  if (dr > MAX_DEFECT_RATE) throw { code: 'INSPECTION_NOT_QUALIFIED', message: `不合格率 ${(dr * 100).toFixed(1)}% 超过上限 3%` };
  // 7. 业务部未批准 → 拒绝
  if (!inspection.approvedByBusiness) throw { code: 'BUSINESS_APPROVAL_REQUIRED', message: '需业务部批准发货' };
}
```

## §3 与生产阶段 qc_shipped 联动

### 3.1 联动链路

```
QC 录入终期验货报告 (PUT /production/:orderId/inspection, inspectionType=final)
  → saveInspectionReport (upsert)
  → 验货结论自动供应商评分 (H1c)
  → [仅 fail 迁移] 广播 critical 通知 (inspection_fail)
  ↓
生产管线推进 qc_shipped (POST /production/:orderId/advance/qc_shipped)
  → advanceStage 事务内校验 Final 报告门禁 6 条
  → 全部通过 → 推进阶段 + 发布 ProductionCompleted 事件
  → 任一失败 → throw INSPECTION_NOT_QUALIFIED / BUSINESS_APPROVAL_REQUIRED
  → 前端 toast danger 显示缺口 → 用户补全后重试
```

### 3.2 ProductionCompleted 事件

qc_shipped 阶段推进成功后发布：

```typescript
if (stageKey === 'qc_shipped') {
  publishBusinessEvent({
    type: 'ProductionCompleted',
    sourceEntityType: 'ProductionStage',
    sourceEntityId: orderId,
    payload: { orderId, stageKey, completedAt: now },
  });
}
```

> ProductionCompleted 事件用于 Phase 1 Sprint 3 触发自动创建发货单联动。

## §4 fail 状态迁移广播通知

### 4.1 触发条件

终期验货结论从**非 fail 迁移为 fail** 时，广播 critical 级通知：

```typescript
// saveInspectionReport 内
const previous = await prisma.inspectionReport.findUnique({
  where: { orderId_inspectionType: { orderId, inspectionType } },
  select: { result: true },
});
// ... upsert ...
if (inspectionType === 'final' && result.result === 'fail' && previous?.result !== 'fail') {
  // 广播 critical 通知
}
```

### 4.2 天然幂等

| 场景 | previous.result | new result | 是否通知 |
|------|----------------|------------|---------|
| 首次 fail | null | fail | ✅ 通知 |
| 重复保存 fail | fail | fail | ❌ 不通知（幂等） |
| 整改后再次 fail | conditional/pass | fail | ✅ 通知（新事件） |
| 整改后 pass | fail | pass | ❌ 不通知（仅 fail 迁移触发） |

### 4.3 通知内容

| 字段 | 值 |
|------|---|
| type | `inspection_fail` |
| level | `critical` |
| title | `订单 ${poNumber} 终期验货不通过（critical=${critical}, major=${major}）` |
| body | 客户/产品 + 三级疵点明细 + defectSummary + 出运门禁锁定说明 + 整改复验提示 |
| link | `/production?orderId=${orderId}` |
| metadata | entityType=InspectionReport, entityId, orderId, criticalDefects, majorDefects, minorDefects |
| 推送对象 | QC + 业务员 + 管理层 |

## §5 终期验货表单字段

### 5.1 与中期验货的对比

| 字段 | 中期 | 终期 | 差异 |
|------|------|------|------|
| inspectionType | midline | final | — |
| id | `INR__${orderId}__midline` | `INR__${orderId}` | final 沿用历史 ID 格式 |
| shipmentId | 通常不填 | 关联出运批次 | 终期对应出运 |
| approvedByBusiness | 通常不批准 | **必须批准**（门禁 6） | 终期业务批准是出运前提 |
| fail 广播通知 | 不广播 | **广播 critical** | 终期 fail 锁定出运 |
| 门禁关联 | 无直接门禁 | **qc_shipped 判据** | 终期是出运门禁 |

### 5.2 业务部批准字段

| 字段 | 类型 | 说明 |
|------|------|------|
| approvedByBusiness | Boolean @default(false) | 业务部是否批准发货 |
| businessApprover | String? | 业务批准人 ID |
| approvedAt | BigInt? | 批准时间（approvedByBusiness=true 时自动设为 now） |

**保存逻辑**：

```typescript
// saveInspectionReport upsert 内
approvedByBusiness: data.approvedByBusiness ?? false,
approvedAt: data.approvedByBusiness ? now : null,  // 批准时自动设时间，取消批准时清空
```

> 业务部批准是 qc_shipped 门禁第 6 条：`approvedByBusiness !== true` → throw BUSINESS_APPROVAL_REQUIRED。

## §6 整改复验流程

### 6.1 当前实现（upsert 覆盖）

```
初次验货 fail → saveInspectionReport (upsert, result=fail)
  → 广播 critical 通知
  → 出运门禁锁定
  ↓
工厂整改
  ↓
复验 → saveInspectionReport (upsert, result=pass/conditional)
  → 覆盖更新报告
  → 验货结论重新评分
  → [fail→非fail 不通知]
  → 出运门禁解锁（满足其他门禁后可推进 qc_shipped）
```

### 6.2 upsert 覆盖的字段更新逻辑

```typescript
update: {
  ...(data.totalUnits !== undefined ? { totalUnits: data.totalUnits } : {}),
  ...(data.passedUnits !== undefined ? { passedUnits: data.passedUnits } : {}),
  ...(data.criticalDefects !== undefined ? { criticalDefects: data.criticalDefects } : {}),
  ...(data.majorDefects !== undefined ? { majorDefects: data.majorDefects } : {}),
  ...(data.minorDefects !== undefined ? { minorDefects: data.minorDefects } : {}),
  ...(data.result !== undefined ? { result: data.result || null } : {}),
  ...(data.approvedByBusiness !== undefined ? {
    approvedByBusiness: data.approvedByBusiness,
    approvedAt: data.approvedByBusiness ? now : null
  } : {}),
  updatedAt: now,
}
```

> ⚠️ 当前整改复验直接覆盖旧报告，无历史版本。规划为多版本报告 + 版本追溯。

## §7 验货结论与供应商评分

终期验货结论保存后，自动追加供应商质量评分（与中期验货共享逻辑）：

```typescript
if (result.result && order.millRelationId) {
  const { inspectionScoreForResult } = await import('../suppliers/factoryService');
  const score = inspectionScoreForResult(result.result, critical);
  await factoryService.recordAutoEvaluation({
    relationId: order.millRelationId,
    kind: 'inspection',
    score,
    sourceType: 'inspectionReport',
    sourceId: result.id,
    note: `验货报告 ${result.id}（订单 ${poNumber}）结论 ${result.result}${critical > 0 ? `，致命疵点 ${critical}` : ''}`,
  });
}
```

**终期验货对供应商评分的权重**：终期验货是出运门禁，fail 对供应商评分影响最大。
