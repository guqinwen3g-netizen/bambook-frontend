### 3.3 生产进度时间线（Production Timeline）

id=`order-detail-timeline`

两个子区域：**6 态步骤条**（状态机推进入口）+ **变更事件时间线**

#### 3.3.1 6 态步骤条

```
Pending ──▶ Confirmed ──▶ Production ──▶ Shipping ──▶ Delivered
                                                         
                     ╳ Alert ╳ （异常态：独立出现在末尾右侧）
```

**ORDER_FLOW_STEPS = ['Pending', 'Confirmed', 'Production', 'Shipping', 'Delivered']**

**ORDER_ALLOWED_TRANSITIONS（合法推进矩阵，点击可触发 → 后端契约强校验）：**

| 当前状态 | 可推进到 | 说明 |
|---------|---------|------|
| Pending（待确认） | Confirmed / Alert | PO 录入后初始态；需客户确认 PO |
| Confirmed（已确认） | Production / Alert | 确认后转生产 |
| Production（生产中） | Shipping / Alert | 厂内生产/加工；完成后转等待出运 |
| Shipping（出运中） | Delivered / Alert | 已发运；客户收货后转交付 |
| Delivered（已交付） | — | 终态，不可变更（无动作） |
| Alert（异常） | Pending / Confirmed / Production / Shipping | 异常态独立分支；恢复时可选"回到任一非终态"（业务上通常回到上一态） |

**按钮样式（4 态）**：

| 类型 | 规格 | 视觉 |
|------|------|------|
| `STEP_BTN_DONE` | 已完成（已路过的步骤） | 勾选图标 ✓ + 弱强调（accent 色 + 文字弱化） |
| `STEP_BTN_CURRENT` | 当前态 | Raised 主按钮（`bds-btn` 默认 + 大圆角），强聚焦 |
| `STEP_BTN_ACTIONABLE` | 下一可推进态 | `bds-btn-outline`，悬停强调（唯一可点击项） |
| `STEP_BTN_DISABLED` | 未达步骤 | `bds-btn-ghost` 禁用灰态 + 无 hover |
| Alert 进行中 | 特殊 danger 风格 | `!min-w-[96px]` + danger tint，AlertTriangle 图标 |

**连接器规则**：
- 步骤之间 `h-px w-4` 发丝线
- Done 段：实色 connector (`STEP_CONNECTOR_DONE_STYLE`)
- Pending 段：低饱和 ghost 色

#### 3.3.2 变更事件时间线（Timeline Events）

`OrderStatusTransition` 表事件按 `createdAt` **升序**排列（旧事件在上，新事件在下）

**每行事件结构**：

```
●─── 待确认 → 已确认    [最新]  2026-08-01
│     客户签字回传 PO（备注）
│     by zhangsan@company.com
│
●─── 已确认 → 生产中            2026-08-03
│     …
```

**视觉规则**：
- 圆点：最新事件 = accent 点亮（`TIMELINE_DOT_ACTIVE_CLASS`），其余 = 灰态（`TIMELINE_DOT_CLASS`）
- 最新事件右侧加一个 `[最新]` badge（accent tint）
- 圆点连线：`h-4 w-px` 发丝线（末位事件无连线）
- 状态中文化：`ORDER_STATUS_LABELS[fromStatus] → ORDER_STATUS_LABELS[toStatus]`
- 备注（note）+ 操作人（operator）= 10px muted（层级降一级）

**空态**：`<p text-xs font-light muted>暂无状态变更记录</p>`（不隐藏区块，保持界面结构稳定）

**Alert 异常提醒**（BDS Alert 族 danger 语义）：
```
┌─ ⚠ ───────────────────────────────┐
│  此订单已超期，请尽快处理           │
└──────────────────────────────────┘
```
当 `status === 'Alert'` 时附加在时间线底部。

## 六、订单状态机（前端步骤条 + 后端契约双校验）

### 6.1 前端限制（交互级拦截）

`ORDER_ALLOWED_TRANSITIONS` → 点击合法态按钮高亮；非法态按钮视觉禁用（不可点击）

### 6.2 后端契约（强校验）

后端路由 `POST /api/v1/orders/:id/transition`：
1. 查询 Order 当前态（DB 值为真源）
2. 若 `ORDER_ALLOWED_TRANSITIONS[currentStatus]` 不含 targetStatus → 409 `状态变更非法：${current} → ${target}`
3. 若 targetStatus === currentStatus → 200 空响应（幂等，不重写 transition 记录）
4. 否则写入 `OrderStatusTransition`（id / orderId / fromStatus / toStatus / note / operator / createdAt）
5. 同步更新 Order.status + Order.updatedAt
6. 写入 AuditLog（`action: transition_order_status`，记录 before/after 值）

### 6.3 10 阶段门禁联动（业务规则 §9.3）

状态推进到 `Production` 前：
- 后端校验：查询 PreCutChecklist 对应 orderId → **必须所有条目已通过 = true**；否则 409 `裁剪前检查未全部通过，禁止进入生产阶段`

状态推进到 `Shipping` 前：
- 后端校验：对应订单最近一条 Final Inspection（type = 'Final'）必须 result = 'pass'
- 否则 409 `最终验货未通过或未执行，禁止进入出运阶段`

（注：前端步骤条视觉上仍高亮"下一步可操作"，但真实后端契约强校验——前端体验上点击推进 → 出现 bds-toast danger 提示具体缺口 → 用户到对应模块补全后可重试）

## 十七、主单下单至条目履约、最终放行（2026-10-11 用户确认）

业务裁决见 [DR-055](../../../10-评审与决策/2026-08-16-设计评审决策记录.md#dr-055-订单确认至生产跟单最终放行的业务分层2026-10-11)。本节是后续详情交互与功能补齐的参考，不是完成功能清单。

### 17.1 主单：客户交易与批准

1. 接到订单，新增主单时录入完整贸易条款、全部条目及各产品参数、数量、销售约定；保存客户 PO，没有客户 PO 文件则据主单制作相应文件。
2. 由有审批职责的负责人、部门负责人或老板确认主单；批准后生成销售合同 SC。PO、主单批准和整单 SC 均在主单层处理。
3. 订单概览展现整单客户、总数量、总金额等摘要；产品与约定展现当前条目的客户产品规格、数量、销售价格及相关约定。客户付款条件归属主单销售约定，其页面展示位置仍可优化，不与工厂付款条件混用。

### 17.2 条目：向工厂下单并落实生产

1. 基于条目向实际工厂下达订单确认通知，记录工厂接单与生产安排确认。
2. 落实履约方式（采购、代加工、自组织原料等）、工厂采购/加工合同、价格与付款条件、工厂承诺交期；工厂交期和向客户承诺的交期分别保留。
3. 确认排产、生产批次和负责该条目/生产范围质量跟踪的 QC，记录实际开工。下单、工厂接单、排产、开工是不同事实；具体字段必填时点及单据签发顺序待进一步细化。
4. 工厂/供应商与以上履约信息进入跟单侧，不把客户产品约定卡变成混合采购表单。

### 17.3 面料与服装必须分开

- **面料：** 下单后进入实际大货生产；取最早能代表大货质量的先锋样（投产后早期生产样），推进内部评审、客户确认与必要的调整。先锋样确认支持继续推进已有生产，不是首次开工前置。界面允许同时显示“生产中”和“样品待评审/待客户确认”，正常反馈不自动产生整单停产事实。
- **服装：** 下单后先完成产前样确认，再推进确认开始大货生产。沿用具体产前样签核、封存及生产放行规则，不把面料顺序套入服装。

### 17.4 完整办理、过程质量与最终放行

- 样品的常规办理：收到实样 → 登记本轮完整事实与证据 → 发起 QC 评审 → 记录结果 → 寄客户 → 记录客户反馈/确认；需改进则工厂调整后接续下一轮。完整信息、附件、评审和历史始终可回看，摘要不代替记录。是否把“先 QC 通过才准寄”设为所有面料样品的硬门禁，本轮没有单独确认。
- 生产中持续汇总 QC 检验结果、技术意见及阻塞。区分普通样品反馈、正式生产质量不合格、整改复验和业务恢复；仅复验通过不能冒充已恢复。
- 临近出运完成船样及本单要求的其他最终样品确认（RC 按约定启用），汇合最终大货 QC 和适用出运条件。实际完成量、允差、是否允许分批等单独判断；满足条件后进入出运交接，不把“全部通过”直接显示为实际已发货。

### 17.5 卡片职责与 BDS 表达

默认仅突出谁在生产、关键数量/交期、当前样品轮次与结果、质量状态及下一步；通过明确入口进入完整办理，完成后返回简洁摘要。遵循共同网格对齐线、文字层级、纵向分组及留白；核心大字可用自然短语融合含义，小参数用字段名加值，隐藏无数据字段。采购为轻量入口；业务员在对应任务中发起 QC，专业 QC 工作台由检验角色使用。
