| **关联 PRD 章节** | §5.6（订单编号）、§9.5（金额联动）、§9 业务规则（MOQ/审批）、§19.7（订单页设计） |
| **关联代码** | [OrderManager.tsx](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/components/OrderManager.tsx#L360-L438) `getDefaultNewOrder` / [orderSchema.ts](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/lib/orderSchema.ts) `fieldsForManualForm` / `requiredKeysForManual` / `computeAutoFillPatch` / `OrderClusterBlock` |

> **2026-10-06 口述确认，优先于本文旧稿：** 面料与成衣订单从入口到业务流程完全分开；一张 PO 若同时含两类产品则拆成两张独立订单，保留相同 PO/合同编号。订单信息由业务员手动填写。上传的客户 PO/合同文件只用于留存订单证据；MVP 不做 OCR、内容解析、字段提取或自动填表，上传文件不能单独创建/转换订单。客户尚未提供正式 PO/合同附件时，业务员仍可先保存订单草稿。外部客户订单提交审批前须关联客户书面确认依据；内部订单不适用客户文件要求，其审批依据待设计。
>
> **订单行粒度：** 面料订单每行代表一种面料规格与颜色，记录该行数量、单位、单价；不同面料或颜色分别成行。成衣订单每行代表一个款式与颜色，行内记录各尺码数量，尺码数量合计必须等于该行总数量。每行关联对应产品档案或准确开发版本。
>
> **履约核心对象：** 订单主单承载客户 PO/销售合同及整单审批；履约模式属于产品行，不放在订单主单。每条产品行是独立履约路径，采购、委外加工、QC、样品和出运都必须能关联回具体产品行；主单只汇总各行进度。商业发票可按实际出运条目合并计费，但明细须保留对来源订单行的追溯。
>
> **内部供货关联：** 内部面料备货或供给成衣组的面料订单由面料组从面料入口按常规面料订单创建，内部供货时记录成衣团队及负责人；成衣订单的具体产品行可关联到具体面料订单行并记录分配米数。成衣组不从成衣订单直接发起面料采购。内部订单的审批依据不要求客户 PO，具体必填的内部用途/依据仍待确认。

## §3 字段分组（Cluster）

录入表单的 cluster 顺序由 `ORDER_CLUSTERS.manualOrder` 决定（与详情页 `detailOrder` 分离）。`manualOrder === 99` 的 cluster 不在录入表单显示（shipment/sampleShipment/sampleFabric/garmentProduction/sampleGarment —— 这些是履约阶段才填的字段）。

| manualOrder | cluster | 中文名 | 适用类型 | 录入字段数 | 说明 |
|-------------|---------|--------|---------|-----------|------|
| 1 | basic | 基础档案 | all | 11 | PO#/PO Item/PO 日期/季节/批次/品色号/客户编码/品名/数量/单位 |
| 2 | parties | 买卖四方 | all | ~22 | 5 子组（客户/工厂/收货/结款/内部团队）每子组 4 字段 |
| 3 | delivery | 交期与物流 | all | 5 | 生产交期/出厂交期/收货方/实际发货日/运输方式 |
| 4 | fabric | 面料规格 | 仅 fabric | 4 | 面料编号/成份/门幅/克重 |
| 4 | materials | 物料信息 | 仅 other | 2 | 分类/规格备注 |
| 5 | sales | 销售与收汇 | all | 11 | 销售单价/合同金额/付款方式/条件/币种/预计付款日/实际付款日/实际金额 |
| 6 | purchase | 采购与供应商 | all | 6 | 采购单价/付款日/供应商发票号/日期/金额 |
| 7 | instructions | 特别说明 | all | 1+ | specialInstructions + ocDays |
| 99 | shipment | 出货与发票 | — | 不录入 | 履约阶段在详情页编辑 |
| 99 | sampleShipment | 大货船样 | — | 不录入 | 同上 |
| 99 | sampleFabric | 匹头样 | — | 不录入 | 同上 |
| 99 | garmentProduction | 成衣生产跟单 | — | 不录入 | OrderLine 级，详情页 + 行编辑 |
| 99 | sampleGarment | 成衣样衣阶段 | — | 不录入 | 同上 |

**渲染真源**：`fieldsForManualForm(typeKey)` → 过滤 `shownInManualForm === true && (!applicableTypes || applicableTypes.includes(typeKey))`，再按 `cluster.manualOrder` + 数组内顺序渲染。

### 5.1 必填校验

| 必填字段 | 适用类型 | 校验时机 |
|---------|---------|---------|
| poNumber | all | 保存前 |
| quantity | all | 保存前 |

**前端表现**：必填未满时「保存」按钮禁用；必填字段 label 前置 `*` 标记。

### 5.2 类型校验

| 字段 | 规则 |
|------|------|
| number | 非负有限数；空值兜底 0 |
| date | `YYYY-MM-DD` 格式（`cleanDate` 校验） |
| enum | 必须在 `enumOptions` 白名单内 |
| currency | 2 位小数（`round2`）|

### 5.3 唯一性校验

| 字段 | 规则 | 校验位置 |
|------|------|---------|
| poNumber | 全局 `@unique` | 后端创建时校验，冲突返回 409 |
| code | 全局 `@unique`（SO-YYYYMM-NNNN） | 后端 SequenceRegister 分配 |
| (orderId, itemNo) | `@@unique` | 同一 PO 下 itemNo 不重复 |

## §7 金额联动（applyAmountLinkage）

合同金额 ↔ 销售单价 × 数量 双向联动，规则在 `OrderManager` L571+：

| 触发 patch | 联动结果 |
|-----------|---------|
| 含 salesPrice | contractAmount = salesPrice × quantity（quantity > 0 时） |
| 含 contractAmount | salesPrice = contractAmount / quantity（quantity > 0 时） |
| 含 quantity（不含单价/合同） | contractAmount = salesPrice × quantity（沿用既存单价） |
| 同时含 salesPrice + contractAmount | 以 contractAmount 口径回算单价兜底，保留用户手动值 |

所有结果 `round2`（2 位小数，避免 float 精度噪音）。详情页编辑态同样复用此联动。

## §9 类型切换动态字段

类型选择（Fabric/Garment/Other）切换时：
- `fieldsForManualForm(typeKey)` 重新过滤 `applicableTypes`
- Fabric → 显示 `fabric` cluster（4 字段），隐藏 `materials`
- Other → 显示 `materials` cluster（2 字段），隐藏 `fabric`
- Garment → 隐藏 `fabric` 与 `materials`（成衣专属字段在 OrderLine 级，录入阶段不显示）
- `unit` 默认值按类型切换：Fabric→Meter / Garment→Pcs / Other→KG

详细字段差异矩阵见 [订单类型分层.md](./订单类型分层.md)。

## §10 保存动作

`handleSaveNewOrder` → `apiService.createOrder(newOrder)`：

1. 前端必填校验通过
2. （待实现）MOQ 校验
3. POST `/api/v1/orders`，后端分配 `code`（SO-YYYYMM-NNNN）+ 写入 `fieldSources`（标记 'manual'）
4. 成功 → 关闭 Modal + `resetNewOrder()` + 新订单合并入 `orders` state + toast success
5. 失败 → `bds-toast danger` 显示后端错误，**不关闭 Modal**（保留用户输入防丢稿）

**默认值**（`getDefaultNewOrder`）：
- status: 'Pending'（创建即待确认）
- paymentMethod: 'Net 30'
- ocDays: 30
- salesCurrency: 'USD' / purchaseCurrency: 'CNY'
- needShipmentSample: true / needHeaderSample: true
