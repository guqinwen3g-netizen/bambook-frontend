## §3 类型 Tab（一级视图切换）

| Tab | UI key | DB 值 | 说明 |
|-----|--------|-------|------|
| 全部 | `all` | — | 不按类型过滤，显示所有未删除订单 |
| 面料 | `fabric` | `Fabric` | 默认 unit=Meter，含 fabric cluster 字段 |
| 成衣 | `garment` | `Garment` | 默认 unit=Pcs，含 garmentProduction/sampleGarment cluster |
| 其他 | `other` | `Other` | 辅料/纱线，含 materials cluster |

**映射真源**：`ORDER_TYPE_TO_DB`（UI key → PascalCase）/ `dbValueToTypeKey`（反向）。Tab 切换回调 `onOrderTypeChange`，组件内 `isAllType` / `currentDbType` 派生。

**Capsule 子视图透镜**（仅成衣 Tab）：
- 成衣 Tab 下追加 `capsuleOnly` 开关（`bds-segment` 双段：成衣大货 / Capsule）
- `capsuleActive = orderType === 'garment' && capsuleOnly`
- 过滤逻辑：`(!capsuleActive || o.businessLine === 'capsule')` —— 仅显示 `businessLine='capsule'` 的成衣；未标记的成衣归"大货"
- Capsule 是设计师小单业务线，MOQ 阈值 20Pcs（详见 [订单类型分层.md](./订单类型分层.md)）

## §4 筛选条件

### 4.1 状态筛选（前端级）

| 项 | 说明 |
|----|------|
| 控件 | `orderFilterStatus` state，下拉单选 |
| 选项 | `all`（默认）/ Pending / Confirmed / Production / Shipping / Delivered / Alert |
| 作用域 | 前端 `lineItems` useMemo 内 `item.order?.status === orderFilterStatus` 过滤 |
| 与后端关系 | 当前为前端过滤；后端 `queryOrders` 支持 `filters.statuses` 数组（后端能力已就绪，前端未完全对接分页） |

### 4.2 模糊搜索（前端级）

| 项 | 说明 |
|----|------|
| 控件 | `orderSearchTerm` state，文本输入框 |
| 命中字段 | `poNumber` / `customer` / `materialCode`（客供品号）/ `description`（描述色号）/ `clientCode`（客户编码）|
| 匹配方式 | `toLowerCase().includes(q)`（大小写不敏感）|
| 作用域 | `lineItems` useMemo 内过滤 |

### 4.3 后端筛选能力（queryOrders 已就绪）

后端 `buildOrderQueryWhere` 支持的筛选维度（前端列表页尚未全部对接，留作分页/服务端筛选扩展）：

| 筛选维度 | 入参字段 | 后端实现 |
|---------|---------|---------|
| 状态 | `filters.statuses` / `filters.status` | `OR` 多状态匹配 |
| 客户 | `filters.customer` | customer / billToName / customerCode 三字段 OR |
| 供应商 | `filters.supplier` / `filters.millName` | millName / millRelationId / lines.millQuality OR |
| PO 号 | `filters.poNumber` / `filters.po` | poNumber contains |
| 交期范围 | `filters.dueDateFrom` / `dueDateTo` | dueDate gte/lte |
| 创建时间范围 | `filters.createdAtFrom` / `createdAtTo` | createdAt BigInt gte/lte |
| 缺字段 | `filters.missingFields` | OR(null, '') 标识字段缺失的订单 |
| 字段级过滤 | `filters.fieldFilters` | path/operator/value，白名单 `SAFE_ORDER_FIELDS` 校验 |
| 通用查询 | `query` | 13 字段 OR 模糊（id/poNumber/customer/customerCode/product/millName/billToName/consigneeName/invoiceNumber/supplierInvoiceNumber/fabricCode/fabricContent + lines 三字段）|

### 4.4 排序

| 项 | 说明 |
|----|------|
| 前端 | 列表当前按后端返回顺序（`updatedAt desc` 默认） |
| 后端 | `orderQueryOrderBy`，白名单 `ORDER_SORT_FIELDS`：updatedAt / importedAt / dueDate / clientDate / customer / status / poNumber；默认 updatedAt desc |

## §5 列定义

6 列固定栅格，header 定义在 `ORDER_TABLE_HEADERS`：

| # | 列名 | 宽度 | 内容 | 对齐 |
|---|------|------|------|------|
| 1 | 订单 / 客户 | 22% | PO# + 客户名 + 类型徽章（Fabric/Garment/Other 彩色圆点）| 左 |
| 2 | 品号 | 15% | clientCode（客供品号）+ productColorCode（工厂品色号）| 左 |
| 3 | 描述 / 色号 | 27% | product + description + 面料成份/规格摘要 | 左 |
| 4 | 数量 / 金额 | 13% | quantity + unit + 金额（contractAmount → quoteAmount 兜底）+ 币种前缀 | 右 |
| 5 | 日期 | 13% | clientDate（出厂交期）→ dueDate 兜底，YYYY-MM-DD | 左 |
| 6 | 状态 / 动作 | 10% | 状态徽章（STATUS_BADGE_VARIANT）+ 行点击/更多操作 | 左 |

**列视觉规范**：
- 状态徽章语义：Pending=neutral / Confirmed·Production·Shipping=info / Delivered=success / Alert=warning
- 类型圆点允许彩色（`ORDER_TYPE_DOT_STYLE`）：Fabric=accent / Garment=wisteria / Other=warning
- 金额归一化：`Number(n).toLocaleString('zh-CN', { maximumFractionDigits: 2 })`，空值显示 `—`
- 日期归一化：`formatYmd` → YYYY-MM-DD

## §6 行级展开（按行渲染）

订单列表采用**行级展开**策略：一个 PO 若有多个 `OrderLine`，每个 line 在列表里独立成一行（共享 order 头信息）。

**实现**：`flattenOrderLines(orders)` → `OrderLineItem[]`，每条含 `order` 引用 + line 字段 + `displayItemNo` / `displayId` / `amount`。

**过滤链**（`lineItems` useMemo）：
1. `flattenOrderLines(orders)` 展平
2. 类型过滤：`isAllType || item.order?.type === currentDbType`
3. Capsule 过滤：`!capsuleActive || item.order?.businessLine === 'capsule'`
4. 状态过滤：`orderFilterStatus === 'all' || item.order?.status === orderFilterStatus`
5. 搜索过滤：命中 5 字段之一

**行点击**：`handleOrderClick(order)` → `onSelectOrder(order)` + 设置 `editForm` + 从 `order.lines` 映射 `poItems` → 进入详情全屏覆盖。

**PO/合同证据附件规则**：
1. 业务员先手动录入订单主单和产品行；
2. 上传的 PO/合同文件只作为该订单的证据附件保存；
3. MVP 不做 PDF/Excel 内容解析、OCR、字段提取或自动填单；上传附件本身不能创建/转换订单。

| 状态 | 触发 | UI 规范 |
