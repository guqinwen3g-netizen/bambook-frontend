## §2 双轨制设计

订单关联实体有两种互补的发现机制：

| 轨 | 数据源 | 服务 | 视角 |
|----|--------|------|------|
| **横向图谱** | EntityLink 表 | `GET /api/v1/relations/by-target?type=order&id={orderId}` | 跨模块横向发现任意实体关联（关联视图面板 §3.4） |
| **纵向聚合**（本文档） | 直接查表 10 实体 | `GET /api/v1/orders/:id/context` → `getOrderContext` | 按业务阶段纵向还原完整生命周期 |

两轨互补：图谱服务"关联发现"（含人工补录的 link）；聚合查询服务"生命周期还原"（按业务阶段固定结构）。

## §4 二级嵌套装配

`getOrderContext` 在 10 阶段一级查询后，做 3 组二级嵌套装配：

### 4.1 样衣节点 → 开发案

```
DevelopmentCase[] (阶段 2)
  └── sampleNodes: SampleNode[] (where developmentCaseId IN caseIds)
```
SampleNode 字段：id + developmentCaseId + level(confirmation/pp/top) + round + status + sentDate + approvedAt

### 4.2 报关单 + 退税 → 运单

```
Shipment[] (阶段 8)
  └── customsDeclarations: CustomsDeclaration[] (where shipmentId IN shipmentIds)
        └── taxRefunds: TaxRefund[] (where declarationId IN declarationIds)
```
- 退税按 orderId 或 declarationId 双路匹配
- 匹配不上 shipment 的报关单/退税归入顶层 `customsDeclarations` / `taxRefunds`（orphan 列表）

### 4.3 核销明细 → 发票

```
Invoice[] (阶段 9)
  └── allocations: InvoiceAllocation[] (where invoiceId IN invoiceIds)
```
InvoiceAllocation 字段：id + invoiceId + voucherId + appliedAmount + appliedDate（支持部分销账，1:N 中间表）

## §5 聚合返回结构

```typescript
{
  found: true,
  order: { id, poNumber },
  quotation: [...],           // 阶段 1
  developmentCase: [{         // 阶段 2（含嵌套 sampleNodes）
    ...case, sampleNodes: [...]
  }],
  bom: [...],                 // 阶段 3
  procurement: [...],         // 阶段 4
  production: {               // 阶段 5 + 6
    stages: [...],            // ProductionStage[]
    inspections: [...]        // InspectionReport[]
  },
  outsourcing: [...],         // 阶段 7
  shipments: [{               // 阶段 8（含嵌套 customsDeclarations → taxRefunds）
    ...shipment, customsDeclarations: [{...d, taxRefunds: [...]}]
  }],
  customsDeclarations: [...], // orphan 报关单（匹配不上 shipment）
  taxRefunds: [...],          // orphan 退税
  finance: {                  // 阶段 9 + 10
    invoices: [{...i, allocations: [...]}],
    vouchers: [...]
  }
}
```

**BigInt/Decimal 序列化**：`serializeBigInts` 递归将 BigInt epoch ms 与 Prisma Decimal 转 Number（JSON 安全）。

## §6 OrderContextSection 组件规格

### 6.1 Props

| Prop | 类型 | 说明 |
|------|------|------|
| orderId | string | 订单 ID（驱动 fetch） |
| onNavigate | `(view: View) => void` | 卡片点击跳转回调；未传入则卡片禁用态 |
| refreshKey | number | 外部递增触发重新拉取（保存后刷新） |

### 6.2 数据源

`GET /api/v1/orders/:id/context` → `getOrderContext(prisma, orderId)`

### 6.3 渲染规则

| 规则 | 说明 |
|------|------|
| 空阶段不隐藏 | 显示"未启动"斜体灰态（让用户看到完整生命周期，防抖动） |
| header meta | `N/10 阶段已启动`（count > 0 的阶段数） |
| 卡片点击 | `onNavigate` 传入 → 跳转对应 view（chevron-right 图标）；未传入 → 禁用态（pointer-default + 无 chevron） |
| loading | `flex items-center gap-2 muted` + Loader2 spin |
| error | `bds-alert danger` 提示网络错误 + Retry（通过 `refreshKey` prop 触发重新拉取） |
| 多记录阶段 | 同一阶段多条记录纵向堆叠（如多个 Shipment） |

### 6.4 卡片字段展示

每张阶段卡 3-5 行摘要字段：
- 第 1 行：编号（quotationNumber/poNumber/shipmentNumber 等）+ 状态徽章
- 第 2 行：金额 + 币种
- 第 3 行：关键日期（issueDate/ETD/paymentDate 等）
- 第 4 行（可选）：关联实体名（supplierName/customerName）

## §9 缓存与刷新

| 项 | 说明 |
|----|------|
| 拉取时机 | 详情页打开 + `refreshKey` 变化（编辑保存后递增） |
| 缓存策略 | 无前端缓存（每次 refreshKey 变化重新 fetch） |
| 并发 | 10 实体 `Promise.all` 并行查询 + 二级 3 组 `Promise.all` |
| 错误隔离 | 任一阶段查询失败不影响整体（catch 兜底返回空数组） |

## §10 性能考量

| 项 | 说明 |
|----|------|
| 查询次数 | 10 一级 + 3 二级 = 13 次 prisma 查询（全并行） |
| select 投影 | 每实体只 select 摘要字段（5-8 个），不展开全字段 |
| 索引依赖 | 各实体 orderId / convertedOrderId / linkedOrderId / shipmentId / invoiceId / declarationId 索引 |
| 数据量 | 单订单关联实体通常 < 50 条，无分页需求 |
