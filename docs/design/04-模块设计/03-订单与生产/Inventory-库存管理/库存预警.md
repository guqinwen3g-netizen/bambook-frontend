## §3 低值预警详解

### 3.1 预警判定逻辑

```
低库存 = (minStock != null) && (Number(quantity) <= Number(minStock))
```

- minStock 为 InventoryItem 字段（Decimal(18,4)? 可空）
- 仅设置了 minStock 的物料参与预警
- `<=` 包含等号（恰好等于 minStock 也预警）

### 3.2 后端查询

```typescript
// inventoryService.ts getLowStockItems()
async function getLowStockItems(): Promise<InventoryItemDetail[]> {
  const items = await prisma.inventoryItem.findMany({
    where: { deletedAt: null, minStock: { not: null } },
    include: { warehouse: true },
  });
  // 跨字段比较 Prisma 不支持，内存过滤兜底
  return items.filter((item: any) => Number(item.quantity) <= Number(item.minStock));
}
```

> ⚠️ Prisma 无法直接做跨字段比较（quantity ≤ minStock），采用先查询再内存过滤的方式。大数据量时需优化为 raw SQL。

### 3.3 前端展示

预警 Tab（activeTab='alerts'）渲染低库存物料卡片列表：

## §4 超储预警详解

### 4.1 预警判定逻辑

```
超储 = (maxStock != null) && (Number(quantity) >= Number(maxStock)) && (type === 'Inbound')
```

- maxStock 为 InventoryItem 字段（Decimal(18,4)? 可空）
- 仅 Inbound（入库）变动后触发（出库不会触发超储预警）
- `>=` 包含等号

### 4.2 事件发布

```typescript
// inventoryService.ts createStockMovement 事务提交后
if (item.maxStock != null && newQty >= Number(item.maxStock) && input.type === 'Inbound') {
  businessEventBus.publish({
    id: `bev_stock_over_${now}_${random}`,
    type: 'StockOverstockAlarm',
    sourceEntityType: 'InventoryItem',
    sourceEntityId: input.itemId,
    payload: {
      itemId, description, materialCode,
      warehouseCode, warehouseName,
      currentQty: newQty, maxStock: Number(item.maxStock), unit,
    },
    occurredAt: now,
    actorId: actorId || 'system',
  });
}
```

## §5 预警阈值配置

### 5.1 当前阈值配置方式

阈值通过 InventoryItem 的 minStock / maxStock 字段配置：

| 字段 | 类型 | 配置入口 | 说明 |
|------|------|---------|------|
| minStock | Decimal(18,4)? | 新建物料表单 / 编辑物料（PUT /items/:id） | 最低库存预警线 |
| maxStock | Decimal(18,4)? | 新建物料表单 / 编辑物料 | 最高库存预警线 |

### 5.2 新建物料表单阈值字段

```
┌ 新增库存物料 ─────────────────────────────────────┐
│ ... 其他字段 ...                                   │
│ ┌最低库存────────┐ ┌最高库存────────┐              │
│ │ [    500    ] │ │ [   5000   ] │              │
│ └───────────────┘ └───────────────┘              │
│ (留空则不参与预警)                                  │
└──────────────────────────────────────────────────────┘
```

- 最低/最高库存留空 → 该物料不参与预警
- 填写数值 → 变动后自动校验并触发事件

### 5.3 阈值配置规则（规划增强）

> ⚠️ 当前阈值为物料级（每个 InventoryItem 独立设置）。规划为多级配置：

| 配置层级 | 粒度 | 优先级 | 说明 |
|---------|------|--------|------|
| 物料级（当前） | InventoryItem.minStock/maxStock | 最高 | 单个物料批次独立阈值 |
| 品类级（规划） | category × minStock/maxStock | 中 | 按品类批量设阈值 |
| 仓库级（规划） | warehouse × minStock/maxStock | 低 | 按仓库容量设阈值 |
| 全局级（规划） | SystemConfig 键值对 | 兜底 | 全局默认阈值 |

## §6 通知触发机制

### 6.1 事件总线发布（fire-and-forget）

```
库存变动事务提交
  ↓
inventoryService.createStockMovement 内：
  if (newQty <= minStock) → publish StockLowAlarm
  if (newQty >= maxStock && type=Inbound) → publish StockOverstockAlarm
  ↓ (try/catch 包裹，失败不阻断业务)
businessEventBus.publish()
  ↓
NotificationService 消费 → broadcastNotification（推送通知）
```

## §7 呆滞预警（规划增强）

> ⚠️ 呆滞预警尚未实现，以下为规划设计。

### 7.1 呆滞判定逻辑

```
呆滞 = (lastInDate != null || lastOutDate != null) && (距今天数 > 呆滞阈值)
呆滞天数 = min(today - lastInDate, today - lastOutDate)  // 取最近一次变动距今
```

| 呆滞等级 | 天数范围 | 语义 |
|---------|---------|------|
| 轻度呆滞 | 60-90 天 | warning |
| 中度呆滞 | 90-180 天 | warning（加粗） |
| 重度呆滞 | > 180 天 | danger |

### 7.2 呆滞预警查询（规划）

```typescript
// 规划端点：GET /api/v1/inventory/alerts/stagnant?days=90
async function getStagnantItems(days: number = 90): Promise<InventoryItemDetail[]> {
  const threshold = new Date(Date.now() - days * 86400000).toISOString().slice(0, 10);
  const items = await prisma.inventoryItem.findMany({
    where: {
      deletedAt: null,
      quantity: { gt: 0 },
      OR: [
        { lastInDate: { lt: threshold } },
        { lastOutDate: { lt: threshold } },
      ],
    },
    include: { warehouse: true },
  });
  return items;
}
```

### 7.3 呆滞阈值配置（规划）

| 配置项 | 默认值 | 配置方式 |
|--------|--------|---------|
| 呆滞预警天数 | 90 天 | SystemConfig `inventory.stagnant.days` |
| 重度呆滞天数 | 180 天 | SystemConfig `inventory.stagnant.critical.days` |

// 规划端点：GET /api/v1/inventory/alerts/expiring?days=30
async function getExpiringItems(days: number = 30): Promise<InventoryItemDetail[]> {
  const today = new Date().toISOString().slice(0, 10);
  const threshold = new Date(Date.now() + days * 86400000).toISOString().slice(0, 10);
  return prisma.inventoryItem.findMany({
    where: {
      deletedAt: null,
      quantity: { gt: 0 },
      expiryDate: { not: null, gte: today, lte: threshold },
    },
    include: { warehouse: true },
  });
}
