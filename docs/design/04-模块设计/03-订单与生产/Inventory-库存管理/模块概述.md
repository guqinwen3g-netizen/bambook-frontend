## §2 模块边界与职责

库存管理模块是 Bambook ERP 供应链执行层的数据枢纽，其核心职责矩阵：

| 职责域 | 已实现 | 规划增强 | 上下游依赖 |
|--------|--------|----------|-----------|
| **多仓库管理** | ✅ Warehouse CRUD（Main/Auxiliary/Temporary/Virtual 四型） | ⚠️ WarehouseLocation（库位精细化管理 A-01-03） | 无上游；下游 InventoryItem |
| **库存台账** | ✅ InventoryItem（仓库×物料×批次维度，quantity/lockedQuantity 双值） | ⚠️ 批次追踪看板（batchNumber 聚合视图） | 上游 ProductAsset/FabricProfile；下游 StockMovement |
| **出入库流水** | ✅ StockMovement 6 型（Inbound/Outbound/Transfer/Adjustment/Lock/Unlock）+ balanceBefore/After 审计 | ⚠️ PreReceiptNotice（预到货）/GoodsReceiptNote（正式入库单） | 上游 PurchaseOrder/Order/Shipment；下游 AuditLog |
| **盘点** | ✅ Adjustment 类型（目标绝对值覆盖式调整 + 流水留痕） | ⚠️ StockCountTask/StockCountItem（任务化盘点 + 差异审批） | 无上游；下游 StockMovement |
| **调拨** | ✅ Transfer 类型（事务内双仓联动：源仓出库 + 目标仓入库/建项） | ⚠️ StockTransfer 独立单据（多步状态机：申请→审批→在途→到货） | 无上游；下游 StockMovement ×2 |
| **库存预警** | ✅ 低库存（quantity ≤ minStock）+ 超储（quantity ≥ maxStock）+ 事件总线 | ⚠️ 呆滞预警（lastInDate/lastOutDate 滞库天数）+ 过期预警（批次有效期） | 上游 InventoryItem min/maxStock；下游 Notification |

## §4 核心数据模型速览

| 模型 | 主键格式 | 职责 | 软删 | 关键约束 |
|------|---------|------|------|---------|
| **Warehouse** | `WH_${shortId}` | 仓库主数据（编码/名称/类型/管理员） | ✅ deletedAt | code @unique |
| **InventoryItem** | `INV_${shortId}` | 库存台账（仓库×物料×批次维度余额） | ✅ deletedAt | 删除前 quantity 必须为 0 |
| **StockMovement** | `SM_${shortId}` | 出入库流水（不可变审计记录） | ❌ 不软删（流水永久留痕） | balanceBefore/After + type 严格校验 |

> ⚠️ 规划模型（尚未建表）：StockCountTask / StockCountItem（任务化盘点）、PreReceiptNotice（预到货通知）、GoodsReceiptNote（正式入库单）、StockTransfer（独立调拨单）。当前盘点走 StockMovement type=Adjustment，调拨走 type=Transfer。

## §5 StockMovement 6 型变动矩阵

| 类型 | 标签 | 图标 | 语义徽章 | 余额影响 | lockedQuantity 影响 | 前端校验 |
|------|------|------|---------|---------|---------------------|---------|
| **Inbound** | 入库 | ArrowDownToLine | success | quantity += qty | 不变 | 无（正数即可） |
| **Outbound** | 出库 | ArrowUpFromLine | warning | quantity -= qty | 不变 | qty ≤ quantity（不足报错） |
| **Transfer** | 调拨 | ArrowLeftRight | info | 源仓 -= qty / 目标仓 += qty | 不变 | 必须指定 targetWarehouseId + qty ≤ 源仓 quantity |
| **Adjustment** | 盘点 | ClipboardCheck | neutral | quantity = qty（绝对值覆盖） | 不变 | 无（可为 0） |
| **Lock** | 锁定 | Lock | warning | 不变 | lockedQuantity += qty | lockedQty + qty ≤ quantity |
| **Unlock** | 解锁 | Unlock | success | 不变 | lockedQuantity -= qty | qty ≤ lockedQuantity |

## §6 业务事件总线集成

库存变动事务提交后，以 fire-and-forget 方式发布业务事件（发布失败不阻断业务）：

| 事件类型 | 触发条件 | payload 关键字段 | 下游消费者 |
|---------|---------|-----------------|-----------|
| **StockLowAlarm** | 变动后 newQty ≤ minStock | itemId / materialCode / warehouseCode / currentQty / minStock / unit / movementType | NotificationService → 推送预警通知 |
| **StockOverstockAlarm** | Inbound 后 newQty ≥ maxStock | itemId / materialCode / warehouseCode / currentQty / maxStock / unit | NotificationService → 推送超储通知 |

## §9 事务原子性保障

所有库存变动在 `prisma.$transaction` 内完成，保证原子性：

```
事务内执行顺序：
1. 创建 StockMovement 流水记录（balanceBefore/After 已预算）
2. 更新 InventoryItem.quantity / lockedQuantity / lastInDate / lastOutDate
3. [仅 Transfer] 目标仓库：创建或更新 InventoryItem + 写入库流水（type=Inbound, referenceType=Transfer）
4. 写 AuditLog（action=stock_movement_{type}, beforeValue/afterValue）
── 事务提交 ──
5. [事务后 fire-and-forget] 发布 StockLowAlarm / StockOverstockAlarm 事件
```

**fail-closed 原则**：Outbound / Transfer / Lock 时若库存不足，事务内 throw → 整个事务回滚，不留半途数据。

## §14 关键业务规则

| # | 规则 | 实现状态 |
|---|------|---------|
| 1 | 余额不可为负（Outbound/Transfer/Lock 时校验 sufficient stock，fail-closed） | ✅ inventoryService 事务内 throw |
| 2 | 所有变动写流水 + 审计日志（StockMovement + AuditLog 双写） | ✅ 事务内完成 |
| 3 | 软删除物料前 quantity 必须为 0（防误删有库存项） | ✅ deleteInventoryItem 校验 |
| 4 | 软删除仓库前无非零库存项 | ✅ deleteWarehouse count 校验 |
| 5 | 初始数量 > 0 的物料自动生成入库流水 | ✅ createInventoryItem 事务内 |
| 6 | Transfer 双仓联动（源仓出库 + 目标仓建项/累加 + 双流水） | ✅ 同一事务内 |
| 7 | 低库存/超储事件发布（fire-and-forget，不阻断业务） | ✅ 事务后 publish |
| 8 | 数值精度 4 位小数（toDecimal: Math.round(n × 10000) / 10000） | ✅ |
