## §2 StockMovement 模型全量字段

| 字段 | 类型 | 说明 | 校验/约束 |
|------|------|------|-----------|
| id | String @id | 格式 `SM_${shortId}` | 系统生成 |
| movementNumber | String | 流水单号（如 `SM-20260806-A1B2`） | 系统生成（日期+随机） |
| type | String | Inbound/Outbound/Transfer/Adjustment/Lock/Unlock | `validateMovementType` 白名单校验 |
| itemId | String | 关联 InventoryItem | 必须存在且未软删 |
| warehouseId | String | 操作仓库（源仓库） | 必须存在且未软删 |
| targetWarehouseId | String? | 调拨目标仓库（仅 Transfer） | Transfer 时必填 + 目标仓活跃 |
| quantity | Decimal(18,4) | 变动数量 | Inbound/Outbound/Transfer/Lock/Unlock > 0；Adjustment 可为 0 |
| unit | String | 单位（继承自 InventoryItem 或传入） | YD/M/KG/PC/SET |
| unitCost | Decimal(18,4)? | 变动时单位成本 | 可选 |
| balanceBefore | Decimal(18,4) | 变动前余额 | 系统计算 = currentQty |
| balanceAfter | Decimal(18,4) | 变动后余额 | 系统计算（按 type 推导） |
| reason | String? | 变动原因 | 可选（建议填写） |
| referenceType | String? | 来源单据类型 | PurchaseOrder/Order/Shipment/ProductionStage/Adjustment/Manual |
| referenceId | String? | 来源单据 ID | 与 referenceType 配对 |
| operator | String? | 操作人 | 从 actorId 传入 |
| movementDate | String | 变动日期 YYYY-MM-DD | 默认今日 |
| notes | String? | 备注 | 可选 |
| createdAt | BigInt | 创建时间戳 | 系统生成（不可变） |

**索引**：itemId / type / warehouseId / movementDate / (referenceType, referenceId)

> ⚠️ StockMovement 不软删 — 流水一旦创建即永久留痕，修改变动 = 新增一条反向流水（Adjustment）。

## §3 六型变动详解

### 3.1 入库 Inbound

| 项 | 说明 |
|----|------|
| 余额影响 | `quantity += moveQty` |
| 日期更新 | `lastInDate = movementDate` |
| lockedQuantity | 不变 |
| 校验 | 无前置校验（正数即可入库） |
| 业务场景 | 采购到货入库（referenceType=PurchaseOrder）/ 生产入库（referenceType=ProductionStage）/ 退货入库（referenceType=Order, reason=退货）/ 初始入库（createInventoryItem 时 quantity > 0 自动生成） |
| 前端徽章 | success 绿 + ArrowDownToLine 图标 |

### 3.2 出库 Outbound

| 项 | 说明 |
|----|------|
| 余额影响 | `quantity -= moveQty` |
| 日期更新 | `lastOutDate = movementDate` |
| lockedQuantity | 不变 |
| 校验 | **fail-closed**：`moveQty > currentQty` → throw「库存不足：当前 X unit，尝试出库 Y unit」 |
| 业务场景 | 生产领料（referenceType=Order）/ 销售出库（referenceType=Shipment）/ 调拨出库（见 Transfer）/ 报废出库（reason=报废） |
| 前端徽章 | warning 橙 + ArrowUpFromLine 图标 |

### 3.3 调拨 Transfer

| 项 | 说明 |
|----|------|
| 余额影响 | 源仓 `quantity -= moveQty` / 目标仓 `quantity += moveQty`（同事务） |
| 日期更新 | 源仓 lastOutDate / 目标仓 lastInDate |
| lockedQuantity | 两仓均不变 |
| 校验 | 必须指定 targetWarehouseId + 源仓库存充足 + 目标仓活跃 |
| 双仓联动 | ① 源仓写 Outbound 流水（balanceBefore/After）② 目标仓：已有同物料批次项则累加，无则新建 InventoryItem ③ 目标仓写 Inbound 流水（referenceType=Transfer, referenceId=源流水 ID） |
| 业务场景 | 跨仓调拨（主仓→辅仓 / 工厂仓→临时仓） |
| 前端徽章 | info 蓝 + ArrowLeftRight 图标 |

**Transfer 事务执行流程**：

```
事务开始
├─ 1. 创建源仓 StockMovement（type=Transfer, balanceBefore/After）
├─ 2. 更新源仓 InventoryItem（quantity -= moveQty, lastOutDate）
├─ 3. 查找目标仓同物料批次 InventoryItem
│   ├─ 找到 → update（quantity += moveQty, lastInDate）
│   └─ 未找到 → create（新建 InventoryItem，notes="从仓库 {源仓code} 调入"）
├─ 4. 创建目标仓 StockMovement（type=Inbound, referenceType=Transfer, referenceId=源流水id）
├─ 5. 写 AuditLog（operationType=decrement, beforeValue/afterValue）
事务提交
├─ 6. [fire-and-forget] StockLowAlarm / StockOverstockAlarm 事件发布
```

### 3.4 盘点 Adjustment

| 项 | 说明 |
|----|------|
| 余额影响 | `quantity = moveQty`（绝对值覆盖，非增量） |
| 日期更新 | 不更新 lastInDate/lastOutDate |
| lockedQuantity | 不变 |
| 校验 | 无前置校验（可为 0，表示清零） |
| 业务场景 | 实地盘点后差异核销（reason=盘点, notes=盘点备注） |
| 前端徽章 | neutral 灰 + ClipboardCheck 图标 |

> ⚠️ 当前盘点以 Adjustment 承载，无独立 StockCountTask 任务化流程。详见 `./盘点与调拨.md`。

### 3.5 锁定 Lock

| 项 | 说明 |
|----|------|
| 余额影响 | `quantity` 不变 |
| lockedQuantity | `lockedQuantity += moveQty` |
| 校验 | **fail-closed**：`lockedQty + moveQty > currentQty` → throw「可锁定库存不足」 |
| 业务场景 | 验货预留（referenceType=InspectionReport）/ 订单预留（referenceType=Order） |
| 前端徽章 | warning 橙 + Lock 图标 |

### 3.6 解锁 Unlock

| 项 | 说明 |
|----|------|
| 余额影响 | `quantity` 不变 |
| lockedQuantity | `lockedQuantity -= moveQty` |
| 校验 | **fail-closed**：`moveQty > lockedQty` → throw「解锁数量超过已锁定」 |
| 业务场景 | 验货取消预留 / 订单取消后释放 |
| 前端徽章 | success 绿 + Unlock 图标 |

## §6 自动联动场景（规划增强）

> ⚠️ 以下联动场景当前需手动录入变动，规划为系统自动联动。

| 上游触发 | 自动变动 | 联动方式 | 状态 |
|---------|---------|---------|------|
| 采购单到货确认（PurchaseOrder.status=Received） | 自动 Inbound（referenceType=PurchaseOrder） | 采购模块 → 事件总线 → 库存模块 | ⚠️ 未联动 |
| 生产阶段 materials_arrived 完成 | 自动 Inbound（referenceType=ProductionStage） | 生产管线 → 事件总线 → 库存模块 | ⚠️ 未联动 |
| 订单出运创建（Shipment.status=Booked） | 自动 Outbound（referenceType=Shipment） | 出运模块 → 事件总线 → 库存模块 | ⚠️ 未联动 |
| QC 验货任务开始 | 自动 Lock（referenceType=InspectionReport） | QC 模块 → 事件总线 → 库存模块 | ⚠️ 未联动 |
| QC 验货任务取消 | 自动 Unlock（referenceType=InspectionReport） | QC 模块 → 事件总线 → 库存模块 | ⚠️ 未联动 |
| 退货入库 | 自动 Inbound（referenceType=Order, reason=退货） | 订单退货流程 → 库存模块 | ⚠️ 未联动 |

## §7 事务原子性与 fail-closed

**核心原则**：所有变动在 `prisma.$transaction` 内完成，保证：
1. **流水与余额原子性** — StockMovement 创建 + InventoryItem 更新同事务，不会出现有流水无余额更新
2. **Transfer 双仓原子性** — 源仓出库 + 目标仓入库同事务，不会出现调拨半途丢失
3. **审计留痕原子性** — AuditLog 与变动同事务，不会出现有变动无审计
4. **fail-closed** — 库存不足时 throw → 整个事务回滚，不留半途数据

**数值精度**：`toDecimal(n) = Math.round(n * 10000) / 10000`（4 位小数）
