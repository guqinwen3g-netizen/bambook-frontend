## §2 盘点 Adjustment 详解

### 2.1 盘点语义

盘点变动以**目标绝对值**覆盖当前 quantity（非增量加减）：

```
balanceBefore = currentQty
balanceAfter = moveQty  ← 覆盖式（不是 currentQty ± moveQty）
newQty = moveQty
```

| 场景 | balanceBefore | moveQty(目标值) | balanceAfter | 差异 |
|------|--------------|----------------|--------------|------|
| 盘亏（实盘 < 账面） | 1000 | 980 | 980 | -20 |
| 盘盈（实盘 > 账面） | 1000 | 1020 | 1020 | +20 |
| 无差异 | 1000 | 1000 | 1000 | 0 |
| 清零（报废/注销） | 500 | 0 | 0 | -500 |

### 2.2 盘点表单字段

| 字段 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 类型 | bds-select | ✅ | 选「盘点 Adjustment」 |
| 数量 | bds-input number | ✅ | **目标绝对值**（非差异数） |
| 日期 | bds-input date | ✅ | 盘点日期（默认今日） |
| 原因 | bds-input text | ❌ | 建议「盘点」 |
| 盘点备注 | bds-input text（xl:col-span-2） | ❌ | **仅 Adjustment 显示**（盘点详情说明） |

### 2.3 盘点事务执行

```
事务内：
1. validateMovementType('Adjustment')
2. 查 InventoryItem（必须存在 + 未软删）
3. 查 Warehouse（必须存在 + 未软删）
4. 计算：newQty = toDecimal(moveQty); balanceAfter = newQty
   - lastInDate/lastOutDate 不更新（盘点不改入出库日期）
5. 创建 StockMovement（type=Adjustment, balanceBefore=currentQty, balanceAfter=newQty）
6. 更新 InventoryItem（quantity=newQty, updatedAt=now）
7. 写 AuditLog（action=stock_movement_adjustment, operationType=increment/decrement, beforeValue/afterValue）
事务提交
8. [fire-and-forget] StockLowAlarm（newQty ≤ minStock）/ StockOverstockAlarm（不触发，仅 Inbound 触发）
```

### 2.4 盘点差异处理（规划增强）

> ⚠️ 当前盘点差异无审批流程，Adjustment 直接执行即生效。规划为任务化盘点 + 差异审批。

**规划设计 — StockCountTask 模型**（待建表）：

| warehouseId | String | 盘点仓库 |
| scope | String? | 盘点范围（全仓/品类/批次/库位） |
| status | String | Draft→Assigned→InProgress→Reconciling→Completed→Cancelled |

| plannedDate | String? | 计划盘点日期 |

| completedAt | BigInt? | 完成时间 |
| notes | String? | 备注 |

**StockCountItem 模型**（待建表）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String @id | — |
| taskId | String | 关联 StockCountTask |

| systemQty | Decimal(18,4) | 系统账面数量（盘点时快照） |

| variance | Decimal(18,4)? | 差异 = countedQty - systemQty |

**任务化盘点流程**（规划）：

```
Draft → Assigned（分配盘点人）
  → InProgress（开始盘点，逐项录入 countedQty）
  → Reconciling（差异复核，差异 > 阈值需审批）
  → Completed（差异审批通过，自动生成 Adjustment 流水核销差异）
  → Cancelled（取消）
```

## §3 调拨 Transfer 详解

### 3.1 调拨语义

调拨 = 源仓出库 + 目标仓入库，同一事务内完成双仓联动：

```
源仓：balanceBefore = currentQty; balanceAfter = currentQty - moveQty; lastOutDate = movementDate
目标仓：新建或累加 InventoryItem; lastInDate = movementDate; 写 Inbound 流水（referenceType=Transfer）
```

### 3.2 调拨表单字段

| 字段 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 类型 | bds-select | ✅ | 选「调拨 Transfer」 |
| 数量 | bds-input number | ✅ | 调拨数量 |
| 日期 | bds-input date | ✅ | 调拨日期（默认今日） |
| 原因 | bds-input text | ❌ | 调拨原因 |
| 目标仓库 | bds-select（xl:col-span-2） | ✅ | **仅 Transfer 显示**（过滤掉当前仓库） |

### 3.3 调拨事务执行（双仓联动）

```
事务内：
1. validateMovementType('Transfer')
2. 查源 InventoryItem + 源 Warehouse（必须存在 + 未软删）
3. 校验：moveQty > currentQty → throw「库存不足」
4. 查目标 Warehouse（必须存在 + 活跃 + 未软删）
5. 创建源仓 StockMovement（type=Transfer, balanceBefore/After, targetWarehouseId）
6. 更新源仓 InventoryItem（quantity -= moveQty, lastOutDate）
7. 查目标仓同物料批次 InventoryItem（where: warehouseId + materialCode + productAssetId + batchNumber）
   ├─ 找到 → update（quantity += moveQty, lastInDate, updatedAt）
   │        balanceBefore = targetItem.quantity - moveQty
   └─ 未找到 → create（新建 InventoryItem，notes="从仓库 {源仓code} 调入"）
               balanceBefore = 0
8. 创建目标仓 StockMovement（type=Inbound, itemId=targetItem.id, referenceType=Transfer, referenceId=源流水id）
9. 写 AuditLog（action=stock_movement_transfer, operationType=decrement, beforeValue/afterValue）
事务提交
10. [fire-and-forget] StockLowAlarm（源仓 newQty ≤ minStock）
```

**关键设计点**：
- 目标仓物料匹配维度：`warehouseId + materialCode + productAssetId + batchNumber`（同物料同批次同产品才累加，否则新建）
- 目标仓流水 referenceId 指向源仓流水 ID，形成可追溯链
- 目标仓流水 reason 自动填写「从仓库 {源仓code} 调入」

### 3.4 目标仓 InventoryItem 新建字段映射

当目标仓无匹配物料时，从源 InventoryItem 复制以下字段：

| 源字段 | 目标字段 | 处理 |
|--------|---------|------|
| materialCode | materialCode | 直接复制 |
| productAssetId | productAssetId | 直接复制 |
| description | description | 直接复制 |
| category | category | 直接复制 |
| specification | specification | 直接复制 |
| batchNumber | batchNumber | 直接复制 |
| unit | unit | 直接复制 |
| unitCost | unitCost | 直接复制 |
| currency | currency | 直接复制 |
| minStock | minStock | 直接复制 |
| maxStock | maxStock | 直接复制 |
| locationCode | locationCode | **置 null**（目标仓需重新分配库位） |
| quantity | quantity | **= moveQty**（调拨数量） |
| lockedQuantity | lockedQuantity | **= 0**（新仓不继承锁定） |
| lastInDate | lastInDate | = movementDate |
| notes | notes | "从仓库 {源仓code} 调入" |

### 3.5 独立调拨单 StockTransfer（规划增强）

> ⚠️ 当前调拨以 Transfer 流水直接执行，无审批/在途状态。规划为独立调拨单。

**规划设计 — StockTransfer 模型**（待建表）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String @id | 格式 `STF_${shortId}` |
| transferNumber | String @unique | 调拨单号（如 STF-20260815-001） |
| sourceWarehouseId | String | 源仓库 |
| targetWarehouseId | String | 目标仓库 |
| status | String | Requested→Approved→InTransit→Received→Cancelled |
| requestedBy | String | 申请人 |
| approvedBy | String? | 审批人 |
| movementDate | String | 调拨日期 |
| notes | String? | 备注 |
| items | StockTransferItem[] | 调拨物料行 |

**独立调拨单流程**（规划）：

```
Requested（申请，多物料行）
  → Approved（审批通过，大额需管理层审批）
  → InTransit（在途，源仓已出库但目标仓未确认到货）
  → Received（到货确认，目标仓入库 + 写双流水）
  → Cancelled（取消，需在 Approved 前取消）
```

## §4 库存锁定与调拨的关系

| 场景 | quantity | lockedQuantity | availableQuantity | 可调拨量 |
|------|----------|----------------|-------------------|---------|
| 正常库存 | 1000 | 0 | 1000 | 1000 |
| 部分锁定 | 1000 | 300 | 700 | 1000（锁定不阻止调拨，但建议仅调拨可用量） |
| 全部锁定 | 1000 | 1000 | 0 | 1000（可调拨但 lockedQuantity 不跟随转移） |

> ⚠️ 当前 Transfer 仅校验 `moveQty > currentQty`（总库存），不校验可用量（quantity - lockedQuantity）。规划设计建议：Transfer 应校验 `moveQty > availableQuantity` → throw「可调拨量不足」（保护已锁定库存不被调走）。

## §13 审计追踪

| 操作 | AuditLog action | operationType | beforeValue/afterValue |
|------|----------------|---------------|----------------------|
| 盘点 | stock_movement_adjustment | increment(盘盈)/decrement(盘亏) | currentQty / newQty |
| 调拨(源仓) | stock_movement_transfer | decrement | currentQty / (currentQty - moveQty) |
| 调拨(目标仓) | — | — | 目标仓流水 Inbound 不单独写 AuditLog（源仓 AuditLog 已覆盖） |

> StockMovement 流水本身即为不可变审计记录，AuditLog 为补充操作日志。

## §14 关键边界条件

| 边界条件 | 处理 |
|---------|------|
| 盘点数量 = 当前数量（无差异） | 允许执行（balanceBefore = balanceAfter，流水记录无差异盘点） |
| 盘点数量 = 0 | 允许执行（清零，如报废/注销） |
| 调拨数量 = 0 | ⚠️ 前端校验 `!movementForm.quantity` 拒绝（必须 > 0） |
| 调拨到同仓库 | 前端过滤目标仓库下拉排除当前仓库 |
| 目标仓库已停用 | 后端校验 `!warehouse.isActive || warehouse.deletedAt` → throw |
| 源物料已软删 | 后端校验 `item.deletedAt` → throw |
