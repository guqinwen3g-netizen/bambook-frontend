## §2 模块定位与范围

### 2.1 在业务链路中的位置

```
立项 ── 来源(来样/色卡/自主) + 染色方式(散纤/色纱/匹染,可建议可手改)
   + 面料规格要求(成分/克重/幅宽/组织/后整理, 与 FabricProfile 同构) + 技术评审(可选动作)
        │
        ├── 开发供应商(关系智库列表多选; 报价/交期/试样结论 建案后渐进披露)
        │
        ▼
打样(统一样品批次模型, 每批归属工厂, 多选/并行/多批)
   ├── 色样批次 lab-dip ── 内嵌缸号/评级/疵点/照片/客户判定(色差扩展)
   ├── 手织样批次 handloom ── 组织/克重描述 + 寄样/反馈/轮次状态机
   └── 米样批次 yardage ── 同上
        │
        ▼
封样(独立实体, 同厂批次组合, 标准样信息, 可绑定客户, 可并存多个)
        │        └─ 检测(第三方测试挂接, 报告归档)
        ▼
产品档案 FabricProfile ←── 批次直接转 或 封样转(字段透传, 强制建档后转)
        │
        ▼
转大货订单 / 面料采购
```

### 2.2 模块边界

| 包含 | 不包含 |
|---|---|
| 面料开发案全链路（立项→技术评审→试样→封样→转档） | 成衣开发链（三级样衣 SampleNode / 双门禁 / 5A 评审——成衣既有，不共享本模型） |
| 开发供应商（多工厂试样） | 供应商/工厂档案本身（Relations 模块） |
| 统一样品批次（色样/手织样/米样） | 大货缸差（SampleColorBatch bulk 态——保留挂订单） |
| 封样组合（同厂）与标准样信息 | 色差评级评分联动（colorBatch 既有，色样批次复用其规则） |
| 批次/封样 → 面料档案 一键转档 | 报价单 / 大货订单本身（Quotation / Order 模块） |
| 检测挂接（开发案 ↔ 第三方测试） | 验货报告（InspectionReport 既有） |
| 设计确认样品（色样/手织样/米样 → 封样） | **生产确认样品（大货船样/匹头样/先锋样）——属 [样品管理域设计.md](./样品管理域设计.md)（DR-052）** |

## §3 核心概念与术语

| 概念 | 说明 |
|---|---|
| **染色方式 dyeMethod** | `top_fiber_dyed` 散纤染 / `yarn_dyed` 色纱织 / `piece_dyed` 匹染。**决定打样类型组合的推荐逻辑**：散纤/色纱通常 lab-dip 少、客户更认米样；匹染通常 lab-dip + 米样。可推荐默认值，**必须保留手动选择**（不绑定）。 |
| **开发供应商 DevelopmentSupplier** | 开发案 ↔ 工厂的多对多。同一开发案可丢给多个工厂分别试样。建案时从关系智库供应商档案**列表多选**（非单选）；试样报价/交期/结论**建案后在开发管理中渐进填入**（立项时不必填）。 |
| **样品批次 SampleBatch** | 统一样品批次模型，三种类型（色样/手织样/米样）一套概念与 UI。每批**归属工厂**，多选、并行、可多批。色样批次内嵌色差专业字段（缸号/评级/疵点/照片/客户判定）。 |
| **封样 SealSample** | 同厂批次组合而成的"标准样"实体：品质基准 + 标准样信息（编号/留底位置/品质说明）+ 可绑定客户（可选，内部标准样可不绑）。**只能组合同一工厂的批次**。一个开发案可并存多个封样，各自转成不同面料档案。 |
| **强制建档后转** | 面料开发确认后**必须先转面料档案**（ProductAsset + FabricProfile），档案是唯一出口，之后才允许转大货订单/进入采购。 |

## §4 业务规则（产品负责人拍板）

1. **样品类型不是固定三级管线**：色样/手织样/米样是**多选、可并行、各自独立确认**的样品任务集合，不是串行顺序，也不是卡死的三级。按染色方式与客户要求决定做哪几种、各做多少批。
2. **批次按工厂归属**：开发案的批次可分散在多个工厂（A 厂色样+手织样、B 厂米样……）。
3. **封样同厂组合**：封样只能组合**同一工厂**的批次（前端限制 + 后端强校验，跨厂组合拒绝）。
4. **多封样并存**：封样 A 来自工厂 A、封样 B 来自工厂 B 可同时存在，各自可转成**不同**产品档案。
5. **批次/封样双路径转档**：某一批次可直接转成产品档案，也可先组封样再转。一个开发案可产出多个产品档案。
6. **强制建档后转**：面料确认后先转 FabricProfile，再谈转大货/采购。
7. **开发案 = 产品档案的"草案前身"**：开发案从立项到技术评审、打样、封样的内容全部独立承载，字段与 FabricProfile 同构（成分/克重/幅宽/组织/后整理/染色方式），确认后一键转档（字段透传），转大货订单基于档案。
8. **技术评审为可选动作**：立项后可登记"技术评审"（可做/不可做/需调整 + 说明 + 评审人/日期）；结论为"不可做"的开发案进入搁置态；不做则不阻塞开发案推进。
9. **关联信息自动关联（2026-09-06 关联信息重设计）**：产品档案、发票等关联信息**不在表单手选**——产品档案在转档/转单时自动回填 `productAssetId`；发票在开发完成（封样）/终止后由财务从开发案开票（下一波）。表单唯一要填的是**开发属性**：内部开发（`source=internal`，挂需求方部门 `departmentId/departmentName`，同公司不同部门，与客户互斥）或客户关联开发（`source=customer-sample/customer-colorcard`，绑客户档案）。关联展示用统一"关联导航卡"（RelatedWorkspacesSection 范式）置于详情页底部。

## §5 数据模型

### 5.1 DevelopmentCase 扩展（type=fabric）

```prisma
// 设计真源：面料开发流程.md §5.1（DR-050）
// 面料开发案在既有 DevelopmentCase 上新增下列字段组（仅 type=fabric 时使用）：
//  ── 立项 ──
source        String? // customer-sample(客户来样) | customer-colorcard(客户色卡) | internal(内部开发)
dyeMethod     String? // top_fiber_dyed | yarn_dyed | piece_dyed
// 需求方部门（source=internal 内部开发：同公司不同部门提出需求，DR-005 内部部门场景；
// 与客户互斥——内部开发挂部门、客户关联开发挂客户）
departmentId     String?
departmentName   String?
//  ── 面料规格要求（与 FabricProfile 同构，开发初期档案未建时先行承载） ──
specComposition String? // 成分要求
specWeight      String? // 克重要求
specWidth       String? // 幅宽要求
specWeave       String? // 组织要求
specFinish      String? // 后整理要求
targetPrice     Decimal? // 目标价
moqEstimate     Float?  // MOQ 预估
//  ── 技术评审（可选动作） ──
techReviewStatus String? // null(未评审) | pass(可做) | adjust(需调整) | reject(不可做)
techReviewNote   String?
techReviewAt     String? // YYYY-MM-DD
techReviewBy     String?
```

> 面料规格要求字段组与 `FabricProfile`（construction/yarnCount/pattern/weightValue/widthValue…）语义对齐，转档时透传映射。面料开发案**不再复用**成衣专用字段（styleSpec/sizeSpec/fabricSpec/processSpec 仅 type=garment 使用）。

### 5.2 DevelopmentSupplier（开发供应商，新增）

```prisma
/// 设计真源：面料开发流程.md §5.2（DR-050）
/// 开发案 ↔ 工厂 多对多。建案时从关系智库供应商档案列表多选；
/// 试样报价/交期/结论为渐进披露字段，立项时不强制。
model DevelopmentSupplier {
  id               String  @id
  developmentCaseId String
  supplierRelationId String
  supplierName     String? // 名称快照

  // 渐进披露（建案后推进中填写）
  quoteNote        String? // 试样报价/报价说明
  leadTime         String? // 试样交期
  trialConclusion  String? // null(进行中) | ok(试样通过) | fail(试样失败)
  notes            String?

  createdAt BigInt
  updatedAt BigInt
  deletedAt BigInt?

  @@unique([developmentCaseId, supplierRelationId])
  @@index([developmentCaseId])
  @@index([supplierRelationId])
}
```

### 5.3 SampleBatch（统一样品批次，新增）

```prisma
/// 设计真源：面料开发流程.md §5.3（DR-050）
/// 统一样品批次：色样 lab-dip / 手织样 handloom / 米样 yardage 一套概念。
/// 每批归属工厂（supplierRelationId）；色样批次内嵌色差扩展字段（与 colorBatch 语义对齐）。
/// 状态机：pending → making → sent → approved / revising(→making, round+1)
model SampleBatch {
  id        String  @id // 格式：SB__${shortId}
  batchCode String  @unique // 业务号：SB-YYYYMMDD-001

  developmentCaseId String
  supplierRelationId String // 归属工厂（必填）
  supplierName       String? // 快照
  sampleType         String // lab-dip | handloom | yardage
  specNote           String? // 描述（色号/组织/克重/颜色等）
  round              Int     @default(1)

  // ── 通用状态机 + 寄样/反馈/批准 ──
  status            String  @default("pending") // pending | making | sent | approved | revising
  sentDate          String?
  courier           String?
  trackingNumber    String?
  shippingFee       Float?
  feedback          String?
  feedbackDate      String?
  approvedAt        BigInt?
  approvedBy        String?

  // ── lab-dip 色差扩展（sampleType=lab-dip 时使用，语义对齐 SampleColorBatch） ──
  dyeLotNo           String? // 缸号
  colorRating        Int?    // 主评级 1-5
  sideDiff           Int?
  endDiff            Int?
  defectCauses       String[] @default([]) // red_cast | blue_cast | lighter | darker
  customerStatus     String? // null(未判定) | approved | rejected | needs_recast
  approvedAsSealed   Boolean @default(false) // 批色通过即封样基准
  customerFeedbackNote String?
  customerFeedbackDate String?
  photos             Json? // [{name,url,uploadedAt}]

  // ── 检测挂接（第三方测试） ──
  testRequestId      String? // 开发案/批次 ↔ QC 第三方测试

  notes String?
  createdAt BigInt
  updatedAt BigInt
  deletedAt BigInt?

  @@index([developmentCaseId])
  @@index([supplierRelationId])
  @@index([sampleType])
  @@index([status])
}
```

### 5.4 SealSample（封样）+ SealSampleBatch（组合表，新增）

```prisma
/// 设计真源：面料开发流程.md §5.4（DR-050）
/// 封样 = 同厂批次组合的标准样实体。品质基准 + 标准样信息 + 可绑定客户。
/// 状态机：draft(草稿) → sealed(已封样) → converted(已转档)；sealed 为可并存的稳定态。
model SealSample {
  id             String  @id // 格式：SEAL__${shortId}
  sealCode       String  @unique // 业务号：SEAL-YYYYMMDD-001

  developmentCaseId String
  supplierRelationId String // 归属工厂（组合同厂强校验）
  name             String? // 封样名称/标准样名

  // 标准样信息
  standardNo     String? // 标准样编号（如客户确认色卡号）
  retainLocation String? // 留底位置
  qualityNote    String? // 品质说明

  // 可选绑定客户（内部标准样可不绑）
  customerRelationId String?
  customerName       String?

  status              String @default("draft") // draft | sealed | converted
  convertedProductAssetId String? // 转档回填
  convertedAt         BigInt?

  notes String?
  createdAt BigInt
  updatedAt BigInt
  deletedAt BigInt?

  @@index([developmentCaseId])
  @@index([supplierRelationId])
}

/// 封样批次组合：SealSample ↔ SampleBatch 多对多
model SealSampleBatch {
  id           String @id
  sealSampleId String
  sampleBatchId String

  @@unique([sealSampleId, sampleBatchId])
  @@index([sampleBatchId])
}
```

### 5.5 转档服务（新增）

`POST /api/v1/development/:id/convert-to-asset`：

- 入参：`sourceType: batch | seal` + `sourceId`（批次或封样）
- 动作（事务内）：创建 `ProductAsset`（mainCategory=Fabric）+ `FabricProfile`，字段透传映射（specComposition→composition、specWeight→weightValue、specWidth→widthValue、specWeave→construction、specFinish→specialNote、dyeMethod 透传、目标价/MOQ 预填）→ 回填开发案/批次/封样的 `productAssetId` → 写审计
- **强制建档后转**：面料开发案 `convert`（转大货订单）时校验 `productAssetId` 非空，否则拒绝（错误码 `ASSET_REQUIRED`）

### 5.6 与既有模型的关系

| 既有模型 | 处置 |
|---|---|
| `SampleColorBatch`（colorBatch） | **退守 bulk（大货缸差）**：只挂 Order。lab-dip 开发侧并入统一 SampleBatch（色差字段内嵌）。迁移策略见 §11 待细化项 |
| `SampleNode`（成衣三级） | 不变，仅成衣系使用 |
| `garmentSampleGateService`（成衣双门禁） | 不变，仅成衣系使用 |
| `DevelopmentCase.stage`（面料） | 面料链**简化**：并行批次下无单一"寄样/反馈"时点，case 阶段定位为 `developing`（开发中）→ `approved`（已确认=有封样转档）→ `cancelled`（终态），中间粒度全部由批次/封样承载（见 §6.2，待细化确认） |

## §6 状态机

### 6.1 SampleBatch 状态机

```
pending ──start──▶ making ──send──▶ sent ──approve──▶ approved (终态)
                       │               │
                       └──revise───────┴──▶ revising ──start──▶ making (round+1)
```

与成衣 SampleNode 同一动作语义（start/send/approve/revise）；lab-dip 型批次客户判定（approved/rejected/needs_recast）作为色差扩展单独登记（对齐 colorBatch 语义）。

### 6.2 SealSample 状态机 + case 阶段联动（设计建议，待细化）

```
draft ──seal──▶ sealed ──convert──▶ converted (终态)
  │                │
  └──────delete────┘   (draft/sealed 可软删；converted 不可删)
```

联动建议：面料开发案任一封样 `converted` 转档成功 → 开发案提示可推进 `approved`；所有关联批次/封样已转档后 case 进入 `approved`。**实现层联动细节（自动 vs 手动确认）待细化**（对齐 §14 既有缺口：三级节点与 case.stage 自动联动未实现，面料链应一并解决）。

## §8 前端设计

### 8.1 新建表单（面料类型）

- 新增区块"立项信息"：开发来源（来样/色卡/自主）、染色方式（三选一，按类型给推荐默认但可手改）、面料规格要求（成分/克重/幅宽/组织/后整理）
- **供应商改列表多选**：从关系智库供应商档案多选（现有客户/供应商单选下拉扩展为多选列表）；目标价 / MOQ 预估选填

### 8.2 详情页（面料类型）

- **开发供应商区块**：工厂卡片列表（每厂：报价/交期/试样结论，渐进披露编辑）
- **样品批次面板**（统一三类型，替代现有 SampleColorBatchPanel 的 lab-dip 固定态）：批次列表按工厂分组或筛选，类型标签（色样/手织样/米样）+ 状态徽章 + 轮次 + 寄样/反馈/批准；色样批次内嵌缸号/评级/疵点/客户判定
- **封样面板**：封样列表（名称/标准样编号/来源工厂/组合批次/状态/已转档案）；新建封样时批次选择**只显示当前所选工厂的批次**（同厂约束 UI）
- **检测入口**：批次行内"送检"→ QC 第三方测试挂接；报告归档回显
- **转档/转单**：封样或批次「转为面料档案」按钮（字段透传预览）；档案已建后「转大货订单」启用；未建档时转单入口禁用并提示"先建档案"
