## §2 流程总览

### 2.1 双模式架构

```
                    ┌──────────────────────────────────┐
                    │  POST /api/v1/development/:id/convert │
                    └──────────────┬───────────────────┘
                                   │
                    ┌──────────────▼───────────────────┐
                    │  判断 mode                        │
                    │  wantAutoCreate = autoCreate ||   │
                    │    (!orderId && !orderPo)         │
                    └──────┬───────────────┬───────────┘
                           │               │
              ┌────────────▼──┐    ┌───────▼──────────┐
              │ link 模式     │    │ autoCreate 模式   │
              │ 关联现有订单  │    │ 自动创建新订单    │
              └───────────────┘    └──────────────────┘
                           │               │
                    ┌──────▼───────────────▼───────────┐
                    │  prisma.$transaction 事务闭环     │
                    │  ① 创建/校验 Order                │
                    │  ② 更新 DevelopmentCase           │
                    │  ③ syncEntityReferences           │
                    │  ④ writeRouteAuditLog             │
                    └──────────────────────────────────┘
```

### 2.2 触发入口

| 入口 | 模式 | 调用方 |
|------|------|--------|
| 详情页「一键转为大货订单」按钮 | autoCreate | 前端 `developmentService.convertToOrder(id, { autoCreate: true })` |
| API `POST /:id/convert` 传入 orderId/orderPo | link | 外部 API / Agent |
| API `POST /:id/convert` 传入 autoCreate:true 或不传 orderId | autoCreate | 外部 API / Agent |
| Agent `development.convert` flow | 两种均可 | Agent loop |

## §5 幂等保护

### 5.1 业务层幂等

`existing.linkedOrderId` 已存在 → 直接返回 `ALREADY_CONVERTED` 错误，携带 `existingOrderId`。

**效果**：同一开发案例不可重复转单。前端详情页据此隐藏转单按钮，改为显示「已转订单」提示。

### 5.2 事务原子性

所有操作在 `prisma.$transaction` 内：
- 创建 Order（autoCreate 模式）
- 创建 OrderLine（autoCreate 模式，有产品时）
- 更新 DevCase（linkedOrderId / stage / convertedAt）
- `syncOrderEntityReferences`（EntityLink 图谱同步）
- `syncDevelopmentCaseReferences`（EntityLink 图谱同步）
- `writeRouteAuditLog`（审计日志）

**fail closed**：任一步骤失败 → 整个事务回滚，DevCase 不变。

### 5.3 ID 生成策略

autoCreate 模式的 ID 生成含时间戳（`Date.now()`），确保不冲突：
- Order ID: `ORD-FROMDEV-${existing.code}-${baseTs}`
- Order PO: `PO-${existing.code}-${baseTs}`

## §6 事务闭环详解

### 6.1 事务步骤（autoCreate 模式）

```
prisma.$transaction(async (tx) => {
  ① tx.order.create({ ... })                    // 创建订单
  ② tx.orderLine.create({ ... })                // 创建首行（有产品时）
  ③ tx.developmentCase.update({ ... })          // 更新 DevCase
  ④ syncOrderEntityReferences(prisma, order, …) // Order EntityLink 同步
  ⑤ syncDevelopmentCaseReferences(prisma, doc, …) // DevCase EntityLink 同步
  ⑥ writeRouteAuditLog({ ... })                 // 审计日志
  return { doc, createdOrder };
})
```

### 6.2 事务步骤（link 模式）

```
prisma.$transaction(async (tx) => {
  ① tx.order.findUnique({ where: { id: finalOrderId } })  // 查关联订单
  ② tx.developmentCase.update({ ... })                     // 更新 DevCase
  ③ syncOrderEntityReferences(prisma, linkedOrder, …)      // Order EntityLink 同步
  ④ syncDevelopmentCaseReferences(prisma, doc, …)          // DevCase EntityLink 同步
  ⑤ writeRouteAuditLog({ ... })                            // 审计日志
  return { doc, createdOrder: null };
})
```

### 6.3 审计日志内容

```typescript
{
  source: 'dev:convert',
  operation: 'convert_dev_case',
  targetType: 'DevelopmentCase',
  targetId: doc.id,
  before: { stage: existing.stage, linkedOrderId: null },
  after: { stage: 'approved', linkedOrderId: finalOrderId, orderId: finalOrderId, autoCreated: wantAutoCreate },
}
```

## §7 API 端点

### 7.1 端点定义

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/development/:id/convert` | 转订单（双模式） |

### 7.2 请求体

**autoCreate 模式**：
```json
{
  "autoCreate": true,
  "orderPo": "PO-DEV-2026-001-optional",
  "customer": "可选覆盖",
  "millName": "可选覆盖",
  "dueDate": "2026-12-31",
  "productName": "可选覆盖",
  "quantity": 1000
}
```

**link 模式**：
```json
{
  "orderId": "ORD-EXISTING-001",
  "orderPo": "PO-EXISTING-001"
}
```

### 7.3 响应体

```json
{
  "ok": true,
  "case": { /* 更新后的 DevelopmentCase */ },
  "order": { /* autoCreate 模式返回新订单；link 模式返回 null */ }
}
```

### 7.4 权限

`requireRole('owner', 'admin', 'manager')` — 仅高风险角色可转单。

### 8.1 共用 service 契约

Agent `development.convert` flow 与 route 共用 `convertDevCaseToOrder()` service（[developmentConvertFlow.ts](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/agent/developmentConvertFlow.ts)）。

### 8.2 Agent 调用路径

```
Agent loop
  → toolDispatchRegistry → developmentConvertFlow
  → convertDevCaseToOrder({ prisma, caseId, mode, ... })
  → 返回 DevConvertResult
```

## §9 EntityLink 同步

### 9.1 同步函数

| 函数 | 作用 | 代码真源 |
|------|------|---------|
| `syncOrderEntityReferences` | 同步 Order 的 EntityLink（customer/mill/product 关联） | `entities/sync.ts` |
| `syncDevelopmentCaseReferences` | 同步 DevCase 的 EntityLink（customer/supplier/product 关联） | `entities/sync.ts` |

### 9.2 关联类型

转单后建立/更新的 EntityLink 关联：
- Order ↔ Customer Relation（customerRelationId）
- Order ↔ Supplier Relation（millRelationId / supplierRelationId）
- Order ↔ Product Asset（productAssetId）
- DevCase ↔ Order（通过 linkedOrderId 快照）
- DevCase ↔ Customer/Supplier/Product（原有关联更新）

## §10 状态机衔接

### 10.1 DevCase 状态变化

转单强制将 DevCase.stage 推进到 `approved`（终态），无论原 stage 是什么（除 cancelled 外）。

```
developing/shipping/feedback/revision ──convert──▶ approved (终态)
```

### 10.2 Order 状态

autoCreate 模式创建的 Order 初始状态为 `Pending`，后续通过订单状态机推进（Pending → Confirmed → Production → Shipping → Delivered）。

### 10.3 后续联动（L6 事件）

Order 后续被确认（OrderConfirmed 事件）→ 触发 L6 联动自动生成 BOM 草稿（[L6CreateBOMDraft.ts](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/events/linkages/L6CreateBOMDraft.ts)）。
