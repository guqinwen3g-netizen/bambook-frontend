# 样品 · 开发 · 费用 · 开票 全局综合设计（DR-054）

> **状态**：设计稿 v1（2026-09-08，产品负责人逐条确认）
> **性质**：全局有机设计，取代 DR-052/DR-053 中与本品冲突的部分；以"全局对象归位、不重复、不冲突、可贯通"为原则，与本仓库既有的库存/财务/单据中心/数字档案体系双向比对后形成。
> **技术负责人**：开发侧实施由技术把控；本文档为实施唯一真源。

---

## 0. 设计原则（本轮共识）

1. **每个业务事实只有一个真源**，其余域通过引用/事件消费它，不复制。
2. **对象按责任归位，不按域分家**：样品=实物账，库存=可消耗商品仓，开票=财务域，单据中心=文件枢纽。
3. **开票永远归财务域**；开发域/样品域只记录"费用事实"，不出现开票动作。
4. **能复用现状就复用**；与本品冲突的现状积极修改；现状缺失的按设计补齐。
5. 全部走既有机制：EntityLink 互链、业务事件总线、快照外键、统一取号、审计、软删。

## 1. 全局对象归位总览

```
【商品主数据】ProductAsset（唯一档案 SKU 全局唯一）
     ↑ 订单行/报价行/采购/库存/BOM/样品 全部引用

【开发域 = 活动与流程】   （新建/改造）
    开发案（面料/成衣分域流程）
      └─ 打样批次（活动：哪家厂/第几轮/寄样反馈）
            → 确认 → 封样 → 转档案（转 ProductAsset）
            └─ ★费用登记（常驻入口，随时补：每件成本+邮寄费）

【样品域 = 实物账】       （改造既有 Sample + SampleCardItem）
    业务身份 Sample（哪个开发案/订单、类型、确认/封样双 tag、成本与邮寄费）
    实物账 SampleCardItem（数量/架位/二维码/借还/盘点/低库存 —— 已有能力保留）
      ├─ 寄出 = 扣减数量 + 归档（新建语义）
      ├─ 借出/看样 = 可还流水（已有）
      └─ 关联：点击条目 ↔ 开发案/订单/档案/样品详情

【库存域 = 可消耗商品仓储】（现状保留，不改）
    建仓库 → 大货/采购入库 → 出库（寄出/领用）
    ★样品不在库存域；样品只能借/寄，不参与销售库存

【开票 = 统一财务入口】   （新建场景化开票）
    场景：开发费用 / 大货货款 / 样品及邮寄 / 面料开发&大货
    → 自动带出源数据（开发案费用行/订单行批次/样品费用）→ 勾选 → 生成
    PI（确认未回款）先，CI（实际收款）后
    收付款核销仍在财务 PaymentVoucher

【单据中心 = 文件枢纽】（现状保留）
    PL/BL/CO… 生成/PDF/留档/交单；商业发票回链财务真源
```

## 2. 关键对象模型（技术落点）

### 2.1 样品：业务身份 `Sample`（改造）

- **与现状的关键修正**：把 `Sample.status` 从"单状态机"改为**双 tag 独立维度**：
  - `confirmedStatus`：设计结果认可（同一批次两件可都确认）——**不绑定实物**
  - `sealedStatus`：物理封样基准（同一批两件只一件封样）——**绑定具体实物**
  - `type` 保留（dev/seal/pp/top/ship/head/pioneer）仅作展示归类
- 归属字段保留：`sourceCaseId`（开发样）/`sourceOrderId`（大货样）——**双向可点**
- 费用字段收敛：`Sample.shippingFee`/`Sample.cost` 从"散落字段"**迁入统一成本记录簿**（见 2.3），Sample 只保留展示冗余
- `Sample.invoiceId` 作废（开票收归财务，见 2.4）

### 2.2 样品：实物账 `SampleCardItem`（改造）

- **保留现状全部能力**：数量/架位/二维码/借还/盘点/低库存（sampleRoomService）
- **新建"寄出出样"语义**：新增出样类型（区别于 `borrow`/`viewing`）——寄出=扣减 `availableQty` + 终态归档
- 与 `Sample` 保持软关联（现状已有 `sampleId`）；面料"一款多形态(卡/米/色样)"在 quantity/unit 上表达

### 2.3 费用：统一成本记录簿（新建，收敛散落费用）

- **落点**：`CostRecord`（费用发生层）+ `BillingItem`（收费决定层）——**DR-053 已建，保留并收敛**
- **sourceType 支持**：`Sample`/`SampleBatch`/`SealSample`/`DevelopmentCase`/`OrderLine`（现状已支持）
- **开发域常驻费用登记入口**：开发详情页（或批次/样品详情）提供"登记费用"入口，随时补每件样品成本 + 邮寄费，不卡状态机
- 散落字段收敛：`DevelopmentCase.sampleShippingFee`/`SampleBatch.shippingFee`/`Sample.shippingFee` 降级为"历史快照"，新建费用统一走 CostRecord

### 2.4 开票：场景化统一入口（新建）

- **落点**：`FinanceManager` 新增"按场景开票"入口（场景：开发费/大货/样品及邮寄/面料开发&大货）
- **数据源自动带出**：
  - 开发费场景 → 开发案下已登记 CostRecord（样品费/开发费/邮寄费）汇总 + 手工补
  - 样品场景 → 样品 Sample 的费用 + 邮寄费
  - 大货场景 → 订单行/批次
- **生成**：复用 `Invoice`（sourceType='BillingItem' 或新增 `DevelopmentCase`）+ `InvoiceOrderAllocation`
- **PI/CI 区分**：开发费/样品费通常直接 CI；外贸确认走 Quotation→PI→Receivable（现状已有）
- **样品域移除开票按钮与费用四层面板**（SampleManager 拆除），只保留"已关联发票跳财务"

### 2.5 单据中心（保留现状）

- `TradeDocument` 文件枢纽，商业发票回链 `sourceInvoiceId`
- 不新增样品/开发费发票类型（开票在财务域）

## 3. 与现状的比对结论（复用/修改/新建清单）

| # | 现状 | 处理 |
|---|---|---|
| 1 | `SampleBatch`+`SealSample`+`SampleNode`+`GarmentSampleRound`+`FabricShipmentSample`+`EarlyProductionSample` 六对象并列 | **收敛**：以 `Sample`（业务身份）+ `SampleBatch`（开发活动）+ `SampleCardItem`（实物账）三件套替代；`SampleNode`/`GarmentSampleRound` 迁出，`ship/head/pioneer` 类型补实际创建路径 |
| 2 | `Sample.status` 把 confirmed/sealed 塞一个字段 | **修改**：拆双 tag |
| 3 | 样品页开票按钮 + 费用四层面板 | **拆除**（收归财务） |
| 4 | 费用散落三处 shippingFee | **收敛**到 CostRecord + 开发域费用入口 |
| 5 | `SampleCardItem` 无"寄出出样" | **新建** |
| 6 | `FinanceManager` 无场景化开票 | **新建** |
| 7 | 开发案无直接开票链路 | **新建** |
| 8 | `InventoryItem` 样品不入库 | **保留**（已符合） |
| 9 | 单据中心回链财务 | **保留**（已符合） |
| 10 | `Invoice.sourceType/sourceId` 幂等 + Quotation→PI 原型 | **复用**为场景化开票底座 |
