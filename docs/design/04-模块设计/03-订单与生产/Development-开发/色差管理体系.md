## §2 模块定位与范围

### 2.1 在业务链路中的位置

```
开发打色阶段（lab_dip）                     大货阶段（bulk）
┌─────────────────────────┐               ┌─────────────────────────┐
│ DevelopmentCase (lab-dip)│               │ Order（面料/成衣大货）     │
│   ↓ 打色 3 缸            │               │   ↓ 染厂分缸生产          │
│ SampleColorBatch ×N      │               │ SampleColorBatch ×N      │
│   （缸号/评级/疵点/照片）  │               │  （缸号/缸差评级/照片）    │
│   ↓ 客户批色             │               │   ↓ 客户投诉缸差          │
│ approved → 封样基准留档   │               │ 一键取证导出（3min SLA）  │
│   ↓                     │               └─────────────────────────┘
│ 疵点原因 → 供应商质量分    │
└─────────────────────────┘
```

| 包含 | 不包含 |
|------|--------|

## §3 核心概念与术语

| 概念 | 说明 |
|------|------|
| **缸号 dyeLotNo** | 染厂染色缸次编号（一缸一色一批）；同一订单多缸生产是缸差根源 |
| **色差评级（4-5 级制）** | `colorRating` 主评级 1-5：5=与标样一致 / 4=轻微差异可接受 / 3=明显差异需评估 / 2=严重偏离 / 1=完全不符。`sideDiff` 左右色差、`endDiff` 前后色差（同缸内均匀性） |
| **疵点原因 defectCauses** | 结构化枚举：`red_cast` 偏红 / `blue_cast` 偏蓝 / `lighter` 色浅 / `darker` 色深（多选）；替代自由文本，供供应商质量分趋势聚合 |
| **封样基准 approvedAsSealed** | 客户批色通过的缸号样本成为该颜色后续生产的比对基准（批色通过即封样留档） |
| **两态 stage** | `lab_dip`（开发打色，挂 DevelopmentCase）/ `bulk`（大货缸差，挂 Order） |

## §4 数据模型

### 4.1 SampleColorBatch（schema.prisma）

```prisma
/// 设计真源：色差管理体系.md §4（REQ2-01，IND-01 L0 → L3）
/// 业务语义：缸号级色差证据链。两态挂载：lab_dip 挂开发案（打色阶段），
/// bulk 挂订单（大货缸差）。批色通过即封样基准；疵点原因结构化入供应商质量分。
model SampleColorBatch {
  id        String  @id // 格式：SCB__${shortId}
  batchCode String  @unique // 业务号：SCB-YYYYMMDD-001

  // ─── 两态挂载（互斥：lab_dip 必填 developmentCaseId；bulk 必填 orderId） ───
  stage             String // lab_dip(开发打色) | bulk(大货缸差)
  developmentCaseId String? // 打色阶段挂开发案
  roundNo           Int? // 开发案轮次快照（登记时 DevelopmentCase.currentRound）
  orderId           String? // 大货阶段挂订单

  // ─── 缸号 / 批次 / 卷号（追溯三键，参考 FabricShipmentSample 范式） ───
  dyeLotNo String   // 缸号（染厂染色缸次）
  batchNo  String?  // 批次号
  rollNos  String[] @default([]) // 取样卷号

  // ─── 色差评级（4-5 级制） ───
  colorRating Int // 主评级 1-5（5=与标样一致…1=完全不符）
  sideDiff    Int? // 左右色差 1-5（null=未评）
  endDiff     Int? // 前后色差 1-5

  // ─── 疵点原因（结构化枚举，多选；供应商质量分趋势聚合维度） ───
  defectCauses String[] @default([]) // red_cast | blue_cast | lighter | darker

  // ─── 客户判定 / 封样衔接 ───
  customerStatus       String  @default("pending") // pending | approved | rejected | needs_recast
  approvedAsSealed     Boolean @default(false) // 批色通过即封样基准（同 case/order 同色仅一个基准）
  customerFeedbackNote String? // @db.Text
  customerFeedbackDate String?

  // ─── 供应商（染厂，质量分联动目标） ───
  supplierRelationId String?
  supplierName       String?

  photos Json? // 照片附件 [{name,url,uploadedAt}]（与既有 attachments Json 范式一致）
  notes  String?

  createdAt BigInt
  updatedAt BigInt
  deletedAt BigInt?

  @@index([developmentCaseId])
  @@index([orderId])
  @@index([supplierRelationId])
  @@index([dyeLotNo])
  @@index([stage])
}
```

### 4.2 模型决策记录

| 决策 | 理由 |
|---|---|
| 独立表而非复用 attachments JSON | 色差记录是可聚合事实数据（按供应商/疵点原因统计），JSON 无法索引查询；garmentSampleGate JSON 是服装双门禁专用结构，打色载体是开发案 lab-dip 场景 |
| 两态 stage 而非两张表 | 打色与大货缸差字段结构完全一致（缸号/评级/疵点/照片），仅挂载点不同；一张表简化取证聚合（按 case 或按 order 一次查询） |
| defectCauses String[] 枚举 | 疵点趋势聚合需要结构化维度（risk defect-trends 现按 defectSummary 分词——色差疵点改为精确枚举统计，不参与分词） |
| colorRating 1-5 Int | 行业 4-5 级制灰卡评级；Int 便于映射 FactoryEvaluation 0-100 分 |

## §5 API 设计

挂载：`/api/v1/color-batches`（samples 域路由文件内，读走 JWT/API-Key，写必须 JWT）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/v1/color-batches` | POST | 登记（stage + 挂载 ID + 缸号 + 评级；A5 场景必填仅 4 项 ≤2min） |
| `/api/v1/color-batches` | GET | 列表（`?developmentCaseId=` 或 `?orderId=`，必传其一） |
| `/api/v1/color-batches/:id` | PATCH | 更新（评级调整/卷号/照片/备注；customerStatus 走专用端点） |
| `/api/v1/color-batches/:id/customer-feedback` | POST | 客户判定 `{status: approved\|rejected\|needs_recast, note?}`；approved 时可 `{asSealed: true}`（唯一基准幂等切换） |
| `/api/v1/color-batches/:id` | DELETE | 软删 |
| `/api/v1/color-batches/evidence` | GET | 取证聚合（`?developmentCaseId=` 或 `?orderId=`）：缸号×批次×批色记录×封样基准一次成型 |

### 5.1 质量分联动（客户判定时自动追加）

`customerStatus` 变为 approved/rejected/needs_recast 时，若记录含 `supplierRelationId` 且其存在 FactoryProfile，则追加 `FactoryEvaluation(kind='inspection')`：

| colorRating | 映射分 |
|---|---|
| 5 | 95 |
| 4 | 85 |
| 3 | 70 |
| 2 | 50 |
| 1 | 30 |

评分 note 带结构化前缀 `色差评级{rating}级 疵点:{causes}`；sourceType='color_batch'，sourceId=batchId——供应商档案评分明细可溯源。同事务复用 factoryService 均值重算（append-only 真源）。

### 5.2 取证聚合（evidence）响应结构

```json
{
  "ok": true,
  "scope": { "developmentCaseId": "...", "caseCode": "DEV-2026-001", "customerName": "..." },
  "sealedBasis": { "batchCode": "SCB-...", "dyeLotNo": "缸A-102", "colorRating": 5, "photos": [...] },
  "batches": [
    { "batchCode": "SCB-...", "dyeLotNo": "缸A-101", "batchNo": "B1", "rollNos": ["R1"],
      "colorRating": 3, "sideDiff": 4, "endDiff": 3, "defectCauses": ["red_cast"],
      "customerStatus": "needs_recast", "photos": [...], "createdAt": ... }
  ],
  "summary": { "total": 3, "approved": 1, "rejected": 0, "needsRecast": 2, "defectCauseCount": { "red_cast": 2 } }
}
```

前端消费此结构一键打印（复用 printDocument 版式：标题=开发案/订单号，正文=批次明细表 + 封样基准 + 疵点统计）。

## §6 前端设计

### 6.1 打色登记（开发详情页 · SampleColorBatchPanel）

挂载 `DevelopmentManager` 详情（SampleNodesPanel 同级新面板"打色批次 Color Batches"）：

- 列表：缸号 / 评级徽章（5=success 4=info 3=warning 1-2=danger）/ 疵点原因 chips / 客户状态 / 封样基准星标
- 登记表单（A5 ≤2min 必填 4 项）：缸号 + 主评级（5 档点选）+ 疵点原因（chips 多选，可跳过）+ 挂载开发案自动带出；卷号/左右前后色差/照片/备注选填
- 客户判定：每行操作（通过/拒绝/重打），通过时勾选"设为封样基准"

### 6.2 大货缸差（订单详情 · 复用同一面板组件）

`SampleColorBatchPanel` 支持 `stage='bulk'` + `orderId` 模式挂订单详情（面料订单详情页"缸差记录"区）。登记表单同构（缸号+评级+疵点）。

### 6.3 取证导出

列表头部「导出色差证据链」按钮 → GET /evidence → printDocument 新窗口打印（PDF 留档/邮件附件）——3 分钟 SLA 的落点：选中开发案/订单 → 点导出 → 打印，全程 3 击。

## §7 交互流程

### 7.1 剧本 A 全链（打色 → 重打 → 批色）

1. 业务员登记 3 缸打色记录（3×30s ≈ 90s，含照片）
2. 客户反馈：2 号缸 OK → 业务员标记 approved + 设为封样基准；1/3 号偏红 → needs_recast（疵点原因 red_cast）
3. 系统自动：①2 号缸成为该 case 唯一封样基准 ②1/3 号缸各追加染厂 inspection 评分（评级 3 → 70 分，note 带疵点）③FactoryProfile.qualityScore 均值重算
4. 重打循环：新缸登记 → 客户批准 → 基准切换（旧基准自动取消 approvedAsSealed）

### 7.2 大货缸差投诉（3 分钟取证）

客户投诉 PO-2601007 缸差 → 订单详情"缸差记录"区 →「导出色差证据链」→ 打印窗呈现：全部缸号评级明细 + 大货封样基准 + 疵点原因统计 → 发客户。

## §9 验收场景（对应需求池 REQ2-01）

| 场景 | 步骤 | 预期 |
|---|---|---|
| A5 打色登记 ≤2min | 开发详情 → 打色批次 → 登记（缸号/评级/疵点/照片） | 必填 4 项 ≤2min 完成，列表即见 |
| 批色即封样 | 客户判定 approved + 设为基准 | 该 case 唯一基准（旧基准自动切换）；evidence.sealedBasis 命中 |
| 疵点入质量分 | needs_recast（评级 3，red_cast） | FactoryEvaluation 追加 70 分 inspection 记录，qualityScore 重算，note 溯源 SCB |
| 3 分钟取证 | 订单详情 → 导出证据链 → 打印 | 缸号×批次×批色×封样基准一次成型，≤3 击 |
| 幂等软删 | 删除已判定的批次 | 软删不回滚已发生的质量分记录（append-only），evidence 不再含该批次 |
