> **DR-051** · 2026-09-06 产品负责人拍板 · **设计真源 · 成衣链已实现（2026-09-07 首批落地）**
> **定位**：与面料开发链（DR-050）对齐口径的成衣开发完整业务链。**成衣开发管理只到"确认样/封样"为止**（设计确认）——产前样/大货样等生产确认样品由 [样品管理域设计.md](./样品管理域设计.md)（DR-052）承载。本设计在其上补齐：技术评审 / 多工厂试样 / 强制建档后转，并规划与面料的数据模型拆分。

## §3 业务规则（产品负责人拍板）

1. **多工厂试样（对等面料）**：同一成衣开发案可丢给多家工厂分别打样，各厂打样进度分别跟踪；最终确认的样衣决定大货厂（转单时指定）。
2. **强制建档后转（对等面料）**：成衣开发确认（封存）后**必须先转成衣档案（ProductAsset(Garment) + GarmentProfile）**，档案是唯一出口；未建档转大货被拦截（`ASSET_REQUIRED`，对齐面料）。
3. **技术评审（对等面料）**：立项可登记可选"技术评审"（可做/需调整/不可做 + 说明），不可做进入搁置态；不阻塞推进。
4. **开发管理收线到确认样/封样（DR-052 域分割）**：开发样 → 确认样（封样=设计确认终点）即开发管理结束；**产前样/大货样等生产确认样品由样品管理域承载**（三级样衣节点收缩，pp/top 移出；DR-008 产前样 QC+客户确认门禁保留在样品管理域，批准=开裁前置）。开发样与产前样可合并：开发管理的确认样在转档案后，由样品管理域按档案复刻出产前样。
5. **case 阶段保留单线 6 态**：developing→shipping→feedback→approved（成衣单线流程语义适配，不简化）。
6. **关联信息自动关联（DR-050 通用原则）**：产品/成衣档案、发票等不在表单手选，自动回填；开发类型=内部开发（部门）或客户关联开发（客户）。

## §4 数据模型

### 4.1 DevelopmentCase（type=garment/pp/trim）扩展（待拆分前现状 + 新增）

```prisma
// 成衣链（DR-051）在既有 DevelopmentCase 上：
//  已有：styleSpec / sizeSpec / fabricSpec / processSpec（成衣规格）、sampleCategory(5A)/reviewStatus、source/departmentId/departmentName（开发类型，已通用）
//  新增：
techReviewStatus String? // null(未评审) | pass(可做) | adjust(需调整) | reject(不可做)  —— 复用面料字段，注释改为通用
techReviewNote   String?
techReviewAt     String?
techReviewBy     String?
targetPrice      Decimal? // 目标价（面料已加，成衣通用）
```

> `techReview*` / `targetPrice` 从"面料专用"标注改为**两链通用**（schema 注释更新，无结构改动）。

### 4.2 多工厂（复用 DevelopmentSupplier）

`DevelopmentSupplier`（DR-050 已建，开发案↔工厂多对多，渐进披露报价/交期/试样结论）为**通用实体**，成衣开发案同样挂载（`developmentCaseId` 软引用）。成衣详情页复用 FabricDevSuppliersPanel 同款"试样工厂"区块。

### 4.3 样品归属工厂（设计决策点）

成衣多工厂打样的归属设计（**待细化**，三选一）：

| 方案 | 说明 | 取舍 |
|---|---|---|
| A. 轮次归属工厂 | DR-008 样品轮次 round 加 `supplierRelationId`（该轮由哪厂打样） | 改动小；同轮多厂需多行轮次，与顺序轮次语义冲突 |
| B. 节点归属工厂 | SampleNode（三级）加 `supplierRelationId` | 一级一行受 `@@unique(developmentCaseId, level)` 限制，多厂同款难表达 |
| C. 引入样品批次到成衣 | SampleBatch 通用化（confirmation/pp/top 作 sampleType），每批归属工厂，对层面料 | 最一致，但动成衣现有 SampleNode/DR-008 大结构，风险大 |

> **已拍板并实现（2026-09-07）**：方案 A——确认样节点（SampleNode）加 `supplierRelationId/supplierName`（开始打样时登记）；DR-008 产前样轮次（round JSON）加 `supplierRelationId/supplierName`（新建轮次时登记）。多厂并行以多轮次表达：A 厂第 1 轮、B 厂第 2 轮并行。若后续出现"同轮多厂同版对比"高频需求，再评估方案 C。

### 4.4 转档服务（新增，对层面料 convert-to-asset）

`POST /api/v1/development/:id/convert-to-asset`（sourceType: `seal` 封存的轮次 / `node` 确认样节点）：

- 创建 `ProductAsset(mainCategory='Garment')` + `GarmentProfile`，字段透传：`styleSpec→styleNo`、`fabricSpec→`、`sizeSpec→`、`processSpec→`、`name/productName→productName`
- 回填开发案 `productAssetId`（首个档案锚点）
- **强制建档后转**：成衣案 convert（转大货）校验 `productAssetId` 非空（`ASSET_REQUIRED`，对层面料）

### 4.5 数据模型拆分（成衣链设计定稿后做）

与面料链拆分一起规划（DR-050 §11 拍板：待成衣链设计定稿后一次做）：

- **目标**：`FabricDevelopmentCase` / `GarmentDevelopmentCase` 两个独立模型（表），消除两套字段互相污染
- **共享部分处置**：寄样字段（已下沉批次/节点级，case 级退役）、`nextAction`、`currentRound`、`source/department`、报价/发票/转单/审计/EntityLink 等通用能力
- **迁移**：现有 `DevelopmentCase` 数据按 `type` 分流到两个新表
- **暂缓**：此拆分为 v1.1 级大动作，成衣链功能先落现状表（复用字段），拆分时一并迁

## §5 状态机

- **case 阶段**：保留单线 6 态（developing→shipping→feedback→approved/cancelled），不简化
- **开发样/确认样（设计确认样品）**：draft→making→sent→confirmed→sealed（封样终态），revising（→making round+1）——由样品管理域 Sample(type=dev/seal) 承载（DR-052）
- **产前样/大货样（生产确认样品）**：draft→making→qc→submitted→confirmed→approved（批准=开裁前置）——样品管理域承载（DR-052）；DR-008 门禁语义保留
