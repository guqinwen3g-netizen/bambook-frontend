# 样品间管理 (Sample Room)

> **REQ2-16** · 痛度 22 · 来源 IND-05 L0 · 批次四 C 级
> **甲方场景**：样品间实体样卡（面料挂样/成衣样/色卡实物）登记贴二维码；业务员/客户借看登记，归还留痕；客户来样间看样记录挂客户档案。
> **验收标准**：IND-05——样卡二维码登记 / 借出归还 / 看样记录实体流程数字化。

## §2 关键设计决策（DR-057）

### DR-057-① 实体样卡与逻辑色卡分轨

- SampleCardItem = **实物**（样品间里贴着二维码的那张卡）：编号/类型/架位/在库状态
- ColorCard（REQ2-09）= **逻辑**色（Pantone 色号/RGB）；`colorCardCode` 可选关联——实体色卡登记时可带出逻辑色
- 不在 ColorCard 上加库存字段（逻辑/实物不混轨）

### DR-057-② 借出与看样统一 Loan 流水（append-only）

- 单一 SampleCardLoan 承载两类事件：`borrow`（内部借出，borrowerUserId+borrowerName）/ `viewing`（客户看样，relationId+relationName 快照）
- 状态机在样卡上：`in_stock → borrowed → in_stock`；`retired` 终态（报废/赠送，不可再借）
- 借出即唯一活跃 loan（在借再借 409 LOAN_ALREADY_ACTIVE）；归还落 returnedAt+conditionNote（损坏备注留痕），不改写历史行
- 逾期 = dueAt < now 且 returnedAt null（列表派生标记，不落状态字段——时间比较零漂移）

### DR-057-③ 二维码载荷 = 样卡编号（打印即扫码直达）

- 编号 `SC-YYYYMMDD-NNN`（当日递增，沿用 FactoryDelayRecord 编号惯例）
- 前端 qrcode 库生成 PNG 打印贴卡；扫码（任意扫码枪/手机）→ GET /room/items?code=SC-xxx 直达详情+借还操作
- 后端不生成图片（无 server 端 qrcode 依赖；编号即载荷，端到端可测）

### DR-057-④ 实物样卡 ↔ 统一样品对象（DR-052 §10#3 迁入对齐）

- **样品库存保留独立库存行**：数量/位置/借还/低库存继续由 SampleCardItem 承载，不并入 Sample
- `SampleCardItem.sampleId`（软关联 Sample.id，无 FK）建立样品归属——样品详情统一呈现库存，样品间登记样卡可搜索关联样品
- listItems 支持 `?sampleId=` 过滤，join 返回 `sampleCode/sampleType` 摘要；getItem 同

## §4 数据模型

```prisma
/// 设计真源：Development-开发/样品间管理.md §4（REQ2-16，IND-05）
model SampleCardItem {
  id            String   @id // 格式：SCI__${shortId}
  code          String   @unique // 样卡编号：SC-YYYYMMDD-NNN（二维码载荷）
  name          String // 样卡名称（面料名/色卡名/成衣款名）
  cardType      String   @default("fabric") // fabric | garment | colorcard | trim | other
  colorCardCode String? // 关联逻辑色卡 ColorCard.code（可选）
  location      String? // 样品间架位（自由文本）
  status        String   @default("in_stock") // in_stock | borrowed | retired
  notes         String?
  createdAt     BigInt
  updatedAt     BigInt
  deletedAt     BigInt?

  @@index([status])
  @@index([cardType])
}

/// 借还/看样流水（append-only：归还只补 returnedAt/conditionNote，不删不改历史）
model SampleCardLoan {
  id            String  @id // 格式：SCL__${shortId}
  itemId        String
  loanType      String // borrow（内部借出）| viewing（客户看样）
  borrowerName  String // 借用人/看样联系人
  borrowerUserId String? // borrow 时关联用户
  relationId    String? // viewing 时关联客户 Relation
  relationName  String? // 冗余快照
  loanedAt      BigInt
  dueAt         BigInt? // 预计归还（borrow 必填，viewing 可空）
  returnedAt    BigInt?
  conditionNote String? // 归还状态备注（损坏/缺失留痕）
  operatorId    String? // 登记人
  createdAt     BigInt

  @@index([itemId])
  @@index([loanType, returnedAt])
}
```

## §5 API 合约（挂 /api/v1/samples/room/*，samples 域同路由）

| 端点 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `/room/items` | POST | `{ name, cardType?, colorCardCode?, location?, notes?, sampleId? }` | `{ item }`（编号自动生成） |
| `/room/items` | GET | `?status=&cardType=&search=&code=&sampleId=` | `{ items, total }`（含 activeLoan 摘要与 overdue 派生标记） |
| `/room/items/:id` | GET | — | `{ item, loans[] }`（借还历史正序） |
| `/room/items/:id/retire` | POST | `{ note? }` | `{ item }`（retired 终态；在借不可退役 409） |
| `/room/items/:id/loans` | POST | `{ loanType, borrowerName, borrowerUserId?, relationId?, dueAt? }` | `{ loan, item }`（借出即 status→borrowed） |
| `/room/loans/:id/return` | POST | `{ conditionNote? }` | `{ loan, item }`（归还→in_stock） |
| `/room/loans` | GET | `?active=true&loanType=&overdue=true` | `{ loans }`（在借/逾期/历史） |

写权限：`sample:room:write`（矩阵新增，SALES_BASE 起步——业务员/主管/QC 均可借还登记；读登录即可，沿 colorCard 惯例）。
错误码：`VALIDATION_FAILED`(400) / `NOT_FOUND`(404) / `LOAN_ALREADY_ACTIVE`(409) / `ITEM_NOT_BORROWABLE`(409) / `ITEM_RETIRED`(409)。

## §6 验收锚点（scripts/acceptance-req2-16.mjs）

1. 登记两张样卡（编号递增 SC-YYYYMMDD-001/002；二维码载荷=编号）
2. 借出（dueAt 未来）→ item.status=borrowed；在借再借 409
3. 逾期借出（dueAt 过去）→ loans?overdue=true 命中；items 列表 overdue 标记
4. 归还（conditionNote 留痕）→ in_stock；历史行 append-only（returnedAt 补记不改内容）
5. 看样登记（relationId）→ loans loanType=viewing 挂客户；不占借出状态（viewing 即看即还）
6. 退役：在借退役 409；归还后退役成功且不可再借 409
7. 权限：无 sample:room:write → 403（如 finance）；搜索/筛选/按 code 直达
