## 二、到货登记流程

### 2.1 整体流程

```
PO Confirmed ──▶ 仓库收货登记 ──▶ QC 质检 ──▶ 入库 ──▶ PO 状态流转
                     │                │          │
                     ▼                ▼          ▼
               MaterialReceipt    合格/拒收   InventoryTransaction
               (Pending)          (Accepted/  (待补)
                                 Rejected/
                                 PartiallyAccepted)
```

### 2.2 收料前置校验

真源 [procurementService.ts createMaterialReceipt L629-L633](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/procurement/procurementService.ts#L629-L633)：

```typescript
if (existing.status !== 'Confirmed'
    && existing.status !== 'PartiallyReceived'
    && existing.status !== 'Received') {
  throw new Error(`仅 Confirmed/PartiallyReceived/Received 状态可收料`);
}
```

| PO 状态 | 可收料 | 说明 |
|---------|--------|------|
| Draft / Sent | ❌ | 未确认的 PO 不收料 |
| Confirmed | ✅ | 首次收料 |
| PartiallyReceived | ✅ | 继续收料 |
| Received | ✅ | 超收（已全部到货后补收） |
| Closed / Cancelled | ❌ | 终态不可收料 |

## 五、PO 状态自动流转

真源 [procurementService.ts L638-L648](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/procurement/procurementService.ts#L638-L648)：

```typescript
const totalOrdered = existing.lines.reduce((sum, l) => sum + Number(l.quantity), 0);
const totalPreviouslyReceived = existing.lines.reduce((sum, l) => sum + Number(l.receivedQuantity), 0);
const totalNowReceived = totalPreviouslyReceived + input.totalAccepted;

let newStatus;
if (totalNowReceived >= totalOrdered) {
  newStatus = 'Received';        // 全部收齐
} else {
  newStatus = 'PartiallyReceived'; // 部分到货
}
```

| 场景 | 累计合格数 vs 订单数 | 新 PO 状态 |
|------|---------------------|-----------|
| 首次部分收料 | 累计 < 订单数 | PartiallyReceived |
| 首次全部收齐 | 累计 ≥ 订单数 | Received |
| 后续补收 | 累计 < 订单数 | PartiallyReceived |
| 后续收齐 | 累计 ≥ 订单数 | Received |
| 超收 | 累计 > 订单数 | Received |

## 六、质检记录

### 6.1 质检流程

```
收货登记(Pending) ──▶ QC 检验(Inspected) ──▶ 判定(Accepted/Rejected/PartiallyAccepted)
```

当前实现为收货时一次性录入质检结果（totalAccepted/totalRejected），无独立"待检→已检"中间态流转。设计建议：

| 阶段 | 状态 | 操作人 | 说明 |
|------|------|--------|------|
| 收货登记 | Pending | warehouse | 仅录 totalReceived，质检字段空 |
| 质检进行 | Inspected | qc | 录入 totalAccepted/totalRejected |
| 判定 | Accepted/Rejected/PartiallyAccepted | 系统 | 自动判定 |

### 6.2 质检字段

| 字段 | 录入人 | 说明 |
|------|--------|------|
| inspectedBy | QC | 检验员 |
| inspectionDate | QC | 检验日期 |
| totalAccepted | QC | 合格数量 |
| totalRejected | QC | 拒收数量 |
| rejectionReason | QC | 拒收原因（拒收时必填） |
| qualityNotes | QC | 质量备注（疵点描述等） |

## 七、入库联动（待实现）

⚠️ **当前未实现**。MaterialReceipt 仅记录收料，未自动写入库存账本。以下为设计方案。

### 7.1 InventoryTransaction 模型（待建）

建议新增 `InventoryTransaction` 模型：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 主键 `IT_${shortId}` |
| transactionType | String | IN（入库）/ OUT（出库）/ ADJUST（调整） |
| materialCode | String? | 物料编码 |
| purchaseOrderId | String? | 关联采购单（入库来源） |
| materialReceiptId | String? | 关联收料记录 |
| warehouseId | String? | 仓库 |
| quantity | Decimal(18,4) | 数量（入库=正，出库=负） |
| unit | String | 单位 |
| balanceAfter | Decimal(18,4) | 库存余额（事务内重算） |
| createdAt | BigInt | 时间戳 |

### 7.2 自动入库联动设计

MaterialReceipt 创建后（status=Accepted/PartiallyAccepted）→ 自动创建 InventoryTransaction：

```
触发点：createMaterialReceipt 事务提交后
条件：totalAccepted > 0
动作：
  INSERT InventoryTransaction {
    transactionType: 'IN',
    materialCode: receipt.materialCode (待补行级关联),
    purchaseOrderId,
    materialReceiptId: receipt.id,
    warehouseId,
    quantity: totalAccepted,  // 仅合格数量入库
    unit,
    balanceAfter: 事务内重算,
  }
```

### 7.3 行级收货数量回写（待补）

当前 `createMaterialReceipt` 操作 PO 级汇总（totalOrdered/totalReceived），未回写 `PurchaseLine.receivedQuantity`。设计建议：

- 收料时按行录入（MaterialReceiptLine 子表，待建）
- 每行收料 → 累加 `PurchaseLine.receivedQuantity` / `rejectedQuantity`
- 行级全部收齐 → 该行标记完成

### H1c 交期自动评分

全部收齐（newStatus === 'Received'）且有关联供应商 → 自动追加交期评分（非阻塞）：

真源 [procurementService.ts L732-L759](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/procurement/procurementService.ts#L732-L759)：

```typescript
if (newStatus === 'Received' && existing.supplierRelationId) {
  const daysLate = (actualMs - expectedMs) / DAY;
  await factoryService.recordAutoEvaluation({
    relationId: existing.supplierRelationId,
    kind: 'delivery',
    score: deliveryScoreForDaysLate(daysLate),
    sourceType: 'purchaseOrder',
    sourceId: purchaseOrderId,
    note: `采购单 ${poNumber} 全部收齐，交期偏差 ${daysLate} 天`,
  });
}
```

- 幂等：同采购单只评一次
- 无档案供应商静默跳过
- daysLate = 实际收货日 - 预计交货日
