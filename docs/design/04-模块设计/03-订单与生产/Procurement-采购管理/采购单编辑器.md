# 采购单编辑器 (Purchase Order Editor)

> **2026-10-07 职责纠偏：** 采购、加工、库存与样品操作通常由对应业务组业务员办理，不设采购员、仓管员或样品管理员专岗。后勤主责为出运与单证；既有协作权限不代表仓储岗位。下文旧权限表、审批阈值和规划状态仅保留作历史线索，不据此新增岗位或扩充MVP。 当前规则见[角色与实际分工](../../../global/2026-10-06/05-roles-and-responsibilities.md)及[对话决策总账](../../../global/2026-10-06/08-2026-10-06-对话设计决策总账.md)。

### 4.4 行金额自动计算

真源 [procurementService.ts calcLineAmount](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/procurement/procurementService.ts#L118-L120)：

```typescript
function calcLineAmount(quantity, unitPrice): number {
  return Math.round(quantity * unitPrice * 10000) / 10000;  // 4 位小数精度
}
function calcTotalAmount(lines): number {
  return lines.reduce((sum, l) => sum + calcLineAmount(l.quantity, l.unitPrice), 0);
}
```

前端编辑时实时联动：数量/单价变化 → 行金额重算 → 总金额重算。

## 五、保存与发送

### 5.1 保存草稿（Draft）

`POST /api/v1/procurement`（创建）或 `PUT /api/v1/procurement/:id`（更新，仅 Draft）。

## 六、审批流设计（待实现）

⚠️ **当前未实现**。采购单创建后直接 Draft → Sent，无审批环节。以下为 PRD §9.2 设计方案。

### 6.1 审批分级规则

| 条件 | 审批级别 | 审批人 | 说明 |
|------|---------|--------|------|
| totalAmount ≤ 50,000（本位币 CNY 换算后） | Level 1 | 业务员（SM）+ 财务（FinMan）双签 | 常规金额双签 |
| totalAmount > 50,000 | Level 2 | 总监审批 | 大额单总监批 |
| 首单供应商（该 supplierRelationId 无历史 Confirmed+ PO） | +1 级 | 在原级别基础上加签 | 首次合作加严 |

**金额换算**：`totalAmount × exchangeRate` → 本位币 CNY，与 50,000 比较。

### 6.2 审批状态机扩展

当前状态机 `Draft → Sent` 之间插入审批环节：

```
Draft ──▶ PendingApproval ──▶ Sent ──▶ Confirmed ──▶ ...
              │
              ├─ Level1: SM签 → FinMan签 → Sent
              ├─ Level2: 总监签 → Sent
              └─ 首单+1级: 在原级别 + 附加审批人 → Sent
```

新增状态 `PendingApproval`（待审批）/ `Approved`（已审批）。

### 6.3 审批数据模型（待建）

建议新增 `PurchaseApproval` 模型：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 主键 |
| purchaseOrderId | String | FK |
| level | Int | 1 / 2 / 3（首单加签） |
| requiredRole | String | SM / FinMan / Director |
| approverId | String? | 审批人 |
| approvedAt | BigInt? | 审批时间 |
| status | String | Pending / Approved / Rejected |
| comment | String? | 审批意见 |

### 6.4 审批交互

| 交互 | 设计 |
|------|------|
| 触发审批 | 保存草稿后点"提交审批"→ 计算 level → 创建 N 条 PurchaseApproval（按级别） |
| 审批人视图 | 审批人的采购列表 tab 新增"待我审批" |
| 审批动作 | 通过/驳回 + 意见；全部通过 → 状态 Sent |
| 驳回 | 任一驳回 → 状态回退 Draft + 通知经办业务员 |
| 首单判定 | 查 PurchaseOrder where supplierRelationId + status in [Confirmed, PartiallyReceived, Received, Closed] count === 0 |

### 6.5 审批锁定

- PendingApproval 状态：采购单只读，禁止编辑
- 审批中行明细锁定，禁止修改数量/单价（防审批后篡改）
