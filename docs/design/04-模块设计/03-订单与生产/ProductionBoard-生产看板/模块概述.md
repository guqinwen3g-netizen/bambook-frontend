## 二、模块边界与职责

### 2.1 模块做什么

生产看板是"全部在手订单 × 10 阶段"的二维矩阵只读视图：

- **横向（列）= 10 个生产阶段**：从业务下单到验货发货的完整管线
- **纵向（卡片）= 每个在手订单**：按交期升序排列，倒计时颜色编码
- **聚合数据源**：后端 `getProductionBoard` 一次性查全部在手订单 + 各自 10 阶段状态，前端零散查询

### 2.2 模块不做什么（边界切割）

| 不做的事 | 由谁负责 |
|---------|---------|
| 阶段推进写入（advanceStage / signStage） | 订单详情页 ProductionPipeline 子组件 |
| 裁剪前检查清单填写 | 订单详情页 PreCutChecklist 区块 |
| 验货报告录入 | QC 工作台（qc-workbench） + 订单详情页 InspectionReport 区块 |
| 外协单创建/编辑 | 外协管理模块（OutsourcingOrder CRUD） |
| 订单字段编辑 | 订单详情页编辑模式 |
| 订单状态机推进 | 订单详情页 6 态步骤条 |

**设计原则**：看板是"看"的入口，不是"改"的场所。卡片点击 → 穿透到订单详情页执行写入操作，保持看板渲染纯净与加载性能。

## 三、10 阶段定义（核心业务模型）

阶段定义真源在 [stageService.ts](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/production/stageService.ts#L16-L27) `PRODUCTION_STAGES` 常量，前端 [ProductionBoard.tsx](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/components/ProductionBoard.tsx#L22-L33) `BOARD_STAGES` 镜像同一顺序与中文标签。

| Seq | Stage Key | 中文标签 | 门禁判据（advanceStage 强校验） |
|-----|-----------|---------|------------------------------|
| 1 | `order_placed` | 业务下单 | 创建订单即 `done`（initProductionStages 默认置 done） |
| 2 | `materials_confirmed` | 面辅料确认 | 无特殊门禁，前置阶段全 done 即可推进 |
| 3 | `production_planned` | 生产计划 | 无特殊门禁 |
| 4 | `in_production` | 货期管理 | 无特殊门禁（进入交期倒计时区间） |
| 5 | `materials_arrived` | 面辅料到厂 | 无特殊门禁（建议联动 PO.status=Received，当前手动确认） |
| 6 | `pre_cut_checked` | 裁剪前检查 | **PreCutChecklist 四项全 true**：推码确认 / 耗料确认 / 样板确认 / 产前会议 |
| 7 | `pp_sample_approved` | 产前样确认 | **双签**：signedByProduction + signedByBusiness 均非空 |
| 8 | `manufacturing` | 生产过程 | 无特殊门禁 |
| 9 | `final_review` | 成品确认 | 无特殊门禁 |
| 10 | `qc_shipped` | 验货发货 | **终期验货三条件**：InspectionReport(final).result≠fail + criticalDefects=0 + passRate≥90% + defectRate≤3% + approvedByBusiness=true |

**门禁错误码**（StageGateErrorCode）：`ORDER_NOT_FOUND` / `INVALID_STAGE` / `STAGE_NOT_SEQUENTIAL` / `PRECUT_CHECKLIST_INCOMPLETE` / `PP_SAMPLE_NOT_SIGNED` / `INSPECTION_NOT_QUALIFIED` / `BUSINESS_APPROVAL_REQUIRED` / `STAGE_UPDATE_FAILED`

## 五、数据模型概览

### 5.1 ProductionStage 模型（阶段状态行）

每订单 × 10 阶段 = 10 行；`id` 格式 `PST__${orderId}__${stageKey}`，`@@unique([orderId, stageKey])`。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 主键（格式化生成） |
| orderId | String | 关联订单 |
| stageKey | String | 阶段枚举（order_placed / ... / qc_shipped） |
| stageSeq | Int | 1-10 序号 |
| status | String | `pending` / `in_progress` / `done` / `blocked` |
| note / operator | String? | 备注 / 操作人 |
| startedAt / doneAt | BigInt? | 开始/完成时间戳 |
| signedByProduction / signedByBusiness | String? | 双签字段（pp_sample_approved 专用） |
| signedAtProduction / signedAtBusiness | BigInt? | 双签时间戳 |

### 5.2 关联模型

| 模型 | 用途 | 关键字段 |
|------|------|---------|
| `PreCutChecklist` | 阶段 6 门禁判据 | gradingConfirmed / consumptionConfirmed / patternConfirmed / preProductionMeeting 四布尔 |
| `InspectionReport` | 阶段 10 门禁判据 | inspectionType(final/midline) / result(pass/conditional/fail) / criticalDefects / passedUnits / totalUnits / approvedByBusiness |
| `OutsourcingOrder` | 外协只读区块 | orderNumber / supplierId / processType / status / quantity / qualityAcceptedQty / qualityRejectedQty |

## 七、看板聚合查询契约

### 7.1 在手口径

```typescript
// stageService.ts getProductionBoard
where: { deletedAt: null, status: { notIn: ['Delivered', 'Cancelled'] } }
orderBy: { dueDate: 'asc' }
take: 500
```

**包含**：Pending / Confirmed / Production / Shipping / Alert（异常单——跟单员最需看见）
**排除**：Delivered（已交付）/ Cancelled（已取消）/ 软删除

### 7.2 自愈回填机制

历史种子/直写库订单可能未经 `initProductionStages` 初始化，缺 10 阶段行会导致泳道空白。看板聚合时检测缺失并幂等回填：

```
1. 查全部订单 stages
2. 找出 missing（orderIds 中无任何 stage 行的）
3. 对每个 missing 调 initProductionStages（upsert + update:{} 幂等）
4. 重查一次 stages
```

### 7.3 卡片归属列规则

- 有 `currentStageKey`（第一个非 done 阶段）→ 归该列
- 全部 done → 归最后一列 `qc_shipped`
- 无阶段记录 → 归第一列 `order_placed`（自愈回填后不会出现）

## 十三、性能考量

| 项 | 说明 |
|----|------|
| 一次性聚合 | 后端 `getProductionBoard` 单次查 500 订单 + 各自 10 阶段，避免前端 N+1 |
| 自愈回填惰性 | 仅对 missing 订单触发，正常情况下零开销 |
| take: 500 上限 | 防止超大数据集拖垮首屏；超 500 单需分批或按交期分页（待补） |
| 前端筛选纯内存 | search/overdueOnly/blockedOnly 不触发后端请求，`useMemo` 重算 |
