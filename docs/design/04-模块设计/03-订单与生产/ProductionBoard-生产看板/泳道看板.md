## 三、10 阶段定义（列模型）

阶段定义真源 [stageService.ts PRODUCTION_STAGES](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/production/stageService.ts#L16-L27)，前端 [ProductionBoard.tsx BOARD_STAGES](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/components/ProductionBoard.tsx#L22-L33) 镜像。

| Seq | Stage Key | 中文标签 | 门禁判据 |
|-----|-----------|---------|---------|
| 1 | `order_placed` | 业务下单 | 创建订单即 done |
| 2 | `materials_confirmed` | 面辅料确认 | 前置全 done |
| 3 | `production_planned` | 生产计划 | 前置全 done |
| 4 | `in_production` | 货期管理 | 前置全 done |
| 5 | `materials_arrived` | 面辅料到厂 | 前置全 done |
| 6 | `pre_cut_checked` | 裁剪前检查 | **PreCutChecklist 四项全 true**（推码/耗料/样板/产前会议） |
| 7 | `pp_sample_approved` | 产前样确认 | **双签**（signedByProduction + signedByBusiness） |
| 8 | `manufacturing` | 生产过程 | 前置全 done |
| 9 | `final_review` | 成品确认 | 前置全 done |
| 10 | `qc_shipped` | 验货发货 | **终期验货**：result≠fail + criticalDefects=0 + passRate≥90% + defectRate≤3% + approvedByBusiness |

**顺序校验铁律**：`advanceStage` 在事务内查 `stageSeq < current.stageSeq` 的所有前序阶段，任一非 done 即抛 `STAGE_NOT_SEQUENTIAL`。看板列顺序与 stageSeq 严格一致，禁止跳列。

## 四、卡片设计

### 4.1 卡片结构

```
┌───────────────────────────────────┐
│ PE25-1234              [⚠ 阻塞]   │  ← PO号/订单ID + 阻塞红标
│ Peerless客户名                    │  ← 客户（truncate）
│ 1,200 件/米 · 面料 · 跟单员张三   │  ← 数量 + 业务线 + 跟单
│ 张家港一厂        [剩 5 天]       │  ← 工厂 + 交期倒计时chip
└───────────────────────────────────┘
```

### 4.2 卡片字段映射

| UI 元素 | 数据字段 | 说明 |
|---------|---------|------|
| 主标题 | `order.poNumber \|\| order.id` | PO 号优先，无则用 ID |
| 阻塞标 | `item.blockedCount > 0` | AlertTriangle + "阻塞" danger chip |
| 客户 | `order.customer` | truncate 单行 |
| 数量 | `order.quantity.toLocaleString()` 件/米 | tabular-nums |
| 业务线 | `BUSINESS_LINE_LABELS[order.businessLine]` | fabric→面料 / garment→成衣 / capsule→Capsule |
| 跟单 | `order.merchandiser` | 可空 |
| 工厂 | `order.millName` | 可空，truncate |
| 交期 chip | `order.dueDate` → `daysUntil()` | 颜色编码见 §五 |

### 4.3 卡片点击行为

```typescript
onClick={() => onOpenOrder?.(o.id)}
```

卡片是 `<button>` 语义，点击触发 `onOpenOrder(orderId)` 回调 → App 层负责完整 Order lookup + 视图切换到订单详情页。看板本身不发起详情拉取。

## 五、颜色编码（交期倒计时）

### 5.1 交期 chip 三态

`daysUntil(dueDate)` 计算剩余天数（负数=已逾期天数）：

| 条件 | 语义 | 颜色 | 文案 |
|------|------|------|------|
| `d < 0` | danger | `statusSemanticClass('danger')` | `逾期 ${-d} 天` |
| `0 ≤ d ≤ 7` | warning | `statusSemanticClass('warning')` | `今日到期`（d=0）/ `剩 ${d} 天` |
| `d > 7` | neutral | `statusSemanticClass('neutral')` | `剩 ${d} 天` |
| `dueDate 为空` | — | 不渲染 | 返回 null |

### 5.2 阻塞红标

`item.blockedCount` = 该订单 `status === 'blocked'` 的阶段数。>0 时卡片右上角显示 danger chip `⚠ 阻塞`。

### 5.3 列入场动画

每列 `motion.div` 错峰入场：`initial opacity:0 y:8 → animate opacity:1 y:0`，delay = `idx * 0.03s`，营造从左到右铺开效果。

## 六、筛选交互

### 6.1 三种筛选器

| 筛选器 | 类型 | 行为 |
|--------|------|------|
| 搜索框 | 文本模糊 | 匹配 `customer / poNumber / millName / merchandiser / id` 五字段（toLowerCase includes） |
| 仅看逾期 | toggle | `daysUntil(dueDate) < 0`（null 或 ≥0 过滤掉） |
| 仅看阻塞 | toggle | `blockedCount > 0` |

### 6.2 筛选特性

- **纯前端内存筛选**：`useMemo` 依赖 `[items, search, overdueOnly, blockedOnly]`，不触发后端请求
- **筛选可叠加**：三筛选器 AND 关系
- **结果计数**：工具行右侧 "在手 N 单"（N = filtered.length，非 items.length）

## 七、卡片归属列规则

```typescript
const columnOf = (item): string => {
  if (item.currentStageKey) return item.currentStageKey;
  return item.stages.length > 0 ? 'qc_shipped' : 'order_placed';
};
```

| 场景 | 归属列 |
|------|--------|
| 有 `currentStageKey`（第一个非 done 阶段） | 该阶段列 |
| 全部阶段 done（currentStageKey=null 且 stages 非空） | `qc_shipped`（最后一列） |
| 无阶段记录（stages 为空） | `order_placed`（第一列；自愈回填后不出现） |

**`byColumn` 构建**：`Map<stageKey, ProductionBoardItem[]>`，遍历 filtered items 按 `columnOf` 分桶。

## 八、门禁校验（看板只读，门禁在详情页触发）

看板本身不触发门禁，但卡片视觉应反映门禁阻塞状态。门禁真源在 [stageService.ts advanceStage](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/production/stageService.ts#L232-L387)：

| 阶段 | 门禁 | 错误码 |
|------|------|--------|
| pre_cut_checked (6) | PreCutChecklist 四项全 true | `PRECUT_CHECKLIST_INCOMPLETE` |
| pp_sample_approved (7) | 双签（生产部+业务部） | `PP_SAMPLE_NOT_SIGNED` |
| qc_shipped (10) | 终期验货 result≠fail + criticalDefects=0 + passRate≥90% + defectRate≤3% + approvedByBusiness | `INSPECTION_NOT_QUALIFIED` / `BUSINESS_APPROVAL_REQUIRED` |

**统一前置门禁**：`STAGE_NOT_SEQUENTIAL`（前序阶段未全 done 则禁止推进）。

**看板与门禁的关系**：看板展示阶段状态（pending/in_progress/done/blocked），跟单员看到某卡片停在门禁列 → 点击卡片进详情页补全门禁条件 → 回看板刷新可见推进。

## 十、数据模型与聚合契约

### 10.1 ProductionBoardItem 结构

```typescript
interface ProductionBoardItem {
  order: {
    id, poNumber, customer, quantity, status, dueDate,
    businessLine, merchandiser, millName
  };
  stages: Array<{ stageKey, stageSeq, status }>;
  currentStageKey: string | null;  // 第一个非 done 阶段
  blockedCount: number;            // status==='blocked' 的阶段数
}
```

### 10.2 在手口径

```typescript
where: { deletedAt: null, status: { notIn: ['Delivered', 'Cancelled'] } }
orderBy: { dueDate: 'asc' }
take: 500
```

包含 Pending / Confirmed / Production / Shipping / Alert；排除 Delivered / Cancelled / 软删除。

### 10.3 自愈回填

历史种子订单未经 `initProductionStages` 初始化 → 缺 10 阶段行 → 泳道空白。`getProductionBoard` 检测 missing 订单并幂等回填（`upsert + update:{}`），随后重查。
