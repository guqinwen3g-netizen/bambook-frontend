# 面料工序级委外链 (Fabric Process-Level Outsourcing Chain)

> **REQ2-05** · 痛度 34（第二轮需求池批次二 A 级）· 来源 IND-06 缺口
> **甲方场景**：面料按单投产的真实链路 = 坯布厂→染厂→后整理（→涂层），各环节有独立损耗率与加工费；当前 MES 外协（L2）只有整体外协单，无工序拆分。

## §2 关键设计决策（DR-047 · 需求池点名的设计评审）

### DR-047-① 工序链与外协单的关系：计划核算层 ∥ 执行单据层

```
订单视角（本模块）                 供应商视角（既有 MES）
┌────────────────────────┐       ┌────────────────────────┐
│ OrderProcessNode（计划+核算） │──可选──→│ OutsourcingOrder（执行单据）│
│ 序/工厂/投入产出/损耗/加工费  │ 关联    │ 流转/到货验收/合格量      │
│ planned→in_progress→done │       │ Draft→…→Received        │
└────────────────────────┘       └────────────────────────┘
```

- **工序链是计划与成本核算层**：这道工序给谁做、投多少出多少、损耗多少、加工费多少——订单成本口径的真源
- **外协单是执行单据层**：供应商协作流转与到货验收，既有结构零侵入
- `OrderProcessNode.outsourcingOrderId` 可选关联：完工登记时可参考关联外协单的 `qualityAcceptedQty` 作为实际产出（前端辅助，不强制回写链路）
- 两者各自独立生命周期，不做状态机耦合（面料工序有平行/外发多厂等现实情况）

### DR-047-② 与采购的关系：加工费成本口径走工序链，应付走既有采购域

- 染费/涂层费等加工费的**应付账款**（对供应商付款、对账）继续走既有采购域（采购单/供应商对账单），工序链**不生成应付**
- 工序链登记的是**成本口径**的加工费（unitPrice × 产出量），供订单利润表/BOM 核算消费——与「内部供料 DR-033 结算价替代 unitPrice 做内部核算」同属核算层口径，不与应付双轨

### DR-047-③ 计费口径：按产出量计费（染厂行业惯例）

- `amount = outputQty × unitPrice`（出缸量计费）；未完工时按投入量预估（estimate 口径标注）
- 损耗率 = (inputQty − outputQty) / inputQty × 100，完工登记时自动计算；订单级累计损耗 = (首道投入 − 末道产出) / 首道投入

## §3 模块边界

| 包含 | 不包含 |
|------|--------|
| 工序节点建模（seq/类型/承接工厂/投入产出/损耗/加工费） | 外协单据流转与到货验收（OutsourcingOrder 既有） |
| 完工登记（产出量→损耗率→金额重算） | 采购应付生成（采购域既有） |
| 订单工序链全景 + 累计损耗/加工费聚合 | 工序级在制看板（增强项，后续） |
| 与 Track A 估算对照展示（dyeing 行 vs 实际工序费） | BOM 插件深度改造（MVP 提供聚合 API 供消费） |

**工序类型枚举**（面料域）：`gray_fabric` 坯布织造 / `dyeing` 染整 / `finishing` 后整理 / `coating` 涂层 / `other` 其他。

## §4 数据模型

```prisma
/// 设计真源：面料工序级委外链.md §4（REQ2-05，IND-06 缺口补齐）
/// 业务语义：面料订单工序链节点（计划+成本核算层，DR-047-①）。
/// 完工登记产出量 → 自动损耗率与加工费金额；订单级聚合供 BOM/利润表消费。
model OrderProcessNode {
  id      String @id // 格式：OPN__${shortId}
  orderId String // 挂订单（面料域）

  seq         Int    // 工序序号（展示排序；同订单唯一）
  processType String // gray_fabric | dyeing | finishing | coating | other
  supplierId   String? // 承接工厂（跨模块 snapshot FK → Relation）
  supplierName String? // 冗余快照

  // ─── 数量（按产出计费 DR-047-③） ───
  inputQty  Decimal @db.Decimal(18, 4) // 投入量
  outputQty Decimal? @db.Decimal(18, 4) // 产出量（完工登记后落值）
  unit      String   @default("M") // M | YD | KG

  // ─── 加工费（成本口径 DR-047-②：不生成应付） ───
  unitPrice Decimal @db.Decimal(18, 4) // 加工费单价（按产出量）
  currency  String  @default("CNY")
  amount    Decimal @default(0) @db.Decimal(18, 4) // 完工 = outputQty×unitPrice；未完工 = inputQty×unitPrice（预估）

  // ─── 状态 ───
  status String @default("planned") // planned | in_progress | done
  completedAt BigInt?
  notes  String?

  // ─── 可选关联外协单（DR-047-① 执行载体，不耦合状态机） ───
  outsourcingOrderId String?

  createdAt BigInt
  updatedAt BigInt
  deletedAt BigInt?

  @@unique([orderId, seq])
  @@index([orderId])
}
```

### 状态机

```
planned ──→ in_progress ──→ done（完工登记 outputQty → 损耗率 + amount 重算）
   └──────────────────────→ done（直接完工，小工序免中间态）
```

- planned/in_progress 可修正计划字段（seq/工厂/投入量/单价）；done 仅可改备注
- 软删仅限 planned 态
- 不强制 seq 顺序推进（面料存在平行工序/外发多厂；seq 仅作链路展示排序）

## §5 API（挂 /api/v1/mes，扩展不新建）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/order-processes` | 创建节点 {orderId, seq, processType, supplierId?, inputQty, unit, unitPrice, notes?} |
| GET | `/order-processes?orderId=` | 订单工序链全景（nodes 按 seq + summary：节点数/完成数/首道投入/末道产出/累计损耗%/加工费合计/预估口径） |
| PATCH | `/order-processes/:id` | 修正计划字段（planned/in_progress 限定） |
| POST | `/order-processes/:id/complete` | 完工登记 {outputQty, actualUnitPrice?} → status=done + amount 重算 + 损耗率 |
| POST | `/order-processes/:id/start` | planned → in_progress（可选中间态） |
| DELETE | `/order-processes/:id` | 软删（仅 planned） |

守卫与 mesRoute 既有外协端点一致（extractActorFromRequest JWT；写操作校验 actor）。

## §6 前端（OrderProcessChainPanel 挂订单详情）

- 位置：OrderManager 订单详情 `id="order-detail-process-chain"`（**Fabric 类型限定**——面料域需求）
- 结构（订单详情区块范式）：
  - **汇总头**：N 道工序 · 完成 x/N · 累计损耗 y%（首道投入 → 末道产出）· 加工费合计 ¥z（预估口径标注）
  - **工序链卡片流**（按 seq）：序号 + 工序类型徽章 + 承接工厂 + 投入→产出 + 损耗% + 金额 + 状态徽章（planned 灰/in_progress 黄/done 绿）
  - **登记 BottomSheet**：工序类型 chips + 工厂下拉（供应商 Relation）+ 投入量/单位/单价
  - **完工登记**：产出量输入 → 预览损耗率与金额 → 确认
- 对照区：summary 返回的加工费合计与 Track A dyeing 行对照（有报价估算时展示差异提示——「工序实际 vs 估算」）

## §7 验收标准（对应需求池）

| 锚点 | 验证方式 |
|------|---------|
| 完整工序链进度 | GET ?orderId= 返回按 seq 排序全链 + 每节点状态 |
| 累计损耗 | summary.cumulativeLossPct =（首道 inputQty − 末道 outputQty）/ 首道 inputQty |
| 工序加工费计入 BOM/利润表 | summary.totalAmount 聚合 API（BOM/利润表消费接口）；前端对照 Track A dyeing 行 |
