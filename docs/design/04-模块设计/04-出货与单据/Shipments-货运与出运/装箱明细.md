## §2 三级数据结构

```
Shipment（运单）
  ├── ShipmentLine（装运行）—— 回答"发什么货"
  │     ├── productCode / productName / colorCode
  │     ├── quantity（Decimal 18,4）/ unit / cartons
  │     ├── grossWeight / netWeight / volume
  │     └── hsCode / countryOfOrigin
  │
  └── ShipmentCarton（逐箱）—— 回答"每个箱子装了什么/多重/多大"
        ├── cartonNo（"1" / "1-60"）
        ├── length / width / height（cm）
        ├── grossWeight / netWeight / volume（CBM 推导）
        └── ShipmentCartonItem[]（箱内分配，混装支持）
              └── shipmentLineId + quantity（该行在此箱中的数量）
```

**互补关系**：行级回答"发什么货"，逐箱回答"每个箱子装了什么"。装箱单（PL）按 C/NO 逐箱列示是外贸刚需，混装经 ShipmentCartonItem 分配数量。

## §3 汇总派生口径（recomputeShipmentTotals）

运单 totalPackages / grossWeight / netWeight / volume 的派生优先级：

| 优先级 | 条件 | 派生口径 |
|---|---|---|
| 1 | 有箱（ShipmentCarton.length > 0） | totalPackages = 箱数；毛/净/体 = 箱级合计 |
| 2 | 无箱有行（ShipmentLine.length > 0） | totalPackages = 行箱数合计；毛/净/体 = 行级合计 |
| 3 | 皆无 | 不动（保持手工录入） |

**触发时机**：每次 `replaceShipmentLinesTx` / `replaceShipmentCartons` 后同事务调用，写回 Shipment 汇总字段。

## §4 编辑窗口

| 状态 | 可编辑装箱 | 说明 |
|---|---|---|
| Draft | ✅ | 草稿，自由编辑 |
| Booked | ✅ | 已订舱，仍可调整装箱 |
| Loading | ✅ | 装货中，装箱最后窗口 |
| Shipped | ❌ 409 | 已发运离厂，锁定 |
| Arrived | ❌ 409 | 已到港，锁定 |
| Cleared | ❌ 409 | 已清关，锁定 |
| Delivered | ❌ 409 | 终态 |

## §7 保存流程（handleSave）

```
1. validate() → 前端预校验（与后端一致）
2. setIsSaving(true)
3. 整组替换装运行：
   shipmentService.replaceShipmentLines(shipment.id, lines.map(...))
   → 返回 savedLines（含服务端行 id）
4. 行 key → 服务端行 id 映射（按 lineNumber 顺序对齐）：
   lines.forEach((l, i) => lineIdByKey.set(l.key, savedLines[i].id))
5. 整组替换逐箱：
   shipmentService.replaceShipmentCartons(shipment.id, cartons.map(...))
   → items 映射 lineKey → shipmentLineId（lineIdByKey.get(item.lineKey)）
   → 过滤无效引用（!shipmentLineId）
6. onSaved() → packingRefreshKey++ → 侧栏刷新
7. onClose() → 关闭 Modal
```

**关键设计**：先保存行（拿服务端 id），再保存箱（用行 id 映射箱内分配），保证混装分配引用有效。

## §8 校验规则

### 8.1 前端预校验（validate）

| 校验 | 失败提示 |
|---|---|
| 每行品名或货号至少填一个 | "第 N 行需填写品名或货号" |
| 行数量非负 | "第 N 行数量不能为负" |
| 行箱数非负整数 | "第 N 行箱数必须为非负整数" |
| 箱号必填 | "第 N 箱箱号必填" |
| 分配数量正数 | "箱 X 分配数量必须为正数" |
| 分配引用有效行 | "箱 X 存在失效的行引用，请移除该分配" |
| 行累计分配 ≤ 行数量 | "行「品名」累计分配 X 超过行数量 Y" |

### 8.2 后端校验（replaceShipmentCartons）

| 校验 | 错误码 | HTTP |
|---|---|---|
| 运单不存在 | NOT_FOUND | 404 |
| 状态不可编辑 | INVALID_CURRENT_STATUS | 409 |
| 箱号必填 | VALIDATION_FAILED | 400 |
| 分配引用本运单既有行 | VALIDATION_FAILED | 400 |
| 分配数量正数 | VALIDATION_FAILED | 400 |
| 行累计分配 ≤ 行数量 | VALIDATION_FAILED | 400 |
| 行数量 null 时不校验上限 | — | — |

## §9 体积推导

箱三尺寸（length/width/height）齐全且 volume 缺省时，服务层自动推导：

```
volume = length × width × height ÷ 1,000,000  // cm³ → CBM
```

**触发**：`replaceShipmentCartons` 内部，每箱创建前检查 `volume === null && length/width/height !== null`。

## §10 从订单带出（pullLinesFromOrder）

### 10.1 流程

```
1. loadEditableShipment（校验状态可编辑）
2. 检查 sh.orderId 存在 → 否则 VALIDATION_FAILED "运单未关联订单"
3. 查询 order + orderLines（lineNumber asc）
4. order 不存在/已删 → ORDER_NOT_FOUND
5. mapOrderLinesToShipmentLineInputs(orderLines) 映射：
   - orderLineId = ol.id
   - productCode = ol.materialCode ?? ol.itemNo
   - productName = ol.description
   - quantity = ol.quantity.toString()
   - unit = ol.unit
6. replaceShipmentLines（整组替换，覆盖现有行）
```

### 10.2 映射口径单一来源

`mapOrderLinesToShipmentLineInputs` 被 3 处共用：
- `createShipment` 首装行（建单时自动带出）
- `pullLinesFromOrder`（手动重新带出）
- pull-from-order 端点

## §12 整组替换语义

行级与箱级均采用 PUT 整组替换语义：

| 步骤 | 行级（replaceShipmentLinesTx） | 箱级（replaceShipmentCartons） |
|---|---|---|
| 1 | 查询既有行 id（removedLineIds） | — |
| 2 | 删除箱内分配（shipmentLineId in removedLineIds） | — |
| 3 | deleteMany shipmentLine | deleteMany shipmentCarton（items 随 Cascade） |
| 4 | 逐行 create（lineNumber 顺序） | 逐箱 create + 逐 item create |
| 5 | recomputeShipmentTotals | recomputeShipmentTotals |
| 6 | writeRouteAuditLog（PACKING_LINES_REPLACE） | writeRouteAuditLog（PACKING_CARTONS_REPLACE） |

**幂等性**：整组替换天然幂等——同输入多次提交结果一致。行被移除时级联清理箱内分配（snapshot FK 无数据库级联，服务层手动 deleteMany）。
