## §4 状态机概要

运单状态机采用"线性物流流 + 可随时取消"模型：

```
Draft ──▶ Booked ──▶ Loading ──▶ Shipped ──▶ Arrived ──▶ Cleared ──▶ Delivered
  │          │          │           │           │           │
  │          │          │           │           │           │
  └──────────┴──────────┴───────────┴───────────┴───────────┴──▶ Cancelled（终态）

合法转移 map（后端 statusTransition.ts SHIPMENT_TRANSITIONS 单一真源）：
  Draft    → {Booked, Cancelled}
  Booked   → {Loading, Shipped, Cancelled}    （可跳过 Loading 直接发运）
  Loading  → {Shipped, Cancelled}
  Shipped  → {Arrived, Cancelled}
  Arrived  → {Cleared, Cancelled}
  Cleared  → {Delivered, Cancelled}
  Delivered → {}                              （终态）
  Cancelled → {}                              （终态）
```

**校验双轨**：
- 后端 `validateStatusTransition('Shipment', from, to)` fail-closed，非法转移返回 400 INVALID_TRANSITION
- 前端编辑器 status 下拉全枚举可选，提交后由后端兜底校验
- 创建时禁止直接创建终态（Delivered/Cancelled），允许补录 Shipped/Arrived/Cleared

## §5 核心业务流程图

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  订单     │───▶│  创建运单  │───▶│  订舱     │───▶│  装货     │───▶│  发运     │
│  Order   │    │ Shipment │    │  Booked  │    │  Loading │    │  Shipped │
│ (prime)  │    │ (首装行)  │    │          │    │ (装箱明细)│    │ (atd回填) │
└──────────┘    └────┬─────┘    └──────────┘    └──────────┘    └────┬─────┘
                     │                                              │
                     │  订单状态联动 (linkOrderStatusFromShipment)     │
                     │  Booked/Loading/Shipped/Arrived/Cleared        │
                     │  → Order.Shipping                             │
                     │  Delivered → Order.Delivered                   │
                     │                                              │
                     │   ┌──────────────────────────────────────────┘
                     │   ▼
                     │  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
                     │  │  到港     │───▶│  清关     │───▶│  交付     │───▶│  制单     │
                     │  │  Arrived │    │  Cleared │    │ Delivered│    │  CI/PL   │
                     │  │ (ata回填) │    │ (清关日)  │    │ (终态)    │    │  CO/BL   │
                     │  └──────────┘    └──────────┘    └──────────┘    └──────────┘
                     │
                     │  ┌──────────────────────┐
                     └─▶│  报关 / 退税 / 信用证   │ (snapshot FK 关联，本模块不编辑)
                        └──────────────────────┘

物流节点时间轴（ShipmentEvent append-only，每次状态变更事务内追加）：
  首节点(fromNode=null) → Booked → Loading → Shipped → Arrived → Cleared → Delivered

业务事件总线（事务提交后发布，失败不阻断业务）：
  • ShipmentCreated       — 所有创建
  • ShipmentStatusChanged — 所有状态变更
  • ShipmentCompleted     — 状态变为 Delivered（触发开票联动）
```

**链路关联双轨制**：
1. **snapshot FK + EntityLink 图谱**（横向发现）：运单 orderId/customerRelationId/carrierRelationId 三向 snapshot FK + syncShipmentReferences 同步 EntityLink
2. **制单数据装配**（纵向聚合）：`GET /api/v1/shipping/:id/document-set` 以运单为主轴回退拉取 Order/OrderLine/CustomsDeclaration/Relation，装配 CI/PL/CO/BL 所需标准化字段

## §6 数据模型概要

出运模块的持久化真源由 5 个核心模型组成（报关/信用证/退税/单据模板另见数据模型组文档）：

| 模型 | 角色 | 关键约束 |
|------|------|---------|
| `Shipment` | 运单主档（60+ 字段，含 3 角色 snapshot + 费用 Decimal×4 + 报关字段） | `id` PK / `shipmentNumber` @unique / `deletedAt` 软删 / 7 索引 |
| `ShipmentLine` | 装运行（产品/数量/箱规/HS） | shipmentId snapshot FK / orderLineId 关联订单行 |
| `ShipmentEvent` | 物流节点事件（append-only 时间轴） | shipmentId snapshot FK / fromNode→toNode / 无软删 |
| `ShipmentCarton` | 逐箱装箱明细（尺寸/重量/体积） | shipmentId snapshot FK / volume 服务层推导 |
| `ShipmentCartonItem` | 箱内货物分配（混装支持） | cartonId FK Cascade / `@@unique([cartonId, shipmentLineId])` |

## §7 字段配置真源约定

运单编辑器的字段分组在 `ShipmentManager.tsx` 的 `SHIPMENT_FORM_SECTIONS` 数组中登记，3 段表单共享单一配置：

- `shipment-basic`（基本信息）：运单号、状态、运输方式
- `shipment-logistics`（物流信息）：承运人、航次、船名/航班、跟踪号、跟踪链接、装运港、卸货港、ETD、ETA
- `shipment-consignee`（收货信息）：客户、承运人、集装箱号、总件数、毛重、体积、备注

每个字段配置含 `name`/`label`/`type`（text/select/textarea）/`required`/`placeholder`/`fullSpan`。`buildPayload` 将草稿转为 API payload，空字符串转 undefined（后端不覆盖空值）。

**装箱编辑器**（`PackingEditorModal`）采用 Tab 切换（lines / cartons），行级与箱级分离编辑，保存时先替换行（拿服务端行 id）再替换箱（行 key→id 映射箱内分配）。

## §10 设计系统约束

本模块遵循 BDS RDL 中性契约：
- 禁止硬编码 hex 颜色 / `rounded-[Npx]` / `box-shadow`，全部走 CSS 变量 + Tailwind 语义类
- 状态徽章通过 `statusTone(status)` 映射 bds-badge 语义变体（neutral/info/success/danger/warning）
- 时间轴节点圆点色与徽章变体同语义 token（`STATUS_TONE_COLOR` 映射 `var(--text-tertiary)`/`var(--accent-text)`/`var(--success-text)` 等）
- 组件对主题透明——无 isDarkMode 分支，暗色由 tokens.css `[data-theme]` 统一覆盖
- 空态不使用插画/吉祥物，仅文字 + Lucide 图标
