## §3 字段分组配置

表单字段定义于 `SHIPMENT_FORM_SECTIONS`（3 段），每个字段含 `name`/`label`/`type`/`required`/`placeholder`/`fullSpan`：

### 3.1 基本信息（shipment-basic）

| 字段 | name | type | required | placeholder | 说明 |
|---|---|---|---|---|---|
| 运单号 | shipmentNumber | text | ✅ | SHIP-2026-001 | 空时服务端自动生成 SH-YYYY-NNNN |
| 状态 | status | select | ✅ | — | 8 态枚举（SHIPMENT_STATUS_OPTIONS） |
| 运输方式 | shippingMethod | text | — | — | Sea/Air/Land/Rail/Courier |

### 3.2 物流信息（shipment-logistics）

| 字段 | name | type | placeholder | 说明 |
|---|---|---|---|---|
| 承运人 | carrierName | text | — | 货代/船公司名 |
| 航次号 | voyageNumber | text | — | 航次 |
| 船名/航班 | vesselOrFlight | text | — | 海运船名 / 空运航班号 |
| 物流跟踪号 | trackingNumber | text | 快递单号 / 集装箱跟踪号 | C4 物流跟踪 |
| 跟踪查询链接 | carrierTrackingUrl | text | https://…（承运商查询页） | C4 前端跳转 |
| 装运港 | portOfLoading | text | — | 装货港 |
| 卸货港 | portOfDischarge | text | — | 卸货港 |
| 预计离港 | etd | text | YYYY-MM-DD | ETD |
| 预计到港 | eta | text | YYYY-MM-DD | ETA |

### 3.3 收货信息（shipment-consignee）

| 字段 | name | type | fullSpan | 说明 |
|---|---|---|---|---|
| 客户 | customerName | text | — | 收货方 |

## §4 全流程编辑场景

### 4.1 订舱阶段（Draft → Booked）

| 操作 | 字段 | 说明 |
|---|---|---|
| 填写运单号 | shipmentNumber | 空时服务端生成 |
| 选择运输方式 | shippingMethod | Sea/Air/Land/Rail/Courier |
| 填写订舱日期 | bookingDate | YYYY-MM-DD |
| 填写承运人 | carrierName / carrierRelationId | 货代/船公司 |
| 填写船名航次 | vesselOrFlight / voyageNumber | 海运必填 |
| 填写港口 | portOfLoading / portOfDischarge | 装运港/卸货港 |
| 填写 ETD/ETA | etd / eta | 预计离港/到港 |
| 推进状态 | status → Booked | 状态机校验 Draft→Booked |

### 4.2 装货阶段（Booked → Loading）

| 操作 | 字段/入口 | 说明 |
|---|---|---|
| 维护装箱明细 | 装箱编辑器（PackingEditorModal） | 行级 + 逐箱 |
| 从订单带出 | pullLinesFromOrder | 覆盖现有行 |
| 填写集装箱号 | containerNumber | 集装箱号 |
| 填写封条号 | sealNumber | 封条号 |
| 推进状态 | status → Loading | 状态机校验 Booked→Loading |

### 4.3 发运阶段（Loading → Shipped）

| 操作 | 字段 | 说明 |
|---|---|---|
| 回填 ATD | atd | 实际离港日 |
| 填写物流跟踪号 | trackingNumber | C4 快递单号/集装箱跟踪号 |
| 填写跟踪链接 | carrierTrackingUrl | C4 承运商查询页 |
| 推进状态 | status → Shipped | 状态机校验 Loading→Shipped；触发 ShipmentStatusChanged 事件 |

### 4.4 到港阶段（Shipped → Arrived）

| 操作 | 字段 | 说明 |
|---|---|---|
| 回填 ATA | ata | 实际到港日 |
| 推进状态 | status → Arrived | 状态机校验 Shipped→Arrived |

### 4.5 清关阶段（Arrived → Cleared）

| 操作 | 字段 | 说明 |
|---|---|---|
| 填写报关单号 | customsDeclarationNumber | 报关单号 |
| 填写清关日期 | customsClearanceDate | 清关完成日 |
| 填写报关行 | customsBroker | 报关行 |
| 推进状态 | status → Cleared | 状态机校验 Arrived→Cleared |

### 4.6 交付阶段（Cleared → Delivered）

| 操作 | 字段 | 说明 |
|---|---|---|
| 确认交付 | status → Delivered | 终态；触发 ShipmentCompleted 事件（开票联动） |

## §5 状态推进机制

### 5.1 前端

- status 字段为 select 下拉，全 8 态枚举可选
- 提交时 `buildPayload` 将 status 转为 `ShipmentStatus` 类型
- 前端不做转移合法性校验（全量可选），后端 fail-closed 兜底

### 5.2 后端（shipmentMutationService.updateShipment）

```
1. 查询 existing shipment（含 status/shipmentNumber/orderId/deletedAt）
2. 若 hasStatus：
   a. newStatus 非 string → 400 INVALID_STATUS
   b. validateStatusTransition('Shipment', existing.status, newStatus)
      → 不合法 → 400 INVALID_TRANSITION
3. update shipment（patch + updatedAt）
4. 若 status 实际变更（existing.status !== upd.status）：
   → appendShipmentEvent（fromNode=existing.status, toNode=upd.status）
5. syncShipmentReferences（EntityLink 同步）
6. 若 orderId 存在：linkOrderStatusFromShipment（同事务联动 Order 状态）
7. writeRouteAuditLog（before/after 状态快照）
8. 事务提交后：publishBusinessEvent（ShipmentStatusChanged / ShipmentCompleted）
```

### 5.3 创建时状态约束

- 禁止直接创建终态（Delivered/Cancelled）→ 400 INVALID_INITIAL_STATUS
- 允许补录 Shipped/Arrived/Cleared（发货后才补录运单的合法场景）
- 默认 status = Booked（未传时）
- 创建即落首节点事件（fromNode=null, toNode=status）

## §6 表单逻辑

### 6.1 草稿状态（ShipmentFormDraft）

23 个字符串字段（数字字段也以字符串存储，`buildPayload` 时转换）。`createEmptyDraft()` 提供默认值（type=Export, status=Draft, shippingMethod=Sea）。`draftFromShipment(shipment)` 从已有运单填充草稿。

### 6.2 buildPayload 转换

| 转换 | 说明 |
|---|---|
| `maybe(v)` | trim 后非空返回值，空返回 undefined（后端不覆盖空值） |
| `numOrUndef(v)` | Number(v) 有限返回数字，否则 undefined |
| shipmentNumber | trim（必填） |
| status | as ShipmentStatus |
| 日期字段 | maybe（空 → undefined） |
| 数值字段 | numOrUndef（totalPackages/grossWeight/netWeight/volume） |

### 6.3 前端校验（submitForm）

| 校验 | 失败提示 |
|---|---|
| shipmentNumber 非空 | "请填写运单号" |
| etd 格式 `/^\d{4}-\d{2}-\d{2}$/` | "预计离港日格式应为 YYYY-MM-DD" |
| eta 格式 `/^\d{4}-\d{2}-\d{2}$/` | "预计到港日格式应为 YYYY-MM-DD" |

### 6.4 保存流程

```
1. 前端校验 → setErrorMessage
2. setIsSaving(true)
3. buildPayload()
4. 编辑：shipmentService.updateShipment(id, payload) → setShipments(map 替换)
   新建：shipmentService.createShipment(payload) → setShipments(prepend) + setSelectedId
5. setShowFormModal(false) + setEditingShipment(null)
6. catch → setErrorMessage
7. finally → setIsSaving(false)
```

**保存中禁用关闭**：`closeFormModal` 检查 `isSaving`，保存中不允许关闭。

## §7 订单 prime 创建

### 7.1 流程

订单详情页「创建出运」按钮 → `primeShipmentCreateFromOrder({ orderId, customerName })` → sessionStorage 写入 `bambook_shipment_create_prime` → 跳转货运管理 → ShipmentManager 挂载时 `useEffect` 读取 prime → 自动打开新建 Modal 预填 orderId + customerName → 清除 sessionStorage。

### 7.2 首装行（createShipment 内部）

创建运单时若关联订单且订单有明细行，自动带出装运行（同事务）：
- `t.orderLine.findMany({ where: { orderId } })`
- `mapOrderLinesToShipmentLineInputs(orderLines)` 映射（productCode/productName/quantity/unit）
- `replaceShipmentLinesTx(t, sh.id, lines, actorId, ip)` 整组替换

## §11 状态机联动

| 运单状态变更 | 订单状态联动 | 事件发布 |
|---|---|---|
| → Booked/Loading/Shipped/Arrived/Cleared | Order → Shipping | ShipmentStatusChanged |
| → Delivered | Order → Delivered | ShipmentStatusChanged + ShipmentCompleted |
| → Draft/Cancelled | 不联动 | ShipmentStatusChanged（Cancelled） |
| 创建（任何状态） | 有 orderId 时联动 | ShipmentCreated（+ ShipmentCompleted if Delivered） |
