## §2 ShipmentEvent 模型

```
model ShipmentEvent {
  id         String @id    // SHPE__${shortId}
  shipmentId String       // snapshot FK → Shipment
  fromNode   String?      // 上一节点（首节点为 null）
  toNode     String       // 到达节点（与运单状态一致）
  eventDate  String       // 节点业务日期 YYYY-MM-DD
  note       String?      // 节点备注
  actorId    String?      // 操作人
  createdAt  BigInt       // epoch ms

  @@index([shipmentId])
  @@index([toNode])
}
```

**核心特征**：
- **append-only**：无软删，仅追加，保证时间轴完整性
- **无 Prisma @relation**：shipmentId 为 snapshot FK，运单软删不级联删事件
- **独立于 auditLog**：面向业务查询与前端时间轴渲染，非通用操作审计
- **fromNode/toNode**：与运单状态枚举一致（Draft/Booked/Loading/Shipped/Arrived/Cleared/Delivered/Cancelled）

## §3 6 节点业务时间轴

```
首节点          订舱           装货           发运           到港           清关           交付
(fromNode=null)  Booked         Loading        Shipped        Arrived        Cleared        Delivered
    │              │              │              │              │              │              │
    ●──────────────●──────────────●──────────────●──────────────●──────────────●──────────────●
    │              │              │              │              │              │              │
  创建运单       订舱日期       装货开始       实际离港       实际到港       清关日期       交付确认
  (任意状态)     bookingDate    (状态推进)     atd/etd        ata/eta        customsClear   (状态推进)
                                                              至上           anceDate
```

**节点说明**：

| 节点 | toNode | 触发时机 | eventDate 取值 |
|---|---|---|---|
| 首节点 | 创建时 status | createShipment 事务内 | 兜底当日 |
| 订舱 | Booked | 状态变更为 Booked | bookingDate ?? 当日 |
| 装货 | Loading | 状态变更为 Loading | 兜底当日 |
| 发运 | Shipped | 状态变更为 Shipped | atd ?? etd ?? 当日 |
| 到港 | Arrived | 状态变更为 Arrived | ata ?? eta ?? 当日 |
| 清关 | Cleared | 状态变更为 Cleared | customsClearanceDate ?? 当日 |
| 交付 | Delivered | 状态变更为 Delivered | 兜底当日 |
| 取消 | Cancelled | 状态变更为 Cancelled | 兜底当日 |

## §4 节点日期取值口径（nodeBusinessDate）

`nodeBusinessDate(toNode, sh)` 函数定义于 `shipmentMutationService.ts`，是节点业务日期的单一权威源：

```typescript
function nodeBusinessDate(toNode: string, sh: any): string {
  const today = new Date().toISOString().slice(0, 10);
  switch (toNode) {
    case 'Booked':  return sh?.bookingDate || today;
    case 'Shipped': return sh?.atd || sh?.etd || today;
    case 'Arrived': return sh?.ata || sh?.eta || today;
    case 'Cleared': return sh?.customsClearanceDate || today;
    default:        return today;  // Draft/Loading/Delivered/Cancelled
  }
}
```

**设计原则**：优先取对应业务日期字段（已回填的实际/预计日期），兜底当日。这保证时间轴展示的是业务实际发生日，而非操作录入日。

## §5 事件追加机制（appendShipmentEvent）

### 5.1 helper 定义

```typescript
export async function appendShipmentEvent(
  t: any,
  params: {
    shipmentId: string;
    fromNode: string | null;
    toNode: string;
    shipment?: any;
    note?: string | null;
    actorId?: string | null;
  },
): Promise<void>
```

### 5.2 调用时机

| 场景 | fromNode | toNode | note | actorId |
|---|---|---|---|---|
| 创建运单 | null | 创建时 status | — | 创建人 |
| 状态变更（实际变化） | existing.status | upd.status | upd.notes ?? null | 操作人 |
| 同状态幂等 patch | — | — | 不落事件 | — |

### 5.3 写路径单一来源

route 和 agent 两条写路径共用 `appendShipmentEvent`，保证时间轴完整性：
- **route 路径**：`createShipment` / `updateShipment` 内部调用
- **agent 路径**：`orderShipFlow` 通过 `tx` 参数复用同一事务

### 5.4 事务闭环

事件追加与业务写入在同一 `$transaction` 内：
```
createShipment:
  1. t.shipment.create
  2. appendShipmentEvent（首节点）
  3. syncShipmentReferences
  4. linkOrderStatusFromShipment（有 orderId 时）
  5. replaceShipmentLinesTx（首装行）
  6. writeRouteAuditLog
  → 任一失败事务回滚，事件不落库

updateShipment:
  1. 查询 existing
  2. validateStatusTransition（有 status 时）
  3. t.shipment.update
  4. appendShipmentEvent（status 实际变更时）
  5. syncShipmentReferences
  6. linkOrderStatusFromShipment
  7. writeRouteAuditLog
  → 任一失败事务回滚，事件不落库
```

## §6 前端时间线渲染

### 6.1 数据拉取

```typescript
// 选中运单时拉取；状态变更后随 selectedShipment.status 联动刷新
useEffect(() => {
  if (!selectedShipmentId) { setShipmentEvents([]); return; }
  shipmentService.listShipmentEvents(selectedShipmentId)
    .then(items => setShipmentEvents(items))
    .catch(() => setShipmentEvents([]))  // 失败静默
}, [selectedShipmentId, selectedShipmentStatus]);
```

API：`GET /api/v1/shipping/:id/events`，返回 `{ items, total }`，按 `eventDate asc, createdAt asc` 排序。

## §7 加载与空态

| 场景 | 展示 |
|---|---|
| 加载中 | `Loader2 animate-spin` + "加载节点时间轴…" |
| 无事件 | "暂无节点记录" |
| 拉取失败 | 静默降级为空数组（不阻断详情面板） |
| 未选中运单 | 不渲染时间轴区域 |

## §8 联动刷新策略

| 触发 | 效果 |
|---|---|
| 选中运单变化（selectedShipmentId） | 重新拉取时间轴 |
| 运单状态变化（selectedShipmentStatus） | 重新拉取时间轴（新状态变更会追加新事件） |
| 装箱保存（packingRefreshKey） | 不影响时间轴（装箱不触发状态变更） |

## §9 与审计日志的分工

| 维度 | ShipmentEvent | RouteAuditLog |
|---|---|---|
| 定位 | 业务时间轴（面向用户） | 操作审计（面向合规） |
| 粒度 | 状态节点级 | 字段级（before/after） |
| 删除 | append-only 无软删 | 有软删 |
| 查询 | by shipmentId（业务查询） | by actor/target/source（审计查询） |
| 消费方 | 前端时间轴渲染 | 审计面板 / 合规报告 |

两者互补：ShipmentEvent 记录"运单走到哪了"，RouteAuditLog 记录"谁改了什么字段"。
