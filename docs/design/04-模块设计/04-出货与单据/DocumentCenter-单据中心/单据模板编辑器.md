## §3 范围与核心能力

### 3.1 范围内

| 能力 | 说明 | 代码入口 |
|------|------|---------|
| 模板列表 | 左列类型筛选（13 类型 + 全部）+ 模板列表（名称/语言/默认标记/变量数/停用标记） | `DocumentTemplateManager` `fetchAll` + `apiService.listDocumentTemplates` |
| 模板创建 | 类型 + 名称 + 语言（zh/en/bilingual）+ HTML content + isDefault + 备注 | `DocumentTemplateManager` `openCreate/handleSave` |
| 模板编辑 | 右列编辑器，类型不可改（编辑时 disabled），其余字段可改 | `DocumentTemplateManager` `openEdit` |
| 变量自动解析 | 保存时服务端从 content 解析 `{{variable}}` 占位符，冗余存储到 `variables` 数组 | `documentTemplateService.createTemplate/updateTemplate` → `extractTemplateVariables` |
| 默认模板唯一性 | 同 type+language 下 isDefault 仅一个，事务内清除其他默认 | `documentTemplateService.applyDefaultUniqueness` |
| 软删除 | `deletedAt` 软删，列表默认过滤；`includeInactive` 可查停用 | `documentTemplateService.deleteTemplate` |
| 审计日志 | 创建/更新/删除均写 AuditLog | `documentTemplateService` 内 `tx.auditLog.create` |
| JWT 写守卫 | 读走 JWT/API-Key，写必须 JWT（`requireJwtForWrite`）；未登录时明确提示 | `documentTemplateRoute` `requireWrite` |

### 3.2 范围外

- ❌ 模板渲染执行（归「制单引擎」，由 `exportDocumentTemplates.ts` 纯函数承载，不依赖 DocumentTemplate）
- ❌ 可视化拖拽编辑器（当前为纯文本 HTML textarea，已知缺口）
- ❌ 模板预览（未实现实时预览，需通过制单引擎实际生成单据查看效果）

> **注意**：DocumentTemplate（模板）与 EXPORT_DOC_RENDERERS（渲染器）是两套独立系统。DocumentTemplate 是用户可编辑的 HTML 模板（含变量占位符），EXPORT_DOC_RENDERERS 是代码内置的纯函数渲染器（直接消费 DocumentSetData）。当前制单引擎使用的是后者，DocumentTemplate 的变量填充渲染尚未接入制单流程（已知缺口）。

## §5 变量系统

### 5.1 占位符语法

模板 content 支持 `{{variable}}` 占位符，如 `{{orderNo}}` / `{{customerName}}` / `{{invoiceDate}}`。

### 5.2 变量解析

服务端使用 `extractTemplateVariables(content)`（共享 `lib/templateVariables`，与邮件模板同口径）自动解析：
- 扫描 content 中所有 `{{...}}` 模式
- 提取变量名，去重存入 `variables: String[]`
- 冗余存储供 UI 生成填写项（当前 UI 展示变量数，未做变量填写表单）

### 5.3 变量清单示例

```html
<h1>Commercial Invoice</h1>
<p>Invoice No: {{invoiceNo}}</p>
<p>Order: {{orderNo}}</p>
<p>Customer: {{customerName}}</p>
<p>Date: {{invoiceDate}}</p>
```

解析后 `variables = ["invoiceNo", "orderNo", "customerName", "invoiceDate"]`。

### 5.4 变量填充渲染（已知缺口）

当前 DocumentTemplate 的变量填充渲染尚未接入制单流程：
- 制单引擎使用的是 EXPORT_DOC_RENDERERS（代码内置纯函数），不读取 DocumentTemplate
- DocumentTemplate 的变量填充需要：模板 content + 变量值字典 → 字符串替换 → HTML
- 变量值字典的来源（订单/运单/报关单字段映射）尚未定义

## §6 默认模板唯一性

### 6.1 规则

同 `type + language` 下仅一个 `isDefault=true` 模板。设为默认时，事务内清除同 type+language 的其他默认：

```typescript
async function applyDefaultUniqueness(tx, type, language, excludeId) {
  await tx.documentTemplate.updateMany({
    where: {
      type, language, isDefault: true, deletedAt: null,
      ...(excludeId ? { id: { not: excludeId } } : {}),
    },
    data: { isDefault: false, updatedAt: now() },
  });
}
```

### 6.2 触发时机

| 时机 | 行为 |
|------|------|
| 创建模板 isDefault=true | 事务内清除同 type+language 其他默认 |
| 更新模板 isDefault=true | 事务内清除同 type+language 其他默认（排除自身） |
| 更新模板 language 变更 | 以 nextLanguage 为准清除默认 |

## §12 与邮件模板的同口径设计

DocumentTemplate 与 EmailSignature/EmailTemplate 共享 `lib/templateVariables` 变量解析口径：
- 相同的 `{{variable}}` 占位符语法
- 相同的 `extractTemplateVariables` 解析函数
- 相同的 isDefault 唯一性事务保证模式

这保证了用户在不同模板编辑场景下有一致的变量语法体验。
