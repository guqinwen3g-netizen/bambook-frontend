## §4 单据类型矩阵

贸易单据 9 类型，对应 EXPORT_DOC_RENDERERS 7 类渲染器（AirWaybill/InspectionCert/PhytosanitaryCert 无专用渲染器）：

| 类型 ID | 中文 | 编号前缀 | 渲染器 Kind | 说明 |
|---------|------|---------|------------|------|
| CommercialInvoice | 商业发票 | CI | CI | 核心单据，金额 + SAY TOTAL 大写 |
| PackingList | 装箱单 | PL | PL | 唛头 + 包装明细 |
| CertificateOfOrigin | 原产地证 | CO | CO | 原产地声明 |
| BillOfLading | 提单 B/L | BL | BL | 提单补料草稿 |
| AirWaybill | 空运单 AWB | AWB | — | 无专用渲染器 |
| InsuranceCert | 保险凭证 | INS | INS | CIF/CIP 场景 |
| InspectionCert | 检验证书 | IC | — | 无专用渲染器 |
| PhytosanitaryCert | 植检证书 | PC | — | 无专用渲染器 |
| Other | 其他 | DOC | — | 通用登记 |

> **TYPE_TO_EXPORT_KIND** 映射决定哪些类型可在版本快照中预览/打印。无映射的类型降级为字段视图，不伪造预览。

## §5 核心业务流程图

```
┌──────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│  运单     │───▶│  从运单生成   │───▶│  TradeDocument│───▶│  版本快照     │
│ Shipment │    │  批量登记    │    │  (Draft)     │    │  DocumentVersion│
│ (FK 源)  │    │  + v1 快照   │    │              │    │  v1 = 装配JSON │
└──────────┘    │  幂等(同type) │    └──────┬───────┘    └──────────────┘
                └──────────────┘           │
                                          │ 编辑（强制版本留痕）
                                          ▼
                ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
                │  手工创建     │───▶│  编辑 Modal  │───▶│  版本 v2/v3  │
                │  (自动取号)  │    │  (仅 Draft)  │    │  max+1 防跳号 │
                └──────────────┘    └──────────────┘    └──────────────┘

状态流转（贯穿生命周期）：
  Draft ──▶ Issued ──▶ Submitted ──▶ Accepted (L/C 交单接受)
                  │           │
                  ▼           ▼
              Cancelled    Rejected ──▶ Draft (退回修改)

打印/打包出口：
  版本快照 ──▶ EXPORT_DOC_RENDERERS[kind].render(ds) ──▶ HTML ──▶ printHtmlDocument ──▶ PDF
  订单打包 ──▶ packTradeDocumentsByOrder ──▶ 各单据最新版本 ──▶ 逐个渲染下载
```

**关键设计决策**：
1. **生成即登记**：从运单生成不仅渲染 PDF，更在台账登记 Draft 单据 + v1 快照，确保单据可追溯
2. **服务端强制留痕**：版本留痕不依赖客户端自觉，由 `appendTradeDocumentVersion` 在事务内强制写入
3. **幂等生成**：同 shipmentId+type 已存在则 skipped，不重复登记
4. **不伪造预览**：无 documentSet 快照的单据（手工创建无运单装配）降级为字段视图

## §6 数据模型概要

本模块持久化真源由 3 个核心模型组成（全量字段见 `server/prisma/schema.prisma` L3693-L3731 / L4522-L4563）：

| 模型 | 角色 | 关键约束 |
|------|------|---------|
| `TradeDocument` | 贸易单据主表（9 类型 + 6 状态 + 4 snapshot FK） | `documentNumber @unique` / `deletedAt` 软删 / 6 索引 |
| `DocumentVersion` | 版本快照（content Json = 变更后整行字段快照） | `@@unique([documentId, version])` / version 单调递增 / 无软删 |
| `DocumentTemplate` | 单据模板（13 类型 + 3 语言 + 变量清单） | `@@index([type, language])` / isDefault 同 type+language 唯一 / 软删 |

**版本快照设计**：
- `content` 为变更后整行字段快照（Json），含 `documentSet`（运单装配数据，供渲染器消费）
- 版本号 `max+1` 事务内计算，防并发跳号
- 创建时 v1 快照 = 装配数据 JSON（从运单生成）或字段快照（手工创建）
- 版本只增不删（append-only），随主单软删隐藏

## §7 版本留痕机制

版本留痕是单据中心的"根因式可追溯设计"，不依赖客户端自觉：

### 7.1 触发时机

| 时机 | 服务端入口 | 版本内容 |
|------|---------|---------|
| 从运单生成 | `generateTradeDocumentsFromShipment` | v1 = `{ documentSet: 装配数据 }` |
| 手工创建 | `customsService.createTradeDocument` | v1 = 字段快照 |
| 编辑更新 | `customsService.updateTradeDocument` | max+1 = 变更后字段快照 |
| 手动追加 | `POST /trade-documents/:id/versions` | max+1 = 传入 content |

### 7.2 防并发跳号

```typescript
const last = await tx.documentVersion.findFirst({
  where: { documentId },
  orderBy: { version: 'desc' },
  select: { version: true },
});
const nextVersion = (last?.version ?? 0) + 1;
```

事务内查询 max + 1，保证并发编辑不会产生重复版本号。`@@unique([documentId, version])` 约束兜底。

- 卡片用 `rounded-card border border-[var(--border-c-subtle)] bg-[var(--hover-darken)]` + `BAMBOOK_OS.material.glassColor`

- 状态徽章通过 `statusSemanticClass` / `statusSemanticText` 取语义样式
