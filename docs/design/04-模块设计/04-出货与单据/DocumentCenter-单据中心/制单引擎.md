## §3 范围与核心能力

### 3.1 范围内

| 能力 | 说明 | 代码入口 |
|------|------|---------|
| 运单选择 | 运单列表 + 搜索（编号/客户/卸货港）+ 选中拉取装配数据 | `ShipmentDocumentGenerator` `fetchShipments/handleSelectShipment` |
| 单据勾选 | 7 类单据勾选，CI/PL/CO/BL 默认勾选，FORMA/INS/BC 按需 | `ShipmentDocumentGenerator` `selectedDocs` state |
| 智能预勾选 | CIF/CIP 保额可推断 → INS 勾选；存在信用证 → BC 勾选 | `handleSelectShipment` 内 `setSelectedDocs` |
| 渲染输出 | 选中类型 → EXPORT_DOC_RENDERERS[kind].render(ds) → HTML → printHtmlDocument | `ShipmentDocumentGenerator` `handleGenerate` |
| 多文档连续打印 | 多类型按序 setTimeout 错开打开窗口，避免浏览器合并弹窗 | `handleGenerate` 内 `forEach + setTimeout` |
| 金额大写 | CI "SAY TOTAL" 行英文金额大写（支持到 billion） | `amountInWords` 函数 |
| 唛头生成 | 数据模型无唛头字段时的通用占位（PO + 目的港 + 件数） | `shippingMarks` 函数 |
| 出口商档案 | 渲染器读取 exporterProfile（名称/地址中英文） | `getExporterProfile` |

### 3.2 范围外

- ❌ 单据模板（DocumentTemplate）的变量填充渲染（当前制单用内置渲染器，非模板系统）
- ❌ AirWaybill / InspectionCert / PhytosanitaryCert 渲染器（未实现，已知缺口）
- ❌ 电子签章 / 数字证书签发（仅本地打印 PDF）

## §5 数据流与装配

```
┌──────────────────────────────────────────────────────────────┐
│  1. 选择运单                                                  │
│     GET /api/v1/shipping/:id/document-set                    │
│     └─ documentSetService.assembleDocumentSetData            │
│        多源装配：Shipment + Order + CustomsDeclaration +      │
│        Relation + OrderLine + LetterOfCredit + Insurance      │
│        → DocumentSetData                                      │
└──────────────────────────┬───────────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────────┐
│  2. 智能预勾选                                                │
│     INS = data.extras.insurance.insuredAmount !== null        │
│     BC  = data.extras.letterOfCredit !== null                 │
│     CI/PL/CO/BL = true（默认）                                │
│     FORMA = false（按需，GSP 目的国）                         │
└──────────────────────────┬───────────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────────┐
│  3. 渲染输出                                                  │
│     for each selectedKind:                                   │
│       html = EXPORT_DOC_RENDERERS[kind].render(docSet)       │
│       printHtmlDocument({ title, htmlBody: html })           │
│       └─ 独立 window.open + document.write + print()         │
│     多文档 setTimeout 错开避免合并弹窗                        │
└──────────────────────────────────────────────────────────────┘
```

## §6 DocumentSetData 数据结构

装配数据是制单引擎的输入真源，由服务端 `documentSetService.assembleDocumentSetData` 多源装配：

| 分区 | 来源 | 关键字段 |
|------|------|---------|
| `shipment` | Shipment | shipmentNumber/status/type/shippingMethod/vesselOrFlight/voyageNumber/portOfLoading/portOfDischarge/containerNumber/sealNumber/etd/atd/eta/totalPackages/grossWeight/netWeight/volume/hsCode/customsDeclarationNumber |
| `order` | Order | id/poNumber/invoiceNumber/invoiceDate/deliveryTerms/currency |
| `customs` | CustomsDeclaration | tradeTerms/consignor/originCountry/currency |
| `parties` | Relation + Order | consignee(名+址+联系方式)/customer/shipper |
| `lines` | OrderLine | productCode/productName/quantity/unit/unitPrice/totalAmount/grossWeight/netWeight/volume/originCountry/hsCode |
| `totals` | 聚合计算 | amount/cartons/grossWeight/netWeight/volume/currency |
| `extras.letterOfCredit` | LetterOfCredit | lcNumber/amount/currency/expiryDate（存在时触发 BC 勾选） |
| `extras.insurance` | 装配推断 | insuredAmount/coverage/voyage（存在时触发 INS 勾选） |
| `missing` | 完整度提示 | 缺失字段清单（透传 UI 展示不阻断） |

## §7 核心渲染器详解

### 7.1 CI 商业发票（renderCommercialInvoiceHtml）

- **发票号**：`order.invoiceNumber` || `INV-{shipmentNumber}`（兜底）
- **发票日期**：`order.invoiceDate` || 当日
- **买卖方**：`partyBlock`（收货人）+ `exporterBlock`（出口商档案）
- **行项**：商品/数量/单价/金额表格
- **金额大写**：`amountInWords(total, currency)` → "SAY TOTAL US DOLLARS ONE HUNDRED THOUSAND AND CENTS FIFTY ONLY"
- **贸易条款**：`order.deliveryTerms` || `customs.tradeTerms` || "FOB SHANGHAI"

### 7.2 PL 装箱单（renderPackingListHtml）

- **唛头**：`shippingMarks(data)` → PO + 目的港 + `C/NO. 1-{pkgs}`，无则 `N/M`
- **包装明细**：行项 + 箱数 + 毛净重 + 体积
- **汇总**：总箱数/总毛重/总净重/总体积

### 7.3 CO 原产地证（renderCertificateOfOriginHtml）

- **原产地**：`customs.originCountry` || 行项 `originCountry` || "CHINA"
- **出口商/收货人**：`exporterBlock` + `partyBlock`
- **运输**：船名航次 + 装卸港
- **行项原产地**：逐行声明原产地

### 7.4 BL 提单补料（renderBillOfLadingHtml）

- **提单草稿**：船名航次/集装箱号/封号/装卸港
- **包装**：总件数 + "SAID TO CONTAIN"
- **运费**：freight prepaid/collect（按贸易条款推断）

### 7.5 FORMA 普惠制产地证（renderFormAHtml）

- **GSP Form A**：普惠制原产地证格式
- **原产地**：同 CO
- **运输**：船名航次 + 装卸港
- **官方机构**：商检局签发栏位

### 7.6 INS 保险单（renderInsurancePolicyHtml）

- **保额**：`extras.insurance.insuredAmount`
- **险别**：coverage（如 All Risks）
- **航程**：装运港 → 卸货港
- **投保人**：出口商档案

### 7.7 BC 受益人证明（renderBeneficiaryCertificateHtml）

- **信用证关联**：`extras.letterOfCredit`（lcNumber/amount/currency/expiryDate）
- **声明内容**：受益人按信用证条款声明（如已邮寄单据副本/已传真装运通知等）
- **日期**：当日

## §8 金额大写函数（amountInWords）

CI 的 "SAY TOTAL" 行需要英文金额大写，支持到 billion + 两位小数：

```
输入: amount=100050.50, currency="USD"
输出: "SAY TOTAL US DOLLARS ONE HUNDRED THOUSAND AND FIFTY AND CENTS FIFTY ONLY"
```

- 整数部分：按 billion/million/thousand 分段 + hundred + and + twoDigits
- 小数部分：`AND CENTS {twoDigits}`
- 币种名：USD→US DOLLARS / EUR→EUROS / CNY→CHINESE YUAN

## §9 出口商档案（exporterProfile）

渲染器通过 `getExporterProfile()` 读取出口商档案（名称/地址中英文），用于所有单据的出口方信息：

- `nameEn` / `nameZh`：出口商名称
- `addressEn` / `addressZh`：出口商地址
- `contact`：联系方式

> 出口商档案当前为静态配置（`exporterProfile.ts`），未做后台可编辑（已知缺口）。

## §10 打印输出机制

```typescript
printHtmlDocument({
  title: `${title} - ${docSet.shipment.shipmentNumber}`,
  htmlBody: render(docSet),
});
```

`printHtmlDocument`（`printDocument.ts`）：
1. `window.open()` 打开独立窗口
2. `document.write(BASE_PRINT_STYLES + htmlBody)` 写入打印文档上下文
3. `window.print()` 触发浏览器打印
4. 多文档 `setTimeout` 错开（i × 300ms），避免浏览器合并弹窗

> 打印文档上下文是独立 window，无应用 CSS 变量，属设计 token 豁免范畴（与邮件/发票模板一致）。

## §11 与单据台账的关系

制单引擎有两层输出：
1. **直接打印**（ShipmentDocumentGenerator）：渲染 PDF 打印，不登记台账
2. **生成即登记**（DocumentCenter `generateTradeDocumentsFromShipment`）：装配数据 + 批量登记 Draft 单据 + v1 快照

两者共享 `assembleDocumentSetData` 装配服务，但：
- ShipmentDocumentGenerator 直接调用渲染器打印，不走台账
- DocumentCenter 生成登记后，版本快照含 `documentSet`，可在台账内预览/打印

> 这意味着同一次制单可能产生"直接打印的 PDF"和"台账登记的 Draft 单据"两条记录。当前两者独立操作，未做联动（已知设计决策，非缺口）。

## §12 API 端点

制单引擎消费的 API：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/shipping` | 运单列表 |
| GET | `/api/v1/shipping/:id/document-set` | 运单装配数据（DocumentSetData） |
| POST | `/api/v1/customs/trade-documents/generate-from-shipment` | 运单生成单据草稿（台账登记） |

> 渲染器为纯函数（`EXPORT_DOC_RENDERERS`），不调用 API，直接在前端执行 DocumentSetData → HTML 转换。
