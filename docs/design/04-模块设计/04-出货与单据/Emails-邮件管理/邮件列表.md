## §3 Workspace Rail（左侧栏）

### 3.1 Compose 按钮 + 折叠开关

顶部 64px 高度区：
- 展开（250px）：`bds-btn bds-btn-primary flex-1` Compose 按钮（Plus 图标 hover 旋转 90°）+ 折叠按钮
- 折叠（68px）：仅折叠按钮（图标态，点击展开）

### 3.2 Primary Hub（一级文件夹）

| NavItem | 图标 | 标签 | 未读数 | 物理/虚拟 |
|---------|------|------|--------|----------|
| Inbox | `Inbox` | Inbox | `folderCounts['INBOX'].unread` | 物理 |
| Unread | `Mail` | Unread | `folderCounts['INBOX'].unread` | 虚拟（INBOX 子集） |
| Flagged | `Flag` | Flagged | — | 虚拟（isStarred） |
| Important | `Star` | Important | — | 虚拟（isImportant） |

### 3.3 System（系统文件夹）

| NavItem | 图标 | 标签 | 物理 box |
|---------|------|------|---------|
| Drafts | `FileText` | Drafts | Drafts（IMAP `\DRAFTS` attr 解析） |
| Sent | `Send` | Sent | Sent Messages（`\SENT`） |
| Deleted | `Trash2` | Deleted | Trash（`\TRASH`） |
| Spams | `ShieldAlert` | Spams | Spams（`\JUNK`） |

**Box 属性解析**：`BOX_ATTR_MAP`（Sent→`\SENT` / Trash→`\TRASH` / Drafts→`\DRAFTS` / Spams→`\JUNK` / Junk→`\JUNK`），`findBoxByAttr` 递归查找真实邮箱名（应对不同 IMAP 服务器命名差异）。

### 3.4 底部配置区

- **邮箱设置** 按钮 → `setIsConfiguring(true)` 打开凭据 Modal
- **同步到 ERP** 按钮 → `handleSyncToErp` 调用 `emailSyncService.syncToErp`（凭据缺失提示）
- 错误/结果反馈：`erpSyncError`（danger-text 色）/ `erpSyncResult`（success-text 色）

## §4 EmailList 中栏（Virtuoso 虚拟滚动）

### 4.1 Virtuoso 配置

```tsx
<Virtuoso
  style={{ height: '100%' }}
  data={emails}
  rangeChanged={(range) => onItemVisible?.(visibleBatch.map(e => e.id))}  // 触发 prefetch
  components={{ Footer }}  // 加载更多 / 到底提示
  itemContent={(index, email) => { /* 行渲染 */ }}
/>
```

- `rangeChanged` 回调驱动 `prefetchDetails`，将可见批次 ids 批量补全 snippet（IDB 命中优先）
- Footer 二态：`hasMore` → 加载按钮 + 加载中 spinner；`!hasMore` → "Bottom of sync stream"

### 4.2 行渲染（itemContent）

每行结构：
```
┌─────────────────────────────────────────────────────────────────────┐
│ [Avatar 36×36 + Unread Dot]  Sender Name ............ 14:30        │
│                              Subject (truncate)                     │
│                              Snippet (line-clamp-1, opacity-70)    │
│                              [chip intent] [chip signal] 📎 ⭐ ✦   │
└─────────────────────────────────────────────────────────────────────┘
```

- **Avatar**：基于 `sender` hash 取色（统一 `bg-[var(--accent)]`），首字母大写
- **Unread Dot**：未读邮件右上角蓝点（`bg-[var(--os-vnext-brand-blue)]`）
- **选中态**：`selectedSurfaceClass` + 左侧 1px 蓝色竖条（`after:bg-[var(--os-vnext-brand-blue)]`）
- **未读文字**：`text-[var(--text-primary)]`（已读 `text-[var(--text-secondary)]`）
- **时间格式**：今天 HH:mm / 昨天 / 今年 MM/dd / 跨年 yyyy/MM/dd（date-fns）

### 4.3 行内徽标区（底部）

| 徽标 | 触发条件 | 样式 |
|------|---------|------|
| 意图 chip | `intentInfo.intent` 非 null 且非 'other' | `INTENT_CHIP_CLASS`（中性 recessed-bg） |
| 信号 chip | `customerSignal` 为 'urgent'/'risk' | `SIGNAL_CHIP_CLASS` + AlertTriangle 图标 |
| 附件 Paperclip | `attachments.length > 0` | 12px stroke-1 中性色 |
| Flag（星标） | `isStarred` | 12px fill-slate-500 |
| Star（重要） | `isImportant` | 12px fill-slate-400 |

**RDL flat 纪律**：意图区分靠文字而非颜色，所有 chip 共享中性色板（`recessed-bg` / `text-tertiary`）；信号 chip 仅前置 AlertTriangle 图标表达紧急/风险。

## §5 分类 chip 与意图徽标

### 5.1 意图徽标覆盖层（intentByUid）

```tsx
const intentInfo = intentByUid?.[String(emailUid)];
// emailUid = email.uid || (id.includes('-') ? id.split('-').pop() : id)
```

**加载策略**：
- `displayEmails` 变化时批量拉取（`fetchEmailIntents(mailbox, missingUids)`）
- 物理箱切换时清空 `intentByUid`（IMAP uid 单箱唯一，跨箱残留错标）
- `intentFetchBoxRef` 守卫：仅在物理箱不变时累积，切换即清空

**返回数据**：
```ts
interface EmailIntentInfo {
  intent: EmailIntent | null;       // inquiry/quotation/order/shipment_notice/invoice/complaint/follow_up/other
  customerSignal: EmailCustomerSignal | null;  // positive/neutral/urgent/risk/unknown
  summary: string | null;
  id: string | null;                // DB id（EML__xx），分类/跟进按钮依赖
  labels: string[];                  // 业务标签（urgent/customer/bulk…）
  relationId: string | null;
  orderId: string | null;
}
```

### 5.2 业务标签 chips（Reading Pane 详情区）

详情页头部展示 `selectedIntentInfo.labels` 数组，每个 label 通过 `EMAIL_LABEL_LABELS` 映射中文：
- inquiry→询价 / quotation→报价 / order→订单 / shipment_notice→出运 / invoice→发票
- complaint→投诉 / follow_up→跟进 / urgent→紧急 / risk→风险 / customer→客户 / bulk→群发

样式：`bds-badge sm neutral`（中性徽章，与列表 chip 同色板）

### 5.3 业务关联徽章

- `relationId` 非空 → `bds-badge sm info` "已关联客户"
- `orderId` 非空 → `bds-badge sm info` "已关联订单"

## §9 加载与分页（prefetch + loadMore）

### 9.1 加载更多（loadMore）

- Footer 按钮"Load Previous Messages"触发 `handleSync(currentBox, true)`
- `isLoadingMore` state 控制 spinner
- `hasMore` 状态：`newEmails.length < 50` → `hasMore=false`，否则 `true`
- 分页偏移：`currentOffset = isLoadMore ? emails.length : 0`

### 9.2 Smart Prefetching（snippet 补全）

`prefetchDetails(targetIds, boxName)`：
1. 过滤已在 pendingPrefetch Set 中的 id（防重复）
2. 标记 pending（10 秒后释放）
3. 批量处理（BATCH_SIZE=5，间隔 200ms）
4. 每封：IDB `EmailDB.getBody(uid)` 命中优先，否则 `apiService.fetchEmailDetail` 网络兜底
5. IDB 命中即 `saveBody`，回填 state 与 LS

### 9.3 后台 60 秒静默同步

```tsx
useEffect(() => {
  const interval = setInterval(() => {
    if (!isSyncing && !isLoadingMore && emailConfig.email && emailConfig.password) {
      handleSync('INBOX', false, true);  // silent
      if (currentBox !== 'INBOX' && !['STARRED', 'IMPORTANT', 'UNREAD'].includes(currentBox)) {
        handleSync(currentBox, false, true);
      }
    }
  }, 60000);
  return () => clearInterval(interval);
}, [currentBox, emailConfig]);
```

- silent 模式不显示 spinner，仅更新 LS 与 state
- 新邮件 console.log 提醒 `📬 New emails detected`
- 初始静默同步：`hasInitialSyncedRef` 守卫，1 秒延迟后并发拉取 5 箱（INBOX/Sent Messages/Drafts/Trash/Spams）

## §10 设计系统约束

- 禁止硬编码 hex 颜色 / `rounded-[Npx]` / `box-shadow`
- 意图/信号 chip 共享中性色板（`recessed-bg` / `text-tertiary`），意图区分靠文字
- 信号 chip 前置 AlertTriangle 图标表达紧急/风险
- Avatar 统一 `bg-[var(--accent)]`（不按意图着色，遵守 flat 纪律）
- 选中态竖条使用 `after:` 伪元素，1px 宽 `bg-[var(--os-vnext-brand-blue)]`
- 空态使用 "Bottom of sync stream" 文字（不使用插画/吉祥物）

## §11 权限矩阵

邮件列表读取无角色限制（凭据齐全即可）；状态回写（mark_read/mark_starred/mark_important/move）走 IMAP-proxy 端点，无 JWT 要求（凭据即权限）。详见 [模块概述 §9](./模块概述.md)。
