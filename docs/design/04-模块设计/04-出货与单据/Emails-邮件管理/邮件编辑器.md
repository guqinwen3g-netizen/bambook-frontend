## §2 编辑器骨架（Compose Modal）

```
┌──────────────────────────────────────────────────────────────────────────┐
│  Header: New Message + [模板] [签名] [X 关闭]                              │
├──────────────────────────────────────────────────────────────────────────┤
│  To:        [Recipient email address...]                                  │
│  Subject:   [Enter subject here...]                                       │
│  ─────────────────────────────────────────────────                       │
│  [模板选择面板]（templatePickerOpen 时）                                    │
│  [签名选择面板]（signaturePickerOpen 时）                                  │
│  [模板变量填写行]（activeTemplate.variables 非空时）                       │
├──────────────────────────────────────────────────────────────────────────┤
│  textarea (flex-1) — 纯文本正文（composeBody）                            │
├──────────────────────────────────────────────────────────────────────────┤
│  [Discard]    [错误反馈]              [Send Message]                       │
└──────────────────────────────────────────────────────────────────────────┘
```

- Modal：`bds-modal w-full h-[80vh]` + `width: 56rem`

- 底部：`px-8 py-5 flex justify-end gap-4`

## §3 纯文本通道与 bodyText

### 3.1 EmailEditor 子组件

```tsx
// components/email/EmailEditor.tsx
export const EmailEditor: React.FC<EmailEditorProps> = ({ value, onChange, placeholder, isDarkMode = false }) => (
  <textarea
    className={`w-full h-full p-6 border rounded-full outline-none transition-all resize-none text-sm leading-relaxed
                placeholder:text-[var(--text-tertiary)]
                bg-[var(--recessed-bg)] dark:bg-[var(--invert-bg)]
                border-[var(--border-c-strong)] dark:border-[var(--border-c-default)]
                text-[var(--text-primary)] dark:text-[var(--text-secondary)]
                focus:bg-[var(--hover-darken)] focus:ring-4 focus:ring-[rgb(var(--os-vnext-brand-blue-rgb)/0.2)]`}
    value={value}
    onChange={(e) => onChange(e.target.value)}
    placeholder={placeholder || 'Write something...'}
  />
);
```

**历史决策**：富文本 react-quill 接线已移除——发送链路不消费 HTML，且 quill.snow.css 与 flat 设计系统冲突。当前 Compose Modal 直接使用 `<textarea>`（不通过 EmailEditor 子组件），保持纯文本主线。

### 3.2 bodyText vs bodyHtml 双字段

| 字段 | 用途 | 当前状态 |
|------|------|---------|
| `bodyText` | 纯文本正文（发送链路主消费） | ✅ 主线 |
| `bodyHtml` | HTML 正文（仅落库保留，发送不消费） | ⚠️ 兼容字段 |

Outbox 落库时 `bodyText: input.bodyText || null, bodyHtml: input.bodyHtml || null`，前端 Compose 仅传 bodyText。

## §4 模板插入与变量渲染

### 4.1 模板选择面板

```tsx
{templatePickerOpen && (
  <div className="rounded-control border p-3 space-y-2 border-[var(--border-c-default)] bg-[var(--bg-panel)]">
    {!templatesLoaded ? <Loader2 /> 加载模板库...
    : emailTemplates.length === 0 ? 暂无可用模板
    : emailTemplates.map(tpl => (
        <button onClick={() => handleSelectTemplate(tpl)}>
          <span className="text-[var(--text-tertiary)]">{EMAIL_TEMPLATE_TYPE_LABELS[tpl.type]} · </span>
          {tpl.name}
        </button>
      ))}
  </div>
)}
```

### 4.2 handleSelectTemplate 流程

```
用户点击模板按钮
  ↓
1. deriveTemplateVars({ to: composeTo })  ← 自动填充已知变量（收件人等）
2. setActiveTemplate(tpl)
3. setTemplateVars(autoVars)
4. setComposeSubject(renderEmailTemplate(tpl.subject, autoVars))  ← 主题实时渲染
5. setComposeBody(renderEmailTemplate(tpl.body, autoVars))         ← 正文实时渲染
6. setTemplatePickerOpen(false)
7. markEmailTemplateUsed(tpl.id)  ← 异步上报使用统计（失败不阻断）
```

### 4.3 模板变量填写行

选中模板且 `variables.length > 0` 时显示：

```tsx
{activeTemplate && activeTemplate.variables.length > 0 && (
  <div className="rounded-control border px-3 py-2.5 flex flex-wrap items-center gap-x-4 gap-y-2">
    <span className="uppercase tracking-widest">
      {activeTemplate.name}
      <button onClick={() => setActiveTemplate(null)}>解除联动</button>
    </span>
    {activeTemplate.variables.map(name => (
      <label>
        <span>{name}</span>
        <input
          value={templateVars[name] || ''}
          onChange={e => handleTemplateVarChange(name, e.target.value)}
          placeholder={`{{${name}}}`}
        />
      </label>
    ))}
  </div>
)}
```

### 4.4 变量输入联动

```tsx
const handleTemplateVarChange = (name: string, value: string) => {
  if (!activeTemplate) return;
  const next = { ...templateVars, [name]: value };
  setTemplateVars(next);
  setComposeSubject(renderEmailTemplate(activeTemplate.subject, next));
  setComposeBody(renderEmailTemplate(activeTemplate.body, next));
};
```

- 每次输入立即从原始模板重新渲染（保留未填变量占位符）
- "解除联动"按钮清空 `activeTemplate`，composeBody/composeSubject 保留当前文本不再联动

### 5.2 handleSelectSignature 流程

```tsx
const handleSelectSignature = (sig: EmailSignature) => {
  const autoVars = emailIntelligenceService.deriveTemplateVars({ to: composeTo });
  const rendered = emailIntelligenceService.renderEmailTemplate(sig.content, autoVars);
  setComposeBody(prev => (prev.trim() ? `${prev.replace(/\s+$/, '')}\n\n${rendered}` : rendered));
```

- 签名追加到正文末尾（`replace(/\s+$/, '')` 去尾空格 + `\n\n` 双换行分隔）

## §6 Compose/Reply/ReplyAll/Forward 四态

### 6.1 Compose（新邮件）

入口：Workspace Rail Compose 按钮 → `setIsComposing(true)`
表单：`composeTo` / `composeSubject` / `composeBody` 全空
发送：`handleSendNew` → `emailOutboxService.createOutboxEmail({ fromAddress, to, subject, bodyText })`

### 6.2 Reply（回复）

入口：详情页 Reply 按钮 → `handleStartReply` → `setIsReplying(true)`
正文：插入引用块（`border-left: 2px solid #2563EB; padding-left: 15px;`）
发送：`handleSendReply` → `emailOutboxService.createReplyOutboxEmail({ originalEmailId, fromAddress, to, subject, bodyText })`
**边界**：`originalEmailId` 必须是 DB id（`EML__` 前缀），纯数字 IMAP uid 会 404，前端校验提示"请先同步到 ERP"

### 6.3 Reply All（回复全部）

入口：详情页 Reply All 按钮 → `handleReplyAll`
表单：`composeTo = selectedEmail.sender`，`composeSubject = Re: ${subject}`，`composeBody` 含引用块
流程：进入 Compose Modal（`setIsComposing(true)`）

### 6.4 Forward（转发）

入口：详情页 Forward 按钮 → `handleForward`
表单：`composeTo = ''`（清空收件人），`composeSubject = Fwd: ${subject}`，`composeBody` 含引用块（带 "Forwarded message" 标头）

## §7 Outbox 落库与 SMTP 发送

### 7.1 Outbox 落库（emailOutboxMutationService）

**Compose 落库** `createOutboxEmail`：
```ts
tx.email.create({
  data: {
    id: emailId,           // EML__${shortId}
    messageId: null,        // 发送前为空，SMTP 发送成功后回填
    direction: 'outbound',
    status: 'read',
    mailbox: 'Outbox',      // 关键：Outbox 标识
    sentAt: null,            // 发送前为空
    fromAddress, toAddresses: JSON.stringify(to), ccAddresses, bccAddresses,
    subject, bodyText, bodyHtml,
    threadId, relationId, relationName, orderId, orderPo, invoiceId, invoiceNumber,
    hasAttachments: false, attachmentCount: 0,
    ...
  }
})
+ syncEmailReferences(prisma, email, { source: 'route:email:compose', tx })  // EntityLink 双写
+ writeRouteAuditLog({ operation: 'create_outbox_email', ... })              // 审计
```

**Reply 落库** `createReplyOutboxEmail`：
- 额外校验 `originalEmailId` 存在且未删除（否则返回 `ORIGINAL_EMAIL_NOT_FOUND`）
- `threadId` 继承：`input.threadId || original.threadId || null`
- 审计 operation: `create_reply_outbox_email`

### 7.2 显式 SMTP 发送（outboxSend）

**前端触发**：详情页"发送"按钮（仅 outbound Outbox 邮件显示）
- `emailOutboxService.isSendableOutbox(selectedEmail)` 判定显示条件
- `handleSendOutbox(emailId)` → `emailOutboxService.sendOutboxEmail(emailId, { user, pass })`

**后端流程** `sendOutboxEmail`：
1. 查询 Email 记录（mailbox='Outbox'）
2. 用凭据创建 nodemailer SMTP transporter
3. 发送邮件（含 to/cc/bcc/subject/bodyText/bodyHtml）
4. 成功：更新 Email（`mailbox: 'Sent'`, `messageId: <...>`, `sentAt: now`, `status: 'read'`）+ 审计
5. 失败：保持 Outbox UI 状态，返回错误码（不本地伪成功）

### 7.3 前端事实回写

```tsx
const result = await emailOutboxService.sendOutboxEmail(emailId, { user, pass });
if (!result.ok || !result.data) {
  const reason = result.error?.message || result.error?.code || '发送失败';
  setOutboxError(`发送失败：${reason}`);
  return;  // 保持 Outbox UI 状态
}
const { messageId, sentAt } = result.data;
setEmails(prev => prev.map(e => e.id === emailId
  ? { ...e, mailbox: 'Sent', sentAt, messageId, isRead: true }
  : e));
```

**契约铁律**：前端不本地伪造 Sent/sentAt/messageId，必须消费后端返回的事实字段。

### 7.4 Compose/Reply 创建后的事实回写

```tsx
const created = await emailOutboxService.createOutboxEmail({...});
// 用 emailId 拉真实 Email 记录，不本地伪造
const detailRes = await fetch(emailApiUrl(`/v1/email/${created.emailId}`), { headers });
const detail = await detailRes.json();
if (detail?.ok && detail.data) setEmails(prev => [detail.data, ...prev]);
```

## §8 校验规则

### 8.1 前端校验

| 字段 | 规则 | 反馈 |
|------|------|------|
| `composeTo` | 非空（Send 按钮 `disabled={!composeTo}`） | 按钮置灰 |
| Reply originalEmailId | 必须是 `EML__` 前缀 DB id | 提示"请先同步到 ERP" |
| 凭据 | `emailConfig.email + password` 非空 | 提示"请先配置邮箱凭据" |

### 8.2 后端校验（emailOutboxMutationService）

`validateComposeInput`：
- `MISSING_FROM`：fromAddress 必填
- `MISSING_RECIPIENT`：to 必须是非空数组
- `MISSING_SUBJECT`：subject 必填非空
- `MISSING_BODY`：bodyText 或 bodyHtml 至少一个非空
- `INVALID_INPUT`：input 对象本身缺失
- `ORIGINAL_EMAIL_NOT_FOUND`：Reply 时原始邮件不存在或已删除
