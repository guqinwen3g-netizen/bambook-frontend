## §3 邮件 → 客户/订单自动归档（C2）

### 3.1 匹配口径（确定性、可解释、无 AI 猜测）

真源 [emailLinkService.ts](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/email/emailLinkService.ts)：

**客户匹配**：
- inbound 取 `fromAddress`，outbound 取首个 `toAddress`
- 与 `Relation.email`（联系人）/ `Relation.primaryContactEmail`（组织主联系人）小写精确比对
- 联系人优先于组织，其次 rating 高者，最后 id 字典序保证确定性

**订单匹配**：
- 主题（snippet 兜底）包含 `poNumber`（长度 ≥4 防误配）
- 已知客户时仅在该客户订单内匹配（防跨客户 PO 子串误配）
- 多命中取最长 poNumber（更具体的编号优先）

**手工优先**：
- 已有 `relationId`/`orderId` 的邮件绝不覆盖

### 3.2 索引预加载（批量性能）

```ts
const [relationIndex, orderCandidates] = await Promise.all([
  loadRelationAddressIndex(prisma),    // 地址 → RelationCandidate Map
  loadOrderCandidates(prisma),          // OrderCandidate[] (id/poNumber/customerRelationId)
]);
```

每封邮件 O(1) 查询，避免逐封全表扫描。索引加载失败降级为不链接，不阻断同步主流程。

### 3.3 纯计算 + 应用分离

```ts

// 应用（DB + EntityLink + 审计）
```

**单封**：`autoLinkEmailById`（已 linked 则 alreadyLinked=true 跳过）
**批量**：`backfillEmailLinks`（扫描 OR relationId/orderId 为空的邮件）

## §4 智能分类（规则 + AI）

真源 [emailClassificationService.ts](file:///Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/email/emailClassificationService.ts)：

### 4.1 规则层（纯函数，零 LLM 成本）

```ts
export function classifyEmailByRules(email: EmailClassifiable): string[] {
  const labels = new Set<string>();
  const text = `${email.subject || ''}\n${email.snippet || ''}`;

  // 群发/机器发件特征
  if (BULK_SENDER_RE.test(email.fromAddress || '') || BULK_SUBJECT_RE.test(text)) {
    labels.add('bulk');
  }
  // 业务关键词 → 标签（中英双语）
  for (const rule of SUBJECT_RULES) {
    if (rule.re.test(text)) labels.add(rule.label);
  }
  // 已归档到客户档案的邮件即客户邮件
  if (email.relationId) labels.add('customer');
  return [...labels];
}
```

**SUBJECT_RULES** 中英双语关键词映射：
- `complaint`：complaint/claim/投诉/索赔/质量问题/defect
- `invoice`：invoice/发票/付款/payment/催款/对账单/remittance
- `shipment_notice`：ship(ping|ment)/出运/发货/装运/delivery/提单/b/l/booking/托书
- `quotation`：quotation/quote/报价/offer
- `inquiry`：inquir/询盘/询价/enquiry/request for (price|quotation)
- `order`：order/订单/purchase order/p.o.#/confirm(ed) order

### 4.2 AI 增强层

```ts
export function labelsFromExtraction(payload: EmailExtractedPayload | null): string[] {
  const labels = new Set<string>();
  if (payload.intent && payload.intent !== 'other') labels.add(payload.intent);
  if (payload.customerSignal === 'urgent') labels.add('urgent');
  if (payload.customerSignal === 'risk') labels.add('risk');
  return [...labels];
}
```

- 复用 `aiExtract` 的 intent/customerSignal（已抽取则直接读）
- 未抽取可由端点触发 `extractEmailAi({ prisma, emailId, llm })` 后再分类
- AI 抽取失败降级为纯规则分类（不阻断）

### 4.3 合并计算（并集语义）

```ts
export function computeEmailLabels(email: EmailClassifiable): { add: string[]; all: string[] } {
  const existing = new Set(Array.isArray(email.labels) ? email.labels : []);
  const extracted = (email.aiExtractedJson ?? null) as EmailExtractedPayload | null;
  const candidates = new Set([...classifyEmailByRules(email), ...labelsFromExtraction(extracted)]);
  // complaint 升级 urgent（投诉必须快速响应）
  if (candidates.has('complaint')) candidates.add('urgent');
  const add = [...candidates].filter(l => !existing.has(l));
  return { add, all: [...new Set([...existing, ...candidates])] };
}
```

**关键不变量**：
- **并集语义**：只增不删，绝不覆盖用户手工标签
- **幂等**：重复分类结果相同，无变化则不写库、不写审计
- **complaint → urgent**：投诉自动升级紧急（业务铁律：投诉必须快速响应）

### 4.4 应用层（写库 + 审计）

```ts
export async function applyEmailClassification(prisma, emailId, opts): Promise<ClassifyApplyResult> {
  const { add, all } = computeEmailLabels(email);
  if (add.length === 0) return { emailId, changed: false, added: [], labels: all };
  await db.email.update({ where: { id: emailId }, data: { labels: all, updatedAt: now } });
  await writeRouteAuditLog({ operation: 'email_classify', after: { added: add, labels: all } });
  return { emailId, changed: true, added: add, labels: all };
}
```

## §5 投诉/紧急自动建跟进

### 5.1 触发条件

```ts
export async function autoFollowUpForClassifiedEmail(
  prisma, emailId, labels, opts
): Promise<{ created: boolean; followUpId?: string }> {
  // 仅 complaint 或 urgent 命中
  if (!labels.includes('complaint') && !labels.includes('urgent')) return { created: false };
  const result = await createFollowUpFromEmail(prisma, emailId, opts);
  if (!result.ok) return { created: false };
  return { created: !result.reused, followUpId: result.followUpId };
}
```

### 5.2 编排位置（路由层）

分类服务**不直接依赖** `autoFollowUpForClassifiedEmail`，由路由层编排（单向依赖）：
- `POST /api/v1/email/:id/classify` 端点先调 `applyEmailClassification`
- 若结果 labels 含 complaint/urgent 且 email 有 relationId → 调 `autoFollowUpForClassifiedEmail`
- 返回 `followUp: { created, followUpId }` 给前端

### 5.3 业务铁律

- **投诉必须快速响应**：complaint → urgent 升级 + 自动建跟进
- **无客户链接不建**：跟进必须挂在客户档案上（relationId 必填），否则服务端返回 `NO_RELATION`

## §7 幂等约束

### 7.1 幂等标记

```ts
export const EMAIL_FOLLOWUP_MARKER_PREFIX = '[email:';

export function emailFollowUpMarker(emailId: string): string {
  return `${EMAIL_FOLLOWUP_MARKER_PREFIX}${emailId}]`;
}
```

### 7.2 复用检查

```ts
export async function createFollowUpFromEmail(prisma, emailId, opts) {
  const email = await db.email.findUnique({ where: { id: emailId } });
  if (!email || email.deletedAt) return { ok: false, error: 'NOT_FOUND' };
  if (!email.relationId) return { ok: false, error: 'NO_RELATION' };

  // 幂等：同邮件已建过跟进 → 直接复用
  const marker = emailFollowUpMarker(emailId);
  const existing = await db.followUpRecord.findFirst({
    where: { deletedAt: null, notes: { contains: marker } },
  });
  if (existing) {
    return { ok: true, reused: true, followUpId: existing.id, nextFollowUpAt: existing.nextFollowUpAt ?? null };
  }
  // ... 创建新跟进
}
```

**幂等保证**：
- 同邮件重复调用返回已建记录（`reused: true`）
- `notes` 字段含 `[email:<emailId>]` 标记，作为幂等查询依据
- 复用不写审计，仅创建写审计

### 8.2 字段优先级

| 字段 | 优先级 | 兜底 |
|------|--------|------|
| `content` | `overrides.content` → `extracted.summary` → `email.aiSummary` → `邮件：${email.subject}` | 主题兜底 |
| `nextFollowUpAt` | `overrides.nextFollowUpAt` → `earliestDeadline(extracted)` → `localDateString(1)` 默认明天 | 确保进入逾期巡检视野 |
| `nextFollowUpTopic` | `overrides.nextFollowUpTopic` → `extracted.actionItems[0]` → `回复邮件：${subject.slice(0, 80)}` | 主题兜底 |

### 8.3 earliestDeadline 抽取

```ts
export function earliestDeadline(payload: EmailExtractedPayload | null | undefined): string | null {
  if (!payload?.deadlines?.length) return null;
  const valid = payload.deadlines
    .map(d => d.date)
    .filter(d => /^\d{4}-\d{2}-\d{2}$/.test(d))  // 仅有效日期
    .sort();  // 升序
  return valid[0] ?? null;  // 最早的
}
```
