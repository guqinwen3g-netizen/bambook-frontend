### 3.1 范围内

| 能力 | 说明 | 代码入口 |
|------|------|---------|
| 报关单录入 | 主表字段（类型/申报口岸/贸易条款/金额/包装/重量/贸易方）+ 明细行批量录入 | `CustomsManager` `showForm` Modal + `apiService.createCustomsDeclaration` |

## §6 HS 编码参考库（HsCode）

HS 编码库是报关明细行 HS 编码的"参考真源"，承载退税率/关税率/监管条件等合规要素：

### 6.1 字段矩阵

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `code` | String | ✅ | HS 编码（如 5208.52.00.00），`@unique` |
| `description` | String | ✅ | 商品描述 |
| `category` | Enum | ✅ | Textile(纺织品)/Garment(服装)/Accessory(辅料)/Material(原料)/Yarn(纱线)/Other |
| `exportTaxRebateRate` | Decimal(6,4)? | — | 出口退税率(%)，4 位小数 |
| `importTariffRate` | Decimal(6,4)? | — | 进口关税率(%) |
| `vatRate` | Decimal(6,4)? | — | 增值税率(%) |
| `unit` | String? | — | 法定计量单位 |
| `supervisionCondition` | String? | — | 监管条件代码（如 A/B/4/6） |
| `inspectionQuarantine` | String? | — | 检验检疫类别（如 M/N/R） |
| `additionalDuty` | String? | — | 附加关税说明 |
| `isActive` | Boolean | — | 默认 true，停用=false（参考数据不物理删） |

### 6.2 停用而非删除的设计决策

HS 编码作为参考数据，被历史报关单明细行 `hsCode` 文本引用。若物理删除会导致：
- 历史报关单明细行的 HS 编码变成"悬空引用"
- 退税核算时无法回溯退税率

故采用 `isActive=false` 软停用：
- 列表默认 `isActive=true` 过滤，停用编码不显示在新建选择中
- 历史数据查询时仍可按 code 反查（`getHsCodeByCode` 不过滤 isActive）
- 审计日志记录 `HS_CODE_DEACTIVATE` 动作

### 6.3 HS 编码与退税的关联

退税率 `exportTaxRebateRate` 是退税核算的关键输入：
- `createTaxRefundFromDeclaration` 从报关单明细行取 HS 编码 → 查 HsCode 库 → 取退税率
- 退税额 = `exportAmountCny × refundableRate`（refundableRate 来自 HS 编码库）

## §7 原产地与监管条件

### 7.1 原产地登记

原产地信息分两层：
- **报关单主表** `originCountry`：整票报关的原产国（默认全部商品同原产国）
- **明细行** `originCountry`：行级原产地（同一报关单内不同商品可来自不同原产国）

原产地影响：
- 原产地证（CO/FormA）的签发依据——制单引擎 `renderCertificateOfOriginHtml` / `renderFormAHtml` 读取 `data.customs.originCountry` 或行级 `originCountry`
- 退税申报的原产地合规校验（出口退税要求原产地为中国）

### 7.2 监管条件

HS 编码库的 `supervisionCondition`（监管条件代码）+ `inspectionQuarantine`（检验检疫类别）决定：
- 报关时是否需要提供额外证件（如出口许可证、检验检疫证书）
- 是否触发查验（`Inspecting` 状态）

> 当前系统仅在 HS 编码库登记监管条件文本，未做报关单提交时的监管条件自动校验（已知缺口）。

## §8 核心录入流程

```
┌─────────────────────────────────────────────────────────┐
│  报关单录入 Modal                                        │
│                                                         │
│  1. 选择类型（Export/Import）                            │
│  2. 填写主表字段（申报口岸/贸易条款/金额/重量/贸易方）    │
│  3. 录入明细行（商品名/HS编码/数量/单价/原产地）          │
│  4. 可选关联运单/订单/客户（snapshot FK）                │
│                                                         │
│  提交 → POST /api/v1/customs/declarations               │
│         ├─ 服务端自动取号 CD-YYYY-NNNN（留空时）         │
│         ├─ 校验 declarationNumber 唯一性                 │
│         ├─ 事务内：创建主表 + 批量明细行 + 审计日志       │
│         ├─ EntityLink 图谱同步（clearsShipment/aboutOrder）│
│         └─ C4 回填运单 customsDeclarationNumber          │
└─────────────────────────────────────────────────────────┘
```

**HS 编码库维护流程**：
```
hsCodes Tab → 新增/编辑 HS 编码
  ├─ 填写 code（唯一）/ description / category
  ├─ 填写退税率/关税率/增值税率（Decimal 4 位小数）
  ├─ 填写监管条件代码/检验检疫类别/附加关税
  └─ 保存 → 审计日志（CREATE/UPDATE/DEACTIVATE）
```

- 录入 Modal 使用 `bds-modal` + `bds-input`/`bds-select`/`bds-btn` 组件族
- 明细行录入采用行内表格 + 增删行按钮（`Plus`/`Trash2` Lucide 图标）

- 状态徽章 `bds-badge sm` + `SEMANTIC_BADGE_VARIANT` 语义变体
- HS 编码 code 用 `bds-mono` 等宽字体
- 禁止硬编码 hex/`rounded-[Npx]`/`box-shadow`
