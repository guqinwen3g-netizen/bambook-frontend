## §5 信用证状态机（LC_TRANSITIONS）

```
                      ┌──────────────┐
                      │   Issued     │ (已开证，首节点)
                      │  (可编辑)    │
                      └──┬───────┬───┘
                         │       │
              交单        │       │ 过期/取消
                         ▼       ▼
              ┌──────────────┐  ┌──────────┐
              │  Presented   │  │ Expired  │ (终态)
              │  (已交单)    │  │ Cancelled│ (终态)
              └──┬───┬───┬───┘  └──────────┘
                 │   │   │
        承兑      │   │   │ 取消
                 ▼   │   ▼
        ┌──────────┐ │ ┌──────────┐
        │ Accepted │ │ │ Cancelled│
        │ (已承兑) │ │ └──────────┘
        └────┬─────┘ │
             │       │ 不符点
             │       ▼
        结算 │ ┌──────────────┐
             │ │ Discrepant   │ (不符点)
             │ │ (可回到交单) │
             ▼ └──────┬───────┘
        ┌──────────┐  │ 修正后重新交单
        │ Settled  │  │
        │ (已结算) │  └─▶ Presented
        └──────────┘
         (终态)
```

| from → to | 触发场景 | 事务内追加 LcEvent |
|-----------|---------|-------------------|
| (null) → Issued | 创建信用证 | ✅ 首节点（eventDate=开证日期） |
| Issued → Presented | 受益人交单 | ✅ |
| Issued → Expired | 有效期到期 | ✅ |
| Issued → Cancelled | 取消 | ✅ |
| Presented → Accepted | 开证行承兑 | ✅ |
| Presented → Discrepant | 发现不符点 | ✅（note=不符点内容） |
| Presented → Cancelled | 取消 | ✅ |
| Accepted → Settled | 结清付款 | ✅ |
| Accepted → Cancelled | 取消 | ✅ |
| Discrepant → Presented | 不符点修正后重新交单 | ✅ |
| Discrepant → Cancelled | 取消 | ✅ |

**状态机设计要点**：
- 服务端 `validateTransition(LC_TRANSITIONS, from, to, '信用证')` fail-closed，非法转换抛错
- 前端 `LC_STATUSES` + `handleTransitionLc` 镜像合法流转，仅渲染当前状态可推进的按钮
- 每次转换同事务内 `tx.lcEvent.create` 追加节点事件，保证时间轴与状态原子一致

## §6 三到期预警

信用证有三类关键期限，任一逾期将导致信用证失效或单证不符：

| 期限字段 | 含义 | 风险 |
|---------|------|------|
| `expiryDate` | **有效期** | 信用证在此日期后失效，无法交单议付 |
| `shipmentDeadline` | **最迟装运期** | 必须在此日期前完成装运，否则提单日期不符 |
| `presentationDeadline` | **交单期限** | 装运后必须在此期限内交单（通常为装运后 21 天或有效期前） |

### 6.1 预警查询

`GET /api/v1/customs/letters-of-credit?expiringBefore=YYYY-MM-DD` 返回 `expiryDate < 指定日期` 的信用证列表。

> 当前 `expiringBefore` 仅过滤 `expiryDate`，未同时覆盖 `shipmentDeadline` 和 `presentationDeadline`（已知缺口，前端列表展示三日期供人工识别）。

### 6.2 前端展示

信用证列表行展示：
- 有效期 `expiryDate`
- 最迟装运期 `shipmentDeadline`（如有）
- 交单期限 `presentationDeadline`（如有，当前未在列表行展示，详情可见）

## §7 议付流程

议付（Negotiation）是信用证收汇的核心环节，指议付行买入受益人提交的符合信用证条款的单据：

```
开证 Issued
  │
  │ 1. 受益人备齐单据（CI/PL/CO/BL/INS/BC 等，按 documentsRequired）
  ▼
交单 Presented
  │
  │ 2. 议付行审单
  ├──▶ 单证相符 ──▶ 承兑 Accepted ──▶ 结清 Settled（收汇完成）
  │
  └──▶ 单证不符 ──▶ 不符点 Discrepant
                      │
                      │ 3. 受益人修正单据 / 申请开证行接受不符点
                      ▼
                    重新交单 Presented（回到交单节点）
```

### 7.1 单据要求与制单联动

信用证 `documentsRequired`（JSON 数组）登记交单所需单据类型。制单引擎（ShipmentDocumentGenerator）在选中运单时：
- 智能预勾选受益人证明（BC）—— 当 `data.extras.letterOfCredit !== null` 时自动勾选
- 保险单（INS）—— 当 CIF/CIP 保额可推断时自动勾选

> 当前制单引擎仅按信用证存在性预勾选，未按 `documentsRequired` 清单逐项校验单据是否齐全（已知缺口）。

### 7.2 不符点处理

`transitionLcStatus(id, 'Discrepant', discrepancies)` 传入不符点文本：
- 写入 `LetterOfCredit.discrepancies` 字段
- 同事务 LcEvent.note 记录不符点内容（时间轴直接展示）
- 前端列表行 `bds-alert warning` 展示不符点提示

不符点修正后 `Discrepant → Presented` 重新交单，时间轴形成完整的不符点发现→修正闭环。

## §8 LcEvent 节点时间轴

LcEvent 是信用证的"业务可追溯时间轴"，独立于通用 auditLog，面向业务查询与前端时间轴渲染：

### 8.1 模型

| 字段 | 类型 | 说明 |
|------|------|------|
| `lcId` | String | 关联信用证 |
| `fromNode` | String? | 上一节点（首节点为 null） |
| `toNode` | String | 到达节点（取值同 LC 状态） |
| `eventDate` | String | 节点业务日期 YYYY-MM-DD（默认当日，可按银行实际日期回填） |
| `note` | String? | 节点备注（不符点内容/银行参考号等） |
| `actorId` | String? | 操作人 |

### 8.2 设计决策

- **append-only，无软删**：LcEvent 是业务事实记录，即使信用证软删，节点历史保留可追溯
- **同事务追加**：状态转换与 LcEvent 写入在同一事务内，保证状态与时间轴原子一致
- **业务日期可回填**：`eventDate` 默认当日，但银行实际处理日期可能滞后，支持手动回填
- **查询排序**：`orderBy: [{ eventDate: 'asc' }, { createdAt: 'asc' }]`——按业务日期升序，同日按创建时间

### 8.3 前端时间轴渲染

`CustomsManager` `handleToggleLcTimeline` 展开时拉取 LcEvent 列表，渲染为纵向时间轴：
- 节点圆点颜色 = `SEMANTIC_TEXT_COLOR[evStatus.semantic]`（Issued=info/Presented=info/Accepted=success/Discrepant=warning/Settled=success/Expired=neutral/Cancelled=neutral）
- 节点标签 + 业务日期 + 操作人
- note 以 `rounded-inset` + `--bg-panel` 展示
