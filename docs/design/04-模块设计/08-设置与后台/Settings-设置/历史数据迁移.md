## §2 关键设计决策（DR-049）

### DR-049-① 校验与落库两段式（不合并）

```
下载模板 → 填 3 年数据 → 上传 → POST /validate（逐行校验，零落库）
                                  ↓ 错误行表（行号+原因）→ 修正重传
                                  ↓ 全绿/接受部分 → POST /commit（重新解析校验后只落 valid 行）
                                                        ↓ ImportBatch 记录（entityIds）
                                                        ↓ 可 POST /rollback（软删整批）
```

- **validate 无副作用**：可反复调，错误行 100% 定位（行号=数据行序，表头为第 1 行）
- **commit 自带二次校验**：validate 与 commit 之间库内可能新增同名 poNumber/发票号——commit 时重复行跳过计入 skipped（不因竞态硬失败）
- 回滚走**软删**（deletedAt），与全系统一致可追溯

### DR-049-② 四类模板列契约（表头=英文 key，模板内附中文示例行）

| 模板 | 必填列 | 可选列 | 落库目标 |
|------|--------|--------|---------|
| customers | name | contactInfo, tags(逗号分隔) | Relation（category=Customer） |
| suppliers | name | contactInfo, tags | Relation（category=Supplier） |
| orders | poNumber, customer, product, type(Fabric/Garment/Other), quantity(>0), dueDate(YYYY-MM-DD), quoteAmount(>0) | status(默认 Pending), currency(默认 USD), salesPerson | Order（source='data-migration'） |
| invoices | invoiceNumber, type(Receivable/Payable), amount(>0), currency, issueDate | status(默认 Issued), dueDate, orderId, customerName | Invoice |

- 列头英文 key（解析稳定），模板第二行给中文示例（用户照填）
- 重复校验双层：**文件内重复** + **库内已存在**（poNumber/invoiceNumber/name+category）

### DR-049-③ 挂载与权限：管理后台 tab + 跨域独立路由

- 前端入口：管理后台 AdminPanel 新增「数据迁移」tab（系统管理员上线动作——数据中心定位是知识中枢不承载，DR 遵循 AdminPanel 既有的「数据字典/系统资产散落在 AdminPanel」收口方向）
- 后端：独立域 `/api/v1/data-migration`（跨 relations/orders/invoices 三域，不挂在任一业务域下避免越界）
- 权限：模块守卫（JWT/API-Key 读）+ requireJwtForWrite（写：validate/commit/rollback 必须 JWT）

## §3 模块边界

| 包含 | 不包含 |
|------|--------|
| 四类模板下载（CSV，表头+示例） | 报价历史导入（增强项，价格历史规则①数据源——后续） |
| 上传解析（.xlsx/.csv 同通道） | 导入批次报告导出（增强项） |
| 逐行校验 + 错误行定位（行号+原因） | Excel 双轨并行的差异比对工具（甲方线下流程） |
| 确认导入（valid 行落库 + 批次留痕） | 运行中数据同步（一次性迁移，非持续同步） |
| 整批回滚（软删） | 字段级合并/更新既有记录（只创建不更新——避免误覆盖） |

**一致性锚点**：发票导入落 Invoice 表后，对账单/账龄读同一 Invoice 真源聚合——数字与 Excel 原账一致是**结构性保证**（同一数据源），验收用金额合计交叉验证。

## §4 数据模型

```prisma
/// 设计真源：历史数据迁移.md §4（REQ2-07，SEC-04 上线阻断）
/// 业务语义：批量导入批次——entityIds 是整批回滚（软删）真源。
model ImportBatch {
  id           String @id // 格式：IMB__${shortId}
  type         String // customers | suppliers | orders | invoices
  fileName     String
  totalRows    Int    // 文件数据行数
  importedRows Int    // 实际落库行数（valid 且非重复）
  skippedRows  Int    // 跳过行数（校验错误 + commit 时库内重复）
  entityIds    String[] @default([]) // 本批次创建的实体 id（回滚软删依据）
  status       String @default("committed") // committed | rolled_back
  rolledBackAt BigInt?
  createdAt    BigInt
  updatedAt    BigInt

  @@index([type])
  @@index([createdAt])
}
```

## §5 API（挂 /api/v1/data-migration）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/templates/:type` | 下载 CSV 模板（表头 + 中文示例行，attachment） |
| POST | `/validate` | multipart {file, type} → 逐行校验（零落库）：rows[{lineNo, data, valid, reason?}] + validCount/errorCount + 文件内重复 |
| POST | `/commit` | multipart {file, type} → 重新解析校验，valid 且非库内重复行落库 + ImportBatch 留痕 |
| GET | `/batches` | 批次列表（倒序，含 entityIds 计数） |
| POST | `/batches/:id/rollback` | 整批软删回滚（entityIds 按 type 分发 relation/order/invoice 软删） |

守卫：createModuleAuthGuard（读）+ requireJwtForWrite（写）。

## §6 前端（DataMigrationPanel — 管理后台新 tab「数据迁移」）

- 四类模板 chips（customers/suppliers/orders/invoices）
- **下载模板**：GET templates/:type → Blob 下载
- **上传校验**：file input (.xlsx/.csv) → POST validate → 结果区：
  - 汇总徽章：valid N / error M / 总行数
  - 错误行表（行号 + 原因，红字）——修正后重传
  - valid 行预览（前 20 行数据表）
- **确认导入**：POST commit → 批次卡（批次号/类型/导入 N/跳过 M/时间）+ 刷新批次列表
- **批次列表**：历史批次卡（状态徽章 committed 绿/rolled_back 灰）+ 回滚按钮（bdsConfirm 二次确认）

## §7 验收标准（对应需求池）

| 锚点 | 验证方式 |
|------|---------|
| 千行级迁移 ≤1 工作日 | 验收脚本生成 1000 行订单 CSV → validate+commit 全链实测（能力锚点） |
| 错误行 100% 可定位可修正重导 | 混合错误 CSV → validate 返回行号+原因逐行断言；修正后全绿 |
| 对账一致 | 发票 CSV 金额合计 vs 导入后发票列表 amount 合计（同一 Invoice 真源） |
| 软删可回滚 | rollback → entityIds 全部 deletedAt 非空 + 批次 rolled_back |
