## §2 业务定位与目标

### 2.1 业务定位

业务自动化触发器是 Bambook 的「**流程联动引擎**」——基于业务事件（BusinessEvent）自动触发下游操作，减少人工重复操作：

```
业务事件发生 → 自动化规则匹配 → 触发下游操作（创建草稿/自动核销/自动入库...）
```

### 2.2 核心目标

1. **事件驱动**：基于 `BusinessEventBus` 发布的事件自动触发
2. **可启停**：每条规则可独立启停，不删除规则本身
3. **草稿优先**：触发的下游操作默认为 Draft 状态，需人工审核后确认
4. **幂等**：同事件多次触发不会重复创建（通过业务唯一键去重）
5. **文件持久化**：配置存 `server/data/automation-config.json`，无需数据库迁移

## §5 配置服务

### 5.1 automationConfig.ts

```typescript
import { readFileSync, writeFileSync, mkdirSync, existsSync } from 'fs';
import { join } from 'path';
import { logger } from '../lib/logger';

export interface AutomationRule {
  id: string;
  name: string;
  description: string;
  eventType: string;
  enabled: boolean;
}

export const AUTOMATION_RULES: readonly AutomationRule[] = [...]; // 9 条

// 内存缓存
let configCache: Record<string, boolean> | null = null;
const CONFIG_FILE = join(process.cwd(), 'server/data/automation-config.json');
```

### 5.2 不变量

```typescript
// 配置读取永不抛错（失败时返回默认值，所有规则默认 enabled）
export function isRuleEnabled(ruleId: string): boolean {
  try {
    if (!configCache) loadConfig();
    return configCache?.[ruleId] ?? true;  // 默认 enabled
  } catch {
    return true;  // 失败也返回 true（不阻断业务）
  }
}

// 配置写入失败仅日志，不阻断 API 响应
export function setRuleEnabled(ruleId: string, enabled: boolean): void {
  try {
    if (!configCache) loadConfig();
    configCache![ruleId] = enabled;
    saveConfig();
  } catch (err) {
    logger.error('Failed to persist automation config', { err });
    // 不抛错，内存缓存已更新
  }
}
```

### 5.3 文件持久化

```typescript
function loadConfig(): void {
  if (!existsSync(CONFIG_FILE)) {
    configCache = {};
    return;
  }
  const raw = readFileSync(CONFIG_FILE, 'utf-8');
  configCache = JSON.parse(raw);
}

function saveConfig(): void {
  if (!existsSync(dirname(CONFIG_FILE))) {
    mkdirSync(dirname(CONFIG_FILE), { recursive: true });
  }
  writeFileSync(CONFIG_FILE, JSON.stringify(configCache, null, 2));
}
```

- 路径：`server/data/automation-config.json`
- 格式：`{ "L1_init_production": true, "L2_create_shipment": false, ... }`
- 启动时加载，API 修改时同步写盘

## §7 前端组件

### 7.1 AutomationRulesSection.tsx

```typescript
interface AutomationRulesSectionProps {
  isDarkMode: boolean;
}

export function AutomationRulesSection({ isDarkMode }: AutomationRulesSectionProps) {
  const [rules, setRules] = useState<AutomationRule[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  // 拉取规则列表
  useEffect(() => {
    apiService.listAutomationRules()
      .then(setRules)
      .catch(e => setError(e?.message || '加载失败'))
      .finally(() => setLoading(false));
  }, []);

  // 启停切换（乐观更新）
  const handleToggle = async (ruleId: string, enabled: boolean) => {
    const prev = rules;
    setRules(rules.map(r => r.id === ruleId ? { ...r, enabled } : r));  // 乐观更新
    try {
      await apiService.updateAutomationRule(ruleId, { enabled });
    } catch (e) {
      setRules(prev);  // 失败回滚
      setError(e?.message || '更新失败');
    }
  };

  return (
    <div>
      {/* 加载骨架 */}
      {/* 错误重试 */}
      {/* 空态 */}
      {/* 规则卡片列表 */}
      {rules.map(rule => (
        <RuleCard
          key={rule.id}
          rule={rule}
          onToggle={(enabled) => handleToggle(rule.id, enabled)}
        />
      ))}
    </div>
  );
}
```

### 7.3 乐观更新策略

```typescript
const handleToggle = async (ruleId, enabled) => {
  const prev = rules;
  setRules(rules.map(r => r.id === ruleId ? { ...r, enabled } : r));  // 即刻反映 UI
```

## §8 交互流程

### 8.1 加载规则

```
用户进入 Settings → automation Tab
  └─► AutomationRulesSection 挂载
      └─► apiService.listAutomationRules()
          ├─► 200: setRules(data) + setLoading(false)
          ├─► 401: setError('未授权')
          └─► 网络错误: setError('加载失败')
```

### 8.2 启停规则

```
用户点击规则卡片的 Toggle
  └─► handleToggle(ruleId, !currentEnabled)
      ├─► setRules(乐观更新)  // UI 即刻反映
      └─► apiService.updateAutomationRule(ruleId, { enabled })
          ├─► 200: 保持新状态
          └─► 失败: setRules(prev) + setError('更新失败')
```

### 8.3 事件触发

```
业务操作（如订单确认）
  └─► businessEventBus.publish({ type: 'OrderConfirmed', payload })
      └─► automationConfig 检查 L1/L6 规则是否 enabled
          ├─► L1 enabled: 触发初始化生产管线
          └─► L6 enabled: 触发生成 BOM 草稿
              └─► 下游服务执行（创建 Draft 状态的实体）
```

### 9.1 规则状态

```
              ┌─────────┐  enable (PATCH enabled=true)
              │ enabled │◄────────────────────────
              └────┬────┘
                   │ disable (PATCH enabled=false)
                   ▼
              ┌─────────┐
              │ disabled│  (事件不触发该规则)
              └────┬────┘
                   │ enable
                   ▼
              ┌─────────┐
              │ enabled │
              └─────────┘
```

### 9.2 事件触发条件

```
BusinessEvent 发布
  └─► for each rule in AUTOMATION_RULES:
      if rule.eventType === event.type AND isRuleEnabled(rule.id):
          trigger(rule, event)  // 触发下游操作
```

## §14 实现备注

### 14.1 单租户设计

```typescript
// 单租户桌面 ERP 场景，无需数据库迁移
// 配置存 server/data/automation-config.json
```

- 不接入 Prisma 数据库
- 文件持久化即可满足单租户需求
- 未来多租户时升级到 `SystemConfig` 表（scope='tenant::{tenantId}'）

### 14.2 草稿优先原则

所有触发的下游操作默认为 Draft 状态，需人工审核后确认。避免：

- 自动创建未审核的正式单据
- 数据不一致（如自动核销到错误发票）
- 业务流程跳过人工把关

### 14.3 幂等保证

- 同事件多次触发不会重复创建（通过业务唯一键去重）
- 如 L9：报价接受 → 转订单，同一报价多次接受事件只创建一个 Draft 订单
- 通过 `Order.quotationId` 唯一约束保证
