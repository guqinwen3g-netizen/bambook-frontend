## §1A 配置分层模型与平台配置迁移（2026-08-18 产品负责人裁决，阶段 1+2 合并实施）

> **裁决背景**：Settings 混入了 5 项平台级配置（MOQ/自动化/公司抬头/API 策略/脱敏），且 `visibleTabs` 唯一过滤是 `canUseAiChat`——任何登录角色可改全公司规则；公司抬头真源存本机 localStorage（见《公司档案与配置》§1A 纠偏）。本裁决确立**三层配置模型**，平台配置一律迁 AdminPanel（导航 `adminOnly: true` 守卫 + 服务端真源）。

### 1A.1 三层配置模型（唯一口径）

| 层 | 定义 | 真源 | 归宿 | 现有 Tab |
| --- | --- | --- | --- | --- |
| **个人偏好** | 只影响当前账号/当前设备体验 | 本机 + 账号 | Settings | account / appearance / ai / voice / storage |
| **本机连接** | 本客户端连后端/知识库的连接参数 | 本机（服务端下发默认值引导，缓行） | Settings（sync 语义收窄为「连接」） | sync + api 的「本客户端凭据」部分 |
| **平台配置** | 全公司生效的业务规则与主体信息 | **服务端** + RBAC | **AdminPanel**（新增 2 Tab，见《管理后台AdminPanel》§4.3） | moq / automation / company / api 策略部分 / security 脱敏 |

### 1A.2 迁移映射（Settings → AdminPanel）

| Settings Tab | 处置 | 目标位置 |
| --- | --- | --- |
| company 公司抬头 | **迁出**；真源改服务端 `SystemConfig global::company.exporterProfile`，localStorage 降级只读缓存 | AdminPanel「公司档案」Tab |
| moq MOQ 阈值 | **迁出**；`CompiledMoqThresholdsPanel` 顺势提级重写为普通组件（清 FR-004 compiled 遗留） | AdminPanel「平台规则」Tab |
| automation 自动化 | **迁出**（`AutomationRulesSection` 整迁 + 守卫） | AdminPanel「平台规则」Tab |
| api API | **拆分**：对外访问策略说明/密钥管理 → 迁出；本客户端凭据（sdkApiKey）并入 sync「连接」 | AdminPanel「平台规则」Tab / Settings sync |
| security 安全 | 脱敏占位开关**移除**（零占位铁律）；待平台脱敏规则设计后随「平台规则」重新引入；改密码等账号安全本就在 account | — |

迁移后 Settings 保留 6 Tab：account / appearance / ai / voice / sync（连接）/ storage，全部为个人层，**不再需要角色过滤**；平台层由 AdminPanel 导航 `adminOnly` 统一守卫。

### 1A.3 已登记缺口（实施时销号）

1. `visibleTabs` 无角色过滤：迁移完成前，任何登录角色可改 MOQ/自动化/公司抬头/API（P0 安全缺口，随迁移自然消除）。
2. §1 表中「company / api / security / automation / moq 已落地」口径自本裁决起标记为**迁移中**，以 §1A 为准。
3. 历史包袱销号：§1 第 15 行「需新增 business_rules Tab」诉求由 AdminPanel「平台规则」Tab 承接，Settings 内不再新增该 Tab。

## §2 业务定位与目标

### 2.1 业务定位

Settings 是 Bambook 的「**个性化与系统配置中枢**」——承载账号身份、外观主题、AI/语音/同步等所有偏好设置，并通过 `SystemConfig` 表持久化系统级配置。

### 2.2 双模式设计

| 模式 | 入口 | 默认 Tab | 用途 |
| --- | --- | --- | --- |
| `account` | 顶部「账号」入口 | `account` | 个人身份与登录管理 |
| `system` | 顶部「系统设置」入口 | `appearance` | 系统级配置 |

### 2.3 核心目标

1. **双模式隔离**：account 模式只展示个人相关 Tab，system 模式展示全部 Tab。
2. **配置真源分离**：用户偏好存本地（IndexedDB），系统配置存 `SystemConfig` 表。
3. **连通性可测**：主数据 API + 知识库 API 双端测试，含延迟日志。
4. **头像本地裁切**：Canvas 圆形裁切，避免服务端处理。
5. **BDS 主题一致**：全 Tab 使用 `BAMBOOK_OS` token，flat 设计统一。

### 5.5 MOQ 阈值配置（独立 MoqThresholdConfig 模型，非泛型 SystemConfig）

> **守卫**：读接口 `requireScope('settings:moq:read')` + `requireRole('SUPER_ADMIN','ADMIN')`；写接口 `requireScope('settings:moq:write')` + `requireRole('SUPER_ADMIN','ADMIN')`。

| 方法 | 路径 | 用途 | 关键约束 |
| --- | --- | --- | ---|
| GET | `/api/v1/moq-thresholds/current` | 获取当前 isActive=true 的生效配置（单条返回：{ fabricDefaultMoq, garmentDefaultMoq, capsuleMoq, effectiveFrom, configId, changedBy, changedAt }） | 始终只返回 1 条 isActive=true；若不存在则兜底返回 seed 默认值（800/200/20）及 source='fallback_constant' 标记 |
| GET | `/api/v1/moq-thresholds/history` | 分页获取 `MoqThresholdConfigHistory` append-only 变更历史（DESC 按 changedAt），含变更前后对比、变更人、变更理由 | query 参数：page/pageSize |
| POST | `/api/v1/moq-thresholds` | 提交新 MOQ 阈值配置（事务内：旧 isActive=true → 翻 false + effectiveTo=now；写入新 isActive=true 记录，effectiveFrom 默认为 now 或可指定 future 时间；append 一条 History） | body 字段：fabricDefaultMoq（正整数）、garmentDefaultMoq（正整数）、capsuleMoq（正整数）、changeReason（≥5 字字符串必填）、effectiveFrom（DateTime，可选，支持定时生效）；并发冲突通过「上次提交配置 ID 校验」乐观锁防止双管理员打架；生效方式默认不追溯（已 Confirmed 订单按 moqSnapshot 不变，新单按新值） |

### X.2 关键交互说明

| 项 | 说明 |
|---|---|
| 守卫显示 | 非 SUPER_ADMIN / ADMIN 打开 `business_rules` Tab → MOQ 配置卡片全部字段 disabled + Toast「暂无权限配置业务规则」+ 历史表格仅读 |
| 提交前校验 | fabricDefaultMoq / garmentDefaultMoq / capsuleMoq 必须为正整数；capsuleMoq 不得高于 garmentDefaultMoq（语义约束：Capsule 是降级豁免不应比成衣档更严格）；changeReason ≥5 字 |
| 乐观锁防冲突 | 提交 body 带 `lastSeenConfigId`（GET current 返回的 configId）→ 服务端校验与 DB 当前 isActive=true 的 ID 一致，不一致返回 409 Conflict「MOQ 配置已被其他管理员变更，请刷新后重试」 |
| 预览影响订单数（可选按钮） | 点击后调用 GET `/api/v1/moq-thresholds/preview-impact` → 返回按 Draft 状态订单估算：若按当前输入值生效，将有多少行订单行触发 MOQ 门禁（纯读接口，不真正修改配置） |
| 提交成功反馈 | Toast 「MOQ 新配置已提交，生效时间：{effectiveFrom}，已 Confirmed 订单不受影响（不追溯），新创建订单/报价按新值执行」+ 新配置自动 append 到历史表格首行 |
| 与 seed 默认值关系 | GET current 若 DB 无 isActive 记录 → 返回 seed 默认 800/200/20 且 payload.source='fallback_constant'，UI 在卡片右上角显示 ⚠️ Badge「当前使用兜底常量，建议首次提交一份配置以记录审计轨迹」 |

```typescript
const createCircularAvatarDataUrl = async (draft: AvatarCropDraft): Promise<string> => {
  const img = await loadAvatarImage(draft.src);
  const canvas = document.createElement('canvas');
  canvas.width = AVATAR_OUTPUT_SIZE;
  canvas.height = AVATAR_OUTPUT_SIZE;
  const ctx = canvas.getContext('2d');
  
  // 圆形裁切
  ctx.beginPath();
  ctx.arc(AVATAR_OUTPUT_SIZE/2, AVATAR_OUTPUT_SIZE/2, AVATAR_OUTPUT_SIZE/2, 0, Math.PI*2);
  ctx.clip();
  
  // 旋转 + 缩放 + 偏移
  ctx.translate(AVATAR_OUTPUT_SIZE/2 + draft.offset.x * offsetScale,
                AVATAR_OUTPUT_SIZE/2 + draft.offset.y * offsetScale);
  ctx.rotate((normalizedRotation * Math.PI) / 180);
  ctx.drawImage(img, -drawW/2, -drawH/2, drawW, drawH);
  
  return canvas.toDataURL('image/webp', 0.86);
};
```

### 7.3 输出

- 格式：webp（质量 0.86）
- 尺寸：256×256
- 形状：圆形（clip）
- 上传：base64 通过 `POST /api/v1/auth/avatar`

## §10 SystemConfig 数据模型

### 10.1 表结构

```prisma
model SystemConfig {
  id          String   @id          // `${scope}::${key}`
  scope       String   @default("global")
  key         String                  // 同 scope 唯一
  group       String                  // company/finance/tax/logistics/ui/rbac/ops/custom
  label       String                  // OPS Panel 展示用
  valueType   String                  // 'string'|'number'|'boolean'|'json'|'enum'
  value       Json?                    // 加密则存 "${iv.hex}.${cipher.hex}.${tag.hex}"
  encrypted   Boolean  @default(false) // AES-GCM
  version     Int      @default(1)
  description String?
  meta        Json?                    // { options?, min?, max?, placeholder? }
  updatedBy   String?
  auditReason String?
  createdAt   DateTime @default(now())
  updatedAt   BigInt

  @@unique([scope, key])
  @@index([group])
  @@index([scope])
  @@index([encrypted])
}
```

### 10.2 分组语义

| group | 用途 |
| --- | --- |
| `company` | 公司基本信息（名称/地址/联系方式） |
| `finance` | 财务（默认币种/汇率/利润比例/佣金率/账期阈值） |
| `tax` | 税务（VAT 率/退税率/开票限额/抬头） |
| `logistics` | 物流（Incoterm/起运港/货代） |
| `ui` | 界面（主题色/Logo/Dashboard 布局/语言） |
| `rbac` | 权限（密码长度/会话 TTL/锁定阈值） |
| `ops` | 运维（SMTP/OPS_TOKEN/备份/LLM 网关） |
| `custom` | 自定义 |

### 10.3 加密配置

- AES-GCM 加密
- 敏感配置（API_KEY / DB_URL / SMTP_PASSWORD / LLM_KEY）必须 `encrypted=true`
- 存储格式：`${iv.hex}.${cipher.hex}.${tag.hex}`

## §11 交互流程

### 11.1 修改密码

```
用户进入 account Tab → 点击「修改密码」
  └─► accountView = 'modify'
      └─► 输入 currentPw + newPw + confirmPw
          └─► authService.changePassword(currentPw, newPw)
              ├─► 200: setPwMsg({ ok: true, text: '密码已更新' })
              └─► 400: setPwMsg({ ok: false, text: '原密码错误' })
              └─► 422: setPwMsg({ ok: false, text: '新密码不符合复杂度要求' })
```

### 11.2 上传头像

```
用户点击头像 → 选择图片
  └─► readImageFileAsDataUrl(file) → dataUrl
      └─► setAvatarCrop({ src, fileName, naturalWidth, naturalHeight, scale:1, rotation:0, offset:{x:0,y:0} })

```

### 11.3 切换主题

```
用户在 appearance Tab 选择「深色模式」
  └─► setLocalConfig({ ...localConfig, themeMode: 'dark' })
      └─► onUpdateConfig(localConfig)
          └─► 父组件持久化到 IndexedDB + 应用主题
```

## §12 权限与访问控制

### 12.1 前端权限

- account Tab：所有已登录用户可访问（个人资料）
- 其他 Tab：要求 `settings:read` 权限
- automation Tab：要求 `settings:write` 权限修改规则

### 12.2 后端权限

- `/api/v1/auth/me`：JWT 鉴权（任何角色）
- `/api/v1/system-config` GET：JWT + `settings:read`
- `/api/v1/system-config` PATCH：JWT + `settings:write` + owner/admin
- 加密配置读取：仅 owner/admin 可见明文（其他角色返回 mask）

### 12.3 SystemConfig 加密保护

- `encrypted=true` 的配置，GET 时：
  - owner/admin → 返回明文 value
  - 其他角色 → 返回 `null` + `description: 'encrypted'`
- 防止 API_KEY / SMTP_PASSWORD 泄露给普通用户
