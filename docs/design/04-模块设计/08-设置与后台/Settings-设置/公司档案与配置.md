## §1A 真源与归宿裁决（2026-08-18 产品负责人裁决，阶段 1+2 合并实施）

**规范条文：**

1. **唯一真源 = 服务端**：exporterProfile 真源为 `SystemConfig global::company.exporterProfile`（schema 在位，`systemConfigService` 全套在位）；本机 localStorage 降级为**只读缓存**（离线兜底，启动时由服务端值刷新，禁止反向写入）。
2. **写入口唯一 = AdminPanel「公司档案」Tab**：Settings company Tab 移除（见《账户与系统配置》§1A 三层配置模型）；写操作走新建 `PUT /api/v1/config/company.exporterProfile`（新建 systemConfigRoute），RBAC 仅 `SUPER_ADMIN`/`ADMIN`；GET 全登录可读（单据生成链路依赖）。
3. **单据链路换源**：`getExporterProfile()` 改为「服务端值 → 本机缓存 → 代码默认值」三级回退；单据模板（CI/PL/BL/CO/INS/Contract/Quote/样品发票）消费方零改动（只换数据源函数实现）。
4. **审计闭环**：写操作经 `systemConfigService.set` 落 `SystemConfigHistory`（versionFrom/To + actorId + reason）；银行字段（bankName/swiftCode/usdAccountNumber）变更在 AdminPanel UI 要求填写变更理由。
5. **迁移**：seed/迁移脚本把当前代码默认值写入服务端（若 `global::company.exporterProfile` 不存在）；现网各机 localStorage 值**不自动上传**（防脏值扩散），由管理员在 AdminPanel 一次配置后全公司生效。

## §2 业务定位与目标

### 2.1 业务定位

公司档案是 Bambook 的「**出口方真源**」——所有外贸单据（CI/PL/Contract/Quote）的抬头信息、银行付款信息、收款账号均从此处引用，确保：

- **一致**：所有单据使用同一套抬头，避免字段不一致
- **可改**：修改后立即生效，后续生成的单据自动引用新值
- **可审**：变更历史可追溯

### 2.2 核心目标

1. **单据抬头真源**：exporterProfile 是 CI/PL/Contract 的唯一抬头来源
2. **银行信息集中**：付款条款引用的银行信息集中管理
3. **实时生效**：修改后立即写入 SystemConfig，后续单据引用新值
4. **审计可追溯**：SystemConfigHistory 记录每次变更
5. **占位符引导**：每个字段含真实业务占位符，引导用户填写

## §4 数据模型

### 4.1 exporterProfile 结构

```typescript
interface ExporterProfile {
```

## §5 字段详情

### 5.1 出口方/公司抬头卡片

| 字段 | 类型 | 占位符 | 用途 |
| --- | --- | --- | --- |
| `nameEn` | string | `JIANGSU PANDA CLOTHING CO.,LTD.` | CI/PL/Contract 抬头 |
| `beneficiary` | string | `JIANGSU PANDA CLOTHING CO.,LTD.` | 银行/保险单据受益人 |
| `addressEn` | textarea | `ROOM A1028 WUYUE PLAZA,\nZHANGJIAGANG CITY, 215600 PR\nCHINA` | 单据地址（多行） |

### 5.2 银行信息卡片

| 字段 | 类型 | 占位符 | 用途 |
| --- | --- | --- | --- |
| `bankName` | string | `BANK OF CHINA ZHANGJIAGANG SUB-BRANCH` | CI 付款条款引用 |
| `swiftCode` | string | `BKCHCNBJ95L` | 银行识别码 |
| `bankAddress` | string | `111 MIDDLE RENMIN ROAD, ZHANGJIAGANG CITY, SUZHOU, JIANGSU PROV., P.R.CHINA.` | 银行地址 |
| `usdAccountNumber` | string | `467668133096` | USD 收款账号 |

### 5.3 字段说明

- **nameEn vs beneficiary**：通常相同，但某些场景受益人可能是子公司或关联公司
- **addressEn 多行**：用换行符分隔，单据渲染时保留换行
- **swiftCode**：8 或 11 位字母数字，银行唯一识别码
- **usdAccountNumber**：美元收款账号，用于 T/T 付款

### 7.2 更新逻辑

```typescript
const handleUpdate = (key: string, value: any) => {
  const next = { ...localConfig, [key]: value };
  setLocalConfig(next);
  onUpdateConfig(next);  // 通知父组件持久化
};
```

- 修改后立即调用 `onUpdateConfig`（无需点击「保存」按钮）
- 父组件负责持久化到 SystemConfig

### 7.3 布局

- **桌面**：`grid-cols-1 sm:grid-cols-2`，两列布局
- **地址/银行地址**：`sm:col-span-2`，跨两列
- **textarea**：`min-h-[60px] resize-y`，可调整高度

## §8 单据引用

### 8.1 引用场景

| 单据 | 引用字段 | 用途 |
| --- | --- | --- |
| Commercial Invoice | nameEn + addressEn | 卖方抬头 |
| Packing List | nameEn + addressEn | 卖方抬头 |
| Contract | nameEn + addressEn | 甲方/卖方 |
| Quotation | nameEn + addressEn | 报价方 |
| 报关单 | nameEn + addressEn | 发货单位 |
| 银行单据 | beneficiary + bankName + swiftCode + bankAddress + usdAccountNumber | 收款信息 |

### 8.2 引用方式

- 单据生成时从 `SystemConfig` 读取 `exporterProfile`
- 渲染到单据模板的 `{{exporterName}}` `{{exporterAddress}}` `{{bankName}}` 等占位符
- 修改 exporterProfile 后，新生成的单据自动引用新值

## §9 交互流程

### 9.1 修改公司抬头

```
用户进入 Settings → company Tab
  └─► 修改「公司英文名」字段
      └─► onChange: handleUpdate('exporterProfile', { ...localConfig.exporterProfile, nameEn: value })
          └─► setLocalConfig(next) + onUpdateConfig(next)
              └─► 父组件持久化到 SystemConfig
                  └─► PATCH /api/v1/system-config/global::company.exporterProfile
                      ├─► 200: version +1 + SystemConfigHistory 记录
                      └─► 失败: 回滚（前端显示错误）
```

### 9.2 单据引用

```
用户生成 Commercial Invoice
  └─► 单据引擎读取 SystemConfig.exporterProfile
      └─► 渲染到模板：
          ├─ 卖方：{{exporterProfile.nameEn}}
          ├─ 地址：{{exporterProfile.addressEn}}
          └─ 付款条款：T/T 30 days to {{exporterProfile.bankName}} {{exporterProfile.swiftCode}} {{exporterProfile.usdAccountNumber}}
```

## §10 权限与访问控制

### 10.1 前端权限

- company Tab 入口要求 `settings:read` 权限
- 修改要求 `settings:write` 权限
- 通常仅 owner/admin/finance 角色可修改

### 10.2 后端权限

- GET SystemConfig：JWT + `settings:read`
- PATCH SystemConfig：JWT + `settings:write` + owner/admin
- exporterProfile 非加密，所有有 `settings:read` 的角色可见

### 10.3 敏感字段保护

- `usdAccountNumber` 当前**非加密**（便于单据引擎读取）
- 未来扩展：敏感字段加密，单据引擎通过专用解密 API 读取

## §13 已知限制与未来扩展

### 13.1 当前限制

- ❌ 仅 USD 账号字段，**无多币种账号**（EUR/CNY/HKD 等）
- ❌ 仅英文名/地址，**无中文**（部分国内单据需中文）
- ❌ 无**公司 Logo 上传**（单据抬头 Logo）
- ❌ 无**多套抬头**（子公司/关联公司场景需多套）
- ❌ `usdAccountNumber` 非加密（敏感信息）
- ❌ 无**SWIFT Code 格式校验**（8 或 11 位字母数字）

### 13.2 未来扩展

- 多币种账号：`accounts: { USD: '...', EUR: '...', CNY: '...' }`
- 中英文双套：`nameCn` / `nameEn` / `addressCn` / `addressEn`
- 公司 Logo 上传 + 单据引用
- 多套抬头：`profiles: ExporterProfile[]` + 默认标记
- SWIFT Code 格式校验
- 敏感字段加密（AES-GCM）
