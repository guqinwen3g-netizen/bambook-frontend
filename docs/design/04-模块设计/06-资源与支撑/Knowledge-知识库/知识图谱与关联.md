## §2 业务定位与目标

### 2.1 业务定位

知识图谱是 Bambook 知识库的「**关联层**」——把知识文档与业务实体（订单/客户/产品/供应商等）双向链接，支撑：

- **正向查询**：这篇文档提到了哪些业务实体？
- **反向查询**：这个订单被哪些知识文档提到过？
- **横向查询**：这个客户还关联了哪些其他实体（产品/订单/发票）？

### 2.2 两层图谱

| 层 | 表 | 边类型 | 用途 |
| --- | --- | --- | --- |
| 知识↔实体 | `KnowledgeRelation` | `relationType`（mentions/refs/cites...） | 文档提到业务实体 |
| 实体↔实体 | `EntityLink` | `linkKind`（aboutOrder/aboutInvoice/customerOf...） | 业务实体横向关联 |

### 2.3 核心目标

1. **零新增模型**：复用既有 `KnowledgeRelation` + `EntityLink` 两张表，不引入新模型。
2. **只读优先**：当前只做结构化关联读取，写入由摄取时 LLM 抽取或 Agent 工具承担。
3. **置信度排序**：所有查询按 `confidence desc` 排序，高置信度优先。
4. **N+1 避免**：`loadDocTitles` 批量查询文档标题，避免逐条查询。
5. **软删除过滤**：所有查询默认过滤 `deletedAt: null` + `status: 'active'`。
6. **上限保护**：所有查询 `take: 200`，防止超大结果集。

## §3 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| `KnowledgeRelation` | 知识文档/块 ↔ 业务实体的关联边 |
| `EntityLink` | 业务实体 ↔ 业务实体的双向链接边 |
| `relationType` | 关联类型（如 `mentions_product` / `refs_order` / `cites_customer`） |
| `linkKind` | 链接类型（如 `aboutOrder` / `aboutInvoice` / `customerOf` / `sentBy`） |
| `confidence` | 置信度（0-1），用于排序；默认 0.7 |
| `targetType` | 目标实体类型（如 `order` / `relation` / `product` / `invoice`） |
| `targetId` | 目标实体 ID |
| `KnowledgeRelationView` | 前端视图对象：含 documentId/documentTitle/chunkId/relationType/targetType/targetId/confidence/createdAt |
| `EntityLinkView` | 前端视图对象：含 fromType/fromId/toType/toId/linkKind/confidence/source |
| `loadDocTitles` | 批量查询文档标题的工具函数，避免 N+1 |

## §4 数据模型

### 4.1 KnowledgeRelation 表

```prisma
model KnowledgeRelation {
  id           String   @id
  documentId   String?
  chunkId      String?
  relationType String
  targetType   String
  targetId     String
  confidence   Float    @default(0.7)
  createdAt    DateTime @default(now())

  document KnowledgeDocument? @relation(fields: [documentId], references: [id], onDelete: Cascade)
  chunk    KnowledgeChunk?    @relation(fields: [chunkId], references: [id], onDelete: Cascade)

  @@index([documentId])
  @@index([chunkId])
  @@index([targetType, targetId])
  @@index([relationType])
}
```

### 4.2 EntityLink 表

```prisma
model EntityLink {
  id         String  @id
  fromType   String
  fromId     String
  fromPath   String?
  toType     String
  toId       String
  toPath     String?
  linkKind   String
  confidence Float?
  metadata   Json?
  source     String?
  status     String  @default("active")
  createdAt  BigInt
  updatedAt  BigInt
  deletedAt  BigInt?

  @@index([fromType, fromId])
  @@index([toType, toId])
  @@index([linkKind])
  @@index([status])
  @@index([source])
}
```

#### 6.2.1 listDocumentRelations

```typescript
export async function listDocumentRelations(prisma, documentId): Promise<KnowledgeRelationView[]> {
  const rows = await prisma.knowledgeRelation.findMany({
    where: { documentId },
    orderBy: [{ confidence: 'desc' }, { createdAt: 'asc' }],
    take: 200,
  });
  const titles = await loadDocTitles(prisma, rows);
  return rows.map(r => toRelationView(r, titles));
}
```

```typescript
export async function listEntityKnowledgeRelations(
```

```typescript
      deletedAt: null,

        { toType: entityType, toId: entityId },
      ],
    },
    orderBy: [{ confidence: 'desc' }],
    take: 200,
  });

}
```

### 6.3 N+1 避免策略

```typescript
async function loadDocTitles(prisma, rows): Promise<Map<string, string>> {
  const ids = [...new Set(rows.map(r => r.documentId).filter(Boolean))];
  if (ids.length === 0) return new Map();
  const docs = await prisma.knowledgeDocument.findMany({
    where: { id: { in: ids }, deletedAt: null },
    select: { id: true, title: true },
  });
  return new Map(docs.map(d => [d.id, d.title]));
}
```

- 收集所有 `documentId` 去重
- 单次 `findMany` 批量查询
- 返回 `Map<id, title>` 供 `toRelationView` 查找

## §7 前端组件

### 7.1 KnowledgeBase.tsx 详情关联区块

```typescript
// 状态
const [viewingItem, setViewingItem] = useState<KnowledgeItem | null>(null);
const [viewingRelations, setViewingRelations] = useState<KnowledgeRelationView[]>([]);
const [relationsLoading, setRelationsLoading] = useState(false);

// 详情打开时加载关联
useEffect(() => {
  if (!viewingItemId) { setViewingRelations([]); return; }
  let cancelled = false;
  setRelationsLoading(true);
  apiService.listKnowledgeDocumentRelations(viewingItemId)
    .then(r => { if (!cancelled) setViewingRelations(r); })
    .catch(() => { if (!cancelled) setViewingRelations([]); })
    .finally(() => { if (!cancelled) setRelationsLoading(false); });
  return () => { cancelled = true; };
}, [viewingItemId]);
```

### 7.2 渲染逻辑

```tsx
{/* 详情面板内的关联区块 */}
<div>
  <div>关联实体 ({viewingRelations.length})</div>
  {relationsLoading ? (
    <div>加载中...</div>
  ) : viewingRelations.length === 0 ? (
    <div>暂无关联</div>
  ) : (
    viewingRelations.map(rel => (
      <div key={rel.id}>
        <span>{rel.relationType}</span>
        <span>{rel.targetType}: {rel.targetId}</span>
        <span>置信度: {(rel.confidence * 100).toFixed(0)}%</span>
      </div>
    ))
  )}
</div>
```

### 7.3 失败降级

```typescript
.catch(() => { if (!cancelled) setViewingRelations([]); })
```

- 关联加载失败**静默为空区块**，不阻断详情浏览
- 不显示错误提示（关联是辅助信息，非核心）

## §10 权限与访问控制

### 10.1 路由级守卫

- 三个 GET 端点统一走 `createModuleAuthGuard({ requireAuth, apiKeys })`
- 要求 JWT + `knowledge:read` 权限
- API-Key 单独访问 → 401

### 10.2 行级 ACL

- `KnowledgeRelation` 本身**不直接受** `KnowledgeAcl` 控制
- 但通过 `documentId` 关联的 `KnowledgeDocument` 受 ACL 控制
- 查询时 `loadDocTitles` 过滤 `deletedAt: null`，但不检查 ACL（未来扩展）

### 10.3 跨模块访问

- 实体反向关联端点 `/entities/:type/:id/relations` 可被其他模块调用
- 调用方需自行校验用户对该实体的访问权限（如订单详情页需先校验 `orders:read`）

## §13 已知限制与未来扩展

### 13.1 当前限制

- ❌ 关联写入无直接 API（依赖摄取时 LLM 抽取或 Agent 工具）
- ❌ 无全图可视化（D3/Cytoscape）
- ❌ `KnowledgeRelation` 不直接受 `KnowledgeAcl` 控制（通过 documentId 间接）
- ❌ 置信度无自动更新机制（写入时设定，不随阅读反馈调整）
- ❌ 无关联类型枚举约束（relationType 为自由字符串）

### 13.2 未来扩展

- 关联写入 API（`POST /relations`）+ 审计
- 全图可视化（D3.js 力导向图 / Cytoscape）
- 关联类型枚举约束（`mentions_product` / `refs_order` / `cites_customer` 等）
- 置信度自动调整（用户点击/忽略反馈 → confidence ± 调整）
- 跨实体 360° 视图（聚合 KnowledgeRelation + EntityLink + 业务数据）
