## §2 业务定位与目标

### 2.1 业务定位

归档问答知识是 Bambook 知识库的「**反哺闭环**」——RAG 问答产生的优质 Q&A 可一键归档为 `KnowledgeDocument`，进入检索池供后续相似问题命中。形成：

```
提问 → RAG 回答 → 优质 Q&A → 归档 → 进入检索池 → 下次相似问题命中
```

### 2.2 与其他 sourceType 的区别

| sourceType | 来源 | 业务场景 |
| --- | --- | --- |
| `manual` | 用户手动录入 | 官方知识文档 |
| `sop` | SOP 模板实例化 | 标准作业流程 |
| `qa` | RAG 问答归档 | 优质问答沉淀 |
| `web` | 网页抽取 | 外部资料 |
| `import` | 批量导入 | 历史数据迁移 |
| `agent` | Agent 工具写入 | AI 自动学习 |

### 2.3 核心目标

1. **闭环反哺**：Q&A 归档后进入检索池，下次相似问题可直接命中。
2. **幂等防重**：同内容（Q+A 完全相同）归档多次只入库一次。
3. **分类可检索**：归档时必须选择 category，便于过滤。
4. **sourceType 可区分**：`sourceType='qa'` 便于后续统计 Q&A 归档质量。
5. **审计可追溯**：归档操作同事务写 AuditLog。

## §3 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| `归档` | 把 Q&A 包装为 `KnowledgeDocument` 入库 |
| `sourceType='qa'` | 归档 Q&A 的专属来源标记 |
| `qaArchiveCategory` | 归档时选择的分类（6 选 1，默认 Company） |
| `qaArchived` | 归档状态布尔（true=已归档，显示成功提示） |
| `qaArchiving` | 归档中状态布尔（true=正在归档，按钮禁用） |
| `title 生成规则` | `问答：${q.slice(0, 40)}${q.length > 40 ? '…' : ''}` |
| `text 拼接规则` | `问题：${q}\n\n回答：${a}` |
| `checksum 幂等` | SHA-256(text)，同内容不重复入库 |

## §4 数据流概览

### 4.1 归档全链路

```
用户在 qa tab 提问 "SS26 季节面料采购流程是什么？"
  └─► RAG 流式回答 + 引用展示
      └─► 用户判断答案有价值
          └─► 选择 category（默认 Company）
              └─► 点击「归档到官方知识库」按钮
                  │
                  ▼
┌──────────────────────────────────────────────────┐
│  前端 handleArchiveQa()                          │
│  ├─ title = `问答：${q.slice(0, 40)}${q.length > 40 ? '…' : ''}`│
│  ├─ text = `问题：${q}\n\n回答：${a}`             │
│  └─ apiService.ingestKnowledgeText({             │
│       title, text,                                │
│       category: qaArchiveCategory,                │
│       sourceType: 'qa'                            │
│     })                                            │
└──────────────────────────────────────────────────┘
                  │
                  ▼
┌──────────────────────────────────────────────────┐
│  Node /api/v1/knowledge/ingest                   │
│  └─ ingestKnowledgeDocument({                    │
│       title, text, sourceType: 'qa',              │
│       category, metadata: { sourceType: 'qa' }   │
│     })                                            │
│  ├─ 校验 + SHA-256 checksum                       │
│  ├─ 分块（800 字/块，overlap 100）                │
│  ├─ KnowledgeDocument + N×KnowledgeChunk 入库     │
│  └─ AuditLog 同事务写入                           │
└──────────────────────────────────────────────────┘
                  │
                  ▼
┌──────────────────────────────────────────────────┐
│  返回 { documentId, checksum, chunkCount, auditId }│
│  ├─ setKnowledge([new, ...])                     │
│  ├─ setQaArchived(true)                          │
│  └─ 显示「已归档到官方知识库」成功提示             │
└──────────────────────────────────────────────────┘
```

### 4.2 反哺检索池

```
下次用户提问相似问题 "SS26 采购流程"
  └─► RAG 检索 top-K chunks
      └─► 命中归档的 Q&A 文档分块
          └─► 引用展示（sourceType='qa' 标记）
```

## §5 API 端点

### 5.1 归档端点

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/v1/knowledge/ingest` | 摄取知识文本（含 sourceType='qa'） |

### 5.2 请求体

```typescript
{
  title: string;       // 问答：${q.slice(0, 40)}${q.length > 40 ? '…' : ''}
  text: string;        // 问题：${q}\n\n回答：${a}
  category: string;    // 6 选 1：Product/Policy/Customer/Production/Company/Supplier
  sourceType?: string; // 'qa'（默认 'manual'）
  metadata?: object;   // 可选：{ askedAt, askedBy, originalCitations? }
}
```

### 5.3 响应

```typescript
{
  documentId: string;
  checksum: string;
  chunkCount: number;
  auditId: string;
}
```

### 5.4 错误码

| code | HTTP | 说明 |
| --- | --- | --- |
| `INVALID_INPUT` | 400 | title/text 为空或超长 |
| `DUPLICATE_CHECKSUM` | 200 | 同内容已入库，返回原 documentId（非错误） |
| `CREATE_FAILED` | 500 | 数据库写入失败 |
| `AUDIT_FAILED` | 500 | 审计日志写入失败 |

## §6 服务层

### 6.1 前端归档函数

```typescript
const handleArchiveQa = async () => {
  const q = qaQuestion.trim();
  const a = qaAnswer.trim();
  if (!q || !a || qaArchiving || qaArchived) return;
  setQaArchiving(true);
  setQaError(null);
  try {
    const title = `问答：${q.slice(0, 40)}${q.length > 40 ? '…' : ''}`;
    const text = `问题：${q}\n\n回答：${a}`;
    const json = await apiService.ingestKnowledgeText({
      title, text, category: qaArchiveCategory, sourceType: 'qa'
    });
    const item: KnowledgeItem = {
      id: json.documentId,
      title,
      content: text,
      category: qaArchiveCategory,
      updatedAt: Date.now(),
      sourceUrl: `checksum:${json.checksum}|chunks:${json.chunkCount}|audit:${json.auditId}`,
    };
    setKnowledge([item, ...knowledgeRef.current], item);
    setQaArchived(true);
  } catch (e: any) {
    setQaError(e?.message || '归档失败，请稍后重试');
  } finally {
    setQaArchiving(false);
  }
};
```

### 6.2 后端摄取管线（复用）

- 入口：`ingestKnowledgeDocument`
- 校验：title 非空、text ≤ 200KB
- checksum：SHA-256(text) 幂等
- 分块：按段落 + 800 字/块，overlap 100
- 入库：`KnowledgeDocument` + N × `KnowledgeChunk`（同事务）
- 审计：`writeRouteAuditLog(operation='knowledge_document_create', targetType='knowledge_document')`

### 7.2 状态流转

```typescript
// 初始

// 失败
```

### 7.3 按钮禁用条件


- 回答为空：禁用
- 正在流式回答：禁用
- 正在归档：禁用
- 已归档：禁用（显示成功提示替代按钮）

## §8 交互流程

### 8.1 完整归档流程

```
1. 用户提问
2. RAG 流式回答 + 引用展示
3. 回答完成后显示「归档」按钮 + category 下拉
4. 用户选择 category（默认 Company）
5. 用户点击「归档到官方知识库」
   ├─► 按钮禁用 + 显示「归档中…」
   ├─► apiService.ingestKnowledgeText({ title, text, category, sourceType: 'qa' })
   │   ├─► 200: setQaArchived(true) + setKnowledge([new, ...])
   │   │        显示「已归档到官方知识库」
   │   └─► 失败: setQaError(e.message) + 按钮恢复
   └─► 用户可切换到 official tab 查看新文档
```

### 8.2 幂等场景

```
用户对同一 Q&A 多次点击归档
  ├─► 第一次: 入库成功 + checksum 记录
  ├─► 第二次: checksum 命中 → 返回原 documentId（不重复入库）
  └─► 用户体验: 每次都显示「已归档」（不感知幂等）
```

### 8.3 离线场景

```
归档时网络断开
  └─► apiService.ingestKnowledgeText 抛错
      └─► setQaError('归档失败，请稍后重试')
          └─► 按钮恢复可用，用户可重试
```

## §10 权限与访问控制

### 10.1 归档权限

- 归档操作要求 `knowledge:write` 权限
- 前端 qa Tab 入口要求 `knowledge:read` 权限（查看回答）
- 写入操作走 `createModuleAuthGuard` + JWT 鉴权

### 10.2 行级 ACL

- 归档生成的 `KnowledgeDocument` 默认 `scope='company'`（全公司可见）
- 未来扩展：归档时选择 scope（company/department/team/private）

### 10.3 审计

- `writeRouteAuditLog` 同事务写入
- `actorId` 从 JWT 解析
- `detail` 含 `{ documentId, checksum, chunkCount, sourceType: 'qa' }`

## §13 已知限制与未来扩展

### 13.1 当前限制

- ❌ 归档 Q&A **无引用继承**：原 RAG 回答的 `KnowledgeCitation[]` 未保存到 metadata
- ❌ 归档 Q&A **无提问者记录**：metadata 未记录 `askedBy` / `askedAt`
- ❌ 归档 Q&A **无质量评分**：无法标记「有用/无用」
- ❌ 归档 Q&A **无去重提示**：幂等命中时用户不感知（已归档过）
- ❌ 归档 Q&A **无 scope 选择**：默认 company，无法选 department/team/private

### 13.2 未来扩展

- 引用继承：metadata 记录 `originalCitations: KnowledgeCitation[]`
- 提问者记录：metadata 记录 `askedBy` / `askedAt`
- 质量评分：增加 `usefulCount` / `notUsefulCount` 字段
- 去重提示：幂等命中时提示「此问答已归档于 {date}」
- scope 选择：归档时选择 company/department/team/private
- 自动归档：高质量 Q&A（如用户停留时间长 + 多次相似提问）自动归档

## §14 实现备注

### 14.1 title 截断规则

```typescript
const title = `问答：${q.slice(0, 40)}${q.length > 40 ? '…' : ''}`;
```

- 截断长度：40 字符
- 省略号：`…`（单字符，非三个点 `...`）
- 前缀：`问答：`（中文冒号）

### 14.2 text 拼接规则

```typescript
const text = `问题：${q}\n\n回答：${a}`;
```

- 格式：markdown 纯文本
- 分隔：两个换行符 `\n\n`
- 前缀：`问题：` / `回答：`（中文冒号）

### 14.3 sourceUrl 标记

```typescript
sourceUrl: `checksum:${json.checksum}|chunks:${json.chunkCount}|audit:${json.auditId}`
```

- 用于 official Tab 列表卡片显示来源信息
- 便于反查审计日志
