## §2 业务定位与目标

### 2.1 业务定位

`Knowledge` 是 Bambook 的「**企业知识中枢**」——承载 SOP 标准作业流程、外贸知识文档、客户/产品/工艺档案、智能问答记忆四类显性知识，并通过 RAG 检索为 Agent 与一线员工提供「**带引用的答案**」。

与 `Products` 数字档案（以物为中心）不同，Knowledge 以「**知识与文档**」为中心，关注：
- **可复用**：SOP 模板可被多次实例化为知识文档
- **可检索**：分块 + 向量化 + RAG 引用
- **可关联**：知识 ↔ 业务实体（订单/客户/产品）双向图谱
- **可权限化**：行级 ACL（scope = company/department/team/private）

### 2.2 三层定位

| 层 | 载体 | 业务用途 |
| --- | --- | --- |
| 模板层 | `SopTemplate` | 可复用的流程知识骨架（title + content + steps） |
| 文档层 | `KnowledgeDocument` + `KnowledgeChunk` | 入库的知识文档（含分块、embedding、checksum 幂等） |
| 应用层 | RAG 问答 + 图谱关联 + Insight 备忘 | 前端 4 Tab 入口，支撑日常查询与 Agent 引用 |

### 2.3 核心目标

1. **一物一源**：每篇知识文档全局唯一 `id`，`checksum` 幂等防重复入库。
2. **模板与实例分离**：`SopTemplate` 是骨架，实例化生成 `KnowledgeDocument` 进入检索池。
3. **图谱双向关联**：`KnowledgeRelation` 正向（知识 → 实体）+ `EntityLink` 横向（实体 ↔ 实体）。
4. **RAG 引用可追溯**：每条 AI 答案必须返回 `KnowledgeCitation[]`，无引用即不可信。
5. **权限分层**：`KnowledgeAcl` 行级控制 read/write/admin，按 scope 四档隔离。
6. **离线降级**：客户端探活失败时降级为本地 IndexedDB 快照只读视图。

## §3 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| `KnowledgeDocument` | 知识文档聚合根，含 title/sourceType/sourceUri/checksum/version/status/metadata |
| `KnowledgeChunk` | 文档分块，含 content/summary/tags/embedding/sourceRange，唯一约束 `[documentId, chunkIndex]` |
| `KnowledgeRelation` | 知识 ↔ 业务实体关联（如「这篇文档提到订单 #1234」），含 relationType/targetType/targetId/confidence |
| `KnowledgeAcl` | 行级权限控制（scope = company/department/team/private × access = read/write/admin/none） |
| `SopTemplate` | SOP 模板（title + category + summary + content + steps），可实例化为 `KnowledgeDocument` |
| `EntityLink` | 业务实体 ↔ 业务实体双向链接（fromType/fromId ↔ toType/toId + linkKind + confidence） |
| `KnowledgeCitation` | RAG 答案引用（documentId + chunkId + content snippet + score），前端渲染为引用卡片 |
| `sourceType` | 文档来源类型枚举：`manual` / `sop` / `web` / `import` / `agent` |
| `checksum` | SHA-256 内容指纹，用于幂等防重复入库 |
| `KB_CATEGORIES` | 前端固定 6 分类：Product / Policy / Customer / Production / Company / Supplier |

## §5 API 端点

### 5.1 知识文档摄取（`/api/v1/knowledge/documents`）

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/v1/knowledge/ingest` | 摄取知识文本（title + text + category），返回 `{ documentId, checksum, chunkCount, auditId }` |
| GET | `/api/v1/knowledge/documents` | 列出知识文档（支持 category/status 过滤） |
| GET | `/api/v1/knowledge/documents/:id` | 获取单篇文档详情 |
| PATCH | `/api/v1/knowledge/documents/:id` | 更新文档（重新分块 + 版本+1 + checksum 重算） |
| DELETE | `/api/v1/knowledge/documents/:id` | 软删除（`deletedAt = now()`） |

### 5.2 SOP 模板（`/api/v1/knowledge/sop-templates`）

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/sop-templates` | 列出模板（支持 category/status 过滤） |
| POST | `/sop-templates` | 创建模板（返回完整 record） |
| PATCH | `/sop-templates/:id` | 更新模板（版本+1） |
| DELETE | `/sop-templates/:id` | 软删除（status='archived' + deletedAt） |
| POST | `/sop-templates/:id/instantiate` | 实例化为知识文档（sourceType='sop'） |

### 5.3 知识图谱（`/api/v1/knowledge/relations`）

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/documents/:id/relations` | 列出某文档的全部实体关联（按 confidence desc） |
| GET | `/entities/:type/:id/relations` | 反向检索：哪些文档提到了某实体 |
| GET | `/entities/:type/:id/links` | 列出某实体的双向 EntityLink |

### 5.4 RAG 问答（`/v1/chat` · Python 服务）

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/v1/chat` | 流式问答（SSE），返回 `{ answer, citations[] }` |
| POST | `/v1/knowledge/search` | 向量检索，返回 top-K chunks + score |

## §6 服务层架构

```
┌─────────────────────────────────────────────────────┐
│  前端 KnowledgeBase.tsx                              │
│  ├─ official tab  ── apiService.listKnowledgeDocuments
│  ├─ memory tab    ── 本地 IndexedDB Insight
│  ├─ qa tab        ── knowledgeApiService.streamKnowledgeChat
│  └─ sop tab       ── apiService.listSopTemplates
└──────────────┬──────────────────────────────────────┘
               │
    ┌──────────▼─────────────────────────────┐
    │  Node.js /api/v1/knowledge               │
    │  knowledgeRoute.ts                       │
    │  ├─ sopTemplateService.ts (CRUD + 实例化)│
    │  ├─ knowledgeGraphService.ts (只读查询)  │
    │  └─ knowledgeIngestService.ts (摄取管线) │
    └──────────┬─────────────────────────────┘
               │ HTTP
    ┌──────────▼─────────────────────────────┐
    │  Python FastAPI /v1/chat                 │
    │  knowledge_api/app/main.py               │
    │  ├─ 向量检索 (top-K chunks)             │
    │  ├─ LLM 流式生成 (带 citations)         │
    │  └─ 三层广告过滤 (a/b/c 层)              │
    └──────────────────────────────────────────┘
```

### 6.1 摄取管线（knowledgeIngestService）

1. **输入校验**：title 非空、content ≤ 200KB、sourceType 枚举
2. **checksum 计算**：SHA-256(content) 去重（已存在同 checksum → 返回原 documentId）
3. **分块**：按段落 + 字数（默认 800 字 / 块，overlap 100）
4. **入库**：`KnowledgeDocument` + N × `KnowledgeChunk`（同事务）
5. **审计**：`writeRouteAuditLog(action='create', targetType='knowledge_document')`
6. **回调**：`onDataChange?.({ entity: 'knowledge-document', action: 'create' })`

### 6.2 SOP 实例化管线（instantiateSopTemplate）

1. 读取 `SopTemplate`（必须是 active，archived 报 409）
2. 渲染 content + steps 为 markdown 正文
3. 调用 `ingestKnowledgeDocument`（sourceType='sop'，metadata.templateId + templateVersion）
4. 返回 `{ documentId, checksum, chunkCount, templateVersion }`
5. 审计日志关联 templateId 与新 documentId

## §7 前端组件架构

### 7.1 KnowledgeBase.tsx 4 Tab

| Tab | 名称 | 数据源 | 操作 |
| --- | --- | --- | --- |
| `official` | 官方知识 | `apiService.listKnowledgeDocuments()` + 本地快照合并 | CRUD + 详情 + 关联视图 |
| `memory` | 备忘 Insight | 本地 IndexedDB（`insights[]`） | 增删改 + 置顶 |
| `qa` | 智能问答 | `knowledgeApiService.streamKnowledgeChat`（Python SSE） | 提问 + 引用展示 + 归档到知识库 |
| `sop` | SOP 模板 | `apiService.listSopTemplates()` | CRUD + 详情 + 实例化 |

### 7.2 离线降级策略

- **official tab**：服务端条目为准，本地独有条目（未同步）保留；探活失败静默降级为本地视图
- **sop tab**：失败显式提示（SOP 无本地快照可降）
- **qa tab**：失败显示错误，不降级（RAG 必须服务端）
- **memory tab**：纯本地，无网络依赖

### 7.3 RAG 问答交互

```
用户输入问题
  └─► POST /v1/chat (SSE stream)
      ├─► onChunk: 累积 answer 文本
      ├─► onCitation: 渲染 KnowledgeCitation 卡片
      │           ├─ documentId
      │           ├─ chunkId
      │           ├─ content snippet
      │           └─ score (0-1)
      └─► onDone: 显示「归档到知识库」按钮
          └─► 用户选择 category + 确认 → POST /ingest
```

## §8 交互流程

### 8.1 知识文档摄取流程

```
用户点击「+ 新增」
  └─► Modal: 填写 title + content + category (6 选 1)
      └─► apiService.ingestKnowledgeText({ title, text, category })
          ├─► 200: 更新 knowledge[] state + 关闭 Modal
          └─► 4xx: setKnowledgeError(e.message) + 保留 Modal
```

### 8.2 SOP 模板实例化流程

```
用户在 sop tab 点击「实例化」
  └─► apiService.instantiateSopTemplate(id)
      ├─► 201: setSopInstantiatedMsg('✓ 已生成知识文档: ' + documentId)
      └─► 409 (archived): 提示「模板已归档，无法实例化」
```

### 8.3 知识图谱浏览流程

```
用户点击文档卡片「查看详情」
  └─► apiService.listKnowledgeDocumentRelations(id)
      ├─► 200: 渲染 KnowledgeRelationView[] 列表
      │           ├─ relationType（提到/关联/引用）
      │           ├─ targetType + targetId（订单/客户/产品）
      │           └─ confidence 进度条
      └─► 失败: 静默为空区块（不阻断详情浏览）
```

## §10 权限与访问控制

### 10.1 路由级守卫

- `/api/v1/knowledge/*` 统一走 `createModuleAuthGuard({ requireAuth, apiKeys })`
- POST/PATCH/DELETE 要求 JWT 认证；API-Key 单独访问 → 401
- 软删除/实例化要求 `knowledge:write` 权限

### 10.2 行级 ACL（KnowledgeAcl）

| scope | 含义 | 适用场景 |
| --- | --- | --- |
| `company` | 全公司可见 | 默认公开知识 |
| `department` | 部门内可见 | 销售部内部资料 |
| `team` | 团队内可见 | 跟单小组 SOP |
| `private` | 仅本人可见 | 个人备忘 |

| access | 含义 |
| --- | --- |
| `read` | 只读 |
| `write` | 可编辑 |
| `admin` | 可管理 ACL |
| `none` | 无权限（显式拒绝） |

### 10.3 AdminPanel 配置入口

`AdminPanel.tsx` 的 `knowledge-acl` Tab 提供可视化 ACL 配置：选文档 → 选 scope → 选 role/department → 设置 access。

- `actorId` 从 JWT 解析，`ip` 从 `req.ip` 提取

## §13 已知限制与未来扩展

### 13.1 当前限制

- ❌ 知识图谱仅支持**只读**查询，关联写入需通过摄取时由 LLM 抽取（Agent 工具）
- ❌ RAG 服务为独立 Python 进程，与 Node.js 主服务**非同进程**，部署需独立维护
- ❌ `embedding` 字段当前为 `Json?`，未接入专用向量数据库（如 Qdrant/Milvus），大规模检索时性能受限
- ❌ 知识文档版本回滚未实现（仅 version 自增，无历史快照）
- ❌ SOP 模板**无审批流**，任何有 `knowledge:write` 权限者即可创建/归档

### 13.2 未来扩展

- 接入专用向量数据库（Qdrant/Milvus）支撑 10w+ chunks 检索
- 知识图谱可视化（D3.js / Cytoscape）渲染全图
- SOP 模板审批流（提交 → 审核 → 发布）
- 知识文档版本树 + 回滚
- 多语言支持（英文文档独立分块策略）

## §14 实现备注

### 14.1 RAG 三层广告过滤

`server/knowledge_api/` 实现 a/b/c 三层过滤：
- **a 层**：内容特征（<200 字 + 推广词黑名单）
- **b 层**：结构过滤（trafilatura 抽取正文 <100 字判图片广告，需人工抽检校准）
- **c 层**：LLM 判断（prompt 使用能力描述式，判断是否为纺织专业知识内容）

### 14.2 客户端 RAG 降级

- Electron 客户端探活失败时，`qa` Tab 显示「RAG 服务离线，请稍后重试」
- 不降级为本地关键词搜索（避免无引用答案）

### 14.3 Insight 备忘

`memory` Tab 的 `Insight` 是轻量 KV（`fact + importance + isPinned`），纯本地 IndexedDB，不与服务端同步。设计意图：员工随手记录的工作笔记，未来可批量升级为 `KnowledgeDocument`。
