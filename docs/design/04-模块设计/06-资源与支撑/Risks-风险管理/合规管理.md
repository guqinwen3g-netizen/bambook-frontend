## §2 模块边界与职责

| 职责域 | 已实现 | 规划增强 | 上下游依赖 |
|--------|--------|----------|-----------|
| **HS Code 归类校验** | ✅ runHsCodeCheck 逐行校验报关单商品行（缺失/格式非法/未注册三级判定 + 注册表非空时才校验未注册） | ⚠️ HS Code 注册表自动同步海关编码库 | 上游 CustomsDeclarationLine；下游 RiskAlert |
| **出口管制校验** | ✅ runExportControlCheck 目的国命中禁运清单（KP/IR/CU/SY + 英文别名）→ fail + critical 预警；目的国为空 → warn | ⚠️ 双用途物项（Dual-Use）清单、最终用户筛查 | 上游 CustomsDeclaration.destinationCountry；下游 RiskAlert |
| **原产地规则人工登记** | ✅ addManualComplianceCheck 人工录入 origin_rule 类型检查（targetType/Id/result/summary/details） | ⚠️ RCEP/普惠制原产地规则自动判定 | 上游人工；下游检查记录档案 |
| **检查记录档案** | ✅ ComplianceCheck append-only（type/targetType/targetId/result/summary/details/checkedById/checkedAt）+ 四维过滤查询 | ⚠️ 检查记录导出、按客户/工厂聚合统计 | 上游三通道；下游合规报表 |
| **fail 自动预警** | ✅ HS Code fail → warning；出口管制 fail → critical；原产地规则无自动预警（人工判定） | ⚠️ 认证预警（工厂资质到期接入预警中心） | 上游检查结果；下游 RiskAlert |

> **职责边界**：合规模块只负责"检查与记录"，HS Code 注册表 CRUD（创建/更新/停用）归报关模块 `customsService` 管理，本模块通过 `db.hsCode.findUnique({ where: { code } })` 只读引用。报关单本身的状态机（Draft→Submitted→Declared→...）也归报关模块，本模块仅在出运前以报关单为对象触发合规检查。

| targetType | String | — | 检查对象类型：`CustomsDeclaration` \| `Order` \| `ProductAsset` |

## §4 HS Code 归类校验流程

```
用户填写报关单 ID
  │
  ▼
runHsCodeCheck(declarationId, actorId?)
  │
  ├─ 校验：declarationId 非空 + 报关单存在且未软删
  ├─ 查报关单全部商品行 CustomsDeclarationLine
  ├─ 查注册表规模 registrySize = hsCode.count()
  │
  ▼ 逐行校验
  ┌─────────────────────────────────────────────────────┐
  │ hs = line.hsCode?.trim()                            │
  │                                                     │
  │  ├─ hs 为空 → fail（缺失 HS 编码）                  │
  │  ├─ hs 格式非法（非纯数字 4-10 位 且 非点分扩展）   │
  │  │     → fail（HS 编码格式非法）                    │
  │  ├─ registrySize > 0 且 hsCode.findUnique 未命中    │
  │  │     → warn（HS 编码未在注册表中）                │
  │  └─ 否则 → pass                                     │
  └─────────────────────────────────────────────────────┘
  │
  ├─ 汇总：result = failCount>0 ? 'fail' : unregisteredCount>0 ? 'warn' : 'pass'
  ├─ 写入 ComplianceCheck（type=hs_code, details={lines:[行级结果]}）
  │
  └─ result === 'fail' → raiseAlert
      ├─ type: compliance_fail
      ├─ level: warning
      ├─ title: "报关单 HS 编码校验未通过"
      ├─ content: 报关单 ID + 失败摘要 + "请修正后重新申报"
      ├─ relatedType: CustomsDeclaration, relatedId: declarationId
      └─ dedupKey: `compliance:hs_code:${declarationId}:${todayStr()}`
```

### 4.1 HS 编码格式校验正则

| 正则 | 接受格式 | 示例 |
|------|---------|------|
| `HS_PLAIN_RE = /^\d{4,10}$/` | 纯数字 4-10 位 | `5208` / `520852` / `5208520000` |
| `HS_DOTTED_RE = /^\d{4}(\.\d{2}){1,3}$/` | 4 位 + 1-3 组 `.xx` 点分扩展 | `5208.52` / `5208.52.00` / `5208.52.00.00` |

**两正则为"或"关系**：`HS_PLAIN_RE.test(hs) || HS_DOTTED_RE.test(hs)`，任一命中即格式合法。

### 4.2 三级判定矩阵

| 行级状态 | 触发条件 | 计入 | 整单 result 影响 |
|---------|---------|------|----------------|
| `fail` | hs 为空 | missingCount | failCount > 0 → 整单 fail |
| `fail` | hs 格式非法 | invalidCount | failCount > 0 → 整单 fail |
| `warn` | 注册表非空且未注册 | unregisteredCount | failCount=0 且 unregisteredCount>0 → 整单 warn |
| `pass` | 格式合法且（注册表为空 或 已注册） | — | failCount=0 且 unregisteredCount=0 → 整单 pass |

> **注册表为空时的语义**：若 `registrySize === 0`（注册表无任何记录），跳过未注册校验，仅校验缺失与格式非法。这避免空注册表导致所有编码都被判 warn 的误报。

## §5 出口管制校验流程

```
用户填写报关单 ID
  │
  ▼
runExportControlCheck(declarationId, actorId?)
  │
  ├─ 校验：declarationId 非空 + 报关单存在且未软删
  ├─ 读取 dest = decl.destinationCountry?.trim()
  │
  ▼ 目的国判定
  ┌─────────────────────────────────────────────────────┐
  │  ├─ dest 为空 → warn（目的国为空，无法判定）         │
  │  ├─ isSanctionedCountry(dest) 命中 → fail + critical │
  │  └─ 否则 → pass                                      │
  └─────────────────────────────────────────────────────┘
  │
  ├─ 写入 ComplianceCheck（type=export_control, details={destinationCountry, sanctioned, sanctionedList}）
  │
  └─ result === 'fail' → raiseAlert
      ├─ type: compliance_fail
      ├─ level: critical
      ├─ title: "报关单命中出口管制禁运国"
      ├─ content: 报关单 ID + 目的国 + 禁运清单 + "出运前必须完成合规审批"
      ├─ relatedType: CustomsDeclaration, relatedId: declarationId
      └─ dedupKey: `compliance:export_control:${declarationId}:${todayStr()}`
```

### 5.1 禁运国清单

```typescript
const SANCTIONED_COUNTRIES = ['KP', 'IR', 'CU', 'SY']; // ISO 两位码
const SANCTIONED_MATCH_SET = new Set([
  ...SANCTIONED_COUNTRIES.map(c => c.toLowerCase()),
  'north korea', 'iran', 'cuba', 'syria', // 英文别名兜底
]);

function isSanctionedCountry(destination: string): boolean {
  return SANCTIONED_MATCH_SET.has(destination.trim().toLowerCase());
}
```

| 匹配方式 | 输入示例 | 命中 |
|---------|---------|------|
| ISO 两位码（大小写不敏感） | `KP` / `kp` / `Kp` | ✅ |
| 英文全名（大小写不敏感） | `North Korea` / `north korea` | ✅ |
| 非 ISO 也非英文全名 | `DPRK` / `朝鲜` | ❌（不命中，需扩充清单） |

> **清单维护**：禁运国清单为常量数组，扩充需修改 `riskService.ts` 顶部 `SANCTIONED_COUNTRIES` 与 `SANCTIONED_MATCH_SET`。规划增强为数据库化 `SanctionedCountry` 表 + 定时同步外部清单。

### 5.2 三级判定矩阵

| dest 状态 | 判定 | 预警 | 说明 |
|----------|------|------|------|
| 为空 | warn | 无 | 目的国未填写，无法自动判定，需人工确认 |
| 命中禁运清单 | fail | critical | 出运前必须完成合规审批（可能涉及特殊许可） |
| 未命中 | pass | 无 | 目的国合规，可正常出运 |

## §6 原产地规则人工登记

原产地规则（origin_rule）无自动检查通道（RCEP 累积规则 / 普惠制 / 双边协定等需人工判定），通过 `addManualComplianceCheck` 人工录入：

```
合规专员填写表单
  │
  ├─ targetType: CustomsDeclaration | Order | ProductAsset（下拉选择）
  ├─ targetId: 检查对象 ID
  ├─ result: pass | warn | fail
  └─ summary: 结论摘要（如"满足 RCEP 原产地累积规则"）
  │
  ▼
addManualComplianceCheck(input, actorId)
  │
  ├─ 校验：
  │   ├─ type ∈ ['hs_code', 'export_control', 'origin_rule']（人工通道一般用 origin_rule）
  │   ├─ result ∈ ['pass', 'warn', 'fail']
  │   ├─ targetType 非空
  │   ├─ targetId 非空
  │   └─ summary 非空
  │
  ├─ 写入 ComplianceCheck（checkedById = actorId，非系统自动）
  │
  └─ 返回检查记录（不自动预警，原产地规则由人工判定风险等级）
```

> **不自动预警的原因**：原产地规则涉及双边协定累积计算，pass/warn/fail 由合规专员根据具体协定人工判定，自动预警可能误报。若需预警，由人工在判定 fail 后手动创建 RiskAlert（规划增强：fail 时提示人工触发预警）。

## §7 检查结果等级与预警联动

| 检查类型 | fail 预警等级 | dedupKey 模式 | 预警标题 |
|---------|-------------|--------------|---------|
| `hs_code` | warning | `compliance:hs_code:${declarationId}:${todayStr()}` | 报关单 HS 编码校验未通过 |
| `export_control` | critical | `compliance:export_control:${declarationId}:${todayStr()}` | 报关单命中出口管制禁运国 |
| `origin_rule` | 无自动预警 | — | — |

### 7.1 dedupKey 日级幂等

同一报关单同一检查类型同一日仅产生一条 fail 预警：

```
dedupKey = `compliance:${type}:${declarationId}:${YYYY-MM-DD}`
```

- 同日多次运行同报关单同类型检查 → raiseAlert 返回 `created:false`，不重复告警
- 跨日运行 → dedupKey 不同，产生新预警（适用于问题持续未修复的场景）

### 7.2 预警等级差异

- **HS Code fail → warning**：HS 编码错误可修正后重新申报，不直接阻断出运
- **出口管制 fail → critical**：禁运国出运涉及法律风险，必须出运前完成合规审批，critical 级强制处置

## §8 检查记录查询与过滤

### 8.1 查询接口

```typescript
listComplianceChecks(query: {
  type?: string;        // hs_code | export_control | origin_rule
  result?: string;      // pass | warn | fail
  targetType?: string;  // CustomsDeclaration | Order | ProductAsset
  targetId?: string;

```

### 8.2 前端双段过滤

CompliancePanel 顶部双段过滤栏：

| 过滤段 | 选项 | 说明 |
|--------|------|------|
| 类型 | 全部 / HS Code 归类 / 出口管制 / 原产地规则 | 按 type 过滤 |
| 结果 | 全部 / 通过 / 警告 / 未通过 | 按 result 过滤 |

> **targetType/targetId 过滤**：前端 UI 不暴露，仅 API 支持（用于按报关单/订单查询其全部合规检查记录的聚合场景）。

### 8.3 排序与分页

- 排序：`checkedAt desc`（最新检查在前）
- 分页：`take = Math.min(limit || 50, 200)`，单次最多 200 条
- 总数：`count({ where })` 与 items 并行查询

## §10 API 端点

| 方法 | 路径 | 守卫 | 说明 |
|------|------|------|------|
| GET | `/api/v1/risk/compliance-checks` | JWT 或 API-Key | 检查记录列表（?type&result&targetType&targetId&limit） |
| POST | `/api/v1/risk/compliance-checks/hs-code` | JWT（requireWrite） | HS Code 校验 `{ declarationId }` → 201 `{ ok, item }` |
| POST | `/api/v1/risk/compliance-checks/export-control` | JWT（requireWrite） | 出口管制校验 `{ declarationId }` → 201 `{ ok, item }` |
| POST | `/api/v1/risk/compliance-checks` | JWT（requireWrite） | 人工录入 `{ type, targetType, targetId, result, summary, details? }` → 201 `{ ok, item }` |

### 10.1 守卫口径

- **读**（GET）：JWT 或 API-Key 均可（与 suppliers/seasons 模块一致）
- **写**（POST 三通道）：必须 JWT（`requireJwtForWrite`），API-Key 仅读
- **角色守卫**：合规检查无额外角色叠加（owner/admin/manager/finance/sales/qc 均可触发，由业务流程约束）

### 10.2 通知

每个 POST 端点成功后调用 `notify(event, [id])`：
- `hs_code_check` / `export_control_check` / `manual_compliance_check`

通知事件由 SSE 推送至前端实时刷新检查记录列表。

### 10.3 错误码

| 错误码 | 触发场景 |
