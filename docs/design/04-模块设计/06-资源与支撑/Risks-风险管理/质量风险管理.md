## §3 数据模型

质量风险模块不引入新数据模型，全部基于 InspectionReport 聚合，预警落地 RiskAlert：

### 3.1 InspectionReport（验货报告 — 聚合数据源）

| 字段 | 类型 | 约束 | 聚合用途 |
|------|------|------|---------|
| id | String | @id `INR__${orderId}` 或 `INR__${orderId}__midline` | 报告唯一标识 |
| orderId | String | — | 关联订单（用于查 Order.millRelationId 分组到工厂） |
| inspectionType | String | @default("final") | midline(中期) \| final(终期/出货前) |
| inspectionDate | String? | YYYY-MM-DD | 季度分组依据 + 90 天窗口过滤 |
| inspectorOrg | String? | — | 验货方（自有 QC / SGS / BV / Intertek / 客户验货员） |
| aqlLevel | String? | — | AQL 等级（如 "2.5/4.0 II"） |
| lotSize | Int? | — | 批量 |
| sampleSize | Int? | — | 抽样数 |
| criticalDefects | Int | @default(0) | 致命疵点数（AQL 0，>0 即整批拒收） |
| majorDefects | Int | @default(0) | 主要疵点数 |
| minorDefects | Int | @default(0) | 次要疵点数 |
| defectSummary | String? | — | 疵点描述（如 "跳线x3 污渍x2"）→ parseDefectKeywords 分词 |
| result | String? | — | pass \| conditional \| fail（failCount 统计依据） |
| shipmentId | String? | — | 关联运单（终期验货对应出运批次） |
| createdAt | BigInt | — | 创建时间戳 |
| updatedAt | BigInt | — | 更新时间戳 |

索引：`@@unique([orderId, inspectionType])` / `@@index([orderId])`。

### 3.2 RiskAlert（quality_repeat 预警落地）

| 字段 | 质量风险用途 |
|------|------------|
| type | `quality_repeat` |
| level | `warning` |
| title | `重复疵点预警：${keyword}（近 90 天 ${reportCount} 张报告）` |

| relatedType | `Relation`（工厂）或 undefined（未关联工厂） |
| relatedId | millRelationId 或 undefined |
| dedupKey | `quality_repeat:${mill ?? 'unlinked'}:${keyword}:${currentQuarter}` |

## §4 疵点趋势聚合流程

```
getDefectTrends({ groupBy: 'factory' | 'quarter' })
  │
  ├─ 查全量 InspectionReport（take: 2000）
  ├─ 提取全部 orderId → loadOrderMillMap 批量查 Order.millRelationId
  │
  ▼ 按 groupBy 分组
  ┌─────────────────────────────────────────────────────────────┐
  │ groupBy = 'factory':                                        │
  │   key = millRelationId ?? 'unlinked'                        │
  │   按 mill 分组验货报告                                       │
  │   items.sort((a,b) => b.reports - a.reports)                │
  │                                                             │
  │ groupBy = 'quarter':                                        │
  │   key = quarterOf(inspectionDate)（如 "2026-Q3"）            │
  │   inspectionDate 缺失/非法 → 跳过                            │
  │   items.sort((a,b) => a.quarter.localeCompare(b.quarter))   │
  └─────────────────────────────────────────────────────────────┘
  │
  ▼ 每组调 aggregateDefectGroup(rows)
  ┌─────────────────────────────────────────────────────────────┐
  │ 遍历 rows：                                                  │
  │   ├─ result === 'fail' → failCount += 1                     │
  │   ├─ criticalDefects += Number(r.criticalDefects ?? 0)      │
  │   ├─ majorDefects += Number(r.majorDefects ?? 0)            │
  │   ├─ minorDefects += Number(r.minorDefects ?? 0)            │
  │   └─ parseDefectKeywords(r.defectSummary) → keywordCounts   │
  │                                                             │
  │ 返回：                                                       │
  │   { reports, failCount, criticalDefects, majorDefects,      │
  │     minorDefects, defectKeywords: Top5 }                    │
  └─────────────────────────────────────────────────────────────┘
```

### 4.1 分组键

| 分组模式 | 分组键 | 来源 | 排序 |
|---------|--------|------|------|
| factory | `Order.millRelationId ?? 'unlinked'` | loadOrderMillMap 批量查 Order | reports 降序（报告数多的工厂在前） |
| quarter | `${year}-Q${q}`（如 `2026-Q3`） | quarterOf(inspectionDate) | quarter 字典序升序（时间正序） |

### 4.2 三级疵点统计

| 疵点级别 | 字段 | AQL 含义 | UI 高亮 |
|---------|------|---------|---------|
| 致命疵点 Critical | criticalDefects | AQL 0，>0 即整批拒收 | `var(--danger-text)` 红色（>0 时） |
| 主要疵点 Major | majorDefects | AQL 2.5（常规水平 II） | `var(--text-secondary)` 常规色 |
| 轻微疵点 Minor | minorDefects | AQL 4.0（常规水平 II） | `var(--text-secondary)` 常规色 |

> **AQL 0 致命疵点的特殊性**：任何一张报告 criticalDefects > 0 即整批拒收，因此在趋势表格中 criticalDefects > 0 的格子单独高亮为红色，提示重点关注。

## §5 疵点描述分词器

```
parseDefectKeywords(summary: string | null | undefined): string[]
  │
  ├─ summary 为空 → 返回 []
  │
  ├─ Step 1：全局去掉数量缀
  │   "跳线x3 污渍x2" → "跳线  污渍"
  │   "色花 x 2"      → "色花"
  │   正则：/[xX×]\s*\d+/g → ' '
  │
  ├─ Step 2：多分隔符切分
  │   分隔符：空白 / 中英文逗号 / 顿号 / 分号
  │   正则：/[\s，、,;；]+/
  │
  ├─ Step 3：trim + 空串过滤
  │
  └─ 返回关键词数组（可能含重复，由调用方聚合计数）
```

### 5.1 分词示例

| 输入 defectSummary | 分词结果 |
|-------------------|---------|
| `"跳线x3 污渍x2"` | `['跳线', '污渍']` |
| `"色花 x 2，破损×1"` | `['色花', '破损']` |
| `"跳线、污渍;色差"` | `['跳线', '污渍', '色差']` |
| `null` / `""` | `[]` |
| `"跳针X5"` | `['跳针']` |

### 5.2 高频疵点词 Top5

aggregateDefectGroup 内部维护 `keywordCounts: Map<string, number>`：
- 遍历该组所有报告的 defectKeywords，按词累加计数
- 排序：`count 降序 → keyword 字典序`（同 count 时按字典序，保证稳定排序）
- 截取前 5 个 → `defectKeywords: [{ keyword, count }]`

> **未做同义词归一**：当前"跳线"/"跳针"/"跳纱"视为不同关键词。规划增强为同义词词典归一，避免同一疵点因表述差异分散计数。

## §6 重复疵点扫描流程

```
runQualityRepeatScan(today = new Date())
  │
  ├─ 计算时间窗口
  │   todayMs = 今日零点毫秒
  │   sinceStr = formatDate(todayMs - 90 * DAY_MS)  // 近 90 天
  │   currentQuarter = quarterOf(formatDate(todayMs))  // 当前季度
  │
  ├─ 查近 90 天验货报告
  │   inspectionReport.findMany({ where: { inspectionDate: { gte: sinceStr } }, take: 2000 })
  │
  ├─ loadOrderMillMap 批量查 Order.millRelationId
  │
  ▼ 按 (mill, keyword) 分组
  ┌─────────────────────────────────────────────────────────────┐
  │ groups = Map<string, { mill, keyword, reportIds: Set }>     │
  │                                                             │
  │ 遍历每张报告 r：                                             │
  │   mill = millMap.get(r.orderId) ?? null                     │
  │   for kw of parseDefectKeywords(r.defectSummary):           │
  │     key = `${mill ?? 'unlinked'}::${kw}`                    │
  │     groups.get(key).reportIds.add(r.id)                     │
  └─────────────────────────────────────────────────────────────┘
  │
  ▼ 遍历 groups，reportIds.size >= 2 → raiseAlert
  ┌─────────────────────────────────────────────────────────────┐
  │ for g of groups.values():                                   │
  │   if g.reportIds.size < 2: continue                         │
  │                                                             │
  │   raiseAlert({                                              │
  │     type: 'quality_repeat',                                 │
  │     level: 'warning',                                       │
  │     title: `重复疵点预警：${g.keyword}（近 90 天 ${g.reportIds.size} 张报告）`,│
  │     content: `工厂 ${g.mill ?? '未关联工厂'} 近 90 天内「${g.keyword}」...`,│
  │     relatedType: g.mill ? 'Relation' : undefined,           │
  │     relatedId: g.mill ?? undefined,                         │
  │     dedupKey: `quality_repeat:${g.mill ?? 'unlinked'}:${g.keyword}:${currentQuarter}`,│
  │   })                                                        │
  │   if created: alerted += 1                                  │
  └─────────────────────────────────────────────────────────────┘
  │
  └─ 返回 { alerted }
```

### 6.1 扫描阈值

| 常量 | 值 | 含义 |
|------|---|------|
| `QUALITY_REPEAT_WINDOW_DAYS` | 90 | 扫描时间窗口（近 90 天的验货报告） |
| 重复阈值 | 2 | 同工厂同疵点词出现在 ≥2 张报告 → 预警 |

### 6.2 dedupKey 季度内幂等

```
dedupKey = `quality_repeat:${mill ?? 'unlinked'}:${keyword}:${currentQuarter}`
```

- **同一季度内**多次扫描同一工厂同一疵点词 → raiseAlert 返回 `created:false`，不重复告警
- **跨季度**扫描 → dedupKey 含新季度，产生新预警（适用于问题持续未整改的场景）

> **季度边界的设计意图**：疵点问题通常按季度复盘，季度内首次预警后，watchdog 重复扫描不会刷屏；下季度若问题仍存在，会重新预警提醒跟进。

### 6.3 预警等级

所有 quality_repeat 预警统一为 `warning` 级（非 critical）：
- 重复疵点不直接阻断出运（验货报告 result 才是出运门禁）
- 但需启动工厂整改流程，warning 级提示关注

## §8 API 端点

| 方法 | 路径 | 守卫 | 说明 |
|------|------|------|------|
| GET | `/api/v1/risk/quality/defect-trends` | JWT 或 API-Key | 疵点趋势（?groupBy=factory\|quarter，默认 factory） |
| POST | `/api/v1/risk/quality/repeat-scan` | JWT（requireWrite） | 重复疵点扫描 → `{ ok, alerted }` |

### 8.1 守卫口径

- **读**（GET defect-trends）：JWT 或 API-Key 均可
- **写**（POST repeat-scan）：必须 JWT（requireWrite），API-Key 仅读
- **角色守卫**：质量扫描无额外角色叠加（owner/admin/manager/qc 均可触发）

### 8.2 通知

POST repeat-scan 成功且 `alerted > 0` 时调用 `notify('quality_repeat_scan')`，SSE 推送至前端实时刷新预警中心。

### 8.3 错误码

| 错误码 | 触发场景 |
|--------|---------|
| `DEFECT_TRENDS_FAILED` | getDefectTrends 抛错 |
| `QUALITY_SCAN_FAILED` | runQualityRepeatScan 抛错 |

## §9 watchdog 日级巡检

qualityRepeatWatchdog 在 scheduler 中注册，每日 10:30 后执行一次：

```typescript
// scheduler/tasks/riskWatchdog.ts
export function createQualityRepeatWatchdogTask(): ScheduledTask {
  return {
    id: 'quality_repeat_watchdog',
    shouldRun: (now: Date) => {
      const dayKey = dayKeyOf(now);
      const afterHalfTen = now.getHours() > 10 || (now.getHours() === 10 && now.getMinutes() >= 30);
      if (afterHalfTen && dayKey !== lastQualityRunDay) {
        lastQualityRunDay = dayKey;
        return true;
      }
      return false;
    },
    run: async (prisma: PrismaClient) => {
      try {
        await createRiskService(prisma).runQualityRepeatScan();
      } catch (e: any) {
        logger.error('[QualityRepeatWatchdog] failed', { error: e?.message });
      }
    },
  };
}
```

| watchdog 属性 | 值 |
|--------------|---|
| id | `quality_repeat_watchdog` |
| 触发时间 | 每日 10:30 后执行一次（dayKey 去重） |
| 调用 | `createRiskService(prisma).runQualityRepeatScan()` |
| 幂等 | watchdog 日级触发去重（lastQualityRunDay）+ RiskAlert.dedupKey 季度内幂等（双重保障） |
| 错误处理 | catch + logger.error，不影响 scheduler 其他任务 |

> **双重幂等设计**：watchdog 的 `lastQualityRunDay` 防止同日内重复触发（进程内状态），RiskAlert.dedupKey 防止跨进程/跨季度重复告警（数据库级真源）。即使 watchdog 重启导致 lastQualityRunDay 丢失，dedupKey 仍能保证不产生重复预警。

## §11 四态规范

| 状态 | 触发 | UI 规范 |
|------|------|---------|
| **加载态** | loadTrends / handleScan 进行中 | Loader2 spin（表格居中 / 按钮内嵌） |
| **空态** | 无验货报告（trends.length === 0） | `bds-empty`：ShieldCheck glyph + "暂无疵点趋势数据" + "验货报告积累后自动聚合" |
| **错误态** | 操作失败 | alert 弹窗显示后端错误消息（含错误码） |
| **无权限** | API-Key 写操作 | 路由层 401，前端按钮不触发 |
