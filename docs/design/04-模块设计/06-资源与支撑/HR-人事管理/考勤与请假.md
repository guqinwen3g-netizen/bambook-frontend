## §2 模块边界与职责

| 职责域 | 已实现 | 规划增强 | 上下游依赖 |
|--------|--------|----------|-----------|
| **考勤打卡** | ✅ AttendanceRecord 每人每日一条（userId+date @unique upsert）+ checkIn/checkOut HH:MM + deriveAttendanceStatus 自动推导 + computeWorkHours 工时计算 + note 备注 | ⚠️ 自动打卡（设备对接：指纹/人脸/移动端定位） | 上游人工录入；下游薪资加班费 |
| **考勤状态推导** | ✅ deriveAttendanceStatus（显式 status 优先；否则按 09:30/17:30 阈值推导 Late/EarlyLeave/LateAndEarly/Normal） | — | 上游 checkIn/checkOut；下游 status 字段 |
| **月度汇总** | ✅ attendanceSummary（按人统计 days/late/earlyLeave/absent/leave/overtime/workHours） | ⚠️ 考勤报表导出 | 上游 AttendanceRecord；下游管理报表 |
| **请假申请** | ✅ LeaveRequest 状态机 Pending→Approved/Rejected/Cancelled + 6 类假期 + days 天数 + reason 理由 + 软删 | ⚠️ 请假余额扣减、假期余额台账 | 上游员工申请；下游考勤 Leave 状态 |
| **请假审批** | ✅ decideLeaveRequest（Approved/Rejected）+ Rejected 必填理由 + Approved 自动标记考勤 Leave（enumerateDates 逐日 upsert）+ publishBusinessEvent | ⚠️ 多级审批、代班审批 | 上游 Pending 请假；下游考勤/通知 |
| **请假撤销** | ✅ cancelLeaveRequest（仅 Pending 可撤销） | — | 上游 Pending 请假 |

> **核心设计**：请假审批通过后，系统自动将请假期间的考勤记录标记为 Leave 状态（upsert 显式 status）。这避免考勤与请假数据脱节，保证月度汇总的 leave 天数与请假记录一致。

## §4 考勤状态自动推导

```
deriveAttendanceStatus(checkIn, checkOut, explicit?)
  │
  ├─ explicit 非空且合法（∈ ATTENDANCE_STATUSES）
  │     → 直接返回 explicit（Absent/Leave/Holiday/Overtime 等人工标记不被覆盖）
  │
  ├─ late = checkIn 存在且 TIME_RE 合法且 toMinutes(checkIn) > toMinutes('09:30')
  ├─ early = checkOut 存在且 TIME_RE 合法且 toMinutes(checkOut) < toMinutes('17:30')
  │
  ├─ late && early → LateAndEarly
  ├─ late → Late
  ├─ early → EarlyLeave
  └─ 否则 → Normal
```

### 4.1 标准工作时间

| 常量 | 值 | 含义 |
|------|---|------|
| `WORK_START` | `09:30` | 标准上班时间（晚于此为迟到） |
| `WORK_END` | `17:30` | 标准下班时间（早于此为早退） |

### 4.2 八种考勤状态

| 状态 | 推导方式 | 语义 | bds-badge 变体 |
|------|---------|------|---------------|
| `Normal` | 自动（未迟到未早退） | 正常 | active（绿） |
| `Late` | 自动（checkIn > 09:30） | 迟到 | warning（黄） |
| `EarlyLeave` | 自动（checkOut < 17:30） | 早退 | warning（黄） |
| `LateAndEarly` | 自动（既迟到又早退） | 迟到且早退 | warning（黄） |
| `Absent` | 显式（人工标记） | 缺勤 | danger（红） |
| `Leave` | 显式（请假审批通过自动标记） | 请假 | info（蓝） |
| `Holiday` | 显式（人工标记） | 节假日 | info（蓝） |
| `Overtime` | 显式（人工标记） | 加班 | info（蓝） |

> **显式 status 优先**：Absent/Leave/Holiday/Overtime 等人工标记不会被自动推导覆盖。upsertAttendance 时若传入 status 参数，直接使用该 status，不重新推导。

### 4.3 工时计算

```typescript
computeWorkHours(checkIn, checkOut)
  │
  ├─ checkIn 或 checkOut 缺失 / 格式非法 → 返回 null
  ├─ diff = toMinutes(checkOut) - toMinutes(checkIn)
  └─ diff > 0 → Math.round((diff / 60) * 100) / 100（小时，两位小数）
```

示例：
- checkIn=09:30, checkOut=17:30 → diff=480 分钟 → 8.0 小时
- checkIn=09:30, checkOut=18:30 → diff=540 分钟 → 9.0 小时
- checkIn=10:00, checkOut=17:00 → diff=420 分钟 → 7.0 小时

## §5 考勤录入流程

```
upsertAttendance(input)
  │
  ├─ 校验
  │   ├─ userId 非空
  │   ├─ date YYYY-MM-DD
  │   ├─ checkIn HH:MM 格式（若提供）
  │   └─ checkOut HH:MM 格式（若提供）
  │
  ├─ status = deriveAttendanceStatus(checkIn, checkOut, input.status)
  ├─ workHours = computeWorkHours(checkIn, checkOut)
  │
  ▼ upsert（userId+date 唯一）
  ┌─────────────────────────────────────────────────────────────┐
  │ db.attendanceRecord.upsert({                                │
  │   where: { userId_date: { userId, date } },                 │
  │   create: { id, userId, date, checkIn, checkOut, status,    │
  │             workHours, note },                              │
  │   update: { checkIn?, checkOut?, status, workHours, note? } │
  │ })                                                          │
  └─────────────────────────────────────────────────────────────┘
  │
  └─ 返回 { record }
```

**upsert 语义**：
- 同一员工同一日期仅一条记录
- 首次录入 → create
- 再次录入 → update（checkIn/checkOut/status/workHours/note 更新）

## §6 月度考勤汇总

```
attendanceSummary(month: string)  // YYYY-MM
  │
  ├─ 校验 month 格式 YYYY-MM
  ├─ 查当月全部考勤记录（date startsWith month）
  │
  ▼ 按人聚合
  ┌─────────────────────────────────────────────────────────────┐
  │ byUser = Map<userId, {                                      │
  │   userId, days, late, earlyLeave, absent, leave, overtime, │
  │   workHours                                                 │
  │ }>                                                          │
  │                                                             │
  │ 遍历每条记录 r：                                             │
  │   agg.days += 1                                             │
  │   r.status ∈ [Late, LateAndEarly] → agg.late += 1          │
  │   r.status ∈ [EarlyLeave, LateAndEarly] → agg.earlyLeave  │
  │   r.status === Absent → agg.absent += 1                    │
  │   r.status === Leave → agg.leave += 1                      │
  │   r.status === Overtime → agg.overtime += 1                │
  │   agg.workHours += r.workHours ?? 0                        │
  └─────────────────────────────────────────────────────────────┘
  │
  ├─ 批量查 UserAccount 补充 displayName
  ├─ workHours 四舍五入两位小数
  └─ 返回汇总数组
```

**汇总字段**：

| 字段 | 含义 | 计算方式 |
|------|------|---------|
| days | 当月考勤记录天数 | count(全部记录) |
| late | 迟到天数 | count(status ∈ [Late, LateAndEarly]) |
| earlyLeave | 早退天数 | count(status ∈ [EarlyLeave, LateAndEarly]) |
| absent | 缺勤天数 | count(status = Absent) |
| leave | 请假天数 | count(status = Leave) |
| overtime | 加班天数 | count(status = Overtime) |
| workHours | 总工时（小时） | sum(workHours) |

> **LateAndEarly 双重计数**：迟到且早退同时计入 late 和 earlyLeave，反映既迟到又早退的事实。

## §7 请假状态机

```
Pending ──(approve)──▶ Approved
   │                     │
   │──(reject)──▶ Rejected
   │
   └──(cancel)──▶ Cancelled
```

| 状态 | bds-badge 变体 | 可执行操作 | 说明 |
|------|---------------|-----------|------|
| Pending | warning（黄） | 审批通过 / 驳回 / 撤销 | 待审批 |
| Approved | active（绿） | — | 已通过（自动标记考勤 Leave） |
| Rejected | danger（红） | — | 已驳回（必填 rejectReason） |
| Cancelled | neutral（灰） | — | 已撤销（仅 Pending 可撤销） |

### 7.1 状态流转校验

- **decideLeaveRequest**：仅 Pending 可审批（Approved/Rejected），其他状态抛 `INVALID_TRANSITION`
- **cancelLeaveRequest**：仅 Pending 可撤销，其他状态抛 `INVALID_TRANSITION`
- **Rejected 必填理由**：rejectReason 为空时抛 `VALIDATION_FAILED`

### 7.2 审批通过自动标记考勤

```
decideLeaveRequest(actorId, id, 'Approved')
  │
  ├─ 校验：请假单存在 + status=Pending
  ├─ 更新 LeaveRequest（status=Approved, approverId, approvedAt）
  │
  ▼ 请假期间考勤自动标记 Leave
  ┌─────────────────────────────────────────────────────────────┐
  │ days = enumerateDates(startDate, endDate)  // 逐日枚举      │
  │                                                             │
  │ for date of days:                                           │
  │   upsertAttendance({                                        │
  │     userId, date,                                           │
  │     status: 'Leave',          // 显式 status，不被推导覆盖  │
  │     note: `请假单 ${req.id}`                                │
  │   })                                                        │
  └─────────────────────────────────────────────────────────────┘
  │
  ├─ publishBusinessEvent LeaveRequestDecided（事务外）
  └─ 返回 { request }
```

**enumerateDates 日期枚举**：

```typescript
enumerateDates(start: string, end: string): string[]
  │
  ├─ cur = new Date(`${start}T00:00:00`)
  ├─ last = new Date(`${end}T00:00:00`)
  │
  └─ while cur <= last:
      out.push(formatDate(cur))
      cur.setDate(cur.getDate() + 1)
```

> **幂等性**：upsertAttendance 使用 userId+date 唯一约束，重复审批不会创建重复考勤记录。但当前实现未防重复审批（status≠Pending 时抛错），由状态机保证。

### 9.4 状态徽章语义映射

```typescript
const attendanceSemantic = (status: string): StatusSemantic => {
  switch (status) {
    case 'Normal': return 'active';                    // 正常 → 绿
    case 'Overtime': return 'info';                    // 加班 → 蓝
    case 'Late':
    case 'EarlyLeave':
    case 'LateAndEarly': return 'warning';             // 迟到/早退 → 黄
    case 'Absent': return 'danger';                    // 缺勤 → 红
    case 'Leave': return 'info';                       // 请假 → 蓝
    default: return 'neutral';
  }
};

const leaveSemantic = (status: string): StatusSemantic => {
  switch (status) {
    case 'Approved': return 'active';                  // 已通过 → 绿
    case 'Pending': return 'warning';                  // 待审批 → 黄
    case 'Rejected': return 'danger';                  // 已驳回 → 红
    default: return 'neutral';                         // 已撤销 → 灰
  }
};
```

| **错误态** | 操作失败 | bds-alert danger 横幅（rounded-full + AlertCircle + 可关闭） |
| **无权限** | 非 owner/admin | 路由层 401，前端不渲染 HR 入口 |
