## §2 模块边界与职责

| 职责域 | 已实现 | 规划增强 | 上下游依赖 |
|--------|--------|----------|-----------|
| **考核周期** | ✅ PerformanceCycle CRUD（name + period @unique + status Open/Closed + startDate/endDate + closePerformanceCycle 关闭校验） | ⚠️ 周期自动创建（按季度/年度） | 上游人工创建；下游评定管理 |
| **自评录入** | ✅ upsertPerformanceReview（upsert by (cycleId,userId) + 仅 Draft 可改 + 周期须 Open + selfScore 0-100 校验 + kpi Json 弹性 + comment） | ⚠️ KPI 模板库、指标项结构化 | 上游 EmployeeProfile；下游主管终评 |
| **提交流转** | ✅ submitPerformanceReview（Draft→Submitted 状态校验 + 仅 Draft 可提交） | ⚠️ 提交提醒通知 | 上游 Draft；下游主管终评 |
| **主管终评** | ✅ confirmPerformanceReview（Submitted→Confirmed + managerScore/finalScore 0-100 校验 + grade A/B/C/D 校验 + reviewerId 留痕 + comment 覆盖） | ⚠️ 360 度评估、多评委加权 | 上游 Submitted；下游调薪/晋升 |
| **评定查询** | ✅ listPerformanceReviews（cycleId/userId/status 多维过滤 + 关联 displayName/reviewerName + listPerformanceCycles 聚合 reviewCount/confirmedCount） | ⚠️ 绩效报表导出、趋势分析 | 上游 PerformanceReview；下游管理报表 |
| **审计日志** | ✅ writeRouteAuditLog（所有写操作记录审计：create/close cycle / upsert/submit/confirm review） | — | 上游路由操作；下游审计追溯 |

> **核心设计纪律**：评定采用"自评→提交→终评确认"三阶段递进式工作流，每个阶段有严格的前置状态校验（Draft 可改自评 → Submitted 锁定自评待终评 → Confirmed 终评锁定），确保评价过程的公正性与可追溯性。一人一周期一评定（@@unique([cycleId, userId])）防止重复评定。

## §3 数据模型

### 3.1 PerformanceCycle（考核周期 — period 唯一）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | String | @id `cycle_${ts}_${rand}` | 主键 |
| name | String | — | 周期名称（如"2026 上半年考核"） |
| period | String | @unique | 考核期间标识（如 2026-H1 / 2026-Q3） |
| status | String | @default("Open") | 状态：Open / Closed |
| startDate | String? | YYYY-MM-DD | 周期开始日期 |
| endDate | String? | YYYY-MM-DD | 周期结束日期 |
| createdAt | DateTime | @default(now()) | 创建时间 |
| updatedAt | DateTime | @updatedAt | 更新时间 |

关系：`reviews PerformanceReview[]`（一对多，删除时级联 Cascade）。
索引：`@@unique([period])`。无软删（Closed 状态替代删除，历史完整保留）。

### 3.2 PerformanceReview（绩效评定 — 一人一周期一评定）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | String | @id `review_${ts}_${rand}` | 主键 |
| cycleId | String | — | 关联考核周期 |
| userId | String | — | 被评定员工 |
| selfScore | Float? | 0-100 | 自评分 |
| managerScore | Float? | 0-100 | 主管评分 |
| finalScore | Float? | 0-100 | 终评分（主管确认写入） |
| grade | String? | A/B/C/D | 评级（终评确认写入） |
| kpi | Json? | — | KPI 指标（弹性结构，保持指标扩展性） |
| comment | String? | — | 评语（自评/终评共用，终评覆盖） |
| status | String | @default("Draft") | 状态：Draft / Submitted / Confirmed |
| reviewerId | String? | — | 终评人 ID（主管，留痕） |
| createdAt | DateTime | @default(now()) | 创建时间 |
| updatedAt | DateTime | @updatedAt | 更新时间 |

关系：`cycle PerformanceCycle @relation(fields: [cycleId], references: [id], onDelete: Cascade)`。
索引：`@@unique([cycleId, userId])`（一人一周期一评定）/ `@@index([userId])`。无软删（状态机锁定替代删除）。

> **设计要点**：kpi 字段为 Json 类型，保持指标项的弹性结构，支持不同岗位/周期配置不同的 KPI 指标集，避免硬编码指标字段导致表结构膨胀。

### 4.1 三阶段职责划分

| 阶段 | 状态 | 操作人 | 可写字段 | 校验规则 |
|------|------|--------|---------|---------|
| 自评 | Draft | 员工/HR 专员 | selfScore / kpi / comment | 周期须 Open + selfScore 0-100 |
| 已提交 | Submitted | 员工（submit 触发） | —（自评锁定） | 仅 Draft 可提交 |

## §5 评定状态机

```
Draft ──(submit)──▶ Submitted ──(confirm)──▶ Confirmed
  │                                          
  ├─ 仅 Draft 可录入/修改自评（upsertPerformanceReview）
  ├─ 周期须 Open 才可录入（cycle.status === 'Open'）
  ├─ submit: Draft → Submitted（自评锁定，待终评）
  ├─ confirm: Submitted → Confirmed（写入 managerScore/finalScore/grade，终态）
  └─ Confirmed 为终态，不可回退
```

| 状态 | bds-badge 变体 | 可执行操作 | 说明 |
|------|---------------|-----------|------|
| Draft | warning（黄） | 录入自评 / 修改自评 / 提交 | 草稿态，自评可改 |
| Submitted | info（蓝） | 终评确认 | 自评已锁定，待主管终评 |
| Confirmed | active（绿） | — | 终态，终评完成 |

### 5.1 前端状态映射（PerformanceTab.tsx）

```typescript
const reviewSemantic = (status: string): StatusSemantic => {
  switch (status) {
    case 'Confirmed': return 'active';   // 绿
    case 'Submitted': return 'info';     // 蓝
    default: return 'warning';           // 黄（Draft）
  }
};

const gradeSemantic = (grade: string | null): StatusSemantic => {
  switch (grade) {
    case 'A': return 'active';           // 绿（优秀）
    case 'B': return 'info';             // 蓝（良好）
    case 'C': return 'warning';          // 黄（合格）
    case 'D': return 'danger';           // 红（待改进）
    default: return 'neutral';           // 灰（未评级）
  }
};
```

## §6 周期状态机

```
Open ──(close)──▶ Closed
  │
  ├─ Open：可录入评定 / 提交评定 / 终评确认
  ├─ Closed：不可录入新评定（upsertPerformanceReview 校验 cycle.status === 'Open'）
  └─ closePerformanceCycle: 仅 Open 可关闭
```

| 状态 | bds-badge 变体 | 可执行操作 | 说明 |
|------|---------------|-----------|------|
| Open | active（绿） | 录入评定 / 提交 / 终评 / 关闭周期 | 开放态，可操作 |
| Closed | neutral（灰） | — | 已关闭，只读 |

### 6.1 前端状态映射（PerformanceTab.tsx）

```typescript
const cycleSemantic = (status: string): StatusSemantic => 
  (status === 'Open' ? 'active' : 'neutral');
```

## §7 终评确认流程

```
┌─────────────────────────────────────────────────────────────────┐
│  主管终评确认流程（confirmPerformanceReview）                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 前置校验                                                    │
│     ├─ 评定记录存在（REVIEW_NOT_FOUND）                          │
│     └─ 状态须为 Submitted（INVALID_TRANSITION）                  │
│                                                                 │
│  2. 评分校验                                                    │
│     ├─ managerScore 须为有限数且 0-100（VALIDATION_FAILED）      │
│     ├─ finalScore 须为有限数且 0-100（VALIDATION_FAILED）        │
│     └─ grade 须为 A/B/C/D 之一（VALIDATION_FAILED）             │
│                                                                 │
│  3. 写入终评数据                                                │
│     ├─ status: Submitted → Confirmed                            │
│     ├─ managerScore: 主管评分                                   │
│     ├─ finalScore: 终评分                                       │
│     ├─ grade: 评级                                              │
│     ├─ comment: 终评评语（覆盖自评说明，可选）                   │
│     └─ reviewerId: 终评人 ID（从 actorIdFromRequest 提取）       │
│                                                                 │
│  4. 审计日志                                                    │
│     └─ writeRouteAuditLog（confirm_performance_review）          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 7.1 评级语义

| 评级 | 标签 | bds-badge 变体 | 语义 |
|------|------|---------------|------|
| A | A（优秀） | active（绿） | 超出预期，卓越贡献 |
| B | B（良好） | info（蓝） | 达到预期，表现良好 |
| C | C（合格） | warning（黄） | 基本达标，有待提升 |
| D | D（待改进） | danger（红） | 未达预期，需重点改进 |

### 8.1 未评定员工筛选

```typescript
// 周期内尚无评定的员工（用于新建评定 picker）
const unreviewed = useMemo(() => {
  const reviewed = new Set(reviews.map(r => r.userId));
  return personnel.filter(p => !reviewed.has(p.id));
}, [reviews, personnel]);
```

> 筛选逻辑：从全体 personnel 中排除已有评定记录的 userId，确保一人一周期一评定。

## §13 关键业务规则

| # | 规则 | 实现位置 |
|---|------|---------|
| 1 | **周期 period 全局唯一** | `@@unique([period])` + createPerformanceCycle 校验 DUPLICATE_PERIOD |
| 2 | **一人一周期一评定** | `@@unique([cycleId, userId])` + upsertPerformanceReview upsert 语义 |
| 3 | **仅 Draft 可改自评** | upsertPerformanceReview 校验 `existing.status !== 'Draft'` → INVALID_TRANSITION |
| 4 | **周期须 Open 才可录入** | upsertPerformanceReview 校验 `cycle.status !== 'Open'` → INVALID_TRANSITION |
| 5 | **仅 Draft 可提交** | submitPerformanceReview 校验 `review.status !== 'Draft'` → INVALID_TRANSITION |
| 6 | **仅 Submitted 可终评** | confirmPerformanceReview 校验 `review.status !== 'Submitted'` → INVALID_TRANSITION |
| 7 | **评分范围 0-100** | selfScore/managerScore/finalScore 均校验 0-100，VALIDATION_FAILED |
| 8 | **评级限定 A/B/C/D** | confirmPerformanceReview 校验 `REVIEW_GRADES.includes(grade)`，VALIDATION_FAILED |

## §14 关键实现细节

### 14.1 upsertPerformanceReview（自评录入/更新）

```typescript
async function upsertPerformanceReview(input: {
  cycleId: string; userId: string; selfScore?: number | null;
  kpi?: unknown; comment?: string | null; reviewerId?: string | null;
}) {
  const cycle = await db.performanceCycle.findUnique({ where: { id: input.cycleId } });
  if (!cycle) throw new HrError('CYCLE_NOT_FOUND', `考核周期 ${input.cycleId} 不存在`);
  if (cycle.status !== 'Open') throw new HrError('INVALID_TRANSITION', `周期已关闭，不可录入`);
  if (input.selfScore !== undefined && input.selfScore !== null && 
      (input.selfScore < 0 || input.selfScore > 100)) {
    throw new HrError('VALIDATION_FAILED', '评分须在 0-100');
  }
  const existing = await db.performanceReview.findUnique({
    where: { cycleId_userId: { cycleId: input.cycleId, userId: input.userId } },
  });
  if (existing && existing.status !== 'Draft') {
    throw new HrError('INVALID_TRANSITION', `评定已 ${existing.status}，不可修改自评`);
  }
  // upsert：存在则更新（仅 Draft），不存在则创建
  const review = existing
    ? await db.performanceReview.update({ where: { id: existing.id }, data })
    : await db.performanceReview.create({ data: { id: genId('review'), ...data } });
  return { review };
}
```

### 14.2 listPerformanceCycles（聚合统计）

```typescript
async function listPerformanceCycles() {
  const cycles = await db.performanceCycle.findMany({
    orderBy: { period: 'desc' },
    include: { reviews: true },  // 关联查询评定记录
  });
  return cycles.map((c: any) => ({
    ...c,
    reviewCount: c.reviews.length,                                    // 评定总数
    confirmedCount: c.reviews.filter((r: any) => r.status === 'Confirmed').length,  // 已确认数
    reviews: undefined,  // 剥离明细，仅返回聚合
  }));
}
```

### 14.3 listPerformanceReviews（关联用户名）

```typescript
async function listPerformanceReviews(query: { cycleId?: string; userId?: string; status?: string } = {}) {
  const rows = await db.performanceReview.findMany({ where, orderBy: { createdAt: 'desc' } });
  // 批量查询关联用户（被评定人 + 终评人）
  const userIds = [...new Set(rows.flatMap((r: any) => [r.userId, r.reviewerId]).filter(Boolean))] as string[];
  const users = await db.userAccount.findMany({ where: { id: { in: userIds } } });
  const nameOf = new Map(users.map((u: any) => [u.id, u.displayName]));
  return rows.map((r: any) => ({
    ...r,
    displayName: nameOf.get(r.userId) ?? null,        // 被评定人姓名
    reviewerName: r.reviewerId ? nameOf.get(r.reviewerId) ?? null : null,  // 终评人姓名
  }));
}
```
