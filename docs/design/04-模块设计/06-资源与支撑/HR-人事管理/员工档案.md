## §2 模块边界与职责

| 职责域 | 已实现 | 规划增强 | 上下游依赖 |
|--------|--------|----------|-----------|
| **员工档案** | ✅ EmployeeProfile 1:1 UserAccount（userId @unique）+ employeeNo 自动生成 + upsertProfile 建档/更新 + 软删 + 状态/部门/姓名/工号/邮箱搜索 + profileView 关联展示（department/position） | ⚠️ 电子合同附件、员工自助修改 | 上游 UserAccount/Department/JobPosition；下游生命周期事件/薪资/绩效 |
| **employeeNo 生成** | ✅ nextEmployeeNo（EMP0001 格式 + count+attempt 计数 + P2002 重试兜底 5 次 + 时间戳极端兜底） | — | 上游 EmployeeProfile.count；下游建档 |
| **生命周期事件** | ✅ EmploymentEvent 历史流水（8 类事件）+ EVENT_TARGET_STATUS 状态映射 + EVENT_ALLOWED_FROM 前置状态校验 + 终态保护 + Onboard 自动建档 + Transfer/Promote 改岗位/部门 + publishBusinessEvent 事件发布 | ⚠️ 试用期转正/合同到期 watchdog | 上游 EmployeeProfile；下游通知引擎/薪资/绩效 |
| **状态变更唯一入口** | ✅ 禁止直接改 Profile.employmentStatus（upsertProfile 校验 STATUS_VIA_EVENT_ONLY） | — | 上游 upsertProfile；下游 recordEmploymentEvent |

> **核心设计纪律**：employmentStatus 字段只能通过 recordEmploymentEvent 变更，upsertProfile 入口若检测到 employmentStatus 变更会抛 `STATUS_VIA_EVENT_ONLY` 错误。这保证所有状态变更有事件流水留痕，可审计。

### 3.2 EmploymentEvent（生命周期事件 — append-only 流水）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | String | @id `evt_${ts}_${rand}` | 主键（genId 生成） |
| userId | String | — | 关联用户（松散引用，无 Prisma relation） |
| type | String | — | 事件类型：Onboard / Regularize / Transfer / Promote / Suspend / Resume / Resign / Terminate |
| effectiveDate | String | YYYY-MM-DD | 生效日期 |
| fromDeptId | String? | — | 原部门 ID（Transfer/Promote） |
| toDeptId | String? | — | 目标部门 ID（Transfer/Promote） |
| fromPositionId | String? | — | 原岗位 ID（Transfer/Promote） |
| toPositionId | String? | — | 目标岗位 ID（Transfer/Promote） |
| reason | String? | — | 异动原因 |
| operatorId | String? | — | 操作人 ID |
| createdAt | DateTime | @default(now()) | 创建时间 |

> **松散 id 引用设计**：EmploymentEvent 的 fromDeptId/toDeptId/fromPositionId/toPositionId 为松散字符串引用，无 Prisma @relation。这避免部门/岗位改名或删除影响历史流水的完整性。

## §4 employeeNo 自动生成

```
nextEmployeeNo()
  │
  ├─ 循环 5 次尝试（P2002 重试兜底并发）
  │   ├─ count = employeeProfile.count()
  │   ├─ candidate = `EMP${String(count + 1 + attempt).padStart(4, '0')}`
  │   │   示例：count=0, attempt=0 → EMP0001
  │   │        count=12, attempt=0 → EMP0013
  │   ├─ clash = employeeProfile.findUnique({ where: { employeeNo: candidate } })
  │   └─ clash 为 null → 返回 candidate
  │
  └─ 5 次均冲突 → 极端兜底：`EMP${Date.now().toString(36).toUpperCase()}`
```

**生成规则**：
- 格式：`EMP` + 4 位数字（左补零），如 `EMP0001`、`EMP0042`、`EMP1234`
- 计数基准：当前 EmployeeProfile 总数 + 1 + 尝试次数偏移
- 并发兜底：5 次重试，每次 candidate 递增 1，避免并发建档冲突
- 极端兜底：5 次均冲突（极端并发场景）→ 时间戳 base36 编码

## §5 生命周期事件状态机

### 5.1 事件 → 目标状态映射（EVENT_TARGET_STATUS）

| 事件类型 | 目标状态 | 说明 |
|---------|---------|------|
| `Onboard` | Probation | 入职（试用期），允许无档案自动建档 |
| `Regularize` | Regular | 转正，同时写入 regularDate = effectiveDate |
| `Transfer` | （不改状态） | 调岗，仅改 positionId + UserAccount.primaryDeptId |
| `Promote` | （不改状态） | 晋升，仅改 positionId（可同时改 primaryDeptId） |
| `Suspend` | Suspended | 停职 |
| `Resume` | Regular | 复职（仅 Suspended 可发起） |
| `Resign` | Resigned | 离职（终态） |
| `Terminate` | Terminated | 终止（终态） |

### 5.2 事件前置状态校验（EVENT_ALLOWED_FROM）

| 事件 | 允许的前置状态 | 校验失败错误 |
|------|--------------|------------|
| `Onboard` | （不限，允许无档案） | — |
| `Regularize` | Probation | INVALID_TRANSITION |
| `Transfer` | Probation, Regular | INVALID_TRANSITION |
| `Promote` | Probation, Regular | INVALID_TRANSITION |
| `Suspend` | Probation, Regular | INVALID_TRANSITION |
| `Resume` | Suspended | INVALID_TRANSITION |
| `Resign` | Probation, Regular, Suspended | INVALID_TRANSITION |
| `Terminate` | Probation, Regular, Suspended | INVALID_TRANSITION |

### 5.3 终态保护

```typescript
if (['Resigned', 'Terminated'].includes(profile.employmentStatus)) {
  throw new HrError('INVALID_TRANSITION',
    `员工已${profile.employmentStatus === 'Resigned' ? '离职' : '终止'}，不可再变更`);
}
```

Resigned/Terminated 为终态，任何事件均不可再发起。

### 5.4 状态流转图

```
                    Onboard
                       │
                       ▼
                  ┌─────────┐
        ┌────────▶│Probation│────────┐
        │         └────┬────┘        │
        │              │             │
        │   Regularize │             │ Suspend
        │              ▼             │
        │         ┌─────────┐◀───────┘
        │         │ Regular │
        │         └────┬────┘
        │              │
        │   Transfer/Promote（不改状态，仅改岗位/部门）
        │              │
        └──────────────┘
                       │
            Resign/Terminate
                       │
                       ▼
              ┌─────────────────┐
              │Resigned/Terminated│（终态，不可回退）
              └─────────────────┘

    Suspend → Resume → Regular（仅 Suspended 可 Resume）
```

## §6 建档与更新流程

### 6.1 upsertProfile 建档/更新

```
upsertProfile(input)
  │
  ├─ 校验
  │   ├─ userId 非空 → 否则 VALIDATION_FAILED
  │   ├─ UserAccount 存在 → 否则 USER_NOT_FOUND
  │   ├─ hireDate/regularDate/contractEnd 格式 YYYY-MM-DD
  │   ├─ contractType ∈ CONTRACT_TYPES
  │   └─ employmentStatus 变更检测 → STATUS_VIA_EVENT_ONLY
  │
  ├─ existing = employeeProfile.findUnique({ where: { userId } })
  │
  ├─ existing 存在 → update（positionId/hireDate/regularDate/contractType/contractEnd/phone/emergencyContact/workLocation/notes）
  │   └─ 返回 { profile: updated, created: false }
  │
  └─ existing 不存在 → create
      ├─ 校验 hireDate 必填（建档必须提供）
      ├─ employeeNo = nextEmployeeNo()
      ├─ employmentStatus 默认 Probation
      └─ 返回 { profile: created, created: true }
```

### 6.2 状态变更唯一入口纪律

```typescript
// upsertProfile 内部校验
if (existing && input.employmentStatus && input.employmentStatus !== existing.employmentStatus) {
  throw new HrError('STATUS_VIA_EVENT_ONLY',
    '在职状态变更必须经生命周期事件（recordEmploymentEvent）');
}
```

> **建档时允许指定初始状态**：若 existing 不存在（新建档），允许 input.employmentStatus 指定初始状态（默认 Probation）。但已存在档案的状态变更必须走 recordEmploymentEvent。

### 6.3 软删

```typescript
deleteProfile(userId)
  │
  └─ employeeProfile.updateMany({
       where: { userId, deletedAt: null },
       data: { deletedAt: BigInt(Date.now()) }
     })
```

软删仅标记 deletedAt，不物理删除。listProfiles 查询时 `where: { deletedAt: null }` 过滤已删除档案。

## §7 生命周期事件记录流程

```
recordEmploymentEvent(actorId, input)
  │
  ├─ 校验
  │   ├─ type ∈ EMPLOYMENT_EVENT_TYPES
  │   ├─ effectiveDate YYYY-MM-DD
  │   ├─ UserAccount 存在
  │   └─ profile = employeeProfile.findUnique({ where: { userId } })
  │
  ▼ 按 type 分支
  ┌─────────────────────────────────────────────────────────────┐
  │ type === 'Onboard':                                        │
  │   ├─ profile 不存在或已软删 → upsertProfile 自动建档       │
  │   └─ profile 存在 → 继续                                   │
  │                                                             │
  │ 其他事件:                                                   │
  │   ├─ profile 不存在或已软删 → PROFILE_NOT_FOUND            │
  │   ├─ allowed = EVENT_ALLOWED_FROM[type]                    │
  │   ├─ allowed 非空且 !allowed.includes(profile.status)      │
  │   │     → INVALID_TRANSITION                               │
  │   └─ profile.status ∈ [Resigned, Terminated]               │
  │         → INVALID_TRANSITION（终态保护）                    │
  └─────────────────────────────────────────────────────────────┘
  │
  ├─ 写入 EmploymentEvent（fromDeptId/toDeptId/fromPositionId/toPositionId/reason/operatorId）
  │
  ▼ 应用状态/岗位变动
  ┌─────────────────────────────────────────────────────────────┐
  │ profilePatch = {}                                          │
  │                                                             │
  │ ├─ targetStatus = EVENT_TARGET_STATUS[type]                │
  │ │   targetStatus 存在且 ≠ profile.status                   │
  │ │     → profilePatch.employmentStatus = targetStatus       │
  │ │                                                             │
  │ ├─ type === 'Regularize'                                   │
  │ │     → profilePatch.regularDate = effectiveDate           │
  │ │                                                             │
  │ ├─ type ∈ ['Transfer', 'Promote'] && toPositionId          │
  │ │     → profilePatch.positionId = toPositionId             │
  │ │                                                             │
  │ └─ profilePatch 非空 → employeeProfile.update              │
  └─────────────────────────────────────────────────────────────┘
  │
  ├─ 部门异动：toDeptId 非空 → userAccount.update({ primaryDeptId: toDeptId })
  │
  ├─ 事件发布（事务外，fire-and-forget）
  │   publishBusinessEvent({
  │     type: 'EmployeeStatusChanged',
  │     sourceEntityType: 'EmployeeProfile',
  │     sourceEntityId: profile.id,
  │     payload: { userId, displayName, eventType, effectiveDate, fromStatus, toStatus, reason },
  │     actorId,
  │   }).catch(e => logger.warn(...))  // 永不阻塞业务
  │
  └─ 返回 { event }
```

### 7.1 事件发布语义

`publishBusinessEvent` 为事务外 fire-and-forget：
- 业务事务提交后异步发布
- 发布失败仅 warn 日志，不回滚业务
- 通知引擎订阅 `EmployeeStatusChanged` 事件触发后续动作（如通知员工/主管）

### 7.2 Transfer/Promote 的特殊性

Transfer/Promote 不改 employmentStatus，仅改：
- positionId（Profile.positionId）
- primaryDeptId（UserAccount.primaryDeptId，若 toDeptId 非空）

这保证调岗/晋升不影响在职状态，但岗位和部门随之变更。

### 9.3 状态徽章语义映射

```typescript
const statusSemantic = (status: string): StatusSemantic => {
  switch (status) {
    case 'Regular': return 'active';      // 正式 → 绿
    case 'Probation': return 'info';      // 试用期 → 蓝
    case 'Suspended': return 'warning';   // 停职 → 黄
    case 'Resigned':
    case 'Terminated': return 'neutral';  // 离职/终止 → 灰
    default: return 'neutral';
  }
};

const eventSemantic = (type: string): StatusSemantic => {
  switch (type) {
    case 'Onboard':
    case 'Regularize':
    case 'Promote':
    case 'Resume': return 'active';       // 入职/转正/晋升/复职 → 绿
    case 'Transfer': return 'info';       // 调岗 → 蓝
    case 'Suspend': return 'warning';     // 停职 → 黄
    case 'Resign':
    case 'Terminate': return 'danger';    // 离职/终止 → 红
    default: return 'neutral';
  }
};
```

| GET | `/api/v1/hr/employment-events` | owner/admin | 生命周期事件列表（?userId&type&limit） |
| POST | `/api/v1/hr/employment-events` | owner/admin | 记录生命周期事件 |

### 10.1 守卫口径

HR 路由全程 `requireRole('owner', 'admin')`，最严格守卫（API-Key 即使通过 moduleGuard 也会因无 actor 被挡 → 401）。

### 10.2 错误码

| 错误码 | 触发场景 |
|--------|---------|
| `VALIDATION_FAILED` | 字段格式非法（日期/合同类型/事件类型等） |
| `USER_NOT_FOUND` | userId 对应的 UserAccount 不存在 |
| `STATUS_VIA_EVENT_ONLY` | upsertProfile 检测到 employmentStatus 变更 |
| `PROFILE_NOT_FOUND` | 非 Onboard 事件但用户无员工档案 |
| `INVALID_TRANSITION` | 事件前置状态校验失败 / 终态保护 |
