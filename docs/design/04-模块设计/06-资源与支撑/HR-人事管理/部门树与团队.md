## §2 模块边界与职责

| 职责域 | 已实现 | 规划增强 | 上下游依赖 |
|--------|--------|----------|-----------|
| **部门树** | ✅ Department 树形自引用（parentId + parent/children relation）+ status active/inactive + 树形导航（多级展开 + 搜索过滤） | ⚠️ 组织架构图可视化（ReactFlow） | 上游人工创建；下游员工档案 primaryDeptId |
| **岗位管理** | ✅ JobPosition CRUD（title + departmentId + description + headcount 编制 + status + 软删） | ⚠️ 岗位编制预警（在编人数超 headcount） | 上游 Department；下游 EmployeeProfile.positionId |
| **跨部门团队** | ✅ Team CRUD（name + description + leaderId + departmentId 可选 + status + 软删）+ TeamMember 关联（@@unique([teamId, userId]) + role + leftAt 退出标记） | ⚠️ 团队权限继承 | 上游 Department/UserAccount；下游 Project |
| **项目管理** | ✅ Project CRUD（name + code + description + teamId 可选 + status planning/active/on_hold/completed/cancelled + priority low/normal/high/urgent + startDate/endDate + 软删）+ ProjectMember 关联（@@unique([projectId, userId])） | ⚠️ 项目甘特图、里程碑管理 | 上游 Team；下游 WorkAssignment |
| **任务分配** | ✅ WorkAssignment CRUD（title + description + projectId 可选 + userId + assignerId + status assigned/in_progress/completed/overdue/cancelled + priority + dueDate + completedAt + 软删） | ⚠️ 任务看板、工时统计 | 上游 Project/UserAccount；下游绩效 |
| **审计日志** | ✅ writeRouteAuditLog（所有写操作记录审计：create/update/delete position/team/project/assignment） | — | 上游路由操作；下游审计追溯 |

> **核心设计**：部门（Department）为正式组织架构，团队（Team）为跨部门灵活组建（departmentId 可选），项目（Project）关联团队（teamId 可选），任务（WorkAssignment）分配到人（userId）且可关联项目（projectId 可选）。四级层次：部门 → 团队 → 项目 → 任务。

## §4 组织架构层次

```
┌─────────────────────────────────────────────────────────┐
│  Department（部门树 — 正式组织架构）                     │
│  ├─ parentId 自引用，多级嵌套                            │
│  ├─ status: active / inactive                            │
│  │                                                       │
│  ├─ JobPosition（岗位 — 编制）                           │
│  │   ├─ departmentId 关联部门                            │
│  │   ├─ headcount 编制人数                               │
│  │   └─ EmployeeProfile.positionId 关联员工              │
│  │                                                       │
│  └─ Team（跨部门团队 — 灵活组建）                        │
│      ├─ departmentId 可选（跨部门时为 null）             │
│      ├─ leaderId 负责人                                  │
│      │                                                   │
│      ├─ TeamMember（团队成员）                           │
│      │   ├─ @@unique([teamId, userId]) 防重复            │
│      │   └─ leftAt 退出标记                              │
│      │                                                   │
│      └─ Project（项目）                                  │
│          ├─ teamId 可选                                  │
│          ├─ status: planning/active/on_hold/completed    │
│          ├─ priority: low/normal/high/urgent             │
│          │                                               │
│          ├─ ProjectMember（项目成员）                    │
│          │   └─ @@unique([projectId, userId])            │
│          │                                               │
│          └─ WorkAssignment（任务分配）                   │
│              ├─ userId 分配给                            │
│              ├─ assignerId 分配人                        │
│              ├─ status: assigned/in_progress/completed   │
│              └─ dueDate / completedAt                    │
└─────────────────────────────────────────────────────────┘
```

### 4.1 层级关系

| 层级 | 实体 | 关联 | 说明 |
|------|------|------|------|
| 1 | Department | parentId 自引用 | 正式部门树 |
| 2 | JobPosition | departmentId → Department | 部门下岗位 |
| 2 | Team | departmentId → Department（可选） | 部门下团队（或跨部门） |
| 3 | TeamMember | teamId → Team | 团队成员 |
| 3 | Project | teamId → Team（可选） | 团队下项目（或独立） |
| 4 | ProjectMember | projectId → Project | 项目成员 |
| 4 | WorkAssignment | projectId → Project（可选） + userId | 任务分配到人 |

### 4.2 跨部门团队设计

Team.departmentId 为可选字段：
- **部门内团队**：departmentId 非空，团队归属某部门
- **跨部门团队**：departmentId 为 null，团队跨部门组建（如专项项目组、虚拟团队）

这允许灵活的组织形式，不强制团队必须归属部门。

### 5.1 OrgForest 数据结构

```typescript
interface OrgForest {
  depts: DeptNode[];           // 部门树（含子部门/团队/项目）
  orphanTeams: TeamNode[];     // 孤立团队（无部门归属）
  orphanProjects: ProjectNode[]; // 孤立项目（无团队归属）
}

interface DeptNode {
  kind: 'dept';
  dept: DeptInfo;
  childDepts: DeptNode[];      // 递归子部门
  teams: TeamNode[];           // 部门下团队
  headcount: number;           // 部门总人数
}

interface TeamNode {
  kind: 'team';
  team: TeamInfo;
  projects: ProjectNode[];     // 团队下项目
  headcount: number;           // 团队人数
}

interface ProjectNode {
  kind: 'project';
  project: ProjectInfo;
  headcount: number;           // 项目人数
}
```

### 5.2 搜索过滤

树形导航支持搜索过滤：
- 输入关键词 → 匹配部门/团队/项目名称
- 匹配节点及其父节点保持显示
- 无匹配时显示"未找到匹配的组织节点"

## §6 项目状态机

```
planning ──(启动)──▶ active ──(完成)──▶ completed
   │                    │
   │                    ├──(暂停)──▶ on_hold ──(恢复)──▶ active
   │                    │
   └──(取消)──▶ cancelled ◀──(取消)──┘
```

| 状态 | 标签 | bds-badge 变体 | 说明 |
|------|------|---------------|------|
| planning | 规划中 | neutral（灰） | 项目规划阶段 |
| active | 进行中 | info（蓝） | 项目进行中 |
| on_hold | 暂停 | warning（黄） | 项目暂停 |
| completed | 已完成 | success（绿） | 项目已完成 |
| cancelled | 已取消 | neutral（灰） | 项目已取消 |

## §7 任务分配状态机

```
assigned ──(开始)──▶ in_progress ──(完成)──▶ completed
   │                       │
   │                       └──(逾期)──▶ overdue
   │
   └──(取消)──▶ cancelled
```

| 状态 | 标签 | bds-badge 变体 | 说明 |
|------|------|---------------|------|
| assigned | 已分配 | neutral（灰） | 任务已分配待开始 |
| in_progress | 进行中 | info（蓝） | 任务进行中 |
| completed | 已完成 | success（绿） | 任务已完成（completedAt） |
| overdue | 已逾期 | danger（红） | 任务超期未完成 |
| cancelled | 已取消 | neutral（灰） | 任务已取消 |
