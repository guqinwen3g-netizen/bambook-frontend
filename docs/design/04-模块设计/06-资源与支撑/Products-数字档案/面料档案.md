## §2 业务定位与目标

### 2.1 业务定位

面料档案是服装生产最核心的物料主数据。每卷面料的技术规格（克重、门幅、成分、组织、纱支）、商务属性（品号、客户码、价格历史）、合规属性（认证许可、风险备注）统一沉淀在 `FabricProfile` 及其子集合中，作为采购、开发、报价、BOM 的物料锚点。

### 2.2 核心目标

1. **一物一档**：每个面料 `ProductAsset.sku` 全局唯一，FabricProfile 1:1 挂靠。
2. **规格标准化**：克重/门幅采用 `Float + Unit` 分离，避免「180g/m²」与「0.18kg/m²」混用。
3. **成分可累加**：`FabricCompositionLine` 多行百分比累加，关联术语库防歧义。
4. **价格历史分轨**：`priceType = factory / customer / sample / cutting` 四轨独立，按客户/来源可追溯。
5. **认证有效期管理**：`FabricCertification.validUntil` 用于预警扫描。
6. **客户专属编码**：一物多客，每客户独立 `clientCode`，避免跨客户混淆。
7. **PDML 外部接入**：ERP 原料库可一键映射为 FabricProfile。

## §3 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| 品号 `articleNo` | 面料厂内部品号（如 `FAB-2026-001`） |
| 厂家品号 `millArticleNo` | 工厂端品号（PDML 同步字段 `factoryArticleNo`） |
| 厂家色号 `millColorCode` | 工厂端色号 |
| 克重 `weightValue + weightUnit` | 单位面积重量（如 180 g/m²） |
| 门幅 `widthValue + widthUnit` | 织物幅宽（如 150 cm） |
| 组织 `construction` | 织物组织（如平纹/斜纹/缎纹） |
| 纱支 `yarnCount` | 纱线细度（如 40s × 40s） |
| 花型 `pattern` | 提花/印花花型 |
| MOQ | 最小起订量（区分 `moqValue / factoryMoqValue / sampleMoqValue` 三档） |
| 成分行 `FabricCompositionLine` | 面料成分行（如「棉 60% + 涤纶 40%」） |
| 客户码 `FabricCustomerCode` | 客户专属编码（一物多客） |
| 价格类型 `priceType` | `factory / customer / sample / cutting` 四轨 |
| 认证 `FabricCertification` | OEKO-TEX / GRS / OCS 等 |
| PDML 原料 | 外部 ERP 同步缓存 `PdmlRawFabric` |

## §5 关键流程

### 5.1 面料档案创建流程

```
1. 用户选 mainCategory=Fabric
2. 填 basic 段：sku, name, season, cost
3. 填 specs 段（FabricProfile 字段）：
   - articleNo, millName, millQuality
   - construction, yarnCount, pattern
   - weightValue + weightUnit, widthValue + widthUnit
   - productionLeadDays, stockStatus, MOQ 三档
4. 填成分行（CompositionLine[]）：
   - 选择 MaterialCompositionTerm（前端 CustomSelect 联想）
   - 输入 percentage
   - 前端校验百分比累加 ≈ 100（建议，不强制）
5. 填 pricing 段：
   - FabricCustomerCode[]（多客户）
   - FabricPriceHistory[]（多价格类型）
6. 填 risk 段：
   - FabricCertification[]（含 validUntil）
   - riskNote, specialNote
7. 提交 → POST /api/products
8. 服务端 $transaction 闭环写入 + AuditLog
```

### 5.2 PDML 映射流程

```
PdmlRawFabric (rawData 含 articleNo/colorCode/supplierName/...)
    │ 用户在「PDML 原料库」点击「映射为档案」
    ▼
POST /api/products/pdml/map { gsid, sourceId }
    │
    ▼
服务端从 rawData 提取字段：
  - articleNo → FabricProfile.articleNo
  - factoryArticleNo → FabricProfile.articleNo（如未指定）
  - colorCode → FabricProfile.millColorCode
  - factoryColorCode → FabricProfile.millColorCode
  - supplierName → FabricProfile.millName
  - registeredDate → 参考
  - imageUrl → ProductAsset.imageUrl
    │
    ▼
创建 ProductAsset (mainCategory=Fabric) + FabricProfile
    │
    ▼
返回 PdmlMapResult { created, updated, skipped }
```

### 5.3 价格历史追加流程

```
场景 A：采购单创建时自动追加 factory 价格
  PurchaseOrder 创建 → 事件 → productAsset 价格追加
  sourceType='order', sourceId=PO.id, priceType='factory'

场景 B：报价单确认时自动追加 customer 价格
  Quotation 确认 → 事件 → 追加
  sourceType='order', priceType='customer', customerOrganizationId

场景 C：手动追加
  用户在 pricing 段点击「+ 价格」
  sourceType='manual'
```

### 5.4 认证到期预警

```
定时扫描（或前端列表加载时触发）
  │
  ▼
GET /api/products/certifications/expiring?days=30
  │
  ▼
返回 FabricCertification[] (validUntil - today ≤ 30 天)
  │
  ▼
前端在 ProductsManager 顶部横幅展示
```

- 价格历史追加支持幂等（`sourceType + sourceId` 唯一约束建议，当前未强制）。

### 6.3 业务事件

- `FabricPriceAdded`：价格追加后发布（如订单/报价触发）。
- `FabricCertificationExpiring`：定时扫描发布，30 天内到期触发。

## §9 性能与扩展性

### 9.1 索引

- `FabricProfile`：`millOrganizationId` / `millQuality` / `articleNo` 三索引，支持厂家筛选与品号搜索。
- `FabricCompositionLine`：`productAssetId` / `termId` 双索引，支持按成分反查面料。
- `FabricCustomerCode`：`clientCode` 索引，支持客户码全局搜索。
- `FabricPriceHistory`：`priceType` / `customerOrganizationId` / `sourceType+sourceId` 三索引。
- `FabricCertification`：`certification` 索引，支持按认证类型筛选。

### 9.2 扩展性

- 成分行 `termId` 引用术语库，新增术语不影响存量数据。
- 价格类型 `priceType` 为 String（非枚举），可扩展新类型（如 `wholesale`）不改表。
- 认证 `certification` 为 String，可扩展新认证类型。
- `FabricProfile.weightValue/widthValue` 分离数值与单位，单位可自定义。

### 9.3 已知优化点

- 成分行百分比累加校验当前仅前端提示，服务端未强制（允许非 100% 的「未确定成分」档案）。
- 价格历史无唯一约束防止重复追加，依赖业务事件幂等（sourceType+sourceId）。

## §10 错误处理与边界

### 10.1 错误码

沿用 `ProductAssetMutationErrorCode`，子集合追加的错误码扩展：

| Code | 触发条件 |
| --- | --- |
| `INVALID_INPUT` | 必填字段缺失（如 clientCode / priceType / amount） |
| `INVALID_AMOUNT` | percentage / amount 非法 decimal |
| `NOT_FOUND` | productAssetId 不存在或已软删 |
| `TERM_NOT_FOUND` | termId 不存在 |

### 10.2 边界

- `weightValue / widthValue` 为 Float，前端校验非负，服务端 `isValidDecimal` 兜底。
- `percentage` 为 Decimal(18,4)，允许小数（如 33.3333%）。
- `validUntil` 为 String YYYY-MM-DD，前端 date input 原生校验。
- `currency` 自由 String，前端建议下拉（CNY/USD/EUR）但不强制。
- PDML 映射时若 articleNo 已存在则跳过或更新（`PdmlMapResult.updated/skipped`）。

## §13 已知限制与技术债务

1. 成分行百分比累加非强制 100%，可能导致数据不准（建议服务端校验或标记「未确定」）。
2. 价格历史无唯一约束防止重复追加，依赖业务事件幂等。
3. `weightUnit / widthUnit` 为 String，未约束为枚举（如 `g/m²` vs `gsm`）。
4. PDML 映射字段映射规则硬编码于服务层，未配置化。
5. 认证无附件上传（`attachmentPath` 字段在 FactoryCertification 有，FabricCertification 无）。
6. 术语库中英文双语维护成本高，无自动同步。

---

## §14 演进路线

1. **成分累加校验**：服务端强制百分比累加 100%（或标记「未确定」状态）。
2. **价格历史幂等约束**：`productAssetId + priceType + sourceType + sourceId` 唯一约束。
3. **单位枚举化**：`weightUnit` / `widthUnit` 改为枚举 + 单位换算工具。
4. **PDML 字段映射配置化**：抽到配置文件或 DB 表，支持可视化配置。
5. **认证附件**：FabricCertification 补 `attachmentPath` 字段。
6. **术语库国际化**：i18n key 替代直接中英文字段，支持多语言。
7. **价格趋势图**：前端按 `effectiveDate` 时间序列可视化价格波动。
8. **成分相似度评分**：扩展 `fabricRecommendationService`，支持跨档案成分相似度匹配。
