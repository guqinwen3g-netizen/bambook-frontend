## §2 业务定位与目标

### 2.1 业务定位

辅料档案承载纽扣、拉链、衬布、里布、缝线、织带、五金、垫肩、包装等辅料物料的规格主数据。每条 `TrimmingProfile` 描述一种辅料的完整属性：编码、名称、分类、材质、规格、尺寸、颜色、供应商、客户、适用产品、库存、价格、合规测试、质量标准。

辅料档案是 BOM 物料清单的核心组件——`GarmentProfile.button / zipper / thread / labelTrims / packaging` 等字段均指向辅料档案；采购单 `PurchaseLine.materialCode` 亦关联辅料编码。

### 2.2 核心目标

1. **一物一档**：每个辅料 `ProductAsset.sku` 唯一，TrimmingProfile 1:1。
2. **编码全局可搜**：`trimmingCode` 索引，支持跨供应商跨客户编码搜索。
3. **供应商关联**：`supplier + supplierRelationId` 双字段，打通 Suppliers 模块。
4. **客户专属辅料**：`customer` 字段支持客户专属辅料标准（如某客户指定纽扣供应商）。
5. **适用产品追溯**：`applicableProducts + usagePosition` 文本承载适用成衣清单与使用位置。
6. **库存与价格统一**：`stockStatus / stockQuantity / stockUnit / price / currency` 五字段统一辅料库存与定价。
7. **合规与质量管理**：`complianceTests / qualityStandard / riskNote` 三字段承载辅料合规与风险。

## §5 关键流程

### 5.1 辅料档案创建流程

```
1. 用户选 mainCategory=Trimmings
2. 选子类目（纽扣/拉链/衬布/里布/缝线/织带/五金/垫肩/包装…）
3. 填 basic 段：sku, name, season, cost
4. 填 specs 段（TrimmingProfile 字段）：
   a. 基础标识：trimmingCode, trimmingName, trimmingCategory
   b. 规格属性：material, specification, size, color, colorCode, finish
   c. 供应商工厂：supplier, supplierRelationId, factory, brand
   d. 客户适用：customer, applicableProducts, usagePosition, careRequirement
   e. 用量库存：unit, unitConsumption, moq, leadTime, stockStatus, stockQuantity, stockUnit
   f. 价格合规：price, currency, complianceTests, qualityStandard, riskNote
5. 填 notes 段：packaging, notes
6. 提交 → POST /api/products
7. 服务端 $transaction 闭环写入 + AuditLog
```

### 5.2 供应商关联流程

```
用户在 supplier 字段选择 Relation
  │
  ▼
前端调用 apiService.listRelations({ category: 'Supplier', isOrganization: true })
  │
  ▼
选中后 supplier = relation.name, supplierRelationId = relation.id
  │
  ▼
保存到 TrimmingProfile
  │
  ▼
SuppliersManager 可通过 relationId 反查关联辅料清单
（通过 RelatedEntitiesPanel 跨模块视图）
```

### 5.3 BOM 物料清单关联流程

```
场景：成衣档案 → BOM 引用辅料
  │
  ▼
方案 A（当前文本承载）：
  GarmentProfile.button = "TRIM-BTN-001（树脂扣 18mm × 8 颗）"
  → 人工录入文本，无强约束

方案 B（BOM 模块结构化）：
  BOM(productAssetId=成衣id) 创建
  + BOMLine(materialAssetId=辅料id, quantity=8, unit='PC')
  → 强约束外键，可追溯
```

### 5.4 编码搜索流程

```
用户在 ProductsManager 搜索框输入辅料编码
  │
  ▼
GET /api/products?search=TRIM-BTN-001&mainCategory=Trimmings
  │
  ▼
服务端 ILIKE 搜索 sku / name / TrimmingProfile.trimmingCode
  │
  ▼
返回匹配档案列表
```

## §6 API 与服务契约

### 6.1 专属端点

| Method | Path | 用途 |
| --- | --- | --- |
| GET | `/api/products/:id/trimming-profile` | 单独获取 TrimmingProfile |
| PUT | `/api/products/:id/trimming-profile` | 更新 TrimmingProfile |
| GET | `/api/products/trimmings/by-code?trimmingCode=TRIM-BTN-001` | 按编码搜索 |
| GET | `/api/products/trimmings/by-supplier?supplierRelationId=xxx` | 按供应商筛选 |
| GET | `/api/products/trimmings/by-category?trimmingCategory=Button` | 按分类筛选 |

### 6.2 服务层契约

- `productAssetMutationService.updateProductAsset` 支持嵌套更新 TrimmingProfile。
- 33 字段均通过 `productAssetWritable` 白名单过滤。
- 字段更新通过 AuditLog 记录 before/after 快照。

### 6.3 业务事件

- `TrimmingProfileUpdated`：字段更新后发布。
- `TrimmingCodeChanged`：编码变更时发布（影响 BOM 关联）。

## §10 错误处理与边界

### 10.1 错误码

沿用 `ProductAssetMutationErrorCode`。

### 10.2 边界

- `trimmingCode` 不强制全局唯一。
- `supplierRelationId` 为松外键，Relation 删除时不级联。
- `stockQuantity` 为 Float?，允许小数（如 0.5 卷）。
- `price` 为 String?，未约束格式（如「¥0.5」「$0.07」），前端建议规范化。

## §13 已知限制与技术债务

1. **适用产品文本承载**：`applicableProducts` 为 String?，无法结构化关联成衣档案，无法做反向查询（哪些成衣用了此辅料）。建议拆出 `GarmentTrimmingLink` 中间表。
2. **价格未历史化**：`price` 为单值字段，无价格历史。建议拆出 `TrimmingPriceHistory` 子表。
3. **供应商松外键**：`supplierRelationId` 未强制约束，Relation 删除后可能产生孤儿引用。
4. **价格字段格式不统一**：`price` 为 String?，币种与金额混用，建议拆为 `priceAmount Decimal + currency String`。
5. **无颜色码本管理**：`color / colorCode` 为自由文本，无标准色卡关联。

---

## §14 演进路线

1. **适用产品结构化**：拆出 `GarmentTrimmingLink` 中间表，承载「成衣 ↔ 辅料 ↔ 使用位置 ↔ 单耗」。
2. **价格历史化**：拆出 `TrimmingPriceHistory` 子表（priceType=supplier/customer）。
3. **供应商强约束**：`supplierRelationId` 加 FK 约束。
4. **价格字段结构化**：`price` 拆为 `priceAmount Decimal + currency String`。
5. **色卡管理**：引入 `ColorCard` 模型，关联 `colorCode`。
6. **BOM 集成**：与 BOM 模块深度整合，BOMLine 强约束外键关联 TrimmingProfile。
7. **AI 辅料推荐**：基于成衣款式 + 历史辅料使用推荐合适辅料。
