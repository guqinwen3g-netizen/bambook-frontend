## §2 业务定位与目标

### 2.1 业务定位

成衣档案是服装生产管理的款式主数据。每个 `GarmentProfile` 承载一款成衣的完整技术规格：款号、品类、客户、工厂、款式结构（廓形/版型/领型/袖型/门襟/口袋/下摆/腰头）、BOM 物料清单（主面料/撞色面料/里布/罗纹/袋布/纽扣/拉链/扣眼/缝线/商标/包装）、尺码规格（尺码范围/基码/测量点/尺寸表/公差/放码规则/缩水率）、价格（目标成本/FOB/EXW/零售价）、生产属性（工艺/品控/包装/产地）。

### 2.2 核心目标

1. **一物一档**：每个成衣 `ProductAsset.sku` 唯一，GarmentProfile 1:1。
2. **款号全局可搜**：`styleNo` 索引，支持跨客户跨季节款号搜索。
3. **客户/工厂双关联**：`customerRelationId` + `factoryRelationId` 双外键，打通 Relation 供应商与客户模块。
4. **BOM 物料清单**：11 类物料字段（主面料/撞色面料/里布/罗纹/袋布/纽扣/拉链/扣眼/缝线/商标/包装），文本承载当前 BOM 摘要。
5. **四档价格管理**：目标成本 / FOB / EXW / 零售价，覆盖成本核算到终端定价。
6. **生产属性沉淀**：工艺备注 / 检验标准 / 常见疵点 / 水洗整理 / 洗水标 / 合规测试 / 包装方式 / 装箱规格 / 原产地 / 质量备注。

## §5 关键流程

### 5.1 成衣档案创建流程

```
1. 用户选 mainCategory=Garment
2. 选子类目（西装/外套/衬衫/裤装…）
3. 填 basic 段：sku, name, season, cost
4. 填 specs 段（GarmentProfile 字段）：
   a. 基础标识：styleNo, garmentCategory, collection
   b. 客户工厂：customer, customerRelationId, factoryRelationId
   c. 款式结构：silhouette, fit, collarType, sleeveType, closureType, pocket/hem/waistband
   d. BOM 物料：mainFabric, contrastFabric, liningFabric, button, zipper...
   e. 尺码规格：sizeRange, baseSize, sizeSpec, tolerance, gradingRule
   f. 品控合规：inspectionStandard, washFinishing, careLabel, complianceTests
5. 填 pricing 段：targetCost, fobPrice, exwPrice, retailPrice
6. 填 notes 段：constructionNote, qualityNote, commonDefects
7. 提交 → POST /api/products
8. 服务端 $transaction 闭环写入 + AuditLog
```

### 5.2 BOM 关联流程

```
场景：成衣档案 → 生成 BOM
  │
  ▼
方案 A（当前文本承载）：
  GarmentProfile.mainFabric = "FAB-2026-001（180g 棉涤混纺）"
  GarmentProfile.button = "金属扣 18mm × 8 颗"
  → 人工录入文本，无强约束

方案 B（BOM 模块结构化）：
  BOM(productAssetId=成衣id) 创建
  + BOMLine(materialAssetId=面料id, quantity=1.5m)
  + BOMLine(materialAssetId=纽扣id, quantity=8)
  → 强约束外键，可追溯
```

### 5.3 客户/工厂关联流程

```
用户在 customer 字段选择 Relation
  │
  ▼
前端调用 apiService.listRelations({ category: 'Customer', isOrganization: true })
  │
  ▼
选中后 customer = relation.name, customerRelationId = relation.id
  │
  ▼
保存到 GarmentProfile
  │
  ▼
SuppliersManager 可通过 relationId 反查本档案
（通过 RelatedEntitiesPanel 跨模块视图）
```

### 5.4 款号搜索流程

```
用户在 ProductsManager 搜索框输入款号
  │
  ▼
GET /api/products?search=M2026-001&mainCategory=Garment
  │
  ▼
服务端 ILIKE 搜索 sku / name / GarmentProfile.styleNo
  │
  ▼
返回匹配档案列表
```

## §6 API 与服务契约

### 6.1 专属端点

| Method | Path | 用途 |
| --- | --- | --- |
| GET | `/api/products/:id/garment-profile` | 单独获取 GarmentProfile |
| PUT | `/api/products/:id/garment-profile` | 更新 GarmentProfile |

### 6.2 服务层契约

- `productAssetMutationService.updateProductAsset` 支持嵌套更新 GarmentProfile。
- GarmentProfile 80+ 字段均通过 `productAssetWritable` 白名单过滤。
- 字段更新通过 AuditLog 记录 before/after 快照。

### 6.3 业务事件

- `GarmentProfileUpdated`：字段更新后发布。
- `GarmentStyleNoChanged`：款号变更时发布（影响订单关联）。

## §9 性能与扩展性

### 9.1 索引

- `styleNo`：款号搜索。
- `garmentCategory`：品类筛选。
- `customer` / `customerRelationId`：客户筛选。
- `factory` / `factoryRelationId`：工厂筛选。

### 9.2 扩展性

- GarmentProfile 80+ 字段均为 String?，可灵活扩展（不强制 schema）。
- 文本承载的 BOM / 尺码表 / 工序可通过 JSON 字符串扩展结构化数据。
- `customerRelationId` / `factoryRelationId` 为松外键（不强制约束），允许跨模块解耦。

### 9.3 已知性能问题

- 80+ 字段单次查询返回较大，建议详情接口才 `include`，列表仅返回基础字段。
- 文本承载的 BOM 无法做关联查询，需前端二次解析。

## §10 错误处理与边界

### 10.1 错误码

沿用 `ProductAssetMutationErrorCode`。

### 10.2 边界

- `styleNo` 不强制全局唯一（不同客户可有同款号）。
- `customerRelationId` / `factoryRelationId` 为松外键，Relation 删除时不级联（业务层处理）。
- `confirmedDate` / `deliveryDate` 为 String YYYY-MM-DD，前端 date input 校验。
- 价格字段（targetCost/FOB/EXW/零售）为 String?，未结构化为 Decimal（建议后续拆为价格历史子表）。

## §13 已知限制与技术债务

1. **BOM 文本承载**：11 类物料字段均为 String?，无法结构化关联面料/辅料档案，无法做 BOM 汇总与物料需求计算。建议拆出 `BOMLine` 子表，外键关联 ProductAsset。
2. **尺码表文本承载**：`sizeSpec / measurementPoints / gradingRule` 均为 String?，无法按尺码筛选或导出。建议拆出 `GarmentSizeSpec` 子表。
3. **工序未落地**：仅有 `constructionNote` 文本字段，无独立工序子表。建议拆出 `GarmentProcessStep` 子表。
4. **价格未历史化**：`targetCost/FOB/EXW/零售` 为单值字段，无价格历史。建议复用 `FabricPriceHistory` 模式拆出 `GarmentPriceHistory`。
5. **客户/工厂松外键**：`customerRelationId / factoryRelationId` 未强制约束，Relation 删除后可能产生孤儿引用。
6. **字段过多**：80+ 字段单表，建议按业务域拆分（如 `GarmentStyleSpec` / `GarmentBOMSummary` / `GarmentPricing` / `GarmentQualityCompliance`）。

## §14 演进路线

1. **BOM 结构化**：拆出 `BOMLine` 子表，外键关联 `ProductAsset`（面料/辅料档案），承载用量/损耗/替代料。与 `BOM` 模块（schema.prisma 3918 行）整合。
2. **尺码表结构化**：拆出 `GarmentSizeSpec` 子表（尺码 + 测量点 + 公差）。
3. **工序子表**：拆出 `GarmentProcessStep` 子表（工序号 + 名称 + 工时 + 设备）。
4. **价格历史化**：复用 `FabricPriceHistory` 模式拆出 `GarmentPriceHistory`（priceType=factory/customer/retail）。
5. **客户/工厂强约束**：`customerRelationId / factoryRelationId` 加 FK 约束。
6. **字段分组拆表**：80+ 字段按业务域拆 4 张子表。
7. **Tech Pack 文件管理**：`techPackUrl` 字段增强为附件管理（多版本）。
8. **款号全局唯一策略**：可选全局唯一约束（按业务策略）。
9. **AI 款式生成**：基于历史款式 + 趋势标签推荐字段值。
