## §2 业务定位与目标

### 本地模拟库补齐（2026-10-10）

- 执行入口：`server/scripts/seed-supplier-workbench.ts --apply`，须在server目录运行；仅允许loopback的`panda_hub_dev`，写前pg_dump。只补已识别的开发档案和本脚本前缀数据，重复运行不重复采购、验收、评分或TC。名称不加“模拟”前缀，银行账户显式使用TEST标识，不提供可支付的真实账号。
- 29个既有工厂补齐设备、人员、月产能、价格档、合作日期及银行字段；导入87笔历史采购和87条配套验收记录。历史记录不执行新增库存/应付过账；累计采购数、金额通过`accumulateCompletedPurchaseOrderStats`同事务累计，不凭空修改排名缓存。评分通过`addEvaluation`写明细并重算，认证与产能使用业务服务。
- 覆盖有效/临期/过期认证、三个月计划产能、3条延迟影响、一个独立整改拉黑供应商、一个再生面料历史订单及三段TC（1050→1020→1000KG）。TC的我方销售段挂客户，原料与工厂段挂供应商；不把普通羊毛/棉订单伪造为GRS订单。
- 发现并修复产能真源缺口：`factoryService.aggregateOccupiedByUnit`按行的`supplierCommittedDeliveryDate`落月，旧单回退主单`expectedDeliveryDate`；未知日期不编造。当前两张已批准采购在10月占用2700M/2800M。
- API核验：列表30家（正常29/拉黑1），逐个正常档案overview回读成功、三段TC校验complete；证据`docs/design-system/evidence/demo-data-audit-2026-10-08/supplier-workbench-api-check.json`。产能/档案/评分15项针对性回归通过，server构建通过。全文件22测试另有两个旧失败：日期跨日硬编码断言和已退役采购创建接口断言；未为造数放开旧接口。浏览器视觉与交互未验。

### 2.1 业务定位

`Suppliers` 是 Bambook 服装生产管理系统的「供应商中枢」——承载服装工厂、面料厂、辅料厂等所有生产供应商的工厂属性、评分、认证、产能、银行、黑名单等管理数据。

**身份真源在 `Relation`（category=Supplier 的组织）**，`FactoryProfile` 以 1:1 关联 Relation 承载工厂专属属性。这是与 CRM 模块一致的设计原则：身份在 Relation，业务属性在 Profile。

### 2.2 核心目标

1. **一厂一档**：每个 `FactoryProfile` 唯一 `relationId` 挂 Relation。
2. **360° 视图**：总览 / 评分记录 / 认证管理 / 产能日历四 Tab 完整呈现工厂全貌。
3. **自动评分**：验货/交货业务事件自动追加评分，事务内重算缓存分。
4. **产能可视化**：月计划产能 + 在手采购单占用实时聚合，忙闲一目了然。
5. **认证预警**：30 天内到期认证顶部横幅提醒，剩余天数色阶（success/warning/danger）。
6. **黑名单管控**：拉黑后禁止新建采购单，服务端 `assertNotBlacklisted` 强制校验。
7. **跨模块落点**：Relations → Suppliers 跨模块跳转，支持黑名单工厂落点。

### 2.3 设计原则

- **软删除**（`deletedAt BigInt?`），不物理删除。
- **事务内写入 + 评分重算**（fail closed）：评分追加同事务重算缓存，禁止客户端直改。
- **事件发布失败不阻断业务**（fire-and-forget）。
- **BDS v2.1 主题透明**：bds 组件类 + 语义 token，无 isDarkMode 样式分支，无阴影，大圆角。

## §4 数据模型概览

### 4.1 聚合根关系图

```
Relation (category=Supplier, isOrganization=true)  ← 身份真源
    │ 1:1 @unique (relationId)
    ▼
FactoryProfile  ← 工厂属性扩展
    │ 1:N (factoryId)
    ├─► FactoryEvaluation (评分明细 append-only)
    ├─► FactoryCertification (认证记录 + 有效期)
    └─► FactoryCapacity (月产能日历)

FactoryProfile
    │ 字段引用
    ├─► qualityScore / deliveryScore（缓存分，事务内重算）
    ├─► blacklistedAt / blacklistReason / blacklistedById（黑名单）
    └─► bankName / bankAccount / bankSwift（银行信息）

FactoryCapacity
    │ 占用量 occupied 实时聚合
    ▼
PurchaseOrder (supplierRelationId, expectedDeliveryDate)
    └─► PurchaseLine (quantity)  → 按落月累加 = occupied
```

### 4.2 关键约束

- `FactoryProfile.relationId` 全局 `@unique`，1:1 挂 Relation，`onDelete: Cascade`。
- `FactoryCapacity` 上 `@@unique([factoryId, month])`，保证一厂一月一行。
- 评分缓存 `qualityScore / deliveryScore` 由服务端事务内重算，禁止客户端直改。
- 产能占用 `occupied` 不落地（实时聚合），口径变更无需回填。
- 黑名单 `blacklistedAt` 非空时禁止新建采购单（`assertNotBlacklisted` 服务端强制）。

### 4.3 ID 生成

- `FactoryProfile.id`：`FACP__${shortId}`（crypto.randomBytes base64url）。
- `FactoryEvaluation.id`：`FAEV__${shortId}`。
- `FactoryCertification.id`：`FACR__${shortId}`。
- `FactoryCapacity.id`：`FACC__${shortId}`。

## §5 关键流程

### 5.1 供应商身份、生产资料与两个入口（2026-10-10 修正）

- 关系智库维护供应商身份、联系人、地址和交易基础信息；供应商管理围绕同一身份展示合作、评分、认证、产能和业务关联。两处不是两个独立档案库。
- 供应商列表以全部有效 `Relation(category=Supplier,isOrganization=true)` 为目录真源，无生产资料者也直接列出。`GET /api/v1/suppliers/directory` 服务端关联 FactoryProfile 后分页、排序、筛选并返回准确总数；不能只列 FactoryProfile，也不全量拉取后前端凑列表。
- 「新增供应商」直接复用关系智库的真实组织录入表单 `SupplierIdentityWorkspace`，默认供应商分类；不再询问新建／已有，不另造工厂／贸易商类型枚举，不夹带产能字段。仅保存 Relation，不为列表可见性生成空生产扩展；保存后回到同供应商的详情。基础创建要求 relations:write。
- 录入供应商身份是独立工作区：进入时隐藏并禁用整个供应商浏览区，注销旧标题栏的导航注册，关闭认证预警浮层，只保留录入标题与操作；返回后恢复原列表DOM及原选择／滚动位置，不能将两个页面透明叠放。
- 已有供应商从现有列表打开。详情内「完善生产资料」仅维护产能、设备、品类等扩展；要求 suppliers:write。首次保存按 relationId ensure 一对一扩展并应用本次填写，后续更新原 profile ID，不覆盖评分／认证／历史采购。黑名单仍要求 suppliers:admin；无扩展时该显式管理操作另须供应商写权限。
- 无扩展时仅展示基础信息和可用业务关联，不展示可写评分／认证／产能空页。目录返回 productionProfileId=null 表达该状态，productionArchived 标识停用扩展；不得自动恢复停用档案。已有 FactoryProfile 模型、ID及关联记录保留，不删除／迁移历史。
- 创建表单沿用关系保存 API、编号和权限门禁；一次草稿沿用稳定 Relation ID，失败保留表单并显示错误。共享创建工作区隔离关系浏览导航，刷新状态按账号和创建会话保存，不能覆盖关系智库的浏览位置。名称不是身份或自动分类依据。
- 验证：共享组织表单创建／失败重试、供应商基础详情、生产扩展复用、返回与同步等16项前端针对性测试；目录与 ensure 后端7项测试。真实开发库只读核对36个供应商（30个有扩展、6个无扩展），全部可列出且分页无重复；重启后目录与基础详情HTTP均返回200。前后端最终构建通过；全仓类型检查有6项其他文件错误，本轮供应商／关系改动未报错。视觉与真实浏览器操作待验；当前浏览器访问受限，无本轮实渲染截图，不得据此宣称视觉完成。

### 5.2 评分追加与重算流程

```
触发源：
  A. 用户手动追加（EvaluationsTab → +手动评分）
  B. 业务事件自动追加（验货报告 / 交货完成 → recordAutoEvaluation）

流程：
  addEvaluation(factoryId, { kind, score, sourceType, sourceId, evaluatedAt, note })
    │
    ▼
  $transaction {
    1. 校验 factoryId 存在且未软删
    2. assertScore(score)  // 0-100
    3. 校验 evaluatedAt 格式 YYYY-MM-DD
    4. 写入 FactoryEvaluation（append-only）
    5. 同事务重算缓存：
       - 查 inspectionRows / deliveryRows
       - avg(inspectionRows) → qualityScore
       - avg(deliveryRows) → deliveryScore
    6. 更新 FactoryProfile.qualityScore / deliveryScore / updatedAt
  }
    │
    ▼
  事务提交后发布事件 FactoryEvaluationAdded（fire-and-forget）
```

### 5.3 自动评分幂等流程

```
业务事件（如验货报告提交）触发 recordAutoEvaluation
  │
  ▼
1. 通过 relationId 查 FactoryProfile（无档案静默跳过，不阻断主流程）
2. 查重：同 (factoryId, kind, sourceType, sourceId) 是否已存在
   - 存在 → 静默跳过（recorded: false, evaluationId: dup.id）
3. 不存在 → 调用 addEvaluation 追加
```

### 5.4 产能占用聚合流程

```
用户进入工厂详情 → 切到「产能日历」Tab
  │
  ▼
listCapacity(factoryId)
  │
  ▼
1. 查 FactoryCapacity[]（按 month 升序）
2. aggregateOccupied(relationId, months[])
   - 查 PurchaseOrder（supplierRelationId + status in [Sent, Confirmed, PartiallyReceived]）
   - 按 expectedDeliveryDate 落月（slice 0,7）
   - 累加 PurchaseLine.quantity 到 occupied[month]
3. 返回 rows.map(r => ({ ...r, occupied: occupied[r.month] || 0 }))
  │
  ▼
前端渲染：
  - 每行：month + capacity + occupied + 占用比%
  - 占用条进度条：>100% danger / >80% warning / 其他 success
```

### 5.5 黑名单流程

```
拉黑：
  setBlacklist(factoryId, reason, actorId)
    │
    ▼
  $transaction {
    1. 校验调用者权限（owner/admin/manager）
    2. FactoryProfile.update({ blacklistedAt: now, blacklistReason: reason, blacklistedById: actorId })
    3. AuditLog
  }
    │
    ▼
  后续新建采购单时：
    assertNotBlacklisted(factoryId)  // 服务端强制校验
    若 blacklistedAt != null → 抛错「工厂已拉黑，禁止新建采购单」

解除拉黑：
  clearBlacklist(factoryId, actorId)
    │
    ▼
  FactoryProfile.update({ blacklistedAt: null, blacklistReason: null, blacklistedById: null })
```

### 5.6 认证预警流程

```
SuppliersManager 加载时 / 定时任务
  │
  ▼
listExpiringCertifications(EXPIRING_DAYS=30)
  │
  ▼
1. 查 FactoryCertification（deletedAt=null, validUntil != null）
2. 计算 validUntil - today ≤ 30 天
3. 返回 FactoryCertification[] (含 factory.profile 关联)
  │
  ▼
前端顶部横幅展示：{N} 项工厂认证将于 30 天内到期
点击展开 → 列表显示工厂名 + 认证类型 + 剩余天数 + 色阶徽章
```

### 6.2 服务层契约（factoryService.ts）

- `createFactoryService(prisma)` 工厂函数，返回所有方法。
- 所有 mutation 走 `$transaction` + AuditLog。
- 评分重算纯函数 `deliveryScoreForDaysLate` / `inspectionScoreForResult`（factoryService.ts 92–106 行）集中口径。
- 评分缓存 `qualityScore / deliveryScore` 由 `addEvaluation` 同事务重算。
- 产能占用 `aggregateOccupied` 纯查询，无写入。

### 6.3 业务事件

- `FactoryEvaluationAdded`：评分追加后发布。
- `FactoryBlacklisted`：拉黑后发布。
- `FactoryUnblacklisted`：解除拉黑后发布。
- `FactoryCertificationExpiring`：定时扫描发布（30 天内到期）。
- `FactoryCapacityUpdated`：月产能 upsert 后发布。

### 6.4 跨模块事件订阅

- 验货报告提交 → `recordAutoEvaluation(kind='inspection')` 自动追加质量分。
- 采购单收齐 → `recordAutoEvaluation(kind='delivery')` 自动追加交期分。

### 7.2 排名列表

- **搜索**：按供应商名称（relation.name）模糊搜索，300ms debounce。
- **过滤**：`active`（正常）/ `blacklisted`（已拉黑）/ `all`（全部）三段控件。
- **排序**：`quality`（质量分优先）/ `delivery`（交期分优先）/ `orders`（订单数优先）/ `amount`（金额优先）。
- **行信息**：供应商名称 + 已拉黑徽章 + 质量分徽章 + 交期分徽章 + 累计单数。
- **色阶**：≥80 success / ≥60 warning / <60 danger。

### 7.3 详情头部卡

- 工厂名 + 已拉黑徽章（danger）+ 价位徽章（info）。
- 累计单数 / 累计金额 / 首次合作 / 月产能。
- 质量分 / 交期分 ScoreBadge（大字 + 标签）。
- 操作行：完善生产资料 / 基础资料（跳 Relations）/ 拉黑或解除拉黑 / 停用生产资料。无扩展者隐藏生产专属操作，停用不删除Relation身份。
- 已拉黑时显示拉黑原因 alert（danger）。

### 7.4 Tab 栏

| Tab | 图标 | 内容 |
| --- | --- | --- |
| 总览 | Building2 | 擅长品类徽章 + 档案字段网格（10 字段） + 备注 + Relation 联系信息 |
| 评分记录 | Star | 评分类型段控件（全部/验货/交期）+ 评分列表（类型徽章 + 分数徽章 + 备注 + 日期 + 来源） |
| 认证管理 | ShieldCheck | 认证列表（图标 + 类型 + 编号 + 签发/有效期 + 剩余天数徽章 + 编辑/删除） |
| 产能日历 | CalendarRange | 月产能列表（月份 + 计划产能 + 占用量 + 占用比 + 进度条 + 编辑/删除） |

### 7.5 弹窗表单

- **SupplierIdentityWorkspace**：共用关系智库组织表单，只建供应商身份。
- **ProfileForm**：在已选供应商内完善生产扩展（产能 + 工人 + 专长 + 价位 + 银行 + 备注），没有身份选择器。
- **EvaluationForm**：手动追加评分（类型 + 分数 0-100 + 日期 + 备注）。
- **CertificationForm**：新增/编辑认证（类型下拉 + 自定义 + 编号 + 签发/有效期 + 长期有效复选框）。
- **CapacityForm**：设置月产能（月份 + 计划产能 + 单位 + 备注）。
- **BlacklistForm**：拉黑表单（拉黑原因必填 + 警示 alert）。

### 7.6 设计系统合规

- 完全使用 BDS v2.1 组件类（bds-btn / bds-card / bds-badge / bds-listrow / bds-segment / bds-alert / bds-modal）。
- 语义 token（`--text-primary` / `--bg-panel` / `--success-tint` 等），主题透明。
- 无 isDarkMode 分支，暗色由 tokens.css `[data-theme]` 统一覆盖。
- 无阴影、无 rim、大圆角（`rounded-card`）。
- 评分色阶：`scoreSemantic` 函数（≥80 success / ≥60 warning / <60 danger）。
- 认证色阶：`certSemantic` 函数（null neutral / <0 danger / ≤30 warning / 其他 success）。

## §9 性能与扩展性

### 9.1 索引

- `FactoryProfile`：`blacklistedAt`（黑名单筛选）、`qualityScore`（排名）。
- `FactoryEvaluation`：`factoryId + kind`（评分查询）、`sourceType + sourceId`（幂等查重）。
- `FactoryCertification`：`factoryId`、`validUntil`（预警扫描）。
- `FactoryCapacity`：`factoryId + month`（unique）、`month`（按月查询）。

### 9.2 扩展性

- 评分类型 `kind` 为 String，可扩展新类型（如 `responsiveness` 响应速度）不改表。
- 认证 `type` 为 String，可扩展新认证类型。
- 产能 `unit` 为 String，可扩展新单位（如 `KG`）。
- `specialties` 为 String[]，可任意扩展品类。

### 9.3 已知性能优化点

- 360° 总览 `getOverview` 并行查 evaluations + certifications + capacity，避免串行。
- 评分列表 `take: 200` 限制返回数量。
- 产能占用聚合按 `expectedDeliveryDate` 索引（PurchaseOrder 已有）。
- 供应商目录默认每页20家，服务端上限200；Relation目录与扩展联合查询后分页，使用同条件count。

## §10 错误处理与边界

### 10.1 错误场景

| 场景 | 错误信息 |
| --- | --- |
| 评分越界 | `评分必须在 0-100 之间` |
| 月份格式错 | `month 必须是 YYYY-MM` |
| 日期格式错 | `evaluatedAt 必须是 YYYY-MM-DD` |
| 产能负数 | `capacity 必须是非负数字` |
| 工厂不存在 | `工厂档案不存在` |
| 拉黑后新建 PO | `工厂已拉黑，禁止新建采购单`（服务端 assertNotBlacklisted） |
| 拉黑原因空 | 前端 `拉黑原因必填` |
| Relation 非 Supplier | `Relation 不是 Supplier 组织` |

### 10.2 边界

- `qualityScore / deliveryScore` 缓存分默认 0（无评分时）。
- 产能占用 `occupied` 无 PO 时为 0。
- 认证 `validUntil` 为 null 时长期有效，预警扫描跳过。
- 黑名单 `blacklistedAt` 为 null 时正常。

## §13 已知限制与技术债务

1. 评分均值算法简单（算术平均），无时间衰减或加权（近期评分权重更高）。建议引入 EWMA 指数加权移动平均。
2. 产能占用聚合按 PO 数量累加，未区分面料（M）与成衣（PC）单位混用场景。建议按 unit 分轨聚合。
3. 黑名单仅本地标记，未同步上游 ERP 或下游客户。
4. 认证预警仅 30 天阈值，未支持多级预警（60/90 天提前通知）。
5. 银行信息明文存储（无加密），建议敏感字段加密。
6. 工厂评分缓存重算仅追加评分时触发，删除评分（软删）后未自动重算（需手动触发或定期重算任务）。

## §14 演进路线

1. **评分时间衰减**：引入 EWMA 算法，近期评分权重更高。
2. **产能分轨聚合**：按 unit（PC/M）分轨占用聚合。
3. **黑名单同步**：与上游 ERP / 下游客户同步拉黑状态。
4. **多级预警**：60/90/30 天多级认证预警。
5. **银行信息加密**：敏感字段 AES 加密存储。
6. **评分删除重算**：软删评分后自动重算缓存分。
7. **AI 工厂推荐**：基于订单需求（品类/产能/价位）推荐合适工厂。
8. **供应商门户**：开放给供应商自助更新产能/认证。
