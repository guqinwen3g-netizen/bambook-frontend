# 工厂延迟链路影响计算 (Factory Delay Impact)

> **REQ2-10** · 痛度 28 · 来源 X-02 L0 · 批次三 B 级
> **甲方场景**（黑天鹅异常分支）：染厂告知交货延迟 30 天——须立即知道影响哪些客户/订单/交期，拿到沟通建议，并让工厂交期分下调留痕。当前 L0：延迟→受影响客户清单/重新排程建议均无，仅有交期变更审批。
> **验收标准**：X-02——延迟 30 天登记后 3 击内拿到受影响清单（客户/订单/交期/建议）。

## §2 关键设计决策（DR-052）

### DR-052-① 延迟登记是事实记录，改期走既有审批（两域分离）

- FactoryDelayRecord 只登记"工厂告知延迟"的**事实**（谁/几天/为什么）+ 登记时快照受影响聚合——延迟本身不直接改任何订单
- 订单交期变更仍走既有 OrderChangeRequest 审批链（交期变更 100% 审批 + Shipping/Delivered 锁死 DR-013）——不重复造改期轮子，审批留痕链不断
- 价值分离：延迟登记回答"影响谁多严重"；变更审批回答"允不允许改"——业务员拿着影响清单去发起变更审批/联系客户

### DR-052-② 影响计算以"缓冲侵蚀"为轴（非简单列表）

- 每受影响订单（该工厂 millRelationId 下活跃订单）计算：`新生产完成日 = productionPlanDeadline + delayDays` vs `dueDate`（客户交期）
  - **critical**：突破交期且剩余缓冲 ≤7 天 → 建议立即通知客户（协商改期/分批出货/关键单空运补货）
  - **warning**：突破交期但剩余缓冲 >7 天 → 建议评估加急工序/部分提前出货，暂不惊动客户
  - **info**：未突破交期（生产缓冲足以消化）→ 内部调整排程即可
- productionPlanDeadline 缺失时回退 dueDate（保守口径：直接判突破）并在结果中标注 `planDateMissing`
- 受影响范围：millRelationId 命中且状态非终态（Cancelled/Delivered/Completed）的订单，含 poNumber/customer/product/quantity/dueDate/productionPlanDeadline/新完成日/剩余缓冲天数

### DR-052-③ 登记即联动工厂交期分下调（X-02 完整期望闭环）

- 登记成功后 `recordAutoEvaluation(kind='delivery', sourceType='factory_delay', sourceId=登记ID)` 幂等追加：延迟天数 → 扣分映射（1-7 天=60 分、8-15 天=40 分、16-30 天=25 分、>30 天=10 分）
- 与 REQ2-01 疵点入分为同一 recordAutoEvaluation 机制（幂等去重，重复事件静默跳过）；无 FactoryProfile 的 Relation 静默跳过不阻断
- 交期分联动为事务外 best-effort（与 REQ2-01 同边界）

## §3 模块边界

| 包含 | 不包含 |
|------|--------|
| 延迟登记（工厂/天数/原因分类/备注）+ 记录留痕 | 订单交期自动顺延（走既有变更审批 DR-052-①） |
| 受影响订单聚合（三级分级 + 逐级沟通建议文案） | 自动重新排程（建议文案给方向，重排列增强） |
| 工厂交期分自动下调（幂等） | 工厂产能日历调整（IND-10 域） |
| 登记前预检（preview：不落库先看影响） | 延迟预警待办化（增强） |

## §4 数据模型

```prisma
/// 设计真源：工厂延迟链路影响计算.md §4（REQ2-10，X-02 L0 → L3）
/// 业务语义：工厂延迟事实登记 + 受影响聚合快照（客户还款/改期后历史不失真同哲学）。
model FactoryDelayRecord {
  id                 String   @id // 格式：FDR__${shortId}
  recordNumber       String   @unique // 业务号：FDR-YYYYMMDD-001
  supplierRelationId String? // 工厂 Relation（快照 FK）
  supplierName       String // 冗余快照
  delayDays          Int // 延迟天数（正整数）
  reason             String? // capacity | material | quality_rework | weather | other
  reasonNote         String? // 自由备注
  affectedOrderIds   String[] @default([]) // 登记时受影响订单快照
  impactSummary      Json? // 分级快照 {critical, warning, info, criticalOrderIds}
  registeredBy       String? // 登记人
  createdAt          BigInt
  deletedAt          BigInt?

  @@index([supplierRelationId])
  @@index([createdAt])
}
```

## §5 API（挂 /api/v1/suppliers，与工厂域同路由）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/delays/preview?supplierRelationId=&delayDays=` | 登记前预检（不落库）：受影响订单聚合 + 分级 + 建议 |
| POST | `/delays` | 登记延迟 {supplierRelationId, supplierName?, delayDays, reason?, reasonNote?} → 落库 + 受影响聚合快照 + 交期分联动 |
| GET | `/delays?supplierRelationId=&limit=` | 延迟记录列表（倒序，含影响快照） |
| GET | `/delays/:id` | 详情（含登记时受影响快照） |

守卫：读模块守卫；写 requireWrite + suppliers 域既有角色链（与 evaluations 写同款）。

## §6 前端（SuppliersManager 工厂详情「延迟影响」区块）

- **登记入口**：BottomSheet（工厂选择回填/延迟天数/原因分类 chips/备注）→ 提交前实时预检面板（受影响订单三级分组 + 建议文案）
- **影响面板**：critical（红）/warning（黄）/info（灰）分组订单行（PO/客户/产品/数量/原交期/新完成日/剩余缓冲）+ 逐级沟通建议
- **记录列表**：该工厂历史延迟（天数/原因/影响计数/登记人/日期）
- 3 击锚点：供应商管理 → 工厂详情 → 延迟影响区块（登记后清单即时呈现）

## §7 验收标准

| 锚点 | 验证方式 |
|------|---------|
| 延迟 30 天登记后 3 击内拿到受影响清单 | API 验收：登记 → 返回体含受影响订单聚合（客户/订单/交期/分级/建议）；前端 3 击路径走通 |
| 影响计算正确 | 缓冲侵蚀三档判定（critical/warning/info 边界：7 天缓冲阈值、planDate 缺失回退） |
| 工厂交期分下调 | 登记 → FactoryEvaluation(delivery) 追加对应扣分（幂等：重复登记不重复扣） |
