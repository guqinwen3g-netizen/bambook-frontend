## §2 业务定位与目标

### 2.1 业务定位

供应商自动评分是 Suppliers 模块的核心智能能力。通过 `FactoryEvaluation` append-only 明细表作为评分真源，配合纯函数口径（交期/验货）+ 事务内均值重算缓存分，实现：

- **评分客观化**：基于业务事件自动追加，减少主观偏差。
- **评分可追溯**：每条评分含 sourceType / sourceId / evaluatedAt / note，可反查来源单据。
- **评分实时化**：缓存分由追加事件同事务重算，列表查询无需重算。
- **评分可手动**：支持手动追加评分（sourceType='manual'），补充自动评分盲区。

### 2.2 核心目标

1. **两类评分维度**：质量分（inspection）+ 交期分（delivery），覆盖供应商核心 KPI。
2. **纯函数口径集中**：交期/验货评分函数独立，供业务事件挂钩复用。
3. **事务内重算**：评分追加同事务重算缓存分，fail closed，禁止客户端直改缓存。
4. **幂等自动评分**：同源事件不重复追加，避免评分虚高。
5. **多来源支持**：inspectionReport / shipment / purchaseOrder / manual 四类来源。
6. **0-100 评分标尺**：色阶可视化（≥80 优 / ≥60 中 / <60 差）。

## §3 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| 评分类型 `kind` | `inspection`（验货质量）/ `delivery`（交期达成） |
| 评分 `score` | 0-100 数值，越高越优 |
| 缓存分 `qualityScore / deliveryScore` | FactoryProfile 上的缓存字段，事务内重算 |
| 评分明细 `FactoryEvaluation` | append-only 真源，每次评分一行记录 |
| 来源类型 `sourceType` | `inspectionReport / shipment / purchaseOrder / manual` |
| 来源 ID `sourceId` | 关联单据 ID（如验货报告 ID / 采购单 ID） |
| 评定日期 `evaluatedAt` | YYYY-MM-DD |
| 操作人 `actorId` | 评分追加人（自动评分为 system） |
| 幂等键 | `(factoryId, kind, sourceType, sourceId)` 唯一组合，防重复追加 |

| 验货结论 `result` | `pass / conditional / fail` |
| 致命疵点 `criticalDefects` | 验货发现的致命疵点数 |

## §4 评分公式

### 4.1 交期评分公式 `deliveryScoreForDaysLate`

**位置**：factoryService.ts 92–99 行

**签名**：`deliveryScoreForDaysLate(daysLate: number | null): number`

**口径**：

```
if (daysLate === null) return 100;   // 未约定交期，不惩罚
if (daysLate <= 0)    return 100;    // 提前或按时，满分
if (daysLate <= 7)    return 80;     // 延期 1-7 天，80 分
if (daysLate <= 14)   return 60;     // 延期 8-14 天，60 分
if (daysLate <= 30)   return 40;     // 延期 15-30 天，40 分
return 20;                            // 延期 30 天以上，20 分
```

**可视化**：

```
score
100 ┤■■■■■■■■■■■■■■■■■■■  daysLate ≤ 0（按时/提前）
    │
 80 ┤                    ■■■■■■■  1 ≤ daysLate ≤ 7
    │
 60 ┤                                        ■■■■■■■  8 ≤ daysLate ≤ 14
    │
 40 ┤                                                              ■■■■■■■  15 ≤ daysLate ≤ 30
    │
 20 ┤                                                                                    ■■■■■■  > 30
    └────────────────────────────────────────────────────────────────────────────────────────────► daysLate
       ≤0      7         14          30        +
```

**边界处理**：
- `daysLate === null`：未约定交期（`expectedDeliveryDate` 为空），不惩罚，返回 100。
- `daysLate < 0`：提前交货，按时满分 100。
- `daysLate = 0`：当天交货，满分 100。

### 4.2 验货评分公式 `inspectionScoreForResult`

**位置**：factoryService.ts 102–106 行

**签名**：`inspectionScoreForResult(result: string, criticalDefects: number): number`

**口径**：

```
if (criticalDefects > 0 || result === 'fail')        return 20;   // 致命疵点或 fail，一票否决，20 分
if (result === 'conditional')                        return 70;   // 有条件通过，70 分
return 95;                                                          // pass，95 分
```

**可视化**：

```
score
 95 ┤■■■■■  result = 'pass'，无致命疵点
    │
 70 ┤        ■■■■■  result = 'conditional'（有条件通过）
    │
 20 ┤                ■■■■■  result = 'fail' 或 criticalDefects > 0
    └────────────────────────────────────────────────────►
       pass          conditional     fail / criticalDefects>0
```

**边界处理**：
- `criticalDefects > 0`：致命疵点一票否决，无论 result 如何均返回 20。
- `result = 'fail'`：直接返回 20。
- `result = 'conditional'`：返回 70（有条件通过，需整改）。
- `result = 'pass'`：返回 95（非满分 100，保留 5 分改进空间）。
- 其他未知 result：默认走 `return 95`（宽容处理）。

### 4.3 缓存分重算公式

**位置**：factoryService.ts 323–332 行

**口径**：

```
inspectionRows = FactoryEvaluation.findMany({ factoryId, kind: 'inspection', deletedAt: null })
deliveryRows   = FactoryEvaluation.findMany({ factoryId, kind: 'delivery',   deletedAt: null })

avg(rows) = rows.length ? rows.reduce((s, r) => s + r.score, 0) / rows.length : 0

FactoryProfile.update({
  qualityScore:  avg(inspectionRows),   // 算术平均
  deliveryScore:  avg(deliveryRows),    // 算术平均
  updatedAt: now
})
```

**特点**：
- **算术平均**：所有评分等权重，无时间衰减。
- **空集返回 0**：无评分时缓存分为 0（danger 色阶）。
- **同事务**：评分追加 + 重算在同一 `$transaction` 内，fail closed。

### 4.4 评分标尺与色阶

| 分数区间 | 语义 | 色阶 | 业务含义 |
| --- | --- | --- | --- |
| 80-100 | 优秀 | success（绿） | 优质供应商，优先合作 |
| 60-79 | 中等 | warning（黄） | 合格供应商，关注改进点 |
| 0-59 | 较差 | danger（红） | 风险供应商，谨慎合作或拉黑 |

**前端实现**：`scoreSemantic(score)` 函数（SuppliersManager.tsx 168–172 行）。

## §5 关键流程

### 5.1 自动评分追加流程（验货报告触发）

```
验货报告提交（inspectionReport 模块）
  │
  ▼
业务事件 InspectionReportSubmitted 触发
  │
  ▼
recordAutoEvaluation({
  relationId: 工厂RelationID,
  kind: 'inspection',
  score: inspectionScoreForResult(report.result, report.criticalDefects),
  sourceType: 'inspectionReport',
  sourceId: report.id,
  evaluatedAt: report.evaluatedAt,
  note: report.summary,
  actorId: 'system'
})
  │
  ▼
1. getProfileByRelation(relationId)
   - 无档案 → return { recorded: false }（静默跳过，不阻断主流程）
2. 查重：findFirst({ factoryId, kind, sourceType, sourceId, deletedAt: null })
   - 已存在 → return { recorded: false, evaluationId: dup.id }（幂等跳过）
3. addEvaluation(profile.id, { kind, score, sourceType, sourceId, evaluatedAt, note })
   - 同事务重算缓存分
4. return { recorded: true, evaluationId: evaluation.id }
```

### 5.2 自动评分追加流程（采购单收齐触发）

```
采购单全部收齐（PurchaseOrder status → Received）
  │
  ▼
业务事件 PurchaseOrderReceived 触发
  │
  ▼
计算交期偏差：
  daysLate = (actualDeliveryDate - expectedDeliveryDate) / 86400000  // 天
  - expectedDeliveryDate 为空 → daysLate = null（不惩罚）
  - actualDeliveryDate 为空 → daysLate = null
  │
  ▼
recordAutoEvaluation({
  relationId: po.supplierRelationId,
  kind: 'delivery',
  score: deliveryScoreForDaysLate(daysLate),
  sourceType: 'purchaseOrder',
  sourceId: po.id,
  evaluatedAt: po.actualDeliveryDate || today,
  note: daysLate === null ? '未约定交期' :
        daysLate <= 0 ? `提前 ${-daysLate} 天` :
        `延期 ${daysLate} 天`,
  actorId: 'system'
})
```

### 5.3 手动评分追加流程

```
用户在 EvaluationsTab 点击「手动评分」
  │
  ▼
EvaluationForm 弹窗：
  - 评分类型（验货质量 / 交期达成）
  - 分数 0-100（前端校验）
  - 评定日期（默认今天）
  - 备注
  │
  ▼
提交 → POST /api/factories/:id/evaluations
  body: { kind, score, sourceType: 'manual', evaluatedAt, note }
  │
  ▼
addEvaluation(factoryId, input)
  - 校验 score 0-100
  - 校验 evaluatedAt YYYY-MM-DD
  - $transaction 写入 + 重算缓存分
```

### 5.4 缓存分重算时序

```
T0: FactoryProfile { qualityScore: 80, deliveryScore: 90 }  // 现有缓存
    FactoryEvaluation[] = [
      { kind: 'inspection', score: 80 },  // 已有
      { kind: 'delivery', score: 90 }     // 已有
    ]

T1: 用户手动追加评分 { kind: 'inspection', score: 60 }
    │
    ▼
$transaction {
  T1.1: FactoryEvaluation.create({ ..., kind: 'inspection', score: 60 })
  T1.2: 查 inspectionRows = [{ score: 80 }, { score: 60 }]
  T1.3: 查 deliveryRows   = [{ score: 90 }]
  T1.4: avg(inspectionRows) = (80 + 60) / 2 = 70
        avg(deliveryRows)   = 90 / 1 = 90
  T1.5: FactoryProfile.update({ qualityScore: 70, deliveryScore: 90 })
}
    │
    ▼
T2: FactoryProfile { qualityScore: 70, deliveryScore: 90 }  // 缓存更新
    FactoryEvaluation[] = [
      { kind: 'inspection', score: 80 },
      { kind: 'inspection', score: 60 },  // 新增
      { kind: 'delivery', score: 90 }
    ]
```

## §6 API 与服务契约

### 6.1 评分端点

| Method | Path | 用途 |
| --- | --- | --- |
| POST | `/api/factories/:id/evaluations` | 追加评分（手动 / 自动） |
| GET | `/api/factories/:id/evaluations` | 评分列表（支持 kind 筛选） |
| GET | `/api/factories/:id/evaluations?kind=inspection` | 仅验货评分 |
| GET | `/api/factories/:id/evaluations?kind=delivery` | 仅交期评分 |

### 6.2 服务层契约

- `addEvaluation(factoryId, input, actorId)`：
  - 校验 factoryId 存在且未软删。
  - `assertScore(score)`：0-100。
  - 校验 `evaluatedAt` YYYY-MM-DD 格式。
  - `$transaction` 写入 FactoryEvaluation + 重算缓存分。
  - 事务后发布 `FactoryEvaluationAdded` 事件（fire-and-forget）。

- `recordAutoEvaluation(params)`：
  - 幂等入口，同 (factoryId, kind, sourceType, sourceId) 只记一次。
  - 无工厂档案静默跳过（不阻断主流程）。
  - 返回 `{ recorded: boolean, evaluationId?: string }`。

- `listEvaluations(factoryId, kind?)`：
  - 按 createdAt desc 排序，take 200。

### 6.3 业务事件

**发布**：
- `FactoryEvaluationAdded`：评分追加后发布，payload 含 factoryId / evaluationId / kind / score / sourceType / sourceId。

**订阅**（外部模块触发自动评分）：
- `InspectionReportSubmitted` → `recordAutoEvaluation(kind='inspection')`
- `PurchaseOrderReceived` → `recordAutoEvaluation(kind='delivery')`
- `ShipmentDelivered` → `recordAutoEvaluation(kind='delivery')`（如启用货运模块）

## §8 权限与审计

### 8.1 权限

- 手动评分追加：登录用户均可。

- 评分缓存字段 `qualityScore / deliveryScore`：禁止客户端直改，仅服务端事务内重算。

- 评分追加通过 `writeRouteAuditLog` 同事务写入 `AuditLog`。
- `targetType = 'FactoryEvaluation'`，`targetId = evaluationId`。
- 含 `actorId`（手动评分）/ 'system'（自动评分）。
- before/after 快照（before 为空，after 为新评分）。
- 缓存分重算不在 AuditLog 中单独记录（在评分追加的 after 中体现）。

## §9 性能与扩展性

### 9.1 索引

- `FactoryEvaluation`：`factoryId + kind`（评分查询）、`sourceType + sourceId`（幂等查重）。

### 9.2 扩展性

- 评分类型 `kind` 为 String，可扩展新类型（如 `responsiveness` 响应速度 / `communication` 沟通评分）不改表。
- 来源类型 `sourceType` 为 String，可扩展新来源。
- 纯函数 `deliveryScoreForDaysLate / inspectionScoreForResult` 集中口径，便于未来调整（如改 EWMA 加权）。

### 9.3 已知性能优化点

- 缓存分重算在同事务内，避免列表查询时重算。
- 评分列表 `take: 200` 限制。
- 幂等查重走 `sourceType + sourceId` 索引。

## §10 错误处理与边界

### 10.1 错误场景

| 场景 | 错误信息 |
| --- | --- |
| score 越界 | `评分必须在 0-100 之间` |
| evaluatedAt 格式错 | `evaluatedAt 必须是 YYYY-MM-DD` |
| factoryId 不存在 | `工厂档案不存在` |
| factoryId 已软删 | `工厂档案不存在` |
| 非法 kind | （服务端宽容处理，原样写入） |

### 10.2 边界

- `score = 0`：合法（最低分）。
- `score = 100`：合法（满分）。
- `score = -1 / 101 / NaN`：拒绝。
- `daysLate = null`：未约定交期，不惩罚（返回 100）。
- `daysLate = 0`：当天交货，满分。
- `criticalDefects > 0`：一票否决，无论 result 如何均 20 分。
- 评分集合为空时：缓存分默认 0（danger 色阶）。
- 无工厂档案的 Relation：自动评分静默跳过，不阻断主流程。

## §12 部署与运维

- 与主服务同进程，无独立部署。
- 评分缓存重算在 `addEvaluation` 事务内完成，无缓存层延迟。
- 自动评分事件订阅在业务事件总线（`businessEventBus`），事件丢失会导致评分缺失（建议定期对账任务）。

## §13 已知限制与技术债务

1. **算术平均无时间衰减**：近期评分与历史评分等权重，无法反映供应商近期表现。建议引入 EWMA 指数加权移动平均或时间窗加权。
2. **评分删除不重算**：评分软删后缓存分未自动重算，需手动触发或定期重算任务。
3. **评分来源单一**：仅支持验货报告 + 采购单 + 手动三类，未支持客户反馈、第三方验厂等来源。
4. **验货评分偏简单**：仅基于 result + criticalDefects，未考虑一般疵点数、AQL 等级、验货批次大小。
5. **交期评分未考虑提前惩罚**：提前交货也满分，可能导致库存积压（建议提前过多降分）。
6. **无评分历史趋势**：缓存分仅当前值，无法查看历史趋势。建议定期快照。
7. **无评分权重配置**：质量分与交期分独立，未支持综合评分（如质量 60% + 交期 40%）。

## §14 演进路线

1. **EWMA 时间衰减**：引入指数加权移动平均，近期评分权重更高。
   - 公式：`newScore = α * newEvaluation + (1-α) * oldScore`，α 建议 0.3。
2. **评分删除重算**：评分软删后自动重算缓存分。
3. **多来源评分**：支持客户反馈、第三方验厂、ISO 审核等来源。
4. **验货评分细化**：考虑一般疵点数、AQL 等级、批次大小。
5. **提前交货惩罚**：提前超过 7 天降分（库存积压风险）。
6. **评分历史快照**：定期（每月）快照缓存分，支持趋势图。
7. **综合评分公式**：支持配置权重（如质量 60% + 交期 40%），生成综合分用于排名。
8. **评分预警**：缓存分低于阈值（如 60）自动发布 `FactoryScoreLowAlarm` 事件，触发拉黑建议。

### 16.1 评分公式速查表

#### 交期评分 `deliveryScoreForDaysLate(daysLate)`

| daysLate | score | 业务含义 |
| --- | --- | --- |
| `null` | 100 | 未约定交期，不惩罚 |
| `≤ 0` | 100 | 提前或按时，满分 |
| `1-7` | 80 | 延期 1 周内 |
| `8-14` | 60 | 延期 1-2 周 |
| `15-30` | 40 | 延期半月-1 月 |
| `> 30` | 20 | 延期 1 月以上 |

#### 验货评分 `inspectionScoreForResult(result, criticalDefects)`

| result | criticalDefects | score | 业务含义 |
| --- | --- | --- | --- |
| `pass` | 0 | 95 | 通过 |
| `conditional` | 0 | 70 | 有条件通过 |
| `pass / conditional` | > 0 | 20 | 致命疵点一票否决 |
| `fail` | 任意 | 20 | 不合格 |
| 未知 | 0 | 95 | 宽容处理 |
