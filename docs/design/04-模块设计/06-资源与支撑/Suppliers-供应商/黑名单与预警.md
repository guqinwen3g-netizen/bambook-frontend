## §2 业务定位与目标

### 2.1 业务定位

黑名单与预警是供应商风险管控的双核心机制：

- **黑名单**：对不合格或风险供应商拉黑，拉黑后禁止新建采购单，服务端强制校验，防止误操作。
- **认证到期预警**：扫描工厂认证（BSCI/SEDEX/WRAP 等）有效期，30 天内到期时顶部横幅提醒，确保合规性。

### 2.2 核心目标

1. **拉黑流程化**：拉黑需填写原因，记录拉黑人 + 时间，可解除。
2. **拉黑强制管控**：拉黑后服务端 `assertNotBlacklisted` 拦截 PO 创建。
3. **黑名单可筛选**：列表支持 active / blacklisted / all 三态筛选。
4. **认证有效期管理**：每条认证含 `validUntil`，支持长期有效（null）。
5. **30 天预警阈值**：30 天内到期认证顶部横幅提醒。
6. **认证色阶**：剩余天数色阶（已过期 danger / 30 天内 warning / 长期 neutral / 其他 success）。
7. **权限分级**：拉黑/解除需 owner/admin/manager 权限。

## §3 核心概念与术语

| 剩余天数 `daysLeft` | `validUntil - today`（天） |
| 认证色阶 `certSemantic` | null neutral / <0 danger / ≤30 warning / 其他 success |

## §5 关键流程

### 5.1 拉黑流程

```
用户在详情头部点击「拉黑」
  │
  ▼
BlacklistForm 弹窗：
  - 警示 alert：拉黑后该工厂将被禁止新建采购单，直至解除拉黑。此操作需要管理权限。
  - 拉黑原因（textarea，必填）
  - 占位符：如：连续两次验货不合格 / 严重延期
  │
  ▼
提交（前端校验 reason 非空）
  │
  ▼
POST /api/factories/:id/blacklist
  body: { reason }
  │
  ▼
setBlacklist(factoryId, reason, actorId):
  $transaction {
    1. 校验 actorId 权限（owner/admin/manager）
    2. FactoryProfile.update({
         blacklistedAt: now,
         blacklistReason: reason,
         blacklistedById: actorId
       })
    3. AuditLog
  }
  │
  ▼
发布 FactoryBlacklisted 事件
  │
  ▼
采购单模块订阅事件 → 后续新建 PO 调用 assertNotBlacklisted 拦截
  │
  ▼
前端 refreshAll() 刷新列表 + 详情
  → 列表卡片显示「已拉黑」danger 徽章
  → 详情头部显示「已拉黑」徽章 + alert（拉黑原因：xxx）
  → 操作行变为「解除拉黑」按钮
```

### 5.2 解除拉黑流程

```
用户在详情头部点击「解除拉黑」
  │
  ▼
confirm 弹窗：确认解除「工厂名」的拉黑？
  │
  ▼
POST /api/factories/:id/unblacklist
  │
  ▼
clearBlacklist(factoryId, actorId):
  $transaction {
    1. 校验 actorId 权限（owner/admin/manager）
    2. FactoryProfile.update({
         blacklistedAt: null,
         blacklistReason: null,
         blacklistedById: null
       })
    3. AuditLog
  }
  │
  ▼
发布 FactoryUnblacklisted 事件
  │
  ▼
前端 refreshAll() 刷新列表 + 详情
  → 列表卡片移除「已拉黑」徽章
  → 详情头部移除徽章 + alert
  → 操作行变为「拉黑」按钮
```

### 5.3 拉黑后 PO 创建拦截流程

```
采购单创建（POST /api/purchase-orders）
  │
  ▼
purchaseOrderService.createOrder({ supplierRelationId, ... })
  │
  ▼
1. 通过 supplierRelationId 查 FactoryProfile
2. assertNotBlacklisted(factoryId)
   - if profile.blacklistedAt != null:
       throw new Error('工厂已拉黑，禁止新建采购单')
3. 继续创建 PO
```

### 5.4 认证到期预警扫描流程

```
SuppliersManager 加载时（useEffect）
  │
  ▼
apiService.listExpiringCertifications(30)
  │
  ▼
GET /api/factories/certifications/expiring?days=30
  │
  ▼
listExpiringCertifications(days):
  today = new Date()
  from = today.toISOString().slice(0, 10)
  to = (today + days).toISOString().slice(0, 10)

  return db.factoryCertification.findMany({
    where: {
      deletedAt: null,
      validUntil: { not: null, gte: from, lte: to }
    },
    include: { factory: { include: { relation: true } } }
  })
  │
  ▼
前端：
  - expiringCerts.length > 0 → 顶部 alert 横幅显示
  - 「{N} 项工厂认证将于 30 天内到期」
  - 点击展开 → 列表显示工厂名 + 认证类型 + 剩余天数徽章
  │
  ▼
每行：
  - 工厂名（cert.factory.relation.name）
  - 认证类型徽章（info）
  - 剩余天数徽章（certSemantic 色阶）：
    - daysLeft < 0 → danger「已过期 {-daysLeft} 天」
    - daysLeft ≤ 30 → warning「剩余 {daysLeft} 天」
```

### 5.5 认证剩余天数计算

```
certDaysLeft(validUntil):
  if not validUntil: return null  // 长期有效
  target = new Date(validUntil + 'T00:00:00').getTime()
  if isNaN(target): return null
  now = new Date()
  today = new Date(now.getFullYear(), now.getMonth(), now.getDate()).getTime()
  return Math.round((target - today) / 86400000)
```

### 5.6 认证色阶策略

```
certSemantic(daysLeft):
  if daysLeft === null: return 'neutral'   // 长期有效，灰色
  if daysLeft < 0:      return 'danger'    // 已过期，红色
  if daysLeft ≤ 30:     return 'warning'   // 30 天内，黄色
  return 'success'                            // 其他（>30 天），绿色
```

## §6 API 与服务契约

### 6.1 黑名单端点

| Method | Path | 用途 |
| --- | --- | --- |
| POST | `/api/factories/:id/blacklist` | 拉黑（body: { reason }） |
| POST | `/api/factories/:id/unblacklist` | 解除拉黑 |

### 6.2 认证预警端点

| Method | Path | 用途 |
| --- | --- | --- |
| GET | `/api/factories/certifications/expiring?days=30` | 到期预警列表 |

### 6.3 服务层契约（factoryService.ts）

- `setBlacklist(factoryId, reason, actorId)`：
  - 校验 actorId 权限（owner/admin/manager）。
  - `$transaction` 更新 blacklistedAt / blacklistReason / blacklistedById + AuditLog。
  - 发布 `FactoryBlacklisted` 事件。

- `clearBlacklist(factoryId, actorId)`：
  - 校验 actorId 权限。
  - `$transaction` 清空黑名单字段 + AuditLog。
  - 发布 `FactoryUnblacklisted` 事件。

- `assertNotBlacklisted(factoryId)`：
  - 查 FactoryProfile。
  - if `blacklistedAt != null` → throw `工厂已拉黑，禁止新建采购单`。
  - 供 PurchaseOrderService 调用。

- `listExpiringCertifications(days)`：
  - 查 FactoryCertification（`validUntil` 在 [today, today+days] 区间）。
  - include factory + relation。
  - 返回 FactoryCertification[]。

### 6.4 业务事件

**发布**：
- `FactoryBlacklisted`：拉黑后发布（采购单模块订阅，拦截后续 PO）。
- `FactoryUnblacklisted`：解除后发布。
- `FactoryCertificationExpiring`：定时扫描发布（30 天内到期，可挂定时任务）。

**订阅**：
- 采购单创建 → 调用 `assertNotBlacklisted` 拦截。

### 6.5 权限矩阵

| 操作 | owner | admin | manager | 普通用户 |
| --- | --- | --- | --- | --- |
| 查看黑名单状态 | ✅ | ✅ | ✅ | ✅ |
| 拉黑 | ✅ | ✅ | ✅ | ❌ |
| 解除拉黑 | ✅ | ✅ | ✅ | ❌ |
| 查看认证 | ✅ | ✅ | ✅ | ✅ |

## §10 错误处理与边界

### 10.1 错误场景

| 场景 | 错误信息 |
| --- | --- |
| 拉黑原因空 | 前端 `拉黑原因必填` |
| 权限不足拉黑 | `无权限执行拉黑操作` |
| 权限不足解除 | `无权限执行解除拉黑操作` |
| 拉黑后新建 PO | `工厂已拉黑，禁止新建采购单`（服务端 assertNotBlacklisted） |
| 工厂不存在 | `工厂档案不存在` |
| 认证 validUntil 格式错 | （前端 date input 校验，服务端宽容） |

### 10.2 边界

- `blacklistedAt = null`：未拉黑，正常。
- `blacklistedAt != null`：已拉黑，PO 创建被拦截。
- `validUntil = null`：长期有效，预警扫描跳过。
- `validUntil < today`：已过期，预警扫描包含（已过期也算「30 天内」）。
- `validUntil > today + 30`：未到期，预警扫描不包含。
- 重复拉黑：upsert 语义，更新 blacklistedAt + reason + byId。
- 重复解除：upsert 语义，清空字段。

## §13 已知限制与技术债务

1. **预警仅 30 天阈值**：未支持多级预警（60/90 天提前通知）。建议引入多级阈值。
2. **黑名单仅本地标记**：未同步上游 ERP 或下游客户，可能导致跨系统不一致。
3. **拉黑不阻断已有 PO**：仅拦截新建 PO，已存在的 PO（Sent/Confirmed）不受影响。建议拉黑时提示用户处理已有 PO。
4. **认证无附件上传**：`attachmentPath` 字段存在但前端未实现上传（仅文本路径）。
5. **认证预警无定时任务**：仅前端列表加载时触发，无主动通知（邮件/IM）。
6. **拉黑无自动触发**：评分低于阈值时不会自动拉黑，需手动操作。
7. **黑名单无期限**：拉黑无自动解除时间，需手动解除。

## §14 演进路线

1. **多级预警**：60/90/30 天多级认证预警，提前通知续证。
2. **黑名单同步**：与上游 ERP / 下游客户同步拉黑状态。
3. **已有 PO 处理提示**：拉黑时提示用户处理已有 PO（取消或转移）。
4. **认证附件上传**：前端实现文件上传，存储到对象存储。
5. **预警定时任务 + 通知**：每日扫描 + 邮件/IM 通知责任人。
6. **评分自动拉黑**：评分低于阈值（如 40）自动发布拉黑建议，需管理员确认。
7. **黑名单期限**：支持设置拉黑期限，到期自动解除（需续审）。
8. **黑名单原因标准化**：引入原因字典（如「质量不合格」「严重延期」「合规问题」），便于统计。

### 16.2 拉黑流程状态机

```
正常 (blacklistedAt=null)
    │
    │ setBlacklist(reason, actorId)
    │   - 校验权限（owner/admin/manager）
    │   - 原因必填
    ▼
已拉黑 (blacklistedAt=now, blacklistReason, blacklistedById)
    │
    │ 期间：assertNotBlacklisted 拦截新建 PO
    │
    │ clearBlacklist(actorId)
    │   - 校验权限
    ▼
正常 (blacklistedAt=null, blacklistReason=null, blacklistedById=null)
```
