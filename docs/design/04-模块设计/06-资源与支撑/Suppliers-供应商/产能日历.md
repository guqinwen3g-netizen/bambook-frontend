## §2 业务定位与目标

### 2.1 业务定位

产能日历是供应商管理的关键决策视图。每个工厂可按月设置计划产能（`FactoryCapacity`），系统实时聚合该供应商在手采购单（已发送/已确认/部分收货）按交期落月的数量总和作为「占用量」，从而直观呈现工厂每月忙闲状态，支撑新订单分配决策。

### 2.2 核心目标

1. **月度产能规划**：`FactoryCapacity` 按 `YYYY-MM` 维度记录计划产能。
2. **占用实时聚合**：`occupied` 不落地，由在手 PO `expectedDeliveryDate` 落月实时聚合，口径变更无需回填。
3. **忙闲可视化**：占用比进度条 + 色阶（>100% danger / >80% warning / 其他 success）。
4. **一厂一月一行**：`@@unique([factoryId, month])` 保证数据唯一。
5. **跨月份对比**：列表按月份升序，便于查看未来数月产能规划。
6. **单位一致性**：`capacityUnit`（PC/M）与 PO 行数量单位需匹配（当前未强制校验）。

### 2.3 设计原则

- **占用量不落地**：避免数据冗余与口径变更回填成本，每次查询实时聚合。
- **产能可编辑**：用户可 upsert 任意月份的计划产能。
- **PO 占用只读**：占用量由 PO 自动计算，用户不可手动调整。

## §3 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| 月计划产能 `capacity` | 工厂该月计划产能数值（Decimal 18,4） |
| 月份 `month` | YYYY-MM 格式字符串 |
| 单位 `unit` | PC（件）/ M（米） |
| 占用量 `occupied` | 在手 PO 按交期落月累加数量（不落地，实时算） |
| 占用比 `ratio` | `occupied / capacity`，>1 表示超载 |
| 在手采购单 `OCCUPYING_PO_STATUSES` | `['Sent', 'Confirmed', 'PartiallyReceived']` 三态 |
| 交期落月 | `PurchaseOrder.expectedDeliveryDate` 切片前 7 位（YYYY-MM） |
| 备注 `note` | 月份备注（如「春节月减半」） |

### 4.2 占用量计算逻辑

**位置**：factoryService.ts 504–523 行

**伪代码**：

```
async function aggregateOccupied(relationId, months[]):
    occupied = {}  // { month: quantity }
    if not months.length: return occupied

    pos = db.purchaseOrder.findMany({
        where: {
            supplierRelationId: relationId,
            deletedAt: null,
            status: { in: ['Sent', 'Confirmed', 'PartiallyReceived'] },  // 在手
            expectedDeliveryDate: { not: null },
        },
        select: {
            expectedDeliveryDate: true,
            lines: {
                where: { deletedAt: null },
                select: { quantity: true }
            }
        }
    })

    for po in pos:
        month = po.expectedDeliveryDate.slice(0, 7)  // YYYY-MM
        if month not in months: continue
        qty = sum(line.quantity for line in po.lines)
        occupied[month] += qty

    return occupied
```

**关键点**：
- 仅统计未删除 PO（`deletedAt: null`）。
- 仅统计三态 PO（Sent/Confirmed/PartiallyReceived），已收齐或已取消不占产能。
- 仅统计未删除 PO 行（`lines.deletedAt: null`）。
- `expectedDeliveryDate` 为空的 PO 不参与占用（无法落月）。
- 累加所有 PO 行 `quantity`（不区分单位，潜在问题见 §13）。

### 4.3 ER 关系图

```
FactoryProfile (1)
    │ 1:N (factoryId, @@unique [factoryId, month])
    ▼
FactoryCapacity (N)  ← 月计划产能（用户编辑）
    │ occupied 字段（不落地，实时聚合）
    │
    ▼
PurchaseOrder (N)  ← supplierRelationId = FactoryProfile.relationId
    │ status in [Sent, Confirmed, PartiallyReceived]
    │ expectedDeliveryDate 落月
    ▼
PurchaseLine (N)  ← quantity 累加 = occupied[month]
```

## §5 关键流程

### 5.1 月产能 upsert 流程

```
用户在 CapacityTab 点击「设置月产能」或「编辑」
  │
  ▼
CapacityForm 弹窗：
  - 月份（YYYY-MM，编辑模式不可改）
  - 计划产能（非负数字）
  - 单位（PC/M，默认 detail.capacityUnit 或 'PC'）
  - 备注
  │
  ▼
提交 → POST /api/factories/:id/capacity
  body: { month, capacity, unit, note }
  │
  ▼
upsertCapacity(factoryId, input, actorId):
  1. 校验 month 格式 /^\d{4}-\d{2}$/
  2. 校验 capacity 非负数字
  3. $transaction {
       db.factoryCapacity.upsert({
         where: { factoryId_month: { factoryId, month } },
         create: { id: generateId('FACC'), factoryId, month, capacity, unit, note, ... },
         update: { capacity, unit, note, updatedAt: now },
       })
       + AuditLog
     }
  4. 发布 FactoryCapacityUpdated 事件
```

### 5.2 产能列表加载流程

```
用户进入工厂详情 → 切到「产能日历」Tab
  │
  ▼
apiService.getFactoryOverview(factoryId) 或 listCapacity(factoryId)
  │
  ▼
listCapacity(factoryId):
  1. getProfileOrThrow(factoryId)
  2. db.factoryCapacity.findMany({
       where: { factoryId, deletedAt: null },
       orderBy: { month: 'asc' }
     })
  3. aggregateOccupied(profile.relationId, rows.map(r => r.month))
  4. return rows.map(r => ({ ...r, occupied: occupied[r.month] || 0 }))
  │
  ▼
前端渲染：
  - 每行：month + 计划产能 + 占用量 + 占用比% + 进度条 + 备注 + 编辑/删除
  - 色阶：>100% danger / >80% warning / 其他 success
```

### 5.3 占用比计算与色阶

```
occupied = row.occupied ?? 0
cap = Number(row.capacity) || 0
ratio = cap > 0 ? occupied / cap : 0

semantic:
  ratio > 1    → 'danger'   // 超载
  ratio > 0.8  → 'warning'  // 接近满载
  else         → 'success'  // 正常

进度条宽度：min(ratio * 100, 100)%
```

### 5.4 删除月产能流程

```
用户点击删除 → confirm 弹窗
  │
  ▼
DELETE /api/factories/:id/capacity/:month
  │
  ▼
deleteCapacity(factoryId, month):
  $transaction {
    db.factoryCapacity.update({
      where: { factoryId_month: { factoryId, month } },
      data: { deletedAt: now }
    })
    + AuditLog
  }
```

### 5.5 PO 状态变更对占用的影响

```
场景：采购单状态变更
  │
  ▼
1. PO 创建（Draft）→ 不计入占用（status 不在 OCCUPYING_PO_STATUSES）
2. PO 发送（Sent）→ 计入占用
3. PO 确认（Confirmed）→ 仍计入占用
4. PO 部分收货（PartiallyReceived）→ 仍计入占用（按完整数量，未减已收）
5. PO 全部收齐（Received）→ 不再计入占用
6. PO 取消（Cancelled）→ 不再计入占用
7. PO 删除（软删）→ 不再计入占用

注意：PartiallyReceived 状态按完整 quantity 计入占用，
     未减去已收数量（receivedQuantity），
     可能高估占用（见 §13 已知限制）。
```

## §6 API 与服务契约

### 6.1 产能端点

| Method | Path | 用途 |
| --- | --- | --- |
| GET | `/api/factories/:id/capacity` | 产能列表（含 occupied） |
| POST | `/api/factories/:id/capacity` | upsert 月产能 |
| DELETE | `/api/factories/:id/capacity/:month` | 删除月产能 |

### 6.2 服务层契约（factoryService.ts）

- `upsertCapacity(factoryId, input, actorId)`：
  - 校验 month 格式 `/^\d{4}-\d{2}$/`。
  - 校验 capacity 非负数字。
  - `$transaction` upsert + AuditLog。

- `deleteCapacity(factoryId, month, actorId)`：
  - `$transaction` 软删 + AuditLog。

- `listCapacity(factoryId)`：
  - 返回含 `occupied` 字段的列表。
  - 并行查 FactoryCapacity + aggregateOccupied。

- `aggregateOccupied(relationId, months)`：
  - 纯查询，无写入。
  - 仅统计三态 PO + expectedDeliveryDate 非空 + 未删除。

### 6.3 业务事件

- `FactoryCapacityUpdated`：月产能 upsert 后发布。
- `FactoryCapacityDeleted`：月产能删除后发布。

### 6.4 输入校验

- `month`：必填，格式 `/^\d{4}-\d{2}$/`（前端 `<input type="month">` 原生约束）。
- `capacity`：必填，非负数字（>= 0）。
- `unit`：可选，PC / M。
- `note`：可选。

## §9 性能与扩展性

### 9.1 索引

- `FactoryCapacity`：`factoryId + month`（unique）、`month`。
- `PurchaseOrder`：`supplierRelationId`、`status`、`expectedDeliveryDate`（隐式）。
- `PurchaseLine`：`purchaseOrderId`。

### 9.2 扩展性

- `unit` 为 String，可扩展新单位（如 `KG` / `SET`）。
- `OCCUPYING_PO_STATUSES` 数组可调整（如未来加入 `Production` 状态）。
- 占用聚合算法独立，可扩展为按单位分轨聚合。

### 9.3 已知性能优化点

- `aggregateOccupied` 一次查询所有相关 PO + lines，避免 N+1。
- 仅查询当前工厂已有产能月份的占用量（`months` 过滤），不查全量 PO。
- 产能列表按 `month asc` 排序，前端无需重排。

## §10 错误处理与边界

### 10.1 错误场景

| 场景 | 错误信息 |
| --- | --- |
| month 格式错 | `month 必须是 YYYY-MM` |
| capacity 负数 | `capacity 必须是非负数字` |
| capacity 非数字 | `capacity 必须是非负数字` |
| factoryId 不存在 | `工厂档案不存在` |
| 重复 upsert 同月份 | 不报错（upsert 语义，更新已有） |

### 10.2 边界

- `capacity = 0`：合法（表示该月无产能，所有占用都超载）。
- `occupied = 0`：无 PO 占用（正常）。
- `ratio = 0`：无占用，进度条空。
- `ratio > 1`：超载，进度条满格，徽章显示实际比例（如 117%）。
- PO `expectedDeliveryDate` 为空：不参与占用聚合。
- PO `expectedDeliveryDate` 格式非 YYYY-MM-DD：`slice(0,7)` 可能错误（依赖格式正确）。

## §13 已知限制与技术债务

1. **单位混用**：占用聚合按 `PurchaseLine.quantity` 累加，不区分单位。若产能单位为 PC（件），PO 行单位为 M（米），累加无意义。建议按 unit 分轨聚合。
2. **PartiallyReceived 按完整数量计入**：部分收货的 PO 仍按完整 `quantity` 计入占用，未减去 `receivedQuantity`，可能高估占用。建议改为 `quantity - receivedQuantity`。
3. **无产能模板**：每月需手动设置产能，无「按模板批量生成」功能（如复制上月产能）。
4. **无历史趋势**：仅展示当前产能规划，无历史占用趋势图。
5. **无产能预警**：占用超载时仅前端色阶提示，未发布事件触发预警。
6. **无跨工厂产能视图**：仅单工厂视图，无法横向对比多工厂产能。

## §14 演进路线

1. **单位分轨聚合**：按 unit（PC/M）分轨占用聚合，避免单位混用。
2. **部分收货扣减**：PartiallyReceived 状态按 `quantity - receivedQuantity` 计入占用。
3. **产能模板**：支持「复制上月产能」批量生成。
4. **历史趋势图**：记录每月占用快照，支持趋势可视化。
5. **产能预警事件**：占用超载时发布 `FactoryCapacityOverloaded` 事件，触发排产建议。
6. **跨工厂产能视图**：多工厂产能对比看板，辅助订单分配。
7. **AI 产能推荐**：基于历史接单 + 季节性 + 工厂专长推荐月产能规划。
8. **产能锁定**：支持锁定某月产能（如已满产不可再接单），PO 创建时服务端校验。

### 16.1 产能占用色阶

| 占用比 | 语义 | 色阶 | 业务含义 |

### 16.2 在手 PO 状态机

```
Draft ──发送──► Sent ──确认──► Confirmed ──部分收货──► PartiallyReceived ──全部收齐──► Received
                                                                                         ▲
                                                                                         │
                                                                                      Closed
Draft / Sent / Confirmed / PartiallyReceived 可取消 → Cancelled
任意状态可软删 → Deleted

占用计入：Sent + Confirmed + PartiallyReceived（三态）
```
