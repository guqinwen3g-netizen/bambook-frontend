## §2 架构总览：两端分离

Bambook OS 采用 **桌面客户端（Electron + React）+ Mac Mini 数据中心（Express + Prisma + PostgreSQL）** 的两端分离架构。

┌─────────────────────────────────────────────────────────────┐
│              员工办公电脑（macOS / Windows）                 │
│  ┌───────────────────────────────────────────────────────┐  │

│  │  ┌─────────────────────┐  ┌───────────────────────┐  │  │
│  │  │  React Renderer     │  │  Node.js Main Process │  │  │
│  │  │  (UI 展示/交互)     │  │  (IPC/窗口/生命周期)  │  │  │
│  │  │  - IndexedDB 缓存   │  │  - 本地 STT sherpa-onnx│ │  │
│  │  │  - 离线探活         │  │  - 本地 Express 只读  │  │  │
│  │  └─────────┬───────────┘  └───────────┬───────────┘  │  │

│               │ HTTPS / WSS (内网优先)   │                 │

## §4 桌面端（Electron）架构

### §4.1 主进程（electron/main.ts）✅
- **职责**：创建 BrowserWindow、处理 IPC、管理窗口生命周期、本地 STT 引擎、探活数据中心、启动本地 Express fallback
- **关键模块**：
  - `BrowserWindow` 配置（无边框/毛玻璃背景/最小尺寸约束）
  - `contextBridge` IPC 白名单（仅暴露允许的 API）
  - 本地 Express 只读模式启动（探活失败时自动降级）
  - 单实例锁（避免多开 Electron 进程冲突）

### §4.2 渲染进程（React / App.tsx）✅
- **职责**：View 切换、Sidebar 渲染、主内容区模块化加载、IndexedDB 离线缓存
- **关键模块**：
  - `View` 枚举驱动的路由（非 React Router，避免 URL 依赖）
  - `moduleRegistry` 注册表统一管理模块元数据、权限、渲染入口
  - `CompiledMainModuleSlot className="contents"` 透明包裹器（compiled 双路径）
  - IndexedDB：最近浏览/草稿/未同步操作缓存

### §4.3 离线 Fallback 机制 ⚠️
1. Electron 启动时 `fetch /health` 探活 Mac Mini 数据中心
2. **探活成功**：正常走远程 REST API
3. **探活失败**：启动本地 Express 只读模式（不持业务真源，仅展示本地缓存数据）+ 顶部红条提示「离线模式，所有写入禁用」
4. **探活恢复**：自动切回远程，静默同步本地缓存的草稿

## §5 数据中心（Mac Mini）架构

### §5.1 Express Server（server/src/index.ts）✅
- **启动流程**：
  1. Winston 日志初始化（双 Channel）
  2. Prisma client 连接 PostgreSQL
  3. `prisma migrate deploy` 按迁移账本同步 schema（部署通道已收敛单一真源，禁止 db push --accept-data-loss；账本断链时先 scripts/fix-migration-ledger.ts 补账）
  4. CORS/JSON body/helmet 中间件挂载
  5. JWT 认证中间件（**所有请求必带**：GET 需做敏感字段遮罩，POST/PATCH/DELETE 需做权限检查）
  6. 20+ 业务路由注册（/v1/orders、/v1/products ...）
  7. Agent 路由（/v1/agent/chat、/v1/agent/tools）
  8. OPS Panel 路由（/ops/*，独立认证）
  9. Port 8081 监听 + 健康检查 /health 暴露

### §5.2 Agent Runtime（server/src/agent/orchestrator.ts）⚠️
- **核心职责**：
  1. **身份解析**：用户 → 角色 → 权限 scope 注入上下文
  2. **知识库检索**：向量查询 + RAG 三层过滤（内容特征/结构过滤/LLM 判专业知识）
  3. **模型完成**：LLM 网关（统一入口，支持多模型 fallback）
  4. **工具编排**：MCP 工具桥接 + 权限门控（scope 不足时直接拒绝执行）
  5. **可审计轨迹**：每步 observation 写入日志，operationId 全局追踪

### §5.3 数据库层（PostgreSQL + Prisma）✅
- **核心表组**：
  - 业务表（全量核心业务数据，当前覆盖 14 类+，后续按需扩展）：Relations / Products / Orders / Quotations / Procurement / BOM / Shipments / Invoices / ...
  - 权限表：Role / Permission / UserRole / RolePermission（isSystem 角色不可删）
  - 编号表：BusinessSequence（SEQ_${prefix}_${year} 主键）+ VoidedNumber 作废占坑
  - 日志表：AuditLog（所有写入操作留痕）+ Winston 文件日志（14 天）

## §7 认证与权限链

```
客户端发请求
    │
    ▼
JWT Token（Authorization: Bearer xxx）
    │
    ▼
Express JWT 中间件校验签名与过期
    │
    ▼
permissionGuard.ts 拉取用户 role + scopes
    │
    ▼
路由级 scope 检查（如 orders:write）
    │
    ▼
permissionService.ts 行级过滤（department/self/all）
    │
    ▼
敏感字段 scope 检查（sensitive:cost / commission / salary）
    │
    ▼
业务逻辑执行 + AuditLog 写入
```

**关键规则**：
- 所有请求必须 JWT 认证：GET 需做敏感字段遮罩（cost/commission/salary 后端序列化时删除，前端拿到的就是 `****`，防抓包），POST/PATCH/DELETE 需做 scope + 行级权限检查
- API Key 单独访问返回 401
- SUPER_ADMIN 角色在 hasPermission 中特判，所有 scope = true（**技术兜底权限**，不走查表）；但**业务审批权（报价/订单/付款）不因此自动获得**，仍需通过组织归属审批链（DR-023 超级管理员与业务审批权分离）
- 敏感字段遮罩在后端序列化时就删除，不是 UI 遮罩

## §8 数据流方向（真源唯一性铁律）

```
Mac Mini PostgreSQL  ──────►  唯一真源（Single Source of Truth）
       ▲
       │  REST API (写操作必须走这里)
       │
Electron 渲染进程
       │
       ▼
IndexedDB ── 仅缓存：最近浏览 / 草稿 / 离线快照（非真源）
```

- **写入路径**：Electron → HTTPS POST → Express → Prisma 事务 → PostgreSQL → 返回确认 → Electron 本地缓存刷新
- **读取路径**：Electron → HTTPS GET → Express → Prisma 查询 → PostgreSQL → 返回（若离线则 IndexedDB fallback 只读）
- **绝不允许**：Electron 直接写 IndexedDB 后不同步到服务端标记写入成功

## §9 Caddy 反向代理 + 灰度发布

### §9.1 为什么选 Caddy 不选 Nginx
Mac Mini 上单二进制部署 + 配置简洁 + HTTPS 自动续期，比 Nginx 更适合小团队无运维场景。

### §9.2 灰度发布四步法（原子切换防竞争）
1. **Validate**：验证新版本 tarball 在备用端口（如 8092） `/health` 返回 200
2. **Reload**：`caddy reload --config Caddyfile.new`（Caddy 内部零停机热切换）
3. **Health Check**：wrk 压测 30 秒，Non-2xx 统计 < 0.1%
4. **Atomic Commit**：`mv Caddyfile.new Caddyfile` + 校验旧端口已无流量

### §9.3 回滚策略
- **Scenario A（切换中发现问题）**：直接 `mv Caddyfile Caddyfile.new` 反向切回旧端口
- **Scenario B（切换后几小时出 bug）**：OPS Panel 重新上传旧版本 tarball → 解压到旧端口 → 再次走四步法

## §10 部署流程（push-based）

```
开发机（本地）                         Mac Mini（生产）
    │                                     │
    │  npm run deploy:web                 │
    │  ├─ electron-vite build             │
    │  ├─ tar -czf bambook-web-X.X.X.tgz  │
    │  ├─ 从 macOS Keychain 取 Ops Token  │
    │  └─ curl -F file=@.tgz /ops/upload ─┼──► OPS Panel 接收
    │                                     │
    │                                     │  ├─ 解压到 /bambookos/releases/X.X.X
    │                                     │  ├─ 备用端口启动 node server
    │                                     │  ├─ Caddyfile.new 生成
    │                                     │  └─ 灰度四步法执行
    ◄─────────────── 部署完成通知 ─────────┘
```

**铁律**：Mac Mini 从不 `git pull`，所有代码变更通过 tarball 上传。

## §12 安全边界

| 风险 | 缓解 |
|---|---|
| JWT 泄露 | 短过期 + HttpOnly（若走 Cookie）+ 设备指纹校验 |
| SQL 注入 | Prisma 参数化查询，禁止业务代码手写 raw SQL |
| XSS | React 默认 XSS 防护 + DOMPurify 清洗 AI 输出 |
| CSRF | SameSite=Strict + Header 校验（Origin/Referer） |
| 权限越级 | SUPER_ADMIN 特判 + 敏感字段后端遮罩 + 审计日志 |
| 编号并发 | PostgreSQL 行锁 FOR UPDATE + 事务内原子递增 |
| Electron 上下文隔离 | contextBridge 白名单 + sandbox:true + nodeIntegration:false |
