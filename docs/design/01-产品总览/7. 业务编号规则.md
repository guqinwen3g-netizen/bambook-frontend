## §1 元信息

| 项 | 值 |
|---|---|

### §2.1 4 种周期（`SequencePeriod`）

| period | 语义 | periodKey 计算 | 示例（2026-08-15） |
|---|---|---|---|
| `year` | 按年重置 | `String(year)` | `2026` |
| `month` | 按月重置 | `${year}-${month2}` | `2026-08` |
| `day` | 按日重置（预留） | `${year}-${month2}-${day2}` | `2026-08-15` |
| `none` | 永不重置（全局累加） | `__global__` | `__global__` |

### §2.2 格式模板变量

| 变量 | 渲染 | 示例 |
|---|---|---|
| `{prefix}` | 前缀（SO/QT/PO...） | `SO` |
| `{year}` | 4 位年 | `2026` |
| `{month}` | 2 位月（补零） | `08` |
| `{day}` | 2 位日（补零） | `15` |
| `{seq}` | 纯序号（按 `defaultPadding` 补零） | `001` |
| `{seq:03}` | 补零到 3 位 | `001` |
| `{seq:pad=4}` | 补零到 4 位 | `0001` |

## §4 取号流程（事务内 upsert + increment + 格式化渲染）

### §4.1 新服务 `nextNumber()` 流程

```
nextNumber(db, seqType, opts?)
        │
        ▼
┌─────────────────────────────────────────────┐
│ 1. 读取 SEQUENCE_TYPE_CONFIGS[seqType] 配置   │
│    cfg = { prefix, period, defaultPadding,   │
│            defaultFormatTemplate }           │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│ 2. 计算 periodKey                            │
│    periodKeyForDate(cfg.period, date)        │
│    year → "2026" / month → "2026-08"         │
│    none → "__global__"                       │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│ 3. upsert 确保行存在（并发安全）              │
│    id = `SEQREG_${seqType}_${periodKey}`     │
│    upsert: create { currentSeq: 0 }          │
│            update {}                         │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│ 4. 原子 increment currentSeq                  │
│    update { currentSeq: { increment: 1 } }   │
│    select: currentSeq, formatTemplate,       │
│            padding, prefix                   │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│ 5. 格式化渲染                                 │
│    renderFormatTemplate(template, {          │
│      prefix, seq: currentSeq, date,          │
│      defaultPadding                          │
│    })                                        │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│ 6. 安全网：检查是否撞 VoidedNumber            │
│    if (isVoided(seqType, number))            │
│      → 递归 nextNumber() 再取下一号           │
│    （极端场景：手工回填未来号）                │
└─────────────────────────────────────────────┘
        │
        ▼
    return number
```

**关键约束**：
- `nextNumber()` **必须在 `$transaction` 内调用**，确保锁与单据创建原子提交
- PG 唯一约束 + upsert 语义保证并发安全（多请求同时取号不会重号）
- Fallback 模式：无 `sequenceRegister` 模型（如 mock/测试）时降级为时间戳+随机后缀

### §4.2 旧服务 `nextBusinessNumber()` 流程

```
nextBusinessNumber(db, prefix, year?)
        │
        ▼
┌─────────────────────────────────────────────┐
│ 1. 校验 prefix ∈ VALID_PREFIXES (21 种)      │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│ 2. id = `SEQ_${prefix}_${year}`              │
│    upsert: create { seq: 0 } / update {}     │
│    SELECT ... FOR UPDATE 行级锁（PG）         │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│ 3. 原子 increment seq                         │
│    update { seq: { increment: 1 } }          │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│ 4. 格式化（固定格式）                         │
│    `${prefix}-${year}-${String(seq).padStart(4,'0')}` │
└─────────────────────────────────────────────┘
        │
        ▼
    return number
```

### §4.3 `peekNextNumber()` 预览（不消费）

- **用途**：前端展示「下一编号」提示，不实际分配
- **实现**：`findUnique` 读取 `currentSeq`，返回 `(currentSeq ?? 0) + 1` 渲染结果
- **不加锁**：非事务调用，允许并发预览
- **Fallback**：无模型时返回 `prefix-periodKey-0001`

## §5 作废追踪（VoidedNumber 表 + 不回收原则）

### §5.1 核心原则

**序号单调递增，已分配序号永久保留，作废不回收。**

- 作废的编号写入 `VoidedNumber` 表「占坑」，后续 `nextNumber()` 不会重新分配该编号
- 极端安全网：`nextNumber()` 第 6 步检查新生成编号是否撞 `VoidedNumber`，撞则递归再取下一号

### §5.2 `markVoided()` 流程

```
markVoided(db, {
  seqType, number, reason?, voidedBy?,
  sourceDocId?, sourceDocType?, periodKey?, metadata?
})
        │
        ▼
┌─────────────────────────────────────────────┐
│ 1. 校验 seqType ∈ ALL_SEQUENCE_TYPES         │
│ 2. 校验 number 非空                           │
│ 3. id = `VOID_${seqType}_${number}`          │
│ 4. upsert VoidedNumber:                       │
│    create { seqType, number, periodKey,       │
│             reason, voidedBy, sourceDocId,    │
│             sourceDocType, metadata }         │
│    update { reason, voidedBy, sourceDocId,    │
│             sourceDocType, metadata }         │
│ 5. logger.info('[Sequence] markVoided', ...) │
└─────────────────────────────────────────────┘
```

### §5.3 辅助函数

| 函数 | 用途 |
|---|---|
| `isVoided(db, seqType, number)` | 检查某编号是否已作废（`findUnique` on `seqType_number` 复合唯一键） |
| `listVoided(db, filter)` | 分页查询作废列表（支持 seqType/periodKey/sourceDocType/sourceDocId/voidedBy/fromDate/toDate 过滤） |

### §5.4 旧服务作废追踪

旧服务 `businessNumberService.ts` **无作废追踪**，仅提供 `resetBusinessSequenceForTest()`（仅测试用，会实际删除 `BusinessSequence` 行重置计数器，业务代码禁用）。

## §9 设计约束

| 约束 | 说明 |
|---|---|
| 前缀强类型化 | `SequenceType` 联合类型 + `SEQUENCE_TYPE_CONFIGS` 常量，禁止业务代码硬编码前缀字符串 |
| 格式模板化 | `defaultFormatTemplate` 支持变量替换，禁止业务代码拼接编号字符串 |
| 事务内取号 | `nextNumber()` 必须在 `$transaction` 内调用，确保锁与单据创建原子提交 |
| 行锁防并发 | PG `upsert` + `update increment` 语义保证并发安全，无需显式 `SELECT FOR UPDATE` |
| 单调递增 | `currentSeq` 只增不减，作废不回收，`VoidedNumber` 占坑 |
| Fallback 降级 | 无 DB 模型时（mock/测试）降级为时间戳+随机后缀，不阻断业务流 |
| 编号不可改 | 单据创建后编号字段服务端强制覆盖，前端不传编号字段 |

## §10 数据模型

### §10.1 `SequenceRegister`（新服务，按 seqType+periodKey 行锁原子递增）

|---|---|---|
| `id` | `String @id` | `SEQREG_${seqType}_${periodKey}` |
| `seqType` | `String` | 12 类 SequenceType 之一 |
| `period` | `String` | year/month/day/none |

| `description` | `String?` | 描述 |

### §10.2 `VoidedNumber`（作废占坑）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String @id` | `VOID_${seqType}_${number}` |

## §15 补充说明

1. **新旧服务并存原因**：旧服务 `businessNumberService.ts` 已接 10+ 业务调用点且已有完整单元测试，新服务 `sequenceService.ts` 为 Phase 0-03 引入的增强版（支持月重置/模板化/作废追踪）。两者并存期间，新业务路由优先用新服务，老代码逐步迁移，避免一次性重构风险。
2. **`PV` 改为 `PAY` 的语义优化**：旧 prefix `PV`（PaymentVoucher）语义不直白，新服务改为 `PAY`，更直观表达「付款凭证」。迁移时需注意历史数据仍为 `PV-YYYY-NNNN` 格式。
3. **`ORD` 改为 `SO` + 按月重置**：旧 prefix `ORD` 按年重置 4 位，新服务 `order` 改为 `SO` 按月重置 3 位。原因：销售订单量大，按年重置 4 位（9999 上限）在大型贸易公司可能不够，按月重置更合理。
4. **主数据永不重置**：`customer`/`supplier`/`material` 三类主数据编号永不重置（`period=none`，`periodKey=__global__`），保证全生命周期唯一性。5 位补零（99999 上限）足够大多数贸易公司使用。
5. **作废不回收的设计权衡**：作废编号占坑不回收，虽然浪费序号空间，但保证了编号的单调递增性和审计可追溯性（作废的编号不会重新出现在新单据上，避免混淆）。这是外贸合规审计的硬性要求。
6. **`peekNextNumber` 的非事务性**：预览不消费序号，不加锁，允许并发预览。但注意：多用户同时预览看到的「下一编号」可能相同，实际取号时由 `nextNumber` 的事务+increment 保证唯一。
7. **DR-028 其他贸易共用编号体系**：其他贸易（非服装/面料的轻量贸易）不新增独立前缀，仍然沿用 SO/QT/PO/INV/SHP/PAY 等现有编号前缀，通过单据中的「业务线 line_of_business」字段（服装/面料/其他）做区分即可；编号体系统一避免碎片化。
8. **DR-029 出运/履约/收款编号分流**：出运=`SHP`（发货运单）、履约= order 状态机（无需独立编号，以 SO 编号为根的状态流转）、收款=`PAY`（付款凭证编号，收付款两条路径都用 PAY prefix + 单据类型字段区分应收/应付）。三者编号前缀或状态机已天然分流，不新增交叉编号。
9. **删除 scope（高危）的编号作废**：`orders:delete` / `quotations:delete` 等删除 scope 默认仅 SuperAdmin 运行时特判（极高危）。业务上取消/废除单据不调用 delete，而是：① 标记单据状态为 Cancelled/Voided ② `markVoided()` 把编号写入 VoidedNumber 表永久占坑——两条路径并行，确保编号可追溯而不是从 DB 物理抹掉。
