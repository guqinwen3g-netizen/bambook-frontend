## §2 IA 设计原则

1. **业务流左对齐**：导航顺序从「老板看数据」→「销售做市场」→「全公司履约」→「财务算钱」→「平台配系统」，对应实际工作流从决策到执行到底层配置
2. **order 段防插值回退**：overview 10-19 / customer 20-39 / fulfillment 40-69 / finance 70-89 / platform 90-119，中间预留大量空位防 49.x 补丁式插值
3. **primary=false 降级准入**：MES、发票、设置等非每日入口不出现在主导航一级，经二级入口进入
4. **compiled 双路径**：Relations/Products/Settings/Dashboard 有 compiled 和 fallback 双入口，UI 修改只改 compiled 版本
5. **权限先行**：每个模块绑定 permission policy，无 scope 时从 Sidebar 自动隐藏，不是 UI 隐藏后仍可直接 URL 跳转

## §6 导航交互规范

### §6.1 侧边栏（Sidebar）渲染规则
- 左侧固定宽度，collapsible（折叠时仅显示图标）
- 5 组之间用发丝分隔线（hairline separator），无实色区块拼凑
- 激活项用半透明雾化 tint（`--recessed-bg-strong`），不是纯蓝填充
- `adminOnly=true` 项：非 Admin/SuperAdmin 登录时从 DOM 中移除（非 display:none 隐藏）

### §6.2 面包屑位置与格式
- **严禁**放在标题左侧，必须放在 **标题栏右侧**
- 标题栏左侧 = 仅页面标题（中英双语，如「订单管理 Orders」）
- 面包屑格式：`经营总览 › 全景看板`，当前项不链接

### §6.3 标题间距铁律
所有页面标题区统一：`px-7 pt-5 pb-4`（左/右内边距 28px，上 20px，下 16px），禁止各页面自定义。

### §6.4 顶部栏超长文本处理
顶部栏所有文字（标题 / 状态 / 面包屑）**禁止换行**，超出部分 `truncate with ellipsis`，Tooltip 鼠标悬停显示全文。

## §7 模块注册与发现机制（moduleRegistry.ts）

```
App.tsx 启动
    │
    ▼
import BAMBOOK_MODULES from moduleRegistry.ts
    │
    ▼
Sidebar.tsx 根据 nav.group + nav.order 渲染 5 组导航
    │
    ▼
用户点击某模块 → View 枚举值写入全局状态
    │
    ▼
App.tsx 根据 View 查找对应 entry.current 渲染 Manager/Page
    │
    ▼
compiler.provenance = accepted 的模块：优先走 compiled 版本渲染
```

**注册表每个模块必填字段**：
- `id`：唯一标识（与 DB 审计关联）
- `view`：View 枚举绑定
- `productLabel`：展示名称（中英双语，如「数字档案 Products」）
- `nav.group` + `nav.order`：导航组 + 排序（防 49.x 插值段空间预留）
- `permissions.policy`：权限策略（与 VIEW_TO_MAIN_SCOPES 关联）
- `entry.current`：实际渲染源（含 compiled 双路径说明）

## §8 跨模块跳转导航机制（navigate + prime）

### §8.1 navigate：纯导航跳转
```typescript
navigate(view: View, params?: Record<string, unknown>)
```
仅切换 View，不做数据预加载。用于侧边栏点击、面包屑回溯等常规跳转。

### §8.2 prime：带上下文预加载的导航
```typescript
prime(view: View, context: {
  targetId?: string;        // 自动定位的业务对象 ID
  openSubView?: string;     // 自动打开的子视图
  filters?: Record<string, any>; // 自动应用的筛选条件
  targetView?: string;      // 订单页导入向导专用
})
```
用于「从客户档案跳到该客户的订单列表并自动筛选」「从报价单转化为订单并预填数据」等带上下文的跳转。

**典型链路**：
- 关系智库 → 客户 360 → 「该客户所有订单」按钮 → prime(View.Orders, { filters: { relationId: 'CUS-00123' } })
- 报价单 → 「转化为订单」 → prime(View.Orders, { context: { convertFromQuotationId: 'QT20260023' } })
