## §3 不做清单（永不做 · 非目标）

源自产品定位 §7「非目标 Out of Scope」，以下能力**永不在 Bambook 范围内**，不接受以"未来扩展"名义预留接口或字段：

| # | 不做项 | 原因 | 替代方案 / 边界澄清 |
|---|--------|------|---------------------|
| 1 | **生产端工位级 MES** | 工厂级排产/工时/计件非贸易公司核心能力 | 降级为可选模块：生产看板 10 阶段泳道（手工推进）+ 外协加工视图；不接工位机、不采集设备遥测 |
| 2 | **移动端 PWA 主形态** | 桌面 Electron 是唯一产品形态，移动端仅远期只读视图 | Phase 4 仅规划 QC 验货 PWA（单一场景），全员移动办公不在范围；详见 [移动端需求.md](./移动端需求.md) |
| 3 | **会计电算化全盘替代** | 不做总账/明细账/资产负债表/现金流量表/利润表 | 仅做业务层应收应付 + 凭证导出，对接金蝶/用友（导出 XML/Excel 标准格式），不做借贷复式记账引擎 |
| 4 | **公域电商平台对接** | 聚焦 B2B 外贸，不做亚马逊/速卖通/Shopee 等 C 端运营 | 不接电商平台 API、不做 listing 管理、不做 C 端订单同步；B2B 询价邮件归档是边界内 |
| 5 | **社交协同（IM/Doc 协同）** | 不替代微信/飞书/钉钉 | 仅绑定业务对象到消息与审批（通知中心 + 审批中心），不做实时 IM 会话、不做多人协同文档编辑 |

**边界铁律**：以上 5 项在任何模块设计文档的"范围外"声明中可直接引用本表，无需重复论证。

## §4 技术边界

### 4.1 架构边界（两端分离）

| 层 | 职责 | 边界约束 |
|----|------|---------|
| **桌面客户端（Electron + React）** | UI 展示 / 交互 / 本地 STT（sherpa-onnx）/ 本地缓存（IndexedDB） | ❌ 不持业务真源（数据真源在 Mac Mini PostgreSQL）；❌ 不做业务规则计算（仅镜像前端校验）；离线 fallback 仅只读模式 |
| **Mac Mini 数据中心** | Express + Prisma + PostgreSQL + Agent Runtime + LLM 网关 + TTS + OPS Panel | ❌ 不渲染 UI（仅 JSON API + 静态 webapp serve）；❌ 不从 GitHub 拉代码（push-based 部署）；✅ 唯一业务真源 |
| **OPS Panel** | 运维操作面（部署 / 日志 / DB / 服务状态 / 远程开发） | ❌ 不承载业务逻辑；❌ 不直接写业务表（仅运维操作 + DB 只读查询）；✅ 独立 tsconfig + 独立 node_modules |
| **Agent Runtime** | 多步规划 + 工具编排 + 可审计轨迹 | ❌ 不绕过权限守卫（所有写工具走 createModuleAuthGuard）；❌ 不直接操作 DB（经 Service 层）；✅ human-in-the-loop 审批 |

### 4.2 数据边界

| 约束 | 说明 |
|------|------|
| **真源唯一** | 每个业务对象只有一个真源表（PostgreSQL via Prisma），其他模块只读关联，不允许重复字段冗余 |
| **关联先行** | 任何新建单据必须先绑到上游对象（订单→客户+报价→产品+BOM），不允许游离单据 |
| **作废不复用** | 所有业务编号一旦分配不回收，作废仅占坑标记（`deletedAt` 软删），保证审计连续 |
| **软删除统一** | 业务实体统一 `deletedAt BigInt` 软删；参考数据（HsCode 等）用 `isActive` 停用 |
| **客户端不写库** | 桌面客户端经 API 写入，离线 fallback 只读（探活失败时启动本地 Express 只读模式） |

### 4.3 设计系统边界

| 约束 | 说明 |
|------|------|
| **权威 token 源** | `styles/os-vnext.css`（320 个 CSS 变量）；实际渲染准源 `styles/flat-experimental.css` |
| **flat 设计特征** | 完全无阴影、无 rim、大圆角（22-34px）、保留半透明膜色（blur + saturate） |
| **禁止硬编码** | tsx 中禁止 `rounded-[Npx]`、hex 颜色（`#xxx`）、`box-shadow` 硬编码 |
| **防回退** | `scripts/check-design-tokens.sh` 基线模式检查新增硬编码 |
| **可豁免** | 吉祥物 SVG/Canvas 颜色、3D 地图 WebGL 颜色、邮件/发票模板（CSS 变量在邮件客户端不可靠） |

### 4.4 渲染路径边界

| 规则 | 说明 |
|------|------|
| **compiled 双路径** | Relations/Products/Settings 有 compiled 版本，改 UI 只改 compiled 版本 |
| **Manager 即渲染源** | 其他页面 Manager 文件即实际渲染源 |
| **透明包裹器** | `CompiledMainModuleSlot` className="contents" 是透明包裹器，不引入额外 DOM 层 |

## §9 边界决策原则

当新需求出现时，按以下优先级判断是否在边界内：

```
新需求
  │
  ├─ 命中 §3 不做清单？ ──是──▶ 🚫 拒绝，引用本文件 §3
  │
  ├─ 命中 §6-§8 Phase 3-5 搁置项？ ──是──▶ ❌ 当前不实现，登记到路线图
  │
  ├─ 命中 Phase 1-2 已交付能力？ ──是──▶ ✅ 在边界内，按模块设计文档推进
  │
  └─ 均未命中？ ──▶ 架构评审：判断是否扩展边界或拒绝
                    │
                    ├─ 扩展边界 → 更新本文件 + 产品定位 §6-§7
                    └─ 拒绝 → 记录决策到审计报告
```

## §10 关键设计原则（边界内行为约束）

源自产品定位 §8，边界内能力必须遵循：

1. **真源唯一原则**：每个业务对象只有一个真源表，其他模块只读关联
2. **关联先行原则**：任何新建单据必须先绑到上游对象，不允许游离单据
3. **权限最小原则**：业务员默认仅本部门可见，敏感字段默认遮罩
4. **作废不复用原则**：所有业务编号一旦分配不回收
5. **设计铁律原则**：所有 UI 必须走 BDS v2.1 语义类，不允许硬编码
