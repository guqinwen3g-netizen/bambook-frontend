## §3 Webhook 告警外发（✅ 已落地）

### 3.1 设计目标

将后端 `error` 级日志外发到外部 Webhook 端点（如飞书/钉钉/企业微信机器人），用于生产环境异常实时告警。

### 3.2 配置契约

| 环境变量 | 说明 | 默认值 |
|---------|------|--------|
| `BAMBOOK_ALERT_WEBHOOK_URL` | Webhook 端点 URL；未配置则不挂载 WebhookAlertTransport（默认关闭） | 空（关闭） |
| `BAMBOOK_ALERT_THROTTLE_MS` | 同源消息节流窗口（毫秒），窗口内重复 error 只外发一次 | 见 logger.ts |
| `BAMBOOK_ALERT_MIN_LEVEL` | 最低告警级别（error/warn 等） | error |

### 3.3 外发契约

```json
POST <BAMBOOK_ALERT_WEBHOOK_URL>
Content-Type: application/json

{
  "source": "bambook-main-api",
  "level": "error",
  "component": "<组件名>",
  "traceId": "<链路追踪 ID>",
  "message": "<错误消息>",
  "timestamp": "<ISO 8601 时间戳>"
}
```

### 3.4 不变量

源自 `alertWebhook.test.ts` 测试覆盖：

| # | 不变量 | 说明 |
|---|--------|------|
| 1 | 默认关闭 | 未配置 `BAMBOOK_ALERT_WEBHOOK_URL` → 不挂载 WebhookAlertTransport |
| 2 | fire-and-forget | webhook 故障（reject/abort）→ 不反噬日志管线（logger.error 正常返回） |
| 3 | 同源节流 | throttle 窗口内重复 error 只外发一次，不同消息各自外发 |
| 4 | 不阻断业务 | 告警外发异步执行，不影响业务请求响应 |

### 3.5 适用场景

- Mac Mini 主 API 进程崩溃（uncaughtException）
- 数据库连接池耗尽
- Agent Runtime 工具执行异常
- 关键业务流程失败（如编号分配冲突、状态机非法转换）

## §4 开放 API（API-Key）（✅ 已落地）

### 4.1 认证机制

| 认证方式 | 用途 | 守卫 |
|---------|------|------|
| JWT | 桌面客户端用户操作 | `requireUser` / `createModuleAuthGuard` |
| API-Key | 外部系统只读访问 + Agent 工具调用 | `createModuleAuthGuard`（JWT 或 API-Key）+ `requireJwtForWrite`（写操作强制 JWT） |

### 4.2 API-Key 适用范围

| 场景 | 权限 | 说明 |
|------|------|------|
| Agent 只读业务工具集 | 只读 | Agent 查询订单/客户/库存/财务等业务数据 |
| 外部报表系统拉取 | 只读 | 经 API-Key 拉取报表数据（如利润表/账龄） |
| OPS Panel 健康检查 | 只读 | `BAMBOOK_SDK_KEY` / `BAMBOOK_API_KEY` 探活 |
| 写操作 | ❌ 禁止 API-Key | 所有写操作（create/update/delete/transition）强制 JWT |

### 4.3 API 路由约定

| 约定 | 说明 |
|------|------|
| 路由前缀 | `/api/v1/<module>`（如 `/api/v1/orders`、`/api/v1/customs`） |
| 读操作 | GET 列表/详情，支持 JWT 或 API-Key |
| 写操作 | POST/PUT/DELETE/transition，强制 JWT（`requireJwtForWrite`） |
| 审计 | 写操作经 `writeRouteAuditLog` 落审计日志 |

## §5 海关申报 API 预留（❌ Phase 5）

### 5.1 当前现状

源自 `customsService.ts` 注释与报关模块概述 §3.2：

| 能力 | 状态 | 说明 |
|------|------|------|
| 报关单 CRUD + 状态机 | ✅ | Draft→Submitted→Declared→Inspecting→Released 7 态，服务端 fail-closed 校验 |
| HS 编码库 | ✅ | 参考数据 CRUD + 退税率/关税率/监管条件 |
| 报关单电子口岸申报直连 | ⚠️ 缺口 | **仅本地登记，未对接海关单一窗口 API** |

### 5.2 Phase 5 对接方案预留

| 维度 | 预留方案 |
|------|---------|
| 对接目标 | 海关单一窗口（中国国际贸易单一窗口）第三方 API |
| 前置条件 | ① 单一窗口开放第三方 API；② 报关员数字证书（U-Key）授权；③ 企业备案信息 |
| 对接范围 | 报关单自动申报（Draft→Submitted 自动推送）+ 申报状态回执（Declared/Inspecting/Released 回填） |
| 数据映射 | CustomsDeclaration 字段 → 单一窗口报文格式（XML/EDI） |
| 安全 | 数字证书签名 + 专线/VPN 传输 |
| 回退 | API 故障时降级为本地登记 + 人工单一窗口录入 |

### 5.3 不预留半成品

当前代码层**不预留**单一窗口 API 桩（无 TODO、无空接口），Phase 5 启动时按新集成完整设计。报关单状态机已含 `Submitted→Declared` 流转，未来对接时复用该状态转换触发 API 推送。

## §6 银行 API 直连预留（❌ Phase 5）

### 6.1 当前现状

源自 `outwardRemittanceService.ts`（汇出汇款）+ `financeServiceV2.ts`：

| 能力 | 状态 | 说明 |
|------|------|------|
| 收付凭证 CRUD | ✅ | PaymentVoucher 本地登记 + 自动核销（L5） |
| 汇出汇款登记 | ✅ | OutwardRemittance 本地登记 + 状态机 |
| 外汇结汇 | ✅ | FxSettlement 本地登记 + 差异损益计算 |
| 银行 API 直连（水单自动认领） | ⚠️ 缺口 | **当前无银企直连，水单人工上传** |

### 6.2 Phase 5 对接方案预留

| 维域 | 预留方案 |
|------|---------|
| 对接目标 | 银企直连（主要银行：中行/工行/建行/招行） |
| 前置条件 | ① 企业开通银企直连服务；② 银行 API 授权凭证；③ 安全审计通过 |
| 对接范围 | 水单自动认领（银行流水 → PaymentVoucher 草稿）+ 汇出汇款自动发起（OutwardRemittance → 银行汇款指令） |
| 数据映射 | 银行流水字段 → PaymentVoucher 字段（金额/币种/付款方/收款方/水单号） |
| 安全 | 银企直连证书 + IP 白名单 + 金额双向校验 |
| 回退 | API 故障时降级为人工上传水单 + 人工核销 |

### 6.3 不预留半成品

当前 PaymentVoucher / OutwardRemittance 模型已含完整状态机与审计字段，Phase 5 对接时复用现有状态转换触发银行 API 调用，不预留 API 桩。

## §8 集成安全约束

| 约束 | 说明 |
|------|------|
| **API-Key 不写** | API-Key 仅用于只读访问，写操作强制 JWT 认证 |
| **Webhook fire-and-forget** | 外发告警不阻断业务，故障仅日志 |
| **证书管理** | 海关/银行 API 证书存 macOS Keychain（同 OPS Token），不入代码库 |
| **传输加密** | 所有外部 API 走 HTTPS；银行/海关 API 加证书签名 |
| **审计留痕** | 外部 API 调用经 `writeRouteAuditLog` 落审计日志 |
| **回退降级** | 外部 API 故障时降级为本地登记 + 人工处理，不阻断业务主流程 |

## §9 Agent 工具与外部集成的关系

源自 `toolRegistry.ts`，Agent 工具支持的通知类型含 `webhook`：

```ts
type: 'email' | 'sms' | 'webhook' | 'notification';
```

| Agent 能力 | 外部集成关系 |
|-----------|-------------|
| 只读业务工具集 | 经 API-Key 调用业务 Service（不直接操作 DB） |
| 写操作工具 | 经 JWT + 审批（human-in-the-loop），不绕过权限守卫 |
| Webhook 通知 | Agent 可触发 webhook 通知（如审批结果外发） |
