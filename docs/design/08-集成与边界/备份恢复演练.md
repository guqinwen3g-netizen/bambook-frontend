## §2 备份机制总览

| 项 | 值 | 说明 |
|---|---|---|
| 备份对象 | `pandahub` 库（Mac Mini 生产） | 业务真源 PostgreSQL |
| 工具 | `pg_dump --format=custom`（-Fc） | 自定义格式，支持 pg_restore 按表恢复与并行恢复 |
| 备份文件 | `bambook-YYYYMMDD-HHmmss.dump` | 例：`bambook-20260828-020000.dump` |
| 备份目录 | `/Users/Shared/BambookBackups` | 不存在时脚本自动创建；`BAMBOOK_BACKUP_DIR` 可覆盖 |
| 保留策略 | 7 天，`find -mtime +7` 自动清理 | `BAMBOOK_BACKUP_RETENTION_DAYS` 可覆盖；模式 `bambook*.dump` 同时覆盖历史命名 `bambook-panda-hub-*` / `bambook-postgres-*` |
| 日志 | stdout + `/Users/Shared/BambookBackups/backup.log` | 每行带 `[YYYY-MM-DD HH:mm:ss]` 时间戳；launchd 场景 stdout 已重定向到同一文件，脚本自动去重 |
| 调度 | launchd `StartCalendarInterval` 每天 02:00 | Label `com.bambook.postgres-backup` |
| 手动备份 | OPS Panel `backupPostgres` 动作 | 走 `ops/ops-backup-postgres.sh`，复用同一脚本与同一备份目录 |

### 连接方式（脚本自动二选一）

1. **`DATABASE_URL` 已设置**（OPS Panel 手动触发路径，env 已从 server `.env` 加载）：直接使用，脚本自动剥掉 Prisma 专有的 `?schema=` 参数。
2. **未设置**（launchd 定时触发路径）：回退 `localhost:5432`，用户 `postgres`，库 `pandahub`；`PGHOST`/`PGPORT`/`PGUSER`/`BAMBOOK_BACKUP_DB` 按 libpq 惯例可覆盖。
   - **密码**：从环境变量 `PGPASSWORD` 读取，**不要写进脚本或 plist**；生产推荐 `~/.pgpass`（内容 `localhost:5432:pandahub:postgres:<密码>`，`chmod 600`）。

## §3 launchd 任务管理命令

以下命令均在 **Mac Mini** 上执行（server 部署后脚本真实路径为 `~/bambook-main-api/scripts/backup-postgres.sh`）。

### 3.1 安装

```bash
# 1. 复制 plist 到 LaunchAgents
cp ~/bambook-main-api/scripts/com.bambook.postgres-backup.plist ~/Library/LaunchAgents/

# 2. 替换 home 目录占位符（与项目其他 plist 同一约定）
sed -i '' "s|CHANGE_ME_HOME|$HOME|g" ~/Library/LaunchAgents/com.bambook.postgres-backup.plist

# 3. 加载（现代 macOS）
launchctl bootstrap "gui/$(id -u)" ~/Library/LaunchAgents/com.bambook.postgres-backup.plist
# 旧版 macOS 等价命令：launchctl load -w ~/Library/LaunchAgents/com.bambook.postgres-backup.plist
```

### 3.2 手动触发一次（不等 02:00，立即验证）

```bash
launchctl kickstart "gui/$(id -u)/com.bambook.postgres-backup"
```

### 3.3 查看状态与日志

```bash
# 任务状态（含 last exit code）
launchctl print "gui/$(id -u)/com.bambook.postgres-backup" | grep -iE 'state|last exit'

# 实时跟踪备份日志
tail -f /Users/Shared/BambookBackups/backup.log

# 查看现有备份与磁盘占用
ls -lh /Users/Shared/BambookBackups/
df -h /Users/Shared
```

### 3.4 卸载

```bash
launchctl bootout "gui/$(id -u)/com.bambook.postgres-backup"
rm ~/Library/LaunchAgents/com.bambook.postgres-backup.plist
```

## §4 恢复步骤（临时库 → 校验 → 切生产）

> 铁律：**永远先恢复到临时库校验，确认无误后再切生产**；禁止直接 pg_restore 覆盖 `pandahub`。

### Step 1：选定备份文件

```bash
ls -lh /Users/Shared/BambookBackups/bambook-*.dump
DUMP=/Users/Shared/BambookBackups/bambook-YYYYMMDD-HHmmss.dump   # 选最近一次备份
pg_restore --list "$DUMP" | head -20                              # 确认 dump 可读、内容符合预期
```

### Step 2：恢复到临时库

```bash
dropdb -h localhost -U postgres pandahub_restore_test 2>/dev/null || true
createdb -h localhost -U postgres pandahub_restore_test
pg_restore -h localhost -U postgres --no-owner --no-acl \
  --dbname=pandahub_restore_test "$DUMP"
```

### Step 3：校验临时库

```bash
# 3.1 表数量与生产一致
psql -h localhost -U postgres -d pandahub_restore_test -tAc \
  "SELECT count(*) FROM information_schema.tables WHERE table_schema='public'"
psql -h localhost -U postgres -d pandahub -tAc \
  "SELECT count(*) FROM information_schema.tables WHERE table_schema='public'"

# 3.2 关键业务表行数抽查（订单/产品/往来单位，两库对比）
for t in "Order" "Product" "Company"; do
  echo "== $t =="
  psql -h localhost -U postgres -d pandahub_restore_test -tAc "SELECT count(*) FROM \"$t\""
  psql -h localhost -U postgres -d pandahub            -tAc "SELECT count(*) FROM \"$t\""
done

# 3.3（可选）应用级冒烟：临时把主 API 的 DATABASE_URL 指向 pandahub_restore_test 起本地实例，
#     走查订单列表/产品列表/三击追溯，确认业务可读
```

### Step 4：切生产（改名切换，可回退）

```bash
# 4.1 停主 API（KeepAlive 服务需 bootout 才会真正停掉，恢复后再 bootstrap 拉起）
launchctl bootout "gui/$(id -u)/com.bambook.main-data-api"

# 4.2 断开残留连接（pandahub 与临时库都不允许有活跃连接，否则 rename 失败）
psql -h localhost -U postgres -d postgres -c \
  "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname IN ('pandahub','pandahub_restore_test') AND pid <> pg_backend_pid()"

# 4.3 改名交换（原子窗口极短）
psql -h localhost -U postgres -d postgres <<'SQL'
BEGIN;
ALTER DATABASE pandahub RENAME TO pandahub_bak_20260828;
ALTER DATABASE pandahub_restore_test RENAME TO pandahub;
COMMIT;
SQL

# 4.4 拉起主 API + 健康检查（OPS Panel healthcheck 动作，或本地）
launchctl bootstrap "gui/$(id -u)" ~/Library/LaunchAgents/com.bambook.main-data-api.plist
sleep 3
curl -fsS http://127.0.0.1:8081/api/health
```

### Step 5：回退（如切换后异常）

```bash
# 与 Step 4 反向：先停主 API → pandahub（恢复版）改名留存 → 原库改回 pandahub → 拉起
launchctl bootout "gui/$(id -u)/com.bambook.main-data-api"
psql -h localhost -U postgres -d postgres -c \
  "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname IN ('pandahub','pandahub_bak_20260828') AND pid <> pg_backend_pid()"
psql -h localhost -U postgres -d postgres <<'SQL'
BEGIN;
ALTER DATABASE pandahub RENAME TO pandahub_restore_failed;
ALTER DATABASE pandahub_bak_20260828 RENAME TO pandahub;
COMMIT;
SQL
launchctl bootstrap "gui/$(id -u)" ~/Library/LaunchAgents/com.bambook.main-data-api.plist
```

切换确认稳定运行 **7 天** 后，再 `dropdb pandahub_bak_20260828` 释放磁盘。

## §5 演练清单（投产前至少完整跑通一次）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | 备份脚本手动跑通 | `bash ~/bambook-main-api/scripts/backup-postgres.sh` 退出码 0，`backup.log` 出现 `backup ok` |
| 2 | dump 完整性 | `pg_restore --list <dump>` 无错误输出，文件大小与库体量相符 |
| 3 | launchd 任务安装 | `launchctl print gui/$(id -u)/com.bambook.postgres-backup` 可见，state 非 error |
| 4 | launchd 手动触发 | kickstart 后 `backup.log` 追加一条完整 backup start → done 记录 |
| 5 | 定时触发确认 | 次日 02:00 后确认新 dump 生成（不能只信手动触发） |
| 6 | 过期清理 | 造一个 8 天前的测试 dump（`touch -t $(date -v-8d +%Y%m%d%H%M.%S) /Users/Shared/BambookBackups/bambook-test-old.dump`），重跑脚本后该文件被删除、日志记录 removed 数量 |
| 7 | 临时库恢复 | §4 Step 2 完成，pg_restore 退出码 0 无 ERROR |
| 8 | 数据校验 | §4 Step 3 表数量一致、关键表行数偏差为 0（备份时刻后的增量除外） |
| 9 | 切换演练 | §4 Step 4 完成，健康检查通过，前端三击走查无异常 |
| 10 | 回退演练 | §4 Step 5 完成，业务恢复原库正常 |
| 11 | 磁盘冗余 | `/Users/Shared` 剩余空间 ≥ 单份 dump × 10（7 份日备 + 增长余量） |

演练结论（日期/执行人/耗时/异常）记录在 `backup.log` 尾部或 DR 台账追加，**不另产新文档**。
