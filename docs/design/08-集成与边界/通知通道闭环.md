## §2 通知闭环骨架

```
┌──────────────────────────────────────────────────────────────────────┐
│ ① 通知产生                                                            │
│    • 业务事件（BusinessEventBus）→ notificationTemplateEngine 渲染     │
│    • D2 主动提醒引擎（scheduler/tasks/* 定时扫描）                     │
└──────┬───────────────────────────────────────────┬───────────────────┘
       │                                           │
       ▼                                           ▼
┌──────────────────────────┐               ┌─────────────────────────┐
│ ② 落库 + 投递             │               │ ② 偏好过滤              │
│    Notification 表落库    │               │  NotificationPreference │
│    SSE 实时推送           │               │  静音类型不投递          │
│    原生推送桥（Electron） │               │                         │
└──────┬───────────────────┘               └─────────────────────────┘
       │
       ▼
┌──────────────────────────────────────────────────────────────────────┐
│ ③ 用户响应（4 种动作）                                                │
│    a. 标记已读（markAsRead / markAllAsRead）                          │
│    b. 忽略填原因（dismiss + reason）→ PRD 7.1 准确率优化              │
│    c. 转跟进（convert-to-followup）→ CRM 跟进任务闭环                 │
│    d. 删除（deleteNotification）                                      │
└──────┬───────────────────┬────────────────────────────────────────────┘
       │                   │
       ▼                   ▼
┌──────────────────────┐  ┌─────────────────────────────────────────────┐
│ ④a 已读 → 退出未读   │  │ ④b 忽略原因 → 准确率反馈循环                │
└──────────────────────┘  │    • dismissedAt + dismissReason 落库        │
                          │    • 原因聚类 → 偏好调优建议（规划增强）     │
                          └─────────────────────────────────────────────┘
       │
       ▼
┌──────────────────────────────────────────────────────────────────────┐
│ ④c 转跟进 → FollowUpRecord（type='Other'，relationId 必填）           │
│    • 幂等标记 [notification:<id>]                                     │
│    • 进入 CRM 跟进逾期看门狗巡检闭环                                  │
└──────────────────────────────────────────────────────────────────────┘
```

## §3 通知产生（业务事件 + D2 主动提醒）

### 3.1 业务事件驱动

源自 `notificationService.ts`：

| 事件源 | 说明 | 示例类型 |
|--------|------|---------|
| BusinessEventBus | 业务操作触发事件 → notificationTemplateEngine 渲染 → 落库 | order_confirmed / shipment_completed / invoice_issued |
| 调度器（scheduler/tasks/*） | 定时扫描业务异常 → D2 主动提醒 | receivable_overdue / production_deadline / shipment_delay |

### 3.2 类型目录（NOTIFICATION_TYPE_LABELS）

`notificationService.ts` 维护已知通知类型中文标签注册表（60+ 类型），键与 scheduler/tasks/* 及 notificationTemplateEngine 实际使用的 type 字符串逐一核对；目录兜底为原始 type 字符串（未知类型自描述，不阻断）。

### 3.3 不变量

| # | 不变量 | 说明 |
|---|--------|------|
| 1 | 通知失败永不阻断业务 | 持久化失败仅日志，不影响业务请求 |
| 2 | SSE 推送失败只影响实时性 | 落库已成功，用户刷新可见，不重试 |
| 3 | 邮件通道默认关闭 | 需 NotificationPreference 配置开启 |
| 4 | 接收人解析 | 单租户场景，所有 active 用户都收到（Phase 1+ 加细粒度路由） |

## §5 忽略填原因（PRD 7.1 推送准确率优化）

### 5.1 端点契约

```
POST /api/v1/notifications/:id/dismiss
入参：
  { reason: string }   // 必填，忽略原因，最长 500 字
出参：
  { ok: true } 或 { error: 'REASON_REQUIRED' | 'REASON_TOO_LONG' | 'NOT_FOUND' }
```

### 5.2 服务端实现

源自 `notificationService.dismissNotification`：

```ts
async dismissNotification(userId, notificationId, reason): Promise<{ ok: boolean }> {
  const now = new Date();
  const result = await prisma.notification.updateMany({
    where: { id: notificationId, userId, dismissedAt: null },
    data: { dismissedAt: now, dismissReason: reason, readAt: now },
    // 忽略即已读，退出未读统计与默认列表
  });
  return { ok: result.count > 0 };
}
```

### 5.3 校验规则

| 规则 | 说明 |
|------|------|
| reason 必填 | 空字符串 → 400 `REASON_REQUIRED` |
| reason 长度 | 最长 500 字 → 超长 400 `REASON_TOO_LONG` |
| 幂等 | 已 dismissed 的通知返回 404 `NOT_FOUND` |
| 忽略即已读 | `dismissedAt` + `dismissReason` + `readAt` 同时写入，退出未读统计 |

### 5.4 业务铁律

**忽略必须填原因**——这是 PRD 7.1 的硬约束，用于推送准确率优化。用户不能无原因地忽略通知，每条忽略原因都是准确率反馈循环的输入数据。

## §6 转跟进（通知 → CRM 跟进任务闭环）

### 6.1 端点契约

```
POST /api/v1/notifications/:id/convert-to-followup
出参：
  { ok: true, reused: boolean, followUpId: string, nextFollowUpAt: string | null }
  或 { error: 'NO_RELATION' | 'NOT_FOUND' }
```

### 6.2 服务端实现

源自 `notificationFollowUpService.ts`（与 C8 emailFollowUpService 同合约）：

| 不变量 | 说明 |
|--------|------|
| 幂等 | notes 内含来源标记 `[notification:<notificationId>]`，重复调用返回已建记录（reused） |
| 跟进必须挂客户档案 | relationId 解析链全部失败 → 409 `NO_RELATION` |
| 通知必须属本人 | 防越权把他人通知转成自己的跟进 |
| 创建写审计 | 复用不写审计 |

### 6.3 relationId 解析链（按优先级）

```
1. metadata.relationId（直接携带）
       │ 失败
       ▼
2. metadata.orderId → Order.customerRelationId
   （生产超期 / 订单卡滞等）
       │ 失败
       ▼
3. metadata.entityType='Invoice' + entityId
   → Invoice.orderId → Order.customerRelationId
   （应收逾期通知只带发票主键）
       │ 全失败
       ▼
   409 NO_RELATION
```

### 6.4 跟进任务字段

```ts
FollowUpRecord.create({
  data: {
    relationId,              // 解析链得到，必填
    type: 'Other',           // 通知转跟进固定类型
    content,                 // 通知标题 + 正文摘要
    followUpAt: 今天,
    nextFollowUpAt,          // 默认明天，进入逾期巡检视野
    salesRepId: actorId,     // 操作人
    notes: `[notification:<id>]`,  // 幂等标记
  },
});
```

### 6.5 闭环下游

转跟进后进入既有 CRM 跟进逾期看门狗巡检闭环（`crmFollowUpWatchdog`）：`nextFollowUpAt` 过期 → 提醒 salesRep → 预警不止于"已读"，而是落到可追踪的后续动作。

## §8 准确率反馈循环（规划增强）

### 8.1 当前能力

| 能力 | 状态 | 说明 |
|------|------|------|
| 忽略原因落库 | ✅ | `dismissedAt` + `dismissReason` 持久化 |
| 偏好手动静音 | ✅ | 用户手动 PUT preferences 静音某类型 |
| 原因聚类分析 | ⚠️ 缺口 | 当前无自动分析忽略原因分布 |
| 自动偏好调优 | ⚠️ 缺口 | 当前无基于忽略原因的自动静音建议 |

### 8.2 反馈循环设计（规划）

```
用户忽略通知（填原因）
       │
       ▼
dismissReason 落库
       │
       ▼
定期聚类分析（按 type × reason 关键词）
       │
       ▼
高忽略率类型 → 偏好调优建议
       │
       ├─ 自动降级（info → 静音，warning → 仅站内）
       └─ 人工确认 → 批量静音
       │
       ▼
推送准确率提升（减少无效打扰）
```

### 8.3 准确率指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 忽略率 | dismissed / total | <20%（高忽略率说明推送不够精准） |
| 转跟进率 | converted-to-followup / total | >10%（高转跟进率说明预警有业务价值） |
| 已读率 | read / total | >70% |
| 有效响应率 | (read + converted) / (total - dismissed) | >80% |

## §9 通知状态机

```
┌──────────┐    标记已读     ┌──────────┐
│  未读     │──────────────▶│  已读     │
│ (默认)   │                │          │
└────┬─────┘                └──────────┘
     │
     │ 忽略填原因
     ▼
┌──────────────────┐
│  已忽略           │
│  dismissedAt +   │
│  dismissReason   │
│  (同时 readAt)   │
└──────────────────┘

任何状态 ──删除──▶ ♻️ 物理删除（deleteMany）
```

| 状态 | 字段 | 列表可见 | 未读统计 |
|------|------|---------|---------|
| 未读 | `readAt: null` | ✅ 默认列表 | ✅ 计入 |
| 已读 | `readAt: <date>` | ✅（unreadOnly=false 时） | ❌ |
| 已忽略 | `dismissedAt + dismissReason + readAt` | ❌ 退出默认列表 | ❌ |
| 已删除 | 物理删除 | ❌ | ❌ |
