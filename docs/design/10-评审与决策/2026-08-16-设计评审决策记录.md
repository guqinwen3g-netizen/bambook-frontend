### DR-003 Capsule 是服装订单的 MOQ 豁免

|---|---|
| 状态 | 已确认 |
| 结论 | Capsule 与服装大货共用同一订单模型、字段、状态机、生产链和单据链；不得创建独立模块或独立流程。 |

| 项 | 决策 |
|---|---|

| 结论 | Track A、Track B 和任何定价模型均为参考/试算，不具有自动定价权。 |

| 回写目标 | 价格审批规则、报价编辑器、报价转订单流程、双轨成本面板、偏差校验与审批链。 |

### DR-009 商业订单批准与生产放行分离

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |
| 商业订单批准 | 客户合同或等效订单依据齐备、交期确认、销售主管或总领导批准后，大货订单成立。定金仅记录和跟踪，不作为统一采购门禁。 |
| 采购先行 | 订单获批后即可启动面料采购及相关开发；这是标准流程，不是紧急例外。 |
| 生产放行 | 内部 QC 通过、业务员已登记客户确认、产前样已封存后，即可完成管理上的生产放行；封样不以大货面料到位为前提。 |
| 放行确认人 | 系统仅在条件满足时显示“具备放行条件”；订单所属团队的销售主管或总领导必须手动确认生产放行。业务员准备资料，QC 提供样品评审结论。 |
| 实际开工 | 生产放行与实际开裁/开工必须分离。面料采购持续并行；只有面料实际可用并完成排产，才可进入实际裁剪、缝制等大货生产。 |
| 出运 QC 门禁 | 大货生产完成后必须经 QC 评审通过，才具备出运条件。样品 QC 与大货出运前 QC 是两道独立、不可替代的质量门禁。 |
| 出运批准 | QC 通过后仍须由订单所属团队的销售主管或总领导手动批准“允许出运”；批准后业务员/跟单才可安排出运执行。 |
| 履约终点 | 出运、合同履约、客户收货、财务结清必须分开记录。每张订单必须记录实际贸易术语、指定地点和适用版本；系统据此判定合同履约节点，禁止把 FOB 作为统一默认。FOB 以约定装运港的装船凭证履约；其他术语按其约定地点与凭证判定。客户收货确认按术语作为后续服务、客诉与回款跟踪或必要的履约证据。 |
| 回写目标 | 核心业务流程、订单状态机、开发转订单流程、采购模块、生产看板、QC 模块。 |

### DR-010 已批准订单的变更与取消控制

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |
| 已确认部分 | 草稿/待审批订单可由业务员撤回、取消或暂停。领导批准订单后，订单进入正式承诺状态：取消、暂停、改价、改数量、改交期均不得由业务员直接修改，必须走正式申请与审批。 |
| 已确认审批 | 改价、改数量、改交期均须由销售主管或总领导审批，并记录前后值、原因与影响。 |
| 取消 | 已批准订单取消先进入“取消申请中”，系统汇总合同、面料采购、样品、生产、付款与库存影响。销售主管或总领导为最终业务审批人；采购、QC、财务仅确认各自影响。无不可逆承诺时批准后直接结案；已有采购或生产承诺时，批准后进入“结案处理中”，完成供应商、物料、客户责任和财务损益处置后才可关闭。 |
| 暂停 | 已批准订单暂停先进入“暂停申请中”，必须记录原因、责任人和预计恢复日期，经销售主管或总领导批准后生效；到期未恢复自动提醒，禁止无限期挂起。 |
| 回写目标 | 订单变更规则、订单状态机、订单详情页、采购模块、生产看板、财务与结算相关设计。 |

### DR-011 面料船样与匹头样规则

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |
| 船样（S/S） | 面料订单必须管理船样。其是面料投产后的客户确认节点：系统须记录寄送、客户确认、确认人、日期、渠道、意见与证据；不得误建成服装产前样或生产前置门禁。 |
| 匹头样（RC） | 匹头样为按订单条件启用的节点，不是每张面料订单的统一必填项。是否启用由业务人员依客户要求、合同约定与本单实际情况决定并留痕；Separates（西服上衣与裤子分开销售）和常年翻单仅为常见参考场景，绝不作为系统自动判定或硬性必填规则。 |
| 时间约束 | 以面料订单的 Exmill Date 驱动倒计时：船样在出厂日前两周寄送并确认；启用 RC 的订单在出厂日前一周完成确认。若客户/合同另有时限，以该订单的明确要求覆盖，并保留原因与审批/确认记录。 |
| 模型边界 | S/S 与 RC 只属于面料订单的样品/客户确认链，不与服装的开发样、产前样封样、生产放行合并。 |
| 回写目标 | 核心业务流程、用户画像与业务线详情、订单与生产模型组、订单类型分层、订单详情页、面料订单状态机与提醒规则。 |

### DR-013 全局业务门禁的受控例外推进

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |
| 原则 | 所有业务状态、质量、客户确认、审批等门禁均默认不可直接绕过；系统不得以隐藏开关、直接改状态或临时脚本规避规则。 |
| 例外申请 | 确需在未满足门禁时继续推进，业务员须提交例外推进申请，至少说明拟越过的门禁、原因、风险、受影响对象和补救/跟进责任人。 |
| 批准 | 仅具备更高业务审批权限的领导可批准例外；负责人团队的销售主管或总领导按组织授权决定。批准后系统只对指定订单、指定动作和指定时点开放推进权限。 |
| 审计与恢复 | 必须记录申请人、批准人、时间、理由、被越过的规则、原始状态与后续结果；例外不改变原规则，也不自动复制到其他订单。未获批准时保持原门禁。 |
| 回写目标 | 审批与 human-in-the-loop、订单状态机、面料订单状态机、QC、采购、出运、订单详情页、审计日志与权限矩阵。 |

### DR-014 面料大货 QC 与客户样品确认并行

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |
| 并行关系 | 面料大货最终 QC 与船样（S/S）、以及按需启用的匹头样（RC）寄送/客户确认并行推进；QC 通过不是 S/S 或 RC 寄送的前置条件，样品确认也不是 QC 的前置条件。 |

### DR-015 出运计划、订舱、放行与实际出运分离

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |
| 独立对象 | 面料和服装订单均须关联独立的出运计划/订舱记录，至少记录计划 ETD、承运/货代、运输方式、订舱信息、关键截点、计划/实际时间与关联单证。计划记录不等于实际出运。 |
| 订舱时机与批准 | 商业订单获批后，业务员可提前创建并提交订舱申请；订单所属团队的销售主管或总领导批准后，才可向货代确认订舱并锁定计划 ETD。订舱不等待 QC、S/S、RC 或生产放行完成。 |
| 放行边界 | QC、样品客户确认和领导“允许出运”控制的是是否允许将货物交运/实际出运，不反向阻断已获批准的订舱计划。关键门禁临近 ETD 未完成时必须预警；硬性推进走 DR-013 的受控例外。 |
| 放行批准 | 订舱批准与“允许出运”必须为两个独立审批动作；已锁定 ETD 不自动产生出运权限。所有适用的质量、样品/客户确认、单证等门禁完成后，仍须由订单所属团队的销售主管或总领导单独批准允许出运。 |
| ETD 变更 | 订舱确认后的任意 ETD 调整均须由订单所属团队的销售主管或总领导审批，不因“看似不影响合同交期”而免除审批。系统记录原值、新值、原因、影响及审批证据，并向相关样品、QC、单证、客户交期责任人同步。 |
| 实际出运 | 仅在出运门禁完成或受控例外获批后，可把计划转为实际出运；实际 ETD/离港或装运凭证必须独立记录，不能覆盖原计划。 |
| 回写目标 | 出运与报关模块、订单状态机、面料订单状态机、订单详情页、交期与生产规则、订单变更规则、提醒与审批规则。 |

### DR-016 订单与出运支持拆分与合并

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |
| 关系 | 必须支持多对多：一张订单/订单行可拆分到多票出运；一票出运可合并多个订单/订单行。禁止假定“一单一票”。 |
| 分配记录 | 每个订单参与某票出运时，须有独立的出运分配记录，保存来源订单/订单行、计划与实际数量、单位、批次/箱号（如适用）、状态与异常；累计实际出运量不得超过该订单可出运量。 |
| 交易方边界 | 订单保存签约/服务客户；每票出运另行保存收货方/目的工厂、单证收件方、商业发票开票对象与实际付款方。它们可与签约客户不同，也不可被系统强制相等。多个订单合票仍仅在同一业务线、同一签约客户时允许；一张订单也可拆为多票，各票分别形成其实际装箱、商业发票、出运与收款记录。 |
| 通用场景 | 任一面料订单可由一个签约客户下达，并拆成任意数量的出运，分别发往不同的收货工厂/交易方；每票可有独立装箱单、商业发票和实际回款。收货、开票、付款交易方均须是正式关联方记录，并可追溯回原始订单与签约客户。 |
| 建档权限 | 业务员可直接新建收货工厂/关联交易方档案，不需要事前审批；建立时须维护与签约客户及本次业务角色的关系，后续出运、发票和回款必须引用档案而非自由文本。 |
| 门禁与审批 | 订舱、ETD、放行和实际运单凭证按“每票出运”管理；每票均独立经过订舱批准与允许出运批准。QC、S/S、已启用 RC、客户确认与订单可用数量按每个来源订单分配逐项核验。合票不得以某一订单已放行掩盖另一订单未满足门禁。 |
| 状态回写 | 订单只在全部应出数量完成相应履约后才进入完整出运/履约完成；部分出运必须可见剩余数量、后续出运计划和分批履约状态。 |
| 业务线隔离 | 出运合并只允许发生在同一业务线内。面料订单与服装订单不得合并为同一票出运，也不得共用订舱、出运放行、QC/样品门禁或单证主档。 |
| 回写目标 | 出运与报关模型组、实体关系总览、Shipment/ShipmentLine 模型、出运编辑器、装箱明细、订单详情页、订单状态机与履约报表。 |

### DR-019 商业发票与回款支持多对多核销

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |
| 关系 | 一张商业发票可由多笔回款分次核销；一笔回款也可按金额分配核销多张商业发票。 |
| 核销记录 | 每次分配须独立保存回款、商业发票、已核销金额、币种/汇率（如适用）、日期、操作人、备注及差异处理；发票与回款均实时保留未核销余额。 |
| 手工匹配与差异 | 业务员可对每笔回款手动勾选并确认其对应的一张或多张商业发票/出运票。实际回款金额无需与发票金额完全相等；允许少收、多收或因样品费、手续费等形成差额。系统必须保留已分配金额、未分配金额和发票剩余金额，并将差额作为独立可说明、可继续处理的余额，而非静默抹平或拒绝登记。 |
| 追溯 | 商业发票仍可追溯其对应的具体出运票与订单分配；回款不因合并或拆分而失去原始付款方、付款凭证和核销去向。禁止以单一“已收/未收”字段替代分配账。 |
| 回写目标 | 应收与回款模型、商业发票、收款核销规则、财务模块、订单/出运详情页、经营报表。 |

### DR-020 回款事实由财务录入，业务员完成核销

|---|---|
| 状态 | 已确认 |
| 到账录入 | 公司账户出现新的银行入账后，由财务录入该笔到账事实及相关银行信息/凭证；业务员不得自行虚构或替代财务登记实际到账。 |

| 职责边界 | 财务确认“钱已实际进入公司账户”；业务员确认“这笔钱对应哪一笔/哪些业务”。二者均保留操作人与时间，形成可审计的到账—匹配链。 |
| 回写目标 | 应收与回款模型、财务收款登记、业务员待办/通知、商业发票详情、核销规则与审计日志。 |

### DR-021 回款按客户/品牌/区域归属路由

|---|---|

### DR-022 回款核销差额采用可配置 allowance 与主管确认

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |

| 回写目标 | 应收与回款规则、财务收款登记、业务员核销界面、主管审批、规则配置与审计日志。 |

### DR-024 客户账户余额与实际付款方分离

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |
| 账户归属 | 每个签约客户拥有独立 account balance，统一反映该客户的应收欠额、预付款、已核销金额与余额。即使实际付款由关联工厂或其他付款方完成，账务归属仍记入对应签约客户账户。 |
| 付款方留痕 | 每笔到账须同时保留实际付款方；付款方是资金来源和对账线索，不自动成为该笔订单/发票的客户账户归属。 |

| 可追溯 | 任一账户余额均须可追溯至原始订单、商业发票、出运票、实际付款方、到账凭证和分配记录；不得以汇总余额掩盖明细来源。 |
| 回写目标 | 客户/关联方账户模型、应收与回款模型、财务收款登记、商业发票、客户详情页、经营报表。 |

### DR-026 面料订单前的开发样客户确认

| 项 | 决策 |
|---|---|

### DR-028 面料投产后的早期生产样与客户反馈

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |
| 投产规则 | 面料客户订单经商业批准后即投产。真实的大货质量无法仅凭手织样确认，系统不得把“开发样待确认”设计为面料投产门禁。 |
| 早期生产样 | 投产后，最早可获得、能够代表实际生产质量的面料样品应尽快寄送客户确认。系统以通用“投产后早期样品”管理，暂不把不稳定的行业叫法写死。 |
| 反馈闭环 | 客户对早期生产样不确认或提出问题时，业务员登记意见与证据并反馈 QC；QC 向工厂提出染整、后整理、成品检验、修布等调整要求；工厂提供新样品；业务员寄送客户并登记确认结果。客户通过则该轮闭环，不通过则业务员将新反馈再次交给 QC，循环继续。系统必须支持不限轮次的该闭环，以尽早使后续大货符合客户需求。 |
| 正常责任流 | 面料样品链中的系统记录由业务员全程登记，包括样品、寄送、客户反馈与每轮结果；QC 负责专业判断并向工厂反馈调整要求；工厂负责按要求调整并提供新样品。正常技术调整不设“调整幅度”硬阈值，也不增加不必要的主管审批门槛。 |
| 生产连续性 | 正常的样品反馈与 QC 调整不自动暂停面料大货生产；订单保持投产/生产中状态。只有重大事故才进入已批准订单的紧急停产/终止等专门受控流程，不应把正常迭代误做成异常停产。 |
| 关系边界 | 投产后早期样品不等同于出运前 S/S，也不替代可选 RC、最终面料 QC 或出运放行。 |
| 回写目标 | 面料订单状态机、面料开发模块、生产跟进、QC 模块、客户反馈与变更规则、订单详情页。 |

### DR-029 服装与面料样品 QC 的不同责任闭环

| 项 | 决策 |
|---|---|
| 状态 | 已确认 |
| 面料样品链 | 业务员全程登记。客户不通过的意见由业务员交给面料 QC；面料 QC 向工厂提出技术调整；工厂提供新样；业务员寄客户并记录下一轮结果。 |
| 服装样品链 | 工厂每一轮产前样直接交给服装 QC；服装 QC 评审并直接在系统填写内部评审意见。多数情况下，QC 将样品与评审意见交给业务员，由业务员决定是否寄客户并登记客户意见；内部评审意见不应被压缩成机械的“通过/不通过”二值。 |
| 服装不通过闭环 | 客户不通过时，业务员直接向工厂业务/跟单反馈修改意见；工厂出下一轮样品后，必须再次先交服装 QC 评审并录入系统，之后才可再次寄客户。客户通过则该轮完成。 |
| QC 直接打回 | 对明显无法通过、寄客户也无意义的批次，服装 QC 在提交评审意见时可选择“直接打回工厂重做”。该批不得寄客户，系统向工厂责任方生成重做要求并记录 QC 意见；同时必须通知业务员，并使其可见打回原因与后续进度。工厂提交新批后，必须重新进入 QC 评审。该能力是 QC 的明确评审结论，不是绕过流程的隐藏状态修改。 |
| 强制边界 | 两条链均可多轮循环，但参与角色、数据录入人和工厂沟通路径不同。系统必须为服装与面料使用不同的状态机、任务路由和权限校验，禁止用统一样品流程硬兼容。 |
| 回写目标 | 开发模块、服装订单状态机、面料订单状态机、QC 模块、样品数据模型、订单详情页、角色与权限矩阵。 |

### DR-030 单据体系以 PI 为常规接单起点

| 项 | 决策 |
|---|---|

### DR-047 Shipment↔Batch 双状态机挂钩：Shipment→Shipped 自动推进挂接批次（W-B 契约表断层④）

| 状态 | 已确认（2026-08-27，W-B 收尾拍板，实现 `5e46d93`） |
| 联动方向 | 单向：Shipment→Shipped 自动推进 `OrderShipmentBatch` planned→shipped；反向不联动（批次不发运运单）。物理事实优先——运单既已发运，批次状态必须同步，否则催款分级/四单对账读批次永远滞后（货发了款没催）。 |

| 尾款门禁语义 | 末批收款门禁（FINAL_PAYMENT_GATE_BLOCKED）的保护点在「发运前」：人工 mark-shipped 与出运放行门禁（DR-012/014）。物理发运既成事实后不再阻断状态同步，缺口以 skipGate+autoLinkage 双标记写入审计，由催款 watchdog（listOverdueFinalBatches）兜底追款。 |

### DR-055 订单确认至生产跟单、最终放行的业务分层（2026-10-11）

| 项 | 决策 |
|---|---|
| 状态 | 用户本轮口述确认；记录业务目标，不代表当前功能全部实现 |
| 主单与客户交易 | 新增订单时录入主单贸易条款及各条目产品、参数、数量等；保存客户 PO 文件，没有客户 PO 文件时据订单制作相应 PO 文件。主单由具有审批职责的负责人、部门负责人或老板确认，批准后生成销售合同 SC。这一段归属主单，不按每条目重复审批或生成整单 SC。 |
| 客户与工厂约定分离 | 客户的贸易/付款条件属于销售约定；工厂的价格、付款条件、采购/加工合同、工厂承诺交期属于履约约定。工厂交期与向客户承诺的交期分别记录。产品与约定卡侧重客户产品约定，供应商/工厂履约信息进入跟单侧；客户付款条款在概览还是产品卡展示尚未锁定，不能因展示位置改变归属。 |
| 工厂下单与排产 | 对每条目向实际工厂下达订单确认通知，取得工厂接单/生产安排确认；在此阶段落实采购、代加工或自组织原料等履约方式、工厂合同和付款条件、工厂交期、生产批次及质量跟踪负责人。区分下单、工厂接单、确认排产和实际开工，不能由一项状态推断其余事实。具体字段在哪一步必填、合同/通知的签发顺序及对外发送机制仍待细化。 |
| 面料生产与先锋样 | 面料下单后直接进入大货生产，不等先锋样确认才开工。先锋样指投产后取自实际大货的早期生产样，用于内部评审、客户确认及尽早调整质量；确认支持继续推进已有大货生产，而非首次开工许可。生产事实与样品评审/客户确认状态分别记录、并行呈现。正常样品反馈不自动暂停整单生产，延续 DR-028。 |
| 服装生产前置 | 服装下单后须先完成产前样确认，再确认开始大货生产；不能套用面料先投产的逻辑。本轮不重定义既有产前样具体签核、封存和生产放行权限。 |
| 样品办理闭环 | 收到实样并登记完整事实 → 发起内部 QC 评审 → 记录评审结果 → 寄送客户并记录确认。需修改时保留意见、证据和历轮记录，工厂调整后接续新轮；不能覆盖旧轮，也不能用旧轮通过替代当前轮结论。这是本轮提出的常规办理顺序；是否对各面料样品强制“QC 通过才可寄送”尚未单独裁决，不擅自新增硬门禁。 |
| 生产中质量跟踪 | 指定负责条目/生产范围质量跟踪的 QC；生产中的检验汇报、意见和阻塞汇总到跟单卡。样品意见与正式生产质量异常分别记录；不合格、整改、复验及业务恢复分别留痕，不能把复验通过直接显示为已恢复。 |
| 最终放行与出运边界 | 临近出运完成船样、面料按约定所需的匹头样/其他最终样品评审和客户确认，以及最终大货质量检查；所需条件通过才结束本段跟单并进入出运。不是所有样品都统一必需；RC 继续按单启用。实际数量、允差、分批约定及适用收款/信用证等出运条件仍须核验；“跟单完成”不等于已装运。 |
| 交互与审美 | 默认卡片以极简、国际主义网格呈现工厂、关键生产数据、当前样品轮次/结果、质量状态及下一步。完整办理按需进入，完成后回摘要，随时可重开全部信息和证据。采购是轻量入口；业务员在相应步骤发起 QC，不在概览常驻专业 QC 工作台入口。 |
| 实现差异待核定 | 当前出运交接对新面料行要求 EPS + SS（RC 选配），并逐批次要求必需样品 QC 通过和需求方确认。既有 DR-014/027 的标准出运描述与此并不完全相同；本轮未裁决 EPS 是否应作为独立硬性出运门禁，不把现行代码反写为用户已确认规则。主单批准自动生成 SC、工厂通知/合同及接单排产闭环也须逐项核验，不凭本记录宣称实现。 |
