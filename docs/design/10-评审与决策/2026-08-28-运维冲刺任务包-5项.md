## 任务 1：迁移账本补账（P0）

**问题**：六张表（FabricProfile/DevelopmentCase/Invoice/PaymentVoucher/Shipment/MaterialReturn）从未被任何迁移 CREATE，部署时 migrate deploy 会报 duplicate column。

**修法**：
1. 给 `MaterialReturn.stockItemId` 补一个带 `IF NOT EXISTS` 的外科迁移：
   - 新建 `server/prisma/migrations/20260828000000_material_return_stock_item_id/migration.sql`
   - 内容：`ALTER TABLE "MaterialReturn" ADD COLUMN IF NOT EXISTS "stockItemId" TEXT;`
2. 把 `20260827143911_supplier_inquiry_and_sample_card_stock/migration.sql` 及所有裸 `ADD COLUMN` 迁移改写为幂等（每条 `ADD COLUMN` 前加 `IF NOT EXISTS`）
3. 写一个补账脚本 `server/scripts/fix-migration-ledger.ts`：
   - 列出所有已生效但未记账的迁移
   - 对每个执行 `npx prisma migrate resolve --applied <目录名>`
   - 输出补账报告

**验收**：在本地用生产库副本跑 `npx prisma migrate deploy`，无 duplicate column 错误

## 任务 3：定时备份 + 恢复演练（P0）

**问题**：没有定时备份，3 年数据导进来后误部署就全丢。

**修法**：
1. 新建 launchd plist `server/scripts/com.bambook.postgres-backup.plist`：
   - 每天凌晨 2 点跑 `server/scripts/backup-postgres.sh`
   - 保留最近 7 天的备份
   - 备份路径 `/Users/Shared/BambookBackups`
2. 修改 `server/scripts/backup-postgres.sh`：
   - 加备份文件命名规则（`bambook-YYYYMMDD-HHmmss.dump`）
   - 加自动清理逻辑（删除 7 天前的备份）
   - 加备份成功/失败日志
3. 写恢复演练文档 `docs/design/08-集成与边界/备份恢复演练.md`：
   - 恢复步骤（pg_restore）
   - 演练清单（至少跑一次完整恢复）

**验收**：launchd 定时任务存在，备份脚本可手动跑通，恢复演练文档就绪

## 任务 4：弱口令治理 + 登录防爆破（P0）

**问题**：默认密码 `bambook2026` 硬编码，登录接口无防爆破，公网谁都能猜。

**修法**：
1. 修改 `server/scripts/seed-rbac.ts`：
   - 默认密码改成随机生成（`crypto.randomBytes(16).toString('hex')`）
   - 打印到 console（部署后首次登录用）
   - 或者：改成必须从环境变量读 `BAMBOOK_INITIAL_ADMIN_PASSWORD`
2. 修改 `server/src/auth/route.ts` `/login` 端点：
   - 加 IP+账号双维速率限制（如 5 次/15 分钟）
   - 用 `express-rate-limit` 或自实现
   - 超过限制返回 429
3. 修改"重置密码"逻辑：
   - 重置密码目标值改成随机一次性密码（不是 `bambook2026`）
   - 强制首登改密

**验收**：默认密码不再是 `bambook2026`，登录接口有防爆破，重置密码不制造弱口令
