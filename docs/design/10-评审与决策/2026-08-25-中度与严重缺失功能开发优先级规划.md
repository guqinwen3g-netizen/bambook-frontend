# 中度与严重缺失功能开发优先级规划

> **生成依据**：`2026-Q3-季度公司运营全景验证剧本.md` 附录 B.10 六轮深度核实结论（2026-08-25，累计 25 个 search subagent 实地核实，20 项结论六轮一致、稳定态）。
> **规划范围**：9 个中度缺失 + 4 个严重缺失，共 13 项功能。3 个"软件未实现"项（库存呆滞盘点 / 客户预付款定金 / 客户索赔退货）不在本表范围，留在待决策台账单独决策。
> **业务背景**：面料 + 服装外贸公司，按单生产（make-to-order）为主，多币种结算（USD/EUR 为主），客户分布于欧美。

---

## 一、评估框架

三项维度综合评分：

| 维度 | 评估口径 |
|---|---|
| **业务价值** | 高 = 外贸日常高频痛点 / 资金风险敞口大 / 行业铁律规则；中 = 中频但有明确场景；低 = 低频或依赖特定业务结构 |
| **实现成本** | S = 既有基础好，纯增量字段+规则；M = 需新模型但链路短；L = 新模型+多模块联动；XL = 跨域流程再造 |
| **依赖关系** | 是否阻塞其他项 / 是否被其他项阻塞 |

**排序原则**：业务价值 × 实现成本性价比优先；有硬前置依赖的项严格排在依赖项之后；触发条件未满足的项沉底按需决策。

## 四、逐项详细规划

### P0-1 订单分批出运与尾款结算（缺口 12 · 严重缺失）

**业务场景**：一张大货订单按船期/验货节奏分 2~4 批出运（如首批 60% + 末批 40%），每批对应部分发票与部分收款，尾款须在末批出运前后结清。当前系统只能整单维度管理出运，无法表达"批次履约进度 → 批次钱流"的对应关系。

**现状基础（六轮核实）**：
- 已有：发票↔订单多对多分配（`InvoiceOrderAllocation`）、发票↔收款核销（`InvoiceAllocation` + voucher 状态机 `unreconciled/partially_reconciled/reconciled`）、出运统计（`shipmentStatsService`）、出运资格门（`shipmentEligibilityGate`）
- 缺失：`partialSettlement/partSettle` 业务代码零命中；schema 无 `OrderShipment` 模型；无批次级核销字段

**建设方案**：
1. **数据模型**：`model OrderShipmentBatch`（orderId / shipmentId / batchNo / plannedQty / plannedRatio / actualQty / amount / currency / settleStatus）+ `schema.prisma` 索引
2. **服务层**：`orderShipmentService` —— 批次登记（挂出运单创建时写批次）、批次进度聚合（已出/未出比例）、尾款计算（订单额 − 已核销额，按批次视图拆分）
3. **规则门禁**：`shipmentEligibilityGate` 扩展——末批发运前校验收款进度（如 ≥ 预付款+进度款阈值，阈值按客户信用等级）；尾款到期 watchdog（末批出运 N 天后未结清 → 升级催款，联动 P0-2）
4. **前端**：OrderManager 订单详情新增「出运批次」区（批次进度条 + 各批次发票/收款对应关系）；FinanceManager 发票↔订单分配视图加批次维度
5. **测试**：批次状态机 + 尾款门禁 + 部分核销回归

**验收要点**：订单录 2 批计划 → 首批出运开部分发票收部分款 → 末批发运触发尾款结算提醒 → 订单履约进度 100% 且资金 100% 核销。

**依赖与风险**：是 P2-6 四单对账的硬前置；存量单据批次数据需迁移策略（默认整单一批）。

### P0-2 催款分级状态机（缺口 15 · 中度缺失）

**业务场景**：逾期账款按账龄分级推进——提醒（d1-30）→ 催款（d31-60）→ 严催（d61-90）→ 法务准备（d90+），每级对应不同催款函模板、升级动作与责任人。

**现状基础**：
- 已有：`DunningRecord` 模型完整（渠道/结果/账龄五桶快照/操作人）、催款函生成（`dunningService.ts L143 buildLetter` 中英双语）、`recordDunning/listDunning`、账龄 `bucketOf` 五桶
- 缺失：`dunningStage/dunningLevel/催款分级` 全库零命中，channel/result 为平铺枚举无阶段递进语义

**建设方案**：
1. **数据模型**：`DunningRecord` 加 `stage` 字段（`reminder/firm/urgent/legal`）+ 客户维度升级时间戳；或独立 `DunningProfile`（客户级催款策略）
2. **状态机**：账龄自动定级（复用五桶 bucketOf 映射）+ 手动升级/降级（留痕）；升级动作绑定分级催款函模板（buildLetter 加 stage 参数）
3. **watchdog**：复用 `crmFollowUpWatchdog` 调度模式新建 `dunningStageWatchdog`——每日扫描逾期发票，跨级自动升级 + 通知责任人（经 riskService.raiseAlert 或通知通道）
4. **前端**：FinanceManager 催款 Tab 加分级看板（按 stage 分列）+ 升级按钮 + 分级模板预览

**验收要点**：d30 客户自动进入 reminder → 登记催款记录 → 模拟 d60 自动升级 firm 并通知业务员 → 分级看板正确归列。

**依赖与风险**：成本 S 性价比最高；尾款到期（P0-1）可直接喂给本状态机，建议两批同框架设计。

### P1-3 客户专属面料规则（缺口 18 · 中度缺失）

**业务场景**：客户 A 出资开发的独家面料（owner fabric），不得用于客户 B 的报价/订单/样品——面料外贸行业铁律，违反即商业事故。

**现状基础**：
- 已有：`FabricCustomerCode`（types.ts L579-588）产品↔客户编码映射
- 缺失：`ownerFabric/独家供应/exclusiveSupply/不得转售` 全库零命中

**建设方案**：
1. **数据模型**：`FabricCustomerCode` 加 `isExclusive Boolean` + `exclusiveOwnerRelationId`（或独立 `OwnerFabricGrant` 表记录授权范围/有效期/违约条款）
2. **校验规则**（核心）：下单/报价/样品登记/出运四个入口的产品行校验——若面料为某客户专属且当前单据客户 ≠ 属主 → fail-closed 阻断（可配为警示放行+审批）
3. **前端**：ProductsManager 档案详情展示专属标记（属主客户+授权范围）；OrderManager/QuotationManager 行级警示
4. **留痕**：违规尝试写入审计日志

**验收要点**：面料 X 标记为客户 A 专属 → 客户 B 订单选 X 被阻断 → A 的订单正常通过 → 档案详情可见专属标识。

**依赖与风险**：成本 S；校验点需覆盖全部四个入口（漏一个即规则失效），需源码契约测试锁住。

### P1-4 物料退换货（缺口 2 · 中度缺失）

**业务场景**：来料质检发现色差/克重不符/破洞 → 向供应商退回、要求换货或索赔扣款。

**现状基础**：
- 已有：`MaterialReceiptInput`（totalRejected/rejectionReason/qualityNotes）来料质检记录、库存变动 6 类（含 Outbound）
- 缺失：退货/换货/索赔动作字段全缺

**建设方案**：
1. **数据模型**：`model MaterialReturn`（receiptId / supplierRelationId / type: `return|exchange|claim` / qty / amount / currency / status: `pending→shipped→confirmed→settled` / 索赔关联采购单）
2. **服务层**：`materialReturnService` —— 登记退换货（联动库存 Outbound 冲减在库次品）、换货到货回冲、索赔确认生成应付调整（联动采购单金额冲减或独立索赔应收）
3. **前端**：ProcurementManager 来料质检 Tab 加「退换货/索赔」动作 + 退换货列表
4. **联动**：供应商绩效评估计入退换率（联动既有交期/质量分体系）

**验收要点**：来料 500 米检出不符 100 米 → 登记退货（库存扣减）→ 供应商确认 → 索赔 200 USD 挂应付冲减 → 供应商绩效更新。

### P1-5 工厂延期处理链（缺口 3 · 中度缺失）

**业务场景**：工厂延期已登记影响（在）→ 业务决策三选一：加急（赶工+可能加急费）/ 换厂（转移生产）/ 索赔（按合同扣款）。

**现状基础**：
- 已有：`registerDelay` + `factoryDelayRecord`（影响快照/受影响订单/缓冲侵蚀分级）+ 交期分联动（DR-052-③）完整
- 缺失：加急/索赔/换厂仅"建议文案"，无动作链

**建设方案**：
1. **数据模型**：`FactoryDelayRecord` 加 `response` 嵌套（type: `expedite|switch_factory|claim` / 成本 / 新工厂 / 状态）或独立 `DelayResponse` 模型
2. **动作链**：
   - 加急：登记加急费 + 新交期承诺 + 二次延期升级告警
   - 换厂：关联新 factory + 受影响采购单/工序链 supplier 字段迁移 + 新厂产能占用检查（联动 P3-10）
   - 索赔：索赔金额登记 + 应付冲减联动（与 P1-4 索赔同一应付调整机制）
3. **前端**：SuppliersManager 延期记录详情加响应动作按钮簇

**验收要点**：登记延期 → 选加急（登记费用+新交期）→ 二次延期触发升级告警；或换厂（采购单工厂字段迁移成功）。

### P2-6 客户四单对账（缺口 10 · 中度缺失）· **硬依赖 P0-1**

**业务场景**：月度/季度对账——订单金额 ↔ 出运金额 ↔ 开票金额 ↔ 收款金额四单自动勾稽，差异（数量差/金额差/汇差）自动识别并生成差异处理任务。

**现状基础**：
- 已有：发票↔收款两单核销（allocationService）、客户/供应商对账单静态报表（getCustomerStatement/getSupplierStatement）、账龄五桶、催款闭环（P0-2 后为分级）
- 缺失：四单自动对账引擎零命中

**建设方案**：
1. **服务层**：`reconciliationService` —— 按客户+币种+周期四表联查（Order / Shipment 批次(P0-1) / Invoice / PaymentVoucher），输出四方差异矩阵
2. **差异引擎**：差异类型分类（未出运已开票 / 已出运未开票 / 已开票未收款 / 金额不匹配 / 币种折算差），生成差异任务（处理动作：调账/挂账/追款联动催款）
3. **前端**：FinanceManager 新增「对账工作台」Tab——客户选择 → 四单对照表 + 差异清单 + 一键生成对账单（升级现有静态报表）
4. **周期化**：月度对账任务 watchdog（复用调度框架）

**验收要点**：造一单四流不一致数据（少开票 500）→ 对账工作台识别"已出运未开票 500"差异 → 生成任务 → 处理后差异清零。

### P2-7 多币种应收应付对账规则（缺口 13 · 中度缺失）

**业务场景**：USD 订单按开票日汇率入账、收款日汇率折算，差额入汇兑损益——规则需显式化并可按客户对账。

**现状基础**：
- 已有：汇率三件套（`ExchangeRate` 档案 / `FxRateLock` 大额锁汇 / `FxGainLossReport` 汇兑损益报表）+ 开票/收付款日 exchangeRate 快照字段
- 缺失：多币种对账规则显式服务零命中

**建设方案**：
1. **规则配置**：折算规则显式化（开票日汇率 vs 收款日汇率 vs 月末汇率，可配置口径）+ 锁汇单优先规则（FxRateLock 命中时用锁定汇率）
2. **报表**：多币种应收应付对账表（客户 × 币种 × 本位币三栏对照，差额自动标注汇兑损益去向），并入 P2-6 对账工作台的币种维度
3. **联动**：与 FxGainLossReport 口径统一（消除报表间口径分裂）

**验收要点**：USD 发票开票日汇率 7.20、收款日 7.25 → 对账表本位币差额 0.05/USD 正确标注为汇兑收益 → 与 FxGainLossReport 合计一致。

### P2-8 运输保险货损理赔（缺口 19 · 中度缺失）

**业务场景**：海运货损 → 向保险公司报案 → 提交理赔（保单+提单+损失证明）→ 赔付到账或拒赔。

**现状基础**：
- 已有：投保侧完整（Shipment `insuranceAmount/insuranceCurrency`、利润表 CIF 保险费、保险单 INS 单据模板 customsDocs L648、documentSet premium 注入）
- 缺失：理赔侧（cargoClaim/货损理赔/lossReport）零命中

**建设方案**：
1. **数据模型**：`model CargoClaim`（shipmentId / policyNo / incidentDate / 损失描述 / claimAmount / currency / status: `reported→submitted→under_review→settled|rejected` / 赔付金额 / 凭证附件）
2. **服务层**：`cargoClaimService` —— 报案登记、理赔提交、赔付入账（保险赔付收入凭证，联动 FinanceManager）、拒赔留痕
3. **前端**：ShipmentManager 出运详情加「货损理赔」入口 + 理赔列表 Tab（FinanceManager 侧可见赔付到账）
4. **联动**：理赔中出运单标记风险状态；利润表重算（赔付冲减损失）

**验收要点**：出运单发起货损报案 3000 USD → 提交理赔 → 赔付 2500 到账生成凭证 → 出运单利润表联动重算。

### P3-9 MRP 物料需求计划（缺口 1 · 严重缺失）

**业务场景**：多张订单合并 → BOM 展开毛需求 → 扣库存+在途采购 → 净需求 → 生成采购建议 → 一键转采购单。

**现状基础**：
- 已有：BOM 损耗计算（calcEffectiveQty）+ 成本汇总 + 采购单关联 BOM + 库存体系
- 缺失：mrpService / 订单展开入口 / 需求 vs 库存对比全无

**建设方案**（建议分两期）：
1. **一期（需求可视化）**：`mrpService.explode`（订单集合 → BOM 展开毛需求，含损耗）+ 净需求计算（扣可用库存+在途采购单）+ MRP 建议清单页（只读，供业务员人工决策）
2. **二期（一键采购）**：建议清单勾选 → 生成采购单草稿（复用 SupplierInquiry 询价比价链路）+ 采购单→需求回销（采购到货冲减净需求）
3. **前端**：OrderManager/BomManager「MRP 运算」入口 + MRP 清单独立 Tab

**依赖与风险**：依赖库存数据准确（建议先跑通盘点流程）；XL 规模建议一期先行验证价值。

### P3-10 工厂产能预定（缺口 17 · 中度缺失）

**业务场景**：大货下单前向工厂预定月度产能 slot，冲突时协调或外协分流。

**现状基础**：
- 已有：capacity 四函数（upsert/delete/aggregateOccupied/list）+ 产能日历可视化（被动占用=已有采购单聚合）
- 缺失：capacityBooking / 冲突协调 / 自动外协分流零命中

**建设方案**：
1. **数据模型**：`model CapacityBooking`（factoryId / month / orderId / qty / status: `pending→confirmed→consumed→released`）
2. **冲突检测**：booked（已确认预定）+ occupied（在手采购）vs capacity 月度上限 → 超限预警
3. **分流建议**：超产能时提示外协候选（联动 MES `OutsourcingOrder` 人工创建确认，不做全自动）
4. **前端**：SuppliersManager 产能日历加预定层（计划产能/已预定/已占用三色），OrderManager 下单时可发起产能预定

**依赖与风险**：与 P1-5 换厂动作联动（换厂需查新厂产能余量）。

### P3-11 季节性备货与现货销售（缺口 16 · 中度缺失）

**业务场景**：趋势面料提前备货 → 现货快速销售（快报价/快订单）→ 季末备货 vs 销售复盘。

**现状基础**：
- 已有：Season（季度档案+日历+回顾）/ TrendTag / TrendTagFabric 数据底座 + 产能体系
- 缺失：seasonalStock/spotSale/备货计划零命中

**建设方案**：
1. **数据模型**：`model SeasonStockPlan`（seasonId / productAssetId / 计划量 / 预算 / 实际备货量）+ 库存现货标记（InventoryItem 加 `spotSellable`）
2. **现货销售流**：快速报价 → 现货订单（跳过生产链路，直接出运）模板
3. **复盘**：季末自动生成备货 vs 销售差异报告（挂 SeasonReview）
4. **前置确认**：现货销售业务模式（是否真实存在）需用户先确认，避免为建而建

### P4-12 银行融资押汇（缺口 11 · 严重缺失）· **条件触发**

**触发条件**：L/C 结算业务占比达到一定规模（如 >30% 订单）时启动；当前 L/C 基础流程（开证→交单→承兑→结清）已够用。

**建设方案（触发后）**：
1. L/C 状态机扩展：+ `Financing / Discounted / Forfaited` 融资节点（LcEvent 追加融资事件类型）
2. `lcFinanceService`：押汇申请（银行+押汇金额+利率+期限）→ 银行扣息到账（收款凭证联动）→ 融资成本入账（财务费用）
3. 前端：CustomsManager L/C 详情加融资动作 + 融资台账

---

### P4-13 海外代理佣金支付（缺口 14 · 严重缺失）· **条件触发**

**触发条件**：存在海外代理（intermediary）成交结构时启动。

**建设方案（触发后）**：
1. **数据模型**：`model CommissionPayment`（commissionRuleId / orderId / 计提金额 / status: `accrued→requested→approved→paid`）
2. **流程**：订单出运/收款触发计提（按 CommissionRule 费率）→ 佣金申请 → 审批 → 支付（付款凭证联动）→ 台账
3. **前端**：PricingManager 佣金 Tab 从规则管理升级为规则+支付台账双视图

## 五、通用工程纪律（每项必守）

1. **实现模式**：schema.prisma 建模 → server service（`$transaction` + `writeRouteAuditLog` + fail-closed 校验）→ route → 前端 service → Manager UI → 源码契约测试（沿用 `SampleRoomPanel.test.tsx` 模式）
2. **三绿门禁**：前后端 tsc 零错误 + `check:tokens` 通过 + 前后端测试全绿 + `electron-vite build` 通过
3. **设计系统**：BDS v2.2 语义类，禁硬编码 rounded/hex/shadow；表单控件 BDS 化（bds-select / CapsuleDateInput）
4. **图谱联动**：每完成一项，更新剧本文档附录 B 对应缺口等级（缺失 → 完整实现），并注明实现位置
5. **种子数据**：每项完成后同步 `seed-demo-data-v2.ts` 演示数据，保证实机验收可用
6. **状态机优先**：所有新流程先定义状态机（状态枚举 + 合法迁移 + 终态），fail-closed 门禁先行
