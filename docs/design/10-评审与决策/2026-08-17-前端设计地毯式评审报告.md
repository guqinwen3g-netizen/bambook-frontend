# Bambook 前端设计地毯式评审报告（2026-08-17）

> **定位**：本文档是对 Bambook 前端实现的专业 UI/UX 设计评审，评审基准为 BDS v2.2 设计系统（`styles/bds/tokens.css` 18 章 token + `components.css` 22 族组件 + `docs/design-system/component-application-spec.md` 应用规范）与专业设计行业的最高交付水准。
>
> **评审纪律**：不以"基本可用"为通过线。任何偏离设计系统真源、破坏全局统一性、降低视觉品质上限的实现，无论功能是否正常，均记为不通过项。评审目标是**高分产品**，不是**及格产品**。
>
> **评审方法**：代码级全量扫描（components/ 全目录 grep 矩阵：圆角/色值/字重/阴影/材质/遮罩/语义色/主题分支）+ 逐页结构核查 + BDS 真源比对。所有结论附文件与行号证据，可追溯、可复核。
>
> **与审计报告的关系**：本文档是前端视觉/交互/一致性的专项评审，与 `.trae/documents/bambook-comprehensive-project-scan.md`（全维度技术审计）互补；发现的违规不回写代码，修复须另行立项执行。

## 二、分项评审

### 2.1 材质与色彩系统（5.5/10）❌

**BDS 真源要求**：玻璃面（`--bg-card` + blur/saturate，仅 modal/浮层壳）与冷墨洗（`--recessed-bg`，嵌套/次级信息区）双层材质模型；静态面零阴影零边框；中性实色块禁止出现在内容区（暖灰 #EAEDEE 与冷蓝青主题色同时对比会产生暖米色差——历史根因已定位并修复过一批）。

**评审发现**：

| # | 违规 | 证据 | 严重度 |

### 2.3 圆角与几何语言（9.0/10）⚠️

**BDS 真源要求**：11 档同心层级刻度（微件→控件→嵌套→卡片→浮层），生成规则 inner = outer − padding；禁止 tsx 硬编码 `rounded-[Npx]`。

**评审发现**：

**已确认合规**：`rounded-[inherit]` 属合规继承写法；34 个测试用例已锁定核心页面圆角断言；守卫脚本拦截新增硬编码。

**BDS 真源要求**：按钮统一走 `bds-btn` 族类（primary/secondary/ghost/danger）；主操作收进 PageHeader actions；行内动作降 secondary。

### 2.5 布局与页面骨架（9.0/10）✅

**已确认合规**：fullBleed 白名单已补齐 Pricing/Marketing，主区域无双层容器嵌套；内容区 padding 统一 `px-7`；PageHeader 标题间距 `px-7 pt-5 pb-4` 全局一致；面包屑右侧、标题左上的布局纪律已贯彻。

**扣分项**：App.tsx 的 isFullBleedView 为枚举字符串拼接（长链 `||`），新增页面需手动登记，属于易腐化的手工名单机制，建议后续收敛为路由元数据驱动。

### 2.6 主题架构（4.5/10）❌ —— 最大失分项

**BDS 真源要求**：主题透明——组件不感知深浅色，由 token 自适应层统一接管；目标零 `dark:` 分支、零 `isDarkMode` 条件渲染。

**评审发现**：

| # | 违规 | 规模 | 严重度 |
|---|------|------|--------|
| TH1 | `dark:` Tailwind 变体残留 | **256 处 / 39 文件**。重灾区：KnowledgeBase.tsx（80 处）、ProductsManager.tsx（46 处）、AdminPanel.tsx（8 处）、DataCenter.tsx（7 处）、ToggleSwitch.tsx（6 处）、ContactList.tsx（7 处）、OrgChart.tsx（9 处）、AgentFormBlock.tsx（6 处） | 极高——每处 `dark:` 都是主题透明架构的破口；两处色调需人工双写，深浅色必然漂移 |
| TH2 | `isDarkMode` 三目条件类名 | 少量残留（UserAvatar、ToggleSwitch 等） | 中 |

**评审意见**：这是"高分产品"与"及格产品"的分水岭。256 处双写意味着任何一次色彩调整都需要改两遍，且 `dark:bg-deep/40`、`dark:bg-black/20`、`dark:text-red-300` 这类散点写法没有统一色温控制——浅色下修好的冷墨洗，深色下可能又是另一种观感。必须建立 token 化收编批次（按文件分批，每批三绿验证）。

**评审发现**：

| S2 | raw 语义色 ~60 处：`text-red-400/500`（危险）、`text-emerald-400/600`（成功）、`text-blue-400`（进行态）、`bg-red-50 border-red-200`（错误横幅）、`bg-blue-400/8`（信息底） | FinanceReportsPanel（red/emerald ×15）、KnowledgeBase.tsx（red/emerald ×10）、WorkflowPanel.tsx（blue/emerald/red ×10）、DataCenter.tsx、EmailManager.tsx、SampleNodesPanel.tsx、DocumentCenter.tsx:458、SignatureManager.tsx:130 | 高——同一"危险"语义在系统里呈现为 red-400/red-500/rose-500 三种色，未走 `--danger-text` |

| S4 | `bg-red-50/bg-red-500/10` 错误横幅双写法 | DataCenter.tsx:129、KnowledgeBase.tsx:487/555 | 中——应统一为 `--danger-tint` + `--danger-text` |

## 四、高分验收标准（修复完成的判定线）

1. **零暖色**：全 grep 无 `amber|orange|yellow|warm` 命中（豁免清单除外）。
2. **唯一遮罩**：全 grep 无 `bg-black/` 命中，全部 `--mask-bg`。
3. **语义色 token 化**：无 `text-(red|emerald|blue|rose|sky|cyan|teal|violet|pink|indigo|green)-[0-9]` 命中；语义呈现 100% 走 BDS token。
4. **主题透明**：`dark:` 命中数从 256 收敛至 ≤10（仅允许 token 层无法覆盖的极少数视觉特例，且需注释说明）。
5. **几何纯净**：无裸 `rounded`、无 `rounded-[Npx]` 硬编码（`rounded-[inherit]` 除外）。
6. **字重单一**：无 `font-medium|semibold|bold|black` 命中。
7. **按钮组件化**：主按钮 100% `bds-btn-primary`，accent 填充上的文字 100% `--on-accent`。
8. **材质分层正确**：嵌套层 0 处 `--bg-card` 直用（modal 壳除外）。
9. **三绿**：`npx tsc --noEmit --skipLibCheck` 零错误 + `npm run check:tokens` 通过 + `npm test` 全绿。
10. **视觉复核**：30 页全量截图走查，深浅双主题无色温断裂、无实色补丁、无规格漂移。

**当前状态对照**：1-8 项均不满足；满足全部 10 项后方可宣布前端达高分验收线。

## 五、Compiled 前端架构专项评审

> 本节针对 `components/ui/osCompiler/` 编译式前端架构的去留问题出具专项评审结论。评审方法：源码级核查 osCompiler.ts 核心机制、App.tsx 运行时路径、moduleRegistry 登记与 compiled 模板实现的真实关系。

### 5.1 架构现状核查（证据链）

| 核查项 | 事实 | 证据 |
|--------|------|------|
| 编译器本质 | `compileBambookPage()` 仅输出描述性蓝图对象（12 个视觉系统的 className/约束声明），**不产生任何代码**；compiled 模板是手写 React 组件，蓝图与实现之间无代码生成器 | osCompiler.ts:338-514 |
| 运行时机制 | 仅 boolean 开关二选一：`compilerSurfaces.xxx ? <CompiledXxxPage/> : <XxxManager/>`，无 slot 注入灵活性 | App.tsx:351/1507/1546/1553/1733 |
| 覆盖面 | 仅 4 页走 compiled（Dashboard/Relations/Products/Settings，均 accepted）；其余 ~26 页只有 Manager 单路径 | moduleRegistry.ts:299-360/671 |
| 模板与 Manager 关系 | compiled 模板大量复用 Manager 导出的视觉常量（`RELATIONS_CATEGORY_CARD_CLASS` 等），本质是 Manager 的重排版副本，业务逻辑同源 | compiledRelationsTemplates.tsx:18-24 |
| fidelity gates | 蓝图声明 `no-page-local-visual-values`、`forbiddenEscapeHatches` 等约束，但无强制机制——本评审发现的 256 处 `dark:` 分支与材质违规大量存在于 compiled 模板中 | osCompiler.ts:35-49/507-511 |

### 5.2 评审结论：虚假抽象层

当前 compiled 架构的设计意图（蓝图驱动页面、代码生成、结构化防回退）与实际形态（手写组件 + boolean 开关）存在根本落差，造成三类真实伤害：

1. **双路径同步负担**：每次设计升级须同步维护 compiled 模板与 Manager 两份实现，漏改即双页漂移。
2. **分工冲突风险源**：同一页面的改动可能在 compiled 与 Manager 两端产生 diff，与团队分工纪律直接冲突。
3. **约束层空转**：蓝图中的防回退约束无人执行，不如转为 jest 断言直接检查 Manager 源码。

BDS v2.2（tokens.css + components.css + Tailwind 语义类 + 守卫脚本）已提供足够统一性，osCompiler 作为"第二套统一层"属冗余抽象。

### 5.3 决策：方案 C —— 保留蓝图约束层，废弃运行时双路径

| 项 | 内容 |
|---|---|
| 决策 | **废弃 compiled 运行时双路径，全部页面统一走 Manager 单路径**；`osCompiler.ts` 降级保留为设计约束描述语言（文档真源 + 测试断言依据），不删除其规范价值 |
