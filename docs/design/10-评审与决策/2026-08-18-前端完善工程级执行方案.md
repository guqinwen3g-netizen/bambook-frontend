## 3. 工程级执行框架

### 3.1 每页重建五步流程（固定流水线，禁止跳步）
```
① 审计   对照 L1-L8 + M1-M5 + 高分验收 1-9，产出该页违例清单（引用台账行号/守卫计数）
② 重建   用规范原语重新组合；业务逻辑同源迁移不重写；禁止引入新违规、禁止特例补丁
③ 三绿   npx tsc --noEmit --skipLibCheck（0 错）+ npm run check:tokens（通过）+ npm test（全绿）
④ 截图   深浅双主题各一张，六区规格对照（标题/筛选/操作/表单/内容/弹层）
⑤ 销号   更新台账验收状态 + 守卫基线回写（只减不增）+ 独立 commit（wave(fe): W-PG-Px-页面名）
```

### 3.2 每页规格化动作清单（九项检查单，全过才算销号）
| # | 动作 | 规范源 | 机器断言 |
|---|---|---|---|
| A1 | 补/核 PageHeader（中英标题 + 右侧 breadcrumb） | page-skeleton §1 + L1 | M1 |
| A2 | filterbar 高度净化（删 `h-auto min-h-11` 等手写撑高） | page-skeleton §2 + L4 | M3 |
| A3 | 原生控件 BDS 化（select→bds-select、date→CapsuleDateInput） | page-skeleton §4 | M4 |
| A4 | 主按钮组件化（bds-btn-primary）、toggle 冷墨洗 | page-skeleton §3 + L8 | M2/M5 + 高分 7 |
| A5 | 布局原语组合（L1 页壳 / L2 间距刻度 / L3 容器尺寸 / L5 表格密度） | 布局构建语言 | L2/L3/L5 |
| A6 | icon 尺寸/笔画体系（size 14/16/18/20/24，strokeWidth 1.3/1） | 布局构建语言 §6 | L6 |

### 3.3 守卫基线回写规则
- 每页销号时，将该页对应的违例计数从基线下调（只减不增）；回写必须在同一 commit 内完成并注释原因。
- 任何**新增**违例计数 > 基线 = 守卫报错 = 该页不得销号。
- 白名单（M2/M5）必须带 `// bds-sm-ok:` / `// bds-dark-ok:` 注释，仅限表格行内操作，spec §3.1/3.2。

## 4. 波次排期与多 subagent 分工

### 4.1 两阶段模型
- **阶段 A（共享层先行，串行）**：先把 8 组共同引用的**共享组件族**（组 8 的 ui/ + tools/ + import/ + agent-response/）规格化稳定。理由：8 组并行时都只读引用共享组件，若共享组件未稳定会引发多写者冲突（历史教训：同文件并发回写丢修改）。
- **阶段 B（8 组并行放量）**：共享层稳定后，8 个 subagent 按组并行，每组 1 个 subagent，逐页走五步流水线。
- **阶段 C（终审）**：全量截图 + 高分验收 10 条机器复核 + 台账 30/30 销号。

### 4.2 波次计划
| 波次 | 内容 | subagent | 出口标准 |
|---|---|---|---|
| **P2-W0 共享层** | C1-C6 + ui/ 共享组件（UserAvatar 尺寸族 / tools 手写按钮组件化 / DetailPanel+CapsuleDateInput 字重 / 原语内联背景统一）+ 壳层（Sidebar/NotificationCenter/CommandPalette/Login/Register） | S0 共享层 + S0b 壳层（2 个并行） | 共享组件三绿稳定；壳层销号；守卫基线回写 |
| **P2-W1 组 1+2** | 订单履约域 + 财务定价关务报表域 | S1 + S2 | 组内页全销号 + 三绿 |
| **P2-W2 组 3+4** | 采购库存生产域 + 关系 CRM 域 | S3 + S4 | 同上 |
| **P2-W3 组 5+6** | 产品开发质检域 + 设置 HR 邮件域 | S5 + S6 | 同上（ProductsManager 为 L3 重灾区，优先级最高） |
| **P2-W4 组 7+8** | 壳层助手域（余量）+ 工具共享域（余量 + agent-response） | S7 + S8 | 同上 |
| **P2-W5 终审** | 全量深浅双主题截图 + 高分验收 10 条机器复核 + 台账 30/30 | 总控 + 视觉复核 subagent | 终审结论文档 |

> 每波次 subagent 并行上限 = 2（阶段 B 每波 2 组）；若要最大化并行可按 4 组/波次（4 个 subagent），但**同一波次内不得有 2 个 subagent 触碰同一文件**（组边界已隔离，共享组件已在 P2-W0 稳定）。

### 4.3 分工边界（单写者规则，沿用协同纪律）
| 资源 | 归属 |
|---|---|
| `components/**`（按组划分） | 对应组 subagent 排他写 |
| `App.tsx` | 冻结（Phase 0 已收口；本方案不新增路由）；任何改动需总控审批 |
| `scripts/check-design-tokens.sh` + 基线 | 总控排他写（subagent 报告计数，总控回写基线） |
| `styles/bds/layout.css` / `components/ui/primitives/` | 总控排他写（原语只增不改，需求进原语由总控落地） |
| `docs/design/**` | 总控排他写（subagent 只读引用） |
| `package.json` / lockfile | 全员冻结；新增依赖申报总控单点执行 |

### 4.4 并行纪律
- worktree 隔离：每个组 subagent 在独立 worktree 开工（`git worktree add ../bambook-p2-groupN -b wave/p2-gN`），物理杜绝并发回写冲突。
- 每页一个 commit（`wave(fe): W-PG-Px-页面名`），禁止跨页混合提交。
- 合并窗口：每波次末总控统一 rebase + 合并 + 全量三绿；波次内各 subagent 不得自行合 main。

## 6. 风险与护栏

| 风险 | 护栏 |
|---|---|
| 直接重写重现漂移 | 规范先行（Phase 1 硬前置完成），重建只允许原语组合，守卫机器判分 |
| 大范围改动破坏业务逻辑 | 每页独立 commit + 三绿门禁 + 截图走查；业务逻辑同源迁移不重写 |
| 多 subagent 并发冲突 | 共享层先稳定（P2-W0）+ 组边界隔离 + worktree 物理隔离 + 单写者规则 |
| 特例补丁破坏一致性 | 禁止为单页/单组件写特例；需求进原语，否则登记不落地（用户红线） |
| 守卫基线被刷大 | 基线只减不增，回写须总控注释原因；新增即报错 |
| 原生控件/M4 清零引发功能回归 | 每页 BDS 化后跑该页相关测试 + 交互走查 |
| 工期拉长 | 波次化放量，可随时停点验收；每波次 ≤4 组并行 |
