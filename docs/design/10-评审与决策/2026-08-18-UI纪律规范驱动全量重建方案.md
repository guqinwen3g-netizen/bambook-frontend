# Bambook UI 纪律：规范驱动全量重建方案（2026-08-18）

> 定位：达成"最严苛、最统一" UI 纪律的长期执行真源。本文件为总控/产品负责人审阅与拍板对象，经确认后进入执行。
> 前置依据：`2026-08-17-前端设计地毯式评审报告.md`（6.4/10，高分验收 10 条全不满足）、`2026-08-17-多会话协同推进纪律.md`（分工/波次/门禁）。

## 0. 决策记录

| 决策 | 选项 | 状态 |
|---|---|---|
| 推进路线 | 规范驱动全量重建（先建构建语言，再逐页重建，杜绝自由手写漂移） | ✅ 用户拍板 2026-08-18 |
| 架构收口 | 同步执行评审方案 C：废弃 compiled 运行时双路径，全部页面统一 Manager 单路径 | ✅ 用户拍板 2026-08-18 |

## 1. 目标与总验收线

**目标**：30+ 视图 / 全部组件达到高分验收线（≥9.0），统一由**机器可强制**的守卫约束长期防回退，不再依赖人肉自觉。

**总验收线（复用评审 §4 并扩展布局维度）**：
1. 零暖色（豁免清单除外）
2. 唯一遮罩（无 `bg-black/` 直用）
3. 语义色 100% token 化
4. 主题透明（`dark:` ≤10 且注释豁免）
5. 几何纯净（无裸 rounded / 硬编码圆角）
6. 字重单一（全局 ≤300，仅徽章/数字特例）
7. 按钮组件化（主按钮 100% `bds-btn-primary`，accent 上文字 100% `--on-accent`）
8. 材质分层正确（嵌套层 0 处 `--bg-card` 直用）
9. **布局原语合规（新增）**：页面骨架/间距刻度/容器比例/工具栏/表格密度/icon 尺寸/空态错误态全部走规范原语，禁裸 `px-*`/`gap-*`/`h-[Npx]`/`aspect-*` 手写（守卫可判分）
10. 三绿（tsc / check:tokens / npm test）+ 30 页深浅双主题截图走查

## 2. 现状与根因（证据）

| 事实 | 证据 |
|---|---|
| 前端体量 | components/ 100 文件、387 个导出组件、~32 主视图（含子视图） |
| token/组件层已就位 | `styles/bds/tokens.css`（v2.2）+ `components.css`（bds-btn/input/card/stat/icon 等）+ Tailwind 语义类 |
| 负面守卫已就位 | `scripts/check-design-tokens.sh` 基线模式（hex/圆角/阴影/语义色/字重/按钮/材质/原生控件/页面规格 M1-M5） |
| **布局层完全缺失** | 无页面骨架、间距刻度、容器尺寸/长宽比、工具栏组合、表格密度、空态/错误态的规范原语；每页手写 Tailwind 布局类 |
| 评审结论 | 2026-08-17：6.4/10，"规范已建立、收编未完成"，330+ 未收编缺口；组件应用 6.5 / 主题架构 4.5 / 语义色彩 4.0；高分验收 10 条全不满足 |
| compiled 双路径 | 评审 §5 判定为"虚假抽象层"（蓝图不产代码、仅 boolean 开关、双路径维护漂移）；方案 C 已裁定废弃 |

**根因（一句话）**：现有纪律是"负面守卫"——只禁止"坏值"（禁硬编码 hex/圆角），但**没有任何正面规范约束"页面该怎么组"**。颜色/圆角/材质被 token 收敛了，布局/间距/比例/结构全靠每页自由手写，所以观感必然漂移。这就是"圆角材质配色都对，但整体还是乱"的本质。

**结论**：直接全量重写不能解决根因（重写仍是自由手写，写完继续漂移）。必须**先建立"页面构建语言"，再以它驱动逐页重建**。

## 3. 三阶段路线

### Phase 0 — 架构收口（废弃 compiled 双路径）

执行评审 §5.3 方案 C，消除双实现漂移这一结构性风险源。

| 步骤 | 内容 | 验收 |
|---|---|---|
| 0.1 | 4 页 compiled 模板（Dashboard/Relations/Products/Settings）与 Manager 逐页比对，优于 Manager 的实现（如 `CompiledTableShell`/`CompiledMotionInteractiveCard`/Relations surface 组织）**单向回收**进 Manager 或提级为公共 UI 组件 | 4 页视觉回归无差异 |
| 0.2 | App.tsx 删除 `compilerSurfaces` 开关、`CompiledXxxPage` 渲染分支、`CompiledMainModuleSlot` 包裹器 | grep 无 `compilerSurfaces` 命中；App.test.ts 断言同步更新 |
| 0.3 | 删除 4 个 compiled 页面模板文件；`osCompiler.ts` 保留为规范文件，`forbiddenEscapeHatches`/fidelity gates 转 jest 断言 | 约束断言进测试套件 |
| 0.4 | 4 页深浅双主题截图走查 + 三绿 + 净瘦身确认 | 三绿 + 走查签字 |

> 纪律：本阶段触及 App.tsx 主渲染链与 4 个核心页，**单独立项执行**，不与批 A-J 机械修复并行（评审 §5.5）。

### Phase 1 — 补全页面构建语言（BDS layout layer）

在 BDS v2.2 之上新增"布局层"，每个原语 = 规范定义 + bds 类/组件 + 守卫断言（可机器判分）。

| # | 布局原语 | 覆盖内容 | 守卫断言 |
|---|---|---|---|
| L1 | 页面骨架 PageShell | PageHeader + 内容画布 + 底边距，统一 inset 刻度（页级/面板级/控件级） | 每页必须含 PageHeader/bds-pagehead；页内 padding 走刻度 |
| L2 | 间距刻度 space-scale | 唯一刻度 4/6/8/12/16/20/24/32/40/48；禁裸 `px-*`/`gap-*`/`space-*` 手写 | 扫描裸间距类，超基线即报 |
| L3 | 容器与长宽比 | 标准卡片尺寸族 + 宽高比族 + 嵌套层级（外大内小圆角） | 禁裸 `aspect-*`/`h-[Npx]`/`max-h-*` 手写 |
| L4 | 工具栏组合 ToolbarPattern | 搜索+筛选+动作统一组合规则（沿用 filterbar 选型规则）；行高 34/40 | filterbar 高度已守卫（M3），扩展到全页工具栏 |
| L5 | 表格密度 TableDensity | 行高/字号/内边距/分隔线统一；表格视图走 CompiledTableShell 提级后的公共组件 | 禁裸表格行高类 |
| L6 | icon 尺寸体系 | 14/16/18/20/24 + strokeWidth 1.3 纪律；按钮/行内/卡片图标分级 | 扫描 icon size/strokeWidth 硬编码 |
| L7 | 空态/错误态/加载态 | EmptyState / ErrorBanner / Skeleton 组件化（评审 I4：错误提示三形态并存需收敛） | 禁裸 `text-red-400` / `bg-red-50 border` 形态 |
| L8 | 视觉反馈 | hover/active/选中统一 token（列表高亮、toggle active 冷墨洗等既有决策固化） | 扫 hover 暖色类 |

**交付物**：
- `docs/design/06-组件规格/` 新增"布局构建语言"规格文档（真源）
- `styles/bds/layout.css`（新 bds 布局类）+ `components/ui/` 新增原语组件
- `scripts/check-design-tokens.sh` 扩展 L1-L8 断言（高分验收 10 条全部可机器判分）
- 布局 showcase 页（BDS 规范要求的完备 showcase 延展到布局层）

**验收**：守卫脚本可对任意页面机器判分（0 违例）；showcase 深浅双主题预览通过；三绿。

### Phase 2 — 逐页规范驱动重建（30 页）

重建 = **用规范原语重新组合**，禁止自由手写布局。每页一套固定流程：

```
审计（对照 L1-L8 + 高分验收 10 条，产出违例清单）
  → 按规范重建（原语组合，不引入新违规）
  → 三绿（tsc + check:tokens + npm test）
  → 深浅双主题截图走查（六区规格对照）
  → 台账销号（每页一个 commit：wave(fe): W-PG-Px-页面名）
```

**页面清单与分组**（32 视图，含子视图，按既有四页优先策略延续）：

| 波次 | 页面 | 备注 |
|---|---|---|
| 首批（四页，延续 W-PG） | Relations / OrderManager / QuotationManager / DocumentCenter | 已完成规格化基线，直接进入重建销号 |
| 批 H/G 在途 | 沿用多会话协同纪律的批 H/G 收编项 | 先完成既有批次再纳入 |
| 放量（26 页） | Cockpit / Dashboard / Assistant / Products(+settings) / Orders(fabric/garment/other) / ProductionBoard / Procurement / Inventory / BOM / CRM / Suppliers / Seasons / Risks / QcWorkbench(3) / Pricing(5) / Marketing(2) / MES / Customs / Invoices / PaymentVouchers / Reports / Shipments / Development / Emails / DataCenter / Settings(account/system) / BusinessTools / AdminPanel / HR(4) | 四页主刀通过校准后放量 |

**门禁**：四页全部销号且总控/产品负责人校准通过后，才放量其余 26 页；每页独立 commit；不跨分工边界改文件（App.tsx 冻结至 W5 规则延续）。

### Phase 3 — 终审

- 30+ 页全量截图（深浅双主题）+ 高分验收 10 条机器复核
- 台账 30/30 销号 = 完工；出具终审结论文档

## 4. 验收与门禁（贯穿全程）

1. **三绿**：`npx tsc --noEmit --skipLibCheck` 零错误 + `npm run check:tokens` 通过 + `npm test` 全绿
2. **布局判分**：新增 L1-L8 断言可对任意页面机器判分，页面 0 违例
3. **截图走查**：每页深浅双主题，无色温断裂/实色补丁/规格漂移
4. **台账**：逐页销号，30/30 完工
5. **防回退**：守卫基线只减不增；任何新增页面必须从规范原语起步

## 5. 风险与护栏

| 风险 | 护栏 |
|---|---|
| 直接重写重现漂移 | 规范先行（Phase 1 是硬前置），重建只允许原语组合 |
| compiled 双路径继续漂移 | Phase 0 先行收口，单独立项不并行 |
| 大范围改动破坏业务逻辑 | 每页独立 commit + 三绿门禁 + 截图走查；业务逻辑同源迁移不重写 |
| App.tsx/check 脚本/package.json 多写者冲突 | 沿用多会话协同纪律：单写者 + 分工矩阵 |
| 特例补丁破坏一致性 | 禁止为单页/单组件写特例；需求进原语，否则登记不落地 |
| 工期拉长 | 波次化放量：四页校准 → 26 页按批推进，可随时停点验收 |

## 6. 执行顺序（本方案批准后）

1. Phase 0 架构收口（独立立项）
2. Phase 1 构建语言（规格 + 原语 + 守卫 + showcase）
3. Phase 2 四页重建 → 校准 → 放量 26 页
4. Phase 3 终审

> 本方案为"真源"，Phase 0-3 各阶段执行细节、commit 清单、台账在推进过程中实时更新并留档。
