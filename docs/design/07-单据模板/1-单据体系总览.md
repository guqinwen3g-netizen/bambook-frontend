## §3 单据状态机（6 态）

### 3.1 状态定义

后端真源 `TradeDocumentStatus`（`types.ts` L3985）：

| 状态 | 中文 | 语义 | 是否终态 |
|------|------|------|---------|
| `Draft` | 草稿 | 登记初始态；可编辑/删除 | 否 |
| `Issued` | 已签发 | 正式签发；锁定编辑 | 否 |
| `Submitted` | 已提交 | 已提交银行/进口商 | 否 |
| `Accepted` | 已接受 | 银行/进口商接受 | **是** |
| `Rejected` | 已拒绝 | 被拒付/退回 | 否（可退回 Draft） |
| `Cancelled` | 已取消 | 作废 | **是** |

### 3.2 合法推进矩阵

前端镜像 `DOC_TRANSITIONS`（`DocumentCenter.tsx` L86-L93，与后端 fail-closed 一致）：

| 当前状态 | 可推进到 | 说明 |
|---------|---------|------|
| Draft | Issued / Cancelled | 草稿可签发或作废 |
| Issued | Submitted / Cancelled | 签发后可提交或作废 |
| Submitted | Accepted / Rejected / Cancelled | 提交后等待接受/拒绝 |
| Accepted | — | 终态 |
| Rejected | Draft | 拒绝后可退回草稿修改 |
| Cancelled | — | 终态 |

```
Draft ──▶ Issued ──▶ Submitted ──▶ Accepted ✓
  │         │           │
  │         │           └──▶ Rejected ──▶ Draft (退回修改)
  │         │
  └─────────┴──────────▶ Cancelled ✓
```

**设计原则**：前端镜像仅做按钮可行动性提示，**唯一状态真源是后端**（`customsService.transitionTradeDocumentStatus` 事务内校验）。

## §4 文档生命周期（版本留痕）

### 4.1 DocumentVersion 模型

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | `DVER_{ts}_{random}` |
| documentId | String | FK → TradeDocument（snapshot） |
| version | Int | 按 documentId 单调递增（1 起，`@@unique([documentId, version])`） |
| content | Json | 变更后整行字段快照 |
| changeReason | String? | 变更原因 |
| changedBy | String? | 修改人 |
| createdAt | BigInt | epoch ms |

### 4.2 版本号生成规则

`appendTradeDocumentVersion`（事务内）：
1. 查询 `documentVersion.findFirst({ where: { documentId }, orderBy: { version: 'desc' } })`
2. `nextVersion = (last?.version ?? 0) + 1`
3. 写入 `documentVersion.create` + `auditLog.create`

**防并发跳号**：版本号在事务内 max+1 计算，不依赖客户端传入，保证单调递增。

### 4.3 留痕触发点

| 触发场景 | 版本 content | changeReason |
|---------|-------------|-------------|
| 运单生成（`generateTradeDocumentsFromShipment`） | `{ documentSet: DocumentSetData }` | "运单生成" |
| 手工创建单据 | TradeDocument 行字段快照 | "创建" |
| 更新单据（`updateTradeDocument`） | 变更后字段快照 | 客户端传入 `changeReason` |
| 手动追加版本（`POST /:id/versions`） | 客户端传入 content | 客户端传入 |

**设计原则**：服务端强制留痕（根因式），不依赖客户端自觉——创建/更新单据的服务必须在同一事务内调用 `appendTradeDocumentVersion`。

## §5 模板与版本双轨模型

### 5.1 DocumentTemplate（模板轨）

| 维度 | 说明 |
|------|------|
| 定位 | 可复用的 HTML 模板，支持 `{{variable}}` 占位符 |
| 语言 | `zh` / `en` / `bilingual`（三选一） |
| 默认唯一性 | 同 `type + language` 下仅一个 `isDefault=true`（事务内 `applyDefaultUniqueness` 清除其他） |
| 变量解析 | `extractTemplateVariables(content)` 自动解析 `{{varName}}`，冗余存储到 `variables: String[]` |
| 软删 | `deletedAt BigInt?`；版本不留 `deletedAt`（随主单软删隐藏） |
| 审计 | 创建/更新/删除均写 `AuditLog`（`DOCUMENT_TEMPLATE_CREATE/UPDATE/DELETE`） |

### 5.2 TradeDocument + DocumentVersion（实例轨）

| 维度 | 说明 |
|------|------|
| 定位 | 实际业务单据实例（一张发票对应一行 TradeDocument） |
| 编号 | 自动取号 `{PREFIX}-{YYYY}-{NNNN}`（作废不回收） |
| 状态 | 6 态状态机（Draft→Issued→Submitted→Accepted/Rejected/Cancelled） |
| 版本 | 每次变更写 DocumentVersion 快照（只增不删） |
| 关联 | shipmentId / declarationId / orderId / relationId（snapshot FK，均可空） |
| 附件 | filePath / fileName（可选，已上传文件路径） |

### 5.3 双轨关系

```
DocumentTemplate（模板）          TradeDocument（实例）
  │ type/language/content           │ type/status/documentNumber
  │ variables[]                     │ shipmentId/orderId/relationId
  │ isDefault（同类型唯一）          │ totalAmount/currency
  │                                 │
  └────── 模板用于 ──────▶ 生成 ◀───── 运单装配数据（DocumentSetData）
                                    │
                                    └──▶ DocumentVersion（版本快照）
                                          │ content: { documentSet: ... }
                                          │ version: 1, 2, 3...
```

模板用于手工制单时的变量填写参考；运单生成时直接装配 DocumentSetData，不经过模板。

## §6 自动取号规则

### 6.1 编号格式

`{PREFIX}-{YYYY}-{NNNN}`

| 组成 | 说明 | 示例 |
|------|------|------|
| PREFIX | 类型前缀（见 §2.1） | `CI` / `PL` / `BL` |
| YYYY | 当前年份 | `2026` |
| NNNN | 年内序号（4 位补零，超 4 位自然扩展） | `0001` / `0042` / `12345` |

### 6.2 序号生成逻辑

`generateTradeDocumentNumber`（`tradeDocumentLifecycleService.ts` L50-L72）：

```
1. 生产环境（有 businessSequence 模型）：
   → nextBusinessNumber(db, prefix)  // 统一编号服务，原子递增

2. 降级（mock/单元测试/无 businessSequence）：
   a. stem = `${prefix}-${year}-`
   b. 查询所有 documentNumber.startsWith(stem) 的记录（含软删）
   c. 解析序号取 max（字符串排序在 >4 位不可靠，故取数值 max）
   d. return `${stem}${String(maxSeq + 1).padStart(4, '0')}`
```

**作废不回收**：序号扫描含软删记录（`deletedAt != null`），作废的编号不回收，保留审计痕迹。

### 6.3 手工创建取号

`POST /api/v1/customs/trade-documents` 时 `documentNumber` 留空 → 服务端自动取号；传入则用自定义编号（需唯一）。

## §7 装配数据源（DocumentSetData）

### 7.1 装配服务

`assembleDocumentSetData(prisma, shipmentId)` → `DocumentSetResult`（`documentSetService.ts` L198+）

### 7.2 数据结构

| 区块 | 字段 | 来源 |
|------|------|------|
| `shipment` | 运单核心（船名/航次/港口/柜号/封号/重量/体积） | Shipment 表 |
| `order` | 订单（PO 号/合同号/发票号/贸易条款/付款条款） | Order 表（经 shipment.orderId） |
| `customs` | 报关单（报关号/报关港/贸易条款/原产国/目的国/收发货人） | CustomsDeclaration 表 |
| `parties.customer` | 客户/买方（CI Buyer） | Relation 表（shipment.customerRelationId） |
| `parties.consignee` | 收货方（BL/CO Consignee） | Relation 表（order.consigneeRelationId） |
| `parties.carrier` | 承运人/货代 | Relation 表（shipment.carrierRelationId） |
| `lines` | 货物明细行 | ShipmentLine / OrderLine / CustomsDeclarationLine 合并 |
| `totals` | 汇总（数量/金额/箱数/毛净重/体积/币种） | lines 聚合计算 |
| `missing` | 数据完整度提示（不阻断） | 装配时检测缺失字段 |
| `extras.originCriterion` | Form A 第 8 栏原产地标准（默认 `P`） | 常量 |
| `extras.insurance` | 投保信息（保额/保费/险别/保险人） | shipment + 推断 |
| `extras.letterOfCredit` | 关联信用证摘要 | LetterOfCredit 表（经 orderId） |

### 7.3 数据合并优先级

`lines` 合并策略（`first()` 辅助函数取第一个非空值）：
- `description`：ShipmentLine → OrderLine → CustomsDeclarationLine
- `quantity` / `unitPrice` / `amount`：OrderLine（价格真源）
- `cartons` / `grossWeight` / `netWeight` / `volume`：ShipmentLine（装箱真源）
- `hsCode` / `originCountry`：CustomsDeclarationLine（报关真源）

### 7.4 完整度提示

`missing: string[]` 列出装配时检测到的缺失字段（如 "缺少 consignee 收货人"、"缺少 vessel 船名"），供 UI 展示提醒，**不阻断生成**。

## §9 前端渲染管线

### 9.1 渲染流程

```
TradeDocument（含 latestVersion.content）
  │
  ├─ 有 documentSet 快照？
  │   ├─ 是 → extractDocumentSet(content) → DocumentSetData
  │   │       → TYPE_TO_EXPORT_KIND[type] → ExportDocKind
  │   │       → EXPORT_DOC_RENDERERS[kind].render(ds) → HTML body
  │   │       → printHtmlDocument({ title, htmlBody }) → 独立打印窗口 → PDF
  │   │
  │   └─ 否 → 降级字段视图（不伪造预览）
```

### 9.2 关键函数

| 函数 | 位置 | 职责 |
|------|------|------|
| `extractDocumentSet(content)` | DocumentCenter.tsx | 从版本快照提取 `{ documentSet: DocumentSetData }` |
| `EXPORT_DOC_RENDERERS[kind].render(ds)` | exportDocumentTemplates.ts | 纯函数渲染器，`DocumentSetData → HTML` |
| `printHtmlDocument({ title, htmlBody })` | printDocument.ts | 独立窗口打印（BASE_PRINT_STYLES 样式） |
| `getExporterProfile()` | exporterProfile.ts | 读取出口方档案（SystemConfig → 默认值） |

### 9.3 出口方档案

`ExporterProfile` 从 `localStorage['panda_system_config'].exporterProfile` 读取，合并默认值：
- `nameEn` / `addressEn`：公司英文抬头
- `beneficiary`：受益人名
- `bankName` / `swiftCode` / `bankAddress` / `usdAccountNumber`：银行信息

## §10 批量生成与打包

### 10.1 运单批量生成（`generateTradeDocumentsFromShipment`）

```
输入：{ shipmentId, types: TradeDocumentType[], actorId }
  │
  ├─ assembleDocumentSetData(shipmentId) → DocumentSetData
  │   └─ 失败 → throw（运单数据装配失败）
  │
  ├─ 解析 relationId（经 order.customerRelationId）
  │
  └─ for each type in types:
      ├─ 查询已存在（shipmentId + type + deletedAt=null）
      │   └─ 已存在 → skipped.push({ reason: 'EXISTS' })
      │
      └─ 事务内：
          a. generateTradeDocumentNumber(tx, type) → 自动取号
          b. tradeDocument.create（status=Draft, issueDate=今天, 装配数据填充）
          c. appendTradeDocumentVersion（v1 快照 = { documentSet: data }）
          d. auditLog.create（TRADE_DOCUMENT_CREATE）
          → created.push({ id, documentNumber, type })
```

**幂等**：同 `shipmentId + type` 已存在则跳过（skipped），不重复登记。

### 10.2 订单批量打包（`packTradeDocumentsByOrder`）

```
输入：orderId
  │
  ├─ tradeDocument.findMany({ where: { orderId, deletedAt: null } })
  │
  └─ for each doc:
      ├─ documentVersion.findFirst({ orderBy: version desc }) → 最新版本
      └─ 组装 TradeDocumentPackItem（含 latestVersion + content 快照）
```

**用途**：L/C 交单场景——订单全部单据逐份渲染打印。

`createModuleAuthGuard({ requireAuth, apiKeys })`：
- 读操作：JWT 或 API-Key 均可
