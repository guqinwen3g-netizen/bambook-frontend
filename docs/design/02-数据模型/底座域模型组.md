## §39 DR-007 组织归属解析（Department.headId / UserAccount.departmentId）× ApprovalRequest 扩展 数据模型验收

> **决策来源**：[DR-007](../10-评审与决策/2026-08-16-设计评审决策记录.md#dr-007-报价审批权限按组织归属解析)
>
> **模型缺口要求（为 resolveReviewerByDepartment 提供真源字段，当前缺漏）**：
> - `Department` 模型（§10）需新增 `headId String?`（FK UserAccount，部门主管用户 id，null=空缺，对应 DR7-A4 兜底条件）；索引 `@@index([headId])`。
> - `UserAccount` 模型（§4）需保证 `departmentId String?` 已存在并与 Department 关联（若无则补齐，对应申请人归属判定入口）。
> - `ApprovalRequest`（§35）需扩展 6 个字段，以支持 DR-007 全量审计链：
>   1. `reviewerResolverRoute String`（解析路径真源：DEPT_HEAD / FALLBACK_DEPT_HEAD_VACANT / FALLBACK_SELF_APPLY_SUPERVISOR / BOSS_FINAL_BYPASS）——本字段 createOnce 写入。
>   2. `delegatedBy String?`、`delegatedAt DateTime?`、`delegateReason String?`（审批人主动转派 3 字段，DR7-B2 真源）。
>   3. `clientReviewerIdSupplied Boolean @default(false)`（A2 前端是否传 reviewerId，用于审计：true=被忽略或拒绝）。
>   4. `bossFinalBypassBy String?` + `bossFinalBypassAt DateTime?` + `bossFinalBypassReason String @db.Text`（BOSS 最终兜底 3 字段，强制 ≥30 字，DR-041 绝密级老板最终）。
>   5. `bypassedApprovalId String?`（DR-013 例外单绑定被拒的原审批 id，DR7-B4 真源，反向关联到本组 ApprovalRequest.id）。
>   6. `departmentSnapshotId String`（创建审批单时申请人的部门 id 快照，不随后续部门归属变更而改变，组织归属变更的幂等 & 审计基础）。
