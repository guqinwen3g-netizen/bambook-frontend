# 财务域模型组 (Finance Domain Model Group)

> **DR-015 关联**：发货与出运以业务事实为准——货物离开工厂即视为已发货，客户订舱 ≠ 已发货，出运 ≠ 合同履约完成
> **DR-016 关联**：运费与结算分离——费用归属（预付/到付/代垫）与实际结算分离；我方承担运费（预付/代垫）才纳入利润表
> **DR-017 关联**：任何对外付款必须先申请后付款；审批通过前不得创建对外付款凭证
> **DR-018 关联**：收款凭证到账后默认锁定；撤销到账必须审批；同一收款凭证只能核销到一张发票；作废仅隐藏不删除
> **DR-019 关联**：预收款必须先建立收款凭证，后续绑定订单核销；预收款订单核销不改变发票与付款凭证一一对应关系
> **DR-020 关联**：费用按归属对象计入订单、供应商、客户、样品、开发案例或内部运营；报销付款统一走对外付款审批链
> **DR-021 关联**：收付汇必须按真实业务发生记账，不强制收汇与付汇一一对应
> **DR-022 关联**：业务成本、样品快递费、客户报销费用分别核算；快递费默认计入内部运营成本

### 5.5 DR-018 收款凭证锁定与作废规则

| 规则 | 说明 |
|------|------|
| 到账锁定 | 收款凭证到账后默认锁定（lockedAt/lockedBy），撤销到账必须审批 |
| 单一发票核销 | 同一收款凭证只能核销到一张发票（InvoiceAllocation 一对一） |
| 撤销到账 | 到账撤销必须走审批流，审批通过后解除锁定 |
| 作废 | 作废仅隐藏不删除（voidedAt/voidedBy/voidReason），保留审计追溯 |
| 异常提交 | 异常提交的凭证默认不进入核销，可隐藏、可作废，但不删除 |

### 5.6 DR-019 预收款规则

| 规则 | 说明 |
|------|------|
| 预收款建立 | 预收款必须先建立收款凭证（voucherCategory=advance） |
| 绑定订单 | 预收款后续绑定订单核销（advanceOrderId） |
| 核销规则 | 预收款订单核销不改变发票与付款凭证一一对应关系（InvoiceAllocation 仍一对一） |
| 未核销状态 | 预收款未绑定订单前 status=unreconciled，不影响发票核销 |

## §6 InvoiceAllocation 模型（核销明细）

### 6.1 全量字段

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | String | @id | `ALLOC__${shortId}` |
| invoiceId | String | — | 核销的发票 |
| voucherId | String | — | 核销的凭证 |
| appliedAmount | Decimal | @db.Decimal(18,4) | 本笔核销金额 |
| appliedDate | String | — | 核销日期 YYYY-MM-DD |
| createdAt | BigInt | — | 创建时间 |
| updatedAt | BigInt | — | 更新时间 |

### 6.2 约束

```
@@unique([invoiceId, voucherId])  // 一对 invoice-voucher 只能有一条明细
@@index([invoiceId])
@@index([voucherId])
```

> **硬删除（无 deletedAt）**：核销调整时先 delete 旧明细再 insert 新明细，避免软删 + unique 冲突。替代 PaymentVoucher.appliedAmount 的单 1:1 表达（后者保留作为主核销快照，向后兼容）。

> **DR-019 预收款核销**：预收款（voucherCategory=advance）绑定订单后，仍通过 InvoiceAllocation 一对一核销到订单关联的发票，不改变"同一收款凭证只能核销到一张发票"的规则。预收款未绑定订单前不进入 InvoiceAllocation。

## §7 FxSettlement 模型（结汇水单）

### 7.1 全量字段

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | String | @id | `FXS__${shortId}` |
| settlementNumber | String | @unique | 结汇水单号（如 FXS-20260808-001） |
| voucherId | String | — | 关联收款凭证（settlesVoucher linkKind） |
| orderId | String? | — | 冗余关联订单（aboutOrder linkKind） |
| customerRelationId | String? | — | 交易对象（billTo linkKind） |
| settleDate | String | — | 结汇日期 YYYY-MM-DD |
| foreignAmount | Decimal | @db.Decimal(18,4) | 结汇外币金额（≤ 凭证未结汇余额） |
| currency | String | — | 外币币种（与凭证一致；CNY 无结汇语义） |
| fxRate | Decimal | @db.Decimal(18,8) | 结汇汇率（外币 → CNY） |
| cnyAmount | Decimal | @db.Decimal(18,4) | 折合人民币（服务端计算 = foreignAmount × fxRate） |
| bank | String? | — | 结汇银行 |
| slipNumber | String? | — | 银行水单号 |
| notes | String? | — | 备注 |
| createdAt | BigInt | — | 创建时间 |
| updatedAt | BigInt | — | 更新时间 |
| deletedAt | BigInt? | — | 软删时间 |

### 7.2 索引

```
@@index([voucherId]) @@index([orderId])
@@index([customerRelationId]) @@index([settleDate])
```

> **业务语义**：一笔外币收款可分次结汇（1:N），核销余额 = voucher.amount - Σsettlements.foreignAmount。cnyAmount 由服务端计算（防篡改），客户端传入一律拒绝。软删即回滚核销余额（derived 查询，无冗余字段）。
>
> **DR-021 收付汇真实记账**：收汇（FxSettlement）与付汇（OutwardRemittance）必须按真实业务发生记账，不强制一一对应。收汇多付汇少或收汇少付汇多均为正常业务场景，系统不强制平衡校验。

> **镜像 FxSettlement 付款侧**：一笔外币付款可分次付汇（1:N），未付余额 = voucher.amount - Σremittances.foreignAmount。cnyAmount 服务端计算，软删回滚余额。

> **DR-021 收付汇真实记账**：付汇与收汇按真实业务发生记账，不强制一一对应。付汇多收汇少（如预付采购款）或收汇多付汇少（如客户定金大于采购支出）均为正常业务场景。

> **无软删字段**：利润表是聚合投影，`deleteProfitSheet` 是硬删除，重生成即可恢复。orderId @unique 保证幂等（重生成=覆盖更新，version+1）。details JSON 含 sales/purchases/freight/misc/unconverted 五个数组。
>
> **DR-016 运费计算规则**：仅我方承担运费（freightResponsibility = prepaid 预付 / collect 代垫）才纳入 freightCost；到付（freightCollect）不纳入。
>
> **DR-020 费用归属**：miscCost 按归属对象计入——订单相关费用计入订单利润表；供应商/客户/样品/开发案例相关费用分别归集；内部运营费用不进入订单利润表。
>
> **DR-022 成本分开核算（决策点 7-A）**：业务成本（采购+运费+杂费）与样品快递费、客户报销费用分别核算。样品快递费默认计入内部运营成本（不进入订单利润表）；客户报销费用单独归集，不混入订单成本。
>
> **details JSON 字段扩展（决策点 7-A）**：`details.costBreakdown: { type: 'sample_express' | 'customer_reimburse' | 'business_cost' | 'other', voucherId: string, amount: Decimal }[]` 用于利润表维度展示三类费用拆分；voucherId 指向 PaymentVoucher.id（voucherCategory 对应 sample_express / customer_reimburse / business_cost 的凭证快照 FK）。
>
> **三类费用审批路由**：voucherCategory ∈ { sample_express, customer_reimburse, business_cost } 的付款审批统一走 DR-007 组织归属路由（付款申请人所属部门主管；申请人无主管/部门为财务→系统管理员 ADMIN 总领导兜底；单次一位审批人即可）。

## §14 通用约定

### 14.1 金额精度

| 用途 | 类型 | 精度 |
|------|------|------|
| 金额（发票/凭证/水单/利润） | Decimal(18,4) | 4 位小数 |
| 汇率 | Decimal(18,8) | 8 位小数（高精度避免累计误差） |
| 税率/退税率 | Decimal(6,4) | 4 位小数（如 13.0000） |
| 毛利率 | Decimal(8,4) | 4 位小数 |

### 14.2 时间戳

| 类型 | 存储 | 说明 |
|------|------|------|
| epoch ms | BigInt | createdAt / updatedAt / deletedAt |
| 业务日期 | String | YYYY-MM-DD（issueDate / paymentDate / settleDate 等） |
| 业务月份 | String | YYYY-MM（deductionPeriod） |

### 14.3 snapshot FK 模式

财务域所有跨模块关联均为 **snapshot FK**（无 Prisma @relation 强制 FK），通过 EntityLink 图谱同步维护。原因：
- 跨模块解耦（财务域不直接依赖订单/关系域的物理 FK）
- 历史快照不可变（Relation 改名不影响历史发票显示）
- EntityLink 提供反向追溯能力

### 14.4 软删策略

| 模型 | 软删 | 原因 |
|------|------|------|
| Invoice / PaymentVoucher / FxSettlement / OutwardRemittance / VatInvoice / TaxRefund / CommissionRule | ✅ deletedAt | 业务实体，需历史留痕 |
| InvoiceAllocation | ❌（硬删除） | 核销调整=delete+insert，避免软删+unique 冲突 |
| OrderProfitSheet | ❌（硬删除） | 聚合投影，重生成即可恢复 |

### 14.5 DR-016 费用归属与结算分离

| 项 | 规则 |
|---|------|
| 费用归属 | 费用按归属对象计入：订单 / 供应商 / 客户 / 样品 / 开发案例 / 内部运营 |
| 结算分离 | 费用归属 ≠ 实际结算：归属是会计分录，结算是资金流水 |
| 运费归属 | prepaid（预付）= 我方承担 → 纳入利润表；collect（到付）= 客户承担 → 不纳入；代垫 = 我方先付后收 → 纳入利润表 |
| 实际结算 | 以 PaymentVoucher 实际收付为准，不受归属影响 |

### 14.6 DR-020 报销付款统一审批链

| 项 | 规则 |
|---|------|
| 报销类型 | 差旅费 / 招待费 / 办公用品 / 其他运营费用 |
| 付款方式 | 报销付款统一走 PaymentRequest（付款申请）审批链（DR-017） |
| 归属规则 | 报销费用按归属对象计入对应科目（订单/供应商/客户/内部运营） |

### 14.7 DR-021 收付汇真实记账

| 项 | 规则 |
|---|------|
| 记账原则 | 收汇（FxSettlement）与付汇（OutwardRemittance）按真实业务发生记账 |
| 非强制对应 | 不强制收汇与付汇一一对应，不强制平衡校验 |
| 正常场景 | 收汇多付汇少（客户定金大于采购支出）、收汇少付汇多（预付采购款）均为正常业务场景 |

### 14.8 DR-022 成本分开核算

| 成本类型 | 归属 | 是否进入订单利润表 |
|---------|------|------------------|
| 业务成本（采购+运费+杂费） | 订单 | ✅ 进入 |
| 样品快递费 | 内部运营 | ❌ 默认不进入（可配置） |
| 客户报销费用 | 客户 | ❌ 单独归集，不混入订单成本 |
