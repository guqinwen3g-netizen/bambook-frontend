**关系类型说明**：

## §6 ShipmentEvent 模型（物流节点事件）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | String | @id | `SHPE__${shortId}` |
| shipmentId | String | snapshot FK → Shipment | 关联运单 |
| fromNode | String? | — | 上一节点（首节点为 null） |
| toNode | String | — | 到达节点（取值与运单状态一致：Draft/Booked/Loading/Shipped/Arrived/Cleared/Delivered/Cancelled） |

| actorId | String? | — | 操作人 |
| createdAt | BigInt | — | epoch ms |

```
@@index([shipmentId]) @@index([toNode])
```

**设计要点**：append-only，无软删。每次状态机转换在事务内追加一条节点事件，形成可回溯的订舱→装货→发运→到港→清关→交付物流时间轴（独立于通用 auditLog，面向业务查询与前端时间轴渲染）。route 与 agent 两条写路径共用 `appendShipmentEvent` helper，保证时间轴完整性单一来源。

## §8 ShipmentCartonItem 模型（箱内货物分配）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | String | @id | `SHPCI__${shortId}` |
| cartonId | String | FK → ShipmentCarton (Cascade) | 所属箱 |
| shipmentLineId | String | snapshot FK → ShipmentLine | 关联装运行（行删除由服务层清理） |
| quantity | Decimal | @db.Decimal(18, 4) | 该行在此箱中的数量 |
| createdAt | BigInt | — | epoch ms |
| updatedAt | BigInt | — | epoch ms |

```
carton ShipmentCarton @relation(fields: [cartonId], references: [id], onDelete: Cascade)
@@unique([cartonId, shipmentLineId])
@@index([shipmentLineId])
```

**设计要点**：混装支持——同一箱可分配多行货物，同一行可分散到多箱。`@@unique([cartonId, shipmentLineId])` 防止同箱同行重复分配。服务层校验每行累计分配量 ≤ 行数量（行数量为 null 时不校验上限）。

| 验收编号 | 场景描述 | 前置条件 | 执行步骤 | 期望结果 | 失败路径 / 约束 |

## §15C DR-013 受控例外 × 出运 3 条件 + 合并 Shipment 门禁验收

## §15D 出运门禁实现收口（2026-08-19 生产回归验证通过）

> DR-012/014 出运放行门禁 shipping 域接线后的实现口径固化。生产环境（jiangsupanda.com）全链路实测：门禁阻断 → QC 报告录入 → 门禁放行。

### 15D.1 门禁触发时机（shipmentMutationService.ts）

| 写路径 | 触发条件 | 校验范围 |
|---|---|---|
| createShipment | 直建 status=Shipped（补录场景） | 仅主订单（create 时合票分配尚未建立） |
| updateShipment | status → Shipped | 主订单 + 全部 ShipmentOrderAllocation 合票订单（逐单校验） |
| Agent 直建/直改工具 | 同上两口径 | 同上（错误码独立映射，见 15D.3） |

面料订单三条件（大货 QC + S/S 客户确认 + RC 客户确认若启用）；服装订单单条件（大货 Final QC）；判定逻辑单一来源 `shipmentEligibilityGate.ts`。

### 15D.2 服装链判定口径（门禁旁路收敛）

`isGarmentChainOrder`（qcChainService.ts）：`businessLine ∈ {garment, capsule}` **或** `type ∈ {garment, apparel}`。
- type=apparel 为 order_type 字典合法值；修复前仅认 garment，type-only 服装订单被误派 other 链绕过 Final QC（门禁旁路，已收敛）
- MOQ 业务线推导（moqValidationService.ts `deriveBusinessLine`/`isCapsuleEligible`）同口径对齐：apparel → garment 家族

### 15D.3 错误语义分流（404 / 409）

| 场景 | 错误码 | HTTP | 语义 |
|---|---|---|---|
| 订单不存在或已删除 | ORDER_NOT_FOUND | 404 | 先决条件失败，与门禁无关 |
| 资格判定未通过且无有效例外 | GATE_BLOCKED | 409 | 门禁阻断，响应携带 gateDetails（blockingReasons / orders / exceptionReason / exceptionEntryHint） |

两类错误独立分流，不聚合为单一 GATE_BLOCKED（修复前订单不存在被聚合进 blockingReasons，丢失 404 语义）。

### 15D.4 大货验货报告 API 写入路径（QC-门禁锚点闭环）

`POST /api/v1/qc/assignments/:id/complete` 携带 `report` 数据 → 自动创建 InspectionReport（此前只能直插 DB）：

| 项 | 口径 |
|---|---|
| final 报告 id 锚点 | `INR__{orderId}`（出运门禁消费锚点，每单唯一，checkShipmentEligibility / checkGarmentShipmentEligibility 消费） |
| midline 报告 id 锚点 | `INR__{orderId}__mid`（中期报告，与 final/样品链锚点不冲突） |
| 必填校验 | report.result ∈ {pass, fail}（400）；任务验货类型须 ∈ {midline, final}；重复锚点已存在 → 400（幂等防重，修正须先处理既有报告） |
| schema 契约 | totalUnits/passedUnits/majorDefects/minorDefects 为 `Int @default(0)` 必填，缺省语义为 **0 而非 null**；lotSize/sampleSize/aqlLevel 等可空字段保持 null |
| 任务回写 | QCAssignment.reportId = 锚点 id，status → Completed |
