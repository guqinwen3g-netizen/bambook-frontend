## §2 业务定位与目标

### 2.1 业务定位

产品与档案模型组是 Bambook 系统的「物料主数据中枢」，承载面料、成衣、辅料三类核心生产资料的数字档案。所有采购、库存、订单、报价、BOM、生产工单均以 `ProductAsset` 为外键锚点。

### 2.2 核心目标

1. **一物一档**：ProductAsset 聚合根，sku 全局唯一。
2. **三档解耦**：FabricProfile / GarmentProfile / TrimmingProfile 三大 Profile 1:1 解耦。
3. **多维度分类**：ProductClassificationLink 支持 6 维分类视图。
4. **成分可累加**：FabricCompositionLine + MaterialCompositionTerm 术语库。
5. **价格历史分轨**：FabricPriceHistory 按 priceType 分轨。
6. **认证有效期管理**：FabricCertification 含 validUntil。
7. **客户专属编码**：FabricCustomerCode 一物多客。
8. **PDML 外部接入**：PdmlRawFabric 独立缓存表。
9. **洞察沉淀**：Insight 轻量 KV。
10. **图片管理**：ProductImage 多图 + 主图标记。

## §3 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| 聚合根 `ProductAsset` | 产品档案主表，承载 SKU/名称/类目/季节/成本/状态 |
| 三大 Profile | FabricProfile / GarmentProfile / TrimmingProfile（1:1 @unique） |
| 子集合 | 6 类反向聚合（composition/customerCodes/prices/certifications/images/classificationLinks） |
| 软删除 | `deletedAt BigInt?` 非空表示已删除，查询默认过滤 |
| 级联删除 | 子集合外键 `onDelete: Cascade`，随主档软删而级联 |
| `MainCategory` | 一级类目枚举（Garment/Fabric/Accessories/Trimmings/Merchandise/Other） |
| `ProductSubCategory` | 二级类目（西装/纽扣等） |
| `MaterialCompositionTerm` | 成分术语库（缩写/中文/英文） |
| `PdmlRawFabric` | PDML 外部 ERP 同步缓存 |
| `Insight` | 洞察笔记（轻量 KV） |
| `ProductImage` | 产品图片（含 isPrimary 主图标记） |

## §6 关键流程

### 6.1 档案创建 + 子集合写入流程

```
POST /api/products
  │
  ▼
$transaction {
  1. productAsset.create（聚合根）
  2. 按 mainCategory 路由：
     - Fabric → fabricProfile.create
     - Garment → garmentProfile.create
     - Trimmings → trimmingProfile.create
  3. 子集合批量 create（如传入）：
     - compositionLines[]
     - fabricCustomerCodes[]
     - fabricPrices[]
     - fabricCertifications[]
     - images[]
     - classificationLinks[]
  4. writeRouteAuditLog
}
```

### 6.2 PDML 映射流程

```
POST /api/products/pdml/map
  body: { gsid, sourceId }
  │
  ▼
1. 查 PdmlRawFabric（gsid + sourceId）
2. 从 rawData 提取字段：
   - articleNo / factoryArticleNo / colorCode / supplierName / imageUrl ...
3. 创建 ProductAsset（mainCategory=Fabric）+ FabricProfile
4. 返回 PdmlMapResult { created, updated, skipped }
```

### 6.3 软删除级联流程

```
DELETE /api/products/:id
  │
  ▼
$transaction {
  1. productAsset.update({ deletedAt: now })
  2. 子集合查询已默认过滤 deletedAt: null（无需显式级联软删）
  3. writeRouteAuditLog
}
```

> 注意：子集合外键 `onDelete: Cascade` 是物理级联，但业务层用软删除（`deletedAt`），不触发物理删除。查询时统一过滤 `deletedAt: null`。

### 16.2 时间戳约定

- 所有时间字段为 `BigInt`（Unix ms），非 Prisma `DateTime`。
- 便于跨时区一致与高精度排序。
- 前端展示时通过 `new Date(timestamp)` 转换。
