## §2 模型组总览

| # | 模型 | 所属域 | 角色 | 主键格式 | 软删 | 关键约束 |
|---|------|--------|------|---------|------|---------|

| 3 | NotificationPreference | 通知 | 用户通知偏好（静音/通道） | cuid() | ❌ | [userId, notificationType] @@unique |
| 4 | Email | 邮件 | 邮件主档（收发/草稿） | `EML__${shortId}` | ✅ deletedAt | messageId @unique；direction + status + 11 索引 |
| 5 | EmailAttachment | 邮件 | 邮件附件 | `EMLATT__${shortId}` | ❌ | emailId FK Cascade；contentType 索引 |
| 6 | EmailTemplate | 邮件 | 业务邮件模板 | `EMTPL__${shortId}` | ✅ deletedAt | type 枚举；usageCount 统计 |
| 7 | EmailSignature | 邮件 | 邮件签名 | `ESIG__${shortId}` | ✅ deletedAt | language + isDefault 唯一默认 |
| 8 | Season | 季节 | 季度主档（开发日历） | `SEAS__${shortId}` | ✅ deletedAt | code @unique；status 状态机 |

| 10 | TrendTagFabric | 季节 | 趋势↔面料关联 | `TRTF__${shortId}` | ❌ | [trendTagId, fabricId] @@unique |
| 11 | TradeShow | 展会 | 展会记录 | `TRDS__${shortId}` | ✅ deletedAt | seasonId SetNull；4 态状态机 |
| 12 | TradeShowLead | 展会 | 展会线索 | `TRDL__${shortId}` | ✅ deletedAt | tradeShowId FK Cascade；4 态转化 |
| 13 | ExchangeRate | 汇率 | 汇率档案 | `FXR__${shortId}` | ❌（append-only） | [currency, effectiveDate] 索引 |

| 17 | SystemConfigHistory | 配置 | 配置变更审计 | 自定义 | ❌ | configId + versionFrom/To 版本链 |

## §4 通知域模型（Notification Domain）

### 4.1 Notification 模型（站内通知记录）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | String | @id @default(cuid()) | 主键 |
| userId | String | — | 接收用户（FK UserAccount） |
| type | String | — | 通知类型（order_confirmed / shipment_completed / invoice_issued / payment_received / stock_low / payment_overdue / agent_message / briefing 等 40+ 类型） |
| title | String | — | 通知标题 |
| body | String | — | 通知正文 |
| level | String | @default("info") | 级别：info / warning / critical |
| link | String? | — | 前端跳转路由 |
| metadata | Json? | — | 附加元数据 |
| readAt | DateTime? | — | 已读时间（null = 未读） |
| dismissedAt | DateTime? | — | 忽略时间（PRD 7.1：忽略需填原因） |
| dismissReason | String? | — | 忽略原因（用于持续优化推送准确率，目标 ≥80%） |
| createdAt | DateTime | @default(now()) | 创建时间 |

**索引**：[userId, readAt]（未读查询）、[type]、[createdAt]、[level]

**关联**：`user UserAccount @relation(fields: [userId], references: [id])`

| createdAt | DateTime | @default(now()) | — |
| updatedAt | DateTime | @updatedAt | — |

## §11 设计约定与不变量

### 11.1 时间戳约定

| 模型域 | 时间字段类型 | 约定 |
|--------|------------|------|
| 通知域 | DateTime | Notification/NotificationPreference 使用 Prisma DateTime（ISO 8601） |
| 邮件域 | BigInt (epoch ms) | createdAt/updatedAt/deletedAt/syncedAt/aiExtractedAt |
| 季节展会域 | BigInt (epoch ms) + String (YYYY-MM-DD) | 系统时间用 BigInt；业务日期用 String |
| 汇率退税域 | BigInt (epoch ms) + String (YYYY-MM-DD) | 系统时间用 BigInt；生效日期用 String |
| 配置域 | DateTime + BigInt | SystemConfig.createdAt/History.createdAt 用 DateTime；SystemConfig.updatedAt 用 BigInt |

### 11.2 软删策略

| 模型 | 软删字段 | 软删行为 |
|------|---------|---------|
| Notification | ❌ 无 | 物理删除（dismissedAt 标记忽略但保留记录） |
| Email | ✅ deletedAt | 软删后可恢复 |
| EmailTemplate | ✅ deletedAt | 软删 |
| EmailSignature | ✅ deletedAt | 软删 |
| Season | ✅ deletedAt | 软删（关联 TradeShow/TrendTag 的 seasonId SetNull） |
| TrendTag | ✅ deletedAt | 软删 |
| TradeShow | ✅ deletedAt | 软删（关联 TradeShowLead 级联删除） |
| TradeShowLead | ✅ deletedAt | 软删 |
| FxRateLock | ✅ deletedAt | 软删 |
| TaxRefundRate | ✅ deletedAt | 软删 |
| ExchangeRate | ❌ 无 | append-only（汇率记录不可删不可改，只能新增） |
| SystemConfig | ❌ 无 | 不软删（变更通过 version + History 审计） |

### 11.3 金额精度约定

| 模型 | 字段 | 精度 | 说明 |
|------|------|------|------|
| TradeShow | cost | Decimal(18, 4) | 展会费用 |
| ExchangeRate | rate | Decimal(18, 8) | 汇率（8 位小数确保精度） |
| FxRateLock | rate | Decimal(18, 8) | 锁定汇率 |
| TaxRefundRate | rate | Decimal(8, 4) | 退税率百分比 |

### 11.4 通知系统不变量

1. **通知失败永不阻断业务**：持久化失败仅日志，不回滚业务事务
2. **SSE 推送失败只影响实时性**：不重试（落库已成功，用户刷新可见）
3. **邮件通道默认关闭**：需 NotificationPreference 配置开启
4. **忽略需填原因**：dismissedAt 必须配合 dismissReason（PRD 7.1，用于持续优化推送准确率 ≥80%）
5. **静音偏好降级安全**：NotificationPreference 查询失败时降级为全员接收（不阻断通知投递）

### 11.5 邮件系统不变量

1. **messageId 唯一**：RFC 2822 Message-ID 作为 IMAP 去重真源
2. **UID + UIDVALIDITY 组合唯一**：同一 mailbox 内 IMAP UID 稳定性保证
3. **threadId 线索聚合**：基于 References/In-Reply-To 头构建邮件线索
4. **AI 抽取幂等**：aiExtractError 成功后清零，失败后保留错误信息供重试
5. **附件级联删除**：邮件删除时附件自动级联删除（onDelete: Cascade）

### 11.6 汇率退税不变量

1. **ExchangeRate append-only**：汇率记录不可删不可改，只能新增（审计需求）
2. **FxRateLock 优先**：订单有锁定汇率时，定价/退税核算优先使用锁定汇率
3. **TaxRefundRate 最长前缀命中**：HS Code 查询按 10→8→6→4→2 位依次尝试，返回最长匹配
4. **派生值后端重算**：退税美元定价的派生值（netUsdCost/finalUnitPrice 等）一律服务端重算

## §12 数据生命周期与软删策略

### 12.1 通知生命周期

```
BusinessEvent 发布
    │
    ▼
notificationService.notifyFromEvent()
    │
    ├─ NotificationTemplate 按 key 查模板渲染
    ├─ NotificationPreference 过滤静音用户
    ├─ Notification 落库（createdAt = now）
    │
    ▼
SSE 实时推送（失败不重试）
    │
    ▼
用户查看 → readAt = now
    │
    ▼
用户忽略 → dismissedAt = now + dismissReason
    │
    ▼
（无软删，物理保留供审计）
```

### 12.2 邮件生命周期

```
IMAP 同步 / 手动创建
    │
    ▼
Email 落库（direction/status/邮箱元数据）
    │
    ├─ hasAttachments = true → EmailAttachment 级联入库
    │
    ▼
AI 抽取（Phase 4b）
    │
    ├─ 成功：aiExtractedJson + aiExtractedAt + aiModel
    ├─ 失败：aiExtractError（保留供重试）
    │
    ▼
用户操作 → status 流转（new→read→starred→archived）
    │
    ▼
软删 → deletedAt = now（附件级联保留，可恢复）
```

### 12.3 季节展会生命周期

```
Season 创建（status=Planning）
    │
    ├─ TradeShow 关联（seasonId FK，SetNull）
    ├─ TrendTag 关联（seasonId FK，SetNull）
    │
    ▼
Season 进入活跃（status=Active）
    │
    ├─ TradeShow 状态流转：Planned→Ongoing→Completed
    ├─ TradeShowLead 转化：New→Following→Converted（convertedRelationId 填充）
    │
    ▼
Season 关闭（status=Closed）
    │
    ├─ reviewJson 生成季度回顾快照
    │
    ▼
软删 → deletedAt = now
    └─ TradeShow.seasonId = null（SetNull）
    └─ TrendTag.seasonId = null（SetNull）
    └─ TradeShowLead 通过 tradeShowId Cascade 级联删除
```

### 12.4 系统配置生命周期

```
SystemConfig 创建（version=1）
    │
    ▼
首次变更
    ├─ SystemConfigHistory 落库（versionFrom=1, versionTo=2, valueFrom/valueTo）
    ├─ SystemConfig.version = 2
    │
    ▼
后续变更（每次 version+1，History 追加一条）
    │
    ▼
加密配置变更
    ├─ sensitiveMasked = true（valueFrom/valueTo 以 *** 展示）
    │
    ▼
（不软删，通过 isActive 启停或 History 回滚）
```

### 13.2 当前限制

- ❌ 汇率无自动拉取（ExchangeRate.source='api' 字段已预留，但无定时任务拉取央行/商业银行汇率）
- ❌ 通知无 Push 通道（当前仅 in_app + SSE，Push 推送未实现）
- ❌ 邮件 AI 抽取无自动重试机制（aiExtractError 保留后需手动触发重试）
- ❌ 季度回顾 reviewJson 需手动触发生成（无定时任务自动生成）
- ❌ TaxRefundRate 无国标同步（HS Code 退税率需手动维护）
- ❌ SystemConfig 无回滚操作（History 仅审计，回滚需手动修改 value + version+1）
- ❌ Notification 无归档/清理策略（数据持续增长无 TTL）

### 14.3 邮件 AI 抽取（Phase 4b）

Email 模型的 AI 抽取字段设计为幂等可重试：
- `aiExtractedJson`：成功时存储结构化数据（intent/products/quantities/prices/deadlines/customerSignal/language/summary）
- `aiExtractError`：失败时存储错误信息（成功后清零，供下次重试判断）
- `aiModel`：记录使用的模型名（如 ark-code-latest），便于模型升级后的批量重抽取
- `aiExtractedAt`：抽取时间 epoch ms

### 14.4 季度回顾快照设计

Season.reviewJson 设计为**可重生成快照**：
- 真源为订单实时聚合（orderCount/shippedCount/revenue/cost/grossProfit/topCustomers）
- reviewJson 字段为生成时点快照（reviewedAt 记录生成时间）
- 季度结束后可多次重新生成覆盖更新

### 14.5 系统配置加密设计

SystemConfig 的 AES-GCM 加密方案：
- 未加密配置：`value` 直接 JSON 存储字符串/数字/布尔
- 加密配置：`value` 存储 `"${iv.hex}.${cipher.hex}.${tag.hex}"` 格式
- 敏感配置（API_KEY / DB_URL / SMTP_PASSWORD / LLM_KEY 等）`encrypted = true`
- History 审计中加密配置的 valueFrom/valueTo 以 `***` 展示（`sensitiveMasked = true`）
