## §2 业务定位与目标

### 2.1 业务定位

采购与库存模型组是 Bambook 系统的「物料流转中枢」，承载从采购下单、收货检验、入库出库、库存预警到调拨盘点的全链路物料流转数据。

- **采购链**：`PurchaseOrder`（采购单）→ `PurchaseLine`（行项）→ `MaterialReceipt`（收料单）。
- **库存链**：`Warehouse`（仓库）→ `InventoryItem`（库存项）→ `StockMovement`（变动流水）。

两条链通过 `MaterialReceipt.warehouseId` 关联——收料检验合格后自动入库到指定仓库的 `InventoryItem`，并写入 `StockMovement` 流水。

### 2.2 核心目标

1. **采购单全生命周期**：Draft → Sent → Confirmed → PartiallyReceived → Received → Closed / Cancelled 七态状态机。
2. **收货检验闭环**：MaterialReceipt 承载检验结果（合格/不合格/部分合格），合格量自动入库。
3. **多仓库支持**：Warehouse 支持主仓/辅仓/临时仓/虚拟仓四类。
4. **库存项精细管理**：InventoryItem 按 仓库+物料 维度管理，含批次号、库位、锁定数量、成本、预警线。
5. **变动流水全程追溯**：StockMovement 记录入库/出库/调拨/盘点/锁定/解锁六类变动，含变动前后余额。
6. **来源追溯**：StockMovement.referenceType + referenceId 关联采购单/订单/货运/生产/调整/手动。
7. **库存预警**：minStock / maxStock 双线预警，触发 `StockLowAlarm` / `StockOverstockAlarm` 事件。

## §3 核心概念与术语

| 术语 | 定义 |
| --- | --- |
| 采购单 `PurchaseOrder` | 采购业务单据，承载供应商/金额/日期/条款 |
| 采购单号 `poNumber` | 业务采购单号（如 PO-20260806-001），全局唯一 |
| 采购行 `PurchaseLine` | 采购单行项，承载物料/数量/价格/收货跟踪 |
| 物料编码 `materialCode` | 行项关联产品档案的编码（面料/辅料） |
| 收料单 `MaterialReceipt` | 收货检验单据 |
| 收料单号 `receiptNumber` | 业务收料单号 |
| 检验状态 `status` | Pending/Inspected/Accepted/Rejected/PartiallyAccepted |
| 仓库 `Warehouse` | 仓库主数据 |
| 仓库类型 `type` | Main(主仓)/Auxiliary(辅仓)/Temporary(临时仓)/Virtual(虚拟仓) |
| 库存项 `InventoryItem` | 按 仓库+物料 维度的库存记录 |
| 库位 `locationCode` | 库位编码（如 A-01-03） |
| 批次号 `batchNumber` | 物料批次（可追溯） |
| 锁定数量 `lockedQuantity` | 已分配未出库数量 |
| 可用数量 `availableQuantity` | `quantity - lockedQuantity`（前端计算） |
| 变动流水 `StockMovement` | 库存变动记录 |
| 变动类型 `type` | Inbound/Outbound/Transfer/Adjustment/Lock/Unlock |
| 变动前后余额 `balanceBefore / balanceAfter` | 变动前后库存数量 |
| 来源追溯 `referenceType + referenceId` | 关联单据类型 + ID |
| 预警线 `minStock / maxStock` | 最低/最高库存预警线 |

## §6 关键流程

### 6.1 采购单创建流程

```
POST /api/purchase-orders
  body: PurchaseOrderInput { poNumber, currency, supplierRelationId, ..., lines[] }
  │
  ▼
1. assertNotBlacklisted(supplierRelationId)  // 黑名单校验
2. $transaction {
     a. PurchaseOrder.create（主表）
     b. PurchaseLine.create[]（行项，批量）
     c. totalAmount = sum(line.amount)
     d. writeAuditLog
   }
3. 发布 PurchaseOrderCreated 事件
4. 返回 PurchaseOrder（含 lines）
```

### 6.2 采购单状态流转

```
Draft ──发送──► Sent ──确认──► Confirmed ──部分收货──► PartiallyReceived ──全部收齐──► Received ──关闭──► Closed
                                                                                                      ▲
Draft / Sent / Confirmed / PartiallyReceived ──取消──► Cancelled

任意状态可软删 → Deleted
```

- **Draft**：草稿，可编辑。
- **Sent**：已发送供应商，计入工厂产能占用。
- **Confirmed**：供应商确认。
- **PartiallyReceived**：部分到货，仍计入产能占用。
- **Received**：全部到货，不再计入产能占用，触发交期评分。
- **Closed**：已关闭（如已付款）。
- **Cancelled**：已取消，不再计入产能占用。

### 6.3 收料检验流程

```
POST /api/purchase-orders/:id/receipts
  body: MaterialReceiptInput { receiptNumber, receivedDate, warehouseId, ... }
  │
  ▼
$transaction {
  1. MaterialReceipt.create
  2. 更新 PurchaseLine.receivedQuantity / rejectedQuantity
  3. if status === 'Accepted' or 'PartiallyAccepted':
       - 自动入库：InventoryItem.upsert（warehouseId + productAssetId/materialCode）
       - 写 StockMovement（type=Inbound, referenceType=PurchaseOrder）
  4. 更新 PurchaseOrder.status：
     - 全部行收齐 → Received
     - 部分行收齐 → PartiallyReceived
  5. writeAuditLog
}
  │
  ▼
发布 MaterialReceiptCreated 事件
  │
  ▼
若 status === 'Received'：
  - 触发交期自动评分（recordAutoEvaluation kind=delivery）
```

### 6.4 库存变动流程

```
POST /api/inventory/movements
  body: StockMovementInput { itemId, type, quantity, ... }
  │
  ▼
$transaction {
  1. 查 InventoryItem（itemId）
  2. 校验变动类型：
     - Inbound: quantity 正数，余额增加
     - Outbound: quantity 正数，余额减少（校验 sufficient stock，余额不可负）
     - Transfer: quantity 正数，源仓减 + 目标仓加
     - Adjustment: quantity 任意正负，余额调整
     - Lock: lockedQuantity 增加（quantity 正数）
     - Unlock: lockedQuantity 减少（quantity 正数）
  3. 计算 balanceBefore / balanceAfter
  4. InventoryItem.update（quantity / lockedQuantity / lastInDate / lastOutDate）
  5. StockMovement.create（含 balanceBefore / balanceAfter）
  6. writeAuditLog
}
  │
  ▼
if quantity < minStock → 发布 StockLowAlarm 事件
if quantity > maxStock → 发布 StockOverstockAlarm 事件
```

### 6.5 库存预警流程

```
库存变动后检查：
  │
  ▼
if item.quantity < item.minStock:
  发布 StockLowAlarm 事件
  payload: { itemId, warehouseId, materialCode, currentQuantity, minStock }
  │
  ▼
if item.quantity > item.maxStock:
  发布 StockOverstockAlarm 事件
  payload: { itemId, warehouseId, materialCode, currentQuantity, maxStock }
```

## §11 错误处理与边界

### 11.1 错误场景

| 场景 | 错误信息 |
| --- | --- |
| 供应商黑名单 | `工厂已拉黑，禁止新建采购单` |
| poNumber 重复 | DB 唯一约束抛错 |
| 库存余额不足 | `库存余额不足`（Outbound 时） |
| 锁定数量超可用 | `锁定数量超过可用数量`（Lock 时） |
| 调拨缺目标仓 | `调拨必须指定目标仓库`（Transfer 时） |
| 仓库不存在 | `仓库 ${warehouseId} 不存在` |
| 库存项不存在 | `库存项 ${itemId} 不存在` |

### 11.2 边界

- `quantity` 为 Decimal(18,4)，允许小数（如 1.5 卷）。
- `lockedQuantity` 默认 0，不可为负。
- `availableQuantity` 前端计算：`quantity - lockedQuantity`。
- Outbound 时 `balanceAfter` 不可为负（fail-closed）。
- Transfer 时需 `targetWarehouseId`，源仓与目标仓不可相同。
- Adjustment 时 `quantity` 可正可负，余额可增可减。

## §14 已知限制与技术债务

1. **PurchaseLine.materialCode 松外键**：未强制约束关联 ProductAsset.sku，可能产生孤儿引用。
2. **InventoryItem 双重关联**：`productAssetId` 与 `materialCode` 可独立存在，可能导致同一物料双份库存记录。
3. **MaterialReceipt 无行级检验**：仅记录总收货/合格/不合格数量，未按行项细分检验结果。
4. **StockMovement 无库存快照**：仅记录变动前后余额，无定期库存快照（建议每日快照）。
5. **无批次先进先出**：批次号记录但未强制 FIFO/FEFO 出库。
6. **无多币种成本核算**：`unitCost + currency` 简单记录，未做汇率换算汇总。
7. **预警仅事件发布**：无主动通知（邮件/IM），仅事件订阅方可感知。
8. **Warehouse 无库位管理**：仅 `locationCode` 字段文本承载，无独立 WarehouseLocation 表（库位结构化管理）。
