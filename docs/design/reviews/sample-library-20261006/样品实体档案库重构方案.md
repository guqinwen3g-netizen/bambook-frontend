# 样品管理实体档案库重构方案

样品管理应承载公司样品间中实际物件的数字记录。员工进入后，能够按面料、成衣、辅料找到一件实物，看清照片、位置、封存和借还情况，再追溯它产生于哪个业务版本、当时经过什么评审。

本方案依据 2026 年 10 月 6 日的用户说明、当前开发页面及源码审阅。页面结构和规则为建议方案；现有实现与缺口在下文单独说明。本轮保存诊断和设计方案，应用代码与业务数据未改。

## 模块职责

| 模块 | 管理的对象 | 在样品详情中的连接 |
| --- | --- | --- |
| 数字档案 | 产品、材料、款式及规格资料 | 查看关联产品档案 |
| 开发管理 | 开发案、工厂、轮次、版本、QC 与客户确认 | 查看产生这件实物的准确版本和当时意见 |
| 订单与生产 | 订单行、生产批次、产前样、船样等业务事实 | 查看准确取样范围和业务记录 |
| QC 工作台 | 实际检验任务、报告与结论 | 查看本轮本版报告原件 |
| 样品管理 | 实物身份、照片、库位、保管与流转 | 查询和管理实际存放或已经流出的样品 |

样品库直接展示关联业务的事实摘要，评审、批准和修改记录继续由原业务流程产生。双方应能互相跳转：业务版本能看到对应实物，实物能打开产生它的版本。业务寄样涉及已有库存时，必须选择实际物件，并形成可核对的实物出库记录。

## 分类与状态

以下维度分别存储与显示，避免一个状态承担多种含义。

| 维度 | 示例 | 用途 |
| --- | --- | --- |
| 实物大类 | 面料、成衣、辅料 | 决定所在的实体库 |
| 实物形态 | 色样、手织样、米样、成衣、纽扣、拉链、衬布 | 描述实际拿在手上的物件 |
| 样品用途 | 开发样、产前样、大货样、船样、匹头样、先锋样、客户来样、参考样 | 说明为何产生、用于什么环节 |
| 保管规则 | 普通流通、封存留样 | 决定是否可借、可寄 |
| 实物流转 | 在库、借出、寄出待回、永久出样、退役 | 说明现在在哪里及是否会回来 |
| 业务结果 | 待 QC、QC 不通过、客户通过、需修改、历史版本 | 说明原业务评审事实 |

“船样”是用途，“已封存”是保管规则；同一件船样可以封存，也可以按规则对外寄出。“客户已批准”与“实物在库”分别显示。用途可在履历中增加或变更，同一件实物继续使用其原编号。

建议色卡作为面料库中的一种形态。辅料独立存储分类，业务归属仍可来自成衣。历史未核实来源以标记和待核对清单呈现；在已有查看权限的范围内，缺少来源信息也能找到实际物件，不自动推断或补成已确认。

## 页面结构

### 第一层 样品库入口

沿用数字档案的大类卡片，显示“面料样品”“成衣样品”“辅料样品”三个主要入口。每类显示可见档案记录数，轻量提示封存、在借数量；不同数量单位分别统计，不把米、件、张相加。

入口保留全库搜索，能按名称、实物编号、开发案号、订单号和库位找样。待上架、待归还、待核对作为较轻的快捷入口，不占据物件大类的位置。常用类别可直接打开，返回时保留筛选和浏览位置。

### 第二层 分类集合

进入大类即看到该类实物，默认照片图册，可切换清单；子类和形态用筛选提供，避免查样前必须通过多级索引。

每张图册卡片只展示识别与拿样所需信息：本件照片、名称和实物编号、用途、当前库位、实物状态、封存标记。开发案或订单简称作为辅助信息。没有照片显示“实物照片待补”；产品参考图和业务附件分别标注来源。

工具区常驻搜索、样品用途、仓库和保管状态。客户、工厂、年份、轮次、是否缺照片等条件收进更多筛选。图册与清单共享筛选，清单增加保管人、数量和预计归还日期，适合盘点和批量查找。

### 第三层 单件实物档案

沿用数字档案的详情结构：左侧是同集合的简短目录，右侧是完整档案。主要资料放在全页详情里，便于浏览照片和长评语；借出、移位等操作用现有表单弹层完成。

首屏左侧为实物相册，右侧显示名称、编号、用途、当前状态、封存规则和具体位置。员工不需要向下滚动就能知道是否可借。当前位置示例为“上海样品间 → A 架 → 第 3 层 → 05 格”；成衣可为“B 挂杆 → 12 挂位”，辅料可为“C 架 → 第 2 层 → 纽扣盒 07”。

借出时显示借用人、去向和预计归还日期，原库位标为归还位置；不把原库位当成实物当前仍在的位置。未登记位置显示“待上架定位”。

| 详情区域 | 内容 |
| --- | --- |
| 实物资料 | 本件照片、品名、尺寸、颜色、材质、数量和单位、实物备注、附件；字段按面料、成衣、辅料变化 |
| 存放与保管 | 样品间、货架或挂杆、层和格位、保管人、收样日期、状态、封存人和日期、可动用数量 |
| 业务来源 | 开发案、工厂、准确批次和制作版本；或订单、订单行、生产批次、取样范围；关联数字档案 |
| 当时评审 | 本轮本版的 QC 意见、客户意见、修改要求、时间、记录人和证据附件 |
| 流转履历 | 收样、上架、移位、借出、归还、寄送、封存、盘点、损耗、退役的实际记录 |

详情完整展示信息，但首屏和集合卡片只放最常用内容。分节导航支持直接跳到评审、来源和历史。

## 业务来源和评审

来源要同时回答“这件实际做出来时是什么”及“业务后来怎样使用它”。实物制作时的规格与版本冻结留存，后续业务状态从原记录读取，二者有清楚的标题和时间。

当前开发模型已定义 R4-A 为有实物的大版本，R4-A-1 为无新实物的小版本。[版本模型](/Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/prisma/schema.prisma:2270) 档案应显示“制作版本 R4-A”及“关联微调 R4-A-1”，并展示微调说明；小版本不重复入库、不重复封存，也不把纸面微调表示成实物已经修改。目前来源冻结函数未纳入这些新版本字段，改造需同时补齐来源契约。[冻结来源](/Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/samples/sampleOriginService.ts:62)

船样等订单样品应定位到准确订单行、工厂、生产批次及代表范围。成衣主样仍归属其大版本；实际独立收到的面料和辅料以组件实物关联该版本，各自登记库位，不因此产生多个成衣版本。保管中的同组数量、独立组件、面料形态与业务版本身份分别承载，不能因拆库位或登记副本而隐式增加版本。不同来源、颜色、尺码或位置的实物按准确来源建立保管明细；关联多个业务用途时，不复制库存记录。

QC 和客户意见在样品库中可直接阅读，并保留“查看原评审”“查看原开发版本”“查看原订单批次”的入口。意见按本轮本版绑定，不能展示另一轮最新意见冒充本件的历史结论。新评审与失效记录追加呈现，原意见仍可追溯。

当前订单原生客户反馈事件有结果、日期、渠道和证据引用，缺少意见正文；需要补受控的正文承载。有邮件或附件证据但没有正文时，显示现有证据入口与缺失提示。[反馈事件](/Users/qinwengu/WorkBuddy/Claw/apps/Bambook/server/src/samples/orderSampleEventReducer.ts:7)

## 实物身份和保管操作

建议成衣、独立封存基准以及需要单独追踪的物件一件一编号、一件一二维码。完全同质、同版本、同库位、同保管规则的辅料或样卡允许按盒或组登记数量。不同位置或封存规则需要拆分库存明细，保持拆分前后数量守恒。仍缝在衣服上的辅料属于成衣内容；实际分离并单独存放的辅料才建立自己的库存记录。

物件件数与长度或重量分别保存：一块面料为 1 件，其实测长度可以是 2.5 M。件数使用整数，长度和重量保留小数精度；计量未知保持未记录，不能由件数推算。封存、借还、拆分和损耗必须指明作用于哪种数量，按同一单位核对变化；M 与 YD 不直接相加。裁切产生新物件时记录派生关系和计量变化，不能把物件数增加误记为额外收样。

| 操作 | 应记录和执行的事实 |
| --- | --- |
| 收样登记 | 选真实来源或客户来样、历史实物来源，核对物件、数量和单位，补照片与库位；未收到的业务计划不计入实物库存 |
| 上架和移位 | 记录前后库位、实际物件或明细数量、经办人与时间；已借出的物件不能当作在库移位 |
| 借出 | 选择实际可动用实物、借用人、用途、归还日期；立即反映实物去向 |
| 归还 | 核对实际返回数量与状态，区分部分归还、损坏和缺失；确认归还库位 |
| 寄送 | 先区分寄借需归还和永久出样，再记录收件对象、快递和运单；两者都形成出库事实 |
| 封存留样 | 指定实际物件或数量，记录对应标准和版本；普通借出和寄送在服务端拒绝 |
| 盘点 | 记录实际清点结果和差异原因；数量和状态变化留痕 |
| 退役或损耗 | 保留原档案和完整历史，退出活跃库存 |
| 标签打印 | 实物编号、名称、类别、库位和二维码；扫码打开该件档案 |

封存规则与业务确认分别处理。业务通过后，仓管选择实际留存物件并确认其位置；封存动作本身不生成客户批准或生产放行。一组 3 件中留存 1 件时，界面明确显示“封存 1，普通可动用 2”，借出并发请求也不能动用留存部分。

## 改造顺序

1. **调整设计契约及关联关系。** 明确实体分类、实物编号与组数量、封存禁借、寄借和永久出样的区别；补齐新开发版本的来源身份；盘点旧接口和业务深链，安排原有推进入口的承接位置。
2. **补足实体服务。** 接通可独立读取的完整实物详情，聚合来源与评审；增加实物照片、库位结构、保管规则与准确流转记录；保留原有授权、并发校验、幂等回执和审计能力。
3. **重建分类和浏览界面。** 使用数字档案现有分类卡片、集合切换和详情壳，加入真实实物照片和位置；原业务按钮通过来源入口进入对应流程。迁移每个入口前确认目的地能承接。
4. **核对历史数据并完成连续业务验收。** 历史库位文本暂保留，不自动猜货架层格；没有可靠来源的实物继续标为待核。旧整行封样标签需要核对实际封存物件，不能自动变成一件已封存的证据。

界面继续使用现有 BDS 的编译原语、玻璃材质、字号、圆角和悬停反馈。数字档案现有记录网格是图标和文字卡，照片卡需要在其体系内增补真实图片区。照片预览和业务信息读取继续服从 catalog/full 等现有可见性，分类改变不扩大权限。

## 验收场景

| 连续场景 | 要证明的结果 |
| --- | --- |
| 成衣 R4-A 收到成衣主样、独立面料和辅料，分别存入挂位、架位、盒位 | 三类均能找到，主样和组件分别可查，来源指向正确版本；成衣版本数量不增加，没有重复入库 |
| R4-A 新增纸面微调 R4-A-1，订单引用小版本 | 原实物档案显示制作版本和微调说明，库存与封存数量不增加 |
| 一组 3 件留存 1 件，其余借出 | 封存部分始终不可借或寄，可用量正确，服务端守卫有效 |
| 普通样品邮寄借给客户，部分归还并发现损坏 | 运单、去向、未还量、归还位置和损坏事实可追溯 |
| 船样带 QC 意见和客户反馈，后来该业务记录失效 | 仍能查看原批次和当时评审；当前失效提示清楚 |
| 面料同轮多工厂、多色样、多形态 | 照片、版本、意见和位置对应正确，数量单位分别展示 |
| 从开发页寄出已有实物，再从样品库查看 | 同一件实物立即反映出库，无第二份库存或相互矛盾的状态 |
| 新账号无某案权限，或操作时账号切换、来源变化 | 无权照片和业务详情不泄露；陈旧操作拒绝并可安全恢复 |
| 重复点击收样或寄出，保存途中中断 | 原事实可读回，不重复建物件、不重复扣库存 |

这些是后续实施验收条件，本轮未执行这些业务操作或测试。
