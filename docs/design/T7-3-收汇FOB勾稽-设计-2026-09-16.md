# T7-3 · ④收汇金额 ↔ 报关 FOB 勾稽 设计（2026-09-16）

> 口径 D 已拍板（2026-09-16 业务方）：
> - **容差：5% 或 500 美元（取大者）以内算正常，超出只预警（不阻断）**
> - **CIF 单必须先减掉运费和保费再比**
> 本文 = 数据源 + 算法 + 接口设计。

## 一、为什么必须有

出口收汇金额需与报关 FOB 金额勾稽（外汇核销 / 退税核查的常规要求）：
- 收汇**显著低于**报关 FOB → 可能有佣金、折让、或**未收汇即申报退税**的风险；
- 收汇**显著高于**报关 FOB → 可能有多收 / 错汇 / 混入非本单款项。

现状：水单核销链（`receiptClaimService` / `allocationService`）只到**发票 / 订单**层，
**完全不碰报关单**（grep `declaration/customs/报关` 零命中）→ 这两笔钱各在各的域，永远碰不上。

## 二、数据源（已核准）

| 项 | 真源 | 说明 |
|---|---|---|
| 收汇 | `PaymentVoucher(type='Receipt', orderId, deletedAt: null).amount` | 按币种分组求和；`orderId` 是该表自带的冗余关联（`schema.prisma` 注释「便于按订单聚合资金流」） |
| 报关申报额 | `CustomsDeclaration.totalValue` + `currency` | 按 `orderId` 找该订单全部报关单（一单可分批报关） |
| 成交方式 | `CustomsDeclaration.tradeTerms` | `FOB \| CIF \| EXW \| DDP \| FCA \| CPT \| CIP \| DAP \| DPU \| CFR`（`customsService.ts:34`） |
| 运费 / 保费 | `Shipment.freightAmount / freightCurrency / insuranceAmount / insuranceCurrency` | 经 `CustomsDeclaration.shipmentId` 找运单（`schema.prisma:3006-3009`） |

**锚点 = 订单**（与对账域 `reconciliationService` 一致；一单可多次报关、多笔收汇）。

## 三、CIF → FOB 的剥离算法（口径 D 第二条）

对每张报关单按 `tradeTerms` 决定剥什么：

| 成交方式 | 是否剥 | 剥什么 |
|---|---|---|
| `FOB` / `FCA` / `EXW` | **不剥** | 本身就是离岸/出厂价（EXW 比 FOB 还低，更保守） |
| `CFR` / `CPT` | 剥 | 运费 |
| `CIF` / `CIP` | 剥 | 运费 + 保费 |
| `DDP` / `DAP` / `DPU` | **不剥但标记** | D 组含运保费+进口关税+送货，全剥需要关税数据，本批**不猜** → 计入 `unStrippable`，该票不参与金额比对并在结果里说明 |
| 其它/空 | **不剥但标记** | 同上，`unStrippable` |

**币种对齐铁律**：只有当运单运费/保费**币种与报关币种一致**时才剥；
不一致（如报关 USD、运单运费 CNY）→ **不换算**（换算要引入汇率口径，与口径 A「汇率锚点只有结汇汇率」冲突）
→ 计入 `unStrippable`，该票不参与比对。

## 四、容差与判定（口径 D 第一条）

```
tolerance = max(0.05 × declaredFob, 500)
超差 ⟺ |receiptAmount − declaredFob| > tolerance
```

⚠️ **近似说明**：固定阈值 `500` 按**该币种金额单位**处理（USD 即 500 美元，主场景正确）。
非 USD 币种未做汇率换算（同上，不引入新汇率口径）；5% 部分本身与币种无关，故非 USD 场景
实际以 5% 为主。结果里带 `toleranceBasis` 字段说明用了什么阈值。

**severity 恒 `'warning'`**（口径 D：超差只预警不阻断）。

## 五、产出与接口

```ts
interface ReceiptFobCurrencyRow {
  currency: string;
  receiptAmount: number;       // Σ 收汇（该币种）
  declaredFob: number;         // Σ 报关 FOB（已剥运保费）
  declaredGross: number;       // Σ 报关原始申报额（未剥，供对照）
  strippedFreight: number;     // 已剥运费
  strippedInsurance: number;   // 已剥保费
  difference: number;          // receiptAmount − declaredFob
  differencePct: number;       // difference / declaredFob（declaredFob=0 时为 null）
  tolerance: number;           // max(5% × declaredFob, 500)
  toleranceBasis: string;      // 说明（如 "5% (5000.00) 大于固定阈值 500"）
  withinTolerance: boolean;
  unStrippable: Array<{ declarationNumber: string; reason: string }>;  // 未参与比对的报关单
}

interface ReceiptFobReconciliation {
  orderId: string; orderCode: string | null; customerName: string | null;
  byCurrency: ReceiptFobCurrencyRow[];
  discrepancies: Array<{ type: 'receipt_fob_mismatch'; currency: string; field: string;
                         expected: string; actual: string; severity: 'warning'; message: string }>;
  receiptVoucherCount: number;
  declarationCount: number;
}
```

- 服务：`server/src/finance/receiptFobReconciliationService.ts`（纯只读）
- 路由：`GET /api/v1/reconciliation/orders/:orderId/receipt-fob`
  （挂 `reconciliationRoute`，沿用 `invoices:read ∨ vouchers:read` 权限；订单不存在 → 404）
- **本批不做 UI**（与 T7-2 同策略：先落服务端 + 测试 + 真库验收）

## 六、验收口径

1. 同币种、全额收汇、FOB 成交 → 零差异。
2. 收汇低于 FOB 超容差 → `warning`（**不得 critical**）。
3. CIF 成交且运单有同币种运费保费 → 剥离后再比（剥离生效可从 `strippedFreight/strippedInsurance` 验证）。
4. CIF 成交但运单缺运费/保费或币种不一致 → 计入 `unStrippable`，**该票不参与比对**（不猜、不换算）。
5. 容差取大者：小金额单走 500 固定阈值，大金额单走 5%。
6. 订单不存在 → 404。
