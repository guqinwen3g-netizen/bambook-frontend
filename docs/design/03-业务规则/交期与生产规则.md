# 交期与生产规则

> **PRD 关联**：§10 业务十条 L1-L10（交期锁死 / 7 天计划死线 / 15 天延期通知 / 验厂 7 天提醒 / 生产 10 阶段门禁）
> **落地状态**：⚠️ 字段与调度 watchdog 已到位；交期锁死门禁未接、7 天计划死线仅预警无硬门禁
> **DR-011 关联**：生产放行是独立步骤，不因商业批准自动完成，须 QC 通过 + 客户确认 + 产前样封存 + 主管手动确认
> **DR-012 关联**：面料开发样阶段独立 S/S 阶段；S/S 后默认追加面料最终 QC，可与 S/S/RC 并行但不可省略
> **DR-013 关联**：打样收费允许不收款但不得未记录；收款可后补；样品收款为收入，运杂费为费用，独立记账
> **DR-014 关联**：产前样/销售样/开发样支持替代物料；不得强制先行采购或占用大货采购单

## 2026-10-09 当前订单日期口径（用户确认）

- 各类订单台账统一显示/排序出厂交期（Ex-mill）；主单行展示完整条目出厂交期的最早—最晚范围；所有条目同日时显示单日，缺失条目标记待定。条目行读取`exMillDate`，无独立值时继承已约定的主单出厂默认值。不以生产、通用交货或到达日期替代缺失的出厂交期。
- 贸易条款复用`server/src/_shared/incoterm.ts`真源；录入显示现行十一项及对应指定地点/港口。`deliveryTerms`仍保留完整合同表达，`deliveryPlace`独立保存地点，避免影响制单/报关消费者。未知贸易条款不再由V2配置自动填成FOB；旧记录不重写。
- 卖方安排运输的C/D条款显示`expectedArrivalDate`（预计）与`agreedArrivalDate`（明确合同承诺）；FOB等不强制填到达日期。切换为非卖方运输条款时清除上述到达字段；生产及出厂交期不变。内部需求订单不强制填写贸易条款。
- 主单贸易与到达字段由V1/V2保存/回读，草稿可编辑；正式商业变更仍受`orderHeaderMutationPolicy`保护。新增三列采用可空增量迁移，不推测历史合同。
- 生产进度预警改用明确的`productionDate`/产品行`deliveryDate`，缺失时不拿通用`dueDate`或到达日期推断生产逾期；实际完工状态继续由生产证据判定。出厂必填的具体阶段正在与用户讨论，尚未更改必填规则。
- 本轮未执行构建、测试或浏览器走查，交互及视觉待用户验收。源码锚点：`lib/orderSchema.ts`、`components/order/OrderClusterBlock.tsx`、`server/src/shared/orderTradeTerms.ts`、`server/src/orders/route.ts`、`orderServiceV2.ts`、`server/src/production/productionProgressService.ts`。

## §3 逐条规则详解

### 3.1 L1 交期锁死（❌ 未接）

**触发条件**：Order.status 迁移至 `Shipping` 或 `Delivered`

**期望动作**：dueDate / clientDate / exMillDate / OrderLine.deliveryDate / OrderLine.shippingDate 等交期相关字段变为只读，任何修改请求被拒绝

**门禁**：应在 `orderLifecycleService.ts` transitionOrderStatus 完成状态迁移后标记字段锁定；Order update 路由按 status 区分可编辑字段白名单

**异常分支**：交期变更需走订单变更审批链（参见 [订单变更规则.md](./订单变更规则.md) §9.7-③），审批通过后由系统解锁一次性写入

**当前缺口**：
- `transitionOrderStatus` 未对字段修改设置状态拦截
- Order update 路由（`server/src/orders/` 路由层）未按 status 区分可编辑字段，Shipping/Delivered 状态下交期字段仍可直通修改
- 无字段锁定标记位（如 `deliveryLockedAt`）

### 3.2 L2 7 天计划死线（⚠️ 字段有 + 预警有 / 硬门禁未接）

**触发条件**：订单确认后，`productionPlanDeadline`（= createdAt + 7d）已过且生产计划阶段（production_planned, seq=3）未完成

**字段定义**（`schema.prisma:195`）：
```
productionPlanDeadline String? // 下单后7天内需出生产计划（createdAt + 7d），超时触发预警
```

**动作**（`productionDeadlineWatchdog.ts`，每小时扫描）：
- 逾期 1-3 天 → `warning` 级通知（broadcastNotification）
- 逾期 >3 天 → `critical` 级通知
- 去重：dedupKey = `prod:plan:${orderId}:${tier}:${today}`，同级当天只发一次

**门禁（未接）**：期望超时后阻断该订单后续生产阶段推进（如禁止推进至 in_production），当前仅通知无硬拦截

**异常分支**：跟单员可在订单表单手动修改 productionPlanDeadline（无门禁校验）

### 3.3 L3 15 天延期通知窗口（✅ 已接）

**触发条件**：`delayNoticeDeadline`（= dueDate - 15d）已到且订单未交付

**字段定义**（`schema.prisma:196`）：
```
delayNoticeDeadline String? // 交货期前15天需发延期通知（dueDate - 15d），超时升级
```

**动作**（`productionDeadlineWatchdog.ts`）：
- delayNoticeDeadline ≤ today → `critical` 级广播通知
- 通知内容：「延期通知窗口已开启，若预计无法按期交付，须立即向客户发出延期通知」
- 去重：dedupKey = `prod:notice:${orderId}:${today}`

**门禁**：无硬门禁（不阻断生产），仅提醒业务员评估并决定是否发延期通知

**异常分支**：若可按期交付，业务员推进生产即可，无需发延期通知

> **注**：本规则是「交期前 15 天开启延期通知窗口」，非「交期延期超 15 天」。delayNoticeDeadline 在订单创建时由 dueDate 倒推计算。

### 3.4 L4 验厂 7 天提醒（✅ 已接）

**触发条件**：`factoryVisitDate`（客户计划实地验厂日）非空且距今天数 ∈ [0, 7]

**字段定义**（`schema.prisma:178`）：
```
factoryVisitDate String? // YYYY-MM-DD 客户计划实地验厂日
```

**动作**（`factoryVisitWatchdog.ts`，每日 11:30 后执行一次）：
- 距验厂日 2-7 天 → `warning`（确认接待安排）
- 距验厂日 0-1 天 → `critical`（临近升级）
- 验厂日已过 → 不再提醒
- 排除已完结/已出运/已开票收款状态（EXCLUDED_STATUSES）

**门禁**：无硬门禁，通过 `riskService.raiseAlert` 产生风险预警（非 notificationService）

**去重**：dedupKey = `factory_visit:${orderId}:${visitDate}:${tier}`，每个 tier 只发一次

### 3.5 L5-L10 生产 10 阶段门禁（✅ / ⚠️ 详见 §4）

10 阶段由 `stageService.ts` 的 `PRODUCTION_STAGES` 常量定义，`advanceStage()` 函数统一推进。核心门禁逻辑：

- **顺序校验**（全阶段）：前置阶段未 done → `STAGE_NOT_SEQUENTIAL`
- **L6 PreCut 4 项**（seq=6）：4 布尔字段 AND 校验 → `PRECUT_CHECKLIST_INCOMPLETE`
- **L7 产前样双签**（seq=7）：signedByProduction && signedByBusiness → `PP_SAMPLE_NOT_SIGNED`
- **L10 终期 AQL**（seq=10）：5 道门禁（result≠fail / criticalDefects=0 / passRate≥90% / defectRate≤3% / approvedByBusiness）→ `INSPECTION_NOT_QUALIFIED` / `BUSINESS_APPROVAL_REQUIRED`

详细门禁规则参见 [质量门禁规则.md](./质量门禁规则.md)。

## §5 交期计算公式

```
Order.productionPlanDeadline = Order.createdAt + 7d          （L2 七天计划死线）
Order.delayNoticeDeadline    = Order.dueDate - 15d           （L3 延期通知窗口）
Order.factoryVisitDate       = 手动录入（YYYY-MM-DD）          （L4 验厂提醒基准）
```

**字段层级关系**：

| 字段 | 所属模型 | 含义 | 计算方式 |
|------|---------|------|---------|
| dueDate | Order | 订单交期（业务约定交付日） | 手动录入 |
| clientDate | Order | 出厂交期 Exmill | 手动录入 |
| exMillDate | OrderLine | 行级出厂交期 | 手动录入 |
| deliveryDate | OrderLine | 行级交货日 | 手动录入 |
| shippingDate | OrderLine | 行级发运日 | 手动录入 |
| productionPlanDeadline | Order | 生产计划死线 | createdAt + 7d（下单时计算） |
| delayNoticeDeadline | Order | 延期通知窗口开启日 | dueDate - 15d（下单时计算） |
| factoryVisitDate | Order | 客户实地验厂日 | 手动录入 |

> **注**：dueDate 在 Order 模型，deliveryDate/shippingDate 在 OrderLine 模型（行级）。L1 交期锁死需同时覆盖 Order 与 OrderLine 两层字段。

## §6 schedulerService 定时检查规则

> **代码真源**：`server/src/scheduler/schedulerService.ts`（调度框架）+ `server/src/scheduler/tasks/`（21 个任务）+ `server/src/scheduler/index.ts`（注册入口，共 23 个任务）

### 6.1 调度框架

| 维度 | 内容 |
|------|------|
| 主循环间隔 | 30 秒（tickIntervalMs=30000） |
| 任务并发 | 单次 tick 内同一任务不并发（task.running 标记） |
| 失败隔离 | 单任务失败仅日志，不影响其他任务 |
| 启动行为 | 启动后立即执行一次 tick（用于崩溃恢复等启动时任务） |

### 6.2 交期相关定时任务

| 任务 ID | 检查频率 | 触发条件 | 动作 | 通知模板 | 代码文件 |
|---------|---------|----------|------|---------|---------|
| production_deadline_watchdog | 每小时 | productionPlanDeadline < today | 逾期 1-3 天 warning / >3 天 critical | 「订单 {poNumber} 生产计划超期 {N} 天」 | `tasks/productionDeadlineWatchdog.ts` |
| production_deadline_watchdog | 每小时 | delayNoticeDeadline ≤ today | critical（延期通知窗口开启） | 「订单 {poNumber} 延期通知窗口已开启」 | 同上 |
| factory_visit_watchdog | 每日 11:30 | factoryVisitDate 距今 0-7 天 | 2-7 天 warning / 0-1 天 critical | 「客户计划于 {date} 实地验厂（订单 {poNumber}）」 | `tasks/factoryVisitWatchdog.ts` |
| shipment_delay_detector | 每小时 | ETD 已过未回填 ATD / ETA 已过未回填 ATA | 1-3 天 warning / >3 天 critical | 「运单 {number} 离港/到港延误 {N} 天」 | `tasks/shipmentDelayDetector.ts` |

### 6.3 去重规则

所有 watchdog 采用「dedupKey 含 tier + 日期」去重策略：
- 同级别当天只发一次通知
- 级别升级（warning → critical）会重新通知（新 dedupKey）
- 示例：`prod:plan:${orderId}:${tier}:${todayStr}`

## §14A DR-011 生产放行独立审批

> **核心决策**（DR-011）：生产放行是独立步骤，不因商业批准自动完成。四条件同时满足 + 主管手动确认才可开工。

### 14A.1 生产放行四条件

| 条件 | 说明 | 当前状态 |
|------|------|---------|
| 内部 QC 通过 | 内部 QC 对生产准备工作评审通过 | ❌ 未建模 |
| 业务员已登记客户确认 | 业务员登记客户已确认产前样 | ⚠️ 部分实现（PreCutChecklist 门禁 7 产前样双签） |
| 产前样已封存归档 | 产前样实物已封存，归档记录完整 | ❌ 未建模 |
| 主管手动确认 | 销售主管或总领导手动批准生产放行 | ❌ 未建模 |

### 14A.2 生产放行与其他门禁的关系

| 门禁 | 关系 |
|------|------|
| 商业订单批准 | 生产放行前置（DR-009 七步分离链） |
| 产前样双签（PreCutChecklist 门禁 7） | 生产放行的子集条件（QC + 客户确认），但不等于生产放行（缺封存归档 + 主管确认） |
| 面料实际到位 | 不阻断生产放行（封样不以面料到位为前提） |

## §14B DR-012 面料开发样与 S/S 分离

> **核心决策**（DR-012）：面料的开发样阶段独立于 S/S 阶段。S/S 之后默认追加一次面料最终 QC；面料 QC 可与 S/S/RC 并行，但不可省略。

### 14B.1 面料样品链

```
开发样 → 早期生产样 → S/S 船样 → 面料最终 QC → 可选 RC 匹头样
```

| 阶段 | 说明 | QC 要求 |
|------|------|---------|
| 开发样 | 面料开发阶段样品 | 独立阶段，不属于 S/S |
| 早期生产样 | 大货生产早期样品 | 独立阶段 |
| S/S 船样 | 船样确认 | S/S 后默认追加面料最终 QC |
| 面料最终 QC | S/S 后必检 | 可与 S/S/RC 并行，但不可省略 |
| RC 匹头样 | 长期翻单 + Separates 类可选 | 独立阶段 |

### 14B.2 当前状态

| 项 | 状态 |
|---|------|
| 面料开发样独立阶段 | ❌ 未建模（当前 DevelopmentCase.type=fabric 无独立面料样品链） |
| S/S 后默认追加面料最终 QC | ❌ 未建模（当前 FabricShipmentSample 无最终 QC 字段） |
| 面料 QC 与 S/S/RC 并行 | ❌ 未建模 |

## §14C DR-013 打样收费独立记账

> **核心决策**（DR-013）：打样收费允许不收款但不得未记录。客户明确以打样费换取未来订单时，必须建立收费义务；收款可后补。

### 14C.1 记账规则

| 项 | 规则 |
|---|------|
| 样品收款 | 作为收入 |
| 样品运杂费 | 作为费用 |
| 独立记账 | 样品收款与运杂费独立记账，不得并入订单收入混算 |
| 收费义务 | 客户明确以打样费换取未来订单时，必须建立收费义务记录 |
| 收款后补 | 允许先发货后收款，但收费义务必须先行记录 |

### 14C.2 当前状态

| 项 | 状态 |
|---|------|
| 打样收费记录 | ❌ 未建模（当前无打样收费实体） |
| 收费义务 | ❌ 未建模 |
| 独立记账（收入 vs 费用） | ❌ 未建模 |

## §14D DR-014 产前样独立物料来源

> **核心决策**（DR-014）：产前样、销售样、开发样均支持替代物料。不得强制要求这些样品先行采购或占用大货采购单。

### 14D.1 物料来源规则

| 销售样 | 替代物料 | 同上 |
| 开发样 | 替代物料 | 同上 |

### 14D.2 关键原则

| 原则 | 说明 |
|------|------|
| 不强制采购 | 样品可使用替代物料，不强制先行采购 |
| 不占大货采购单 | 样品物料不得占用大货采购单数量 |
| 独立记录 | 样品物料来源须独立记录（替代物料/库存/新采购） |

### 14D.3 当前状态

| 项 | 状态 |

| 替代物料支持 | ❌ 未建模 |
