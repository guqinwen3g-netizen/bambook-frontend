> **PRD 关联**：§9.2 价格审批 5 条件（①-⑤）
> **落地状态**：⚠️ 仅 ⑤ 双轨偏差 >15%/>30% 已落地；① 折扣>10% / ② 新客首单 / ③ 改价±5% / ④ 低于成本价 4 条未接入

## §2A DR-006 价格冻结与版本纪律

> **核心决策**（DR-006）：Track A、Track B 和任何定价模型均为参考/试算，不具有自动定价权。

### 2A.1 三态价格生命周期

| 状态 | 说明 | 审批要求 | 可编辑性 |
|------|------|---------|---------|
| **草稿** | 业务员自由试算与改价 | 不触发审批 | 完全可编辑 |
| **正式承诺** | 报价对外发送、创建订单、生成合同、成为内部面料结算价 | 必须冻结该报价版本并提交领导审批 | 未批准版本不得对外发送或被正式业务单据引用 |
| **已批准** | 审批通过的正式价格 | 变更必须创建新版本并重新审批 | 不可直接修改，只能新建版本 |

### 2A.2 冻结时机

| 动作 | 冻结内容 |
|------|---------|
| 报价对外发送 | 冻结报价版本 + 价格快照 + 双轨数据 |
| 创建订单 | 冻结订单价格 + 关联报价版本引用 |
| 生成合同 | 冻结合同金额 + 价格条款快照 |
| 内部面料结算价 | 冻结内部结算价 + 关联服装订单引用 |

### 2A.3 变更规则

| 场景 | 规则 |
|------|------|
| 草稿修改 | 直接修改，不触发审批，不产生新版本 |
| 已批准价格变更 | 必须创建新版本 → 重新提交审批 → 审批通过后替换旧版本 |
| 版本追溯 | 每次变更保留前后值、变更人、时间、原因与审批证据 |

## §2B DR-007 审批路由按组织归属

> **核心决策**（DR-007）：保持"销售主管"通用角色，不新增写死的"服装主管"或"面料主管"。业务员归属的团队/部门决定其主管负责的业务线与客户。

### 2B.1 审批人解析规则

| 项 | 说明 |
|---|---|
| 审批人 | 负责团队的销售主管或总领导 |
| 单次审批 | 每次只需一位有效审批人 |
| 兜底权 | 总领导拥有跨团队兜底审批权 |
| 技术边界 | 总领导的业务审批权不得依赖技术超级管理员身份；通过业务审批 scope 和组织关系授权 |

### 2B.2 审批范围

| 价格类型 | 审批人 |
|---------|--------|
| 服装价格 | 负责团队的销售主管或总领导 |
| 面料价格 | 负责团队的销售主管或总领导 |
| 内部面料结算价 | 负责团队的销售主管或总领导 |

## §2 五条件说明（DR-007 彻底去阈值化 · 决策点 3-A）

> **§9.2 DR-007 去阈值声明（决策点 3-A）**：折扣/改价/低于成本价/双轨>15%/双轨>30%/新客首单 等所有价格偏差触发的审批，**任何偏差幅度统一走 DR-007 组织归属路由**（申请人所属部门主管，无主管或部门为财务时总领导兜底，单次一位审批人即可）。不再看阈值比例（折扣>10%/改价±5% 触发条件保留为命中判断依据，但审批路由与阈值幅度无关）；多条触发条件合并为**单个 ApprovalRequest**（不重复发单），payload.hitConditions 中标注所有命中的条件编号。

| 编号 | 条件 | 判断公式 / 触发阈值（命中判断用，不影响审批路由） | 风险等级（UI 展示参考） | 审批人（统一 DR-007） | 落地 |
|------|------|------------------------------------------|----------------------|---------------------|------|
| ① | 折扣 >10% | `discountPercent = 1 - (finalUnitPrice / catalogPrice)`；discountPercent > 0.10 → 命中 | medium 黄标 warn | 申请人所属部门主管；无主管/财务部门→总领导兜底（单次一位即可） | ❌ |
| ② | 新客首单 | `Relation.stage ∈ {Lead, Opportunity, Quotation, TrialOrder}`（非 Customer/Key/Churned）且该 Relation 下 Order 数量 = 0 → 命中 | medium 黄标 warn | 同上（统一 DR-007） | ❌ |
| ③ | 改价 ±5% | `|newUnitPrice - oldUnitPrice| / oldUnitPrice > 0.05` → 命中（Quotation→Order 转换 diff / Order 二次编辑 diff） | medium / high（参考） | 同上（统一 DR-007） | ❌ |
| ④ | 低于成本价 | `finalUnitPrice < rolledUpCost`（BOM roll-up 成本或 CostEstimate.cost）→ 命中（**即时亏损风险**） | high 红标 block（UI 最严标注） | 同上（统一 DR-007，必须审批，无豁免自批） | ❌ |
| ⑤ | 双轨偏差 >15% />30% | `deviationPercent = |trackBFinalUsd - trackAMedianUsd| / trackAMedianUsd`；>15% → warn（medium）；>30% → block（high）→ 命中 | medium / high（参考） | 同上（统一 DR-007） | ✅ |

**审批多条件叠加规则（决策点 3-A）**：同时命中 2+ 条件时 → 生成 **单个** ApprovalRequest（payload 带 `hitConditions: ["①","③","⑤"]` 数组，备注中标注所有命中的条件编号）→ reviewerId 统一在服务端 `resolveReviewerByDepartment(申请人userId)` 解析（DR-007，每次只需一位有效审批人）→ 不重复创建多条。

**兼容 Scope 命名保留（与阈值无关）**：
- `lt10_`、`gt5_` 等 scope 前缀标记为兼容保留名，实质逻辑与偏差幅度无关，全部走 DR-007 统一路由

## §3 审批人链分级定义（DR-007 组织归属版）

> **DR-007 核心**：审批路由以负责团队销售主管或总领导为准，替换旧版固定 L1/L2/L3 金额阈值层级。每次只需一位有效审批人；总领导拥有跨团队兜底权。

| 审批人 | 解析逻辑 | 可审批范围 | 超时处理 |
|------|---------|-----------|---------|
| 销售主管 | 业务员归属的团队/部门主管（通过 UserAccount.departmentId → Department.head 解析）；负责该业务线与客户 | 所有价格审批（服装/面料/内部结算价）；风险 medium/high 均可审批 | 24h 未审批 → 自动抄送总领导 + App 推送加急 |
| 总领导 | 跨团队兜底审批人（Role=总领导 或硬编码 ownerId）；不依赖技术角色身份，通过业务审批 scope 授权 | 跨团队兜底 + 被销售主管驳回的申诉 + 战略特批 | 48h 未审批 → 系统提醒；72h 未审批 → auto-reject（默认保护亏损单，需总领导手工 override） |

**审批链解析实现**（待接入 approvalPolicy）：当前 `approvalPolicy` 全局为 `manual always`（即所有审批手工指定 reviewerId）；需升级为规则驱动：`resolveReviewerFor(actionType, hitConditions, requesterDept, requesterTeam)` → 返回负责团队销售主管或总领导的 userId。

## §4 ⑤ 双轨偏差已实现细节剖析（✅）

### 4.1 实现链路

1. **A/B 双轨价完备性判断**：`quotationService.ts:125-126` `trackAOk && trackBOk`（两者都有限且 >0）才计算偏差
2. **calculatePriceDeviation 计算**：`server/src/pricing/trackAEstimator.ts` 导入（quotationService.ts:21）→ 返回 `{ deviationPercent, level }`，level ∈ {ok, warn, block}
3. **审批请求生成**：`quotationService.ts:136-152` level≠ok → `resolveActorUserAccountId` 解析 requester → 生成 approvalId
4. **同事务写入 ApprovalRequest**：`quotationService.ts:204-227` `tx.approvalRequest.create`，actionType=`quotation:price-deviation`，risk=deviation.level==='block' ? 'high' : 'medium'，payload 含双轨快照 + 偏差值
5. **发送门禁（fail-closed）**：`quotationService.ts:432-445` 若 `priceDeviationLevel === 'block'` → 查询 ApprovalRequest.status === 'approved' → 未通过则抛出 `需审批通过后方可发送` 错误
