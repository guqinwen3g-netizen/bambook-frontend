## §2 成衣业务主流程（Bulk 大货）

> PRD §5.1 真源。成衣大货是最核心的业务线，覆盖从询价到收款核销的完整链路。

### 2.1 端到端流程图

```
客户询价 → 报价 → 开发样 → 厂前样 → 签订单 → 采购物料
→ 物料确认 → 开裁 → 生产 → 中期验货（可能含客户实地验厂）→ 包装
→ 船样/大货样确认 → 终期验货 → 出货 → 报关 → 开票 → 收款 → 核销
```

### 2.2 样品流程（设计确认 vs 生产确认，DR-052/DR-054 口径）

样品拆两阶段、两概念（联动且独立）：

- **设计确认（开发域 dev）**：开发批次 `SampleBatch`（=dev batch，含确认样/封样）确认样板符合客户设计 → 转正式产品档案（ProductAsset）。面料链批次为确认单位，成衣经批次轮次；**确认锚点 = `SampleBatch.confirmStatus`**；`SampleNode` 旧节点刻度迁出（DR-054）。
- **生产确认（样品管理/生产域 sample）**：对**大货生产**的确认，由统一样品 `Sample`（pp/top/ship 类型）承载，**不进开发批次**。

| 样品 | 阶段 | 说明 | 门禁关系 |
|---|---|---|---|
| 确认样 / 封样（开发批次 dev） | 开发阶段 | 确认设计匹配客户，确认后转产品档案 | 确认锚点后转档（字段契约取确认版实际规格） |
| 厂前样 / 产前样（PP，生产确认 sample） | 签单后开裁前 | 确认生产工艺和尺寸（属生产确认） | **门禁 7**：产前样批准（双签）为开裁前置 |
| 船样 / 大货样（生产确认 sample） | 出货前 | 从大货首件抽取，确认大货质量 | **门禁 10**：终期验货前置 |

> 2026-09-11 回写：本表由旧「三级样品（SampleNode 口径）」改为 DR-052/DR-054「设计确认（dev 批次）/ 生产确认（统一样品）」两阶段口径；样品库=实物域（寄送/借阅/出库），寄样动作归开发流程。

### 2.3 验厂环节

部分客户会在生产中期安排实地验厂 + 大货检验，这是额外的质量门禁。系统通过 Order.notes 或标签标记验厂需求，Agent 提醒引擎在验厂日期前推送通知（PRD §7.1）。

### 2.4 付款条件

成衣以 T/T 60 天为主，也有 L/C 等其他方式。

## §3 面料业务主流程（投产型大货）

> PRD §5.2 真源。面料业务**不是库存销售**，是**按单投产**——客户下单后安排工厂生产，70 天生产周期。

### 3.1 端到端流程图

```
客户询价（面料） → 报价（按米/码） → 剪样/寄样 → 确认 → 签订单
→ 投产（70 天生产周期）
→ Exmill Date 前 2 周：邮寄船样并确认
→ Exmill Date 前 1 周：确认匹头样（长期翻单 + Separates 类产品）
→ 出货 → 开票 → 收款
```

### 3.2 关键节点说明

| 节点 | 时间要求 | 说明 | 系统落地 |
|---|---|---|---|
| 投产 | 接单后 | 70 天生产周期 | Order.exmillDate 记录出厂日期 |
| 船样确认 | Exmill Date 前 2 周 | 邮寄船样给客户确认 | FabricShipmentSample + Agent 提醒（§7.1） |
| 匹头样确认 | Exmill Date 前 1 周 | 长期翻单 + Separates 类产品有此要求 | FabricShipmentSample（isSeparates=true 必填） |

### 3.3 面料样品流程（与成衣差异）

| 阶段 | 成衣样品 | 面料样品 |
|---|---|---|
| 报价阶段 | 开发样（展示工艺） | 剪样（寄色卡/小样） |
| 签单后 | 厂前样（确认生产工艺） | 船样（大货首件确认） |
| 出货前 | 船样/大货样 | 匹头样（Separates 类确认） |

### 3.4 面料 QC 标准

面料 QC 不使用 AQL 抽样，而是按匹抽检（4% 抽检率），关键指标为：
- 色牢度（color fastness）
- 缩水率（shrinkage rate）
- 克重偏差（weight deviation）
- 幅宽偏差（width deviation）

QC 驻地：苏州（面料 QC），区别于温州（服装 QC）。

| FAB-GATE-B1 | 未确认 S/S 客户回复——直接拒绝正常路径出运（DR-012 待细化） | 1. S/S 寄送已超 5 天无回复；2. QC 通过；3. 业务紧迫希望先发货 | 1. 业务员正常路径出运申请 | 1. 拦截，明确门禁为"S/S 客户未确认"；2. 系统不得把"未确认"视作可发货；3. 提供"受控例外申请"入口 | DR-012：未确认时正常路径一律阻断（"未回复、明确拒绝、紧急例外"规则待补，此阶段不绕过） |
| FAB-GATE-B2 | QC 未通过或缺陷率超标——禁止出运 | 1. 面料最终 QC inspectionReport.status=Fail 或 defectRate 超标；2. S/S 已确认 | 1. 申请出运 | 1. 拦截并返回 QC_FAILED；2. 前端显示 InspectionReport 链接跳转查看疵点 | 只能走 DR-013 例外，例外必须说明越过 QC 的原因、风险、补救、责任人 |
| FAB-GATE-C1 | DR-013 受控例外推进——仅对指定订单、指定动作、指定时点开放 | 1. 3 项门禁中 1 项未满足；2. 业务员提交例外申请（拟越门禁、原因、风险、受影响对象、补救跟进责任人） | 1. 提交 DR-013 例外单；2. 销售主管或总领导审批；3. 审批通过后尝试出运 | 1. 例外单状态=Approved，绑定具体订单 ID+出运动作；2. 出运申请携带 exceptionId，后端校验并允许推进；3. 完整审计（申请人、批准人、时间、理由、越过的规则、原始状态与后续结果） | 审批 Rejected → 保持原门禁，不可再次复用未批准例外 |

## §4 Capsule 流程（主业务）

> PRD §5.3 真源。Capsule 是设计师系列/小单业务，对接大品牌客户。

### 4.1 端到端流程图

```
品牌设计师需求 → 面料推荐 → 打样 → 确认 → 小批量生产 → 出货
```

### 4.2 与 Bulk 大货的关系

- 对接的是大品牌客户的设计师线
- 客户可能从小单转化为大订单，客户关系不能剥离
- MOQ 更低（20-200 件），交期更紧
- 面料推荐是核心增值环节

### 4.3 系统处理

Capsule 订单 `businessLine = capsule`，与成衣大货共用订单模型和生产流程，但：
- MOQ 校验阈值不同（≥20 件正常接单，§9.1）
- 门禁可简化（厂前样双签可放宽）
- 面料推荐通过 AI 助手辅助（Phase 4）

## §5 拓展小业务流程

> PRD §5.4 真源。MTM 定制、周边品类、周边服务等拓展业务**不走独立流程**。

### 5.1 处理方式

在主业务流程中用备注/标签标记，仅作财务统计记录：
- 订单备注中标记 `MTM`/`周边品类`/`周边服务`
- 不触发 MOQ 校验
- 不改变生产流程
- 财务报表可按标签筛选统计

### 5.2 边界声明

拓展小业务不投入系统开发资源，不建独立数据模型，不设独立 UI 入口。仅在订单备注和财务报表标签中体现。

## §6 其他贸易（DR-028）精简流程

> **DR-028 关联**：其他贸易是完全独立业务域，非服装/面料/Capsule/拓展小业务的其他品类贸易。独立报表聚合，不混入服装/面料部 KPI。决策点 5-A 方案：轻量归集，共用表单透镜过滤，不独立建视图。

### 6.1 定位

完全独立业务域（非服装/面料/Capsule/拓展小业务的其他品类贸易），独立报表聚合，不混入服装/面料部 KPI。与拓展小业务（§5）的关键区别：
- 拓展小业务：服装/面料部内部的变种，`businessLine` 仍为 garment/capsule/fabric 之一，仅备注/标签标记
- 其他贸易（DR-028）：完全不同品类，`Order.type=Other` + `businessLine=other`，完整独立记录，有进度、有统计、有报表聚合

### 6.2 数据模型

| 字段 | 值 | 说明 |
|------|---|------|
| `Order.type` | `Other` | Order.type ∈ { Fabric, Garment, Other }（3值主分类） |
| `Order.businessLine` | `other` | businessLine ∈ { garment, capsule, fabric, other }（4值业务线标签） |

### 6.3 录入表单最小必填字段簇

从成衣/面料表单中隐藏专业字段，保留的最小字段清单：

| 字段 | 必填 | 说明 |
|------|:----:|------|
| 订单编号 | 自动 | SO-YYYYMM-NNNN，由 SequenceRegister 自动分配 |
| 负责人 | 默认当前用户所属部门 | ownerId / departmentId 自动填充 |
| 业务方向 | ✅ | 自由文本（如"机械配件出口"、"耗材内贸"等） |
| 交易对方名称 | ✅ | 关联 Customer（Relation.category=Customer）但不强制 CRM 建档，未建档可临时填备注 |
| 交易对方国家 | ✅ | 同上 |
| 订单总金额 | ✅ | 币种 + 金额（currency / totalNet 字段） |
| 预期交付日期 | ❌ | 可选 dueDate（YYYY-MM-DD） |
| 备注说明 | ❌ | 自由文本 specialInstructions |

**隐藏的专业字段**：面料规格（fabricCode/fabricContent/width/gsm）、成衣生产跟单（sizeBreakdown/productionSteps/styleNo/bomItems）、样衣阶段（全部）、Exmill Date、客户 PO 日期等非通用字段。

### 6.4 列表/看板视图

共用订单列表页/生产看板，通过 `businessLine=other` 的 Tab/过滤透镜切换：
- **订单列表页**：在现有 Fabric / Garment / Other 类型 Tab 中选择 Other → 自动应用 `businessLine=other` 过滤透镜
- **生产看板泳道**：仅保留最精简 4 阶段（Draft→Confirmed→Fulfilled→Closed），不显示面料裁床/QC 等服装/面料专属阶段——前端按 `Order.type=Other` 条件渲染，阶段列表隐藏到 4 列

### 6.5 360°全链路

共用 360° 视图（`/api/v1/orders/:id/context`），但按 `Order.type=Other` 条件渲染：
- **保留的通用区块**：基本信息 / 关联采购 / 出运记录 / 收付款 / 附件
- **隐藏的专业区块**：生产管线（ProductionStage 10 阶段）/ 面料明细 / QC 门禁（InspectionReport）/ 装箱明细（ShipmentCarton）/ 样品链（DevelopmentCase + SampleBatch，设计确认；实物样品走样品域）/ BOM

### 6.6 审批规则

| 规则项 | 说明 |

## §7 成衣 vs 面料线关键差异矩阵

> PRD §5.2 真源。此矩阵是系统行为分支的业务真源。

| 维度 | 成衣 | 面料 |
|---|---|---|
| 计量单位 | 件（PC/SET） | 米/码（M/YD） |
| 业务模式 | CMT/FOB 加工 | 按单投产，70 天周期 |
| MOQ | 200-300+ 件 | 800 米+，主力数千米 |
| 样品流程 | 开发样→厂前样→船样/大货样 | 剪样→船样→匹头样 |
| QC 标准 | AQL 抽样 + 疵点 | 色牢度/缩水率/克重/幅宽 |
| QC 驻地 | 温州 | 苏州 |
| 报关 HS Code | 61/62 章（服装） | 51/52/54/55 章（面料） |
| 付款条件 | T/T 60 天为主 | T/T 30 天为主 |
| 关键时间节点 | 交期（deliveryDate） | Exmill Date + 船样/匹头样倒计时 |
| 生产阶段 | 10 阶段 + 3 门禁 | 投产→船样→匹头样→出货 |
| 退税率 | 按成衣 HS Code（通常 13%-16%） | 按面料 HS Code（通常 13%-16%） |

## §8 流程与状态机联动

### 8.1 订单状态机（6 态）

> 详细状态机定义见 [订单状态机](../04-模块设计/03-订单与生产/Orders-订单管理/订单状态机.md)
>
> **代码真源**：`orderLifecycleService.ts` `VALID_ORDER_STATUSES = ['Pending', 'Confirmed', 'Production', 'Shipping', 'Delivered', 'Alert']`

```
Pending ──▶ Confirmed ──▶ Production ──▶ Shipping ──▶ Delivered
   │            │              │             │
   └────────────┴──────────────┴─────────────┘
                       │
                       ▼
                    ╳ Alert ╳  ──▶ 可恢复到 Pending/Confirmed/Production/Shipping
```

**说明**：订单状态机聚焦"履约推进"维度（6 态），发票/收款/利润由独立实体（Invoice / PaymentVoucher / OrderProfitSheet）跟踪，不纳入订单状态机。取消订单通过软删（`deletedAt`）实现，不新增 Cancelled 状态。

### 8.2 关键状态转换与自动动作

| 状态转换 | 触发条件 | 自动动作 | 事件发布 |
|---|---|---|---|
| Pending → Confirmed | PO 审核通过 | 初始化 10 阶段生产进度；预留面料/辅料库存 | OrderConfirmed |
| Confirmed → Production | 门禁 1（裁剪前 PreCutChecklist 4 项全通过） | 通知 QC 安排中期验货 | OrderStatusChanged |
| Production → Shipping | 门禁 2（终期验货 InspectionReport result=pass） | 通知跟单安排订舱/报关 | OrderStatusChanged |
| Shipping → Delivered | 运单确认收货 | 触发应收发票草稿（Invoice Draft） | ShipmentCompleted |
| 任意 → Alert | 异常触发（质量/交期/信用问题） | 通知管理层介入 | OrderStatusChanged |
| Alert → 恢复 | 异常解决 | 恢复到异常前的非终态 | OrderStatusChanged |

**发票与收款联动**（独立于订单状态机，由 Invoice/PaymentVoucher 实体跟踪）：
- Shipping → Delivered 时自动创建 Invoice（Draft 态）→ 签发后启动账期计时（T/T 30/60 天）
- PaymentVoucher 核销 → 更新客户信用记录 → 触发 PaymentReceived 事件
- Delivered 后财务确认 → 自动生成 OrderProfitSheet（订单利润表）

### 8.3 事件总线联动（L1-L10）

> 详细联动定义见 [10 条事件联动](./10条事件联动（L1-L10）与事件总线.md)

业务流程中的关键联动：
- **L1 订单确认 → 初始化 10 阶段生产管线**：OrderConfirmed 事件触发
- **L2 生产完成 → 创建运单 Draft**：ProductionCompleted 事件触发
- **L3 运单交付 → 创建发票 Draft**：ShipmentCompleted 事件触发
- **L4 发票签发 → 启动账期计时**：InvoiceIssued 事件触发（由通知系统覆盖）
- **L5 收款凭证 → 自动核销到关联发票**：PaymentVoucherCreated 事件触发
