## 一、已拍板口径（2026-09-16 业务方现场定，勿再改）

### 口径 A · 对账多币种（业务方原话 + 落地解读）

> 「就是美元，一般是发过去给客户用来收汇用的……如果公司内部结算的话，那肯定都是转成人民币呀。
> 而且要注意，就是中间涉及到一个退税的问题……如果是销售的对账的话，都是美元，也可以转换成多币种展示，
> 这个都没有问题的。销售的这种东西，然后，如果销售的已经确认汇结过汇的，那直接按照结汇的这个汇率敲定。」

落地为三条：
1. **销售对账口径 = 原币（主要是 USD）**，同时**必须支持多币种分组展示**——不再出现"USD 10000 + CNY 5000 = 15000"。
2. **内部结算口径 = 折人民币（CNY）**。
3. **折算规则：已结汇的按结汇汇率锁定**（结汇汇率是已实现的、确定的，不用任何估算汇率）；
   **未结汇的不折算**，按原币展示。
   - 汇率来源：`fxReconciliationService` 汇率链 **C 段（结汇）** 的 `documentRate`
     （`FxChainSegment.stage` 的结算段，实现时先核对 `fxReconciliationService.ts:60` 上方
     `FxChainSegmentType` 的枚举值再取值——**不在本设计里猜**）。
   - 结汇金额 = 该段 `foreignAmount × documentRate`（CNY）。

### 口径 B · 多币种开票

> 「我不觉得会有多币种的情况，因为采购这些基本上都是人民币……在中国就是人民币，在国外那就是美元。」

落地：**保持现状语义——一张票只许单币种**，多币种按币种分开开（`sceneInvoiceService.ts:131` 的
`MULTI_CURRENCY` 硬拦不动）。**但要修掉 preview 显示 0 的 bug**：多币种候选行时按币种分组展示，
并明确提示"多币种请按币种分开开票"，让 preview 与 create 的口径一致（现在是 preview 说 0、点下去才说不行）。

### 口径 C · 三单一致核对

**比金额 + 数量 + 品名，不一致只预警（不阻断）**。
理由（业务方认可）：三单对不上常有正当原因（赠品、样品不计价），阻断会卡死正常业务。

### 口径 D · 收汇 ↔ 报关 FOB 勾稽

- **容差：5% 或 500 美元（取大者）以内算正常，超出只预警**。
- **CIF 单必须先减掉运费和保费再比**（收汇对应的只是货值，CIF 里的运费保费是代垫的）。
  - 运费/保费来源：运单上已采集 `Shipment.freightAmount` / `Shipment.insuranceAmount`
    （含各自币种列），实现时按币种对齐后再剥。

### 口径 E · 退税算不出来时

**显式报缺 + 补齐后一键重算**（不用市场汇率/默认退税率静默兜底——算错的退税额比没有更危险）。
- 缺什么就写什么：缺结汇/发票汇率、或缺某 HS 的 `exportTaxRebateRate`。
- 需提供**重算入口**（现在 `declarationId` 唯一 + "不可重复生成"拦截，重算要走"更新既有草稿"而非新建）。

## 三、T7-1 设计（下一批就做它）

### ①对账跨币种裸加

**改 `server/src/finance/reconciliationService.ts`**（纯只读服务，不写库）。

现状问题点（复核确认）：
- `:190-195` `invoicedAmount` 累加不看 `inv.currency`
- `:204-205` `paidAmount` 累加不看币种
- `:258` / `:280` 差异判定 `invoicedAmount.gt(orderAmount)` / `paidAmount.gt(invoicedAmount)` 跨币种裸比
  → **产出假的"超开/超收 critical"**
- `:422-424` 客户级 `totalOrderAmount/totalInvoicedAmount/totalPaidAmount` 跨订单跨币种裸加

改造：
1. **订单级**：`invoicedAmount` / `paidAmount` 改为**按币种分组**
   （新字段 `invoicedByCurrency` / `paidByCurrency: Array<{currency, amount}>`）。
   保留 `invoicedAmount` / `paidAmount` 的**语义收窄**：仅当全部同币种（或为空）时才等于该币种金额，
   **跨币种时置 `null`**（绝不返回无意义数字）。
2. **差异判定**：只在**同币种内**比。跨币种时 `currency_mismatch`（`:213-234`）**升级为阻断级**：
   不再参与金额比较，message 明确写"跨币种无法比对金额"。
3. **客户级汇总**：`totalOrderAmount/totalInvoicedAmount/totalPaidAmount` 同样改为按币种分组的
   `Record<currency, {order, invoiced, paid}>`；跨币种不出总和。
4. **内部结算折 CNY（口径 A-2/A-3）**：新增 `settledCny` 汇总——取汇率链 C 段（结汇）
   `foreignAmount × documentRate` 累加；未结汇部分**不计入** `settledCny`，只在原币分组里体现。
   - 复用现成的 `reconcileOrderFx`（`:352`）结果，不新造汇率来源。

**前端**：对账页改成分币种展示（原币 + "已结汇折 CNY"两栏）。前端消费点实现时先 grep 确认。

**验收口径**：
- 单币种场景：所有现有行为与数字**完全不变**（回归钉）。
- 跨币种场景：不再出现任何 `critical` 金额类差异；改为 `currency_mismatch` 且说明无法比对。
- 已结汇订单：`settledCny` = 结汇外币额 × 结汇汇率（真库可算）。

### ②多币种开票显示 0

**改 `server/src/finance/sceneInvoiceService.ts:84-86` + `components/FinanceManager.tsx:3762`**。

- preview 返回 `summaryByCurrency: Array<{currency, amount}>`（替代现在的 `summaryAmount`/`summaryCurrency`），
  多币种时**不再返回 0**。
- 多币种时附带提示（与 create 的 `MULTI_CURRENCY` 同口径）："多币种请按币种分开开票"。
- 前端分币种渲染。

**验收口径**：多币种候选行 → preview 各币种金额正确、无 0；单币种行为不变。
