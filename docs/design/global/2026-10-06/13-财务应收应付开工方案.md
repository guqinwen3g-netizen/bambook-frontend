# 财务应收与应付开工方案（草案 v0.1）

**状态：**业务职责和多笔核销规则已由总账确认；具体票据字段、余额及冲回边界需用户评判。
**业务决定真源：**[对话设计决策总账](./08-2026-10-06-对话设计决策总账.md) §4.5、§5.4.1、§8.3–8.4。
**相关交接：**开发 CI 由业务员在开发模块发出；货物出运 CI 由后勤单证制作；供应商应付依据由业务采购/加工单及供应商增值税发票进入财务。

## 1. 财务模块范围

财务只管理真实票据、收付款、公司账户余额、供应商/客户余额和票款核销事实，不接管业务履约状态。

- **应收**：查看业务/后勤已经制作的 CI 和其他合法应收票据；登记到账；把一笔收款分配到多张 CI，也允许一张 CI 由多笔款分次核销。
- **应付**：登记供应商开具的国内增值税发票及其对应采购/加工合同或应付项；记录我方实际付款；一笔付款可分配核销多笔供应商应付，一笔应付也可分次付款。
- **账户**：登记公司实际银行账户余额相关交易事实；余额由期初余额与实际收付款流水计算，不由业务模块或用户改写系统算出的余额。
- **财务不做**：不开销售 CI，不制作 Packing List、采购合同或委外加工合同；不判断订单生产完成或出运完成；不以已收款作为开始生产、解除 QC 阻断或订单结案的条件。

## 2. 首页与工作区结构

### 2.1 财务首页

首页固定为四个独立入口：

1. **应收待办**：新进已开票据、即将/已到期未核销票据、未分配收款。
2. **应付待办**：已登记供应商应付、付款条件/日期、部分或未付款余额。
3. **收付款记录**：公司账户中的真实收到/支付交易及附件凭证。
4. **账户与余额**：客户应收余额、供应商未付余额、公司银行账户余额及未分配款。

首页上方指标：应收未收总额、应付未付总额、未分配客户到账、可用公司账户余额。每个指标点开都可追溯到具体票据/交易明细，不显示无法解释的数字。

### 2.2 列表通用交互

- 默认列表按到期/待处理时间排序，未处理项优先。
- 统一支持关键字（票据号、客户/供应商、合同/PO、出运号）、币种、来源模块、日期范围、未结状态过滤。
- 列表将“票据应收/应付”和“资金收/付款”分开显示，不混成一条无法追溯的账。
- 订单/开发页面仅只读显示由财务写入的财务状态；任何业务员不得从业务模块改金额到账或核销事实。

## 3. 应收票据登记

### 3.1 票据进入财务

- 开发/寻样产生的对客 CI：业务员从开发模块按全案费用开具并提交，生成财务待登记应收。
- 货物出运 CI：后勤单证在出运模块按实际出运制作；文件退回业务员并同步财务待登记应收。
- 其它业务票据：由产生该票据的业务模块按其职责制作后进入财务，不能要求财务先创建一张 CI 再让业务回填。
- 财务收到的记录包含来源单据和附件；财务登记是“确认财务台账已纳入”，不是再制作/改写原票。

### 3.2 应收票据字段（推荐）

| 字段 | 类型/来源 | 规则 |
|---|---|---|
| 财务票据记录号 | 系统生成、只读 | 财务内部身份，不替换对客 CI 编号 |
| 原始票据类型 | 来源带入 | CI/其他已开票据；不在财务页选择“新建 CI” |
| CI/票据编号 | 业务/后勤来源，必填 | 与文件一致；编号重复时提示并阻止第二张同来源票据 |
| 开票/签发日期 | 来源字段 | 只读显示；错误更正回来源业务单据走票据版本更正流程 |
| 客户/付款方 | 来源带入；财务校对 | 默认从合同/订单/开发案带入，允许为实际付款方指定关联关系需确认 |
| 票据金额/币种 | 来源带入，必填 | 财务不得自行覆盖票据金额；系统用应收原币核销 |
| 来源业务 | 自动关联 | 开发案、出运/Shipment、订单/合同等；至少一个准确来源 |
| 票据附件 | 业务/后勤来源文件 | 版本可读和下载；不让财务重建内容 |
| 合同付款条件/到期日 | 来源条款/财务登记 | T/T、L/C 等按业务合同记录；到期日需要有可追溯依据 |
| 登记人/登记时间 | 系统生成 | 保留实际财务操作者和时间 |
| 应收状态 | 派生、只读 | 未收/部分收款/已核销；状态由金额分配计算 |

入口按钮：票据来源记录的 **“财务登记”** 进入信息复核；按钮 **“确认纳入应收”** 才写入财务台账。重复来源或重复 CI 编号时，提供已有票据链接，不重复建账。

## 4. 客户收款和应收核销

### 4.1 收款登记

财务点击 **“登记客户收款”**，输入一笔实际到账交易：

| 字段 | 类型/必填建议 | 说明 |
|---|---|---|
| 到账日期 | 日期，必填 | 实际银行入账日，不是付款承诺日 |
| 付款方 | 客户/其他付款方，必填 | 若付款方和票据客户不同，明确选择关系/备注，不自动冒充同一方 |
| 收款公司账户 | 账户选择，必填 | 记入公司真实账户余额 |
| 收款金额/币种 | 正数货币金额，必填 | 记录原币；不得自动等同任何一张 CI |
| 银行流水号/参考号 | 文本，建议必填 | 防止重复录入；相同账号/币种/日期/流水号重复时警告 |
| 到账凭据 | 图片/PDF/银行文件，可上传 | 记录来源与操作者 |
| 关联 CI | 初始可不选 | 可在本次录入之后分配；支持一笔到账对多张 CI |
| 备注 | 选填 | 例如客户、合同或付款原因 |

### 4.2 分配/核销界面

收款保存后进入 **“分配到应收票据”**：

- 顶部显示本次收款金额、币种、已分配、剩余未分配金额。
- 下方仅列同客户/明确相关付款方关系且同币种的未结 CI；每行显示 CI 号、来源、应收金额、已核销、未核销、到期日、本次分配金额。
- 财务可分配一笔款至多张 CI，分配金额不得超过本次收款剩余额或该 CI 未核销额。
- 一张 CI 未结余额允许被后续另一笔收款继续分配。
- 未分配余额保留在该客户/付款方账户下作为未分配资金，不能消失或自动冲抵非匹配 CI；是否允许手动留作客户预收款需确认。
- 点击 **“确认核销分配”** 后写入本次分配事实并更新 CI 已收/未收余额；后续更正需冲回/新增分配流水，不能删除原交易。

## 5. 供应商应付登记

### 5.1 来源和职责

- 供应商合同/采购单/委外加工单由相应业务组建立和对外发送；财务从来源链接查看合同付款条件。
- 供应商提供国内增值税发票后，财务登记票据并形成/核对应付。财务不是向供应商开发票。
- 一家供应商可以同时有多个采购/加工合同和多笔应付账；财务看供应商累计余额，也可下钻每一来源。

### 5.2 应付记录字段（推荐）

| 字段 | 类型/来源 | 规则 |
|---|---|---|
| 应付记录号 | 系统生成 | 财务内部主键 |
| 供应商 | 来源带入/供应商选择，必填 | 一个应付关联准确供应方 |
| 供应商增值税发票号 | 文本，必填建议 | 支持图片/PDF附件；重复编号警告 |
| 发票日期、税额/金额、币种 | 发票录入，必填 | 金额、税额、税率记录发票原文；其完整性政策待确认 |
| 来源采购/加工合同 | 选择已审批业务单据，可多项对应需确认 | 一笔发票若覆盖多个合同，逐项分配应付金额，不能只挂供应商总额 |
| 付款条件 | 从业务合同带入 | 记录 TT/账期/分期及其来源条款 |
| 到期日期 | 合同日期推导或财务录入 | 保留计算依据；修改留痕 |
| 应付金额/未付余额 | 系统计算 | 应付金额减去核销付款，不允许手工改余额 |
| 发票附件 | 文件上传，必填建议 | 证明供应商对我方开票 |
| 登记人/时间 | 系统审计 | 财务角色实际登记 |

应付来源待办可按供应商、合同、到期日聚合，但每笔应付保持自己的金额、币种、付款条件和来源条目，不能因为同供应商而把采购与委外加工合并为一个业务类型。

## 6. 供应商付款和多账核销

财务点击 **“登记供应商付款”**，记录一笔实际公司付款：

| 字段 | 类型/必填建议 | 规则 |
|---|---|---|
| 付款日期 | 日期，必填 | 实际银行支付日 |
| 收款供应商 | 供应商选择，必填 | 默认从选择的应付记录带入 |
| 付款公司账户 | 公司账户选择，必填 | 付款后计算账户余额 |
| 付款金额/币种 | 正数货币金额，必填 | 可能只覆盖部分未付账，也可能结清数笔应付 |
| 银行流水号/参考号 | 文本，建议必填 | 重复防护 |
| 凭据/付款回单 | 文件附件，建议必填 | 说明实际支付事实 |
| 关联应付记录 | 多选分配 | 一笔付款可分至多条同供应商、同币种应付 |
| 备注 | 选填 | 付款情况说明 |

分配界面显示本次付款金额、已分配/未分配、供应商每笔应付的未付余额和到期日。不得按“一合同一次付款”强迫业务录多笔；不得超额核销；付款未分配金额需保留并警示，而不是丢弃。用户说“供应商给我们开增值税发票、我们财务付款”，付款事实和供应商发票事实分开记录。

## 7. 公司账户及余额视图

- 公司每个银行账户显示账户名、币种、期初余额、累计收款、累计付款、系统计算余额；一个账户只使用一种余额币种。
- 账户交易只能通过登记实际收款、实际付款或明确期初余额建立；业务合同、CI、供应商发票本身不直接改变银行账户余额。
- 客户应收与客户资金余额分开：每客户的未核销 CI、未分配收款分别显示。
- 供应商应付与公司资金分开：每供应商未付应付、公司各账户余额并列显示。
- 多币种之间不自动按当前汇率折算为同一余额。汇率、换汇损益与跨币种冲销不在本次确认的 MVP 内，需明确是否要做。

## 8. 各业务模块的财务回读

| 来源模块 | 由谁生成票据 | 财务收到什么 | 原业务模块可读回 |
|---|---|---|---|
| 开发与寻样 | 业务员在开发流程生成开发费用 CI | CI 号/金额/客户/币种/费用清单/开发案引用及文件 | 是否已登记、已收款/未收余额；业务员继续联系客户催款 |
| 大货出运 | 后勤单证在出运工作台生成 CI | 本批实际出运 CI、来源合同、装箱金额/币种、shipment 和条目链接、文件 | CI/PL 版本、客户发送状态、财务登记/回款摘要；不改变生产/出运事实 |
| 采购/委外加工 | 业务组发合同；供应商开增值税发票；财务登记 | 供应商、发票、应付明细、合同付款条件和来源 | 已登记应付、付款状态、未付余额；不改变采购/加工交付状态 |
| 面料佣金模式 | 业务员在所有出运批次结束后提交一次佣金结算 | 佣金计算依据、最终出运额×佣金率、供应商应付我方佣金票据/应收来源 | 已提交/已收款/未收余额；不按每批出运频繁结算 |

财务视图写回由财务记账服务权威产生；来源模块只读投影，必须能直接返回财务票据/收付款分配明细。

## 9. 状态和按钮矩阵（建议）

| 对象 | 状态 | 主要按钮 | 结果 |
|---|---|---|---|
| 票据来源项 | 待财务登记 | 查看来源 / 确认纳入应收 | 建财务应收记录；不生成新 CI |
| 应收 CI | 未收 | 登记收款 / 查看票据 | 新建实际资金交易并进入分配 |
| 收款 | 未分配 | 分配到 CI / 保留未分配 | 多对多分配，按原币保持余额 |
| 收款 | 部分/全部分配 | 确认核销分配 | 新增核销关系，重算剩余 |
| 供应商票据 | 待登记 | 登记应付 | 保存供应商票据与应付来源 |
| 应付 | 未付款/部分付款 | 登记付款 | 新建账户付款交易，进入应付分配 |
| 付款 | 未分配 | 分配到应付 | 多账核销，余额留痕 |
| 账户交易 | 已记账 | 查看凭据 | 只读，不物理删除；错误更正用冲回/更正动作 |

## 10. 安全与一致性

- 原始 CI/Packing List 和供应商发票采用文件版本；财务不得改写来源文件或金额。
- 应收登记、收款流水、核销分配、公司账户变动须在一个受保护的写入过程中保持一致；任一环节失败都不能出现钱已分配但账户余额未记账的部分提交。
- 每笔资金写入记录操作者、时间、公司账户、客户/供应商、原币金额、银行凭证、来源、分配和冲回事实。
- 余额是交易和核销记录的投影，不提供任意编辑入口。
- 重复到账/付款提交以银行流水号和交易字段提醒，避免重试造成重复到账/出款。
- 账户资金、付款回单及客户财务信息仅限有财务权限人员读取；业务员看到的是自己来源记录所需的最小票据/核销摘要。
- 财务不得使业务模块因财务屏幕/服务暂时不可用而回滚已经发生的生产或实际离港事实；跨模块事件需可重试、幂等。

## 11. 必须覆盖的财务连续验收

1. 开发业务员生成开发 CI；财务待登记中出现原票文件并登记应收；客户一次收款部分核销；开发页显示未收余款。
2. 后勤单证生成出运 CI 并退给业务员，CI 自动进入财务待登记；财务无权改 CI 内容；业务发送 CI 不等待财务先建票。
3. 同一个客户有 3 张 CI，两笔收款分配覆盖其中两张；第三张部分未收；回款、票据余额和业务回读一致。
4. 一张收款分给同币种多张 CI；余额有结余时保留未分配并可后续处理，不自动错配。
5. 一个供应商有多份采购/加工合同和多张增值税发票，一笔付款覆盖其中多笔；供应商余额精确扣减，订单交付状态独立。
6. 一个应付分两笔付款，一笔只付部分；系统正确显示剩余应付与付款账面。
7. 账户期初余额已登记时，收款增加、付款扣减；不把 CI 开票金额当银行到账，不把供应商开票金额当已付款。
8. 不同币种收款不得在未设汇率规则情况下自动核销不匹配币种 CI；提示用户币种冲突。
9. 财务误选付款方、金额、账号、票据重复或上传文件失败时，写入有明确错误，禁止账户/应付/应收部分记账。
10. 操作者无财务权限时不能登记票据、款项或余额；业务员仍可从原业务链接查看已授权范围的财务摘要。
11. 冲回/更正后保留原票据/资金流水和旧分配；供应商或客户余额按新增冲回事实重新计算。
12. 佣金模式在最后一批出运前不产生分批结算待办；全部批次出运后由业务一次提交，财务登记并核销。

## 12. 需要用户评判后冻结的项目

1. **未分配收款/付款余额：**推荐留在客户/供应商资金账户中作为未分配余额，可之后再选票据核销，不能自动分配。客户款在明确成为预收款前不要自动当预收款。是否接受这一口径？
2. **客户/供应商第三方付款方：**实际付款方不等于票据客户/供应商时，需记录 `付款方` 与业务方的关联；是否要求每次上传代付/代收依据？
3. **多币种：**推荐 MVP 只支持同币种核销；不做汇率、换汇损益、跨币种自动换算。是否接受？
4. **供应商应付的来源粒度：**建议每张增值税票逐行分配到一个或多个已审批采购/加工合同及对应来源条目；若供应商发票同时覆盖多个项目、税额和费用的分配依据怎么录？
5. **应付形成时点：**是业务合同/收货先形成预计应付，收到供应商增值税票后财务确认正式应付；还是只有发票到财务才形成应付余额？建议分为业务预计付款提醒与财务已入账应付两种视图，但不把两者混成法定余额。
6. **错误冲回权：**建议原财务经办人可发起冲回，财务负责人/复核人批准后由财务入账；真实人员及是否要审批须按公司现行授权确认。
7. **银行账户初始化：**账户、期初余额、开户行/尾号和是否按币种独立账户的维护人/初始化证据待确认。
8. **税费内容：**国内增值税票登记需要哪些税率、税额/抵扣字段；出口 CI 是否要登记其商业金额之外的本地税费，待实际财务要求确认。
9. **供应商付款审批：**现有讨论明确财务根据合同期限/TT和账户余额实际处理付款，但付款前是否另需业务/老板审批，尚未冻结。

## 13. 当前实现对照重点（非验收）

- 样品/开发费用流程仍可能把 CI 制作跳到财务模块；必须按本总账的“业务先制单、财务登记”修正责任归属。
- 出运 CI 现有服务依赖财务应收记录；方向反了，必须改成 CI 来源创建财务待登记应收。
- 现有 AR/AP 分配接口有部分能力不代表 UI、权限、多账/多票读回和账户余额已闭合。
- 对部分分配、资金未分配余额、并发、重复提交、冲回、跨币种、付款方与票据对象不同的具体实现均需在决策闭合后验证。
