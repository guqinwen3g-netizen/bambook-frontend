## 7. 待决定与可先推进事项

**定案（2026-10-17，用户在「供应商/关系 包 A」工单中确认；以下 P1–P13 均为【定】）：**

- 【定】**P1 回价字段**：规格、单位、单价、币种、是否含税（含税须填税率）必填；MOQ、交期、报价有效期、付款条件可以记“供应商未提供”；转采购时必须补齐交期和付款条件。
- 【定】**P2 比价**：只按原币、原单位并排展示，系统不换算汇率，也不推荐选哪家。
- 【定】**P3** 回价不设“候选”状态。
- 【定】**P4 价格可见范围**：看回价价格须有 `procurement:read`；普通业务员只看本业务组，主管、财务、管理员看全部。
- 【定】**P5** 同一供应商每个业务组设一名经手人。
- 【定】**P6** 业务员（`suppliers:write`）维护档案、认证、联系人；主管（`suppliers:admin`）办评级、暂停、拉黑、恢复，必须填原因。
- 【定】**P7 换厂**：在途采购换供应商由采购经手人发起，主管审批；供应商被暂停或拉黑时，给在手采购的经手人派待办。
- 【定】**P8** 换厂时原单剩余量终止，另开新单给新供应商，新单回链到原单。
- 【定】**P9** 余量关闭或转新单，由经手人发起，主管审批。
- 【定】**P10** 预付不跨供应商转移；差价和补偿走索赔。
- 【定】**P11 可转交对象**：客户、供应商经手、订单、报价、商机、开发案、面料寻样。
- 【定】**P12 交接流程**：接收人可以拒收；发起人在对方接收前可以撤回；3 个工作日无人接收就转主管待办；主管可以强制指派。交接上线后取消直接改负责人。
- 【定】**P13 交接后**：原负责人保留只读；已归档到该对象的邮件对接收人可见；跨业务组接收须接收方主管确认。

## 8. 后续实施包（包 A 已按 §7 定案实施 P5、P6，其余未开工）

各包验收分四层：**命令**（服务端成功与拒绝结果）、**读投影**（不同权限账号看到的字段）、**真实页面**（从角色首页走到完成并回到来源）、**角色**（两个不同真实账号办理同一业务）。“拟定”指新协议，尚不存在；“失败/重试/并发”写的是拟定协议应有的确定结果，实施时须逐条成为命令层测试。

### 包 A：负责人与供应商稳定引用

- **角色与入口：**业务员在供应商档案、开发新建、客户/订单编辑中选择负责人或供应商；主管在成员管理查看。
- **已有命令：**`market.supplier.save`、`customer.update`、`order.update`、开发创建。**拟定：**供应商经手人字段（按业务组）；负责人账号引用 + 名称快照；开发工厂存供应商 ID；负责人变更事件记录新旧值。
- **状态→动作→写入→回程：**保存档案 → 校验账号为工作区成员且有效 → 写引用与快照 → 处理记录显示“负责人：A→B” → 档案与列表回读新负责人。
- **失败/重试/并发：**账号非成员或已停用 → 拒绝并提示，不写入；同名账号 → 必须按账号选择，不按名称匹配；两人同时修改 → 后提交者因版本变化被拒并重载；同一请求重试 → 结果相同不重复记事件。
- **历史数据：**~~旧姓名/名称原样保留并标“未关联账号/未关联供应商”~~——已由包 A 工单取代：当前为开发/测试模拟数据，直接改种子与演示数据，**不做旧数据兼容**，不出现“未关联账号”类状态。
- **验收：**命令层拒绝非成员与过期版本；读投影按账号列出某人负责的对象；页面改名后开发与采购引用不丢；两个账号互改时事件可追溯。
- **可先推进：**负责人账号引用、开发工厂 ID、变更事件。**依赖：**P5（两组经手人形式）；P6 不阻塞字段，只阻塞授权调整。（P5、P6 已于 §7 定案，包 A 按定案实施。）
- **包 A 范围补充（工单）：**成员“业务组”（面料/成衣，可多选）由所有者在成员管理页设置；供应商每组一名经手人，存账号 ID + 显示名快照，服务端校验为本工作区有效成员且属于该组。客户、订单、开发案、面料寻样、商机负责人统一为账号 ID + 显示名；开发工厂存供应商 ID。本包保留直接改负责人，交接流程（P11–P13）不在本包。

### 包 B：询价、比价与采购/报价承接

- **角色与入口：**对应业务组业务员从订单行、开发/寻样、报价条目或供应商档案发起；在询价详情登记回价、比较、选定；审批仍在采购单。
- **已有命令：**`fulfillment.procurement.save/submit`、报价核算保存。**拟定：**询价创建/编辑、线下发出登记、回价登记/更正、选定/取消选定、转采购草稿、报价引用回价。
- **状态（拟定）：**草稿 → 已发出（逐家）→ 已回价（逐家，可多次版本）→ 已选定 → 已转采购/已被报价引用；可关闭（填原因）。
- **写入与回程：**回价写入逐家版本与附件；选定写理由并保留落选回价；转采购在采购草稿保存回价引用，采购详情可回到询价，询价显示生成的采购单；报价引用在报价核算冻结快照并回链。
- **失败/重试/并发：**供应商已暂停/拉黑 → 不能发出或选定，已有回价保留；回价已过有效期 → 显示过期，选定须重新确认有效期；订单已关闭或取消 → 不能转采购；同一回价重复转采购 → 返回已生成的草稿，不建第二张；两人同时选定 → 后者因版本变化被拒。
- **权限：**沿用 `suppliers:read`、`procurement:write` 等现有分区，不扩大价格读取，直到 P4 决定。
- **验收：**命令层拒绝暂停供应商与重复转采购；读投影无权账号看不到回价；页面同一需求多家回价并排、选定、转采购、回看来源；后续回价变化不改已报价/已审批记录。
- **可先推进：**询价对象、线下登记、原币并排比较、转采购与报价引用。**依赖：**P1（回价暂缺项校验）、P4（价格可见）、P3（采购候选状态）；P2 只影响可选折算；系统外发依赖 #122 合入及另包。

### 包 C：在手业务责任交接

- **角色与入口：**主管或本人在成员管理按人员列出在手；业务员在关系页按对象发起；接收人在“我的工作”看到待接收。
- **已有命令：**`customer.update`、`order.update`（直接改负责人）。**拟定：**交接发起（对象清单、依据、接收人或队列、期限、缺项）、接收、拒收、撤回、超期升级。
- **状态→动作→写入→回程：**待接收（原负责人仍负责）→ 接收（写新负责人与事件，旧负责人保留在历史）→ 发起人看到结果；拒收或撤回 → 负责人不变，发起人收到原因。
- **失败/重试/并发：**接收人停用或非成员 → 不能发起；对象已关闭 → 从清单排除并说明；交接期间对象被修改 → 接收时按当前版本展示变化；同一对象已有未完成交接 → 拒绝第二份；重复接收 → 返回已接收结果。
- **权限：**发起、接收、强制指派分别定权（S1 L195），具体授权待 P12、P13；未决定前不实现强制指派、不迁移历史消息可见性。
- **验收：**命令层拒绝重复交接与停用接收人；读投影接收前后负责人显示正确；页面从人员入口到接收后回到来源对象；两个账号交接后历史保留原操作人。
- **可先推进：**按人在手清单（依包 A）、交接单与接收/回程。**依赖：**P11（对象范围）、P12、P13；D02、D16。

### 包 D：在途采购换供应商

- **角色与入口：**对应业务组业务员在采购单详情发起“换供应商”；供应商暂停/拉黑弹窗列出在手采购并跳转；审批人在审批待办处理。
- **已有命令：**`payable.purchase.cancel`（无执行的已批准合同取消，预付退款或同供应商转抵）、`fulfillment.procurement.save/submit/decide`、收货、结算、票据、付款命令。**拟定：**原单余量终止（依 P8/P9）及新单回链。
- **输入：**原采购单、终止原因、未交余量、新供应商（须可用且未冻结）、新价格/交期/条件。**输出：**原单（保留已批版本、已收事实与财务记录）+ 新单（同一订单行来源，回链原单）。
- **状态→动作→写入→回程：**原单已批准 → 提交换供应商申请（原单进入变更待审，原约定收货仍可登记）→ 审批通过：原单余量终止、新单进入已批准待线下发送；驳回：原单不变 → 订单行显示两张采购单及累计数量，供应商档案在手列表更新。
- **财务：**已收票据、结算、付款留在原合同；剩余预付只走现有退款或同供应商转抵，跨供应商处理与差价/补偿待 P10，不自动转账、不改历史。
- **失败/重试/并发：**新供应商已暂停/拉黑 → 拒绝；原单有待审付款申请 → 须先撤回；审批期间原单到货超过余量 → 只据实登记并标差异，审批时重新校验余量；重复提交 → 返回同一申请。
- **验收：**命令层拒绝冻结供应商与未撤回付款申请；读投影订单行累计数量正确；页面从供应商暂停到采购单换供应商、审批、回到订单行；财务记录不被改写。
- **可先推进：**无交付合同复用现有取消 + 新单回链。**依赖：**P7、P8、P9、P10。
