# 样品仓库开工方案

状态：设计规格 v0.2，面料/成衣档案粒度与开发版本、产品档案的关系已经由用户确认。类别与形态清单保持可扩展；本方案不把未逐项列举的类型当成封闭枚举。

本方案把全公司的实体样品放在同一仓库台账中查询和流转，同时保留每件或每份样品的真实身份。成衣逐件记录；面料按同款产品或准确开发版本归档，再按样品形态记录数量/长度。开发、订单、QC、数字档案与仓库读取同一来源关系，不重复登记、重复扣减或混淆开发版本。

业务决定依据：[对话设计决策总账第七节](08-2026-10-06-对话设计决策总账.md#七样品仓库)。与旧版“样品实体档案库重构方案”冲突时，以总账和本方案中标注的最新状态为准；旧文档中的专职保管人、结构化库位、盘点调整、逐张样卡条码等设计不属于本方案。

## 1. 范围与角色

### 1.1 本模块负责

- 统一查询所有类别的实体样品，包括开发样、订单生产样、客户来样、工厂/供应商样、销售展示样、参考样及其他实物。
- 保留样品身份、来源、产品/版本归属、各形态数量或长度、照片、自由文本位置和出入/移位记录。
- 允许业务员在来源业务中登记样品并自动同步同一台账；允许在仓库中手工建档或补录。
- 允许从原出库记录登记借出样品的分次归还；开发、订单等来源业务产生的寄样由来源模块发起并同步数量。

### 1.2 不由本模块处理

- 不代替开发案/订单管理样品的业务要求、费用、QC 发起、需求方确认或履约门禁；来源业务保留这些动作。
- 不代替 QC 创建或保存第二份样品对象；QC 报告引用本模块中的准确实物/版本。
- 不实现盘点、库存数量调整、差异修正、未入库或在途状态；不设样品保管人、样品仓库管理员或其他专职仓库账号。
- 不给每张面料色卡、样卡或挂钩样单独贴码。

### 1.3 操作者

样品业务由业务员操作。读取和写入继续服从现有账号权限；不得新增“样品保管人/样品仓库管理员”角色，也不得默认只允许记录创建人查看。准确账号与权限分配由全站账号/权限矩阵统一校对。

## 2. 记录对象与数量口径

### 2.1 样品档案归属

一份仓库档案必须能够回答“它是哪一个明确产品，或哪一个明确业务版本”。档案归属按以下优先顺序确定：

1. 已转产品档案的样品，关联一个准确的数字产品档案及其公司产品/销售编码、供应商编码；保留原开发版本和工厂来源。
2. 尚未转产品的开发样，按一个准确工厂版本建立独立开发样档案。不同轮次或工厂版本不得合并。
3. 订单样品关联准确订单条目/生产分支；若同一条目已经关联数字产品档案，仍同时保留订单来源。
4. 客户来样、供应商样、历史样等手工档案保留其录入来源；没有系统来源时标记为手工/无来源，不伪造业务编号。

产品化只增加准确的产品身份与回链，不复制同一批实体样品、数量或流转历史。QC 通过的具体开发版本可以转档；是否得到客户选用不是转档门槛。

### 2.2 面料档案

- 一个同款/同型号的正式面料产品形成一个面料档案；尚未转产品的开发面料按准确的开发版本形成独立档案。一个开发版本下不同形态的 SampleBatch 归入同一版本档案，不按批次拆成多个面料档案。
- 面料档案详情按形态分行汇总库存，例如米样、色样、手织样、样卡、挂钩样、先锋样、船样、匹头样或其他用户确认的形态；每行有自己的单位、数量/长度和位置。
- 米样使用米为单位，保留小数长度；裁片、色样、手织样、卡片类使用“份”。同一档案内的米数与份数分别显示，不相加。
- 同一面料形态若存放位置不同，分别保留库存位置行，在档案页顶部按形态合计可用量；用户可展开查看各位置明细。
- 同一面料产品或准确开发版本下的多次收样、不同形态和不同位置都保留在同一个档案中；余额按形态、单位及自由文本位置分别显示，不复制档案身份。确属不同款/不同开发版本时不得仅凭名称相似合并。

### 2.3 成衣档案

- 每件实际成衣样是台账中一条独立记录，数量固定为 1，系统独立生成编号。
- 同一款、同一尺码、同一来源、同一批次收到两件，仍是两条记录，有各自照片、位置和流转历史；不得保存为一条 quantity=2 的成衣档案。
- 每件可记录尺码、颜色、来源版本/订单分支、照片、自由文本位置和备注。缺少某项时显示“未记录”，不得从其他款式/尺码推断。
- 产品档案可作为多件成衣实物共同指向的产品身份；台账仍逐件显示与操作。

### 2.4 其他样品类别

样品仓库覆盖公司实际产生的各种实物样，不限制为开发样。类别与形态需可扩展；任何固定选项集只是便捷常用项，不能阻止业务员记录其他类别或形态。当前设计不将源码里已有枚举等同于用户已确认的封闭目录。

## 3. 页面与导航

### 3.1 仓库首页

入口仍对应真实侧边栏“样品仓库”，不新增“全景看板”等页面。打开默认显示实体样品台账，不默认进入开发业务样品流程。

页面自上而下固定为：

1. 页面标题“样品仓库”及副标题“Sample Library”。
2. 顶部操作区：`刷新`、`新建样品`。无写权限时保留可读界面并隐藏/禁用 `新建样品`，显示清楚的无权提示。
3. 类别入口切换：面料、成衣及其余由用户确认的类别；切换保留上次筛选状态但清空不适用筛选。
4. 检索区：关键字、形态、来源、状态筛选、排序、当前结果数；筛选项组合为“同组多选 OR、不同组 AND”。
5. 结果区：面料显示档案级汇总行；成衣显示逐件行；不混合不同计量单位做总量。
6. 选择结果后打开详情侧栏；关闭详情回列表时保留滚动位置、查询条件和分页。

### 3.2 检索与列表字段

全局关键字检索档案编号/产品编码、名称、供应商编码、开发案/轮次/准确版本、订单号、客户/供应商名称及自由文本位置。查询不得搜索无权读取的关联对象。面料按档案分页，不按形态行分页；成衣仍按每件实物分页。

面料列表每行列：

| 列 | 内容 |
|---|---|
| 面料档案 | 档案号、名称、照片缩略图；有正式产品档案时显示公司产品码与供应商码 |
| 来源 | 开发版本、订单条目，或客户/供应商/手工来源；可点击打开有权限的原记录 |
| 样品形态与余额 | 每种形态一行摘要，例如“米样 12.5 米可用”“色样 3 份可用”；不同单位绝不合计 |
| 位置 | 当前形态位置摘要；多位置显示“多个位置”，点详情查看明细 |
| 最近流转 | 最近入库、借出、归还、寄出或移位时间和操作人 |
| 行操作 | `打开档案`；有写权限时可进入对应形态的借出/寄出/移位操作 |

成衣列表每行列：

| 列 | 内容 |
|---|---|
| 实物编号 | 唯一编号，不允许同一行表现为多件成衣 |
| 样品 | 名称、照片缩略图、用途/形态 |
| 规格 | 尺码、颜色及已登记的识别规格 |
| 来源 | 准确开发版本、订单条目/工厂分支，或手工来源 |
| 位置 | 自由文本位置；空值显示“位置未记录” |
| 状态 | 在库、借出中、已寄出或其他经用户确认并允许的状态 |
| 最近流转 | 最近动作时间和操作人 |
| 行操作 | `打开档案`；有写权限时可对本件执行借出/寄出/移位 |

结果区定义四种反馈：首次加载显示骨架和“正在读取样品”；读取失败显示错误原因与`重试`；过滤后无结果显示“没有符合条件的样品”与`清除筛选`；全库无记录显示“还没有样品档案”及`新建样品`（有写权限时）。

### 3.3 档案详情

详情侧栏首屏显示：`返回列表`、档案名称/实物编号、类别、来源/版本或产品档案、当前可用状态、位置摘要、`编辑资料`、`查看来源`。

面料详情自上而下显示：

1. 产品/版本身份卡：公司产品码、供应商码，或开发案号、轮次、工厂、版本；关联订单来源作为次级链接。
2. 形态库存表：`形态`、`总量`、`已借出`、`可用`、`单位`、`位置`、`最近更新`、`操作`。一行对应“档案 + 形态 + 位置”；顶部另显示按形态合并的汇总。
3. 该档案照片、描述、来源人/公司、备注及已登记属性。
4. 流转记录，按时间倒序显示操作类型、数量/长度、去向、经手人、时间、位置变化和来源单据链接。

成衣详情首屏显示唯一实物编号、照片、尺码/颜色、来源版本或订单分支、当前自由文本位置、在库/借出/已寄出状态。以下分节依次为：`实物资料`、`来源与产品档案`、`流转记录`。产品图与本件实物照片必须明确区分。

没有权限的来源链接不显示敏感摘要；点击无权链接显示“你没有查看该业务记录的权限”，不返回未经授权的快照字段。

## 4. 登记与来源同步

### 4.1 来源模块自动同步

- 开发与寻样在准确工厂版本下登记实物；订单履约在准确条目/工厂分支下登记订单样品。来源保存一次后，仓库读到同一批实物和流水，不要求第二次重复建档。
- 面料来源事件按准确产品/开发版本及样品形态增加数量或米数；成衣来源事件按实际件数为每件生成一条独立记录及编号。
- 来源事件、库存变化、流转流水、审计和幂等键必须在同一事务里完成；重试相同请求不得重复增加或扣除数量。
- 来源页面仍负责其业务属性与通知；仓库页只读回显来源字段，不能反向改写开发版本、订单数量、QC 结果或需求方确认。

### 4.2 手工新建/补录

首页`新建样品`打开新增表单。共用字段：样品大类、名称、形态、来源类型、来源人/公司、可选客户/供应商、照片、备注、自由文本位置。

面料新增时先选一个准确身份：正式产品档案、未产品化的准确开发版本、准确订单条目/工厂分支，或手工档案；不得用名称相似自动归并。无来源或无法关联系统对象时，业务员可建立手工档案；后续同款登记可显式选择该档案。再录一条或多条形态库存，每行填写`形态`、`初始数量/长度`、只读`单位`、自由文本`位置`。米样的数量是大于 0 的小数米；份类的数量是大于 0 的整数份。不同单位分行。

成衣新增时每件单独保存并生成一个档案编号，数量固定为 1；表单可提供“连续新增下一件”按钮，不能提供“件数=2 后生成聚合行”。每件分别填写名称、尺码、颜色、来源/版本、照片及位置。

无系统来源的历史样和临时来样允许手工补录。发现可能重复时显示候选档案与其来源/形态/位置，提供`打开候选`、`仍然新增`；重复提示不阻止合法补录。来源身份准确且已存在时，默认进入该档案增加形态库存，不另造重复档案。

按钮为`取消`、`保存并登记入库`。保存成功显示新编号及`打开档案`；返回列表并选中新档案。保存失败保留输入；服务端结果不确定时显示`核对并重试`，沿用原幂等请求，不得生成重复档案。

## 5. 借出、寄出、归还与移位

### 5.1 发起位置

- 开发寄样从开发版本/工厂任务发起；订单样品寄送从准确订单条目/工厂分支发起。来源模块选择样品实物并填本次数量/米数，一次提交同时保存业务寄样记录、仓库出库流水及余额变化。
- 普通借出、无来源的寄样以及补录后的样品流转从仓库详情发起。
- 来源模块执行的寄样不再要求仓库二次确认。系统必须检查可用量，不能超出可用数量或长度。

### 5.2 借出

详情中的`借出`打开借出表单。成衣先勾选一件或多件具体实物，每件以独立编号显示；面料先选形态/位置，再填数量或米数。字段：借用人、去向/用途、是否预计归还、预计归还日期（仅选择预计归还时必填）、本次数量/长度、备注。单位只读来自对应档案/形态。

校验：借用人必填；数量为正；不得超过该对象/位置的可用量；设置预计归还时归还日不得早于借出日期。提交成功立即计入借出余额并写入不可覆盖的借出流水，显示`借出已登记`与借出流水详情。

### 5.3 不归还的寄出

`寄出`表示永久送出，不等同借出。成衣选择准确单件；面料选择形态/位置并录本次份数或米数。字段：收件人、客户/公司（可关联客户）、寄出日期（默认当前日期）、本次数量/长度、寄出原因/备注。不得要求仓库管理员二次确认；不必添加在途状态或系统邮件发送。

寄出保存后立即扣减同一库存、写入寄出流水，并在该来源档案内显示已寄出记录；可用量不足时整笔拒绝且不部分扣减。由开发/订单来源发起的寄样使用对应来源单据和费用记录，不在样品仓库重复登记第二次业务费用。

### 5.4 分次归还

仅对原借出流水登记归还。面料选择该借出形态并填写本次归还份数/米数；成衣选择原借出中仍未归还的准确单件。字段：本次实还量、归还日期（默认当前日期）、归还位置（自由文本）、状态备注。保存成功新增一条归还流水并增加原位置/新位置可用量，不覆盖原借出事实。

可重复部分归还，直至累计归还量等于原借出量；禁止超过未归还量；成衣实物若缺失不得通过普通归还操作虚增库存。历史出借人、每次归还经手人、数量和时间均可追溯。

### 5.5 移位

详情中的`移位`填写新位置自由文本和移位备注；保存前显示原位置→新位置。保存追加移位记录（操作人、时间、原位置、新位置），不改变数量/状态。无固定“仓库-区域-货架-层-格”必填结构。

## 6. 字段、校验与异常反馈

| 字段 | 类型/来源 | 必填 | 校验与显示 |
|---|---|---:|---|
| 档案编号 | 服务端生成，唯一 | 自动 | 成衣逐件唯一；面料档案唯一；保存后不可手改 |
| 名称 | 文本，来源页带入或手工填写 | 是 | 去首尾空格，不得为空；同名本身不拦截 |
| 顶层类别/形态 | 当前表单选择 | 是 | 仅使用经用户确认的选项；`其他`允许填写自定义名称 |
| 来源类型与来源引用 | 来源模块带入或手工选择 | 否 | 有来源时保存准确 ID、显示名称与只读来源快照；不得用名称模糊替代关联 ID |
| 产品档案/开发版本/订单条目 | 业务链接 | 适用时必填 | 每条实物/形态余额只归属一个明确产品身份或来源版本；并保留其他关联来源 |
| 数量 | 整数或小数，按形态确定 | 是 | 份/件为正整数；米为正小数；不得与不同单位合并 |
| 位置 | 自由文本 | 可选 | 不校验预设库位语法；未录入显示“位置未记录” |
| 照片 | 图片附件 | 可选 | 失败须说明格式/数量/大小；列表显示占位文字，不拿产品图冒充实物图 |
| 借用人/收件人 | 文本或客户档案 | 借出/寄出必填 | 清空或未选客户不影响记录临时个人收件人 |
| 预计归还日期 | 日期 | 条件必填 | 仅预计归还的借出需要；不归还寄出不显示 |
| 操作人/操作时间 | 当前登录身份/服务端时间 | 自动 | 不可由业务员伪填；所有流水保存真实账号 |

共通错误：没有写权限→“当前账号没有样品操作权限”；数量不足→显示当前可用量并不保存；原档案已更新→提示先刷新后重试；网络结果不确定→保留同一请求键并显示刷新核对入口；无来源记录权限→拒绝查看并不暴露关联字段。

## 7. 状态和业务门禁

- 可用量只由首次登记、来源样品登记、借出、寄出和归还流水计算；不存在直接覆盖总量或盘点调整按钮/API。
- 面料按形态/位置/单位分别计算。成衣每件独立，借出中即是那件实物状态变化。
- 开发或订单来源寄样必须绑定准确样品记录。QC 和需求方确认状态由原来源业务保存并显示；仓库不自行设置“QC通过/客户通过”状态。
- QC 通过可由原开发/订单流程发起产品档案转档；样品台账不提供绕开 QC 的产品化按钮。
- 不做待收、未入库、在途或到货确认状态。实体记录在业务员登记样品时建立；直接从来源流程寄出的实物以同一次事务记录寄出及余额变化，不先生成虚假的在库数量。
- 已借出、已寄出和在库的状态命名/过滤方式，需与第 10 节类别与形态方案一并确认；任何用于“退役/封存”的额外状态暂不纳入 MVP。

## 8. 审计、可靠性和数据归属

- 所有来源样登记、手工新增、借出、寄出、归还和移位均记录操作者、服务端时间、准确对象、数量/长度、旧值/新值及来源请求。
- 已发生流水不允许编辑或删除；更正只能通过明确的后续业务动作，不提供库存调整替代。
- 与来源业务的初始样品登记或寄样必须幂等；请求重复提交时回读原结果，不重复建档/扣减。
- 数量变更、流水写入、来源事件和审计在同一事务提交；任一失败则全部回滚。
- 身份、权限、来源版本和库存余额在最终写入前重新检查；账号切换或数据版本变化时不提交旧表单。
- 图片文件只保存私有对象引用和元数据；未经来源权限验证不展示业务附件。

## 9. 必须覆盖的验收场景

1. 同一服装版本收到两件完全相同衣服：仓库中出现两条不同编号的实物，各自可单独查看、借出、寄出和登记位置。
2. 同一面料产品登记米样 12.5 米、色样 3 份、挂钩样 2 份：一个产品档案内分形态显示；各单位分别累计，不创建每张卡的编号。
3. 同一面料存在两个位置：档案汇总仍正确；形态明细能看到每处余额和自由文本位置。
4. 开发案多个轮次/工厂版本：每个准确版本保持独立档案；其中 QC 通过的版本转产品档案后可按产品码查询，原开发来源仍可追溯且库存未复制。
5. 开发或订单页发起部分寄样：来源业务记录和样品余额一次性同步；网络重试不重复扣减；库存不足时不产生半笔记录。
6. 通用借出后分两次归还：每次增加归还流水；不超过借出量；未还余额正确。
7. 有无来源的手工样都可建档；潜在重复只提示、允许继续；准确来源重复请求命中同一结果。
8. 任一业务员执行样品操作，无新增专职角色；无权限账号不能写或读取受限来源资料。
9. 样品移位保留前后位置及经手人；无需建立固定货架层级。
10. 前端不存在盘点调整入口，后端也不能通过旧 API 改库存；无在途/未入库/到货确认状态。

## 10. 已确认的目录规则与实现约束

### 10.1 面料档案分组

- 产品化面料按准确 `ProductAsset` 身份归档；面料档案展示公司产品/销售编码、供应商编码以及其对应的开发来源。
- 未产品化的开发面料按准确开发版本归档。同一版本的不同形态批次归入同一个档案；不同版本不可合并。转产品档案只建立身份回链，不复制同一实物、库存或流转流水。
- 订单样品若有准确产品身份，归入该产品档案并保留订单条目/工厂分支来源；没有产品身份时须按准确条目/分支留档，不得按整张订单粗略合并不同产品。
- 手工样可以显式加入准确已有档案，也可以建立手工档案。系统可显示可能重复项供业务员判断；重复提示不阻止补录，也不因名称相似自动合并。
- 档案是业务身份与查询展示边界；库存流水仍以真实登记的样品/形态/位置记录保存。列表一行代表一个档案，详情内按形态与位置显示现存总量、可用量和单位。

### 10.2 类别与形态目录

- 常见面料形态包括米样、色样、手织样、样卡、挂钩样、先锋样、船样、匹头样及业务员填写的其他形态；这些常见项不构成封闭清单。
- 米样单位为米，允许小数；色样、手织样、样卡、挂钩样及其他剪片类按份管理。系统不逐张给样卡贴条码。相同布款/产品档案下可同时显示多类形态及各自余额。
- 成衣实物必须逐件建档、独立编号和自由文本定位；不得把两件相同服装合成一个 quantity=2 的实物档案。
- 样品仓库本身还要容纳订单生产样、客户来样、供应商/工厂样、参考样、辅料和其他公司实物样。常用入口可以提供面料、成衣、辅料/其他等宽类，形态值须允许按实际补充；不因本规格列举不全拒绝登记。
- 任何业务来源已有准确类别/形态时优先带入。若业务员手工新增其他类别/形态，保持其填写值并供后续筛选，不自动改写成猜测的既有类型。

### 10.3 明确不纳入 MVP

- 不做盘点调整、库存差异修正、在途/未入库/待收货状态、逐张面料样卡编码或复杂库位层级。
- 不增加样品仓库专职岗位或账号；由业务员操作并按现有权限记录经手人。
- 本方案没有待用户拍板的面料分组或常见形态封闭清单。实现过程中若遇到本总账与本规格之外、会改变业务边界的新规则，应回到设计确认；不影响本范围的技术选型由实现方按最简可维护方式完成。

## 11. 对现有实现的定向改造

以下只列当前已发现的硬差异；实现者须在开始前重新核对工作树和最新代码，不得覆盖用户已有改动。

| 范围 | 当前差异 | 目标 |
|---|---|---|
| 样品主档 | 一行既承担档案身份、产品身份和库存形态；面料聚合视图不足 | 支持开发版本/产品档案身份与多形态余额的清楚读写映射 |
| 成衣登记 | 一个来源 batch 可以以数量大于 1 合并到一行 | 每件生成独立 Sample item、独立编号和流转/位置 |
| 面料数量 | 米样长度与整数件数并存，列表可能读错整数数量 | 用户界面统一按单位显示米数或份数；米样仅对其形态使用 Decimal 长度流水 |
| 位置 | UI 强制区域/货架/层/格，移位要求结构层级 | 仅自由文本位置；迁移保留旧位置字符串，不推断新层级 |
| 盘点调整 | UI、API 与服务开放数量修正 | 删除面向用户的入口和写路由/服务能力；旧数据保留，不提供绕过接口 |
| 归还 | 现有借出流水只支持一次整笔归还 | 增加追加式分次归还流水，正确累计每种单位 |
| 类别枚举 | 常见项不等于封闭清单，实际要覆盖多种业务来源和实物样 | 提供宽类和常见形态快捷值，同时允许业务员录入/筛选自定义类别与形态；不得凭源码枚举拒绝其他实物样 |
| 权限和角色 | 当前统一使用 `sample:room:write`，账号授予范围未核实 | 不新建专职角色；与现有业务员账号和全站权限矩阵核实 |

数据库迁移不得虚构库存、来源或库位。迁移前按类别统计现有 `quantity>1`、米样双口径、重复来源、空库位、旧盘点流水及封样字段；每类写出可逆迁移或历史保留策略，先保全审计再改模型。无法自动拆出不同真实位置的成衣，不得根据件数编造具体库位。

## 12. 本轮手工登记与轻量提示实施选择（2026-10-07）

本节是依本轮全站落地授权补齐的最小界面选择，对应总账 7.1、7.3、7.5；不把匹配算法写成此前用户已确认的业务公式。

- 手工登记可无业务来源，也可明确关联可见客户或已有准确产品档案；开发批次返样仍由开发原生入口产生，不能用普通登记伪造已验证返样凭据。
- 新增时，在名称输入后按当前可读样品目录查询同实物分类的相近名称，最多显示五条已有档案的编号、名称、登记日期及已有来源名称。来源明确不同的条目不提示；缺少来源不能推断相同来源。名称相近不合并身份，不复制数量，不构造新的来源事实。
- 提示文案说明“仅供核对，可以继续登记不同实物”。成衣同款多件仍允许每件另建档案。提示读取失败时如实显示暂不可核对，不显示“无重复”，也不阻止真实实物补录。
- 身份、权限、名称、实物分类或来源变化后，旧请求结果立即失效；关闭窗口后不再展示迟到的数据。提示使用现有受控读接口，不扩大来源、照片或库存可见范围。
- 借出、寄出、归还继续写同一实物与原借用的数量流水。米样以精确十进制米数验证；分次归还保留每次实际操作者、时间和请求依据，不把请求重试变成第二次归还。

验收包括：同款两件可分别建档；相近提示不拦保存；迟到的旧名称查询不回显；2.75 米借出 0.75 米后两次归还及永久寄出保持精确余额；来源返样、QC 任务与仓库引用同一实物；撤权旧会话不得继续借还或修改档案。
