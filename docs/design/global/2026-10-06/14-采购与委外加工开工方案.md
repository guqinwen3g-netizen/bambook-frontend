# 采购与委外加工开工方案（草案 v0.1）

**状态：**业务边界、组别责任、合单条件和审批时点已确认；表单、到货/加工结果、损耗和具体批准人尚待用户评判。
**业务决定真源：**[对话设计决策总账](./08-2026-10-06-对话设计决策总账.md) §5.4、§5.4.1、§8.4。
**相关方案：**[大货订单管理](./12-大货订单管理开工方案.md)、[QC 工作台](./11-QC工作台开工方案.md)、[样品仓库](./09-样品仓库开工方案.md)、[财务应收应付](./13-财务应收应付开工方案.md)。

## 1. MVP 责任和边界

- 采购与委外加工是两个不同业务类型。采购买入物料/成品；委外加工将原料交给加工方处理并收回加工结果。不能仅因为同一供应商承担两种工作，就把两类合同合成一个流程。
- 业务责任按来源业务组：面料事项由面料组经办；服装辅料、服装 CMT 加工由成衣组经办。没有专职统一采购角色；用现有业务员账号操作。
- 采购/加工需求从准确订单行或公司内部业务对象发起。允许兼容需求合并成同一张供应商单据，但每一行仍保持独立的来源条目、数量、单价、日期、费用归属和回写目标。
- 供应商正式订单/采购合同/委托加工合同由对应业务组制作并线下发送；MVP 不集成在线签署、供应商账号、在线回执。
- 对外承诺前由授权业务审批人审批；获批后再制作/发送正式供应商合同。供应商票据、财务应付、付款和核销由财务模块管理。
- 物流收货/加工回交的真实数量回到原采购/加工行和订单条目；原料直接送加工方不伪造我方入库，先入我方仓库再交加工方则登记两次真实交接。

## 2. 入口和主工作区

### 2.1 来源入口

- 成衣订单条目的履约步骤根据纯 CMT、辅料+CMT、全包模式，分别出现工厂加工、辅料采购或内部面料订单链接。
- 面料条目的履约步骤根据成品采购、原料+加工、佣金模式，出现对应的采购/委外加工/佣金责任。
- 业务员点击 **“新建采购需求”** 或 **“新建加工需求”** 时，准确订单条目已锁定并进入需求行；不允许从全局采购页创建一个没有来源的订单行。内部采购/备货可从内部订单条目发起。
- 成衣全包模式下，面料采购由面料组通过“面料订单”入口建立；成衣订单仅关联准确面料订单行和需求量，不得在服装订单中代为采购。

### 2.2 业务组工作台

顶部有两个不可合并的入口：

- **采购订单**：采购已制成品/原料/辅料。
- **委外加工单**：原料交外部加工后取回成品或半成品。

每个入口有 `需求草稿`、`待审批`、`已批准待供应商确认`、`供应履约中`、`已完成` 视图。实际空状态和排序建议按最近到期时间以及异常优先。

列表显示：单据号、业务类型、负责业务组、供应商、币种、合同付款条件、主要交付地点、要求交付日期、来源订单行数、审批状态、供应商承诺日期、累计交付/加工回交数量、差异/待处理标志。

## 3. 采购与加工单据对象

| 对象 | 业务含义 | 建立/维护方 | 关键来源和回程 |
|---|---|---|---|
| 需求行 | 某一订单条目需要采购/加工的一个项目 | 对应业务组业务员 | 订单行、履约模式、规格和费用责任 |
| 采购单主单 | 发给同一供应商的一组兼容采购需求 | 对应业务组 | 多采购行、供应商、币种、付款条件、主要交付地点 |
| 采购单行 | 一项物料/成品采购承诺及分批交付记录 | 对应业务组 | 单一需求行或同项需求组，数量/价格/日期和交付结果 |
| 委外加工主单 | 发给同一加工方的一组兼容加工需求 | 对应业务组 | 多加工行和加工方承诺 |
| 委外加工行 | 一个原料/规格送交加工处理及其回交结果 | 对应业务组 | 加工需求行、原料来源/交接、工序、加工价、加工结果 |
| 供应商确认记录 | 线下取得的接单/交期/要求确认 | 对应业务组 | 供应商承诺、日期、联系记录/附件 |
| 交付事件 | 一次实际采购到货、原料交接或加工回交 | 对应业务组登记 | 对应采购/加工行、数量、时间、实际地点及凭据 |
| 供应商税务票据 | 供应商对我方开的国内增值税票 | 财务 | 对应一笔/多笔应付及采购/加工合同，进入财务 |

采购单和委外加工单可互相链接，但不得共用同一个主单类型。采购原料后委外加工时明确记录“采购行 → 原料去向/交接 → 加工行”。

## 4. 兼容需求合单

### 4.1 必须一致的主单合并条件

允许合并的需求必须同时满足：

1. 同一业务类型：采购只和采购合并；加工只和加工合并。
2. 同一供应商。
3. 同一币种。
4. 同一付款条件。
5. 同一主要交付地点。

任何一项不同，创建另一张单据。满足这些主单条件后，不同产品、规格、工序、数量、单价、交付日期、来源订单/条目仍各自保留在独立行。

### 4.2 交互建议

点击 **“合并兼容需求”** 后显示候选行清单及合并键差异。只有五项相同时候选框默认勾选并允许加入；不一致项直接显示“不兼容：币种不同”等原因，不提供覆盖字段强行合并。

合并不会改写各来源需求的业务责任；订单行能查看自己需求已进入哪张采购/加工单、各自实际交付数量和费用。

## 5. 采购需求与采购单

### 5.1 采购需求行建议字段

| 字段 | 类型/必填建议 | 说明 |
|---|---|---|
| 来源订单/内部条目 | 自动带入、只读 | 可返回准确订单行/内部备货行 |
| 采购用途 | 单选建议 | 成衣辅料、面料原料、面料成品、内部备货、其他 |
| 物料/成品名称及规格 | 文本/产品档案来源 | 明确采购对象；不得只写“辅料” |
| 数量/单位 | 正数十进制、必填 | 和来源订单单位或物料单位对应 |
| 供应商 | 供应商选择、必填 | 当前供应商或候选供应商；是否先需求后定供应商待定 |
| 币种/单价 | 合同货币及十进制 | 主单汇总前保持兼容币种；按合同确认 |
| 费用承担条目 | 自动带入、可多来源拆分 | 逐条归入对应订单/成本对象，不混账 |
| 要求交付日期 | 日期、必填建议 | 对外承诺值审批锁定 |
| 主要交付地点 | 地点文本/资料选择、必填建议 | 主单合并字段；加工方或我方地点依实际选 |
| 交付方式/地址联系人 | 文本/地点选择 | 需要供应商交付信息 |
| 规格附件/参考文件 | 多文件 | 图样、技术说明、客户要求等 |
| 备注 | 文本 | 只补充信息，不替代规格字段 |

### 5.2 采购单主单字段建议

- 采购单号（系统自动）、采购业务类型、发起业务组/经办人。
- 供应商、币种、付款条件、主要交付地点（合并键）。
- 联系人、地址和电话（由供应商档案带入，可按本单更新并留档）。
- 合同/订单日期、要求交期范围、关联订单/内部需求列表。
- 采购单各行：来源对象、产品/物料、规格、数量/单位、单价、行金额、交期、本行交付地点、附件/说明。
- 采购条款文件/附件、版本、审批记录、供应商线下确认日期与承诺日期。
- 已收/待收数量由交付事件汇总，不可手改累计。

不同采购行可要求不同到期日；交期汇总建议显示最早/最晚日期，列表能逐行下钻，不把行间差异揉成一个虚假的单一交期。

## 6. 委外加工需求和加工单

### 6.1 加工行建议字段

| 字段 | 类型/必填建议 | 说明 |
|---|---|---|
| 来源订单/条目/履约分支 | 自动带入、只读 | 费用/结果回到正确来源 |
| 加工方 | 供应商选择、必填 | 生产加工方及联系人 |
| 加工对象/规格/工序 | 文本和分类选择、必填 | 例如原料、颜色、整理或服装 CMT；不得把采购商品当加工任务 |
| 投入物料 | 选择原料/采购行或登记实际外部来料 | 输入来源可为我方采购、订单/客户来料或实际其他来源 |
| 投入数量/单位 | 数量和单位 | 与交出实物事实一致 |
| 交付路径 | 单选：直接送加工方 / 先入我方仓库再领出 | 根据真实发生登记，不强行所有原料过我方仓库 |
| 加工费用 | 数量/计价方式/金额 | 加工费与原料采购费用分开归集 |
| 要求完成/回交日期 | 日期 | 对外承诺审批字段 |
| 回交地点 | 地点选择/文本 | 我方仓库、下个工厂或其他真实地点 |
| 加工要求/参考附件 | 多文件/说明 | 工艺、色样、技术资料等 |

### 6.2 原料交接

- **供应商直送加工方：**采购交付事件的实际收货地点记录为加工方，随后加工行引用该到货；不得虚构仓库入库/出库。
- **原料先到我方仓库再交加工方：**记录供应商到我方仓库的采购收货，然后记录从该实际库存交给加工方；库存出入与加工交接引用同一原料身份和数量。
- 客户来料或其他非采购原料必须标明真实所有方和来源，不伪造我方采购成本。
- 加工回交根据实际数量逐次登记，允许少数批次；不要求提前建立完整多批次计划。

原料接收、在制、加工耗损、余料回库、损坏/短交的字段目前未定；此流程不能先用“收货完成”糊成一项，需要确认 MVP 最小交接记录后再实施库存联动。

## 7. 审批、正式供应商文件和修改

### 7.1 审批门禁

- 采购单/委外加工单在形成对外承诺、发给供应商前必须审批。
- 提交审批时锁定供应商、币种、付款条件、交付地点以及单行物品、规格、数量、价格、交期等关键承诺字段。
- 通过后业务组按已批内容生成相应采购订单或委托加工合同，下载后线下发送供应商；系统不要求在线签署/已发送回执。
- 业务组在线下取得供应商确认后，录入供应商确认结果和承诺交付日期。
- 如果供应商承诺与已批数量、单价、供应方或日期不同，业务员申请修改并重新审批；不重新审批的实际交货分批不构成承诺变更。

### 7.2 审批页面建议

待办卡显示单据类型、供应商、总额/币种、来源订单/条目、交付地点、最早交期和提交人。审批详情逐行展示承诺，显示订单对应关系和本次/历史版本差异。

按钮：

- **批准并允许发出**：记录审批人、角色范围、时间、版本和条目快照；解锁下载/制作供应商合同。
- **退回修改**：必须填写原因；恢复业务员编辑，保留退回版本；重提创建新审批轮次。
- **查看来源订单**：只读返回来源条目。

批准人、业务负责人/老板范围以及能否批准本人创建的采购/加工单，待与真实账号权限规则对齐；不能从订单主单审批权限自动推导采购/加工审批名单。

## 8. 供应商确认和交付登记

### 8.1 供应商确认

业务员在审批通过详情点击 **“登记供应商确认”**：填线下确认时间、确认/拒绝结果、承诺交期（逐行）、供应商联系人和沟通凭据。确认日期可晚于审批日期。

如果供应商拒绝或交期不接受，当前单据保持“待业务处理”，业务员可以联系替代供应商并提交变更审批；不能直接改供应商字段继续执行。

### 8.2 分批交付/加工回交

- 采购到货或加工回交每次都从对应单据行点击 **“登记本次交付”**，填写实际数量、单位、日期、交接地点、接收/交付方和凭据。
- 同一行允许少数分次记录，每次新增交付事件；累计量自动合计并与承诺量对比，不覆盖历史。
- 记录完后回写准确来源订单行/面料内部订单的已采购/加工状态与当前可用数量。
- 交付超量、短量、损耗、质量不合格、拒收和退回的处置流程尚未定稿；系统至少必须允许记录实际差异及附件，并阻止把不同状态错误显示成“已完成”。

## 9. 采购与履约模式的自动化关系

只根据订单已经选定的履约模式展示/建立采购加工责任，不自动臆测用量或供应商：

| 来源条目模式 | 允许产生的业务行 | 不允许的误操作 |
|---|---|---|
| 成衣纯 CMT | CMT 委外加工/费用，按合同记录已含面辅料范围 | 已含项目重复建立辅料采购 |
| 成衣辅料 + CMT | 成衣组辅料采购行 + CMT 加工行 | 创建我方负责的成衣面料采购 |
| 成衣全包 | 服装辅料采购、CMT 加工；面料另由面料组创建内部面料订单，成衣准确关联其行 | 在成衣订单内部直接建面料采购；产前样前没有面料订单仍继续 |
| 面料成品直采 | 成品面料采购行 | 无采购订单/虚构面料加工任务 |
| 面料原料 + 加工 | 原料采购行、委外加工行及其关系 | 原料成本与加工费用合并或丢掉来源 |
| 面料佣金 | 供应商、约定佣金率和最终出运结算 | 不为节省讨论而继续扩充重型采购页面；不将供货方货款当我方采购成本 |

佣金相关规则保持在面料条目中作为轻量履约模式，按最终全部出运后一次结算；本方案不扩展成采购/应付的独立复杂子系统。

## 10. 财务交接

以下按决策总账 8.4.1 的后续确认方向实施；当前票据首轮不代表预付款闭环已完成。

- 采购/加工业务合同与审批留在业务模块。
- 合同付款计划、预付款、已确认结算、发票状态与实际付款分别记录；签订合同不代表整额到期。供应商发票到后，财务关联已有采购/加工合同、预付和结算，不重复形成第二笔应付。
- 财务掌握并登记合同付款触发条件与到期安排；付款申请和实际付款分开。一笔实付仍可分配同一供应商多笔应付，一笔应付也可分次付；结算确认人、抵扣方式、付款审批岗位/条件和冲回权限仍待冻结。
- 供应商实付和财务核销回到业务采购/加工详情作为只读付款状态；财务未付不直接改写采购到货或加工完成事实，采购履约未完成也不代表财务未登记发票。

## 11. 消息、权限和审计

- 采购/加工待审批进入授权审批人待办；通过/退回后发起业务人员收到结果。
- 供应商确认交期变化、部分交付、交付差异和待登记供应商票据均在对应业务条目及待办里提示。
- 经办业务组看到自己的或授权范围内的单据；面料组处理面料/面料内部供给，成衣组处理服装辅料和 CMT；不存在统一采购专岗。
- QC 可访问相关采购/加工来源上下文用于质量检验，但不填写财务或供应商承诺；财务只读业务单据/合同依据。
- 每次草稿、提交审批、审批、改承诺、制单、供应商确认、分次收交、取消、更正，记录操作者、时间、字段版本、前后值、理由及附件。
- 已发生交付记录不物理删除；重复请求幂等；并发编辑旧版本返回刷新冲突。

## 12. 必须覆盖的跨模块验收

1. 成衣全包条目关联面料组内部订单行，面料组从面料入口建单；成衣组不能直接采购面料；面料数量不得多分配。
2. 同一供应商两条采购需求，五个合并条件一致时可放同采购主单，但各行规格、数量、价格、交期和源订单行独立；任一主单键不同则不能合并。
3. 同一供应商同时需要买原料并加工：系统创建采购单与加工单两种对象，互相链接但审批/合同独立。
4. 一条原料采购直送加工方：原料采购交付地点真实写加工方，库存账不产生虚假的收货再领出。
5. 一条原料先到我方仓库：录真实入库，后续实际领出交加工方；采购单、库存流水和加工行对应数量一致。
6. 未审批单不得下载/发送正式供应商合同；批准后如改供应方、规格、数量、价格或交期，系统要求修改审批并保留旧版。
7. 获批后供应商确认不同交期时，不能直接用确认日期覆盖已批交期；业务发起改承诺并重审。
8. 一个采购行/加工行分两次交付：分别留事件、累计数正确，来源订单条目正确更新。
9. 采购/加工需求金额进入对应费用归集；供应商增值税票进财务应付；财务一笔付款核销多笔同供应商应付后，业务单据只读显示付款结果。
10. 服装纯 CMT 范围内已包含的辅料不重复建辅料采购；辅料+CMT、全包分别显示正确采购责任。
11. 佣金模式所有实际出运完成前不推送频繁结算；最终一次结算按全部实际出运金额×佣金约定率提交财务。
12. 无权限账号、重复审批、并发编辑、交付重复提交、附件保存失败时不能出现部分提交或断失来源。

## 13. 需用户评判后冻结的字段/权限

1. 采购与加工各自订单字段目录、编号格式、正式模板。
2. 初次需求时是否已选供应商/已取得报价；如果未知，如何留候选而不误送审批。
3. 对应业务负责人/大老板的采购及委外审批权限，能否审批自己的单；是否继承订单审批人须显式确认。
4. 供应商拒单/未确认、供应商交期超期、暂时换厂的工作流及待办责任。
5. 多个来源条目共用一行同类物料时，是否允许保留多个来源分配行还是要求拆开采购行；推荐保留来源分配子行。
6. 采购收货、客户来料、委外交料/回交、质量拒收、超收/短收及加工损耗的最小数量与附件字段；其与库存模块的权威数据边界。
7. 到货/加工回交是否需要业务员双人复核；当前用户只确认由相应业务组操作，未确认二次确认角色，建议 MVP 不增加仓库审批岗。
8. 供应商增值税票覆盖多合同/多采购行时的税额/费用分摊方法；财务以供应商原票和可追溯分配为准。
9. 采购单部分交付后整单关闭、未交余量取消/转新单的动作和权限。
10. 本方案的“供应商确认凭据”和“登记本次交付”是否只用日期/数量/备注，还是必须上传附件。

## 14. 现有实现对照提醒（不是验收）

- 采购管理、库存与仓储和生产跟单存在多条历史写入路径；先区分采购承诺、真实仓库库存和委外加工交接的权威来源。
- “记录供应商/费用”不等于真实采购/加工对象已建立；必须从订单条目连到供应商承诺、交付事件和财务应付，再回到来源。
- 样品仓库与大货库存是两套产品范围；不能把样品仓库规则（逐件成衣、面料按形态、禁止盘点调整）自动套到生产物料库存。
- 询价比价、选定后转采购及暂停/拉黑后在手采购转供应商的现状与缺口，见 [27-供应商询价比价与在手业务交接范围核对-2026-10-17.md](27-供应商询价比价与在手业务交接范围核对-2026-10-17.md) §3-§4（范围核对，不是验收）。
- 本规格没有数据库/浏览器/实际业务账号验收证据；只有在后续逐项实现与验证后才可登记完成。
