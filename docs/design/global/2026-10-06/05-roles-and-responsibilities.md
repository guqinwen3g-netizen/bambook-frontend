# Bambook 角色与实际操作分工

修订日期：2026 年 10 月 7 日。状态：按用户最新澄清修订；与旧稿冲突时以本版为准。

## 一、核心口径：模块不等于岗位

“采购管理”“库存与仓储”“样品仓库”“生产跟单”等是系统模块和业务操作集合，不表示公司另有同名专职岗位。当前业务里没有采购员、采购经手专岗、仓管员、仓库管理员、样品保管人或独立样品管理员。相关操作通常由对应业务组的业务员在自己负责的业务对象上完成。

系统仍保留采购、库存和样品模块，因为它们承载业务资料、实物数量、位置和操作记录。职责由实际业务归属、对应面料/成衣业务组、真实用户账号、对象权限和状态共同确定，不另外造岗位名称或资格层。

## 二、系统内置角色

代码中现有七类内置角色码。它们是访问控制的容器，不是公司全部岗位清单；面料/成衣团队、QC专业组和业务模块入口可以再区分数据范围与工作队列，但不得据此创造采购或仓储岗位。

| 角色码 | 系统名称 | 业务定位 |
|---|---|---|
| `role-sales` | 业务员 | 面料或成衣业务组成员，负责本人经手的业务操作 |
| `role-sales-manager` | 销售主管 | 业务负责人；在获授权的业务范围内处理协调和审批，包括本人负责范围内的审批 |
| `role-finance` | 财务 | 登记业务已开具的CI及供应商票据，处理应收应付、收付款、核销和对账 |
| `role-admin` | 领导 | 处理获授权的业务审批与领导事项；不替代QC、财务的专业事实 |
| `role-qc` | QC | 处理专业检验任务和报告；面料与成衣团队、入口和任务范围分开 |
| `role-logistics` | 后勤 | 接收业务出运交接，处理货运与出运/报关单证；不是仓储岗位 |
| `role-super-admin` | 老板 | 系统最高权限及获授权的经营审批；技术权限不覆盖专业结论和业务证据 |

不得新增 `采购员`、`仓管员`、`仓库管理员`、`样品保管人` 等系统角色或职责资格。谁可以处理具体记录，按实际账号授权和对象数据范围控制。

## 三、模块操作由谁承担

| 业务操作 | 实际经办 | 专业交接及边界 |
|---|---|---|
| 面料需求、寻样、开发、报价、订单和客户沟通 | 面料业务组内实际负责该业务的业务员 | QC由面料QC完成；审批由有对应面料业务范围权限的负责人处理 |
| 成衣需求、开发、报价、订单和客户沟通 | 成衣业务组内实际负责该业务的业务员 | QC由成衣QC完成；审批由有对应成衣业务范围权限的负责人处理 |
| 面料采购、原料采购及面料加工 | 面料业务组的实际经办业务员 | 适用业务审批人审批；QC按需要处理专业检验；财务登记供应商票据、应付、付款与核销 |
| 成衣加工、辅料采购及成衣履约 | 成衣业务组的实际经办业务员 | 面料内部供给仍由面料业务组创建面料订单；财务不代替业务采购或签合同 |
| 业务条目生产跟进、生产完成数量登记 | 对应订单业务员 | QC持续记录专业生产检验；后勤单证接手出运阶段的物流和单据工作 |
| 样品登记、借出/寄出等样品管理操作 | 对应来源业务的业务员；无系统来源的补录由业务员操作 | 开发或订单来源保存后联动同一条实物档案；QC评审仍由QC完成；MVP不设盘点调整 |
| 大货库存、仓储、收发等实物动作 | 对应业务组内实际经手的业务员按其业务路径操作 | “库存与仓储”是记录与操作模块，不设专职仓储执行人；实际出运单证由后勤单证处理 |
| QC评审和报告 | 分开的面料QC团队或成衣QC团队 | 业务员发起任务并在来源对象接收结果，不代填QC结论 |
| 出运、运输安排和单证 | 后勤单证 | CI/Packing List等出运单据完成后回到业务员，由业务员继续对客沟通和发送 |
| 财务登记与核销 | 财务 | 不负责开具业务CI/Packing List，不判断订单是否履约完成 |

## 四、账号与权限规则

1. 业务操作落到真实用户账号，并限制到该用户有权处理的团队、来源对象和订单条目；同一模块中的不同动作可以由不同专业人员处理。
2. 业务负责人和老板按各自获授权的业务范围接收审批待办；某一获授权审批人处理后，其结果对其他审批人可见，记录实际审批人。业务负责人可以审批自己负责范围内的单据。
3. QC、财务、后勤单证的专业权限仍保持分开。业务员的采购或库存操作权限不意味着可以提交QC报告、正式账务或后勤单证事实。
4. 模块访问权限、对象数据范围、审批范围和状态门禁分别配置。不能通过岗位名推断权限，也不能因为某人能查看一个模块就推断其可以改写其中所有数据。
5. 默认经办归属不等于排他禁令。保留后勤等真实账号已有的必要协作能力；不能因“不设仓储岗位”而一概撤掉其协作权限，也不能把这些权限反过来解释为仓储专岗。具体动作仍须通过来源对象、业务范围和状态校验。

## 五、对旧资料的纠正

本版替代旧稿中以下错误口径：

- “职责资格层”及由Kevin另指定采购经手主责/备选名单；
- “仓储收发由后勤独占”“库存写权限只给后勤”；
- 采购与仓储分别由独立职责承担人操作；
- 业务员只能提出仓储请求、不能办理实际样品或库存操作。

采购/加工、样品仓库、库存与仓储模块继续保留，受影响的只是虚构的岗位归属。全局图、角色权限文稿、交接目录和模块设计引用本版时必须同步使用这一口径。
