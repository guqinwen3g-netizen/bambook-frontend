# Bambook 布局构建语言（BDS Layout Layer，Phase 1 真源）

> 定位：在 BDS v2.2（tokens.css + components.css）之上新增的**布局层规范**，是"页面该怎么组"的正面真源。每个原语 = 规范定义 + bds 类/组件 + 守卫断言（可机器判分）。Phase 2 逐页重建只能由本语言的原语组合，禁止自由手写 Tailwind 布局。
> 前置依据：`10-评审与决策/2026-08-18-UI纪律规范驱动全量重建方案.md`（§3 Phase 1）+ `2026-08-18-全页面UI纪律排查台账.md`（布局层违例实证）。
> 版本：v1.0（2026-08-18）。真源状态：随 Phase 2 逐页销号实时回写。

## 0. 设计原则

1. **刻度唯一**：一切间距/尺寸/圆角/字重只能取 BDS token 刻度值（`--space-*`/`--r-*`/`--p-*`/`--h-*`），禁任意值。
2. **语义化**：容器表达"角色"（页壳/面板/井/缩略图/工具栏/空态），不表达"像素"。
3. **机器可判分**：每个原语附守卫断言，`scripts/check-design-tokens.sh` 基线模式扫描，只减不增。
4. **复用优先**：已有类（pagehead/filterbar/table/empty/skeleton/toolbar/stat/segment）一律继承，不另起炉灶；本层只补缺口。
5. **嵌套层级**：底座容器浅 → 内嵌容器深（recessed 蚀刻），选中项更浮（raised）；深浅主题同心不反转。

## 1. L1 页面骨架 PageShell

**规范**：每页 = PageHeader（中英混排标题 + 右侧 breadcrumb 槽）+ 内容画布 + 底边距。
- 页级 inset 唯一刻度：`px-7 pt-5 pb-4`（=`--p-pagehead` 同源）。
- PageHeader 必含：`ph-main`（title 中英 + sub）+ `ph-side`（breadcrumb/动作槽）。
- 内容画布滚动区内 `pb-4`（--space-4），允许 `pb-5` 缓冲。

**bds 类**：`.bds-pagehead`（已有，components.css §）+ `--p-pagehead`（tokens.css）。
**React 原语**：`components/ui/PageHeader.tsx`（已有，保留为唯一入口）+ 新增 `PageShell` 包裹组件（见 §9）。
**守卫断言（L1）**：每个 `*Manager.tsx` 必须含 `PageHeader` 或 `bds-pagehead`（沿用 M1 基线，当前 2 处缺失 = EmailManager / SignatureManager）。

## 2. L2 间距刻度 space-scale

**规范**：全仓间距（padding/margin/gap/space）只能取刻度：`4/8/12/16/20/24/28/32/40/48/64`（=`--space-1/2/3/4/5/6/7/8/10/12/16`）。
- Tailwind 语义类映射：`p-1`(4) `p-2`(8) `p-3`(12) `p-4`(16) `p-5`(20) `p-6`(24) `p-7`(28) `p-8`(32) `p-10`(40) `p-12`(48) `p-16`(64)。
- **违例**：Tailwind 刻度外类（`p-9`=36 / `p-11`=44）与任意值（`px-[15px]`/`gap-[7px]`/`space-y-[9px]`）。
- 说明：BDS 既有 `--space-7`(28) 是页面横向 padding 规范值（px-7），属合法刻度；方案文档 §3 所列"4/6/8/..."为缩写，以本表为准。

**bds 类**：无新增（Tailwind on-scale 类即规范载体）；如需语义命名（如 `--p-card`）走 token。
**守卫断言（L2）**：扫描 `(p|px|py|pt|pr|pb|pl|m|mx|my|mt|mr|mb|ml|gap|gap-x|gap-y|space-x|space-y)-[0-9]+` 中数值 ∉ {1..8,10,12,16} 即违例；扫描 `-[0-9]+px]` 任意值中数值 ∉ {4,8,12,16,20,24,28,32,40,48,64} 即违例。基线 = 当前计数，只减不增。

## 3. L3 容器与长宽比

**规范**：
- **卡片高度族**：标准卡/工具卡/统计卡内容自适应高度，**禁写死 `h-[Npx]`**；确需等高的用 CSS grid 拉伸。
- **图表井（well）**：图表/可视化容器统一 `.bds-well`，内置统一最小高度（--well-h，默认 220px）与 recessed 蚀刻底。
- **缩略图（thumb）**：方形图片占位统一 `.bds-thumb`（aspect-ratio 1/1，尺寸用 `--thumb-*` 档：40/56/72/96/116px），禁裸 `w-[Npx] h-[Npx]`。
- **浮层尺寸族**：菜单/抽屉宽高取 `--pop-*`/`--sheet-*` 档，禁任意值。
- **嵌套层级**：外卡 `.bds-card`（--r-card）> 内嵌行 `.bds-row`/`.bds-surface`（--r-inset）> 蚀刻控件（--r-control），圆角随层级递减，同心。

### 3.1 区域边界组合（2026-10-04 用户裁决）

同一区域只保留一种划分方式：连续的平面内容用满宽直角行和发丝分隔线；独立的内嵌圆角区域用 recessed 表面、圆角和留白。禁止让直线紧贴内层圆角区域的上沿、下沿或侧沿，形成重复边界；也不能把直角选中底面内缩成左右留缝的小块。

- 圆角内嵌区域与父容器之间须保留 BDS 间距刻度的内距；写信弹窗正文使用 `--space-6`（24px）横向内距和下方留白，收件区不再添加贴着正文上沿的分隔线。
- 平面列表、表格和工作区分栏可以保留分隔线；不为取消分隔线给这些行额外套圆角卡片。
- 连续的 ListRow 列表显式使用 `.bds-listrows.flat`：列表包装层外围 padding、行间 gap 与行外 margin 为 0；行底面与相邻 hairline 填满所属列表表面的内部可用宽度，行圆角为 0，外围表面负责圆角和裁切。文字与控件的 padding 保留在行内，当前 flat ListRow 横向使用 `--space-4`（16px），纵向沿既有密度；不能清空内容内距，也不能新增 `px-*` 包装层恢复两侧 gutter。该变体不改变选中底色或点击行为。
- flat 的零外围留白是列表内部边界规则，不是页面外距归零。独立内嵌区域则保留自己的圆角、内容内距及与父容器/相邻区域之间的 BDS 留白；两种模式不能混用。`.bds-card.flat` 仍是既有材质变体，不因同名而变成零圆角列表。
- 页头的 `--p-pagehead`（20/28/16px）与桌面主面板外曲线的底部 inset 是不同的边界职责。当前 desktop/compiled 主面板消费 `.bambook-main-panel-bottom-inset`（`styles/os-vnext.css:633`），由既有 `--ui-lab-main-panel-bottom-inset` 提供34px；不能用页头的16px或内容缓冲的20px替换，也不能在同一边界重复叠加。内容滚动区的内距仍按其组件族规则处理。
- 邮箱虚拟连续列表使用 `.bds-email-listrow`，选中底面圆角为 0。专用双类选择器覆盖全局 selected-surface 的 inset 圆角，保留既有行尺寸、选中底色和左侧标记，不套用通用 ListRow 的密度。
- 具有独立交互含义的输入框描边、聚焦态和校验态保留；它们不等同于区域分隔线。
- 验收必须检查实际渲染的相邻父子结构和样式覆盖。不能仅凭同时出现 `rounded-*` 与 `border-*` 就批量删线或改圆角；Dashboard 继续按既有 UI 豁免执行。

同语义、同语境、同密度、同边界模式必须消费同一配方；不同内容不机械锁为同一高度。全局收拢按组件族推进，当前映射、已确认几何与待处理冲突见 [`同语义同规格收拢表`](../../design-system/同语义同规格收拢表-2026-10-04.md)。

**bds 类（新增，layout.css）**：
- `.bds-well`（图表井，min-height 族 `--well-h`）+ `.bds-well--sm`（180px）/`--lg`（280px）
- `.bds-thumb`（方形容器 `aspect-ratio:1/1`）+ `--s`/`--m`/`--l`/`--xl` 尺寸档
- `.bds-card--tall`（等宽卡片列内补足高度，替代 h-[Npx]）

**守卫断言（L3）**：扫描 `h-[Npx]`/`min-h-[Npx]`/`w-[Npx]`/`aspect-[N/N]` 任意值（排除豁免清单：模态 `max-h-[85vh/88vh]`、Agent 滚动区 `max-h-[Npx]`、图片预览 `max-h-[90vh]`、`.bds-thumb` 内部）。基线 = 当前计数（台账 L3-1~L3-10），只减不增。

## 4. L4 工具栏组合 ToolbarPattern

**规范**（沿用 filterbar 选型规则 + M3）：
- 纯单搜索页 → 简单搜索框（leading icon 在输入框内）。
- 搜索 + ≥1 筛选共行 → `.bds-filterbar` 组合 bar。
- 行高唯一：input 34px（`--h-input-sm`）/ 按钮 40px（`--h-btn-md`）；`.bds-filterbar` 作用域禁手写 `h-*` 覆盖。
- 工具栏动作区：左侧标题/计数（`.tb-count`）、右侧动作按钮组。

**bds 类**：`.bds-filterbar`（已有）+ `.bds-toolbar`（已有，tb-left/tb-right/tb-count）。
**守卫断言（L4）**：沿用 M3（filterbar 高度违例基线 3 处）；扩展扫描 `bds-toolbar` 内裸 `h-*` 覆盖（基线 0）。

## 5. L5 表格密度 TableDensity

**规范**：
- 行高族：`compact`（40px）/`standard`（48px）/`relaxed`（56px）三档，由 `.bds-table` 密度修饰符表达，禁行内 `h-[Npx]`。
- 单元格 padding：`td` 纵 `8px`（compact）/`12px`（standard），横 `--space-4`(16px)；表头 10px 大写微标签。
- 分隔：hairline `--border-subtle`；hover `--hover-darken`；选中 `.rowsel` `--accent-tint-strong` + 左缘 `inset 2.5px accent`。

**bds 类**：`.bds-table`（已有）+ `.compact`/`.sticky`/`.rowsel`（已有）+ 新增 `.dense`（40px）/`.cozy`（56px）修饰符。
**守卫断言（L5）**：扫描表格行高硬编码 `h-[4-9][0-9]px`（台账 L3-3 `PRODUCT_SUB_INDEX_ROW_CLASS h-[72px]` 等）与 `max-h-[Npx]` 表体；基线 = 当前计数，只减不增。

## 6. L6 icon 尺寸体系

**规范**：
- 尺寸档：`xs`(14)/`sm`(16)/`md`(18)/`lg`(20)/`xl`(24)；按钮内 16、行内 18、卡片标题 20。
- strokeWidth 纪律（以 tokens.css §16 为真源）：`--icon-w-sm` 1.75（≤18px 默认光学粗细）、`--icon-w-lg` 2（≥20px 默认）、`--icon-w-light` 1.5（细）、`--icon-w-thin` 1.25（极细）。icon 只允许此四档，禁 `strokeWidth={1}` 及任意自由数值。
- 容器：`size={14|16|18|20|24}` 外的数值视为违例。

**bds 类**：`.bds-icon` + `.xs/.sm/.lg/.xl` + `.w-light/.w-thin`（已有）。
**守卫断言（L6）**：扫描 `size={N}` 中 N ∉ {14,16,18,20,24} 即违例；扫描 `strokeWidth={N}` 中 N ∉ {1.75, 2, 1.5, 1.25} 即违例（基线 = 当前计数，只减不增）。

## 7. L7 空态/错误态/加载态

**规范**：
- **空态**：`.bds-empty`（glyph 圆形雾化图标 + title + desc）；mist 变体用于玻璃背景卡。
- **错误态**：统一 `.bds-error-banner`（--danger-tint 底 + --danger-text + 左缘 danger 条），替代各页手写 `p-3 rounded-inset border + text-red-400` 拼装；字段级错误走 `.bds-formfield.error`。
- **加载态**：`.bds-skeleton`（shimmer 骨架）行级/块级；页面级骨架用骨架块组合。

**bds 类**：`.bds-empty`/`.bds-skeleton`（已有）+ 新增 `.bds-error-banner`。
**React 原语**：`EmptyState` / `ErrorBanner` / `Skeleton` / `SkeletonLine`（见 §9）。
**守卫断言（L7）**：扫描 raw 错误色 `text-red-400`/`bg-red-50`/`border-red-400` 等（台账 T2 EmailManager ×2）；扫描 `font-medium`/`font-semibold` 错误文案残留。基线 = 当前计数，只减不增。

## 8. L8 视觉反馈

**规范**：
- hover 统一 `--hover-darken`；active 统一 `--active-darken`；选中 `--selected-surface`（冷墨洗，禁实心黑/暖色）。
- 行/卡反馈收敛为 `.bds-row`（hover/press/active 三态类）；toggle active 用冷墨洗 tint/inset（既有决策固化）。
- 禁暖色 hover（amber/orange 系）。

**bds 类**：`.bds-row`（新增：`--hover`/`--press`/`--active` 修饰）+ 已有 `.bds-segment`/`.bds-toggle`/`--hover-darken`/`--active-darken`/`--selected-surface`。
**守卫断言（L8）**：扫描暖色 hover `hover:bg-amber|orange|yellow`（基线 = 当前计数，只减不增）。

## 9. L9 排版层 TypographyLayer（2026-10-01 补齐）

> **为什么补这一层**：L1–L8 覆盖了间距/容器/工具栏/表格/图标/空态/反馈，唯独排版没有对应原语，
> 于是字号与字距成为**唯一没有机器可判分护栏的视觉维度**。后果是仓库里长出了 ~1200 处 `text-[10px]`
> （低于 §9.1 明文否决的可读硬底）与 252 处越界字距（0.14/0.18em 均超出0.12em 上限）。
> 补齐本层后，排版第一次可以被 `scripts/check-design-tokens.sh` 机器判分。

### 9.1 字号刻度（唯一合法值）

七档刻度，**起点就是 12px**：

| 类 | px | 用途 |
|---|---|---|
| `text-xs` | 12 | 微标签 / 表头 / 时间戳 / 徽章（**最小刻度**） |
| `text-sm` | 14 | 正文 / 分区标题 / 表单 label |
| `text-base` | 16 | 面板主标题 / 高亮数值 |
| `text-lg` | 18 | 页面级标题 / 抽屉标题 |
| `text-xl` | 20 | 大数 KPI |
| `text-2xl` | 24 | hero 数字 |
| `text-3xl` | 32 | hero 主标题 |

**硬底裁决（不可推翻）**：`tokens.css:332` 与 `tailwind.config.js:75-77` 双向载明
「**11px 中文低于可读硬底（CJK 笔画密度高，12px 以下发虚）**」。因此 8/9/10/11px 一律禁止，
统一收敛到 `text-xs`。

**违例**：任意值字号 `text-[Npx]` 全部属违例。含 `text-[12px]` / `text-[18px]` 这类「数值恰好合规」的写法
——它们绕过刻度体系，不与 §9.1 这张表同源，下一次调刻度时不会跟着变，属隐性双轨。

### 9.2 字重（单一值）

**只准 `font-light`（300）**。

机制保障：`tailwind.config.js:62-72` 已把 medium/semibold/bold/extrabold/black 全部坍缩为 300。
强调只靠**墨色层级与字号**，不靠字重。写 `font-bold` 属于源码级违例（视觉上无害）。

### 9.3 字距刻度

```
tracking-wide     0.04em   一般加宽
tracking-wider    0.08em   表头 caps
tracking-widest   0.12em   上限（2026-10-01 前的最宽档）
tracking-caps     0.14em   表单 label / 分区标签   ← 2026-10-01 收编（原 198 处任意值）
tracking-caps-wide 0.18em  大写分组标题            ← 2026-10-01 收编（原 54 处任意值）
```

> 注意 2026-10-01 同时修了一处**双轨**：Tailwind 默认 `wide/wider/widest` = 0.025/0.05/0.1em，
> 与 tokens.css 的 0.04/0.08/0.12em 不一致。已在 `tailwind.config.js` 显式对齐 token。

### 9.4 标题不许靠继承

preflight 生效（`index.css:40 @tailwind base`）⇒ 裸 `<h1>`~`<h6>` 的 font-size 被重置为 `inherit`。
**任何标题都必须显式落字号类**，否则大小由父容器随机决定。

| 标签 | 应为 |
|---|---|
| `<h1>` `<h2>` | `text-lg font-light` |
| `<h3>` | `text-base font-light`（面板主标题） |
| `<h4>`~`<h6>` | `text-sm font-light`（分区标题） |

### 9.5 守卫断言（L9）

1. 扫 `text-\[\d+px\]` → 必须为 0（Dashboard / 单据打印模板 / 邮件模板 / SVG-GL / 吉祥物按既有豁免清单排除）
2. 扫 `font-(medium|semibold|bold|black|extrabold)` → 只减不增
3. 扫 `tracking-\[[\d.]+em\]` → 必须为 0（改用 §9.3 五档）
4. 扫写了 `<h[1-6]>` 却不含任何字号类的标签 → 必须为 0

### 9.6 本次收编的豁免边界（2026-10-01 生效）

| 范围 | 是否纳入 | 理由 |
|---|---|---|
| `components/Dashboard*` | **否** | Kevin 2026-10-01 指定整体豁免 |
| `components/tools/**` 单据生成器 | **否** | 字号属对外单据版式（发票/装箱单/合同），改了会影响发给客户的文件 |
| 邮件模板 / 发票模板 | **否** | 邮件客户端不支持 CSS 变量（既有守卫豁免） |
| `mascot` / `Globe` | **否** | SVG / WebGL 渲染（既有守卫豁免） |
| 其余业务组件 | **是** | 本次已归一 |
