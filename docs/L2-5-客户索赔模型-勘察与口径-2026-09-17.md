## 一、为什么必须先谈这个（不是「功能缺失」而是「账实不符」）

- 设计侧**早已识别**：`docs/design/10-评审与决策/2026-08-25-中度与严重缺失功能开发优先级规划.md:4`
  把「**客户索赔退货**」列为 3 个「软件未实现」项之一，**刻意**留在待决策台账单独决策。
- 业务侧：面料 + 服装外贸，质量索赔（**色差 / 克重 / 缩率**）是家常便饭。
- 后果不是「少个功能」，而是：**这笔钱只能走系统外** → 发票永远收不满 → 应收/账龄/授信全失真。

## 二、对撞清单：系统写死的假设 × 业务需要

| # | 能力面 | 系统现状（可扫描的事实） | 业务侧变异（Kevin 才知道） | 撞墙点 |
|---|---|---|---|---|
| 1 | **权限码** | `aftersales:read/write/approve` 三码在 `server/src/_shared/rolePermissionMatrix.ts:163-165` **已定义**，且已按设计矩阵分配给业务员 / SM / 总领导 / QC / 单证 / 财务 / 审计 | — | **0 个路由消费** → 三个码悬空（`grep requirePermission` 无命中） |
| 2 | **模型** | `MaterialReturn` 只覆盖**对供应商**：`type = return \| exchange \| claim`；`claim` → 生成**负向 Payable** 贷项发票（`CLM-YYYY-NNNN`）+ 库存 Outbound 冲减 / 换货回冲 + 供应商绩效 | 客户侧同源场景（退货 / 折让 / 索赔） | **客户侧无任何模型**（schema 里不存在 CustomerClaim / CreditNote） |
| 3 | **发票类型** | `Invoice.type ∈ { Receivable, Payable }`（schema 注释只这两个） | 外贸实务：质量索赔通常开 **Credit Note（贷项通知单）** | 没有 `CreditNote` 类型；`docs/archive/superseded/` 有一版已归档的 CN 计划 |
| 4 | **发票状态机** | `recalcInvoiceStatus` 的 Paid 判据 = `amount.gt(0) && Σapplied ≥ amount` | 贷项票（负额）应当「开完即结清」 | **`amount ≤ 0` 的票永远不可能 Paid** —— 真库实测：0 元票停在 `Issued`（见 §四.2 S4） |
| 5 | **「未结清应收」判据** | 原先 **6 处**手写 `type='Receivable' && status∈{Issued,PartiallyPaid}`，**不看金额 / 不看未结额** | — | **0 元/负额票被当成逾期** → 虚增 `maxOverdueDays` → 挡单 / 冻结 / 催办；且该票永不 Paid ⇒ **无任何自动解冻路径**。★ 这是 5 号的**地基**，**已修**（§四） |
| 6 | **金额符号守卫** | `invoiceMutationService`：`POSITIVE_ONLY_FIELDS = {exchangeRate}`、`NON_NEGATIVE_FIELDS = {amount}` → 金额**禁负数、放行 0** | 客户贷项需要「负向应收」 | **走 API 建不出负额应收票**（400 INVALID_AMOUNT）→ 路线 B/C 必须同时放宽守卫（并补齐下游） |
| 7 | **库存侧** | `MaterialReturn` 退货 → 库存 Outbound 冲减；换货供应商确认后回冲同一库存项 | 客户退货：实物**回到自己仓库** | 客户退货没有入库链（更别说「不良品仓 / 待判定仓」） |
| 8 | **QC 侧** | `docs/Bambook-操作手册.md:654` 的「不合格品登记退货/换货/索赔」是**来料检验**（对供应商） | 客户投诉走的是**出货后**质量异议 | 两条链不能复用：来料 QC 的 `MaterialReceipt` 锚点对客户投诉不成立 |
| 9 | **处置动作** | 生产侧有返修 / 加急 / 换厂（`releaseService` 等） | 客诉处置三种：**折让（钱）/ 换货补发（货）/ 退货退款（钱+货）** | 「因客诉补发」没有来源标识 → 补发批次无法回溯到客诉，成本也归不到索赔头上 |
| 10 | **审批链** | `docs/design/01-产品总览/6. 角色与权限矩阵.md:506`：`aftersales:approve` 归 **SM（本团队）→ 总领导（大金额兜底）**，且**影响应收金额** | 大金额阈值是多少？ | 阈值与「谁能最终定损」需业务给数（DR-007） |

## 三、三条路线（改动面 / 风险 / 建议）

| 路线 | 做法 | 优点 | 代价 | 评价 |
|---|---|---|---|---|
| **A. 不建模型**：用「改发票金额」抹平 | 财务把索赔额直接从原票金额里减掉 | 零改动 | **审计链断裂**（改金额无「为什么改」的语义）；原票金额与实际开票额不一致；**这条路上批已被我修出 `AMOUNT_BELOW_ALLOCATED` 守卫挡住一部分** | ❌ 不建议（当前就是这条路的退化版） |
| **B. 新增 `CustomerClaim` 模型（镜像 `MaterialReturn`）** | 新模型 `type = allowance(折让) \| return(退货) \| repair(返修) \| exchange(换货补发)`；审批走 `aftersales:approve`；确认后生成**负向 `Receivable`** 贷项发票（复用 `CLM-` 号段）冲减应收 | **最贴本仓既有范式**（供应商侧已跑通同一套：类型 + 状态机 + 贷项票 + 库存联动 + 绩效）；货物侧可挂库存/生产 | ① 必须放宽 `amount` 符号守卫（且逐点核对下游）② 必须修 `recalcInvoiceStatus` 的 Paid 判据（撞墙点 4）③ 新增路由 + 前端 | ✅ **推荐**（可分阶段：先只做「折让」= 纯金额，再补「退货/返修」的货物侧） |
| **C. 贷项通知单 CreditNote（负数发票 + 原票被 CN 核销）** | 新增 `Invoice.type = CreditNote`，原票通过一笔 allocation 被 CN 核销 | **最贴外贸实务**；审计链最完整（原票金额不动） | 改动面最大：`IOA` / 批次结算 / 退税联动 / 账龄 / 授信全要跟；`Invoice.type` 的 2 值假设散布多处 | ⚠️ 长期正解，但**不建议作为第一步** |

**我的建议**：**B 分两阶段**。阶段 1 = 「客户折让（纯金额）」打通 `aftersales:approve` → 负向贷项票 → 应收冲减，把 §四的前置修复用上；阶段 2 = 补「退货/返修/补发」的货物侧（库存 + 生产来源标识）。这样每阶段都能被 Kevin 用真实业务走一遍。

## 五、★ 待 Kevin 判的口径（5 号开工前必须定的 5 条）

1. **客诉处置有哪几种？** 折让（钱）/ 退货退款（钱+货）/ 换货补发（货）/ 返修（货）——
   四种都要，还是先只做「折让」？（决定是阶段 1 还是直接上全量）
2. **钱怎么走？** (a) 负向 `Receivable` 贷项票（复用 `CLM-` 号段，需放宽 amount 符号守卫）
   / (b) 独立 `CreditNote` 类型（最贴外贸实务，改动面最大）/ (c) 不建票，只做「应收调整单」。
   > **建议 (a) 起步**，但请确认：**客户拿到的是贷项通知单（CN）还是直接在下张发票里抵扣？**
   > 这决定「是否必须能打印一张 CN 单据」。
3. **贷项票的终态是什么？** 现状：`amount ≤ 0` 的票**永远到不了 `Paid`**（停在 Issued）。
   选项：(a) 改 `recalcInvoiceStatus` 让 `amount ≤ 0` 视为「开完即结清」→ Paid
   / (b) 新增 `Settled` 语义 / (c) 贷项票不参与状态机（独立 `status`）。
4. **0 元应收票要不要直接拒？** 现在 API 放行（0 元票本身无意义，但**不能**用「拒绝 0」替代判据修复——
   负额贷项是**合法**的）。选项：(a) 拒绝 `amount == 0`（更干净）/(b) 保持放行（判据已修，无信用后果）。
5. **审批阈值与归属**：`aftersales:approve` 设计归 SM → 总领导（大金额兜底）。
   **大金额的线划在哪？**（例如 ≤ 5000 USD 由 SM 直接批，超过要总领导）—— 这决定审批链的分支。
   > 另：`aftersales:*` 三码现在**零路由消费**，接了模型才会真正生效；接之前请确认角色分配是否还准。
